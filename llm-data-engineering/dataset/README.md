## 0. 一句话锚点

**预训练数据集 = 把人类互联网/书籍/代码「洗干净、按比例配好」的超大文本堆，模型在它上面做「预测下一个 token」来学会语言与知识。**

一句口诀：**Garbage In, Garbage Out（垃圾进、垃圾出）**。模型架构相近时，谁的数据更干净、配比更合理、规模更匹配算力，谁就更强。

```
   原始互联网（脏、重复、有毒）
        │  抽取 + 清洗 + 去重 + 过滤 + 去毒
        ▼
   预训练语料（万亿级 token，干净、配好比例）
        │  喂给 Transformer，做 next-token prediction
        ▼
   基座大模型（懂语言、有知识、能推理的底子）
```

## 1. 地基 / 前置（不假设你记得）

**① 什么是 token？**
模型不直接读「字」，而是读分词器（tokenizer）切出来的 token（子词单元）。粗略换算（以官方分词器为准）：

- 英文：1 token ≈ 0.75 个单词 ≈ 4 个字符。
- 中文：1 个汉字 ≈ 1~2 token（取决于分词器，BPE 对中文常 1 字 1~2 token）。

所以「800GB 文本 ≈ 180B token」这种说法，是**字节→token**的经验换算，不是固定汇率。

**② 什么是语料（corpus）？**
一大堆文本文档的集合。预训练语料动辄 **TB 级原始数据 → 万亿（T）级 token**。

**③ 数据流水线（data pipeline）长什么样？**

```
 ┌─────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐
 │ 原始抓取 │→│ 文本抽取│→│  去重   │→│ 质量过滤│→│  去毒   │→│ 配比&切分│
 │  (WARC) │  │(去HTML)│  │(dedup) │  │(filter)│  │(detox) │  │(mixture)│
 └─────────┘  └────────┘  └────────┘  └────────┘  └────────┘  └────────┘
   PB 级         TB 级       砍掉重复     砍掉低质     降低有害     最终 token
```

**④ 为什么「书籍 / 维基百科 / 代码」是好数据？**

| 来源 | 为什么好 |
|------|----------|
| 书籍（BookCorpus 等） | 长上下文、逻辑连贯、语言规范 → 教模型「长程依赖」 |
| 维基百科 | 高密度事实、结构清晰 → 教模型「世界知识」 |
| 代码（GitHub） | 强逻辑、严格语法 → 显著提升模型「推理/链式思考」能力 |

经验结论：高质量、低重复、逻辑性强的数据，**单位 token 的「营养」远高于**网页噪声。

## 2. 常用语料全景

### 2.1 Common Crawl（CC）—— 一切的源头

- **是什么**：非营利组织 Common Crawl 每月抓取的**整个公开网页**快照。单月就有 ~**PB 级**、数百亿网页。
- **格式**：WARC（原始 HTTP 响应，含 HTML）、WAT（元数据）、WET（已抽好的纯文本）。
- **为什么用它**：唯一免费、超大、覆盖全网的语料来源。几乎所有开源大模型的「网页」部分都来自 CC。
- **痛点**：极脏——满是导航栏、广告、乱码、重复、垃圾站、成人内容。**直接用会拉垮模型**，必须重度清洗。

```
Common Crawl 一个月快照
 ┌──────────────────────────────────────┐
 │  ~PB 级 WARC（数百亿网页，含大量垃圾） │  ← 原料
 └──────────────────────────────────────┘
        │  抽取 + 清洗（通常只保留 1%~10%）
        ▼
   可用网页 token（GB~TB 级）
```

### 2.2 C4（Colossal Clean Crawled Corpus）

- **是什么**：Google 为 **T5** 制作的 CC 清洗版（约 **750GB** 英文）。
- **清洗规则（启发式，经典范例）**：只保留以标点结尾的句子；丢弃含「脏词表」的页面；丢弃含 `lorem ipsum`、`{`（疑似代码/模板）、`JavaScript` 提示等的行；用 langdetect 只留英文且置信度高的页面；按 3 句去重。
- **意义**：第一个把「CC 清洗」标准化、可复现的数据集，后续工作的基线。

### 2.3 The Pile

- **是什么**：EleutherAI 制作的 **825GB** 多样化英文语料，由 **22 个子集**拼成（不止网页）。
- **组成（部分）**：Pile-CC、PubMed、ArXiv、GitHub、Wikipedia、OpenWebText2、StackExchange、USPTO 专利、Project Gutenberg（古登堡书籍）、DM Mathematics、HackerNews、OpenSubtitles 等。
- **理念**：**多样性 > 单纯堆量**。学术、代码、数学、法律、对话都来一点，模型能力更全面。

### 2.4 RedPajama —— 复刻 LLaMA 的数据配方

- **是什么**：开源社区按 **LLaMA 论文**披露的配方复现的 **~1.2T token** 语料（RedPajama-1T）；后续 RedPajama-V2 扩到 **~30T token**（含多语言、质量打分信号）。
- **七大子集与近似配比**（贴近 LLaMA-1）：

```
RedPajama-1T 配比（约 1.2T token）
 CommonCrawl ████████████████████  ~67%   (5 个 CC 快照，已清洗)
 C4          ███████               ~15%
 GitHub      ██                     ~4.5% (代码)
 Books       █                      ~4.5% (书籍)
 ArXiv       █                      ~2.5% (论文)
 Wikipedia   █                      ~4.5% (多语种)
 StackExch.  ▏                      ~2%   (问答)
```

- **意义**：让没有 Meta 内部数据的团队，也能拿到「LLaMA 级」开源语料，是开源生态的里程碑。

### 2.5 中文语料

中文公开高质量语料相对稀缺，常见来源：

| 数据集 | 内容 | 备注 |
|--------|------|------|
| CLUECorpus2020 | 100GB 中文网页 | 经典中文预训练基线 |
| WuDaoCorpora（悟道） | TB 级中文，含清洗版 | 智源出品 |
| Wikipedia-zh / 百科类 | 高密度中文知识 | 质量高但量小 |
| 中文 CommonCrawl 切片 | 从 CC 按语言过滤出中文 | 量大但需重洗 |
| 书籍 / 新闻 / 论坛 | 多领域中文 | 注意版权与去毒 |
| SkyPile / MNBVC / Telechat 等社区集 | 大规模中文清洗集 | 持续更新 |

> 参考：[预训练中文语料汇总（附数据）](https://zhuanlan.zhihu.com/p/163616279)

**中文特有难点**：繁简混杂、全角半角、乱码编码、广告/SEO 垃圾站比例高、优质长文偏少 → 清洗与去重权重更大。

## 3. 清洗流程（数据工程核心）

目标：把「脏 CC」变成「干净语料」。三大支柱——**去重、质量过滤、去毒**。

```
 抽取后的纯文本
   │
   ├─[A] 去重 Dedup ───── 精确去重 + 模糊去重(MinHash/SimHash)
   │
   ├─[B] 质量过滤 ─────── 启发式规则 + 分类器打分 + 困惑度
   │
   ├─[C] 去毒 Detox ───── 脏词表 + 毒性分类器 + 隐私(PII)脱敏
   │
   ▼
 干净语料（送去配比）
```

### 3.1 去重（Deduplication）

**为什么必须去重？** 网页天然海量重复（镜像站、转载、模板）。重复数据会：① 让模型「死记硬背」少数文本，过拟合；② 浪费算力训练同一句话；③ 污染评测（训练集泄漏到测试集）。研究表明去重后**同样算力下效果更好**。

两种粒度：

- **精确去重（exact dedup）**：完全相同的文档/段落，用哈希直接删。
- **模糊去重（fuzzy / near-dedup）**：内容相似但不完全相同（如改了一个词）。用 **MinHash + LSH** 或 **SimHash** 估计相似度，相似度超阈值（如 Jaccard > 0.8）则删。

```
   文档A: "今天天气很好，适合出门散步。"
   文档B: "今天天气很好,适合出去散步！"   ← 精确去重抓不到
        │  shingle 成 n-gram 集合 → MinHash 签名 → LSH 分桶
        ▼
   Jaccard 相似度 = 0.85 > 阈值 0.8  → 判为重复，删一个
```

### 3.2 质量过滤（Quality Filtering）

把「人写的连贯文本」留下，把「机器生成/垃圾/乱码」扔掉。三类方法：

1. **启发式规则（heuristic）**：文档过短/过长丢弃；符号比例过高丢弃；停用词太少（疑似关键词堆砌）丢弃；行内重复率高丢弃；非目标语言丢弃。（C4、Gopher、MassiveText 的规则集是经典模板。）
2. **分类器打分（classifier）**：训一个分类器，正样本=维基/书籍等高质量文本，负样本=随机 CC，给每个 CC 文档打「像不像高质量」分数，按分数采样（GPT-3、LLaMA 都用过）。
3. **困惑度过滤（perplexity）**：用一个小语言模型对文档算困惑度，太高（乱码）或异常太低（重复模板）都丢。

```
 质量打分采样示意
   CC 文档 ──► 分类器 ──► 质量分 0~1
                              │
              分高 ──保留概率大──► 进语料
              分低 ──保留概率小──► 多半丢弃
```

### 3.3 去毒与隐私（Detoxification / PII）

- **去毒**：用脏词表 + 毒性分类器（如 toxicity score）识别仇恨、暴力、色情、辱骂内容并过滤/降权。
- **隐私脱敏（PII）**：识别并屏蔽身份证号、电话、邮箱、银行卡等个人信息。

**关键 trade-off（来自 BLOOM 经验，务必记住）**：

```
   过滤掉有害数据  ──► 模型「不会说脏话」↑   但「识别有害内容」能力 ↓
   保留有害数据    ──► 模型「能识别有害」↑   但自己也可能「学会输出有害」↑
```

> 即「有害信息生成」与「有害信息鉴别」难以两全。实践常做法：预训练阶段适度过滤保安全，把更精细的安全行为留给后续对齐（SFT/RLHF）。同时：**低质量过滤能提升下游任务表现，但过度去毒反而损伤鉴别能力**。

### 3.4 一条容易忽略的规律：数据「时效性」

预训练数据的**来源时间**与下游任务时间越接近，模型表现越好。**数据过时**有负面影响，**过于超前**也会（分布漂移）。所以语料要定期「换新血」。

## 4. Token 配比（Domain Mixture）

不是把所有数据一锅烩，而是**给每个领域设权重**，决定它在最终训练中占多少 token（或被重复采样多少次）。

```
 最终训练 token 构成（示意 LLaMA 风格）
 网页(CC+C4) ████████████████  ~82%  ← 量大、覆盖广，但单位营养低
 代码        ███                ~4.5% ← 提升推理，权重虽小但关键
 书籍        ██                 ~4.5% ← 长程逻辑
 百科        ██                 ~4.5% ← 事实知识
 论文/问答   █                  ~4.5% ← 专业/对话
```

配比的两个核心操作：

- **上采样（upsample）**：高质量但量小的数据（维基、书籍）重复多遍，提高它的「话语权」。例：维基重复 ~3 遍。
- **下采样（downsample）**：量大质低的网页，只取一部分，避免「网页噪声淹没好数据」。

**为什么配比这么重要？**
同样的算力预算（总 token 数固定），把 5% 的预算从「随机网页」换成「代码」，模型的代码/推理能力可能显著提升——这就是「配方」的价值。配比通常靠**小模型扫描实验**（scaling 小跑）来调，再放大到大模型。

经验要点（来自 BLOOM 等）：**数据多样性很重要，涉及领域越丰富越好**。

## 5. 规模与 Scaling（要多少数据？）

### 5.1 Scaling Law 直觉

模型 loss 随**参数量 $N$、数据量 $D$（token）、算力 $C$** 平滑下降，近似幂律：

$$L(N, D) \approx L_\infty + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}$$

含义：单方面堆参数或堆数据都会**边际递减**，必须**协同放大**。

### 5.2 Chinchilla 法则（计算最优）

DeepMind Chinchilla 的关键发现：在固定算力下，**参数量和数据量应同比例增长**，经验最优比例约：

$$D \approx 20 \times N \quad(\text{每个参数约配 20 个训练 token})$$

- 一个 **70B** 模型，计算最优数据量 ≈ $70\text{B} \times 20 = \mathbf{1.4T}$ token（正是 Chinchilla 的配置）。
- 反例：GPT-3（175B）只训了 ~300B token，按此法则**严重「欠喂数据」**——参数太多、数据太少。

### 5.3 推理最优：超 Chinchilla 训练

LLaMA 的思路：模型部署后要被**调用无数次**，推理成本远大于训练成本。所以**故意多喂数据**（远超 20×），把模型「训得更透」，换取更小、更省、推理更快的模型。

- LLaMA-1 7B 训了 **1T** token（≈ 143× 参数）；65B 训了 **1.4T**。
- 现代趋势：7B 级模型训到 **2T~15T** token 已是常态。

```
 计算最优 (Chinchilla)        推理最优 (LLaMA 及之后)
   N 大、D=20N                  N 小、D >> 20N
   训练省，但模型大、推理贵      训练贵，但模型小、推理省
   ──────────────────►  实践偏向右侧（部署成本主导）
```

### 5.4 数据不够怎么办？重复（multi-epoch）

优质数据有限时，可重复训练（多 epoch）。经验结论：**重复约 4 次以内**，效果接近「全新数据」；重复太多（如 >16 次）则收益骤减甚至记忆退化。所以「再多搞点新数据」通常优于「反复刷旧数据」。

## 6. 业界实例（真实配方）

### 6.1 OPT-175B（Meta）

Meta 希望在尽可能大的语料上训练，由 5 个过滤后的文本数据集并集组成：

- **BookCorpus**：超过 10K 本未出版书籍。
- **CC-Stories**：CommonCrawl 子集，过滤成 Winograd 故事风格。
- **The Pile**：含 Pile-CC、OpenWebText2、USPTO、Project Gutenberg、OpenSubtitles、Wikipedia、DM Mathematics、HackerNews 等。
- **Pushshift.io Reddit**（Baumgartner 等开发，Roller 等处理）。
- **CCNewsV2**：RoBERTa 用的 CommonCrawl 新闻数据集英文部分的更新版。

最终：**约 180B token，对应 800GB 数据**；验证集为 200MB，按各子集大小**按比例采样**。注意：数据含公共 CC 与 Reddit 子集，**可能包含令人反感的内容**（侮辱/威胁性句子），这是直接用公网数据的固有风险。

### 6.2 BLOOM-176B（BigScience）

- **41.5TB** 经大量去重和清洗的文本 → 最终 **350B token**。
- **46 种自然语言 + 13 种编程语言**（强多语言）。
- 词表 **250,680** 个 token（多语言需要大词表）。
- 经验总结（前文已展开）：多样性重要；有害信息生成/鉴别难两全；低质过滤提升鉴别与下游表现，去毒过度反伤鉴别；数据时效性影响表现。

### 6.3 LLaMA（Meta，开源配方范本）

- LLaMA-1 用**全公开数据**复现，约 **1.0T~1.4T token**；配比即 §2.4 的七子集。
- 影响：直接催生 RedPajama 复现、Alpaca/Vicuna 等微调生态，是开源大模型的「数据宪法」。

## 数值例子 / 手算

**例 1：字节 ↔ token 换算（英文）**
经验：1 token ≈ 4 字符。800GB ≈ $800 \times 10^9$ 字符。
$$\frac{800\times10^9}{4} = 2\times10^{11} = 200\text{B token (粗估)}$$
与 OPT 的「800GB ≈ 180B token」量级一致（差异来自空格/多字节/分词器）。

**例 2：Chinchilla 最优数据量**
模型 $N = 13\text{B}$，按 $D = 20N$：
$$D = 20 \times 13\text{B} = 260\text{B token}$$
若只想「推理最优」训到 10×Chinchilla，则需 **2.6T token**。

**例 3：去重砍掉多少？**
原始 CC 抽取出 1000B token，精确去重删 15%，模糊去重再删 25%（对剩余）：
$$1000 \times (1-0.15) = 850\text{B} \xrightarrow{\times(1-0.25)} 637.5\text{B token}$$
即约 **64%** 留存，符合「CC 清洗后大量缩水」的经验。

**例 4：上采样配比**
维基 5B token 想占最终语料 4.5%。若总语料 1000B：
$$\text{目标 token} = 1000 \times 4.5\% = 45\text{B}$$
$$\text{需重复} = 45 / 5 = 9 \text{ 遍}$$
（实践会控制在 ~4 遍内，否则改为减小总量或换更高目标占比的策略。）

**例 5：训练 token 数 ↔ 算力（呼应 [[llm-algo/FLOPs]]）**
经典近似：$C \approx 6 \times N \times D$（FLOPs）。
$N=7\text{B}$、$D=1\text{T}$：
$$C \approx 6 \times 7\times10^9 \times 1\times10^{12} = 4.2\times10^{22}\ \text{FLOPs}$$
这把「数据规模」直接换算成「算力账单」——数据越多，FLOPs 线性上涨。

## 常见问题

| 问题 | 速答 |
|------|------|
| CC 能直接拿来训吗？ | 不能，太脏，必须去重+过滤+去毒，通常只留 1%~10%。 |
| 去重为什么这么重要？ | 防过拟合、省算力、避免评测泄漏；去重后同算力效果更好。 |
| 精确去重和模糊去重区别？ | 精确=完全相同删；模糊=MinHash/SimHash 判相似删（抓「改一个字」的转载）。 |
| 代码占比不高，为什么还要加？ | 代码逻辑强，显著提升推理/链式思考，性价比高。 |
| 数据越多越好吗？ | 在算力允许下基本是；但 Chinchilla 说要与参数同比例放大，欠喂/欠参数都浪费。 |
| 优质数据不够怎么办？ | 重复训练（≤4 epoch 接近新数据），或上采样高质量子集。 |
| 去毒越狠越好吗？ | 不是。过度去毒会削弱模型「识别有害内容」的能力，是 trade-off。 |
| 配比怎么定？ | 小模型扫描实验调 mixture，再放大到大模型。 |
| 中文语料难在哪？ | 高质量公开数据少、垃圾站多、繁简/编码混乱，清洗与去重权重更高。 |
| 数据时效重要吗？ | 重要。来源时间与下游任务越接近越好，过时和过于超前都有害。 |
