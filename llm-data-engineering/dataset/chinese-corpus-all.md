## 0. 一句话锚点

**中文预训练语料 = 把海量中文文本，洗成"干净、不重复、编码统一、质量可控"的 token 流，再按合理比例和英文/代码混合，喂给大模型学语言。**

一句话记忆：**找料 → 洗料 → 去重 → 统一编码 → 评质量 → 配比 → 混合**。

## 1. 地基：什么是"语料"，中文为什么特殊

### 1.1 语料 / corpus 是什么

- **语料（corpus）**：一大堆文本的集合。预训练阶段模型不需要标注（label），只需要"通顺的人类文本"，让模型做 **下一个 token 预测**（next-token prediction）。
- **token**：模型看到的不是"字"也不是"词"，而是 **分词器（tokenizer，通常是 BPE/BBPE）** 切出来的"子词单元"。模型规模常用 **token 数** 衡量，而不是字节数或字数。

```
原始网页 ──抽正文──► 纯文本 ──清洗去重──► 干净文本 ──tokenizer──► token 流 ──► 模型
 (HTML)              (string)            (string)              ([2031, 845, ...])
```

### 1.2 中文为什么"特殊"——三个底层差异

1. **没有空格分词**。英文 `the cat sat` 天然用空格切；中文"今天天气不错"是连续的。对 BPE 影响巨大：一个汉字在 UTF-8 里是 **3 个字节**，BBPE（byte-level BPE）先在字节上学合并，所以**一个常用汉字往往占 1 个 token，生僻字可能 2~3 个 token**。
   - 经验值（约，以具体 tokenizer 为准）：**1 个汉字 ≈ 0.6~1.0 token**；**1 个英文单词 ≈ 1.3 token**。
2. **繁简 + 多种编码并存**。同一个意思有"简体/繁体"，历史网页有 GBK/GB2312/Big5/UTF-8 多种编码，乱码风险高。
3. **网页质量噪声大**。中文互联网充斥广告、SEO 垃圾、内容农场、复制粘贴文章，**去重和质量过滤的收益比英文更大**。

> 直觉：英文语料"开箱即用"程度高；中文语料更像"毛矿石"，**清洗+去重的工程量是中文 corpus 的核心成本**。

## 3. 数据流水线总览（先看全景）

```
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 1.采集    │→ │ 2.抽正文  │→ │ 3.语言识别│→ │ 4.清洗    │→ │ 5.去重    │→ │ 6.质量过滤│
│ CC/网页   │  │ HTML→text│  │ 中文?    │  │ 启发式    │  │ 精确+模糊 │  │ 分类器/PPL│
└──────────┘  └──────────┘  └────┬─────┘  └──────────┘  └──────────┘  └────┬─────┘
                                 │丢非中文                                  │
                                 ▼                                          ▼
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐         ┌────────────────────┐
│ 9.混合    │← │ 8.配比    │← │ 7.编码繁简│← │ PII/有害  │ ◄──────│ 干净中文文本(shard)│
│ 中英代码  │  │ 上/下采样 │  │ UTF-8统一 │  │ 过滤      │         └────────────────────┘
└────┬─────┘  └──────────┘  └──────────┘  └──────────┘
     ▼
  tokenizer → token 流 → 训练
```

记住顺序的"为什么"：
- **先抽正文再识别语言**：HTML 里全是标签，先抽出正文（如 trafilatura/justext 思路）再判断中英。
- **先清洗再去重**：去重很贵（要算指纹），先用便宜的启发式扔掉明显垃圾，能省大量算力。
- **去重要早于质量分类器**：重复样本会污染分类器的统计，也浪费打分算力。
- **编码繁简放在文本已经"是中文"之后**：避免对乱码做无意义的转换。

## 4. 清洗（Cleaning）：把"毛文本"修干净

清洗 = 用一堆**便宜、可解释的规则（启发式 heuristics）** 先扔掉明显垃圾，再用**模型打分**做细筛。

### 4.1 启发式过滤（便宜、先做）

```
一段文本 ──► [ 规则闸门 ] ──► 通过 / 丢弃
              ├─ 长度太短（<N 字）           → 丢
              ├─ 中文字符占比过低            → 丢（疑似乱码/外文/代码）
              ├─ 标点/数字/符号占比过高      → 丢（表格残渣、目录）
              ├─ 重复行比例过高              → 丢（导航栏、版权footer）
              ├─ 含大量"乱码替换符" �        → 丢（编码坏掉）
              ├─ 黑名单域名/敏感词模板        → 丢（赌博/色情/SEO农场）
              └─ 困惑度异常高/低             → 标记
```

几个**中文特有**的判定信号（含义优先，阈值"按数据调"）：
- **中文字符占比**：统计落在 CJK Unicode 区间（如 `一-鿿`）的字符比例，太低说明不是有效中文正文。
- **"的/了/是/在"等高频虚词命中率**：真正的中文句子几乎一定带这些；缺失常意味着关键词堆砌（SEO 垃圾）。
- **行级去模板**：网页页眉页脚、"上一篇/下一篇""版权所有"等，按行频率剔除。

### 4.2 质量分类器（贵一点、后做）

- **思路**：训练一个二分类器，正例 = 高质量文本（如维基、书籍、人审过的网页），负例 = 随机网页。给每段打"像不像高质量文本"的分。
- **常见实现**：fastText 轻量分类器（快）或更强的小模型；CCNet 用 **语言模型困惑度（perplexity）** 对维基训的 KenLM 打分，**困惑度低=更像规范文本**。

$$\text{PPL}(x)=\exp\!\Big(-\frac{1}{N}\sum_{i=1}^{N}\log p(x_i\mid x_{<i})\Big)$$

- $N$=token 数，$p$=语言模型给的概率。PPL 越低，文本越"被模型预测得出来"，通常越规范（但**过低也可能是模板化/重复**，要配合去重）。

> 权衡：启发式**召回高、精度糙**；分类器**精度高、成本高**。实践是**先粗后细**，让贵的步骤只处理少量数据。

## 5. 去重（Deduplication）：删掉重复，收益最大的一步

为什么去重对中文尤其重要：中文互联网**洗稿、转载、内容农场**严重，同一篇文章可能出现成百上千次。**重复样本会让模型记忆而非泛化，还浪费算力。** 研究普遍表明：去重能显著降低记忆、提升等量算力下的效果。

### 5.1 三个层级

```
精确去重(exact)        模糊去重(near-dup)        子串去重(substring)
   │                       │                          │
按文档哈希完全相同      MinHash+LSH 找"相似文档"   后缀数组找长重复片段
   │                       │                          │
   ▼                       ▼                          ▼
SHA1(doc) 相同→删一个   Jaccard相似度>阈值→删       重复的长段落整段切掉
便宜、抓"完全复制"      抓"改了几个字的洗稿"        抓"跨文档共享的样板段"
```

### 5.2 模糊去重的核心：MinHash + LSH（一步步讲）

目标：在亿级文档里，快速找出"内容高度相似"的文档对。直接两两比是 $O(n^2)$，不可行。

1. **Shingling（切片）**：把文档切成 k 个连续 token 的集合（k-shingle）。中文常按字或词切。
2. **Jaccard 相似度**：两个集合 $A,B$ 的相似度

$$J(A,B)=\frac{|A\cap B|}{|A\cup B|}$$

3. **MinHash**：用多个哈希函数取每个集合的最小哈希值，组成"签名（signature）"。关键性质：

$$\Pr[\,\text{minhash}_h(A)=\text{minhash}_h(B)\,]=J(A,B)$$

   于是用"签名相等的比例"就能**无偏估计** Jaccard，且签名很短（如 128 个哈希）。
4. **LSH（局部敏感哈希）**：把签名分成若干 band，只要某个 band 完全相同就当作"候选相似对"。让相似文档以高概率落进同一个桶，**把比较量从全量降到候选对**。

```
doc → shingles → MinHash签名(128维) → 切成 b 个band
                                          │
                                          ▼ 同一band哈希相同 → 进同一桶
                              桶内才两两算 Jaccard → 超阈值则判重复
```

- **关键参数权衡**：band 数 b、每 band 行数 r。$b\cdot r=$ 签名长度。**b 大→召回高（更激进去重，可能误删）；r 大→精度高（更保守，可能漏删）。** 相似度阈值 $s$ 与 $(b,r)$ 的 S 曲线大致满足 $1-(1-s^{r})^{b}$。

### 5.3 实践要点

- **先精确去重再模糊去重**：精确去重便宜，先把"完全复制"清掉。
- **去重粒度**：文档级（删整篇）vs 段落/行级（删重复段）。中文页脚、免责声明适合行级去重。
- **跨数据集去重**：CC、WuDao、维基之间也会重复，**合并后要再做一次全局去重**，否则上采样维基时会把重复放大。
- 工具方向：Google 的 `text-dedup` 思路、`datatrove`、`dolma` 等流水线都内置 MinHash 去重（**具体参数以官方文档为准**）。

## 6. 繁简与编码：中文的"隐形地雷"

### 6.1 编码（encoding）——先把字节读对

- **问题**：老中文网页可能是 **GBK / GB2312 / GB18030 / Big5（繁体）/ UTF-8**。读错编码 → 满屏乱码 `锟斤拷` / `�`。
- **流程**：用编码探测（如 `chardet`/`charset-normalizer`）猜编码 → 统一 **decode 成 Unicode** → 统一 **encode 成 UTF-8**。

```
原始字节 ──探测编码──► 解码为 Unicode ──► 统一 UTF-8 ──► 后续处理
 (bytes)   chardet        (str)            (bytes)
   │
   └─ 探测失败/含大量 � → 直接丢弃（编码已坏，救不回来）
```

- **常见乱码信号**：
  - `锟斤拷`：UTF-8 被当 GBK 反复转码的经典产物。
  - `�`（U+FFFD 替换符）：解码失败占位；**占比高就丢**。

### 6.2 Unicode 归一化（normalization）——同形不同码

- **NFKC 归一化**：把"看起来一样但码不同"的字符统一。例如全角 `１２３Ａ` → 半角 `123A`，兼容字符 → 标准字符。**统一后能减少 tokenizer 的碎片化和无意义重复。**
- 注意别"过度归一化"：有些场景（如保留全角标点的风格）需要权衡，**按训练目标决定**。

### 6.3 繁简转换（traditional ↔ simplified）

- **工具**：**OpenCC** 是事实标准。它不仅做字符映射，还能做**词汇级**转换（如 台湾"滑鼠" ↔ 大陆"鼠标"），有多种配置（`t2s` 繁转简、`s2t` 简转繁、`t2tw`、`s2twp` 含词汇）。
- **策略选择**（看你训什么模型）：
  - **统一为简体**：简化分布、利于简体下游任务；但**丢失繁体能力**。
  - **保留繁简共存**：模型同时学繁简；**词表更大、需要更多数据覆盖**。
  - **折中**：主语料简体为主，**额外保留一部分高质量繁体**（港台维基、书籍），保住繁体能力。

```
繁体文本 ──OpenCC t2s──► 简体文本
   │                        │
   └── 想保留繁体能力？ ──► 不转，单独成一路语料，配比里给小权重
```

> 一个易错点：**繁简转换要在去重"之后"还是"之前"？** 若先转简体，繁/简两份"同一文章"会变成完全相同 → 利于精确去重抓到；但也可能把本应保留的繁体多样性抹掉。常见做法：**去重用归一化后的文本算指纹，但保留原文用于训练**（指纹归一化 ≠ 训练文本归一化）。

## 7. 质量评估：怎么知道洗得好不好

```
              质量评估三件套
   ┌──────────────┬──────────────┬──────────────┐
   │ 1.规则统计    │ 2.模型打分    │ 3.人工抽检    │
   ├──────────────┼──────────────┼──────────────┤
   │ 中文字占比    │ 困惑度PPL     │ 随机抽N条     │
   │ 平均句长      │ 质量分类器分  │ 人读"像不像   │
   │ 重复率        │ (高质量概率)  │  正常文章"    │
   │ �占比/黑词率  │               │ 标注good/bad  │
   └──────────────┴──────────────┴──────────────┘
        便宜、可批量          中等            最准、最慢
```

- **不要只看单一指标**：低 PPL 可能是模板化垃圾；高中文占比也可能是关键词堆砌。**多信号交叉。**
- **下游验证才是金标准**：最终用"训出来的小模型在中文评测（如 C-Eval/CMMLU 等）上的表现"反推数据质量，比任何离线指标都可信。
- **保留可追溯性**：每条样本记下来源、清洗规则命中情况，便于回溯"哪批数据拉低了效果"。

## 8. 配比与中英混合：决定模型"性格"的旋钮

### 8.1 为什么要配比

- 不同语料**量级悬殊**：CC 几个 TB，维基几个 GB。若按原始比例直接混，**维基会被淹没**；若过度上采样维基，又会**重复记忆**。
- **配比（sampling weight / mixture）= 决定每个数据源被采样到的概率**。这是预训练里最影响"模型能力分布"的超参之一。

### 8.2 上采样 / 下采样

```
原始体量              训练中的"有效占比"（按权重重采样）
CC中文  ████████████  → ████████      （下采样，因为脏且冗余）
维基    █             → ██            （上采样，因为质量高但量小）
书籍    ██            → ███           （上采样，长文本、连贯性好）
代码    ███           → ███           （保持，帮助推理）
英文    ███████       → ██████        （混入，提升通用/推理能力）
```

- **上采样（oversample）**：重复使用高质量小语料（维基、书籍）。**但重复 epoch 过多会过拟合/记忆**，一般控制重复次数。
- **下采样（downsample）**：对量大质糙的 CC 取子集。

### 8.3 中英（及代码）混合——为什么要混

- **纯中文不够**：高质量推理、代码、STEM 文本，英文世界存量大得多。**混入英文+代码能显著提升推理与代码能力**，再迁移回中文。
- **典型权衡**：
  - 中文占比太低 → 中文表达、本土知识弱。
  - 中文占比太高 → 通用推理、代码、世界知识弱。
- 不存在唯一正确比例，**取决于目标**（偏中文产品 vs 通用大模型）。很多中文向模型会让**中文占比偏高但仍保留可观英文+代码**。

### 8.4 配比的两种确定方式

1. **拍脑袋 + 小规模消融**：定几组配比，各训一个小模型，看下游评测，选最好的（可靠但贵）。
2. **数据混合优化（如 DoReMi 思路）**：用代理模型自动学各域权重，**让被"学得差"的域获得更高权重**。方向性强，**实现细节以原论文/官方为准**。

> 工程提醒：配比不是"一刀切到底"。可以做**课程（curriculum）**——早期多铺量，后期切高质量小语料"收尾"，或在退火（annealing）阶段提高优质中文/代码比例。

## 9. 数值例子 / 对照 / 实践

### 9.1 手算：100GB 中文原始文本 ≈ 多少 token

设：UTF-8 下**1 个汉字 = 3 字节**，文本里中文占比 ~90%，其余符号忽略简化。
- 字符数：$\dfrac{100\times 10^9\ \text{B}}{3\ \text{B/字}}\approx 3.3\times10^{10}$ 个汉字 ≈ **330 亿字**。
- 取 **1 字 ≈ 0.7 token**（BBPE 经验值，约）：$3.3\times10^{10}\times0.7\approx 2.3\times10^{10}$ → **约 230 亿 token**。

> 直觉刻度（约）：**100GB 中文 ≈ 200~300 亿 token**。要训"几 T token"的模型，光中文得攒到 **TB 级原始文本**。

### 9.2 手算：去重能扔掉多少

假设 CC 中文原始 1.0 TB，经验上：
- 精确去重去掉 ~**20%**（完全转载） → 剩 0.80 TB
- 模糊去重再去 ~**30%**（洗稿/近重复） → 剩 0.56 TB

$$1.0\times(1-0.20)\times(1-0.30)=0.56\ \text{TB}$$

**约一半被去重清掉**——这正是"去重是性价比最高一步"的来源（数值随快照、阈值大幅波动，**仅示意**）。

### 9.3 配比小例（示意，非推荐值）

| 数据源 | 原始体量 | 采样权重 | 有效 token 占比 |
|--------|---------|---------|----------------|
| 中文 CC（清洗后） | 大 | 下采样 | ~35% |
| 英文 CC/网页 | 大 | 下采样 | ~30% |
| 中文维基/百科 | 小 | 上采样×K | ~6% |
| 书籍（中+英） | 中 | 上采样 | ~12% |
| 代码 | 中 | 保持 | ~12% |
| 学术/问答 | 小 | 上采样 | ~5% |

> 数字仅演示"如何思考配比"，**真实比例需消融，以你的目标和评测为准**。

### 9.4 对照：常见工具 / 步骤定位

| 步骤 | 代表工具/方法（方向，以官方为准） | 解决什么 |
|------|----------------------------------|---------|
| 抽正文 | trafilatura / justext / boilerpipe 思路 | HTML→正文 |
| 语言识别 | fastText langid / CLD | 筛中文 |
| 编码 | chardet / charset-normalizer | 字节→Unicode |
| 归一化 | NFKC（unicodedata） | 全半角/兼容字符统一 |
| 繁简 | **OpenCC** | 繁⇄简 |
| 清洗规则 | C4/Gopher 规则的中文化改造 | 启发式过滤 |
| 质量分类 | fastText 分类器 / KenLM PPL（CCNet 思路） | 高质量筛选 |
| 去重 | MinHash+LSH（datatrove/dolma/text-dedup） | 删重复 |
| 配比 | 手工消融 / DoReMi 思路 | 各域权重 |

### 9.5 实践 checklist（落地时照着走）

```
[ ] 先抽正文，再判语言（别在 HTML 上判中文）
[ ] 编码统一 UTF-8；� 占比高的整篇丢
[ ] NFKC 归一化（全/半角统一）
[ ] 繁简策略想清楚：统一简体？还是保留繁体一路？
[ ] 启发式过滤在前（便宜），分类器在后（贵）
[ ] 精确去重 → 模糊去重(MinHash+LSH)，跨数据集再全局去重
[ ] 维基/书籍上采样，但限制重复次数，防记忆
[ ] 混入英文+代码，定几组配比做小模型消融
[ ] 用中文评测(C-Eval/CMMLU 等)反推数据质量
[ ] 全程留来源元数据，便于回溯坏批次
```

## 常见问题

| 问题 | 回答 |
|------|------|
| 中文为什么去重收益比英文大？ | 中文互联网洗稿、转载、内容农场极多，近重复比例高，去重后等量算力效果提升更明显。 |
| 1 个汉字几个 token？ | BBPE 下常用字约 1 token，生僻字 2~3 token；经验 1 字≈0.6~1.0 token，**以具体 tokenizer 为准**。 |
| 全转简体好不好？ | 简化分布、利下游简体任务，但丢繁体能力。想保留繁体就单列一路语料给小权重。 |
| MinHash 的 b、r 怎么调？ | b 大更激进（召回高、可能误删）；r 大更保守（精度高、可能漏删），按可接受的去重力度调。 |
| 困惑度低就一定好吗？ | 不一定。模板化/重复文本 PPL 也低，要配合去重和多信号判断。 |
| 中英怎么配比？ | 没有唯一答案，取决目标；偏中文产品中文占比偏高，但仍混入可观英文+代码提推理。需消融。 |
| `锟斤拷` 是什么？ | UTF-8 被反复错当 GBK 转码的经典乱码，出现即说明编码处理出错，整篇建议丢弃。 |
| 去重和繁简转换谁先谁后？ | 常用归一化后的文本算去重指纹，但训练保留原文；避免把繁体多样性误删。 |
