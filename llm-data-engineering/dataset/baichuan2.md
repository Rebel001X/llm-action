## 0. 一句话锚点

**Baichuan2 的数据工程 = 把「网页、书籍、论文、代码」等多源原始语料，经过「频率维度的聚类去重打分」和「质量维度的句级 + 安全过滤」，再按精心设计的「采样配比」混合成 ~2.6T tokens 的高质量预训练数据集。** 它的核心思想是：**数据的质量与配比，比单纯堆数据量更决定模型上限**。

> 重要前提：本文讲的是 Baichuan2 技术报告所披露的**机制与方法论**。报告并未公开「过滤后各类数据的精确采样比例 / 分布数值 / 去重阈值」，凡涉及确切数字处一律标注「具体以官方技术报告/源码为准」，不臆造。

## 1. 地基：预训练数据工程到底解决什么问题

大模型的能力本质来自「在海量 token 上做 next-token 预测」。但原始互联网语料有几个致命问题，数据工程就是为它们而生：

- **GIGO（Garbage In, Garbage Out）**：网页里充斥乱码、模板噪声、广告、导航栏、机器翻译垃圾。低质 token 会稀释有效梯度信号，甚至教坏模型。
- **重复（Duplication）**：互联网上同一篇文章被无数站点转载。重复样本会让模型**过拟合记忆**而非学习泛化，还浪费算力。研究普遍发现：去重能显著提升下游效果并降低记忆/泄漏风险。
- **分布失衡（长尾与配比）**：直接按互联网自然分布，会让低质网页淹没高价值的书籍/论文/代码。需要**人为调整配比**，把高价值数据「上采样」。
- **安全与合规**：暴力、色情、仇恨、隐私（PII）等有害内容必须在源头过滤，否则会被模型习得并在生成时复现。

一句话：**数据工程 = 在「量、质、配比、安全」四个维度上做权衡，把原始语料炼成对模型最有营养的训练集。**

```
   原始互联网语料(脏、重、偏、险)
            │
            ▼  数据工程四件事
   ┌────────┴────────┐
   │ 量   质   配比   安全 │
   └────────┬────────┘
            ▼
   高质量预训练数据集 → 喂给模型 → 决定能力上限
```

## 2. Baichuan2 数据管线全景

Baichuan2 技术报告把数据处理聚焦在两条主线：**数据频率（frequency）** 与 **数据质量（quality）**。整体管线可抽象为下图：

```
┌──────────────────────────────────────────────────────────────┐
│                    Baichuan2 预训练数据管线                      │
└──────────────────────────────────────────────────────────────┘

 (1) 多源采集 Collection
   网页 │ 书籍 │ 研究论文 │ 代码 │ ...
        └──────┬──────┘
               ▼
 (2) 清洗 Cleaning ───────────────┐
   ┌───────────────┐  ┌───────────────┐
   │  频率维 Frequency │  │  质量维 Quality  │
   │  • LSH-like 近重检测│  │  • 句级质量过滤   │
   │  • Embedding 聚类  │  │  • 安全/有害过滤   │
   │  • 簇内文档/段/句去重│  │  (暴力/色情/歧视/  │
   │  • 打分(供采样用)  │  │   仇恨言论等)     │
   └───────┬───────┘  └───────┬───────┘
           └─────────┬─────────┘
                     ▼
 (3) 采样 Sampling
   依据打分 + 配比策略，对各源/各簇做加权采样
                     ▼
 (4) ~2.6T tokens 预训练数据集
   (Baichuan2-7B / 13B 在此之上训练)
```

要点：**去重发生在「文档 / 段落 / 句子」三种粒度**，并且每个聚类簇会被打分，分值最终用于**数据采样**——这是 Baichuan2 数据处理的一个标志性设计：去重不是简单丢弃，而是「聚类 + 打分 + 加权采样」。

## 3. 多源采集与数据分布

为保证**全面性与代表性**，Baichuan2 从多个来源采集，包括但不限于：

| 数据源 | 为什么需要它 | 典型贡献的能力 |
|--------|-------------|----------------|
| 网页（Web） | 量大、覆盖广、时效性 | 世界知识、口语化表达 |
| 书籍（Books） | 长文本、逻辑连贯、高质量 | 长程依赖、深度知识、写作 |
| 研究论文（Papers） | 专业、严谨、术语密集 | 学术/推理/专业领域能力 |
| 代码（Code） | 结构化、强逻辑 | 代码生成、推理、formal 思维 |
| 其他（垂域等） | 补齐特定领域 | 如医疗、法律等垂域表现 |

> ⚠️ 报告未公开**过滤后**各类别的精确采样比例与分布数值。但可从结果反推一些倾向（属合理推测，非官方数字）：Baichuan2 在医疗、法律等垂域表现较好，说明这些**垂域数据占比不会太低**；书籍与论文本身质量高，**采样率可能也偏高**。具体配比以官方技术报告为准。

```
        多源 → 单一统一格式
  Web ─┐
 Book ─┤
Paper ─┼──► 归一化(去模板/抽正文/编码统一) ──► 进入清洗
 Code ─┤
其他 ─┘
```

采集后的第一步通常是**归一化**：抽取正文、去除 HTML 模板/导航/广告、统一编码（如统一为 UTF-8）、语言识别与分流。这一步把异构来源拉齐成统一文本，后续清洗才能批量进行。

## 4. 频率维度：聚类 + 多粒度去重 + 打分

这是 Baichuan2 数据处理「数据频率」分支的核心。目标是**识别并稀释重复内容**，但保留有用的高频信号。

**机制拆解（自底向上）：**

1. **相似度检测（LSH-like）**
   - LSH = Locality-Sensitive Hashing（局部敏感哈希）。它的本质是：把文本映射成指纹（如 MinHash / SimHash 签名），**让相似文本以高概率落进同一个桶**，从而把「两两 O(N²) 比对」降为近线性，可在 T 级语料上做近重（near-duplicate）检测。
   - 「LSH-like」表示用的是这一类思想的方法（指纹 + 分桶），具体实现细节以官方为准。

2. **Embedding 特征聚类**
   - 用向量表示（Embedding）刻画语义相似度，对文档做聚类。LSH 抓「字面近重」，Embedding 抓「语义近重」，两者互补。

3. **多粒度去重**
   - 在每个聚类**簇（cluster）** 内，对**文档 / 段落 / 句子**三种粒度分别去重。粒度越细，能去掉「整篇不重复但句子大量重复」的隐性冗余。

4. **簇打分 → 用于采样**
   - 每个簇会被**打分**，分值不直接决定丢弃，而是**作为最终数据采样的权重**。高频且低价值的簇可被下采样，稀有但有价值的内容得以保留。

```
        T 级语料
           │
   ┌───────▼────────┐
   │ LSH-like 指纹分桶 │ (字面近重，O(N) 量级)
   └───────┬────────┘
           ▼
   ┌────────────────┐
   │ Embedding 语义聚类 │ (语义近重)
   └───────┬────────┘
           ▼  对每个簇:
   ┌──────────────────────────┐
   │ 文档级 ┐                   │
   │ 段落级 ├─ 去重(保留代表样本)  │
   │ 句子级 ┘                   │
   │ + 簇打分 score ───────────┐ │
   └────────────────────────│─┘
                            ▼
                  采样阶段按 score 加权
```

> 数值直觉（示意，非官方数字）：若某条新闻被 500 个站点转载，朴素做法会让模型见到 500 次几乎相同的文本；经簇去重+打分加权后，等效曝光被压到接近 1 次量级，既防过拟合记忆又省算力。

## 5. 质量维度：句级过滤 + 安全过滤

这是「数据质量」分支。Baichuan2 报告提到做了**句子级别的质量过滤**，但**未公开明确的过滤规则**。结合业界通行做法，这一类过滤通常包含：

- **启发式规则过滤**：句长异常、标点/特殊符号占比过高、重复字符、停用词比例异常、明显乱码等。
- **困惑度（PPL）/语言模型打分**：用一个小语言模型给文本打分，过滤掉「读起来不通顺」的低质文本（$\text{PPL} = \exp\left(-\frac{1}{N}\sum_{i=1}^{N}\log p(x_i)\right)$，PPL 越高越不通顺）。
- **语言/字符占比过滤**：剔除目标语言占比过低的文本。

**安全过滤（报告明确提及）**：从 Baichuan2 的「模型安全」部分可推知，预训练阶段对数据做了**有害内容过滤**，包括：**暴力、色情、种族歧视、仇恨言论**等；报告原文用「等（etc.）」措辞，说明实际过滤范围**应不止这几类**（很可能还含隐私 PII、政治敏感、违法等）。

```
   清洗后文档
       │
       ▼  句级质量过滤
  ┌──────────────┐
  │ 规则启发式      │ 长度/符号/重复…
  │ PPL/LM 打分    │ 通顺度
  │ 语言/字符占比   │ 语种纯度
  └──────┬───────┘
         ▼  安全过滤(分类器/词表/模型)
  ┌──────────────┐
  │ 暴力 色情      │
  │ 种族歧视 仇恨  │  ← 命中即剔除/降权
  │ …(还有更多)   │
  └──────┬───────┘
         ▼
   保留的高质 + 安全文本
```

> ⚠️ 「句子级质量过滤的明确规则」报告未公开；上面是该类任务的通行机制，**具体规则以官方技术报告/源码为准**。

## 6. 采样配比的权衡（数据混合 Data Mixing）

去重打分和质量过滤只是「筛」，最终喂给模型前还要**混合配比（mixing）**。这是数据工程中最影响效果、也最依赖经验的一步。

核心权衡：

- **上采样高价值源**：书籍、论文、代码等高质量源，往往按超过其「自然占比」的比例采样，让模型多学。
- **下采样冗余源**：网页等量大但噪声多，结合簇打分做加权下采样。
- **垂域补强**：为提升医疗/法律等垂域，需保证相应数据有足够曝光。
- **温度采样的思想**：多语种/多源混合时常用「温度」$\tau$ 调节配比的「尖锐/平滑」，$p_i \propto q_i^{1/\tau}$。$\tau>1$ 会拉平差距（让小源被更多采样），$\tau\to 1$ 接近自然分布。（Baichuan2 是否采用此式以官方为准，此处仅说明该类机制。）

```
   各源(去重打分后)
   Web   Book  Paper  Code  垂域
    │     │     │      │     │
    ▼     ▼     ▼      ▼     ▼   ← 各自配比权重 w_i
  ┌────────────────────────────┐
  │  加权混合 + shuffle          │
  └─────────────┬──────────────┘
                ▼
      训练数据流 (~2.6T tokens)
```

## 7. 数据与分词器 / 模型的耦合

数据工程不止「准备文本」，它和分词器、模型是耦合的：

- **分词器（Tokenizer）**：Baichuan2 使用 BPE（Byte-Pair Encoding）类分词，并扩大词表以**对中文更友好**（更高的中文压缩率 → 同样 token 预算下能塞进更多中文信息）。词表与训练数据分布需匹配。
- **数据量 ↔ 模型规模**：~2.6T tokens 对应 7B/13B 量级模型，呼应「数据量需与参数量匹配（Scaling Laws）」的直觉——数据太少则模型欠训，配比失衡则能力偏科。
- **下游对齐数据**：本文讲的是**预训练**数据；SFT / RLHF 阶段另有独立的指令与偏好数据管线（见 `sft-dataset`、[[llm-alignment/RLHF]]）。

## 端到端流程示例：一条网页文档的命运

```
[原始 HTML 网页]
   │ 1. 抽正文 + 去模板/广告 + UTF-8 归一 + 语言识别
   ▼
[纯文本文档]
   │ 2. LSH-like 指纹 → 分到某个桶
   ▼
[进入候选簇]
   │ 3. Embedding 聚类 → 落入语义簇 C
   │    簇 C 内做 文档/段落/句子 去重
   │    簇 C 打分 score=0.x (示意)
   ▼
[去重后文档 + 簇分]
   │ 4. 句级质量过滤: PPL/规则/语种 → 通过
   │ 5. 安全过滤: 暴力/色情/歧视/仇恨 → 未命中, 保留
   ▼
[合格文档]
   │ 6. 按源配比 w_web 与簇分 score 加权采样
   ▼
[进入 ~2.6T 训练集] → 分词 → 喂给 Baichuan2 训练
```

> 上述 score / w 为示意，用于说明「打分如何流向采样」，非官方数值。

## 常见问题 / 坑

| 坑 / 问题 | 说明 | 实践建议 |
|-----------|------|----------|
| 去重粒度太粗 | 只做文档级，漏掉「整篇不同但句子大量重复」的冗余 | 做文档/段落/句子多粒度（Baichuan2 即如此） |
| 去重=粗暴删除 | 直接删可能丢掉稀有有用样本 | 用「聚类+打分+加权采样」而非一刀切 |
| 配比泄漏到评测 | 训练集含评测集近重样本 → 指标虚高 | 对 benchmark 做 n-gram/近重剔除（去污染） |
| 质量过滤误杀 | 规则过严会误删低资源语种/专业文本 | 规则 + LM 打分组合，阈值审慎调 |
| 安全过滤不足 | 仅过滤几类，漏掉 PII/违法等 | 报告用「等」，实际范围更广，分类器+词表+人审多层 |
| 只看数据量 | 堆量但配比失衡 → 能力偏科 | 量、质、配比、安全四者一起调 |
| 数值当真 | 报告未公开精确比例 | 凡缺失的数字标注「以官方为准」，不臆造 |
| LSH 误判 | 阈值松→漏重，紧→误删 | 字面(LSH)+语义(Embedding)双路互补 |
