## 0. 一句话锚点

**英文语料数据集 = 喂给大模型“读”的英文文本集合。** 模型的知识、语感、推理能力，本质上都来自它在训练时“读过什么”。语料的**规模、质量、多样性、配比**，直接决定了模型上限——算法和算力只是把语料里的信息“压缩”进参数。

一句话原则：**Garbage in, garbage out（垃圾进，垃圾出）**。再大的模型，喂脏数据也学不好。

---

## 1. 地基/前置：英文语料解决什么问题

大语言模型的训练目标（最经典的预训练目标）是**自回归语言建模**：给定前文，预测下一个 token 的概率分布。

$$\mathcal{L} = -\sum_{t} \log P_\theta(x_t \mid x_{<t})$$

要让这个损失下降到有用的程度，需要的不是“一篇好文章”，而是**数千亿到数万亿级别的 token**。这就带来三个现实问题，语料工程正是为了解决它们：

1. **规模问题**：从哪里搞到 $10^{12}$ 级别的 token？→ 主要靠**网页爬取（Web crawl）**，辅以书籍、代码、百科、论文。
2. **质量问题**：网页里 90% 以上是广告、导航、乱码、垃圾。直接喂会污染模型。→ 需要**清洗 + 去重 + 过滤**。
3. **能力定向问题**：想让模型会写代码就得喂代码，想让它会聊天就得喂对话。→ 需要**配比与指令/对齐数据**。

> 直觉：预训练像“让模型大量泛读建立世界模型”，微调像“教它如何把知识用成对话/任务”，对齐像“教它符合人类偏好”。三者用的语料完全不同。

## 2. 语料分层：三层语料各司其职

```
          训练阶段                  语料类型                    目标
   ┌───────────────────┐   ┌──────────────────────┐   ┌──────────────────┐
   │  ① 预训练          │ → │ 海量无标注纯文本       │ → │ 学语言+世界知识   │
   │  (Pre-training)    │   │ Web/书籍/代码/百科     │   │ ~T 级 token       │
   ├───────────────────┤   ├──────────────────────┤   ├──────────────────┤
   │  ② 指令微调(SFT)   │ → │ (指令, 期望回答) 对    │ → │ 学“听懂任务”      │
   │  (Instruction)     │   │ Alpaca/Dolly/FLAN     │   │ ~万~百万条        │
   ├───────────────────┤   ├──────────────────────┤   ├──────────────────┤
   │  ③ 对齐(RLHF/DPO)  │ → │ (prompt, chosen,      │ → │ 学“符合人类偏好”  │
   │  (Alignment)       │   │   rejected) 偏好对     │   │ ~万~十万条        │
   └───────────────────┘   └──────────────────────┘   └──────────────────┘
```

| 层 | 数据形态 | 量级（数量级，非精确）| 关注点 |
| --- | --- | --- | --- |
| 预训练 | 纯文本流 | $10^{11}\sim10^{13}$ token | 规模、去重、配比 |
| SFT | 指令-回答对 | $10^4\sim10^6$ 条 | 多样性、回答质量 |
| 对齐 | 偏好/打分对 | $10^4\sim10^5$ 条 | 标注一致性、覆盖度 |

关联阅读：SFT 与对齐的训练侧细节见 [[llm-alignment/RLHF]]。

## 3. 语料地图：主流英文数据集分类

下面按用途分类列出**代表性公开数据集**。这里只讲“是什么、定位、注意点”，**具体条数/字节数/版本以各数据集官方页面为准**（随时间更新）。

### 3.1 预训练：通用网页（Web）
- **Common Crawl**：互联网公开网页的大规模快照，几乎所有大模型预训练的“原料矿”。原始数据极脏，必须清洗。
- **C4 (Colossal Clean Crawled Corpus)**：对 Common Crawl 做规则清洗后的版本，T5 使用。
- **The Pile**：EleutherAI 整理的多来源混合语料（含网页、书籍、代码、学术等 22 个子集）。
- **RefinedWeb / FineWeb**：强调“仅靠高质量网页清洗就能达到优秀效果”的精炼网页语料路线。
- **RedPajama**：开源社区复现 LLaMA 训练数据配比的尝试。

### 3.2 预训练：书籍 / 百科 / 学术 / 代码
- **Wikipedia (English)**：高质量百科，几乎是“标配”子集。
- **Books / Gutenberg**：长文本、连贯叙事，利于长上下文与文学语感。
- **arXiv / PubMed / S2ORC**：学术论文，注入专业知识与公式语境。
- **The Stack / GitHub code**：源代码语料，是模型获得编程与逻辑能力的关键。
- **StackExchange**：问答形式的高质量技术文本。

### 3.3 指令微调（SFT）
- **FLAN Collection**：把大量 NLP 任务模板化成指令格式的合集。
- **Alpaca**：用强模型自指令生成（self-instruct）得到的指令数据，开创“蒸馏式”SFT 路线。
- **Dolly-15k**：人工编写的指令数据。
- **OpenAssistant (OASST)**：众包的多轮对话与树状会话数据。
- **ShareGPT 系**：来自真实对话日志的指令数据（**注意许可与隐私合规**）。

### 3.4 对齐（偏好）
- **Anthropic HH-RLHF**：helpful/harmless 偏好对，经典 RLHF 数据。
- **UltraFeedback**：大规模偏好打分数据，常用于 DPO。
- **Stanford SHP**：来自社区投票的偏好信号。

```
        英文语料家族树
                        ┌── Web ──── Common Crawl / C4 / FineWeb / RefinedWeb
                        │
        预训练 ─────────┼── 百科 ─── Wikipedia
        (无标注)        ├── 书籍 ─── Books / Gutenberg
                        ├── 学术 ─── arXiv / PubMed / S2ORC
                        ├── 代码 ─── The Stack / GitHub
                        └── 混合 ─── The Pile / RedPajama
                        
        SFT(指令) ──────── FLAN / Alpaca / Dolly / OASST / ShareGPT
        
        对齐(偏好) ─────── HH-RLHF / UltraFeedback / SHP
```

## 4. 数据流水线：从原始网页到可训练 token

这是语料工程的“主干道”。每一步都在**“多但脏”和“干净但少”之间做权衡**。

```
 [原始爬取]        [文本抽取]       [语言识别]      [质量过滤]
 WARC/HTML  ──►  去 HTML 标签  ──►  保留 en   ──►  规则+模型打分
 (TB 级)         正文抽取         丢非英文       丢低质/乱码
     │                                              │
     ▼                                              ▼
 [去重 Dedup]   ◄── [去毒/隐私] ◄── [格式归一化] ◄────┘
 精确+模糊去重      去 PII/毒性       Unicode 归一
     │
     ▼
 [配比混合]  ──►  [分词 Tokenize]  ──►  [打包成训练分片]
 data mixture     BPE/SentencePiece    .bin / .idx / parquet
     │                                       │
     └────────────► 喂给训练框架 ◄───────────┘
              (Megatron / DeepSpeed 等，见 ai-framework/README)
```

每一步的“为什么”：
1. **文本抽取**：网页 90% 是模板（菜单、页脚、广告），只想要正文。
2. **语言识别**：用 fastText 之类的语言分类器，丢掉非英文（除非要做多语）。
3. **质量过滤**：分**规则过滤**（标点比例、平均词长、停用词比例、是否含大量重复行）和**模型过滤**（用分类器判断“像不像维基/书这种高质量文本”）。
4. **去重**：互联网大量内容重复，重复会让模型“死记硬背”、降低有效信息密度。
5. **去毒/隐私**：去掉仇恨言论、成人内容、个人身份信息（PII）。
6. **配比 → 分词 → 打包**：把多源数据按比例混合，切成 token，存成训练框架能高效读取的二进制分片。

## 5. 质量与去重：核心机制拆原子

### 5.1 去重的两种粒度
- **精确去重（Exact dedup）**：对文档/段落算哈希，哈希相同即重复。快，但改一个字就漏掉。
- **模糊去重（Fuzzy/Near dedup）**：用 **MinHash + LSH** 估计两文档的 **Jaccard 相似度**，相似度高于阈值即视为重复。

Jaccard 相似度定义（两个文档的 n-gram 集合 $A,B$）：

$$J(A,B) = \frac{|A \cap B|}{|A \cup B|}$$

MinHash 的核心直觉：随机哈希下，两集合“最小哈希值相等”的概率正好等于 $J(A,B)$。于是用很多个哈希函数估计这个概率，就能在不两两比较的情况下近似相似度。LSH 再把相似文档分到同一“桶”，避免 $O(n^2)$ 爆炸。

```
 文档 → n-gram 集合 → MinHash 签名(k 维) → LSH 分桶 → 桶内才两两比对
   去掉了对全体文档做 O(n²) 比较的开销
```

### 5.2 质量过滤的两条路线
| 路线 | 机制 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 规则启发式 | 标点/词长/重复行阈值 | 快、可解释 | 漏检、误杀 |
| 分类器打分 | 训练“高质 vs 低质”分类器 | 召回更细致 | 引入分类器偏见 |

### 5.3 关键原则
- **顺序很重要**：一般先抽取/语言识别，再过滤，**最后或较后做去重**（去重很贵，先把垃圾删掉能省算力）。
- **去重要跨数据集做**：否则书籍里的句子和网页里的同句重复仍在。
- **过度过滤有害**：把所有“非维基风格”都删掉，会损失对话、口语、长尾知识的多样性。

## 6. 配比与采样：data mixture

不同领域语料按比例混合，比例就是一个**超参数**。常见做法是给每个数据源一个采样权重 $w_i$，按权重决定该源在一个训练 epoch 中被采样的概率：

$$p_i = \frac{w_i \cdot n_i}{\sum_j w_j \cdot n_j}$$

其中 $n_i$ 是源 $i$ 的 token 数。权衡逻辑：

```
   多代码  ─► 编程/逻辑强，但自然语言流畅度可能下降
   多书籍  ─► 长上下文/叙事强，但时效性差
   多网页  ─► 覆盖广/时效新，但噪声高
   多学术  ─► 专业知识强，但通用对话能力弱
        ↘                                  ↙
            最终配比 = 在“目标能力”上做的取舍
```

实践要点：
- **高质量小数据源常被“上采样（upsample）”**（如 Wikipedia 重复多读几遍），低质量大数据源被“下采样”。
- 上采样次数过多会**过拟合**（模型背诵）；这就是为什么去重 + 限制重复次数很关键。
- 现代研究趋势：用**小规模代理实验**搜索最佳配比，而不是拍脑袋。

## 7. 选型与许可：怎么挑、有什么坑

### 选型决策（按目标倒推）
```
 你的目标？
   ├─ 从零预训练通用底座 → Web 为主(FineWeb/RedPajama) + 维基/书/代码/学术
   ├─ 增强代码能力        → The Stack / StackExchange 加大配比
   ├─ 做对话助手(SFT)     → FLAN + Alpaca + OASST
   └─ 做对齐(RLHF/DPO)    → HH-RLHF / UltraFeedback
```

### 许可证陷阱（必须看清楚）
| 风险点 | 说明 |
| --- | --- |
| 许可证传染 | 某些数据“仅供研究”，不可商用 |
| 蒸馏数据 | Alpaca/ShareGPT 等由商业模型生成，可能受其服务条款限制 |
| 版权文本 | 书籍/新闻语料可能涉及版权，商用前需法务确认 |
| 隐私(PII) | 网页含真实个人信息，需去除以符合 GDPR 等 |

> 护栏：以上数据集的**具体许可、条数、字节数会随版本变化，使用前务必以各数据集官方仓库/论文/HuggingFace 卡片为准**。

## 常见问题/坑

| 现象/坑 | 根因 | 应对 |
| --- | --- | --- |
| 模型“背诵”训练数据 | 去重不彻底 / 上采样过度 | 跨源模糊去重，限制重复次数 |
| 评测分数虚高 | 训练集污染了测试集（contamination）| 做 benchmark 去重，剔除测试样本 |
| 输出毒性/偏见 | 语料含有害内容 | 加去毒过滤 + 对齐阶段纠偏 |
| 多语料拼接后能力反降 | 配比失衡 | 用代理实验调 mixture 权重 |
| 中文/小语种能力差 | 语料几乎全英文 | 显式加入目标语言语料 |
| 数据读取成为瓶颈 | 未打包成高效分片 | 预先 tokenize 成二进制分片，流式读取 |
| 商用被律师叫停 | 忽视许可证 | 选型即审许可，优先 permissive 许可数据 |
