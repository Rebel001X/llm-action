## 0. 一句话锚点

> **Garbage In, Garbage Out（垃圾进，垃圾出）**。

大模型本质是"对训练数据分布的压缩与拟合"。它学到的世界知识、语言风格、推理习惯、价值观，**全部来自数据**。你给它喂论坛骂战，它就学会骂街；你给它喂高质量论文与代码，它就学会推理与编程。架构（Transformer）和算力（GPU）只是"锅和火"，**数据是食材**——食材烂了，再好的厨师也做不出好菜。

数据工程要回答三个问题：**从哪弄数据（来源）→ 怎么变干净（清洗/去重）→ 怎么搭配（配比）**，并在训练后形成**闭环**持续改进，同时严防**污染**导致评测虚高。

## 1. 地基/前置

### 1.1 最原子的单位：token

模型不直接读"字"，而是读 **token**（分词后的整数 ID）。一段中文 "我爱学习" 经 BPE 分词器后可能变成 `[2769, 4263, 1359]` 这样的整数序列。

- 经验换算（粗略，**因分词器而异，以实测为准**）：英文 **1 token ≈ 0.75 个单词 ≈ 4 个字符**；中文 **1 token ≈ 1~1.5 个汉字**。
- 训练数据规模一律用 **token 数** 度量，而非"多少 GB"。因为同样 1GB，英文文本的 token 数和中文/代码差别很大。

```
原始文本 ──分词器(Tokenizer)──> token ID 序列 ──> 模型输入
"Hello world"  ──BPE──>  ["Hello", " world"]  ──>  [15496, 995]
```

### 1.2 三种数据，对应训练三阶段

| 阶段 | 数据类型 | 数据量级（典型，**以官方为准**） | 目标 | 形态 |
|------|---------|------------------|------|------|
| 预训练 Pretrain | 无标注海量文本 | **数 T ~ 十几 T token** | 学语言+世界知识 | 纯文本流 |
| 指令微调 SFT | 指令-回答对 | **数万 ~ 数百万 条** | 学会"听话/对话" | (instruction, output) |
| 偏好对齐 RLHF/DPO | 偏好对 | **数万 ~ 数十万 对** | 学会"答得让人满意" | (prompt, chosen, rejected) |

```
   数据金字塔（量级递减，质量/标注成本递增）
            ┌───────────────┐
            │  偏好对齐数据   │  几万对，人工偏好    最贵
            ├───────────────┤
            │   SFT 指令数据  │  几十万~几百万条，需标注
            ├───────────────┤
            │                │
            │   预训练语料    │  数 T~十几 T token，弱标注/无标注
            │                │  最便宜（单位），但总量最大
            └───────────────┘
```

本总览重点讲**预训练数据**（来源/清洗/去重/配比/质量）与 **SFT 数据**（多样性），并贯穿"为什么数据决定上限 / 数据闭环 / 污染"三条主线。

## 2. 数据来源：原始语料从哪来

预训练语料的"原材料"主要来自下列几类。不同语料的**信息密度、知识价值、噪声水平**差异巨大。

```
            互联网级原始数据来源
 ┌─────────────┬──────────────┬─────────────┐
 │ 网页(最大量)  │  代码        │  书籍/论文   │
 │ CommonCrawl │  GitHub      │  ArXiv/书籍  │
 │ C4/RefinedWeb│             │             │
 ├─────────────┼──────────────┼─────────────┤
 │ 噪声高、量大  │ 强逻辑/结构化 │ 高质量长文本 │
 │ 需重度清洗    │ 提升推理能力  │ 知识密度高   │
 └─────────────┴──────────────┴─────────────┘
   + 百科(Wikipedia) + 问答(StackExchange) + 对话(Reddit) + 多语
```

| 来源 | 代表数据集 | 特点 | 作用 |
|------|-----------|------|------|
| 网页抓取 | CommonCrawl / C4 / RefinedWeb / FineWeb | 量巨大、噪声重 | 语言广度、世界知识 |
| 代码 | GitHub / The Stack | 结构化、强逻辑 | **显著提升推理/数学能力** |
| 书籍 | Books3 / 古登堡 | 长上下文、连贯 | 长文理解、文笔 |
| 学术 | ArXiv / PubMed | 专业、高密度 | 科学/数学知识 |
| 百科 | Wikipedia | 高质量、事实性强 | 常被**多次过采样** |
| 问答/论坛 | StackExchange / Reddit | 自带指令-回答结构 | 对话、问答能力 |

> 关键洞见：**加代码数据能提升自然语言推理能力**——代码的严格逻辑结构像"逻辑训练操"，迁移到了语言推理上。这是 LLM 数据工程最反直觉也最重要的经验之一。

中英文具体语料清单见 [[llm-data-engineering/dataset/README]]、[[llm-data-engineering/dataset/chinese-corpus-all]]、[[llm-data-engineering/dataset/english-corpus-all]]。

## 3. 清洗（Cleaning）：把脏数据洗干净

CommonCrawl 这类原始网页抓取里充斥着：HTML 标签残渣、导航栏/广告、乱码、机器生成垃圾、色情/暴力、个人隐私（PII）、重复模板……**直接拿去训练等于喂毒**。清洗流水线像一道道筛网：

```
原始网页 (100% 体量)
   │  ① 语言识别(fastText)        丢掉非目标语言
   ▼
   │  ② 启发式规则过滤            丢掉过短/符号过多/重复行
   ▼
   │  ③ 质量分类器打分            丢掉"不像维基/书籍"的低质文本
   ▼
   │  ④ 安全/隐私过滤             去 PII、去毒、去黄
   ▼
   │  ⑤ 去重(见第4节)            丢掉重复
   ▼
清洗后语料 (常仅剩 1%~10% 体量)
```

**① 语言识别**：用 fastText 等分类器判定语言，只保留目标语言（如中/英），并设置置信度阈值。

**② 启发式规则（heuristic filters）**：基于人工经验的简单硬规则，便宜高效。典型规则：
- 文档词数 < 50 或 > 100000 → 丢（太短无信息/太长多是垃圾堆）
- 平均词长异常（< 3 或 > 10 个字符）→ 丢
- 标点符号占比过高、含 `{` `}` `<` `>` 等符号过多 → 丢（残留代码/HTML）
- 重复行比例 / 重复 n-gram 比例过高 → 丢（模板、刷屏）
- 含敏感词、停用词比例过低（不像自然语言）→ 丢

**③ 质量分类器（model-based filtering）**：训练一个轻量分类器（如逻辑回归 + fastText 特征），**正样本=高质量参考语料（Wikipedia、书籍）**，**负样本=随机网页**，给每篇文档打"像不像高质量文本"的分，按阈值保留。GPT-3、LLaMA 等都用过这类方法。

**④ 安全与隐私**：去除个人身份信息（邮箱、电话、身份证号），过滤色情/暴力/仇恨内容。

> 触目惊心的事实：原始 CommonCrawl 经过完整清洗+去重后，**常常只剩下 1% 左右可用**。FineWeb 等现代流水线公开了详细的逐级保留率。**清洗的核心权衡：过滤太狠→丢掉有用数据、损失多样性；过滤太松→噪声拖垮模型。**

## 4. 去重（Deduplication）：为什么必须去重

互联网充满重复：同一篇新闻被无数站转载、模板页、镜像站。重复数据的危害：
1. **浪费算力**：把同样内容学很多遍。
2. **记忆与泄漏**：高频重复样本会被模型**逐字背诵**，加剧隐私泄漏与版权风险。
3. **分布扭曲**：某些内容被过度加权，损害泛化。
4. **评测污染**：测试集若在训练数据里重复出现，评分虚高（见第10节）。

研究表明：**去重后用更少数据反而能训出更好/相当的模型**——证明很多 token 是"无效重复"。

### 两种去重粒度

```
精确去重(Exact)            模糊去重(Fuzzy / Near-dup)
─────────────             ──────────────────────
完全相同的文档/段落         "几乎一样"的文档(改了几个字)
方法: 哈希(MD5/SHA) 比对    方法: MinHash + LSH 估计 Jaccard 相似度
      或后缀数组找重复子串         相似度 > 阈值(如0.8) → 判重
快但只能抓完全相同          能抓改写/转载, 是主力
```

**MinHash + LSH 直觉（最底层讲）**：
- **Jaccard 相似度**衡量两文档的 n-gram 集合重叠度：$J(A,B)=\dfrac{|A\cap B|}{|A\cup B|}$。
- 直接两两算 $O(N^2)$，对十亿文档不可行。
- **MinHash**：对每个文档用 $k$ 个哈希函数，取每个哈希下的最小值，得到一个长度 $k$ 的"指纹"。神奇性质：两文档指纹某一位相等的概率 ≈ 它们的 Jaccard 相似度。
- **LSH（局部敏感哈希）**：把指纹分段，相似文档大概率落进同一个"桶"，**只在桶内比对**，把 $O(N^2)$ 降到近线性。

```
文档 → n-gram集合 → MinHash指纹(k维) → 分桶(LSH) → 桶内比对 → 判重
                                        ↑ 把相似文档"撞"到一起
```

## 5. 配比（Data Mixture）：不同来源按什么比例混

清洗去重后，你有了网页、代码、书籍、百科……几个"料桶"。**按什么比例混进训练？** 这就是配比，对最终能力**影响巨大**。

```
        训练 token 预算 = 15T (举例)
 ┌────────────────────────────────────────┐
 │ 网页 67%  代码 15%  书籍 8%  百科5%  论文5%│ ← 权重需调优
 └────────────────────────────────────────┘
   ↑ 高质量小语料(百科)常 over-sample(重复采样2~5轮)
   ↑ 网页量大但质量参差, 占比高但不是越高越好
```

核心原则：
- **不是越多越好**：网页量最大，但全用网页会拉低质量；适度加代码/书籍能显著提升推理与文笔。
- **高质量小语料过采样（up-sampling）**：Wikipedia 总量不大，但价值高，常重复 2~5 个 epoch；网页则通常 < 1 epoch（采样一部分）。
- **学习配比（learned mixture）**：如 DoReMi 用一个小模型自动搜索各领域的最优权重，再用于训大模型，比人工拍脑袋更优。
- **课程式（curriculum）**：训练后期切换到更高质量/更专的数据（如代码、数学），类似"先泛读再精读"。

> 配比是 LLM 数据工程里"最玄学也最值钱"的部分，各家配方多为商业机密。经验法则：**多样性 > 单纯堆量**。

## 6. 质量评估：怎么判断"这批数据好不好"

数据洗完、混好了，怎么知道它真的好？三类方法：

| 方法 | 怎么做 | 优点 | 局限 |
|------|--------|------|------|
| 困惑度 Perplexity | 用一个参考模型在该数据上算 PPL | 自动、便宜 | 低 PPL ≠ 高价值 |
| 分类器打分 | 训"高质量 vs 低质量"分类器评分 | 可规模化 | 依赖正样本定义 |
| **消融实验（金标准）** | 用不同数据配方各训一个小模型，比下游评测 | 最可信 | 贵、慢 |

```
数据配方 A ─训小模型─> 下游评测分 78
数据配方 B ─训小模型─> 下游评测分 82  ← 选B的配方
            (用 1B 小模型快速试错, 再放大到 70B)
```

实践要点：**先用小模型（1B 级）做数据消融试错，确认配方后再砸算力训大模型**——这是省钱的关键，因为数据配方在小模型上的相对优劣大体可迁移到大模型。

## 7. SFT 数据：指令多样性是灵魂

预训练让模型"博学但不听话"。**SFT（监督微调）**用 (指令, 回答) 对，教模型"按人类要求作答"。数据格式见 [[llm-data-engineering/sft-dataset/数据格式设计]]。

> 反直觉结论（LIMA 论文）："**Less Is More for Alignment**"——只用 **1000 条** 极高质量、**高多样性**的指令样本，就能让模型表现优秀。说明 SFT 阶段**质量与多样性 >> 数量**。

### 为什么多样性是关键？

SFT 不是教新知识（知识在预训练已学），而是**激活并对齐**已有能力。如果指令只覆盖"翻译"，模型就只在翻译上听话，其他任务仍乱来。**多样性 = 覆盖的任务类型、领域、难度、回答风格、语言越广越好。**

```
指令多样性的几个维度
 ├─ 任务类型: 问答/翻译/摘要/分类/代码/数学/角色扮演/改写...
 ├─ 领域:     科技/法律/医疗/金融/日常/创意写作...
 ├─ 难度:     简单事实 → 多步推理 → 开放生成
 ├─ 输入形式: 有上下文/无上下文/多轮对话
 └─ 输出风格: 简短/详尽/分点/带格式
```

### SFT 数据的构造方法

| 方法 | 思路 | 代表 |
|------|------|------|
| 人工标注 | 人写指令和回答 | 质量最高，最贵 |
| Self-Instruct | 用少量种子指令，让强模型**自生成**大量新指令+回答 | Alpaca |
| **Evol-Instruct** | 让模型把简单指令**进化**得更难/更复杂/更深 | WizardLM，见 [[llm-data-engineering/sft-dataset/evol-instruct]] |
| 真实日志回流 | 从线上用户真实问题中筛选标注 | 闭环，见第9节 |

```
Self-Instruct 流程:
175条种子指令 ──喂给强模型──> 生成新指令 ──生成对应回答──> 过滤去重 ──> 数万条指令数据
                    ↑ 自举(bootstrap), 低成本造数据
Evol-Instruct 进化:
"写个排序" ──In-depth进化──> "写个稳定排序并分析复杂度" ──> 更难更多样
```

## 8. 为什么数据决定上限（Scaling Law 的数据侧）

模型能力随**参数量 $N$、数据量 $D$、算力 $C$** 提升，遵循**幂律（Scaling Law）**：损失大致服从

$$L(N, D) = L_\infty + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}$$

其中 $D$ 是训练 token 数。两点关键：

1. **Chinchilla 最优**：DeepMind 发现，**很多大模型"训练不足"——参数堆太大、数据喂太少**。经验法则：**参数量与训练 token 数应大致按 $D \approx 20N$ 配比**（每 1 个参数约配 20 个 token）才算"算力最优"。后来推理成本考量下，业界常**远超 20×**（如 LLaMA 系列用极多 token 训相对小的模型，换取部署便宜）。

2. **质量是天花板**：Scaling Law 描述的是"**同质量数据**下，加量降损失"。但 $L_\infty$（不可约损失）由数据质量与任务本身决定。**数据有多干净、多有信息量，决定了模型能逼近的极限**——这就是"数据决定上限"的数学含义。脏数据再多也只是把模型推向一个**更差的下限**。

```
   loss
    │＼
    │ ＼____ 高质量数据: 收敛到更低的 loss 平台 (上限高)
    │      ＼________
    │                ＼___________  ← 低质量数据: 卡在更高平台(上限低)
    └────────────────────────────► 训练数据量 D
       加量有用, 但"质量天花板"由数据决定, 加量无法突破
```

## 9. 数据闭环（Data Flywheel）：让数据飞轮转起来

好模型不是训一次就完事，而是靠**数据闭环**持续迭代。模型上线后产生的真实交互，是最宝贵的"新食材"。

```
        ┌────────────────────────────────────┐
        ▼                                    │
   ① 模型上线  ──②用户真实交互/日志──>  ③ 难例挖掘     │
        ▲                              (用户点踩/模型答错) │
        │                                    │           │
   ⑥ 训练新模型 <──⑤数据回流入训练集── ④ 人工/模型标注修正 ┘
        └────────────────────── 飞轮越转越快 ──────────────┘
```

闭环各环节：
- **采集**：记录线上 prompt、模型回答、用户反馈（点赞/点踩/重写）。
- **难例挖掘（hard example mining）**：自动找出模型答错、用户不满意、置信度低的样本——这些**信息量最大**。
- **标注/修正**：人工或更强模型给出正确答案，构成新的 SFT/偏好数据。
- **回流**：清洗去重去污染后，混入下一轮训练。
- **评估再上线**：A/B 测试确认提升后部署，开启下一圈。

> 飞轮效应：**用户越多 → 难例越多 → 模型越强 → 用户更多**。这是数据驱动产品的核心护城河，胜过单纯堆参数。

## 10. 数据污染（Contamination）：测试集泄漏

**污染** = 评测的测试集（题目+答案）**意外混进了训练数据**。后果：模型其实是**背过答案**，评测分虚高，但真实能力没那么强——你以为做出了 GPT-4，其实是"开卷考试作弊"。

```
   正常:  训练集 ┃ 测试集   (严格隔离, 分数可信)
   污染:  训练集 ▓▓▓测试集▓▓▓  (重叠! 模型见过答案 → 假高分)
                  ↑ CommonCrawl 里恰好抓到了某 benchmark 网页
```

**污染怎么发生**：网页抓取无意中包含了 benchmark 题库网页、GitHub 上的评测数据集、博客里贴的题目答案。

**怎么检测污染**：
- **n-gram 重叠**：检查测试样本的 n-gram（如 13-gram）是否出现在训练集里，重叠率高即疑似污染。
- **去污染（decontamination）**：训练前主动从训练集中删除与所有已知 benchmark 重叠的文档（GPT-3、LLaMA 都做）。
- **行为侧信号**：模型对"原题"答得异常好、改写一下就崩，或能补全测试集后续题目，提示它"背过"。

**实践纪律**：
1. 训练前对所有评测集做去污染。
2. 用**新发布、训练截止日之后**的评测集（模型不可能见过）。
3. 报告时披露去污染流程，警惕"刷榜"。

> 一句话：**不去污染的评测分，等于开卷考试的成绩**——好看但不可信。这也是为什么严肃报告必须公开去污染细节。

## 数值例子：15T token 规模手算

假设训一个类 LLaMA-3 级别模型，目标 **15T（15 万亿）token**。

**① 原始数据要抓多少？** 清洗+去重后保留率按 **10%**（已偏乐观）算：
$$ \text{原始 token} = \frac{15\text{T}}{0.10} = 150\text{T token} $$
按 1 token ≈ 4 字节粗算，原始文本约 $150\times10^{12}\times4 = 6\times10^{14}$ 字节 ≈ **600 TB 原始文本**（抓取/存储压力巨大）。

**② Chinchilla 视角的模型大小**：若严格按 $D=20N$，
$$ N = \frac{D}{20} = \frac{15\text{T}}{20} = 0.75\text{T} = 750\text{B 参数} $$
但 LLaMA 系列**故意"过度训练"小模型**（如 8B 模型喂 15T token，$D/N \approx 1875$！），远超 20×。**为什么？** 训练贵一次，推理要跑无数次——小模型部署便宜，值得在训练时多喂数据把它"喂饱"。

**③ 配比手算**：15T 按 网页67% / 代码15% / 书籍8% / 百科5% / 论文5%：
| 来源 | 占比 | token 数 |
|------|------|---------|
| 网页 | 67% | 10.05 T |
| 代码 | 15% | 2.25 T |
| 书籍 | 8% | 1.20 T |
| 百科 | 5% | 0.75 T（可能过采样 3 轮，原始仅 0.25T）|
| 论文 | 5% | 0.75 T |

**④ 训练算力粗估**：稠密 Transformer 经验公式 $C \approx 6ND$ FLOPs。以 $N=8\text{B}$、$D=15\text{T}$：
$$ C \approx 6 \times 8\times10^{9} \times 15\times10^{12} = 7.2\times10^{23}\ \text{FLOPs} $$
一张 H100 约 **1000 TFLOPS（BF16，理论峰值，以官方为准）**，按 40% 有效利用率（MFU）：
$$ \text{卡时} = \frac{7.2\times10^{23}}{1000\times10^{12}\times0.4} \approx 1.8\times10^{9}\ \text{秒} \approx 5\times10^{5}\ \text{H100·小时} $$
即约 **50 万 H100 卡时**——折合 1000 张 H100 跑约 **3 周**（数量级示意，实际受并行效率影响）。这清楚说明：**每一个 token 都很贵，数据质量必须配得上这份算力投入。**

## 常见问题

| 问题 | 答案 |
|------|------|
| 数据 GB 和 token 怎么换算？ | 因分词器/语言而异；英文约 1 token≈4 字符，中文约 1 token≈1~1.5 汉字，**以实测为准** |
| 清洗后为什么只剩 1%~10%？ | 原始网页绝大多数是垃圾/模板/重复，重度过滤+去重后所剩无几 |
| 去重为什么用 MinHash 不直接比对？ | 两两比对 $O(N^2)$ 对十亿级文档不可行，MinHash+LSH 降到近线性 |
| 加代码数据有什么用？ | 代码的严格逻辑结构能**迁移提升自然语言推理/数学能力** |
| SFT 是数量重要还是质量重要？ | 质量与多样性远胜数量（LIMA：1000 条高质量样本即可） |
| 为什么说"数据决定上限"？ | Scaling Law 的不可约损失 $L_\infty$ 由数据质量决定，堆量无法突破质量天花板 |
| 模型评测分很高就一定强吗？ | 不一定——可能数据污染（背过测试集），须先去污染再看分 |
| 高质量小语料怎么用？ | 过采样（up-sampling），重复训 2~5 轮，提高其有效权重 |
