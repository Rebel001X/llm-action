## 1. 地基：为什么需要 BLOOM？

### 1.1 2020–2022 年的封闭困局

GPT-3（见 [[llm-algo/gpt3/README]]）在 2020 年证明了"规模即能力"：175B 参数 + 海量数据 → 涌现少样本学习。但 GPT-3：

- **权重不开放**：只能通过 OpenAI 付费 API 调用，研究者拿不到模型本体。
- **数据不透明**：训练语料的确切构成、清洗规则未完整公开。
- **以英语为中心**：非英语语言（尤其是低资源语言）覆盖很差。

这造成一个结构性问题：**学术界无法独立研究、审计、复现超大模型**。你想研究"大模型为什么有偏见""它记住了哪些训练数据""换个数据配方会怎样"——你连模型都摸不到。

### 1.2 BigScience：一次开放科学实验

```
   传统大模型              BigScience / BLOOM
   ┌──────────┐           ┌──────────────────────┐
   │ 一家公司  │           │ 1000+ 研究者          │
   │ 闭门训练  │   VS      │ 60+ 国家协作           │
   │ 只放API   │           │ 公开数据/代码/权重/日志 │
   └──────────┘           └──────────────────────┘
```

BigScience 是 2021–2022 年由 Hugging Face 发起、欧盟与法国学术机构支持的为期一年的开放协作项目。它不是一家公司的产品，而像粒子物理界的"大型对撞机协作"——上千名志愿研究者分成数据、建模、工程、伦理、评测等工作组共同完成。**BLOOM（BigScience Large Open-science Open-access Multilingual Language Model）是这个项目的旗舰产物。**

> 关键意义：BLOOM 第一次让"超大模型的训练全过程"成为公共知识。任何人都能下载权重、查看训练日志、审计数据来源、复现实验。这对科学的价值，远超它在某个榜单上的排名。

## 2. 整体架构与规模

BLOOM 是标准的 **decoder-only（仅解码器）自回归 Transformer**，和 GPT 系列同属一类：从左到右预测下一个 token。但它在两个细节上做了改动（第 3、4 节展开）。

### 2.1 旗舰版 BLOOM-176B 规格

| 超参数 | 取值 | 说明 |
|---|---|---|
| 参数量 | ≈176B（1760 亿） | 含 embedding |
| 层数 $L$ | 70 | Transformer block 数 |
| 隐藏维度 $d_{model}$ | 14336 | |
| 注意力头数 $h$ | 112 | 每头 $14336/112=128$ 维 |
| 词表大小 $V$ | 250680 | 多语言 BPE，比 GPT-3 的 ~50k 大很多 |
| 上下文长度 | 2048 | 训练时序列长度 |
| 激活函数 | GELU | |
| 位置编码 | **ALiBi**（无位置嵌入） | 核心创新 |

BLOOM 还发布了一整套小尺寸版本：560M / 1.1B / 1.7B / 3B / 7.1B / 176B，方便算力有限者使用与研究 scaling 规律。

### 2.2 单个 Transformer Block 的数据流

```
  输入 x  (序列长 T, 维度 d=14336)
    │
    ▼
 ┌───────────────────────────────────────┐
 │ BloomBlock                            │
 │                                       │
 │  x ─► LayerNorm ─► Self-Attention ─┐  │
 │  │                  (含 ALiBi 偏置)  │  │
 │  └──────────(残差相加)◄────────────┘  │
 │  │                                    │
 │  └─► LayerNorm ─► MLP(GELU) ──┐       │
 │      │                         │       │
 │      └────────(残差相加)◄──────┘       │
 └───────────────────────────────────────┘
    │
    ▼
  输出（送入下一层，共 70 层）
```

注意：BLOOM 用的是 **pre-LN（先归一化再进子层）**，比 post-LN 在深层网络上更易训练。

## 3. 核心创新①：ALiBi 位置编码

这是 BLOOM 最具技术辨识度的选择。要讲清它，先回顾"位置编码"为什么必要。

### 3.1 为什么 Transformer 需要位置信息？

自注意力的本质是"加权求和所有 token"：

$$
\text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

这个公式对 token 的**顺序完全无感**——打乱输入顺序，$QK^\top$ 矩阵只是行列重排，注意力结果一样。可"猫追狗"和"狗追猫"意思完全不同。所以必须额外注入位置信息。

历史上三种做法：

| 方案 | 代表模型 | 做法 |
|---|---|---|
| 绝对位置嵌入 | GPT-3 / BERT | 每个位置一个可学习向量，加到 token embedding 上 |
| 旋转位置编码 RoPE | LLaMA / GPT-NeoX | 把位置编码成旋转角，乘进 Q、K（见 [[llm-algo/旋转编码RoPE]]） |
| **线性偏置 ALiBi** | **BLOOM** | 不加任何位置向量，直接在注意力分数上加一个"距离惩罚" |

### 3.2 ALiBi 的机制：给注意力分数加一把"距离尺子"

ALiBi（Attention with Linear Biases）的思想极简：**离得越远的 token，注意力分数被减得越多。**

在 softmax 之前，对第 $i$ 个查询、第 $j$ 个键的注意力分数加一个偏置：

$$
\text{score}_{ij} = \frac{q_i \cdot k_j}{\sqrt{d_k}} + m \cdot (j - i)
$$

其中 $(j-i)\le 0$（只能看左边，因果掩码），$m$ 是每个注意力头**固定（不学习）**的斜率。距离 $|i-j|$ 越大，$m\cdot(j-i)$ 越负，惩罚越重。

```
   查询位置 i=5, 看左边各 key:
   key位置:    0     1     2     3     4     5
   距离 j-i:  -5    -4    -3    -2    -1     0
   偏置 m*(j-i): ↓更负 ────────────────► 0
              惩罚重                    无惩罚
   直觉：越近的词，越该被关注
```

不同的头用不同的斜率 $m$（按几何序列分配，如 $1/2, 1/4, 1/8,\dots$）：斜率大的头"近视"（只看附近），斜率小的头"远视"（能顾及远处）。多头组合 → 模型自动学会在不同距离尺度上分配注意力。

### 3.3 为什么 BLOOM 选 ALiBi？两大好处

```
   好处①：长度外推 (extrapolation)
   ┌─────────────────────────────────────┐
   │ 训练长度 2048                         │
   │ ███████████████████  ← 训练见过       │
   │ ███████████████████░░░░░░░  ← 推理时   │
   │                     更长也不崩         │
   │ 绝对位置嵌入：没学过的位置=随机向量→崩  │
   │ ALiBi：偏置只是距离的线性函数→平滑外推  │
   └─────────────────────────────────────┘
```

1. **长度外推**：绝对位置嵌入在超过训练长度的位置上"没有定义"，性能骤降。ALiBi 的偏置是距离的解析函数，对任意距离都成立，所以**训练用 2048，推理可以更长而不崩溃**。

2. **更省、更简单**：不需要一张位置嵌入表（省参数、省显存），实现也简单——只是在 attention score 上加一个预先算好的偏置矩阵。

> 一句话记忆：**RoPE 是"旋转 Q/K"，ALiBi 是"按距离扣分"。** 两者都不用绝对位置表，但 ALiBi 更轻、外推更自然；RoPE 表达更精细，后来被 LLaMA 等主流采用。BLOOM 选 ALiBi 是 2022 年的合理工程权衡。

## 4. 核心创新②：Embedding LayerNorm

### 4.1 问题：176B 训练极易发散

训练几百亿、上千亿参数的模型时，最怕的是**loss 突然爆炸（spike）**——一旦发散，几小时甚至几天的算力白烧。BLOOM 团队在前期实验中发现，紧跟在词嵌入之后立刻加一层 LayerNorm，能显著提升训练稳定性（虽然理论上略微影响 zero-shot 泛化，但稳定性收益更重要）。

```
  常规：  token ─► Embedding ──────────► 第1个Block
  BLOOM： token ─► Embedding ─► LayerNorm ─► 第1个Block
                              └─ 把输入尺度先"拉平" ─┘
                                防止初期激活值过大→梯度爆炸
```

直觉：词表 25 万、嵌入维度 14336，初始嵌入的数值尺度可能很大且不均匀。先做一次归一化，把分布拉到 0 均值、单位方差，后续每一层的输入都更"温顺"，减少了训练初期的不稳定。这类"为了能稳定训出超大模型而做的工程取舍"，正是 BLOOM 公开训练经验的价值所在。

## 5. 多语言语料 ROOTS

### 5.1 数据是 BLOOM 的灵魂

BLOOM 的训练语料叫 **ROOTS（Responsible Open-science Open-collaboration Text Sources）**，约 **1.6 TB 文本**，覆盖 **46 种自然语言 + 13 种编程语言**。这是它"多语言"标签的来源。

```
  ROOTS 1.6TB 语言构成（示意，比例为近似）
  英语        ████████████████  ~30%
  中文(简繁)  ███████           ~16%
  法语        ██████            ~13%
  西班牙语    ████              ~11%
  代码        ████              ~11%
  阿拉伯/葡/越/印地等 ████████   其余多语言
  （含非洲、南亚等大量低资源语言，以官方数据卡为准）
```

### 5.2 为什么"多语言"很难也很重要？

- **难**：大多数公开语料以英语为主，低资源语言（如约鲁巴语、斯瓦希里语、孟加拉语方言）数据稀缺、质量参差。BigScience 专门组织了各语种社区参与数据收集与清洗。
- **重要**：让全球非英语使用者也能用上、研究自己语言的大模型，是 BLOOM 的核心使命之一。它对一批此前几乎没有大模型支持的语言提供了基础能力。

### 5.3 负责任的数据治理

ROOTS 强调**数据来源可追溯、版权与隐私可审计**：每条数据知道来自哪里、走了什么清洗流程。这与 GPT-3 等"数据黑箱"形成鲜明对比，也是"开放科学"理念的体现。

## 6. 训练公开：3D 并行与公共算力

### 6.1 在哪儿、用什么训的？

| 项目 | 内容 |
|---|---|
| 算力平台 | 法国 **Jean Zay** 公共超算（IDRIS / CNRS） |
| 加速卡 | 约 **384 张 NVIDIA A100 80GB**（以官方为准） |
| 训练框架 | **Megatron-DeepSpeed**（Megatron-LM + DeepSpeed） |
| 训练时长 | 约 3.5 个月（数据并行展开） |
| 训练 token | 约 **3660 亿 token** |
| 能源透明 | 公开了碳足迹估算（用法国低碳核电，碳排相对低） |

> 重点意义：**训练用的是公共科研算力、而非私有云**，且**训练日志、loss 曲线、配置、中间 checkpoint 都公开**。任何研究者都能看到"176B 模型是怎么一步步训出来的"，这在大模型史上极为罕见。

### 6.2 176B 必须用 3D 并行

176B 参数根本塞不进单张 80GB 显卡（光是 fp16 权重就 352GB，见第 9 节手算），必须把模型切开放到几百张卡上。这叫 **3D 并行**：

```
  ┌──────────── 3D 并行 ────────────┐
  │                                  │
  │  ① 张量并行 (TP)：一层切成多片     │
  │     ┌──┬──┬──┬──┐               │
  │     │W1│W2│W3│W4│  4 张卡分担一层 │
  │     └──┴──┴──┴──┘               │
  │                                  │
  │  ② 流水线并行 (PP)：层切成多段     │
  │     卡组A[第1-10层]→卡组B[11-20层]→…│
  │                                  │
  │  ③ 数据并行 (DP)：多份副本喂不同batch│
  │     副本1  副本2  副本3 ... 同步梯度 │
  └──────────────────────────────────┘
   总卡数 = TP × PP × DP
```

- **张量并行 TP**：把一层的大矩阵按列/行切给多张卡，各算一部分再拼接（通信密集，放在同机 NVLink 内）。
- **流水线并行 PP**：把 70 层切成几段，分给不同卡组，像工厂流水线一样接力。
- **数据并行 DP**：复制多份模型，各喂不同 batch，再用 all-reduce 同步梯度。

BLOOM 用了 TP=4、PP=12（约）等配置组合，这正是 AI-Infra 工程师最该研究的"真实超大模型并行落地案例"。

## 7. HuggingFace 代码结构

BLOOM 在 `transformers` 库中的实现类层级（也就是原文件给出的骨架）：

```
BloomGelu              ← GELU 激活（带近似实现）
BloomAttention         ← 多头自注意力 + ALiBi 偏置
BloomMLP               ← 前馈网络：Linear→GELU→Linear
BloomBlock             ← 一个 Transformer 层 = LN+Attn+残差 + LN+MLP+残差
BloomPreTrainedModel   ← 抽象基类：权重初始化、ALiBi 斜率计算等
  ├─ BloomModel(BloomPreTrainedModel)        ← 主干：Embedding+EmbeddingLN+70×Block
  └─ BloomForCausalLM(BloomPreTrainedModel)  ← 主干 + LM 头（输出 V=250680 维 logits）
```

对应数据流（从一句话到下一个 token 的概率）：

```
  "我爱"  ─tokenizer→ [id1,id2]
     │
     ▼  BloomModel
  Embedding(250680×14336) ─► Embedding LayerNorm
     │
     ▼  70 × BloomBlock（每个含 ALiBi 注意力）
  最后一层隐藏态 h  (T×14336)
     │
     ▼  BloomForCausalLM 的 LM 头  (14336×250680)
  logits (T×250680) ─softmax→ 下一个词概率 → "北"? "你"? …
```

要点：
- `BloomAttention` 里**不计算位置嵌入**，而是构造 ALiBi 偏置矩阵加到 attention score 上。
- `BloomForCausalLM` 的 LM 头通常与输入 Embedding **权重共享（tied）**，节省 $250680\times14336\approx 36$ 亿参数。

## 9. 数值例子 / 手算

### 9.1 参数量从哪来（估算 176B）

主要来自 70 层 Transformer。单层参数 ≈ 注意力（$4d^2$）+ MLP（$8d^2$）= $12d^2$：

$$
12 \times d_{model}^2 = 12 \times 14336^2 \approx 12 \times 2.055\times10^8 \approx 2.47\times10^9
$$

70 层：

$$
70 \times 2.47\times10^9 \approx 1.73\times10^{11} = 173\text{B}
$$

再加 Embedding $V\times d = 250680\times14336\approx 3.6\times10^9$（约 3.6B，因 tied 只算一份）→ 合计 ≈ **176B**。✓ 和官方数字吻合。

### 9.2 推理显存：176B 装得下吗？

权重显存（不同精度）：

$$
\text{显存} = \text{参数量} \times \text{每参数字节数}
$$

| 精度 | 每参数字节 | 176B 权重显存 |
|---|---|---|
| fp32 | 4 | $176\times10^9\times4 = 704$ GB |
| fp16/bf16 | 2 | $352$ GB |
| int8 | 1 | $176$ GB |

结论：即使 fp16 也要 **352GB**，**单张 80GB A100 装不下**，至少需要 5–8 张卡做张量并行才能推理（这正是 BLOOM 推理也得讲并行的原因）。int8 量化后可压到 ~176GB，仍需多卡。

### 9.3 训练算力：要多少 FLOPs？

经验公式：训练总算力 $\approx 6 \times N \times D$（$N$=参数量，$D$=训练 token 数，系数 6 含前向+反向）：

$$
6 \times 176\times10^9 \times 366\times10^9 \approx 3.86\times10^{23}\ \text{FLOPs}
$$

按 384 张 A100、单卡有效算力约 150 TFLOP/s（实际利用率打折，以官方为准）：

$$
\text{时间} \approx \frac{3.86\times10^{23}}{384 \times 150\times10^{12}} \approx 6.7\times10^{6}\ \text{秒} \approx 78\ \text{天}
$$

量级与官方公布的约 3.5 个月相符（含数据加载、checkpoint、重启等开销）。✓ 这说明"176B 训练 ≈ 几百张 A100 跑几个月"是真实门槛。

| 问题 | 解答 |
|---|---|
| BLOOM 是谁做的？ | BigScience 协作项目，Hugging Face 发起，1000+ 研究者，法国公共算力训练 |
| BLOOM 用什么位置编码？ | **ALiBi**（线性偏置），不用绝对位置嵌入，外推友好 |
| ALiBi 和 RoPE 区别？ | ALiBi 在 score 上按距离"扣分"、不加位置向量；RoPE 把位置编成旋转角乘进 Q/K（见 [[llm-algo/旋转编码RoPE]]） |
| 为什么加 Embedding LayerNorm？ | 提升 176B 训练稳定性，防止初期 loss spike |
| 支持多少语言？ | 46 种自然语言 + 13 种编程语言，语料 ROOTS 约 1.6TB |
| BLOOM 比 GPT-3 强吗？ | 规模相当；纯英文未必更强，但**开源、多语言、可复现**是其独有价值 |
| 能在单卡跑 176B 吗？ | 不能。fp16 权重 352GB，需多卡张量并行；有 560M–7B 小版本可单卡用 |
| BLOOM 最大历史意义？ | **第一个权重/数据/训练日志/碳足迹全部公开的超大模型**，开放科学的里程碑 |
| BLOOMZ 是什么？ | BLOOM 的指令微调版（在 xP3 多语言指令数据上微调），zero-shot 跨语言泛化更好 |
