## 0. 一句话锚点

**`config.json` 是模型的"身份证 + 施工图"**：它不含任何权重数值，只用几十个超参数描述"这个网络长什么样"。`AutoModelForCausalLM.from_pretrained` 先读 config 把**空骨架**搭出来（决定每个矩阵的形状），再把 `*.safetensors` 里的权重灌进去。所以——

> **改 config 的结构字段 = 改网络形状 = 权重对不上号会直接报错**；改采样字段（在 `generation_config` 里）才是"安全的运行时旋钮"。

记忆钩子：**结构字段定形状（建图期），生成字段定行为（推理期）**。

## 1. 地基：config.json 从哪来、怎么驱动建网络

### 1.1 它在哪

每个 Qwen 模型仓库根目录都有两个 JSON：

```
Qwen2.5-7B-Instruct/
├── config.json              ← 结构字段（本文 §2–§6）：建图用
├── generation_config.json   ← 生成字段（本文 §9）：generate() 默认值
├── model.safetensors.*      ← 真正的权重
└── tokenizer.json / merges  ← 分词器
```

### 1.2 一个最小 Qwen2 config 长这样（字段名以官方为准）

```jsonc
{
  "architectures": ["Qwen2ForCausalLM"],
  "hidden_size": 3584,                // d：每个 token 的向量维度
  "num_hidden_layers": 28,            // L：Decoder Block 堆几层
  "num_attention_heads": 28,          // Q 头数
  "num_key_value_heads": 4,           // KV 头数（GQA，<Q 头数）
  "intermediate_size": 18944,         // FFN 中间维 d_ff
  "vocab_size": 152064,               // 词表大小 V
  "max_position_embeddings": 32768,   // 训练/支持的最长序列
  "rope_theta": 1000000.0,            // RoPE 的 base
  "rms_norm_eps": 1e-6,               // RMSNorm 稳定项
  "tie_word_embeddings": false,       // 输入输出 embedding 是否共享
  "torch_dtype": "bfloat16"
}
```

### 1.3 字段如何变成矩阵形状

```
config 字段                网络里被它决定的张量形状
─────────────────────────────────────────────────────────
hidden_size = d        ─►  embedding: [V, d]；每个残差流宽度 = d
num_attention_heads    ─►  Q 投影: [d, n_q · head_dim]
num_key_value_heads    ─►  K,V 投影: [d, n_kv · head_dim]  ← GQA 在这变窄
head_dim (= d / n_q)   ─►  单头维度；softmax 缩放用 √head_dim
intermediate_size      ─►  gate/up: [d, d_ff]；down: [d_ff, d]
num_hidden_layers = L  ─►  上面这一坨 ×L
vocab_size = V         ─►  LM head: [d, V]
```

**关键认知**：config 里没有一个数是"装饰"，每个数都唯一确定某个 `nn.Linear` 的 `in_features`/`out_features`。这也是为什么下文能纯靠 config 把参数量算到个位。

## 2. 结构字段（决定形状的核心五件套）

### 2.1 `hidden_size`（记作 $d$）

每个 token 在残差流中的向量维度，是全网最核心的"宽度"。几乎所有矩阵都带一个 $d$，参数量对 $d$ 是**平方级**敏感（见 §7）。直觉：$d$ 翻倍，注意力和 FFN 的矩阵参数约翻 4 倍。

### 2.2 `num_hidden_layers`（记作 $L$）

Decoder Block 堆叠层数，决定"深度"。参数量对 $L$ 是**线性**敏感。深度给抽象层级，宽度给单层容量；同参数预算下深/宽的取舍是架构设计的经典权衡。

### 2.3 `num_attention_heads`（$n_q$）与 `head_dim`

注意力把 $d$ 维切成 $n_q$ 个"头"，每头独立做一套注意力，再拼回。通常

$$\text{head\_dim} = \frac{d}{n_q}, \qquad d = n_q \times \text{head\_dim}$$

多头的意义：不同头可以关注不同子空间（语法/指代/位置等），比单头 $d$ 维更有表达力。注意：注意力的**计算量主要由 $n_q$、序列长决定**，而**显存（KV cache）由下面的 $n_{kv}$ 决定**——这是 GQA 能省显存的根。

### 2.4 `num_key_value_heads`（$n_{kv}$）—— GQA 的开关

K、V 只用 $n_{kv}$ 个头（$n_{kv} \le n_q$，且 $n_q$ 必须能被 $n_{kv}$ 整除）。每 $\frac{n_q}{n_{kv}}$ 个 Q 头共享一组 KV：

```
n_q = 28, n_kv = 4  →  分组比 = 7
Q:  [q0 q1 q2 q3 q4 q5 q6] [q7 ... q13] [q14...] [q21...]
            共享 ↓             ↓            ↓         ↓
KV:        k/v 0            k/v 1        k/v 2     k/v 3
```

- $n_{kv} = n_q$ → 退化为 **MHA**（最费显存）；
- $n_{kv} = 1$ → **MQA**（最省，质量略降）；
- 中间值 → **GQA**（Qwen2+ 全系采用）。

含义层面记住一句：**$n_{kv}$ 是"显存预算"旋钮，调小直接按 $\frac{n_q}{n_{kv}}$ 倍压缩 KV cache，几乎不动主干算力。**

### 2.5 `intermediate_size`（$d_{ff}$）

FFN（SwiGLU）的中间膨胀维。Qwen 用门控 FFN，有 gate/up/down 三个矩阵（详见 [[llm-algo/qwen/README]] §4）。$d_{ff}$ 越大单层表达力越强，但它是参数量大头（约占单层 2/3）。因 SwiGLU 比普通 FFN 多一个矩阵，$d_{ff}$ 常取约 $\frac{2}{3}\times 4d$ 来平衡总参数。

### 2.6 ASCII：五件套如何拼成一个 Block

```
        x (d=hidden_size)
         │
      RMSNorm
         │
  ┌──────┴───────── Attention ─────────────┐
  │  Q:[d, n_q·hd]   K,V:[d, n_kv·hd]       │   hd = head_dim
  │  RoPE 注入 Q,K → softmax(QKᵀ/√hd)V → O  │
  └──────┬──────────────────────────────────┘
        (+) 残差
         │
      RMSNorm
         │
  ┌──────┴────── SwiGLU FFN ────────────────┐
  │  gate,up:[d, d_ff]   down:[d_ff, d]      │
  └──────┬──────────────────────────────────┘
        (+) 残差   ── 这整块 × L 层
```

## 3. 位置与长度字段

### 3.1 `max_position_embeddings`

训练/官方支持的**最长序列长度**（如 32768）。它不是硬上限——RoPE 可外推——但超过它需要 YaRN/DCA 等手段（见 README §8），否则注意力可能崩坏。

### 3.2 `rope_theta`（RoPE 的 base，记作 $\theta_{\text{base}}$）

RoPE 各维旋转频率 $\theta_i = \theta_{\text{base}}^{-2i/d}$。

- base 默认 $10^4$；**Qwen 长文模型调到 $10^6$**。
- base 调大 → 所有频率变小 → 旋转变慢 → 同样 token 距离的角度跨度变小 → **长上下文外推更平滑**。

这是"想要更长窗口就把 base 调大"的最底层原因（RoPE 手算见 [[llm-algo/qwen/README]] §2.4）。

### 3.3 `rope_scaling`（可选）

一个嵌套字段，声明外推方式，如 `{"type": "yarn", "factor": 4.0}`。`factor=4` 表示把窗口从 base 长度扩 4×。不写则不外推。具体子字段以官方 config 为准。

### 3.4 `sliding_window` / `max_window_layers`（部分模型）

滑动窗口注意力：每个 token 只看最近 $w$ 个 token，把注意力复杂度从 $O(S^2)$ 降到 $O(S\cdot w)$。`max_window_layers` 控制只在前若干层用滑窗。是否启用、阈值以官方 config 为准（很多 Qwen2.5 默认不启用全局滑窗）。

```
全局注意力:  token_t 看 [0 .. t]          → 距离越长越费
滑动窗口  :  token_t 看 [t-w .. t]         → 恒定窗口，省算力/显存
```

## 4. 词表与共享字段

### 4.1 `vocab_size`（$V$）

分词器的 token 总数（Qwen 约 15.2 万，超大）。它决定两个最大的矩阵：input embedding `[V, d]` 与 LM head `[d, V]`。大词表把中文/多语言/代码编码得更短（省 token），代价是这两块参数巨大——在小模型里占比可达 30%+。

### 4.2 `tie_word_embeddings`

是否让**输入 embedding 与输出 LM head 共享同一份权重**：

- `true`（共享）：省下一个 $V\times d$ 矩阵的参数。小模型（如 0.5B/1.5B）常开，因词表参数占比高。
- `false`（不共享）：两份独立权重，表达力略强。大模型常关。

> 算参数量时这是个 ±$V\times d$ 的大头，**务必先看这个字段**。

## 5. 数值稳定字段（原文已涉及，补到位）

### 5.1 `rms_norm_eps`

RMSNorm 公式 $\dfrac{x}{\sqrt{\frac{1}{d}\sum x_i^2 + \epsilon}}\cdot\gamma$ 里分母的 $\epsilon$（典型 $10^{-6}$）。

**为什么需要它**：当某个 token 的向量全为 0 或极小，均方根 $\to 0$，除法会变成"除以 0"产生 `inf/NaN`。$\epsilon$ 是一个微小正数，保证分母**永远不为 0**，让归一化数值稳定。它太大会轻微改变缩放尺度，太小起不到保护作用，故取一个很小的常数。它**不是可学习参数**，是固定常量。

### 5.2 `initializer_range`

训练**从零开始时**权重初始化用的截断正态分布标准差（典型 0.02）。即权重从 $\mathcal{N}(0, 0.02^2)$ 截断采样。

**为什么是这个值**：标准差太大 → 前向激活逐层放大 → 梯度爆炸；太小 → 激活逐层衰减 → 梯度消失。0.02 是经验上让深层 Transformer 初始信号尺度稳定的常用值。**截断**（truncated）指砍掉 ±2σ 外的极端值，避免个别异常大权重。

> 重要：**加载预训练权重时这个字段无效**——它只在 `from_config`（随机初始化）时起作用。微调/推理时它躺在 config 里不参与计算。

## 6. attention 细节字段

### 6.1 QKV 的 bias（Qwen 标志性细节）

Qwen 的 **Q、K、V 投影带 bias**，而 O 投影和 FFN/embedding 无 bias（LLaMA 全程无 bias）。带 bias 让每个头的投影多一个可学习偏移，经验上略增表达力/稳定性，参数代价极小（$+n_q\cdot hd + 2\,n_{kv}\cdot hd$ 每层，相对矩阵可忽略）。这是 Qwen 与 LLaMA 在 config/权重层面最易识别的差异。

### 6.2 `attention_dropout`

注意力权重上的 dropout 概率。预训练大模型通常为 0（数据足够，不靠 dropout 正则）。微调小数据时可调大防过拟合。推理时 dropout 自动关闭。

### 6.3 `torch_dtype`

权重存储精度（`bfloat16`/`float16`/`float32`）。它**直接决定权重显存**：每参数 fp32=4B、fp16/bf16=2B、int8=1B、int4≈0.5B。算显存第一步就看它（见 §8）。

## 7. 从 config 手算参数量（一行公式 + 全程手算）

### 7.1 单层公式（GQA 版）

记 $d$=hidden，$d_{ff}$=intermediate，$hd$=head_dim，$n_q$/$n_{kv}$=Q/KV 头数。每个 Decoder 层：

$$P_{\text{layer}} = \underbrace{d(n_q\,hd) + 2\,d(n_{kv}\,hd) + d(n_q\,hd)}_{\text{Q,K,V,O 投影}} + \underbrace{3\,d\,d_{ff}}_{\text{SwiGLU 三矩阵}}$$

加上 embedding 与 head：

$$P_{\text{total}} \approx L\cdot P_{\text{layer}} + V\,d \times (\text{tie? }1:2)$$

### 7.2 用 Qwen2-7B 配置全程手算

取 $d=3584,\ d_{ff}=18944,\ hd=128,\ n_q=28,\ n_{kv}=4,\ L=28,\ V=152064,\ \text{tie}=\text{false}$。

**Attention 投影**（$n_q\cdot hd=3584$，$n_{kv}\cdot hd=512$）：

$$d(3584) + 2\,d(512) + d(3584) = 3584(3584+512+512+3584)=3584\times 8192 \approx 2.94\times10^7$$

**FFN（SwiGLU 三矩阵）**：

$$3\times 3584\times 18944 \approx 2.04\times10^8$$

**单层合计**：$2.94\times10^7 + 2.04\times10^8 \approx 2.33\times10^8$（FFN 占约 87%）。

**所有层**：$28 \times 2.33\times10^8 \approx 6.52\times10^9$（约 65 亿）。

**embedding + head（不共享，两份）**：$2\times 152064\times 3584 \approx 1.09\times10^9$（约 11 亿）。

**总计**：$6.52\times10^9 + 1.09\times10^9 \approx 7.6\times10^9$ ≈ **7.6B**，与官方"7B"量级吻合（差异来自 norm 的 $\gamma$、bias 等小项及配置近似）。

> 一行速记（与 [[llm-algo/FLOPs]] 的 $12Ld^2$ 对应）：**主干 ≈ $L\cdot(4d^2_{\text{有效}} + 3d\,d_{ff})$，再加 $V\,d$ 的词表头。** GQA 让 K/V 项从 $2d^2$ 缩到 $2d\cdot n_{kv}hd$。

## 8. 从 config 手算显存（权重 + KV + 激活）

显存 = **权重** + **KV cache** + **激活/中间量** + 框架开销。前两块能纯靠 config 算。

### 8.1 权重显存

$$\text{权重显存} = P \times \text{每参数字节数（看 torch\_dtype）}$$

7.6B 模型：bf16 → $7.6\times10^9 \times 2 \approx 15.2\,\text{GB}$；int4 量化 → $\approx 3.8\,\text{GB}$。这是"模型能不能装进卡"的第一道门槛。

### 8.2 KV cache 显存（推理长序列的隐形大户）

$$\text{KV bytes} = 2 \times L \times S \times (n_{kv}\times hd) \times \text{bytes}$$

（系数 2 = K 和 V 各一份；$S$=当前序列长，含 batch 时再乘 $b$。）

7B 配置（$L=28,\ n_{kv}\cdot hd=512$），$S=32768$，bf16：

$$2\times 28\times 32768 \times 512 \times 2 \approx 1.88\times10^9 \approx 1.9\,\text{GB}$$

对比若用 MHA（$n_q=28$，$n_q\cdot hd=3584$）则是 $\approx 13\,\text{GB}$ → **GQA 省到约 1/7**（=分组比）。这就是 $n_{kv}$ 这个 config 字段的真金白银价值。

### 8.3 三块叠加直觉

```
总显存 ≈  权重(看 dtype，固定)
        + KV cache(随 batch×序列长 线性增长)  ← 长上下文/高并发的瓶颈
        + 激活(随 batch×序列长，可被 flash-attn/重计算压缩)
        + 框架/碎片开销(经验上再 +10~20%)
```

容量规划口诀：**短序列看权重，长序列看 KV，训练看激活与优化器状态。**（KV 公式同源见 [[llm-algo/FLOPs]] §6。）

## 9. generate() 采样参数（运行时旋钮）

这些**不在 config.json**，而在 `generation_config.json`，或调用 `model.generate(...)` 时临时传。它们不改网络，只改"从 logits 怎么挑下一个 token"。

### 9.1 采样总流程 ASCII

```
模型输出 logits (V 维)
   │
   ▼ ÷ temperature        ← 调"分布陡峭/平缓"
softmax → 概率分布
   │
   ▼ top_k 截断           ← 只留概率最高的 k 个
   ▼ top_p(nucleus) 截断  ← 留累计概率达 p 的最小集合
   ▼ repetition_penalty   ← 压低已出现 token 的分数
   │
   ▼ 重新归一化 → 按概率采样 / 或 greedy 取 argmax
   ▼ 直到 eos 或 max_new_tokens
下一个 token
```

### 9.2 逐参数含义与权衡

| 参数 | 含义（最底层） | 调大 / 调小的效果 |
|------|----------------|--------------------|
| `do_sample` | 采样(True) vs 贪心 argmax(False) | False 确定且可复现；True 才有多样性 |
| `temperature` $T$ | logits 除以 $T$ 再 softmax | $T\to0$ 趋近贪心（更稳/更死板）；$T>1$ 更随机/有创意；$T=1$ 原始分布 |
| `top_k` | 只在概率最高的 $k$ 个里采样 | 小 $k$ 更保守安全；大 $k$/0(不截) 更发散 |
| `top_p`（nucleus） | 取累计概率 $\ge p$ 的最小候选集 | 比 top_k 更自适应（分布尖时候选少、平时多）；常 0.8~0.95 |
| `repetition_penalty` | 对已生成 token 的 logit 除以惩罚系数 | >1 抑制复读；过大伤流畅度 |
| `presence/frequency_penalty` | 按是否出现/出现次数减分 | 控复读与话题漂移（部分接口提供） |
| `max_new_tokens` | 最多新生成多少 token | 控长度上限与延迟（与输入长度无关，比 `max_length` 直观） |
| `min_new_tokens` | 最少生成多少 | 防过早 eos 截断 |
| `num_beams` | beam search 宽度 | >1 找更"高概率整句"，慢、偏死板；聊天通常 =1 |
| `eos_token_id` / `pad_token_id` | 终止符 / 填充符 id | 配错会不停或对齐错乱 |
| `stop_strings` | 命中即停的字符串 | 配合对话模板停在角色边界 |

### 9.3 数值直觉：temperature 怎么改分布

设两个 token 的 logits 为 $(2.0, 1.0)$。

- $T=1$：softmax → $(\,e^2,e^1\,)$ 归一 $\approx(0.73, 0.27)$。
- $T=0.5$（÷0.5 = 放大到 $4.0,2.0$）：$\approx(0.88, 0.12)$ → **更尖锐、更确定**。
- $T=2$（÷2 = 压到 $1.0,0.5$）：$\approx(0.62, 0.38)$ → **更平、更随机**。

一句话：**温度是"信心放大器"——降温让模型更笃定，升温让它更敢冒险。**

### 9.4 实践要点

- 聊天/对话：常用 `do_sample=True, temperature≈0.7, top_p≈0.8`（具体默认以 Qwen 官方 `generation_config.json` 为准）。
- 代码/数学/抽取：偏向低温甚至贪心，要可复现就 `do_sample=False`。
- `top_k` 与 `top_p` 常二选一或叠加；nucleus（top_p）更主流。
- **想完全复现**：固定 `seed`、`do_sample=False`、相同框架/精度——否则同一 prompt 也可能不同输出。

## 数值对照 / 实践要点速查

| 你想知道 | 看哪个 config 字段 | 一行算法 |
|----------|--------------------|----------|
| 模型多大（参数量） | hidden/layers/heads/kv/intermediate/vocab/tie | $L(4d^2_{\text{eff}}+3dd_{ff})+Vd(\text{tie?}1{:}2)$ |
| 权重占多少显存 | + torch_dtype | $P\times$ 字节数（bf16=2） |
| 长序列吃多少 KV | num_key_value_heads, head_dim, layers | $2LS(n_{kv}hd)\times$ 字节 |
| 能开多长窗口 | max_position_embeddings, rope_theta, rope_scaling | 超出需 YaRN/DCA |
| 是 MHA/GQA/MQA | num_attention_heads vs num_key_value_heads | 相等=MHA，1=MQA，之间=GQA |
| 小模型省参数招 | tie_word_embeddings | true 省一份 $Vd$ |
| 输出随机性 | （generation_config）temperature/top_p/top_k | 温度=信心放大器 |

> 提醒：以上区分"**含义恒成立**"与"**具体数值以官方 config / 技术报告为准**"。结构字段会随模型尺寸变，本文数字是 7B 量级的近似演示。

## 常见问题

| 问题 | 踩点答案 | 追问 / 陷阱 |
|------|----------|-------------|
| config 改了为什么加载报错？ | 结构字段改了→矩阵形状变→和 safetensors 权重对不上 | 只有 generation 字段能安全运行时改 |
| 怎么一眼看出是不是 GQA？ | `num_key_value_heads < num_attention_heads` 即 GQA | 相等是 MHA，=1 是 MQA |
| head_dim 怎么来？ | 一般 $= d / n_q$；少数模型显式给 `head_dim` | 别假设永远整除，看 config |
| rms_norm_eps 作用？ | 防分母为 0 的稳定项，非可学习参数 | 太大轻微改尺度，太小失保护 |
| initializer_range 推理时有用吗？ | 没用，只在随机初始化（from_config）时生效 | 加载预训练权重时被覆盖 |
| 为什么 Qwen 的 QKV 有 bias？ | Qwen 标志性设计，略增表达/稳定，代价极小 | LLaMA 全程无 bias，可据此区分 |
| 怎么纯靠 config 估参数量？ | $L(4d^2_{\text{eff}}+3dd_{ff})+Vd$，先看 tie | FFN 占大头（~2/3）；GQA 缩 K/V 项 |
| 长序列显存为什么暴涨？ | KV cache 随 $L\times S\times n_{kv}hd$ 线性涨 | 调小 $n_{kv}$ 或量化 KV |
| temperature 和 top_p 区别？ | 温度改分布形状，top_p 改候选集合 | 二者可叠加；要确定就贪心 |
| 想复现输出怎么办？ | `do_sample=False` + 固定 seed/精度/框架 | 采样默认开时同 prompt 也会变 |
