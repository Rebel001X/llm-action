## 0. 一句话锚点

**LLM = 一个超大的"下一个 token 概率预测器"，用 Transformer 实现，在海量文本上预训练、再微调对齐，推理时一个一个 token 自回归地往外吐字。**

记住这一句，后面所有概念都是它的展开。

---

## 1. 地基：文本是怎么变成数字的(Token / Tokenizer)

模型内部全是矩阵乘法和加法，**只能处理数字**。所以第一步必须把文字切成小块、再映射成整数 ID。这个小块叫 **token**。

- 一个 token 不等于一个字，也不等于一个单词。常见做法是 **BPE / BBPE**(字节对编码)：把高频字符组合合并成一个 token。
- 经验值(英文)：1 token ≈ 0.75 个英文单词 ≈ 4 个字符；中文一个汉字常常是 1~2 个 token。

```
原文:  "我爱 LLM"
          │  分词器(tokenizer)
          ▼
tokens: [ "我", "爱", " LL", "M" ]
          │  查词表 → 整数 ID
          ▼
ids:    [ 1182,  9043,  29871, 44 ]
          │  查 embedding 表(每个 ID 一行向量)
          ▼
向量:   [ [0.1,-0.3,...],  [...],  [...],  [...] ]   形状 = (4, d_model)
```

**为什么要 token 而不是直接用字符？** 字符太细(序列变长、算力爆炸)，整词太粗(词表无穷大、未登录词没法表示)。token 是"长度"和"词表大小"之间的折中。

**为什么和钱有关？** API 按 token 计费，上下文长度按 token 计数。算 token 数能直接估成本和能不能塞下。

## 2. 参数(Parameters)：知识存在哪

**参数 = 模型里一大堆可学习的浮点数(权重 weight + 偏置 bias)。** 训练就是不断微调这些数，让预测更准；推理时这些数固定不动。

"7B 模型"指约 70 亿个参数。参数主要分布在：

- **Embedding 表**：`词表大小 × d_model`
- **每层 Attention**：Q/K/V/O 四个投影矩阵，各约 `d_model × d_model`
- **每层 FFN(前馈)**：两个大矩阵 `d_model × d_ff`，通常 `d_ff = 4·d_model`(SwiGLU 结构里会拆成 3 个矩阵，见 [[llm-algo/transformer/模型架构]])

```
参数总量(粗算) ≈ 层数 L × ( Attention 参数 + FFN 参数 )
              ≈ L × ( 4·d_model² + 2·(4·d_model²) )      ← FFN 约是 Attn 的 2 倍
              ≈ 12 · L · d_model²
```

**显存换算(关键直觉)**：1 个 FP16 参数 = 2 字节。
- 仅加载 7B 模型权重(FP16)：`7e9 × 2 字节 = 14 GB`。
- 这就是"7B 模型至少要 ~14GB 显存才能推理"的来源。INT8 量化后 ≈ 7GB，INT4 ≈ 3.5GB。详见 [[llm-algo/FLOPs]] 的显存章节。

## 3. 上下文窗口(Context Window):一次能看多远

**上下文窗口 = 模型一次前向能同时处理的最大 token 数(输入 + 已生成)。** 比如 8K、128K、1M。

为什么有上限？两个原因：
1. **位置编码**(如 RoPE，见 [[llm-algo/transformer/模型架构]])在训练时只见过有限长度，外推会失真。
2. **注意力是平方复杂度**：序列长 $n$，注意力矩阵是 $n \times n$。

```
注意力计算量 ∝ n²      显存(KV Cache) ∝ n
n=1K   → 1,000,000 对打分          n=128K → 16,384,000,000 对打分
                                   (长上下文为何这么贵的根源)
```

超出窗口怎么办：滑动窗口、丢弃最早的 token、或用 RAG/记忆把外部信息按需塞进窗口。

---

## 4. 自回归(Auto-Regressive):一次只吐一个 token

LLM 是 **自回归**模型：给定前面所有 token，预测**下一个** token 的概率分布；采一个出来，拼回输入，再预测下一个。如此循环，直到遇到结束符或达到长度上限。

形式化：模型把一句话的联合概率拆成连乘
$$
P(x_1, x_2, \dots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, \dots, x_{t-1})
$$
每一步只学一个条件概率 $P(x_t \mid x_{<t})$。这就是预训练的"猜下一个词"目标。

```
输入: 我 爱
  step1: P(?|我,爱) → 采样 → "学"        序列: 我 爱 学
  step2: P(?|我,爱,学) → 采样 → "习"      序列: 我 爱 学 习
  step3: P(?|我,爱,学,习) → 采样 → <eos>  停止
```

**为什么训练时用 Causal Mask(因果掩码)？** 训练时整句话一次性喂进去并行算，但预测第 $t$ 个 token 时**不能偷看**第 $t$ 个及以后的内容，否则就是抄答案。掩码把"未来"位置的注意力分数置成 $-\infty$。

```
Causal Mask (n=4，✓可见 ✗屏蔽):
        看 我 爱 学
预测我  ✓  ✗  ✗  ✗
预测爱  ✓  ✓  ✗  ✗
预测学  ✓  ✓  ✓  ✗
预测习  ✓  ✓  ✓  ✓
```

## 5. 从 logits 到文字:概率与采样

模型最后一层输出每个词表 token 的**原始分数 logits**，经 **softmax** 变成概率，再**采样**选一个。

$$
p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

其中 $T$ 是 **temperature(温度)**：$T{=}0$ 退化成贪心(永远选最大，确定性)；$T$ 越大分布越平、越随机。

控制采样的常见旋钮：
- **top-k**：只在概率最高的 k 个里采。
- **top-p(nucleus)**：累积概率到 p 的最小集合里采。

> 一个数值例子见下方"数值示例"节。

## 6. 预训练(Pre-training):打通用地基

**预训练 = 在海量无标注文本(网页、书、代码…万亿 token 级)上做自回归"猜下一个词"。** 不需要人工标注——文本本身就是答案(下一个词就是标签)，这叫**自监督**。

产物叫 **base model(基座模型)**：知识丰富、会续写，但**不会聊天、不听指令**(你问它问题，它可能继续编更多问题)。

- 训练目标:最小化交叉熵 / 等价于最小化 **困惑度 perplexity** $\text{PPL}=e^{\text{loss}}$。
- 代价极大:训练算力 $\approx 6 \times N_{\text{参数}} \times N_{\text{token}}$ FLOPs(推导见 [[llm-algo/FLOPs]])。

```
预训练         微调(SFT)        对齐(RLHF/DPO)
万亿 token      几万~几十万条      偏好数据/奖励
无标注          指令-回答对        人类排序
   │               │                  │
   ▼               ▼                  ▼
[base 模型] → [听话会答题] → [有用·无害·讨喜]
 懂世界          懂格式            懂偏好
```

---

## 7. 微调(Fine-tuning):学会按格式答题

**微调 = 在小而精的"指令-回答"数据上继续训练 base 模型**，让它学会"看到问题就给答案"的对话格式。这一步常称 **SFT(Supervised Fine-Tuning，监督微调)**。

- **全参微调**：更新所有参数，效果好但显存/算力贵。
- **PEFT(参数高效微调)**：只训练极少量新增参数，如 **LoRA**——把权重更新近似成两个小矩阵的乘积 $\Delta W = BA$($A,B$ 远小于 $W$)，省显存、可插拔。详见 [[llm-algo/训练范式]]。

为什么微调用的数据这么少也有效？因为知识在预训练阶段已经学好了，微调只是"激活+对齐格式",不是重新学世界。

---

## 8. 对齐(Alignment):有用·无害·符合偏好

光会答题不够，还要答得**有用(helpful)、无害(harmless)、诚实(honest)**。对齐就是把模型的输出"拉"向人类偏好。

主流两条路线：

1. **RLHF(基于人类反馈的强化学习)**：先训一个**奖励模型(RM)** 学人类对回答的排序偏好，再用 PPO 等 RL 算法让 LLM 去最大化奖励。
2. **DPO(直接偏好优化)**：跳过显式奖励模型，直接用"好答案 > 坏答案"的偏好对，把偏好写进一个分类式损失里，更简单稳定。

```
RLHF:  偏好数据 → 训练奖励模型 RM → RL(PPO) 优化策略 LLM
DPO:   偏好数据 ───────────────────→ 直接优化 LLM (一个损失搞定)
```

对齐后的模型才是你日常用到的"聊天助手"。训练范式细节见 [[llm-algo/训练范式]]。

## 9. 涌现(Emergent Abilities):规模过阈值才冒出来

**涌现能力 = 小模型几乎为零、模型规模(参数/数据/算力)超过某个阈值后突然显著出现的能力。** 例如多步推理、少样本上下文学习(in-context learning)、思维链(CoT)。

```
能力
 ▲
 │                         ╭──── 大模型:能力跃升
 │                        ╱
 │  ____________________╱     ← 阈值前几乎随机
 └──────────────────────────► 规模(参数/算力，对数轴)
```

**为什么叫涌现？** 在某个尺度下随机水平，再大一点忽然"会了"，不是平滑长出来的——这让"能力预测"变难。注：也有研究指出部分"涌现"是评测指标(全对才算分)造成的视觉效应，连续指标下其实是渐变。理解为"非线性、依赖规模"即可。

## 10. Scaling Law(缩放定律):性能可预测地随规模提升

**Scaling Law = 模型测试损失随参数量 $N$、数据量 $D$、算力 $C$ 呈幂律下降的经验规律。** 它让你**在小规模实验就能外推大模型表现**，从而合理分配训练预算。

近似形式(只看一个变量时)：
$$
L(N) \approx L_\infty + \left(\frac{N_c}{N}\right)^{\alpha}
$$
$L_\infty$ 是不可约损失(语言本身的熵)，指数 $\alpha$ 通常是零点几——意味着**损失下降很慢，要数量级的投入换一点点提升**。

**Chinchilla 最优**(关键工程结论)：给定算力预算，**参数量 $N$ 和训练 token 数 $D$ 应大致同比例增长**，经验上 $D \approx 20 \times N$。早期大模型普遍"参数太大、数据太少",其实"训练不充分"。

```
固定算力 C ≈ 6·N·D 下，怎么花？
  方案A: N 大 D 小  → 参数没喂饱，欠训练 ✗
  方案B: N 小 D 大  → 模型太小，装不下 ✗
  方案C: N、D 同步放大(D≈20N) → Chinchilla 最优 ✓
```

详细 FLOPs/算力推导见 [[llm-algo/FLOPs]]。

## 11. 推理两阶段:Prefill(并行) + Decode(串行)

LLM 推理一次请求分两段，性能特性完全不同——这是部署优化的核心。

| 阶段 | 做什么 | 并行性 | 瓶颈 | 一次处理 token 数 |
|---|---|---|---|---|
| **Prefill(预填充)** | 把整段 prompt 一次性前向，建立 KV Cache | 高(整段并行) | 算力(compute-bound) | 全部输入 token |
| **Decode(解码)** | 自回归一次生成 1 个 token | 低(必须串行) | 显存带宽(memory-bound) | 每步 1 个 |

**KV Cache 是关键**：Decode 时，前面 token 的 Key/Value 已经算过，缓存下来避免重复计算。代价是显存随生成长度线性增长。

```
请求: "翻译这句话: hello" → 生成 "你好"

[Prefill]  一次喂入  翻译 这 句 话 : hello   ── 5个token并行算 ──► 建好 KV Cache，吐第1个 token "你"
                                                                          │
[Decode]   "你" → 算1步 → "好"        (复用 KV Cache，只算新 token)        ▼
           "好" → 算1步 → <eos> 停止
            └─ 每步只 1 个 token，串行，受显存带宽限制
```

**为什么 Decode 是 memory-bound？** 每生成 1 个 token 都要把整个模型权重从显存读一遍，但只算了 1 个 token 的矩阵乘——算力闲置、带宽吃满。这就催生了批处理(batching)、量化、投机解码等优化。

## 数值示例 / 逐数手算

### 例 1:7B 模型推理显存(FP16)
- 权重:$7 \times 10^9 \times 2\text{ B} = 14\text{ GB}$
- KV Cache(单条、上下文 2048、`d_model=4096`、`L=32`、FP16):
  每 token 每层 K+V = `2 × 4096 × 2 B = 16384 B`；
  总计 `16384 × 32 层 × 2048 token ≈ 1.07 GB`。
- 合计 ≈ **15 GB 左右**(还没算激活值),所以"24GB 卡能跑 7B,跑不动同精度的 13B"。

### 例 2:softmax + temperature 采样
三个候选 logits $z = [2.0,\ 1.0,\ 0.0]$。

**$T=1$:** $e^2{=}7.389,\ e^1{=}2.718,\ e^0{=}1$，和 $=11.107$。
概率 $=[0.665,\ 0.245,\ 0.090]$ → 多数时候选第一个，偶尔冒险。

**$T=0.5$(更确定):** 指数变 $e^{z/0.5}=e^{2z}=[54.6,\ 7.389,\ 1]$，和 $=62.99$。
概率 $=[0.867,\ 0.117,\ 0.016]$ → 第一个几乎必选。**温度降低 → 分布变尖 → 更确定。**

### 例 3:预训练算力(FLOPs)
用经验式 $C \approx 6ND$。训练 7B 模型(N=7e9)用 1.4T token(D=1.4e12)：
$$C \approx 6 \times 7\times10^9 \times 1.4\times10^{12} \approx 5.9 \times 10^{22}\text{ FLOPs}$$
按 Chinchilla `D≈20N` 检验:$20 \times 7e9 = 1.4e11$,而我们用了 1.4e12,即 **数据是"最优"的 10 倍**——属于刻意过训练以换取推理期更省(小模型多喂数据)。推导细节见 [[llm-algo/FLOPs]]。

|---|---|---|---|---|

| 算力 | 极高(6ND) | 中 | 中-高 | 低(单次前向) |

|---|---|---|---|

| Decode(每 token) | $O(n d + d^2)$ | 读全部权重 | 显存带宽 |

## 常见问题

| 疑问 | 真相 |
|---|---|
| token 就是单词吗？ | 不是。是子词单元(BPE)，1 词可能拆成多个 token，中文 1 字常 1~2 token。 |
| 参数越多一定越强？ | 不一定。数据不够(欠训练)时大参数浪费，要按 Chinchilla `D≈20N` 配比。 |
| base 模型能直接当聊天机器人？ | 不能。base 只会续写，要经 SFT+对齐才会"听话答题"。 |
| 上下文越长越好？ | 长上下文显存/算力按 $n$、$n^2$ 涨，且超训练长度会失真,需要外推技巧。 |
| temperature=0 是没有随机？ | 是确定性贪心解码,每次选概率最大的 token(实现层面仍可能有微小非确定)。 |
| 涌现是魔法吗？ | 不是,是规模驱动的非线性现象,部分还受评测指标影响,可被 Scaling Law 部分预测。 |
| 为什么生成慢、对话快？ | 生成走串行 Decode(memory-bound,逐 token);Prefill 是并行的,所以读你的长 prompt 反而快。 |
| 微调会让模型忘掉旧知识吗？ | 可能(灾难性遗忘),所以常用小学习率/LoRA/混入通用数据缓解。 |
