## 0. 一句话锚点

GPT-2 = **N 层相同的 Transformer Decoder Block 堆叠**，每个 token 只能看见**它自己和它左边**的 token（因果注意力），模型被训练去**预测下一个 token**。把"预测下一个词"这一件事做到极致、再把模型和数据一起放大，就涌现出翻译、问答、摘要等能力——这就是 GPT-2 想证明的事。

## 1. 地基：语言建模到底在建什么

一句话（token 序列）$x = (x_1, x_2, \dots, x_T)$ 的联合概率，可以**无损地**按链式法则拆成一串条件概率：

$$
P(x_1,\dots,x_T) = \prod_{t=1}^{T} P(x_t \mid x_1,\dots,x_{t-1})
$$

**为什么这样拆？** 因为它把"建模一整句话"这个难题，变成"给定前缀、预测下一个词"这个可重复、可并行训练的子任务。GPT-2 用一个神经网络 $f_\theta$ 去拟合每个条件分布：

$$
P(x_t \mid x_{<t}) = \text{softmax}\big(f_\theta(x_{<t})\big)
$$

注意关键约束：预测 $x_t$ 时**只能用 $x_{<t}$**，绝不能偷看 $x_t$ 及之后。这个"不能偷看未来"的约束，在架构里就靠**因果注意力掩码**实现（见第 4 节）。

**自回归（autoregressive）**：生成时把模型自己上一步的输出，当作下一步的输入，一个一个 token 往外吐。

```
训练（teacher forcing，一次并行算全部位置）：
  输入:  [The] [cat] [sat] [on]
  目标:  [cat] [sat] [on]  [the]    ← 每个位置预测它的下一个

生成（自回归，逐步）：
  step1: [The]                 -> 预测 "cat"
  step2: [The][cat]            -> 预测 "sat"
  step3: [The][cat][sat]       -> 预测 "on"
         └ 上一步输出回灌成本步输入 ┘
```

## 2. 整体结构与数据流

GPT-2 是 **Decoder-only**：相比原始 Transformer，它**砍掉了 Encoder，也砍掉了 Decoder 里的 Cross-Attention**，只留下"带掩码的自注意力 + FFN"这一种 Block，堆 N 层。

```
                      token ids  (shape: [B, T])
                          │
              ┌───────────┴────────────┐
              │ WTE 词嵌入查表  [V,d]   │  ← token 含义
              │ WPE 位置嵌入查表 [n_ctx,d]│ ← token 位置
              └───────────┬────────────┘
                          │  逐元素相加  -> h0  [B,T,d]
                          ▼
        ┌──────────────  GPT2Block × N  ──────────────┐
        │   ┌────────────────────────────────────┐    │
        │   │ x ─► LN1 ─► 因果多头注意力 ─► (+x)  │    │  ← 残差
        │   │ y ─► LN2 ─► MLP(GELU) ─────► (+y)   │    │  ← 残差
        │   └────────────────────────────────────┘    │
        └──────────────────────┬──────────────────────┘
                               ▼
                     LN_f 最终 LayerNorm
                               ▼
                  lm_head: h · WTEᵀ   ->  logits [B,T,V]
                               ▼
                        softmax -> 下一个 token 概率
```

对应 HuggingFace 的类（与原文件呼应）：

| 类名 | 职责 |
|------|------|
| `GPT2LMHeadModel` | 最外层；= `GPT2Model` + `lm_head` 线性投影到词表，算 logits 与 loss |
| `GPT2Model` | 主干；WTE + WPE + N 个 `GPT2Block` + 末尾 `LN_f` |
| `GPT2Block` | 一层：`LN1→Attn→残差`，`LN2→MLP→残差` |
| `GPT2Attention` | 因果多头自注意力（含 QKV 投影、掩码、输出投影） |
| `GPT2PreTrainedModel` | 基类；权重初始化、加载预训练等公共逻辑 |

## 3. 输入表示：词嵌入 + 可学习位置编码

两张可学习的查找表，把"离散 id"变成"稠密向量"：

- **WTE（Word Token Embedding）**：形状 $[V, d]$，$V$=词表大小（GPT-2 为 50257，用 BPE 分词），$d$=隐藏维。给定 token id，取出对应那一行。
- **WPE（Word Position Embedding）**：形状 $[n_{ctx}, d]$，$n_{ctx}$=最大上下文长度（1024）。给定位置 $0,1,2,\dots$，取出对应那一行。

最终输入向量是两者**逐元素相加**：

$$
h^{(0)}_t = \text{WTE}[x_t] + \text{WPE}[t]
$$

**为什么要位置编码？** 注意力本身是"对集合的操作"，天然**无序**——打乱输入顺序，注意力的结果只是跟着换位置，模型分不清"猫追狗"和"狗追猫"。必须显式注入位置信息。

**为什么是"可学习"而不是 Transformer 原论文的正弦/余弦固定编码？** GPT-2 选择让位置向量也成为可训练参数，模型自己学出最有利于任务的位置表示。代价是：**位置数被写死为 1024，外推到更长序列没有定义**（这也是后来 RoPE/ALiBi 等相对位置方案要解决的问题）。

```
token: "cat"(id=5247)            位置: t=2
WTE 表                            WPE 表
┌───────────────┐                ┌───────────────┐
│ 0: [...]      │                │ 0: [...]      │
│ ...           │                │ 1: [...]      │
│ 5247:[a b c..]│ ──取行──►       │ 2:[p q r ..]  │ ──取行──►
│ ...           │       │        │ ...           │      │
└───────────────┘       └──── + ──┘  （逐元素相加）─────┘
                              ▼
                        h0 = [a+p, b+q, c+r, ...]
```

## 4. 因果（掩码）自注意力——"不能偷看未来"的实现

### 4.1 注意力三件套 Q/K/V

对每个位置的输入向量 $h$，用三个线性变换得到 Query、Key、Value：

$$
Q = hW_Q,\quad K = hW_K,\quad V = hW_V
$$

直觉：**Q 是"我想找什么"，K 是"我能提供什么"，V 是"我实际携带的信息"**。Q 和所有 K 做点积，得到"我该关注谁"的打分。

$$
\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V
$$

- $\frac{1}{\sqrt{d_k}}$：缩放，防止点积随维度变大而过大、把 softmax 推到饱和区导致梯度消失。
- $M$：**因果掩码**，是关键。

### 4.2 因果掩码长什么样

打分矩阵 $S = QK^\top$ 是 $T\times T$，$S_{ij}$ = "位置 i 对位置 j 的关注度"。我们要求 **i 不能关注 j>i（未来）**，于是把上三角（不含对角线）全部加上 $-\infty$，softmax 后这些位置概率变成 0：

```
       注意力打分 S (T=4)，✓可见 ✗屏蔽
            被关注 j →
            k0   k1   k2   k3
   q0(看)  ✓    -∞   -∞   -∞
   q1      ✓    ✓    -∞   -∞
   q2      ✓    ✓    ✓    -∞
   q3      ✓    ✓    ✓    ✓
            ↑ 下三角(含对角)保留，上三角置 -∞
```

**为什么是 -∞ 而不是直接删？** 因为要保持矩阵形状好做并行；$e^{-\infty}=0$，softmax 自动把权重清零，等价于"看不见"。

**手算一个 mini 例子**（$d_k=1$，看位置 q2 如何聚合）：
设 $q_2=1$，$k_0=2,k_1=0,k_2=1,k_3=3$，$v_0=10,v_1=20,v_2=30,v_3=40$。
- 原始分：$s = q_2\cdot k = [2,0,1,3]$。
- 加掩码（j=3 是未来，置 -∞）：$[2,0,1,-\infty]$。
- 缩放略（$d_k=1$）。softmax：$e^{[2,0,1]}=[7.389,1,2.718]$，和=11.107 → 权重 $[0.665,0.090,0.245]$。
- 输出：$0.665\cdot10 + 0.090\cdot20 + 0.245\cdot30 = 6.65+1.80+7.35 = 15.8$。
未来位置 v3=40 **完全没参与**——这就是因果性。

## 5. 多头：把注意力拆成 n_head 个并行子空间

一个 $d$ 维注意力只能学一种"关注模式"。多头把 $d$ 切成 $n_{head}$ 份，每份 $d_{head}=d/n_{head}$，各自独立做注意力，再拼回来：

$$
\text{head}_i = \text{Attn}(QW_i^Q, KW_i^K, VW_i^V),\quad
\text{MHA} = \text{Concat}(\text{head}_1,\dots,\text{head}_h)\,W_O
$$

```
 h [B,T,d=768]
   │  QKV 投影后 reshape 成多头
   ▼
 ┌── head0 [d_head=64] ──► 注意力 ──┐
 ┌── head1 [64]        ──► 注意力 ──┤
 │   ...   (共 12 头)              ├─ Concat 回 768 ─► W_O ─► [B,T,768]
 └── head11[64]        ──► 注意力 ──┘
```

GPT-2 small：$d=768,\ n_{head}=12,\ d_{head}=64$。**为什么 64 这个数好？** 经验上每头维度 64～128 兼顾表达力与稳定性；$12\times64=768$ 刚好整除。不同头能各管一摊（有的管语法邻接、有的管长程指代）。

## 6. Pre-LN：GPT-2 相对原 Transformer 的核心架构改动

原始 Transformer 用 **Post-LN**：`x + Sublayer(x)` 之后再 LayerNorm。GPT-2 改成 **Pre-LN**：先 LayerNorm 再进子层，残差直接相加。

$$
\textbf{Post-LN（原版）:}\quad x_{out} = \text{LN}\big(x + \text{Sublayer}(x)\big)
$$
$$
\textbf{Pre-LN（GPT-2）:}\quad x_{out} = x + \text{Sublayer}\big(\text{LN}(x)\big)
$$

```
   Post-LN                      Pre-LN (GPT-2)
   x ──┬─► Sublayer ─► + ─► LN ─► out      x ──┬───────────────► + ─► out
       └──────────────┘                        └─► LN ─► Sublayer ┘
   残差路径上"夹着"LN              残差路径是一条干净的恒等高速路
```

**为什么 GPT-2 选 Pre-LN（这是面试高频）？**

1. **残差成为"恒等捷径"**：Pre-LN 下 $x_{out}=x+\dots$，残差路径上没有任何归一化/缩放，梯度可以**原样**反向流回浅层 → 深层网络更易训练、几乎不需要复杂的学习率 warmup。
2. **数值稳定**：每个子层的输入都被归一化到稳定尺度，避免激活值随层数累积爆炸。
3. **代价**：理论分析指出 Pre-LN 各层"有效贡献"会随深度衰减，表达力略受影响；但工程上稳定性收益更大，后续 GPT-3、LLaMA 等几乎全用 Pre-LN。

GPT-2 在**最后一个 Block 之后还有一个额外的 LayerNorm（LN_f）**，因为 Pre-LN 结构里主干输出未被归一化，需补一刀再送入 lm_head。

## 7. FFN（MLP）：逐位置的非线性加工

注意力负责"跨位置混信息"，FFN 负责"对每个位置单独做非线性变换、扩容算力"。两层线性 + 中间 GELU，先把维度**放大 4 倍**再缩回：

$$
\text{FFN}(x) = \text{GELU}(xW_1 + b_1)\,W_2 + b_2,\quad W_1\in\mathbb{R}^{d\times 4d},\ W_2\in\mathbb{R}^{4d\times d}
$$

GPT-2：$d=768 \to 3072 \to 768$。**为什么是 4×？** 经验最优点：放大倍数给非线性足够"工作空间"，4 是性价比甜点（参数/算力 vs 收益）。GELU 比 ReLU 平滑，在小负值区不是硬截断，训练更稳。

$$
\text{GELU}(x)=x\cdot\Phi(x)\approx 0.5x\Big(1+\tanh\big[\sqrt{2/\pi}(x+0.044715x^3)\big]\Big)
$$

## 8. 权重共享（Weight Tying）：输入嵌入 = 输出投影

GPT-2 把**输入词嵌入 WTE** 和**输出层 lm_head 的权重**绑成同一张矩阵：

$$
\text{logits} = h^{(N)} \cdot \text{WTE}^\top
$$

```
  输入端: id ──► WTE[id]  (查行 = 取嵌入)
  输出端: h  ──► h · WTEᵀ (与每个词向量做内积 = 打分)
                 └ 同一张 [V,d] 矩阵被用了两次 ┘
```

**为什么共享？**
1. **省参数**：$V\times d = 50257\times768 \approx 3860$ 万个参数。不共享要存两份，共享省一份——对 117M 的 small 来说占比极大。
2. **语义一致**：输入"把 id 映射到向量"和输出"把向量映射回 id 打分"本质是一对逆操作，用同一空间更自然，常带来更好困惑度。

## 9. 训练目标与自回归生成

### 训练：最小化下一个 token 的负对数似然（交叉熵）

$$
\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T}\log P_\theta(x_t \mid x_{<t})
$$

借助因果掩码，**一次前向就能并行计算所有 $T$ 个位置的预测**（teacher forcing：每个位置的"前缀"用真实数据，而非模型自己的预测），效率极高。

**损失手算**：词表 50257，若模型对真实词给出概率 0.1，则该位置损失 $-\ln 0.1 = 2.303$ nats。完全随机猜（均匀）时 $-\ln(1/50257)=10.82$ nats，对应困惑度 $\text{PPL}=e^{\mathcal{L}}=50257$。GPT-2 在 WebText 上把 PPL 压到远低于此，说明它学到了真实分布。

### 生成：逐 token 自回归采样

```
prompt ─► 前向 ─► 最后位置 logits ─► (温度T/top-k/top-p) ─► 采样1个token
   ▲                                                          │
   └──────────────── 拼接到序列末尾，再来一轮 ◄────────────────┘
```

- **温度 T**：$\text{softmax}(z/T)$。T<1 更确定（尖锐），T>1 更随机（平坦）。
- **top-k / top-p（核采样）**：只在概率最高的 k 个 / 累积概率达 p 的最小集合里采样，砍掉长尾胡言乱语。

## 10. 规模配置：GPT → GPT-2 → GPT-3

GPT-2 与 GPT/GPT-3 **架构同源**（都是 Decoder-only + 因果注意力 + 可学习位置编码），差异主要在**规模**与少量细节（GPT-2 引入 Pre-LN 与更大上下文/词表；GPT-3 进一步在部分层用稀疏注意力）。

| 模型 | 层数 N | 隐藏维 d | 头数 | 上下文 | 参数量 | 备注 |
|------|--------|----------|------|--------|--------|------|
| GPT-1 (2018) | 12 | 768 | 12 | 512 | ~117M | 首提"预训练+微调" |
| **GPT-2 small** | 12 | 768 | 12 | 1024 | ~117M | Pre-LN，零样本 |
| GPT-2 medium | 24 | 1024 | 16 | 1024 | ~345M | |
| GPT-2 large | 36 | 1280 | 20 | 1024 | ~762M | |
| **GPT-2 XL** | 48 | 1600 | 25 | 1024 | ~1.5B | 发布时分阶段放出 |
| GPT-3 (2020) | 96 | 12288 | 96 | 2048 | ~175B | 上下文学习/few-shot |

> 规模数字以官方技术报告为准；GPT-2 词表统一为 50257（BPE）。GPT-2 论文核心主张：**模型与数据足够大时，单一语言模型可零样本（zero-shot）完成多任务，无需逐任务微调**——这条路被 GPT-3 的 few-shot in-context learning 进一步放大。详见 [[llm-algo/gpt3/README]]。

## 11. 参数量逐数手算（GPT-2 small，d=768, N=12, V=50257, n_ctx=1024）

**嵌入层**
- WTE：$V\times d = 50257\times768 = 38{,}597{,}376$
- WPE：$1024\times768 = 786{,}432$

**每层 Block**（忽略 LN 的微小参数，含偏置近似）
- Attention QKV 投影：$d\times 3d = 768\times2304 = 1{,}769{,}472$
- Attention 输出投影 $W_O$：$d\times d = 768\times768 = 589{,}824$
- MLP $W_1$：$d\times4d = 768\times3072 = 2{,}359{,}296$
- MLP $W_2$：$4d\times d = 3072\times768 = 2{,}359{,}296$
- 单层合计 ≈ $1{,}769{,}472+589{,}824+2{,}359{,}296+2{,}359{,}296 = 7{,}077{,}888$

**12 层**：$7{,}077{,}888 \times 12 = 84{,}934{,}656$

**总计（含嵌入，因 lm_head 与 WTE 共享不重复计）**：
$$
38{,}597{,}376 + 786{,}432 + 84{,}934{,}656 \approx 124{,}318{,}464 \approx \textbf{124M}
$$

> 常说的"117M"是论文口径（统计方式略有出入，如是否计 LN/bias、是否计位置嵌入）；HF 实现按上面口径约 124M。量级对得上即可，关键是**理解每一块参数从哪来**：嵌入占 ~31%，注意力 ~28%，MLP ~38%。

## 12. 显存与 KV Cache 手算

**模型权重显存**（FP16，每参数 2 字节）：$124\text{M}\times2\text{B} \approx 248\,\text{MB}$。FP32 则约 496 MB。

**推理 KV Cache**（自回归生成时缓存历史 K、V 避免重算，是显存大头）：每个 token、每层都要存 K 和 V 各 $d$ 维：

$$
\text{KV} = 2 \times N \times d \times T \times \text{bytes}
$$

GPT-2 small、序列 1024、FP16：
$$
2\times12\times768\times1024\times2\text{B} = 38{,}654{,}705 \text{B} \approx 36.9\,\text{MB（每条序列）}
$$

batch=32 时约 1.2 GB——**KV Cache 随 batch 与序列长度线性增长**，是长上下文推理的主要瓶颈（后续 GQA/MQA、PagedAttention 正是为压它）。

## 复杂度对照表

| 维度 | 表达式 | 说明 |
|------|--------|------|
| 自注意力时间 | $O(T^2 d)$ | 序列长度的**平方**，长文本痛点 |
| FFN 时间 | $O(T d^2)$ | 通常 d≫T 时是主算力 |
| 注意力打分显存 | $O(T^2)$ | 每层每头一张 T×T 矩阵 |
| 单 token 推理 | $O(N d^2)$ | 配 KV Cache，每步与历史长度成 $O(NdT)$ |
| 参数量 | $\approx 12 N d^2 + Vd$ | 12 来自 QKV+O+两层MLP 的系数和 |

## 常见问题 / 高频追问

| 问题 | 踩点答案 | 追问/陷阱 |
|------|----------|-----------|
| GPT-2 为什么是 Decoder-only？ | 任务是单向语言建模，只需"看左边预测右边"；砍掉 Encoder 与 Cross-Attn，结构更简、更易放大 | 追问：和 BERT（Encoder-only、双向 MLM）差别？→ BERT 看双向做完形填空，不能直接自回归生成 |
| 因果掩码具体怎么实现？ | 打分矩阵上三角加 $-\infty$，softmax 后未来位置权重归零 | 陷阱：别说"删掉未来"，是置 -∞ 保形状 |
| Pre-LN vs Post-LN 选哪个、为什么？ | GPT-2 用 Pre-LN：残差为恒等捷径、梯度直通、训练稳、少依赖 warmup；代价是深层有效性衰减 | 追问：为什么末尾还要 LN_f？→ 主干输出未归一化，送 lm_head 前补一刀 |
| 位置编码用的可学习还是正弦？ | 可学习（WPE 查表）；灵活但写死 1024，无法外推 | 追问：怎么外推？→ RoPE/ALiBi 等相对位置方案 |
| 权重共享共享了什么、好处？ | WTE 与 lm_head 同一张 $[V,d]$；省~38M 参数 + 输入输出语义一致 | 陷阱：共享的是权重矩阵，不是 bias |
| 训练为什么能并行而生成不能？ | 训练用 teacher forcing+因果掩码，一次前向算全部位置；生成依赖自己上一步输出，必须串行 | 追问：KV Cache 如何加速？→ 缓存历史 K/V，每步只算新 token |
| GPT-2 和 GPT-3 架构差别？ | 同源 Decoder-only；GPT-3 主要是放大（175B、96 层、上下文 2048），部分层用稀疏注意力，并主打 few-shot in-context learning | 见 [[llm-algo/gpt3/README]] |
| FFN 为什么放大 4 倍？ | 给非线性足够工作空间，4× 是参数/算力与收益的经验甜点 | 追问：换 GELU 而非 ReLU 的好处？→ 平滑、小负区不硬截断 |
| $\sqrt{d_k}$ 缩放为什么必要？ | 防点积随维度变大、softmax 饱和、梯度消失 | 不缩放时大 d 下注意力近似 one-hot |
