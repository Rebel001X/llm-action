## 0. 一句话锚点

> **InternLM = 一个标准的 Transformer Decoder-only 大语言模型 + 一套「能训、能调、能推、能评、能做 Agent」的全开源工具链。**

把它拆成两半你就懂了：

1. **模型本体**：和 LLaMA / Qwen 同家族——纯解码器(Decoder-only)、自回归(预测下一个 token)、用 RMSNorm + RoPE + SwiGLU。InternLM-20B 是其中 200 亿参数的「中杯」。
2. **工具链**：InternLM 最独特处。它不只放权重，而是把**训练框架(InternEvo)、微调(XTuner)、推理引擎(LMDeploy)、评测(OpenCompass)、智能体框架(Lagent)** 全部开源，形成闭环。

## 1. 地基/前置：一个 LLM 的参数从哪来

不假设你记得公式，我们从最原子讲起。一个 Decoder-only Transformer 由 $L$ 个相同的「层(Layer)」堆叠，每层有两个子模块：

- **自注意力(Self-Attention)**：让每个 token「看」前面的所有 token，决定该关注谁。
- **前馈网络(FFN / MLP)**：对每个位置做一次非线性变换，提升表达力。

### 1.1 隐藏维度与参数量

设：隐藏维度 $d$(每个 token 的向量长度)、层数 $L$、FFN 中间维度 $d_{ff}$、词表大小 $V$。

**单层注意力参数**：四个投影矩阵 $W_Q, W_K, W_V, W_O$，每个约 $d \times d$，合计 $\approx 4d^2$。

**单层 FFN 参数**：现代模型用 **SwiGLU**，有三个矩阵($W_{gate}, W_{up}$ 各 $d\times d_{ff}$，$W_{down}$ 为 $d_{ff}\times d$)，合计 $\approx 3 \cdot d \cdot d_{ff}$。

**总参数(忽略 Norm/Embedding 的小项)**：
$$
N \approx L \cdot (4d^2 + 3\,d\,d_{ff}) + V \cdot d
$$

> 直觉：参数主要堆在「层数 × 每层矩阵」上。20B 这个数字就是靠调 $L, d, d_{ff}$ 凑出来的——第 9 节会用 InternLM-20B 的真实配置反算给你看。

### 1.2 三个关键组件（为什么这么设计）

```
   ┌──────────── 一层 Decoder Layer ────────────┐
   │  x ──▶ RMSNorm ──▶ Attention(RoPE) ──▶ +x  │  (残差)
   │    └──▶ RMSNorm ──▶ SwiGLU FFN ──▶ +(上一步) │
   └────────────────────────────────────────────┘
```

| 组件 | 是什么 | 为什么用它 |
|---|---|---|
| **RMSNorm** | 只用均方根归一化，不减均值 | 比 LayerNorm 少一半计算，训练更稳、更省 |
| **RoPE**(旋转位置编码) | 把位置信息编成「旋转角度」乘进 Q/K | 相对位置感知，**可外推到训练没见过的长度** |
| **SwiGLU** | 带门控的 FFN，激活用 SiLU | 同等参数下效果优于普通 ReLU-FFN |

这三件套是 LLaMA 定下的「现代配方」，InternLM、Qwen 都沿用。理解了它们，再看 InternLM 的特殊设计就清楚了。

## 2. InternLM-20B 架构与规模

InternLM-20B 的核心选择：**「深而窄(deep-and-thin)」+ 分组查询注意力(GQA)**。

### 2.1 典型规格（以官方为准）

> 下列数字基于 InternLM-20B / InternLM2-20B 公开技术报告与配置，标「约」，精确值以官方 config 为准。

| 维度 | InternLM-20B(约) | 对照：LLaMA2-13B | 说明 |
|---|---|---|---|
| 参数量 | 约 200 亿 | 130 亿 | — |
| 层数 $L$ | **约 60 层** | 40 层 | InternLM 特意加深 |
| 隐藏维度 $d$ | 约 5120 | 5120 | 与 13B 相近 |
| 注意力头数 | 约 40 | 40 | — |
| KV 头数(GQA) | 约 8(InternLM2) | 40(MHA) | KV 共享，省显存 |
| 词表 $V$ | 约 10.3 万 | 3.2 万 | 中文友好的大词表 |
| 训练上下文 | 4K(基座) | 4K | 后续外推到 200K |

### 2.2 为什么「深而窄」

同样 20B 预算，可以选「层少而宽」或「层多而窄」。InternLM-20B 选了 **60 层**(比常规 13B 的 40 层多 50%)，而宽度只略增。

```
   宽而浅(40层)          深而窄(60层, InternLM-20B)
   ┌──────────┐          ┌────┐
   │██████████│          │████│  层
   │██████████│ × 40     │████│
   │██████████│          │████│  × 60
   └──────────┘          │████│
                         │████│
   表达「宽度」强        └────┘
                         「组合/推理深度」强
```

**直觉**：更深的网络能做更多层「思考的串联」，对推理、代码这类需要多步组合的任务更有利；官方实验表明这种结构在多数评测上优于同量级的宽而浅模型。**代价**：层多 → 串行依赖长 → 推理时延略增、流水线并行更难切。

### 2.3 GQA：MHA 与 MQA 的折中

注意力有三种 KV 共享策略，决定推理时 **KV Cache 显存**：

```
   MHA(每头独立KV)   GQA(分组共享)        MQA(全共享1组)
   Q Q Q Q           Q Q Q Q              Q Q Q Q
   │ │ │ │           └┬┘ └┬┘              └─┬───┘
   K K K K            K    K                 K
   V V V V            V    V                 V
   显存大,质量高      平衡(InternLM2选)     显存最小,质量略降
```

InternLM2 系列采用 **GQA**：40 个 Query 头共享 8 组 KV。KV Cache 显存近似降到 MHA 的 $8/40 = 1/5$，这正是**支撑长上下文推理的关键**——上下文越长，KV Cache 越大，省下的就越值钱。

## 3. 长上下文：从 4K 到 200K

长上下文是 InternLM 的招牌能力之一。要理解它，先看「为什么默认上下文是有限的」。

### 3.1 问题根源：位置编码的「外推墙」

RoPE 给位置 $m$ 的 token 施加旋转角 $\theta_m$。训练时只见过 $m \in [0, 4096)$ 的角度。一旦推理时 $m$ 超过训练长度，模型遇到「没见过的角度」→ 注意力分数崩坏 → 胡言乱语。这就是**外推墙**。

```
   训练见过           推理想要
   0 ........ 4K  |  4K ............ 200K
   ▓▓▓▓▓▓▓▓▓▓▓▓▓  |  ░░░░░░░░░░░░░░░░░░  ← 没见过 → 崩
```

### 3.2 解决方案：位置插值 + 长文续训

InternLM 用两步突破外推墙：

1. **位置插值(Position Interpolation)/ RoPE 频率缩放**：把超长的位置「压缩」回训练见过的区间。直觉：与其让模型外推到 200K 这个陌生角度，不如把 200K 个位置「插值」成它熟悉的 4K 角度密度。等价于调整 RoPE 的基频 base($\theta$ 的底数从 10000 调大）。

```
   原始: 位置 0,1,2,...,200000  → 角度跨度巨大(墙外)
   插值: 把 200000 个位置映射到 [0,4096] 的角度密度内
         位置 0  ─┐
         位置 1  ─┼─▶ 密集落在「训练熟悉」的角度区
         ...      │
         200000 ─┘
```

2. **长文本续训(Long-context Continued Pretraining)**：在插值基础上，用真实长文档(书籍、长代码库、拼接语料)再训一段，让模型「亲眼见过」长序列，巩固长程依赖。

InternLM2 通过这套方案，把上下文从 4K 一路扩展到 **32K 训练 / 200K 推理(「大海捞针」近乎满分)**。

### 3.3 工程配套

长上下文不仅是模型问题，也是显存/速度问题。InternLM 生态配套：

- **训练侧**：InternEvo 提供序列并行(Sequence Parallel)，把一条长序列切到多卡，突破单卡显存。
- **推理侧**：LMDeploy 的 PagedAttention(分页 KV Cache)，避免长 KV 占满显存碎片。

## 4. 训练数据：高质量优先 + 数据飞轮

模型上限由数据决定。InternLM 的数据哲学是**「质 > 量」+ 持续迭代的数据飞轮**。

### 4.1 规模与配比（以官方为准）

InternLM2 基座约在 **2T+ tokens** 量级上预训练(标「约」)。数据来源大致分为：

```
   ┌─────────────────────────────────────────┐
   │            预训练数据池(约 2T+ tokens)    │
   ├──────────────┬──────────────┬────────────┤
   │  网页文本     │   代码        │  书籍/论文  │
   │ (中+英为主)   │ (多语言代码)  │ (高质量长文)│
   ├──────────────┴──────────────┴────────────┤
   │   中英双语并重 + 代码增强(强化推理/编程)   │
   └─────────────────────────────────────────┘
```

关键点：

- **中英并重**：不像很多英文模型把中文当「附加」，InternLM 从数据层就把中文当一等公民(配比显著)。
- **代码强化**：大量高质量代码，既提升编程能力，也间接增强**逻辑推理**(代码是结构化的推理)。
- **长文档**：书籍/论文比例对长上下文与知识深度至关重要。

### 4.2 数据清洗管线

```
   原始爬取 ──▶ 语言识别 ──▶ 去重(URL/段落/MinHash)
        │                         │
        ▼                         ▼
   规则过滤(垃圾/广告) ──▶ 质量打分模型 ──▶ 安全过滤 ──▶ 入池
```

每一步都在「为什么」：去重防止重复样本让模型过拟合记忆；质量打分用小模型给文档评分，只留高分；安全过滤剔除有害内容。

### 4.3 数据飞轮（DataFlywheel）

InternLM 提出**数据飞轮**思想：用当前模型去「评估/清洗/标注」下一轮数据，再训出更好的模型，循环上升。这让数据质量随版本迭代持续提升，是 1.0→2.0→2.5 能力跃升的隐形引擎。

## 5. 训练工具链：InternEvo

> **InternEvo** 是 InternLM 自研的大规模预训练框架(早期内嵌于 InternLM 仓库，后独立开源)，解决一个核心问题：**怎么用上千张 GPU 高效地把 20B/100B+ 模型训出来，且尽量不浪费算力。**

### 5.1 它解决什么问题

单卡装不下 20B：光参数(FP16)就 $20\text{B}\times 2\text{B} = 40\text{GB}$，加上梯度、优化器状态会膨胀到几倍(见第 9 节手算)。必须**并行**。

### 5.2 核心机制：混合并行 + ZeRO

```
        一个超大模型 → 怎么切到很多 GPU?
   ┌──────────────────────────────────────────┐
   │ 数据并行 DP : 每卡一份完整模型, 切「数据」  │
   │ 张量并行 TP : 把单层的大矩阵切到多卡(切宽) │
   │ 流水并行 PP : 把不同「层」放不同卡(切深)   │
   │ 序列并行 SP : 把一条长序列切到多卡(切长度) │
   │ ZeRO       : 把优化器状态/梯度分片省显存   │
   └──────────────────────────────────────────┘
                 ↓ 组合成「3D/4D 并行」
```

- **张量并行(TP)**：把注意力/FFN 的大矩阵按列/行切开，多卡分别算再聚合。适合切「宽度」。
- **流水线并行(PP)**：把 60 层分成几段放不同卡，像流水线一样传递激活。适合切「深度」——InternLM-20B 深而窄，PP 切起来正合适。
- **序列并行(SP)**：长上下文训练的关键，把超长序列的 token 维度切开。
- **ZeRO(零冗余优化器)**：DP 中每卡本来都存一份优化器状态(很占显存)，ZeRO 把它们**分片**到各卡，需要时再通信取回，大幅省显存。

InternEvo 的卖点是**高 MFU(模型算力利用率)**：通过通信/计算重叠、显存优化，让上千卡集群的算力不被通信「饿死」。

### 5.3 与同类对比

| 框架 | 出身 | 特点 |
|---|---|---|
| **InternEvo** | 上海 AI Lab | 内置长序列并行、与 InternLM 数据/模型深度协同、高 MFU |
| Megatron-LM | NVIDIA | TP/PP 标杆，生态广 |
| DeepSpeed | 微软 | ZeRO 起源，易用 |

> 何时用 InternEvo：你要复现/续训 InternLM 系列，或需要开箱即用的长上下文训练 + 中文友好工具链。

## 6. 全栈生态：微调 / 推理 / 评测 / Agent

InternLM 的差异化在于**完整闭环**。逐个看(CLI/API 细节以官方文档为准)。

```
   基座 InternLM-20B
        │
   ┌────┼────────────┬────────────┬───────────┐
   ▼    ▼            ▼            ▼            ▼
 XTuner  LMDeploy   OpenCompass   Lagent    (HuggingFace
 微调    推理部署     评测          Agent      权重开源)
```

### 6.1 XTuner —— 微调工具箱

解决「我想用自己的数据微调 InternLM」。

- 支持 **LoRA / QLoRA / 全参** 微调；**QLoRA** 让 20B 在单张消费级/专业卡上也能调(4bit 量化基座 + 低秩适配器)。
- 支持 SFT、增量预训练、对齐(DPO 等)，配置式上手。

```
   预训练基座(冻结/量化) ─┐
                          ├─▶ + 小的 LoRA 适配器(可训) ─▶ 领域模型
   你的领域数据 ──────────┘   只训 <1% 参数, 显存大降
```

### 6.2 LMDeploy —— 推理与部署

解决「训好了怎么跑得快、跑得省」。

- **量化**：W4A16 / KV Cache INT8，把 20B 压进更小显存。
- **TurboMind 引擎**：高性能 CUDA kernel + **PagedAttention** + **continuous batching(连续批处理)**，高吞吐。
- **服务化**：一行命令起 OpenAI 兼容 API 服务。

```
   请求1 ─┐  continuous batching: 谁先生成完谁先走,
   请求2 ─┼─▶ 空位立刻补新请求 ─▶ GPU 利用率拉满 ─▶ 高吞吐
   请求3 ─┘
```

### 6.3 OpenCompass —— 评测平台

解决「我怎么客观知道模型好不好」。

- 覆盖数十~上百个数据集(中文 C-Eval/CMMLU、英文 MMLU、推理 GSM8K、代码 HumanEval 等)。
- 统一评测协议，支持主观评测(模型当裁判)。InternLM 的「数据飞轮」也靠它度量。

### 6.4 Lagent —— 智能体框架

解决「让模型会用工具、做多步任务」。

- 轻量 Agent 框架，支持 ReAct、ToolCalling 范式；可挂搜索、代码解释器、计算器等工具。
- 与 InternLM 的工具调用能力配套，做 RAG / 多步推理 Agent。

> 一句话记忆：**XTuner 喂数据、LMDeploy 跑得快、OpenCompass 打分、Lagent 长手脚。**

## 7. 中文能力：为什么 InternLM 中文强

### 7.1 三个层面的「中文优待」

```
   ┌─────────── 中文能力来源 ───────────┐
   │ ① 分词器: 大词表(约10万), 中文token   │
   │            少→序列短→省算力, 切分准   │
   │ ② 语料:   中英并重, 海量高质量中文    │
   │ ③ 评测:   OpenCompass 内置 C-Eval/   │
   │            CMMLU 等中文基准持续优化   │
   └────────────────────────────────────┘
```

- **分词器**：英文模型常把一个汉字切成 2~3 个 token，浪费上下文。InternLM 大词表对中文友好——同样一句中文，**用更少 token** 表示(省钱、省上下文、表意更准)。
- **语料**：中文从预训练就占重要配比，不是「翻译补丁」。
- **闭环评测**：用中文基准 + 数据飞轮持续打磨。

### 7.2 一个直观对比

```
   句子: "人工智能正在改变世界"
   英文向 tokenizer: 人|工|智|能|正|在|改|变|世|界  → 约10+ token
   中文友好 tokenizer: 人工智能|正在|改变|世界        → 约4~6 token
   → 更短 → 同样上下文窗口能塞更多内容
```

|---|---|---|---|
| 主打 | **全栈开源工具链** | 高质量基座+生态 | 强中文+多尺寸+多模态 |
| 长上下文 | 200K(招牌) | 视版本 | 长上下文也强 |
| 中文 | 强(双语并重) | 偏弱(英文为主) | 强 |
| 训练框架 | **自带 InternEvo 开源** | 不开源训练栈 | Megatron 系 |
| Agent | **Lagent 原生** | 第三方 | 有工具调用 |

> InternLM 的核心贡献：**不只放权重，而是把「数据飞轮→训练→微调→推理→评测→Agent」整条链路开源**，让研究者能端到端复现与改造。这是它在开源社区的独特价值。

### 8.3 何时选 InternLM / 权衡

- **选它**：需要中英双语 + 长上下文 + 想要可复现的开源训练/评测栈 + 做 Agent。
- **权衡**：深而窄结构推理时延略高；超大词表略增 Embedding 参数；生态学习曲线(5 个工具)比单点方案陡。

## 9. 数值例子 / 对照（手算）

### 9.1 用配置反算参数量

取 InternLM-20B 近似配置：$L=60$，$d=5120$，$d_{ff}\approx 13824$，$V\approx 103168$。

**注意力部分**：$L \cdot 4d^2 = 60 \times 4 \times 5120^2 \approx 60 \times 4 \times 2.62\times10^7 \approx 6.29\times10^9$。

**FFN 部分(SwiGLU 三矩阵)**：$L \cdot 3\,d\,d_{ff} = 60 \times 3 \times 5120 \times 13824 \approx 60 \times 2.12\times10^8 \approx 1.27\times10^{10}$。

**Embedding**：$V \cdot d = 103168 \times 5120 \approx 5.28\times10^8$。

**合计**：$6.29\times10^9 + 1.27\times10^{10} + 5.28\times10^8 \approx 1.95\times10^{10} \approx 195$ 亿 ✓ 与「约 200 亿」吻合(实际还有 GQA 让 KV 投影变小、共享 Embedding 等微调，精确值以官方 config 为准)。

> 收获：FFN 是参数大头(约 65%)，这就是为什么量化/MoE 往往先动 FFN。

### 9.2 训练显存为什么要并行（Adam 手算）

20B 参数，用混合精度 + Adam：

- 参数(FP16)：$20\text{B}\times 2 = 40$ GB
- 梯度(FP16)：$20\text{B}\times 2 = 40$ GB
- Adam 状态(FP32 的 momentum+variance + FP32 参数副本)：约 $20\text{B}\times(4+4+4)=240$ GB

合计 **约 320 GB**(还没算激活值！)。一张 80GB A100 远远装不下 → 必须 ZeRO 分片 + 张量/流水并行。这就是 InternEvo 存在的理由。

### 9.3 长上下文 KV Cache：GQA 省多少

设 200K 上下文、$d=5120$、$L=60$、FP16。

- **MHA(40 头全存 KV)**：每 token 的 KV $\approx 2 \times d \times L \times 2\text{B} = 2\times5120\times60\times2 \approx 1.23$ MB；200K token $\approx 1.23\text{MB}\times200000 \approx 246$ GB(爆炸！)
- **GQA(8 组 KV)**：KV 维度降到 $8/40 = 1/5$ → 约 **49 GB**。

> 这就是为什么「长上下文」必须配「GQA + PagedAttention」——否则 KV Cache 直接撑爆显存。数字为量级估算，实际以实现为准。

## 常见问题

| 问题 | 速查答案 |
|---|---|
| InternLM 和 InternLM2 啥区别？ | 2 引入 GQA、长上下文(200K)、数据飞轮成熟；2.5 再强化推理与原生 Agent。 |
| InternEvo 和 Megatron/DeepSpeed 关系？ | 同类训练框架，InternEvo 是上海 AI Lab 自研，强在长序列并行+中文工具链协同。 |
| 为什么 20B 用 60 层这么深？ | 深而窄，强在多步推理/组合；代价是推理时延与流水并行复杂度。 |
| 长上下文靠什么实现？ | RoPE 位置插值(调 base) + 长文续训 + 序列并行(训) + PagedAttention(推)。 |
| 中文为什么强？ | 大词表中文友好 + 中英双语并重的高质量语料 + 中文基准闭环评测。 |
| 想微调 20B 显卡不够？ | 用 XTuner 的 QLoRA(4bit 量化基座 + LoRA)，单卡可调。 |
| 想部署得快/省？ | LMDeploy(TurboMind + W4A16 + PagedAttention + continuous batching)。 |
| 怎么客观评测？ | OpenCompass，内置 C-Eval/CMMLU/MMLU/GSM8K/HumanEval 等。 |
| 想做工具调用 Agent？ | Lagent，支持 ReAct/ToolCalling，挂搜索/代码解释器。 |
| 这些数字准吗？ | 架构数字为公开近似，标「约」；精确值与版本以官方技术报告/config 为准。 |
