## 0. 一句话锚点

**MoE = 把 Transformer 里那一层稠密 FFN,换成"N 个小 FFN(专家)+ 一个门控网络"。每个 token 来了,门控只挑出 Top-k 个专家干活,其余专家睡觉。** 于是模型总参数可以做到几百 B,但每个 token 实际只用到其中几 B —— **参数大、算力小**。

---

## 1. 地基:稠密 FFN 长什么样、为什么贵

要懂 MoE,先必须懂它替换掉的东西 —— Transformer 里的 **FFN(前馈网络,Feed-Forward Network)**。详见 [[llm-algo/mlp]]。

一个标准 FFN 对**每个 token 的向量** $x \in \mathbb{R}^{d}$ 做两次线性变换 + 一次非线性:

$$
\text{FFN}(x) = W_2 \,\sigma(W_1 x + b_1) + b_2
$$

其中 $W_1 \in \mathbb{R}^{d_{ff}\times d}$ 把维度从 $d$ 升到中间维 $d_{ff}$(典型 $d_{ff}=4d$),$\sigma$ 是激活(GELU/SiLU),$W_2 \in \mathbb{R}^{d\times d_{ff}}$ 再降回 $d$。

**为什么贵?** 数一下参数和算力(忽略 bias):

- 参数量:$d \cdot d_{ff} + d_{ff}\cdot d = 2 d\, d_{ff} = 8 d^2$(当 $d_{ff}=4d$)。
- 每个 token 的 FLOPs:同样约 $2 \times 2 d d_{ff} = 4 d d_{ff}$(乘加各算一次)。

```
   稠密 FFN: 每个 token 都走完整条 8d² 参数的路
   ┌────────────────────────────────────────────┐
   │  x(d)                                        │
   │   │   W1 (d_ff × d)  升维                     │
   │   ▼                                          │
   │  h(d_ff=4d) ── σ ──► h'                      │
   │   │   W2 (d × d_ff)  降维                     │
   │   ▼                                          │
   │  y(d)                                        │
   └────────────────────────────────────────────┘
   关键痛点:想让模型更"聪明"就得把 d_ff 调大,
   但 d_ff 一大,每个 token 的算力也跟着线性涨。
```

**核心矛盾:在稠密结构里,"参数量"和"每 token 算力"是死死绑在一起的 —— 你想多塞知识(大参数),就必须多付算力。MoE 就是来解开这个绑定的。**

---

## 2. 从稠密 FFN → 稀疏 MoE:把一个胖子拆成一群瘦子

MoE 的第一步动作非常朴素:**把那一层 FFN 复制成 $N$ 份,叫 $N$ 个"专家"(Expert),每个专家就是一个完整的小 FFN。** 然后加一个**门控网络(Gate / Router)**决定每个 token 该送给谁。

```
        稠密层                          MoE 层
   ┌──────────────┐         ┌────────────────────────────────┐
   │              │         │            Gate(router)         │
   │   一个大 FFN  │   ==>   │            ▲                    │
   │              │         │   x ───────┘  打分→挑 Top-k      │
   └──────────────┘         │      │  │  │  │  │ ... │ (N个)   │
                            │     E0 E1 E2 E3 E4    E_{N-1}    │
                            │     (每个 Ei 都是一个小 FFN)      │
                            └────────────────────────────────┘
```

注意一个**容易踩的坑**:并不是"专家越多 = 模型越大就一定换算力"。关键在于**每个 token 只激活 Top-k 个专家**(典型 $k=1$ 或 $2$),而不是全部 $N$ 个。这一步"只挑几个"才是省算力的灵魂,见第 5 节。

通常**不是每一层都换成 MoE**,而是隔层替换(如偶数层用 MoE、奇数层保留稠密 FFN),或干脆每个 Transformer block 的 FFN 都换成 MoE,具体取决于设计。

---

## 3. 门控网络 + Top-k 路由:谁来决定 token 去哪

门控是一个**极小的线性层**:把 token 向量 $x\in\mathbb{R}^d$ 投影到 $N$ 维(N=专家数),得到每个专家的"得分"(logit):

$$
g = W_g\, x, \qquad W_g \in \mathbb{R}^{N\times d}, \quad g\in\mathbb{R}^{N}
$$

然后两步:

**(a) 选 Top-k:** 取 $g$ 里最大的 $k$ 个分量对应的专家索引集合 $\mathcal{T} = \text{argtopk}(g, k)$。其余专家直接不参与(它们的输出当 0)。

**(b) 归一化权重:** 只对被选中的那 $k$ 个 logit 做 softmax,得到每个被选专家的混合权重:

$$
p_i = \frac{\exp(g_i)}{\sum_{j\in\mathcal{T}}\exp(g_j)}, \quad i\in\mathcal{T}
$$

```
   x ──► W_g ──► g = [g0, g1, g2, g3]   (假设 N=4, k=2)
                     │
            argtopk(k=2) 选出最大的两个: 比如 {E1, E3}
                     │
            只对 {g1,g3} 做 softmax → p1, p3   (p1+p3=1)
                     │
            E0、E2 这一步直接 sleep(输出视为 0)
```

**为什么"只对 Top-k 做 softmax"而不是对全部 N 个?** 因为我们只激活了 $k$ 个专家,没被选的专家根本没算输出,给它们分配权重没意义;在选中子集内归一化,能保证被激活专家的权重之和恒为 1,**幅度稳定**,不会因为 $N$ 变大而被稀释。

> 还有一种顺序是"先全 softmax 再选 Top-k"(如早期 Switch/Mixtral 的一种实现)。两种都在用,差异在于权重幅度的归一化口径,效果接近,理解原理为主。

## 4. 加权合并:把被选专家的输出按权重相加

设被选专家集合 $\mathcal{T}$,每个 $i\in\mathcal{T}$ 的小 FFN 给出输出 $E_i(x)$,最终该层输出:

$$
y = \sum_{i\in\mathcal{T}} p_i \cdot E_i(x)
$$

```
   x ──┬──► E1 ──► E1(x) ──×p1 ─┐
       └──► E3 ──► E3(x) ──×p3 ─┴──(+)──► y
   (E0,E2 不算)
```

**为什么要乘门控权重 $p_i$ 再相加,而不是直接平均?** 两个原因:
1. **可微 → 可学**:门控权重出现在前向里,梯度才能流回门控网络 $W_g$,门控才能"学会"该把什么样的 token 送给谁。如果只是硬选不加权,门控的选择是离散的、不可导。
2. **软混合**:权重让模型能"七三开"地融合两个专家的意见,而不是非黑即白。

## 5. 省算力原理:大参数、小算力到底怎么来的

这是 MoE 最值钱的一句话,必须算给你看。

定义:
- $N$ = 专家总数,$k$ = 每 token 激活的专家数,单个专家参数量 $\approx P_e$。
- **总参数(模型有多大)**:$P_{total} \approx N \cdot P_e$(全部专家都要存在显存/磁盘里)。
- **激活参数(每 token 实际算多少)**:$P_{act} \approx k \cdot P_e$。

**每 token FLOPs 只正比于激活参数 $P_{act}$,而不是总参数 $P_{total}$。**

逐数手算(取一个 DeepSeek-V2 风格的量级,见 [[llm-algo/deepseek/DeepSeek-V2]]):

```
   假设: 总参数 P_total = 236 B
          激活参数 P_act  = 21 B
   稀疏率 = P_act / P_total = 21 / 236 ≈ 8.9%
   ──────────────────────────────────────────
   含义: 模型"肚子里"装着 236B 的知识,
        但处理每个 token 时只调用其中 ~9% 去算。
        → 推理算力 ≈ 一个 21B 稠密模型,
          知识容量 ≈ 一个 236B 稠密模型。
```

再用专家口径算一遍直觉:$N=64$ 个专家、每 token 激活 $k=6$ 个(含共享),则算力比 $\approx k/N = 6/64 \approx 9.4\%$。**专家越多、激活越少,稀疏率越极致,"省"得越狠。**

> 注意:省的是**计算(FLOPs)**,不省**显存**。所有专家都得常驻显存,所以 MoE 模型的显存/带宽压力反而很大 —— 这也是为什么要做 [[llm-compression/quantization/moe模型量化]]。

## 6. 专家容量与丢 token(Expert Capacity)

理想很美:每个 token 自由选专家。**现实很骨感**:训练/推理为了能在 GPU 上批量并行,每个专家有一个**固定大小的"桶"(capacity)** —— 一次最多接收多少 token。

容量通常这样定义:

$$
C = \text{capacity\_factor} \times \frac{k\cdot T}{N}
$$

其中 $T$ = 这个 batch 里的 token 数,$\frac{kT}{N}$ 是"理想均匀情况下每个专家应分到的 token 数",`capacity_factor`(如 1.0 ~ 1.25)留出缓冲。

```
   专家 E2 的桶 (容量 C=4)
   ┌───┬───┬───┬───┐
   │ t1│ t7│ t9│t13│ ← 已满
   └───┴───┴───┴───┘
   t20 也被路由到 E2 → 桶满了 → t20 在这一层被 DROP(丢弃)
   → t20 这一层不经过 FFN,只靠残差 (x 原样 +到输出) 通过
```

**逐数手算容量与丢弃:**

```
   batch T=8 个 token, N=4 专家, k=1, capacity_factor=1.0
   理想每专家 = k·T/N = 1×8/4 = 2 个
   容量 C = 1.0 × 2 = 2
   实际门控结果(每 token 选 1 专家):
     E0: t1            (1个,未满)
     E1: t2 t3 t4 t5   (4个 > C=2 → 留前2个 t2,t3,丢 t4,t5)
     E2: t6 t7         (2个,刚好满)
     E3: t8            (1个)
   → 被丢弃: t4, t5 (这一层走残差跳过)
   丢弃率 = 2/8 = 25%  ← 太高,说明负载严重不均
```

**为什么丢 token 还能不崩?** 因为有**残差连接**:被丢的 token 输出 = 它的输入原样传下去,损失的只是这一层的"加工",不是整条命。但丢太多必然掉点 —— 这就引出第 7 节。

## 7. 负载均衡 loss:不加它,MoE 会"路由坍缩"

**最大的失败模式:训练初期门控随机偏爱某几个专家 → 这几个专家被喂得多、学得快 → 门控更爱它们 → 正反馈滚雪球 → 最后只有 2~3 个专家在干活,其余全废。** 这叫**路由坍缩(routing collapse)**,等价于花了 N 个专家的显存只用到了 3 个。

解决:在主任务 loss 之外,加一个**辅助负载均衡损失(auxiliary load-balancing loss)**,惩罚"不均匀"。Switch Transformer 的经典形式:

$$
L_{aux} = \alpha \cdot N \cdot \sum_{i=1}^{N} f_i \cdot P_i
$$

- $f_i$ = 实际被路由到专家 $i$ 的 token 比例(硬计数,不可导,只当系数)。
- $P_i$ = 门控分配给专家 $i$ 的平均概率(可导,梯度从这里走)。
- $\alpha$ = 小系数(如 0.01),别让它压过主任务。

**为什么这个式子能"逼平均"?** 当某专家又被多选($f_i$ 大)又被高估($P_i$ 大),乘积 $f_i P_i$ 就大,loss 上升,梯度会**压低**它的门控概率;均匀时 $f_i=P_i=1/N$,$\sum f_i P_i = N\cdot \frac1{N^2}=\frac1N$ 取到最小。乘 $N$ 是为了让数值与专家数无关。

```
   坍缩态(坏):                  均衡态(好):
   f=[0.7,0.2,0.07,0.03]        f=[0.25,0.25,0.25,0.25]
   ████████████  E0             ██████ E0
   ████ E1                       ██████ E1
   █ E2                          ██████ E2
   ▏ E3  (E3 几乎饿死)            ██████ E3
   L_aux 大 → 被惩罚             L_aux 最小 → 满意
```

> **DeepSeek 的演进**:辅助 loss 会和主任务"打架"(为了均衡牺牲了一点性能)。DeepSeek-V2/V3 提出**辅助损失更轻 / 无辅助损失的均衡策略**(给每个专家一个可调的 bias 项,动态调节路由热度),目标是"既均衡又不伤性能"。原理理解为主,细节以官方论文为准。

## 8. 共享专家 + 细粒度专家:DeepSeekMoE 的两板斧

朴素 MoE 还有两个隐患,DeepSeekMoE(用于 [[llm-algo/deepseek/DeepSeek-V2]])针对性地各打一拳:

### 8.1 细粒度专家(Fine-Grained Expert Segmentation)

**问题:** 专家数少、每个专家很大时,一个专家被迫塞进太多杂乱知识 → "知识纠缠",学不专。

**做法:** 把每个专家**切得更细更小**(比如把 $N$ 个大专家切成 $2N$ 或更多小专家,同时把激活数 $k$ 也按比例调大)。**总参数、总激活量基本不变,但专家组合数爆炸式增长。**

```
   粗粒度: 8 专家选 2 → 组合 C(8,2)=28 种"知识配方"
   细粒度: 16 专家选 4 → 组合 C(16,4)=1820 种
   → 同样算力,模型能表达的"专家组合"多了 60 倍,
     每个小专家也能学得更专一。
```

### 8.2 共享专家(Shared Expert Isolation)

**问题:** 有些知识是**所有 token 都要用的公共常识**(语法、通用语义)。如果让路由专家去学这些,等于每个专家都重复学一遍公共知识 —— 浪费容量、加剧冗余。

**做法:** 单独划出 1~少数几个**共享专家**,**所有 token 必过**(不参与路由竞争),专门承接公共知识;剩下的**路由专家**只负责各自的"专精领域"。

```
   x ──┬──────────► [共享专家 Es](永远激活) ───────┐
       │                                           │
       └──► Gate ──► Top-k 路由专家 (如 E3,E7) ──────┤
                       ×p3, ×p7                     │
                                                   (+)──► y
   每个 token 实际激活 = 1 个共享 + k 个路由
```

**为什么这俩组合很香?** 共享专家兜住公共知识 → 路由专家被"解放",可以更纯粹地分化成细粒度专精;细粒度又让专精组合数暴涨。**两者叠加,在相同激活算力下,专家利用率和专精度都更高。**

## 9. 完整逐数手算:一个 4 专家 Top-2 的小 MoE

把第 3、4 节串起来,用真实小数字从头算到尾(纯叙述太抽象,这里全程数字)。

**设定:** $d=2$,专家数 $N=4$,$k=2$;输入 token 向量 $x=[1,\ 2]$。

**Step 1 —— 门控打分** $g = W_g x$。设门控权重

$$
W_g=\begin{bmatrix}0.5 & 0.0\\ 0.1 & 0.3\\ -0.2 & 0.4\\ 0.0 & 0.1\end{bmatrix},\quad x=\begin{bmatrix}1\\2\end{bmatrix}
$$

逐行算内积:
```
   g0 = 0.5·1 + 0.0·2 = 0.5
   g1 = 0.1·1 + 0.3·2 = 0.1 + 0.6 = 0.7
   g2 = -0.2·1 + 0.4·2 = -0.2 + 0.8 = 0.6
   g3 = 0.0·1 + 0.1·2 = 0.2
   g = [0.5, 0.7, 0.6, 0.2]
```

**Step 2 —— 选 Top-2:** 最大的两个是 $g_1=0.7$(E1)、$g_2=0.6$(E2)。→ $\mathcal{T}=\{1,2\}$,E0、E3 睡觉。

**Step 3 —— 子集 softmax 求权重:**
```
   只看 g1=0.7, g2=0.6
   exp(0.7)=2.0138 ,  exp(0.6)=1.8221
   分母 = 2.0138 + 1.8221 = 3.8359
   p1 = 2.0138/3.8359 = 0.5250
   p2 = 1.8221/3.8359 = 0.4750
   校验: p1+p2 = 1.000 ✓
```

**Step 4 —— 专家前向**(为简洁,设每个专家是线性 $E_i(x)=W_i x$,无激活):
```
   设 W1 = [[1,0],[0,1]] (恒等)      → E1(x) = [1, 2]
   设 W2 = [[2,0],[0,0]]            → E2(x) = [2·1, 0] = [2, 0]
```

**Step 5 —— 加权合并** $y = p_1 E_1(x) + p_2 E_2(x)$:
```
   第1维: 0.5250·1 + 0.4750·2 = 0.5250 + 0.9500 = 1.4750
   第2维: 0.5250·2 + 0.4750·0 = 1.0500 + 0      = 1.0500
   y = [1.475, 1.050]
```

**Step 6 —— 残差(若有):** 真实 Transformer 里还要加回输入 $x$:$\text{out}=x+y=[1+1.475,\ 2+1.050]=[2.475,\ 3.050]$。

**算力对比(直觉):** 这一层有 4 个专家,但只算了 E1、E2 两个的前向 —— **省了 50% 专家计算**(本例 $k/N=2/4$);若是 $N=64,k=2$,则只算 $2/64\approx3\%$。这就是第 5 节那句"大参数小算力"在一个 token 上的微观证据。

## 10. 对照 / 复杂度表

| 维度 | 稠密 FFN | 稀疏 MoE |
|------|----------|----------|
| 总参数 | $P$ | $\sim N\cdot P_e$(大很多) |
| 每 token 激活参数 | $P$(全用) | $\sim k\cdot P_e$(只用一小撮) |
| 每 token FLOPs | 正比总参数 | 正比**激活**参数 |
| 显存占用 | 正比总参数 | 正比总参数(**不省**,全专家常驻) |
| 通信开销 | 无特殊 | 高(all-to-all 把 token 分发到专家所在卡) |
| 训练稳定性 | 稳 | 需 aux loss 防坍缩、需调容量 |
| 典型代表 | GPT/LLaMA 稠密 | Switch、Mixtral 8×7B、DeepSeek-V2/V3 |

**一句总结:MoE 用"显存换算力"—— 多花显存把所有专家存下来,换每 token 只算一小撮的低算力。**

## 11. 常见问题

| 疑问 | 真相 |
|------|------|
| "8×7B 是不是 56B?" | 总参≈47B 而非 56B(注意力等是共享的,不乘 8);每 token 激活≈13B(2 专家)。**"乘 8"只乘 FFN 那部分,且只算激活的 2 个。** |
| MoE 省显存吗? | **不省**。省的是 FLOPs/算力,所有专家都得常驻显存,带宽压力更大 → 需量化 [[llm-compression/quantization/moe模型量化]]。 |
| Top-1 和 Top-2 怎么选? | k=1(Switch)最省算力但表达弱、对路由噪声敏感;k=2(Mixtral)更稳更强、算力翻倍。常见折中是 k=2。 |
| 为什么会"丢 token"? | 专家容量是固定桶,负载不均时溢出的 token 被丢,靠残差跳过这一层。**aux loss + 合理 capacity_factor** 来压低丢弃率。 |
| 不加负载均衡 loss 会怎样? | **路由坍缩**:正反馈让少数专家垄断,其余饿死,等于白买显存。 |
| 共享专家和路由专家区别? | 共享专家**所有 token 必过**(学公共知识),路由专家**按门控竞争**(学专精)。DeepSeekMoE 让二者分工。 |
| MoE 一定每层都用吗? | 不一定。可隔层用,也可每层用;注意力层通常仍是稠密共享的。 |
| 门控权重为啥乘进输出? | 让门控**可微可学**,梯度能流回 $W_g$;否则"选哪个专家"是离散不可导的。 |
