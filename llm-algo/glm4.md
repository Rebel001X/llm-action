## 0. 一句话锚点

GLM-4 = **「GLM 预训练范式」的工程结晶 + 现代 Decoder 架构（RoPE/GQA/SwiGLU）+ 超长上下文 + 原生 Agent 能力**。

- **GLM** 这个名字来自原始论文 *General Language Model*（通用语言模型），其精髓是「**自回归空白填充**（Autoregressive Blank Infilling）」——一个统一目标同时具备 BERT 式理解与 GPT 式生成的能力。
- 到了 GLM-4，对话/推理形态已经**完全 Decoder-only 自回归**（和 GPT/LLaMA 一样从左到右生成），但血统上承袭 ChatGLM 系列。
- **代表型号**：闭源旗舰 `GLM-4`/`GLM-4-Plus`、长文本 `GLM-4-Long`、轻量 `GLM-4-Air/AirX/Flash`、多模态 `GLM-4V`，以及开源的 `GLM-4-9B` / `GLM-4-9B-Chat`（128K，部分变体 1M）。

> 记忆钩子：**GLM-4 是「能看长文档、会用工具、中文最顺」的国产 GPT-4 平替**。

## 1. 地基/前置

### 1.1 GLM 的原始思想：自回归空白填充

要理解 GLM-4 为什么叫 GLM，必须回到它的训练目标。普通模型的两条路线：

```
 BERT (Encoder)            GPT (Decoder)
 ─────────────             ─────────────
 双向看全文                 只看左边
 擅长「理解/填空」          擅长「续写/生成」
 [MASK] 独立预测            P(x_t | x_<t)
 不会生成长文本             不会用右侧上下文
```

GLM 想「鱼与熊掌兼得」：把一句话里随机抽掉若干**连续片段（span）**，然后让模型**自回归地、按打乱顺序**把这些空白一段一段填回去。

```
原句:  我 爱 北京 天安门 广场
挖空:  我 爱 [S1]   广场                (S1 = 「北京 天安门」)
任务:  自回归生成 S1 内部 token： 北京 → 天安门
```

- 填**空白外**的部分用双向注意力（像 BERT，能看全局）；
- 填**空白内**的部分用单向注意力（像 GPT，自回归逐 token）。

这就是 GLM 名字与早期优势的来源：**一个目标统一了理解与生成**。GLM-4 在大规模对话场景下把这套思想工程化、Decoder 化。

### 1.2 从 GLM-130B 到 ChatGLM 到 GLM-4

```
GLM-130B (2022, 双语千亿基座, 8-bit/4-bit 量化首发)
        │  对齐/指令化 + 缩小到 6B 方便部署
        ▼
ChatGLM-6B (2023, 火爆开源, 2D-RoPE + GLU + DeepNorm)
        ▼
ChatGLM2-6B (32K上下文, FlashAttention, Multi-Query Attn, 推理提速)
        ▼
ChatGLM3-6B (Function Call + 代码解释器 + Agent 提示模板)
        ▼
GLM-4 / GLM-4-9B (2024, 128K~1M, GQA, All Tools, 多模态 GLM-4V)
        ▼
GLM-4-Plus / GLM-4-0520 等持续迭代（以官方为准）
```

记住这条线：**能力是「逐代叠加」的——上下文越来越长、工具能力越来越原生、对齐越来越好。**

> 详见 [[llm-algo/chatglm/README]]。

## 2. 整体家族与定位

GLM-4 不是单一模型，而是一组**按成本/能力/模态分层**的产品矩阵：

```
                       能力/成本 高 ───────────────► 低
 旗舰推理   GLM-4-Plus ─ GLM-4(-0520) ─ GLM-4-Air ─ GLM-4-AirX ─ GLM-4-Flash
 长文本     GLM-4-Long  (最高 ~1M tokens 级)
 多模态     GLM-4V / GLM-4V-Plus  (图文理解)
 开源自部署 GLM-4-9B / GLM-4-9B-Chat (128K) / GLM-4-9B-Chat-1M
 代码       CodeGeeX(同源系列, 代码专精)
```

- **GLM-4-Plus**：综合最强，对标 GPT-4 / GPT-4o 级别（语言、推理、长文）。
- **GLM-4-Air / Flash**：极致性价比，Flash 常被定位为「快且便宜甚至免费」，适合高并发/Agent 批处理。
- **GLM-4-9B**：开源主力，9B 激活全参数，128K 上下文，单卡可跑，是社区微调与本地部署首选。
- **GLM-4V**：在语言塔上接视觉编码器，做图文问答、OCR、图表理解。

> 选型口诀：**要私有化/微调选 9B；要最强选 Plus；要省钱高并发选 Air/Flash；要看图选 V；要读整本书选 Long。**

## 3. 架构逐层拆解（GLM-4-9B 为代表）

GLM-4 已是标准的 **Decoder-only Transformer**，但在多个组件上采用了「现代最优解」组合。下面逐个原子拆开。

### 3.1 一层 Transformer Block 长什么样

```
            ┌──────────── 输入 hidden h (维度 d) ────────────┐
            │                                                │
   ┌────────▼────────┐                                       │
   │  RMSNorm (Pre)  │                                       │
   └────────┬────────┘                                       │
            │                                                │
   ┌────────▼────────────────────────┐                       │
   │  Self-Attention                 │                       │
   │   Q,K,V 投影                    │                       │
   │   RoPE 给 Q,K 注入位置          │                       │
   │   GQA: 多个Q头共享少量KV头       │                       │
   │   Causal Mask (只看左边)        │                       │
   └────────┬────────────────────────┘                       │
            │                                                │
            ▼ (+) 残差 ◄──────────────────────────────────────┘
            │
   ┌────────▼────────┐
   │  RMSNorm        │
   └────────┬────────┘
            │
   ┌────────▼──────────────────────┐
   │  FFN = SwiGLU                 │
   │   gate = SiLU(W_g x)          │
   │   up   = W_u x                │
   │   out  = W_d (gate ⊙ up)      │
   └────────┬──────────────────────┘
            │
            ▼ (+) 残差
            ▼
        下一层 / 输出
```

### 3.2 组件逐一「为什么」

**(a) RMSNorm（替代 LayerNorm）**
$$\text{RMSNorm}(x)=\frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2+\epsilon}}\cdot g$$
- 只做「均方根缩放」，**不减均值、不加偏置**，比 LayerNorm 少一半统计量，更快更稳。
- 为什么：大模型里减均值收益小，去掉省算力且训练更稳。

**(b) RoPE 旋转位置编码**
- 把位置信息编码成对 Q、K 向量的**旋转**，第 $m$ 个 token、第 $i$ 对维度旋转角 $\theta_i = 10000^{-2i/d}$，旋转量 $m\theta_i$。
- 注意力打分时两个旋转相减，自然得到**相对位置** $m-n$：$\langle R_m q, R_n k\rangle$ 只依赖 $m-n$。
- 为什么用它：相对位置 + 可外推（调 base 就能拉长上下文），是长文本的基础。详见 [[llm-algo/旋转编码RoPE]]。

**(c) GQA 分组查询注意力（GLM-4 的关键升级）**
- MHA：每个 Query 头配独立 K/V 头 → KV Cache 巨大。
- MQA（ChatGLM2 用）：所有 Q 头共享 **1 组** K/V → 省显存但略掉点。
- **GQA**：折中，把 Q 头分成 $G$ 组，每组共享一组 K/V。

```
 MHA            MQA              GQA (GLM-4)
 Q1 Q2 Q3 Q4    Q1 Q2 Q3 Q4      Q1 Q2 | Q3 Q4
 │  │  │  │      \ \ / /          \  /    \  /
 K1 K2 K3 K4        KV             KV1     KV2
 V1 V2 V3 V4
 KV 最大         KV 最小          KV 适中, 质量好
```
- 为什么：KV Cache 大小 ∝ KV 头数。GQA 把推理显存压到 MHA 的 $G/H$，几乎不掉点 → **长上下文推理可行的关键**。

**(d) SwiGLU 前馈网络**
$$\text{SwiGLU}(x)=\big(\text{SiLU}(xW_g)\odot xW_u\big)W_d,\quad \text{SiLU}(z)=z\cdot\sigma(z)$$
- 用「门控」让网络自适应放大/抑制特征，比 ReLU-FFN 表达力强。
- 代价：FFN 多一个矩阵，所以隐藏维通常设为 $\frac{2}{3}\times$ 原来的 4d，使参数量持平。

**(e) Post-Norm / 深度稳定**
- GLM 系列历史上偏好把归一化放在残差之后或采用 DeepNorm 思路以稳住深层训练；GLM-4 在大深度下做了相应稳定化处理（以官方实现为准）。

### 3.3 数据流总览（一次前向）

```
token id ──► Embedding(d) ──► [Block × L] ──► RMSNorm ──► LM Head(weight tied?) ──► logits(vocab)
                                  ▲
            每层: Attn(RoPE+GQA+Causal) + SwiGLU FFN + 残差
```

## 4. 长上下文：128K ~ 1M token 怎么实现

长上下文是 GLM-4 最被强调的卖点之一。它由「三件套」共同支撑：

### 4.1 位置外推：RoPE base 缩放

- 原始 RoPE 在训练长度外会「角度转太快」失真。把基频 $\text{base}=10000$ 调大（NTK-aware / 频率插值），相当于**把刻度尺拉长**，让模型在更长序列上仍能区分相对位置。

```
短训练(2K)        外推到 128K
角度密            角度稀疏(调大base)
位置可分          否则远处位置"绕圈"混叠
```

### 4.2 训练阶段渐进式拉长

```
阶段1: 大批量 4K~8K 学语言        (便宜, 学知识)
阶段2: 续训 32K → 128K           (拉长, 学远距离依赖)
阶段3: 1M 变体专门长序列续训      (GLM-4-9B-Chat-1M)
```
为什么分阶段：直接全程超长训练成本爆炸（注意力是 $O(n^2)$），先短后长最省。

### 4.3 推理显存：KV Cache 才是瓶颈

注意力计算可用 FlashAttention 把显存从 $O(n^2)$ 降到 $O(n)$，但 **KV Cache 随上下文线性增长**才是部署痛点 —— 这正是 GQA 的价值。

KV Cache 显存（每 token）：
$$M_{kv/tok}=2\times L \times H_{kv}\times d_{head}\times \text{bytes}$$
- 2 = K 和 V；$L$ 层数；$H_{kv}$ KV 头数（GQA 下很小）；$d_{head}$ 每头维度。

> 直觉：**RoPE 让模型「看得到」远处，GQA 让显存「装得下」远处，渐进训练让模型「学得会」远处。** 三者缺一不可。

## 5. 与 ChatGLM 的演进对比

| 维度 | ChatGLM-6B | ChatGLM2-6B | ChatGLM3-6B | **GLM-4 / 9B** |
|------|-----------|-------------|-------------|----------------|
| 上下文 | 2K | 32K | 8K(对话) | **128K（部分 1M）** |
| 位置编码 | 2D-RoPE | RoPE | RoPE | RoPE(+外推) |
| 注意力 | MHA | **MQA** | MQA | **GQA** |
| 激活/FFN | GLU | SwiGLU | SwiGLU | SwiGLU |
| 工具调用 | 无 | 无 | **Function Call/代码解释器** | **All Tools 原生** |
| 多模态 | 无 | 无 | 无 | **GLM-4V** |
| 对齐 | SFT | SFT/RLHF | 改进 | **更强 RLHF/对齐** |
| 定位 | 入门开源 | 提速长文 | Agent 雏形 | 旗舰全能 |

```
能力堆叠示意:
ChatGLM   : [基础对话]
ChatGLM2  : [基础对话] + [长文32K] + [快]
ChatGLM3  : 上面 + [工具/Agent雏形]
GLM-4     : 上面 + [128K~1M] + [GQA省显存] + [多模态] + [强Agent] + [更好中文对齐]
```

- **演进逻辑**：每代解决上一代最痛的点。2 解决「太短太慢」，3 解决「不会用工具」，4 解决「不够长、不够多模态、对齐不够强」。

## 6. 多模态 GLM-4V

GLM-4V 让语言塔「长出眼睛」。基本范式：**视觉编码器 → 投影对齐 → 拼进语言模型**。

```
 图像 ─► [Vision Encoder (ViT 类)] ─► 视觉特征 (一堆 patch 向量)
                                          │
                                  ┌───────▼────────┐
                                  │  投影/对齐 MLP  │  把视觉维度映射到语言维度
                                  └───────┬────────┘
                                          ▼
 文本 token ──► Embedding ──►  [图像token | 文本token] 拼成序列
                                          │
                                  ┌───────▼────────┐
                                  │  GLM-4 语言塔   │  统一自回归生成回答
                                  └────────────────┘
```

- **为什么这样设计**：复用强大的语言塔，只需让视觉特征「说语言塔听得懂的话」（同一向量空间），训练成本远低于从零做多模态。
- **能力**：图文问答、OCR/文档理解、图表/表格解读、中文场景图像理解（中文 OCR 是其强项）。
- 训练通常分「视觉-语言对齐预训练 → 多模态指令微调」。

## 7. Agent / 工具调用（All Tools）

GLM-4 的一大招牌是 **All Tools**：模型自主判断何时调用网页浏览、代码解释器、文生图、自定义函数（Function Call）。

```
用户: "帮我查今天上证指数收盘并画个最近5日折线"
        │
        ▼  模型推理 → 决定调用工具
   ┌────────────────────────────────────┐
   │ 1) web_browser(query=...)  取数据   │
   │ 2) code_interpreter(...)   画图     │
   └────────────────────────────────────┘
        │ 工具返回结果(observation)
        ▼
   模型读结果 → 继续推理 / 再调工具 / 最终作答
```

机制要点：
- **结构化协议**：SFT 阶段注入特殊 token / 角色（如工具调用块、observation 块），模型学会输出「调用哪个工具 + 参数（JSON）」。
- **多轮 ReAct 循环**：思考(Reason) → 行动(Act/调用) → 观察(Observe) → 再思考，直到给出答案。
- **Function Call**：开发者声明函数签名（名称/参数 schema），模型按需返回要调用的函数与入参，外部执行后回灌结果。

> 这把 ChatGLM3 的「工具雏形」升级成了**原生、可组合、多工具协同**的 Agent 能力。

## 8. 中文优化：为什么 GLM-4 中文顺

中文优势不是单点，而是三层叠加：

```
┌──────────────────────────────────────────────┐
│ 数据层:  高质量中文语料占比高(网页/书籍/百科/   │
│          学术/代码) + 严格清洗去重             │
├──────────────────────────────────────────────┤
│ 分词层:  词表对中文友好, 常用汉字/词组单 token, │
│          压缩率高 → 同样字数占用更少 token      │
├──────────────────────────────────────────────┤
│ 对齐层:  中文指令/对话/安全数据做 SFT+RLHF,     │
│          贴合中文表达习惯/语气/格式             │
└──────────────────────────────────────────────┘
```

- **分词压缩率**例子：英文 BPE 常把一个汉字切成 2~3 个 token；若词表针对中文优化，一个常用汉字 ≈ 1 token，则同一段 1000 字中文文本占用 token 数显著更少 → **同样 128K 窗口能装更多中文内容**、推理更省、更便宜。
- **本土知识/语料**：成语、古文、法律、行业术语覆盖更全，少出现「中式英文翻译腔」。
- 这也是国产模型（GLM-4、Qwen 等）在中文榜单常领先海外通用模型的根因之一。对比 Qwen 系列见 [[llm-algo/qwen/README]]。

## 9. 训练流程（三段式）

```
①预训练 Pretrain
   万亿级 token 中英双语 + 代码; 渐进拉长上下文
   目标: 自回归语言建模(Next-token); 学知识与语言
            │
②监督微调 SFT
   高质量指令/对话/工具调用/多轮数据
   目标: 学"按指令做事""会调工具"的格式
            │
③对齐 RLHF / 偏好优化
   人类偏好/规则反馈 (RM + PPO 或 DPO 类)
   目标: 更有用、更安全、更符合人类期望
```

- **为什么三段**：预训练给「知识与语言能力」，SFT 给「听话与工具格式」，RLHF 给「价值观与偏好」。缺 SFT 不会对话，缺 RLHF 容易胡说/不安全。

## 数值例子 / 对照（以 GLM-4-9B 量级估算，仅示意）

> 下列均为**量级手算**，帮助建立直觉；精确数字以官方为准。

设近似超参：层数 $L\approx 40$，隐藏维 $d\approx 4096$，注意力头 $H=32$，GQA 的 KV 头 $H_{kv}=8$，每头维 $d_{head}=128$，参数 $P\approx 9\times10^9$，词表 $V\approx 15$万。

**(1) 推理权重显存**
- FP16：$9\text{B}\times 2\,\text{B} = 18\,\text{GB}$
- INT8：$\approx 9\,\text{GB}$；INT4：$\approx 4.5\,\text{GB}$
- 结论：**一张 24GB 显卡（如 4090）FP16 勉强放下、INT4 轻松跑**，这正是 9B 开源的实用意义。

**(2) KV Cache（GQA 的威力）**
每 token KV：$2\times L\times H_{kv}\times d_{head}\times 2\,\text{B}=2\times40\times8\times128\times2=163{,}840\,\text{B}\approx 0.16\,\text{MB/tok}$
- 128K token：$0.16\,\text{MB}\times131072\approx 20.5\,\text{GB}$
- 若用 MHA（$H_{kv}=32$）：同样 128K 需 $\approx 82\,\text{GB}$ —— **GQA 直接省到 1/4**，这就是为什么长上下文必须用 GQA。

**(3) 中文 token 压缩**
- 一篇 5 万字中文长报告：英文向 BPE（约 2 token/字）≈ 10 万 token，可能塞不进 128K 的其它内容；中文友好分词（约 0.7~1 token/字）≈ 4~5 万 token，**还剩一半多窗口放对话/工具结果**。

**(4) 单次前向 FLOPs（直觉）**
- 经验式：每 token 前向 $\approx 2P$ FLOPs ⇒ $2\times9\times10^9=1.8\times10^{10}$ FLOPs/token。
- 一张约 100 TFLOPS（FP16 有效）卡，理论上限 $\approx 100\times10^{12}/1.8\times10^{10}\approx 5500$ token/s（实际受访存/KV/批次限制，远低于此，仅示意）。详见 [[llm-algo/FLOPs]]。

```
显存账本(128K, FP16 权重 + GQA KV):
 权重 18GB  ████████████████
 KV   20GB  ██████████████████   ← 长上下文的真正大头
 激活/其它 ~数GB
 → 单卡 48GB(如 A6000) 可跑 9B 128K; 24GB 需量化/缩短上下文
```

## 常见问题（FAQ）

| 问题 | 回答 |
|------|------|
| GLM-4 还是「空白填充」目标吗？ | 血统来自 GLM，但对话推理形态是标准 Decoder-only 自回归；空白填充思想更多体现在早期 GLM/预训练设计 |
| GLM-4 和 ChatGLM 什么关系？ | ChatGLM 是前几代（1/2/3），GLM-4 是第四代旗舰，能力是逐代叠加 |
| 9B 一定要多卡吗？ | 不必。FP16 约 18GB 单卡可放；INT4 约 4.5GB 消费卡可跑；长上下文才需更多显存（KV Cache） |
| 为什么长上下文要 GQA？ | KV Cache ∝ KV 头数，GQA 把它压到 MHA 的 1/4 左右，否则 128K 显存爆炸 |
| GLM-4 中文为什么强？ | 数据中文占比高 + 分词压缩率好 + 中文 SFT/RLHF 对齐，三层叠加 |
| All Tools 和 Function Call 区别？ | Function Call 是「让模型按 schema 返回要调的函数」；All Tools 是更上层的多工具自主编排（含浏览/代码/绘图/自定义函数） |
| GLM-4 vs Qwen 怎么选？ | 都是中文强、Agent 强的国产第一梯队；按生态/价格/榜单/微调便利性择优，见 [[llm-algo/qwen/README]] |
| GLM-4-Plus 对标谁？ | 综合能力对标 GPT-4 / GPT-4o 级（具体以官方评测为准） |
| 1M 上下文实用吗？ | 适合整书/大型代码库检索式任务，但显存与延迟代价高，多数场景 128K 足够 |
