## 0. 一句话锚点

把 Baichuan2 想成一句话：

```
Baichuan2 ≈ LLaMA 的「身体」（Decoder-only + RMSNorm + SwiGLU + RoPE）
          + 一颗「中文大脑」（125696 大词表，中英文混训 2.6T tokens）
          + 三贴「稳定膏药」（NormHead、max-z loss、13B 改用 ALiBi）
```

如果你已经懂 LLaMA（见 [[llm-algo/llama/模型架构]]），那么学 Baichuan2 只需要记住它**改了哪几处**——本文的重点就是这几处「Delta」。

## 1. 地基 / 前置（不假设你记得）

在看改造之前，先把三块地基铺平、拆到最原子。

### 1.1 什么是 Decoder-only Transformer

现代主流大模型（GPT、LLaMA、Baichuan、Qwen）都是 **Decoder-only**：只有堆叠的 Block、没有 Encoder；任务是「预测下一个 token」；每个 Block = 一个**自注意力**（Self-Attention）+ 一个**前馈网络**（FFN）；用**因果掩码**（causal mask）保证第 $i$ 个位置只能看到 $\le i$ 的位置（不偷看未来）。

```
输入: "今天 天气 真"
       ↓  词嵌入(Embedding) + 位置信息
  ┌─────────────────────────────┐
  │  Block 1: Attn → FFN         │  ← 残差 + 归一化
  │  Block 2: Attn → FFN         │
  │     ...  (共 L 层)            │
  │  Block L: Attn → FFN         │
  └─────────────────────────────┘
       ↓  输出头(LM Head) → softmax
输出: P(下一个词 = "好"/"不错"/...)
```

### 1.2 为什么需要「位置编码」

注意力机制本身是**置换不变**的：打乱词序，纯注意力算出来一样。但语言有顺序（"猫追狗" ≠ "狗追猫"）。所以必须显式告诉模型「每个词在第几个位置」。这就是**位置编码**。两大流派：

- **RoPE（旋转位置编码）**：把位置以「旋转角度」乘进 Q、K 向量里（详见 [[llm-algo/旋转编码RoPE]]）。
- **ALiBi（Attention with Linear Biases）**：不显式编码位置，而在注意力分数上**按距离加线性惩罚**，越远惩罚越大。

Baichuan2 的一个独特设计：**7B 用 RoPE，13B 用 ALiBi**（第 4 节细讲）。

### 1.3 什么是「词表 / Tokenizer」

模型不能直接读汉字，要先把文本切成 **token**（子词单元），再映射成整数 ID。

- **词表大小（vocab size）** = 模型认识多少个不同 token。
- 词表越大 → 同一句中文用越少的 token 表示（**压缩率高**）→ 同样上下文长度能装下更多内容，推理更快。
- LLaMA 原版词表 32000，偏英文，中文常被切成很碎的字节，压缩率差。Baichuan2 把词表扩到 **125696**，大幅改善中文（第 3 节）。

## 2. 整体架构与超参

Baichuan2 整体是标准 Decoder-only，单层结构如下（Pre-Norm，残差包裹）：

```
        x  (隐藏状态)
        │
   ┌────┴─────────────────────────┐
   │  RMSNorm                      │
   │      │                        │
   │  Self-Attention (RoPE 或 ALiBi)│
   │      │                        │
   └──────┼── + x  (残差相加) ──────┘
          │
   ┌──────┴─────────────────────────┐
   │  RMSNorm                        │
   │      │                          │
   │  FFN (SwiGLU: gate·up → down)   │
   │      │                          │
   └──────┼── + 上一步 (残差) ────────┘
          │
        输出 → 下一层
```

堆叠 $L$ 层后，最后接一个 **RMSNorm + NormHead 输出头**。两个规模的核心超参对照：

| 超参 | Baichuan2-7B | Baichuan2-13B |
|------|--------------|----------------|
| 参数量 | ~7.0 B | ~13.0 B |
| 层数 $L$ | 32 | 40 |
| 隐藏维度 $d$ | 4096 | 5120 |
| 注意力头数 | 32 | 40 |
| FFN 中间维度 | 11008 | 13696 |
| **位置编码** | **RoPE** | **ALiBi** |
| 词表大小 | 125696 | 125696 |
| 上下文长度 | 4096 | 4096 |
| 归一化 | RMSNorm | RMSNorm |
| 激活 | SwiGLU | SwiGLU |
| 输出头 | NormHead | NormHead |
| 训练数据 | 2.6T tokens | 2.6T tokens |

> 直觉：7B 和 13B 共享词表、数据、骨架，主要差别是「层数/宽度」和「位置编码方案」。

## 3. 词表与中文优化

这是 Baichuan2「中文优化」的第一根支柱。

### 3.1 为什么扩词表

LLaMA 词表 32000，主要面向英文。中文很多字/词在它的 BPE 里被拆成多个 **UTF-8 字节 token**。例如「人工智能」在小词表里可能要 8~12 个 token，而在大词表里只要 2~4 个。

Baichuan2 把词表扩到 **125696**，并用 **SentencePiece BPE** 在中英文混合语料上重新训练。同时：

- 数字按**单个数字**切分（"2023" → "2","0","2","3"），有利于数学/数值任务。
- 保留对代码空白（连续空格、缩进）友好的处理。

### 3.2 压缩率对比（直觉图）

```
句子: "人工智能正在改变世界"  (10 个汉字)

LLaMA(32k词表):   人  工  智  能 ... → 字节级拆分 ≈ 18~24 tokens
  [▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮]   token 多 → 上下文吃紧

Baichuan2(125k):  人工 智能 正在 改变 世界 → ≈ 5~8 tokens
  [▮▮▮▮▮▮▮]                  token 少 → 同窗口装更多 → 更快更省
```

更高的中文压缩率意味着：**相同 4096 上下文窗口，Baichuan2 能塞进更多实际汉字内容**，训练和推理都更高效。

### 3.3 大词表的代价

词表从 32000 → 125696，输出层（LM Head）和输入嵌入的参数量随之增大：
- 嵌入参数 = $V \times d$。7B 时 $125696 \times 4096 \approx 5.15$ 亿，比 32000 词表多约 3.8 亿参数。
- 这也是 NormHead（第 5 节）要解决稳定性问题的背景之一。

## 4. 位置编码：7B 的 RoPE vs 13B 的 ALiBi

Baichuan2 最有「记忆点」的设计：**两个规模用了不同的位置编码**。

### 4.1 RoPE（7B 用）—— 旋转位置编码

核心思想：把每个位置 $m$ 对应一个**旋转角度**，按维度成对地把 Q、K 向量「转一个角」。位置 $m$ 的旋转角与频率 $\theta_i = 10000^{-2i/d}$ 有关：

$$
\text{RoPE}(x_m, m) = R_{\Theta,m}\, x_m, \quad
R \text{ 是按 } m\theta_i \text{ 旋转的分块对角矩阵}
$$

旋转后，注意力分数 $q_m^\top k_n$ 只依赖**相对位置** $m-n$。这就是 RoPE 的精髓——**相对位置感知 + 良好外推**。

```
维度对 (x0,x1):
  位置 m=0:  →  (不转)
  位置 m=1:  ↗  (转 θ)
  位置 m=2:  ↑  (转 2θ)
  ...        旋转角随位置线性增长
注意力只看 "两个向量转角之差" = 相对距离
```

### 4.2 ALiBi（13B 用）—— 线性偏置

ALiBi 不动 Q、K，而是**直接在注意力分数矩阵上加一个与距离成正比的负偏置**：

$$
\text{score}(i,j) = \frac{q_i \cdot k_j}{\sqrt{d_k}} - m \cdot (i - j)
$$

其中 $m$ 是每个注意力头一个的**固定斜率**（不可学习），距离 $(i-j)$ 越大，惩罚越大 → 越远的 token 越被「压低」。

```
注意力偏置（某个头，斜率 m）:
  query 位置 i, 看 key 位置 j
  j 越远(i-j 越大) → 减得越多
        j=i  j-1  j-2  j-3  j-4
  bias:  0   -m  -2m  -3m  -4m
  ┌──────────────────────────┐
  │ 近 ████████  权重高        │
  │ 远 ██        权重被线性压低 │
  └──────────────────────────┘
```

### 4.3 为什么 7B 和 13B 分叉

| 对比 | RoPE（7B） | ALiBi（13B） |
|------|-----------|---------------|
| 机制 | 旋转 Q/K，编码相对位置 | 在 score 上加距离惩罚 |
| 额外参数 | 无（频率固定） | 无（斜率固定） |
| 长度外推 | 需配合插值/调频 | 天然较好（惩罚线性） |
| 显存/速度 | 旋转开销小 | 实现简单，KV 缓存友好 |
| Baichuan2 取舍 | 小模型上效果好、生态成熟 | 大模型长序列外推更稳 |

官方说法是两种方案在各自规模上表现更佳，本质都不引入可学习位置参数。延伸阅读 [[llm-algo/旋转编码RoPE]]。

## 5. NormHead：归一化输出嵌入头

这是 Baichuan2「稳定性」的第二根支柱，针对**输出层**。

### 5.1 问题：输出嵌入范数失衡

LM Head（输出投影）权重矩阵 $W \in \mathbb{R}^{V \times d}$，每一行 $w_v$ 对应一个 token 的「输出嵌入」。logit 计算：

$$
\text{logit}_v = h \cdot w_v
$$

训练中发现：**低频 token 的 $\|w_v\|$ 会越训越大或越小**，导致 logit 主要被「范数」而非「方向（语义）」主导。罕见词容易被范数放大而异常高分，影响稳定性和生成质量。

### 5.2 解法：把输出权重逐行 L2 归一化

NormHead 在算 logit 前，先把每行权重归一化到单位长度：

$$
\hat{w}_v = \frac{w_v}{\|w_v\|_2}, \qquad \text{logit}_v = h \cdot \hat{w}_v
$$

这样 logit 只取决于隐藏状态 $h$ 与 token 嵌入的**方向（余弦相似度）**，与范数无关。

```
普通 Head:        NormHead:
  w_v 范数各异      w_v 全部投到单位球面
   w_a ──────►        ŵ_a ─►│
   w_b ─►             ŵ_b ─►│   (都 = 1)
   w_c ────────►      ŵ_c ─►│
  logit 受范数干扰   logit 只看方向(语义)
```

### 5.3 效果

- 稳定训练，缓解低频 token 的范数漂移，让生成更依赖语义相似度、提升收敛稳定性；代价是每步多一次按行归一化（开销很小）。

## 6. max-z loss：抑制 logits 数值爆炸

第三根稳定性支柱，针对**整体 logits 量级**。

### 6.1 问题：logits 越训越大

随训练进行，最大 logit（记 $z_{\max} = \max_v \text{logit}_v$）可能持续膨胀。后果：
- softmax 输出过度尖锐、数值溢出风险；
- 对推理时的温度/重复惩罚等超参敏感；
- 训练不稳定。

这与 PaLM 论文报告的现象一致，Baichuan2 借鉴并加了一个正则项。

### 6.2 解法：在交叉熵基础上加一个惩罚最大 logit 的项

$$
\mathcal{L} = \mathcal{L}_{\text{CE}} + \lambda \cdot z_{\max}^2
$$

直觉：$z_{\max}^2$ 这一项**把最大 logit 往 0 拉**，防止它无限增大。$\lambda$ 是很小的系数（Baichuan2 论文取约 $2\text{e-}4$）。

```
不加 max-z:                加 max-z loss:
 z_max ↑↑↑ 持续膨胀         z_max 被 λ·z² 拉住
 logit  ╱                  logit  ╱‾‾‾  (饱和)
        ╱                         ╱
 →softmax 尖锐/溢出         → softmax 平滑/稳定
```

### 6.3 与 NormHead 的分工

| 机制 | 管什么 | 作用对象 |
|------|--------|----------|
| NormHead | logit 的**方向 vs 范数** | 输出权重行 $w_v$ |
| max-z loss | logit 的**整体量级** | 最终 logits 最大值 |

两者配合，共同把「输出端」的数值稳住。

## 7. 训练数据

Baichuan2「中文优化」的根基不只在词表，更在**数据**。

### 7.1 规模与配比

- **总量约 2.6 T tokens**（2.6 万亿），比上一代 Baichuan1（1.2T）翻倍多；**中英文 + 多语种 + 代码**混合，强调中文高质量语料占比，兼顾英文与多领域（网页、书籍、论文、代码、问答等）。

```
数据来源（示意，比例以官方为准）：
  网页文本   ████████████████  最大头
  书籍/百科  ██████
  代码        ████
  学术/论文   ███
  社区问答    ███
  其他多语种  ██
  ─────────────────────  合计 ≈ 2.6T tokens
```

### 7.2 数据处理流水线（为什么要清洗）

垃圾数据进 → 垃圾模型出。Baichuan2 的数据管线大致包含：

```
原始语料
   │  ① 去重(段落/文档/全局 dedup)
   ▼
   │  ② 质量过滤(规则 + 模型打分，剔低质/广告/乱码)
   ▼
   │  ③ 安全过滤(剔有害/隐私内容)
   ▼
   │  ④ 配比采样(按领域/语种调权重)
   ▼
高质量 2.6T tokens → 训练
```

### 7.3 训练配置要点

- **优化器** AdamW（$\beta_1{=}0.9,\beta_2{=}0.95$ 量级，带权重衰减）；**学习率** warmup → cosine 衰减；**精度** BFloat16 混合精度；**上下文** 4096；训练用数千张 NVIDIA GPU（集群规模以官方为准）。

## 8. 其余组件（与 LLaMA 同源，快速过）

这些组件 Baichuan2 沿用 LLaMA 系做法，点名即可（细节见 [[llm-algo/llama/模型架构]]）：

### 8.1 RMSNorm（替代 LayerNorm）

只用均方根缩放，不减均值、无 bias：

$$
\text{RMSNorm}(x) = \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}} \cdot g
$$

比 LayerNorm 少一次求均值，更快且稳定。

### 8.2 SwiGLU 前馈网络

FFN 用门控线性单元，三个权重 $W_{\text{gate}}, W_{\text{up}}, W_{\text{down}}$：

$$
\text{FFN}(x) = W_{\text{down}}\big(\text{SiLU}(W_{\text{gate}} x) \odot (W_{\text{up}} x)\big)
$$

$\odot$ 是逐元素相乘的「门」。比普通 ReLU-FFN 表达力更强，这也是中间维度（11008/13696）不是 $4d$ 整数倍的原因——为了在等参数量下补偿三矩阵结构。

### 8.3 与同类中文模型的关系

| 模型 | 词表 | 位置编码 | 稳定性技巧 | 备注 |
|------|------|----------|-----------|------|
| LLaMA | 32000 | RoPE | — | 英文为主，骨架来源 |
| Baichuan2-7B | 125696 | RoPE | NormHead + max-z | 中文优化 |
| Baichuan2-13B | 125696 | ALiBi | NormHead + max-z | 大模型外推 |
| Qwen | 151k+ | RoPE | logit cap 等 | 见 [[llm-algo/qwen/README]] |

## 9. 数值例子 / 对照（手算）

把抽象数字落到实处，全部可手算复核。

### 9.1 嵌入层参数量（大词表的代价）

输入嵌入 / 输出头参数 = $V \times d$：

- Baichuan2-7B：$125696 \times 4096 = 514{,}850{,}816 \approx 5.15$ 亿（输入+输出若共享则一份，不共享则两份）。
- 若用 LLaMA 词表 32000：$32000 \times 4096 = 131{,}072{,}000 \approx 1.31$ 亿。
- **多出约 3.84 亿参数**，几乎全是为中文压缩率买的单——但换来推理时更少的 token 数。

### 9.2 单层注意力 + FFN 参数量（7B）

设 $d=4096$，FFN 中间维 $f=11008$：

- 注意力 $W_Q,W_K,W_V,W_O$：$4 \times d^2 = 4 \times 4096^2 = 67{,}108{,}864 \approx 0.67$ 亿。
- FFN（SwiGLU 三矩阵）：$3 \times d \times f = 3 \times 4096 \times 11008 = 135{,}266{,}304 \approx 1.35$ 亿。
- 单层合计 $\approx 2.02$ 亿；$\times 32$ 层 $\approx 64.7$ 亿，加嵌入 $\approx 70$ 亿，与「7B」吻合。✅

### 9.3 推理显存粗算（7B，FP16）

- 权重：$7\text{B} \times 2\text{ 字节} = 14$ GB。
- 4096 上下文的 KV 缓存（单条）：约 $2 \times L \times d \times \text{seq} \times 2\text{ 字节} = 2 \times 32 \times 4096 \times 4096 \times 2 \approx 2.1$ GB。
- 合计约 **16 GB 量级** → 一张 24GB 显卡（如 RTX 3090/4090）可跑 7B 推理（以实际框架/量化为准）。

### 9.4 中文压缩率收益（直觉账）

假设一篇 1 万汉字中文文档：
- LLaMA 词表 ≈ 每字 1.8 token → 约 18000 token，超出 4096 窗口，需切 5 段。
- Baichuan2 ≈ 每字 0.7 token → 约 7000 token，仍超 4096 但只需切 2 段。
- 同样模型上下文，Baichuan2 处理同篇文档的**调用次数显著更少**，吞吐更高。

| Baichuan2 和 LLaMA 什么关系？ | 沿用 LLaMA 的 Decoder-only 骨架（RMSNorm/SwiGLU/RoPE），但换了大词表、加了 NormHead/max-z、13B 改 ALiBi，并用中英文 2.6T 数据重训。 |
| 为什么 7B 用 RoPE 而 13B 用 ALiBi？ | 官方在各自规模上调优的结果：小模型 RoPE 表现好，大模型长序列 ALiBi 外推更稳。两者都不引入可学习位置参数。 |
| NormHead 解决什么问题？ | 输出权重各行范数失衡导致 logit 被范数而非语义主导；逐行 L2 归一化后 logit 只看方向，训练更稳。 |
| max-z loss 是什么？ | 在交叉熵上加 $\lambda z_{\max}^2$，把最大 logit 往下拉，防止 logits 数值爆炸、softmax 过尖。 |
| 词表为什么扩到 12.5 万？ | 提升中文压缩率：同样上下文窗口装更多汉字，训练/推理更高效；代价是嵌入层多约 3.8 亿参数。 |
| 训练数据规模？ | 约 2.6T tokens，中英文+多语种+代码混合，经去重/质量/安全过滤（具体配比以官方为准）。 |
| Base 和 Chat 区别？ | Base 是预训练基座；Chat 在其上做 SFT + 人类对齐（RLHF/偏好优化），可直接对话。上下文长度 4096。 |
