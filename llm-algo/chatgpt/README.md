## 0. 一句话锚点

**InstructGPT = GPT-3 + RLHF（基于人类反馈的强化学习）。**

- GPT-3 学会的是「给一段文字，猜下一个词」。
- InstructGPT 在此之上，用人类的「示范」和「偏好」教它：当人给你一条**指令**时，要给出一个人类**真正想要**的回答。
- ChatGPT 是把同一套方法（SFT → RM → PPO）用在对话场景、并叠加更多迭代后的产品。

记住一句话：**预训练给模型「知识与能力」，对齐给模型「意图与行为」。**

## 1. 地基/前置：GPT-3 为什么「能力强但不好用」

详细的 GPT-3 本体见 [[llm-algo/gpt3/README]]。这里只讲它留下的「坑」。

### 1.1 预训练目标是「续写」，不是「听话」

GPT-3 的训练目标只有一个——**最大化下一个词的似然**：

$$\mathcal{L}_{\text{pretrain}} = -\sum_{t} \log P_\theta(x_t \mid x_{<t})$$

它在海量互联网文本上学到「人类一般会怎么往下写」。但「互联网上最可能的续写」**不等于**「用户此刻想要的答案」。

举个直观例子：

```
用户输入:  "解释一下什么是黑洞。"
GPT-3(纯预训练)可能续写:  "解释一下什么是中子星。解释一下什么是白矮星。"
                          (它在模仿一份"问题清单"文档，继续列问题！)
人类真正想要:  "黑洞是一种引力极强、连光都无法逃逸的天体……"
```

模型没错——它只是忠实地「续写」了最可能的文本模式。**问题在于目标本身和人的意图错位。**

### 1.2 「指令鸿沟 (instruction gap)」

| 维度 | 预训练模型期望的输入 | 人类实际给的输入 |
|------|--------------------|-----------------|
| 形式 | 一段待续写的文本 | 一条命令/问题 |
| 期望输出 | 统计上最可能的续写 | 有用、正确、安全的回应 |
| 隐含契约 | 无 | "你是助手，要帮我" |

```
  ┌─ GPT-3 的"能力空间"(知识/推理/语言都在里面) ─┐
  └───────────────────┬──────────────────────────┘
            指令鸿沟：能力够，但"不知道该把能力用来干嘛"
  ┌───────────────────▼──────────────────────────┐
  └─ 用户想要的"行为" ───────────────────────────┘
```

InstructGPT 的全部工作，就是**架一座桥跨过这条鸿沟**——不是教新知识，而是教「怎么把已有能力对准人的意图」。

## 2. 什么是「对齐」，为什么它让模型可用

### 2.1 对齐的三个目标：3H

InstructGPT 论文把「对齐」操作化为三个标准（业内常称 **3H**）：

| 字母 | 含义 | 反例（未对齐） |
|------|------|----------------|
| **H**elpful | 有用：理解并完成用户意图 | 答非所问、续写问题清单 |
| **H**onest | 诚实：不编造、不胡说 | 一本正经地瞎编（幻觉） |
| **H**armless | 无害：不输出有害内容 | 教人造危险品、歧视言论 |

### 2.2 为什么「对齐」直接等于「可用」

```
   能力(会推理/懂知识/语言流畅)  +  对齐(听懂指令/给人想要的/不乱说不作恶)  =  可用产品
        └─ GPT-3 已经有了 ─┘          └──── InstructGPT 补上的 ────┘         (ChatGPT)
```

一个震撼的实证结果（InstructGPT 论文，2022）：

> **1.3B 参数的 InstructGPT，其输出在人类评测中比 175B 参数的 GPT-3 更受偏好。**

也就是说，**对齐带来的「可用性」收益，超过了把模型放大 100 倍**。这解释了为什么 ChatGPT 一出现就引爆——不是因为模型更大，而是因为它终于「会好好说话」。

## 3. 三阶段总览图

InstructGPT/ChatGPT 的训练流水线 = **三个阶段**，环环相扣：

```
┌──────────────────────────────────────────────────────────────────────┐
│  起点：预训练好的 GPT-3 (只会续写)                                      │
└───────────────────────────────┬──────────────────────────────────────┘
                                 │
        ┌────────────────────────▼─────────────────────────┐
        │  阶段 1：SFT  监督微调                             │
        │  数据：人类对 prompt 写的"示范回答"                 │
        │  做法：标准监督学习，模仿人类回答                  │
        │  产物：一个"初步会听话"的模型  π_SFT               │
        └────────────────────────┬─────────────────────────┘
                                 │
        ┌────────────────────────▼─────────────────────────┐
        │  阶段 2：RM   训练奖励模型                          │
        │  数据：同一 prompt 让模型生成多个回答，人类"排序"   │
        │  做法：学一个打分函数 r_φ(prompt, 回答) → 标量      │
        │  产物：一个"会替人类打分"的奖励模型  r_φ            │
        └────────────────────────┬─────────────────────────┘
                                 │
        ┌────────────────────────▼─────────────────────────┐
        │  阶段 3：PPO  强化学习微调                          │
        │  数据：大量 prompt（无需人工答案）                  │
        │  做法：让 π 生成回答 → 用 r_φ 打分 → PPO 更新 π     │
        │  约束：KL 惩罚，别跑离 π_SFT 太远                   │
        │  产物：最终模型  π_RLHF  =  InstructGPT             │
        └──────────────────────────────────────────────────┘
```

一句话记忆链：**示范（教它怎么答）→ 排序（教它什么更好）→ 优化（让它自己变好）。** 下面逐阶段拆到最底层。

## 4. 阶段一：SFT —— 监督微调（Supervised Fine-Tuning）

### 4.1 在干什么

收集一批真实/构造的 prompt，让**人类标注员亲手写出**「理想回答」，然后用标准监督学习让模型去模仿。

这本质是**行为克隆 (behavior cloning)**：给模型看「好回答长什么样」，让它照抄风格与格式。

```
  prompt:  "用三句话介绍长城。"
              │  人类标注员手写示范答案 (demonstration)
              ▼
  answer:  "长城是中国古代的军事防御工程。它东起山海关，西至嘉峪关……"
              │
              ▼  监督学习：最大化 log P(answer | prompt)
  （和预训练同一个 loss，只是数据变成 (指令, 理想答案) 对）
```

### 4.2 目标函数

和预训练**同一形式**的交叉熵，只是数据集换成「指令-示范」对 $\mathcal{D}_{\text{SFT}}$：

$$\mathcal{L}_{\text{SFT}} = -\mathbb{E}_{(x,y)\sim\mathcal{D}_{\text{SFT}}} \sum_{t} \log P_\theta(y_t \mid x, y_{<t})$$

- $x$ = prompt（指令），$y$ = 人类写的理想回答。
- 只在回答 $y$ 的 token 上算 loss（prompt 部分通常不算）。

### 4.3 为什么还不够，需要后续阶段

- 人工写示范**很贵很慢**，规模有限（InstructGPT 约万级量级）。
- SFT 只能学到「人类写过的答案」，无法表达「A 比 B 好多少」这种**偏好排序**信息，缺乏「区分好坏」的能力。

所以需要阶段 2、3 引入**偏好信号**，并让模型「自我探索 + 被打分反馈」。

---

## 5. 阶段二：RM —— 奖励模型（Reward Model）

### 5.1 核心思路：让人「排序」而不是「写答案」

让人**从头写**一个好答案很难；但让人**比较**两个答案哪个更好——很容易。RM 阶段就是把「人类偏好」这种廉价信号，蒸馏进一个可自动打分的模型。

```
  同一 prompt → SFT 模型采样出 K 个回答(K约4~9):  A  B  C  D
                            │
            人类标注员排序:  B ≻ D ≻ A ≻ C
                            │
   拆成 C(4,2)=6 个"两两对比"训练对: (B≻D)(B≻A)(B≻C)(D≻A)(D≻C)(A≻C)
```

### 5.2 RM 的结构

把 SFT 模型的最后「预测词」头换成一个**输出单个标量**的头：

```
  (prompt + 回答) ──► Transformer 主干 ──► [取最后 token 隐状态] ──► 线性层 ──► r ∈ ℝ
                                                                          (一个分数)
```

### 5.3 损失函数（Bradley-Terry 偏好模型）

设人类认为回答 $y_w$（win，更好）优于 $y_l$（lose，更差）。我们希望 RM 给的分数满足 $r_\phi(x,y_w) > r_\phi(x,y_l)$。用 logistic（Bradley-Terry）建模「$y_w$ 胜出」的概率：

$$P(y_w \succ y_l) = \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big),\quad \sigma(z)=\frac{1}{1+e^{-z}}$$

损失就是让这个概率尽量大（负对数似然）：

$$\mathcal{L}_{\text{RM}} = -\mathbb{E}_{(x,y_w,y_l)}\Big[\log \sigma\big(r_\phi(x,y_w) - r_\phi(x,y_l)\big)\Big]$$

**直觉**：只要「好答案的分」减「坏答案的分」是个**大正数**，$\sigma(\cdot)$ 趋近 1，loss 趋近 0。RM 学的是**相对高低**而非绝对分值，本身没有绝对意义——它是阶段 3 的「自动裁判」。

## 6. 阶段三：PPO —— 用强化学习微调策略

这是把「会打分的 RM」变成「真正改进模型」的关键一跃。先建立 RL 的语言映射。

### 6.1 把「生成文本」翻译成强化学习语言

| RL 术语 | 在语言模型里对应什么 |
|---------|---------------------|
| 策略 (policy) $\pi_\theta$ | 语言模型本身（给上下文，输出下一个词的概率分布） |
| 状态 (state) $s_t$ | 当前已生成的 prompt + 前 $t-1$ 个 token |
| 动作 (action) $a_t$ | 选下一个 token |
| 回合 (episode) | 生成一个完整回答 |
| 奖励 (reward) | 回答生成完，由 RM 打一个分 $r_\phi(x,y)$ |

```
  prompt x ─► [π 生成 token₁] ─► [token₂] ─► ... ─► [完整回答 y]
                                                        │
                                          ┌─────────────▼───────────┐
                                          │ 奖励模型 r_φ(x, y) → 分数 │
                                          └─────────────────────────┘
                                                        │
                                          反馈给 PPO，更新 π 的参数
```

### 6.2 为什么需要 KL 惩罚（最重要的工程细节）

如果只让模型「最大化 RM 分数」，会发生 **reward hacking（奖励作弊）**：模型发现 RM 的漏洞，生成一些 RM 给高分、但人类看了直摇头的怪话（RM 毕竟只是个近似裁判）。

解决：在奖励里加一项**惩罚**，不让新策略 $\pi_\theta$ 跑离原始 SFT 策略 $\pi_{\text{ref}}$ 太远：

$$R(x,y) = \underbrace{r_\phi(x,y)}_{\text{RM 给的分}} - \underbrace{\beta \,\mathrm{KL}\big(\pi_\theta(\cdot|x)\,\|\,\pi_{\text{ref}}(\cdot|x)\big)}_{\text{别跑太远的"绳子"}}$$

```
        奖励高 ↑
          │        × reward hacking 区
          │      ×   (RM 高分但人类讨厌)
          │    ×
    π_ref ●━━━━━━━━━━━━━●  ← KL 把 π 拴在 ref 附近
          │   合理改进区   "绳子"长度由 β 控制
          └──────────────────► 离 π_ref 的距离
```

- $\beta$ 大 → 绳子短，改动保守，更安全但提升有限。
- $\beta$ 小 → 绳子长，提升快但易作弊/退化。

### 6.3 PPO 本体：为什么不用普通策略梯度

朴素策略梯度一步更新太大，容易把策略「带崩」。**PPO（Proximal Policy Optimization）的核心思想：每次只允许策略小步、稳健地更新。**

定义新旧策略的概率比：

$$\rho_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{\theta_{\text{old}}}(a_t|s_t)}$$

PPO 的「裁剪（clip）」目标：

$$\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[\min\big(\rho_t \hat{A}_t,\ \mathrm{clip}(\rho_t, 1-\epsilon, 1+\epsilon)\,\hat{A}_t\big)\Big]$$

- $\hat{A}_t$ = **优势 (advantage)**：这个动作比「平均」好多少（好则正，差则负）。通常由 RM 奖励配合一个 value 头用 GAE 估计。
- $\mathrm{clip}(\rho_t, 1-\epsilon, 1+\epsilon)$：把概率比锁在 $[1-\epsilon, 1+\epsilon]$（如 $\epsilon=0.2$）内。
- $\min(\cdot)$：取「裁剪前」和「裁剪后」中**更保守**的那个——这就是「近端 (proximal)」之意：阻止单步更新走太远。

```
  A>0 (动作不错想多做)：ρ 涨到 1+ε 就"封顶"，不让一次涨太猛 → 防过冲
  A<0 (动作不好想少做)：ρ 跌到 1-ε 就"触底"，不让一次砍太狠 → 防崩溃
```

### 6.4 完整 PPO 阶段目标（InstructGPT 论文版）

实际还会混入一点预训练 loss，防止「学会对话却忘了语言能力」（称 **PPO-ptx**）：

$$\mathcal{L}_{\text{PPO}} = \underbrace{\mathbb{E}\big[r_\phi(x,y) - \beta\,\mathrm{KL}\big]}_{\text{RLHF 主目标}} + \underbrace{\gamma\,\mathbb{E}_{x\sim\mathcal{D}_{\text{pretrain}}}\big[\log \pi_\theta(x)\big]}_{\text{保留通用语言能力}}$$

```
  三股力量在拔河：RM 奖励(往"人喜欢"拉) + KL 惩罚(往"别乱跑"拽) + 预训练项(往"别忘老本"拽)
  三者平衡 → 既好用、又稳定、又不退化
```

## 7. InstructGPT vs GPT-3：差在哪

**关键认知：两者参数量可以一样，差别全在「行为」，不在「容量」。**

```
  同一具"大脑"(可同规模)，差别全在"行为"：
    GPT-3        : 只预训练 | 续写文本 | 不懂"你在命令我" | 爱编造跑题 | 安全性弱
    InstructGPT  : +RLHF三段 | 完成指令 | 理解并执行意图  | 更诚实切题 | 拒答有害
```

| 维度 | GPT-3 | InstructGPT |
|------|-------|-------------|
| 训练 | 仅预训练（续写目标） | 预训练 + RLHF 三阶段 |
| 人类偏好度 | 基线 | 显著更受偏好（1.3B 即胜 175B GPT-3） |
| 诚实性 | 易幻觉 | TruthfulQA 等指标更优 |
| 无害性 | 较弱 | 毒性、有害输出更少 |

> 数字「1.3B InstructGPT > 175B GPT-3（人类偏好）」来自 InstructGPT 论文（Ouyang et al., 2022），以官方论文为准。

## 8. 从 InstructGPT 到 ChatGPT

ChatGPT（2022.11 发布）在方法学上**就是 InstructGPT 的同款配方**，OpenAI 官方称其为「sibling model（姊妹模型）」，主要差异是**面向对话**并做了更多迭代：

```
  InstructGPT (单轮指令→回答)  ──对话化改造──►  ChatGPT (多轮 system/user/assistant)
                                                 ├─ 记住上下文、能追问澄清
                                                 ├─ 更强的拒答与安全护栏
                                                 └─ 更大规模、更多轮 RLHF 迭代
```

要点：
- **对话数据格式**：把训练数据组织成多轮对话，引入「系统提示 (system prompt)」设定助手人设与规则。
- **同一三段式**：SFT（人扮演用户和助手写对话）→ RM（对对话回复排序）→ PPO。
- **产品化**：上线后用真实用户反馈持续迭代（数据飞轮）。

> ChatGPT 的精确数据规模与基座模型版本 OpenAI 未完全公开，**以官方说明为准**，不做编造。

## 9. 贡献与影响

```
  历史意义： ① 证明"对齐 > 单纯放大"(1.3B 对齐胜 175B 未对齐)
            ② 把 RLHF 三段式确立为工业标准范式(LLaMA-Chat/Claude 等沿用)
            ③ 让大模型从"研究玩具"变成"人人可用的助手"
            ④ 把"人类偏好数据"提升为核心生产要素(数据飞轮)
            ⑤ 催生后续对齐演进：DPO / RLAIF / Constitutional AI
```

- **范式转变**：从「更大的模型」转向「更好的对齐」。算力之外，**人类反馈数据**成为竞争壁垒。
- **可用性革命**：ChatGPT 5 天破百万用户、2 个月破亿，开启「大模型应用元年」。
- **方法学奠基**：SFT→RM→PPO 成为后续几乎所有对话模型的起点。关于 RLHF 的更系统讲解，见 [[llm-alignment/RLHF]]。
- **激发后续简化**：因为 PPO 工程复杂（要同时跑 4 个模型：policy / ref / RM / value），后来出现 **DPO** 等「绕过显式 RM 和 PPO」的方法——这是站在 InstructGPT 肩膀上的优化。

## 数值例子 / 对照

### 例 1：RM 的 pairwise loss 手算

设某 prompt 下，人类认为回答 $y_w$ 优于 $y_l$。RM 当前给分：

- 好答案 $r_\phi(x, y_w) = 2.0$
- 差答案 $r_\phi(x, y_l) = 0.5$

代入 $\mathcal{L}_{\text{RM}} = -\log\sigma(r_w - r_l)$：

$$r_w - r_l = 2.0 - 0.5 = 1.5$$
$$\sigma(1.5) = \frac{1}{1+e^{-1.5}} = \frac{1}{1+0.2231} \approx 0.818$$
$$\mathcal{L}_{\text{RM}} = -\log(0.818) \approx 0.201$$

对照：若 RM **打反了**（$r_w=0.5, r_l=2.0$，差值 $-1.5$），$\sigma(-1.5)\approx0.182$，loss $\approx 1.70$。

```
  RM 排序正确  →  差值=+1.5  →  loss≈0.20  (小，几乎不罚)
  RM 排序错误  →  差值=-1.5  →  loss≈1.70  (大，狠狠罚)
```

**结论**：loss 在「逼 RM 把好答案的分抬高、坏答案的分压低」。

### 例 2：PPO 单步奖励手算（含 KL 惩罚）

设某条回答 $y$：
- RM 给分 $r_\phi(x,y) = 1.2$
- 新旧策略在该回答上的 KL 散度 $\mathrm{KL} = 0.8$
- KL 系数 $\beta = 0.2$

最终用于 PPO 的奖励：

$$R = r_\phi - \beta\cdot\mathrm{KL} = 1.2 - 0.2\times 0.8 = 1.2 - 0.16 = 1.04$$

若模型为讨好 RM 严重偏离 ref（$\mathrm{KL}=5.0$）：$R = 1.2 - 0.2\times 5.0 = 0.2$。

```
  小幅改进 (KL=0.8)  →  净奖励 1.04   ✓ 鼓励
  剧烈偏离 (KL=5.0)  →  净奖励 0.20   ✗ 几乎被惩罚抵消
```

**结论**：KL 惩罚像一根「橡皮筋」，越往外拉、拉力越大，自然阻止 reward hacking。

### 例 3：clip 机制对照

设某动作优势 $\hat{A}_t = +1$（好动作），$\epsilon=0.2$：概率比 $\rho_t=1.1$ 时在区间内，正常更新得 $1.1$；但 $\rho_t=1.5$ 想冲出 $1+\epsilon=1.2$，被 clip 按回 $1.2$，单步不再更新过猛——这就是 PPO「稳」的来源。

## 常见问题

| 问题 | 解答 |
|------|------|
| InstructGPT 和 ChatGPT 是一回事吗？ | 方法学同款（SFT→RM→PPO）。ChatGPT 是其面向**对话**的姊妹模型，做了对话格式化与更多迭代。 |
| 为什么不直接用 SFT，非要 RL？ | SFT 只能模仿「人写过的答案」，无法表达「A 比 B 好多少」的偏好梯度；RLHF 能用排序信号持续优化到示范之外。 |
| RM 不准会怎样？ | 模型会 **reward hacking**：钻 RM 漏洞拿高分却让人类反感。KL 惩罚 + 持续更新 RM 缓解。 |
| KL 惩罚 / clip 各防什么？ | KL 防策略跑离 SFT 太远而退化作弊（$\beta$ 调保守/激进）；clip 把概率比锁在 $[1-\epsilon,1+\epsilon]$ 防单步更新过猛把策略带崩。 |
| 对齐会不会降低模型能力？ | 可能有轻微「对齐税 (alignment tax)」；InstructGPT 用 **PPO-ptx**（混入预训练 loss）来缓解能力退化。 |
| 1.3B 真能胜过 175B？ | 指「人类偏好度」上胜出，不是指知识容量。说明**好用 ≠ 更大**。以原论文为准。 |
| PPO 阶段要跑几个模型？ | 通常 4 个：策略 π、参考 π_ref、奖励模型 RM、价值网络 value。工程复杂，催生了后来的 DPO 等简化方法。 |
