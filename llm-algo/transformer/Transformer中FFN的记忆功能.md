## 0. 一句话锚点

> **Attention 负责"在序列里搬运信息 (谁该看谁)"，FFN 负责"对单个 token 做查表式的知识检索与改写"。** 一个 Transformer 块 = `Attention(混合 token) + FFN(逐 token 查记忆)`。把 FFN 删掉模型还能跑，但效果断崖式下降——因为知识没地方存了。

代表论文：

- **Geva et al., 2021《Transformer Feed-Forward Layers Are Key-Value Memories》** —— 指出 FFN 在数学上等价于一个 key-value 记忆。
- **Dai et al., 2022《Knowledge Neurons in Pretrained Transformers》** —— 给出如何"定位"并"编辑"FFN 里存知识的神经元。

## 1. 地基：FFN 在 Transformer 里的位置和形状

一个标准 Transformer 编码/解码块的数据流（Pre-LN 风格）：

```
            ┌──────────────────────────────────────────┐
   x ──────►│  + ◄── Multi-Head Self-Attention ◄── LN   │   (跨 token 混合)
            └───────────────────┬──────────────────────┘
                                │  h  (每个 token 一个向量)
            ┌───────────────────▼──────────────────────┐
   h ──────►│  + ◄────────  FFN  ◄──────────────── LN   │   (逐 token 处理)
            └───────────────────┬──────────────────────┘
                                ▼
                              out
```

**关键点：FFN 是"逐位置 (position-wise)"的**——序列里每个 token 的向量各自独立过同一个 FFN，token 之间不交互（交互全交给 Attention）。

FFN 本体就是一个两层 MLP（详见 [[llm-algo/mlp]]）：

$$
\text{FFN}(\mathbf{x}) = f(\mathbf{x} W_1 + \mathbf{b}_1)\, W_2 + \mathbf{b}_2
$$

- $\mathbf{x}\in\mathbb{R}^{d}$：输入向量，$d$ 是模型隐藏维 (hidden size，如 4096)。
- $W_1\in\mathbb{R}^{d\times d_{ff}}$：**升维**矩阵，$d_{ff}$ 通常是 $4d$（如 16384）。
- $f$：非线性激活（原始 Transformer 用 ReLU，现代多用 GeLU / SwiGLU）。
- $W_2\in\mathbb{R}^{d_{ff}\times d}$：**降维**矩阵，把维度从 $d_{ff}$ 拉回 $d$。

```
        d=4096            d_ff=16384            d=4096
  x ───────────► [ W1 ] ───────────► f(·) ───────────► [ W2 ] ──► out
  (输入)          升维     (中间激活, 很宽)   激活        降维      (输出)
                              │
                              └── 这一层很"宽"，参数和算力主要在这里
```

**为什么 FFN 占了模型大部分参数？** 因为 $W_1, W_2$ 各有约 $d\times d_{ff}=4d^2$ 个参数，两个加起来 $8d^2$；而 Attention 的 $Q,K,V,O$ 四个矩阵共 $4d^2$。所以**FFN 参数量约是 Attention 的 2 倍**，是模型存知识的主战场。

**Attention vs FFN 分工对照：**

```
┌────────────┬───────────────────────┬──────────────────────────┐
│            │     Attention          │          FFN             │
├────────────┼───────────────────────┼──────────────────────────┤
│ 作用对象    │ token 之间 (序列维)    │ 单个 token (特征维)       │
│ 直觉        │ "去别处取信息"          │ "查自己脑子里的知识"      │
│ 是否混合序列│ 是                     │ 否 (position-wise)        │
│ 参数占比    │ ~1/3                   │ ~2/3                     │
│ 比喻        │ 路由器/检索器           │ 知识库/记忆库            │
└────────────┴───────────────────────┴──────────────────────────┘
```

## 2. 把 FFN 改写成"记忆查询"——核心洞见

Geva 论文的核心是一个**形式上的恒等改写**。先忽略偏置，FFN 写成：

$$
\text{FFN}(\mathbf{x}) = f(\mathbf{x}\, W_1)\, W_2
$$

现在做一件关键的事：把 $W_1$ 按**列**拆，把 $W_2$ 按**行**拆。

- $W_1$ 的第 $i$ **列** 记为 $\mathbf{k}_i\in\mathbb{R}^{d}$ —— 称为第 $i$ 个 **key**。
- $W_2$ 的第 $i$ **行** 记为 $\mathbf{v}_i\in\mathbb{R}^{d}$ —— 称为第 $i$ 个 **value**。

中间激活向量 $\mathbf{m}=f(\mathbf{x}W_1)\in\mathbb{R}^{d_{ff}}$ 的第 $i$ 个分量是：

$$
m_i = f(\mathbf{x}\cdot \mathbf{k}_i)
$$

即 **"输入 $\mathbf{x}$ 与 key $\mathbf{k}_i$ 的内积，再过激活"**。最后输出：

$$
\text{FFN}(\mathbf{x}) = \sum_{i=1}^{d_{ff}} m_i\, \mathbf{v}_i = \sum_{i=1}^{d_{ff}} f(\mathbf{x}\cdot\mathbf{k}_i)\,\mathbf{v}_i
$$

**这就是一个记忆库的"软查询"！**

```
   输入 x
     │
     ├──► (x · k1) ─► f ─► m1 ──┐
     ├──► (x · k2) ─► f ─► m2 ──┤
     ├──► (x · k3) ─► f ─► m3 ──┤   每个 mi 是"第 i 条记忆被激活的强度"
     │        ...               │
     └──► (x · kN) ─► f ─► mN ──┤   N = d_ff 条记忆
                                 ▼
        out = m1·v1 + m2·v2 + ... + mN·vN
              └──────────┬──────────┘
        被激活的 value 加权求和 = 检索结果
```

**和 Attention 的相似性**：Attention 也是 $\text{softmax}(QK^\top)V$ 的"查询 key 取 value"，区别在于：

| | Attention 的记忆 | FFN 的记忆 |
|---|---|---|
| key/value 来自 | 当前序列里的其它 token（动态） | 训练学到的**固定参数**（静态） |
| 归一化 | softmax（行内竞争，和为 1） | 激活函数（如 ReLU/GeLU，无归一化） |
| 内容 | 上下文信息 | 世界知识/语言模式 |

所以一句话：**FFN = 一个 key 和 value 都写死在权重里的、不做 softmax 归一化的 Attention。**

## 3. 第一层 = pattern 检测 (key)

每个 key $\mathbf{k}_i$ 检测一种**输入模式 (pattern)**。$\mathbf{x}\cdot\mathbf{k}_i$ 大，说明当前 token 的表示"长得像" $\mathbf{k}_i$ 想找的东西，于是 $m_i$ 被点亮。

Geva 论文做了实验：对每个 key，找出训练语料中最能激活它的那些前缀 (prefix)，再让人类标注这些前缀的共性。结论非常清晰——

```
┌──────────────────────────────────────────────────────────────┐
│  浅层 (靠近输入)         →           深层 (靠近输出)            │
│                                                                │
│  key 检测的是              key 检测的是                          │
│  「表层/语法模式」          「语义/主题模式」                    │
│                                                                │
│  例: 以 "substitute" 结尾   例: 句子在讲「电视节目」            │
│      句子里含 "a" + 形容词   例: 句子在讲「军事/战争」          │
│      固定短语模式           例: 在引出某个国家的首都           │
└──────────────────────────────────────────────────────────────┘
```

**直觉理解（为什么浅层管语法、深层管语义）**：

- 浅层的 $\mathbf{x}$ 还很"原始"，主要带词形/位置信息，所以 key 只能识别表层模式；
- 经过多层叠加后，$\mathbf{x}$ 已被反复加工，承载了抽象语义，key 才能识别"这句话在讲什么主题"。

```
   表层信号  ──堆叠 N 层后──►  抽象语义
   "字面长相"                  "话题/事实关系"
   浅层 key 抓这个              深层 key 抓这个
```

每个 key 像一个**触发器/探测器 (detector)**：只对特定输入模式响应。$d_{ff}=16384$ 就意味着有上万个这样的探测器并行扫描每个 token。

## 4. 第二层 = 词表分布 (value)

被点亮的 key 会"召唤"它配对的 value $\mathbf{v}_i$。Geva 论文的第二个关键发现：**value 编码的是"接下来该输出什么词"的分布**，尤其在深层最明显。

怎么验证？用**模型自己的输出嵌入矩阵 $E$ (unembedding)** 把 value 投影到词表上：

$$
p_i = \text{softmax}(\mathbf{v}_i\, E^\top) \in \mathbb{R}^{|\text{vocab}|}
$$

得到的 $p_i$ 是一个词表上的概率分布。论文发现：**深层 value 的 top 词，恰好就是该 key 所检测的模式之后真正会出现的下一个词。**

```
  key k_i 检测到模式: "...这句话在引出某国首都, 且国家是中国"
                         │
                         ▼  (k_i 被激活, 召唤 v_i)
  value v_i 投影到词表 → top tokens: ["北京", "Beijing", "京", ...]
                         │
                         ▼
            把 "北京" 的方向加进残差流, 推高它的输出概率
```

所以一对 $(\mathbf{k}_i,\mathbf{v}_i)$ 就是一条记忆规则：

> **"如果输入符合模式 $\mathbf{k}_i$，那么往输出里加一票给 $\mathbf{v}_i$ 对应的词。"**

这正是"中国的首都是 → 北京"这类事实知识在参数里的存在形式：某个 key 检测"在问中国首都"，它配对的 value 推高"北京"。

**层间对比小结：**

```
┌───────────┬───────────────────────┬───────────────────────┐
│           │  第一层 (W1, keys)     │  第二层 (W2, values)   │
├───────────┼───────────────────────┼───────────────────────┤
│ 数学角色   │ x·k_i, 算激活强度      │ Σ m_i·v_i, 加权输出    │
│ 语义角色   │ 模式检测 (输入侧)       │ 词表分布 (输出侧)      │
│ "记忆"类比 │ 记忆的「索引/条件」     │ 记忆的「内容/结论」    │
│ 类比键值对 │ key                    │ value                  │
└───────────┴───────────────────────┴───────────────────────┘
```

## 5. 多条记忆如何聚合成最终输出

单层 FFN 的输出是几百上千条被激活记忆的 value 的**加权和**：$\sum_i m_i \mathbf{v}_i$。再经过残差连接加回主干（残差流, residual stream），然后传给下一层：

```
   残差流 (token 的"工作记忆")
      │
      ▼
   [LN] ─► FFN ─► Σ m_i v_i ──(+)──► 更新后的残差流 ──► 下一层
      │                          ▲
      └──────────────────────────┘
            残差直连 (信息不丢)
```

**为什么是"加"而不是"替换"？** 残差流像一块共享白板：每一层 FFN 不是重写白板，而是**往上添加自己的一票 (vote)**。多层 FFN 的 value 累加起来，逐步把残差流推向"正确的下一个词"。最后一层的残差流过 unembedding，就得到最终的 next-token 分布。

```
  层1 FFN: 在白板上加一点点 "可能是地名"
  层5 FFN: 加 "是首都类的词"
  层9 FFN: 加 "是中国的首都"
  层N FFN: 强力加 "北京"  ────►  softmax 后 "北京" 概率最高
```

**单条记忆是局部的，知识往往分布在多层、多个神经元上**——这也是后面"知识编辑"既可能又困难的根源。

## 6. 为什么"知识"恰好存在 FFN 里？

把上面的机制和训练目标连起来，就能回答"为什么 FFN 是知识仓库"：

1. **容量在这里**：FFN 占了约 2/3 的参数（见 §1）。要塞下海量事实，必须用参数最多的地方。$d_{ff}$ 越大，能存的 (key,value) 记忆条数越多。

2. **结构天然适合查表**：§2 证明了 FFN 形式上就是 key-value 检索。模型在预测下一个词时，最经济的实现就是"检测模式→输出对应词"，梯度自然把权重训成这种形态。

3. **逐 token 处理**：知识是关于"当前在说什么"的，不需要跨 token 混合（那是 Attention 的活），所以 position-wise 的 FFN 正好承接。

4. **激活稀疏**：实测每个 token 只点亮一小部分神经元（ReLU/GeLU 把很多压到 0），相当于"按需检索几条相关记忆"，而非全库扫描——这与人类"联想式记忆"很像。

```
   预测目标(下一个词) ──► 梯度 ──► 把"检测模式→投票该词"压进 W1,W2
                                          │
                                          ▼
                          FFN 自发学成 key-value 记忆库
```

**实验佐证**：把 FFN 去掉，模型语言能力骤降（仅靠 Attention 难以存储事实）；放大 $d_{ff}$（更多记忆槽位）通常能存更多知识、提升性能。

## 7. Knowledge Neurons：定位与编辑 FFN 里的知识

既然知识是一条条 (key,value) 记忆，能不能**找到并修改**某条事实？Dai et al. 2022 给出方法。

**第一步：定位（哪个神经元负责这条知识）。** 用**梯度归因 (integrated gradients)**：对某个事实（如"中国的首都是[北京]"），看每个 FFN 中间神经元 $m_i$ 对正确答案概率的贡献（积分梯度）。

> **梯度大 ⇒ 该神经元对输出该答案的影响大 ⇒ 它很可能是这条知识的"知识神经元"。**

```
   填空: "中国的首都是 ___"  (正确答案: 北京)
        │
        ▼  对每个神经元算积分梯度 ∂P(北京)/∂m_i
   ┌──────────────────────────────────────────┐
   │ neuron #1532  ████████████  高 ← 知识神经元 │
   │ neuron #88    █                            │
   │ neuron #9001  ███████████   高 ← 知识神经元 │
   │ neuron #421   ▍                            │
   └──────────────────────────────────────────┘
```

**第二步：编辑（改这条知识）。** 定位到知识神经元后，可以直接操作它的激活：

```
   ┌───────────────┬────────────────────────────────────────┐
   │ 操作           │ 效果                                    │
   ├───────────────┼────────────────────────────────────────┤
   │ 激活置 0 (抑制) │ 模型说不出"北京"了 → 抑制该知识表达      │
   │ 激活翻倍 (增强) │ 模型更强烈地输出"北京" → 增强该知识      │
   │ 改写对应 value │ 把 v_i 换成"上海" → 知识被改写(注入新知)│
   └───────────────┴────────────────────────────────────────┘
```

**实践要点（论文强调）**：编辑时要**避开"多条事实共用的神经元"**，只动该关系/该事实专属的神经元，否则会误伤其它知识（牵一发动全身）。这正是因为 §5 说的"知识分布在多处、且部分共享"。

**意义**：这条线索通往**模型知识编辑 (Knowledge Editing)** 这个研究方向——

- 去除模型里的**错误/过时知识**（如旧首都、错误事实）；
- 注入**新知识**而无需重新训练整个模型；
- 后续工作如 ROME / MEMIT 进一步把 FFN 当作可定位、可写入的"记忆矩阵"，做精准的事实更新。

```
   旧知识: France 首都 = Paris  (假设要改)
        │ 定位负责该事实的 (k_i, v_i)
        ▼ 用最小二乘解一个新的 v_i', 使输出指向新目标
   新知识: France 首都 = London  (仅改这一条, 不动其它)
```

## 8. 与 MoE 的联系

把 §2 的视角推到极致：**MoE (Mixture-of-Experts) 就是"把一个大记忆库拆成若干小记忆库，每个 token 只查其中几个"**。详见 [[llm-algo/moe/README]]。

```
  普通 FFN：每个 token 都过同一个大记忆库 (d_ff=16384, 全部参与)

   x ──► [ 一个大 FFN ] ──► out      (稠密, dense)


  MoE：把 FFN 复制成 E 个"专家", 路由器只挑 top-k 个执行

           ┌─► Expert 1 (一个小 FFN/小记忆库)
   x ──► [Router] ─► Expert 2  ✔ ─┐
           ├─► Expert 3  ✔ ───────┤─► 加权和 ──► out
           └─► Expert 4           │
                ...               │   (稀疏, 只激活 top-k)
```

**为什么 FFN-as-memory 的视角让 MoE 顺理成章：**

| 概念 | 稠密 FFN | MoE |
|------|---------|-----|
| 记忆库 | 1 个大库 | E 个小库（专家） |
| 每 token 查多少 | 全部 $d_{ff}$ 个槽位 | 仅 top-k 个专家 |
| 激活稀疏性 | 隐式（激活函数压零） | 显式（路由器选择） |
| 收益 | — | 总记忆容量 ↑↑，单次算力不变 |

直觉：既然每个 token 本来就只点亮 FFN 里一小撮神经元（§6 的稀疏性），那干脆**把记忆库切块、用路由器显式地只取相关的块**——这样可以把总参数（总记忆量）放大 10 倍，而每个 token 的实际计算几乎不变。MoE 本质是"**把 FFN 的隐式稀疏检索，变成显式的、可扩展的稀疏记忆检索**"。

```
  稠密FFN稀疏激活  ──(显式化 + 分块 + 路由)──►  MoE
  "本来就只用一小部分"        "那就只取要用的那块, 顺便把库做大"
```

## 数值例子 / 手算

以一个 ~7B 规模、$d=4096$、$d_{ff}=16384$、层数 $L=32$ 的典型解码器为例（数字为帮助直觉的近似估算，具体以官方为准）。

**(1) 单层 FFN 参数量**（忽略偏置）：

$$
|W_1| + |W_2| = d\cdot d_{ff} + d_{ff}\cdot d = 2\times 4096\times 16384 \approx 1.34\times 10^8
$$

即**单层 FFN 约 1.34 亿参数**。32 层共 $\approx 4.3\times 10^9$，约 **4.3B**——占 7B 模型的 **6 成以上**。这直观印证"FFN 是知识主战场"。

**(2) FFN vs Attention 参数对比**（单层）：

$$
\text{FFN} = 8d^2 \approx 1.34\times 10^8, \qquad
\text{Attn} = 4d^2 \approx 6.7\times 10^7
$$

**FFN 参数是 Attention 的约 2 倍**。

**(3) "记忆条数"**：单层 FFN 的中间宽度 $d_{ff}=16384$，意味着这一层有 **16384 条 (key,value) 记忆**；32 层共约 **52 万条**记忆槽位（多数会被多个事实共享/复用）。

**(4) 一次前向的 FFN 显存（中间激活）**：序列长 $S=2048$、batch $B=1$、FP16(2 字节)：

$$
\text{激活}\approx B\times S\times d_{ff}\times 2 = 1\times 2048\times 16384\times 2\ \text{B} \approx 64\ \text{MB (单层)}
$$

32 层若全部保存用于反向，约 **2 GB** 仅 FFN 中间激活——这也是训练时显存大头之一（推理时不保存可释放）。

**(5) 手算一条记忆的激活（玩具例子）**：设 $d=4$，某 key $\mathbf{k}_i=[1,0,-1,0]$，输入 $\mathbf{x}=[2,1,0,1]$：

$$
\mathbf{x}\cdot\mathbf{k}_i = 2\cdot1 + 1\cdot0 + 0\cdot(-1) + 1\cdot0 = 2
$$

过 ReLU：$m_i=\max(0,2)=2$（被点亮）。若另一输入 $\mathbf{x}'=[-1,0,3,0]$：$\mathbf{x}'\cdot\mathbf{k}_i=-1-3=-4$，ReLU 后 $m_i=0$（**没被点亮，这条记忆对该输入不触发**）。这就是 §3"key 是模式探测器、激活函数实现稀疏检索"的最小演示。

## 常见问题

| 问题 | 解答 |
|------|------|
| FFN 和 MLP 是一回事吗？ | 是。Transformer 里把这个两层 MLP 叫 FFN（前馈网络），见 [[llm-algo/mlp]]。 |
| 为什么说 FFN 是"记忆"而 Attention 不是？ | Attention 的 key/value 来自当前序列（动态、上下文）；FFN 的 key/value 写死在权重里（静态、世界知识）。 |
| key 是哪个矩阵？value 是哪个？ | key = $W_1$ 的列（输入侧，检测模式）；value = $W_2$ 的行（输出侧，词表分布）。 |
| 浅层 vs 深层 FFN 有何不同？ | 浅层 key 抓表层/语法模式，深层 key 抓语义/事实模式，深层 value 直接对应下一个词。 |
| 删掉 FFN 会怎样？ | 模型仍能跑但效果大幅下降——知识没地方存了，只剩 Attention 的"搬运"能力。 |
| 知识能精准编辑吗？ | 能定位（梯度归因）也能改（改激活/改 value），但知识分布且部分共享，须避开公用神经元，否则误伤其它事实。 |
| 为什么激活函数重要？ | 它引入非线性、且把弱激活压到 0，实现"按需检索几条记忆"的稀疏性——这正是 MoE 显式化的基础。 |
| MoE 改变了记忆本质吗？ | 没有。MoE 只是把一个大记忆库切块 + 用路由器显式只取相关块，换来更大总容量、不变的单步算力。 |
