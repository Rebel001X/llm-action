## 0. 一句话锚点

把 DeepSeek 想成「**用一半甚至十分之一的钱，造出和 GPT-4 / Llama-3 同级别的开源模型**」的团队。它没有靠堆更多卡、更多数据去硬刚，而是从三个地方抠效率：

1. **注意力层**：发明 MLA，把推理时最占显存的 KV Cache 压到原来的几十分之一。
2. **前馈层**：把稠密 FFN 换成「细粒度 MoE」，671B 总参数每个 token 只激活约 37B，算力只花零头。
3. **后训练**：用纯强化学习（R1-Zero）证明「不需要海量人工标注的思维链，模型也能自己学会推理」。

一句话：**DeepSeek = 架构省显存 + MoE 省算力 + RL 省标注**。

```
        贵                                              省
   ┌──────────────┐                            ┌──────────────┐
   │ 标准 MHA      │  ── MLA ──────────────▶    │ KV Cache↓10× │
   │ 稠密 FFN      │  ── 细粒度 MoE ───────▶    │ 激活参数↓18× │
   │ 海量 SFT 标注 │  ── GRPO 纯 RL ───────▶    │ 标注成本↓    │
   └──────────────┘                            └──────────────┘
```

## 1. 地基/前置

读懂 DeepSeek 前，先把四块积木拆到最原子。**如果你已经很熟，可跳到第 2 节。**

### 1.1 Transformer 一层在干嘛

一个 Transformer Decoder Block = **注意力子层 + 前馈子层（FFN）**，各套一层残差和归一化。

```
输入 x ─┬─▶ [Attention] ─▶ + ─▶ [FFN] ─▶ + ─▶ 输出
        └────────残差───────┘   └──残差──┘
```

- **注意力**：让每个 token「看」前面所有 token，做信息聚合。代价是要缓存历史 Key/Value（KV Cache）。
- **FFN**：对每个 token 做「升维→非线性→降维」的特征变换，参数量占大头（约 2/3）。

DeepSeek 两大创新正好各打一个子层：**MLA 改注意力，MoE 改 FFN**。

### 1.2 KV Cache：推理慢和占显存的根源

自回归生成是「一个字一个字吐」。生成第 $t$ 个 token 时，要和前面 $t-1$ 个 token 算注意力。为了不重复计算，把历史每个 token 的 Key、Value 存下来，这就是 **KV Cache**。

标准多头注意力（MHA）的 KV Cache 大小（单层、单序列）：

$$\text{KV Cache} = 2 \times L \times n_h \times d_h \times \text{bytes}$$

其中 $L$=序列长度，$n_h$=头数，$d_h$=每头维度，乘 2 是 K 和 V 各一份。**序列越长、并发越多，KV Cache 越爆显存**——这是长上下文推理的头号瓶颈。MLA 就是来砍这个数的。

### 1.3 MoE（混合专家）：让参数「按需激活」

稠密模型每个 token 都过同一个大 FFN。MoE 把这个大 FFN 拆成很多个小 FFN（叫**专家 Expert**），再加一个**路由器（Router/Gate）**，每个 token 只挑 Top-K 个专家来算。

```
            ┌── 专家1 ──┐
  token ─▶ Router ─挑Top2─▶ 专家3 ──┐
            └── 专家2 ──┘           ▼
            （只算选中的，其它不动）  加权求和 ─▶ 输出
```

好处：**总参数可做到很大（容量大），但每 token 的计算量只取决于激活的 K 个专家（算力小）**——这就是「参数多但便宜」的秘密。难点：让专家负载均衡，不让某几个被挤爆。

### 1.4 RLHF / 推理 RL：让模型对齐 + 学会思考

- **SFT（监督微调）**：用人工写好的「问题→答案」对教模型。
- **RLHF**：用人类偏好训一个奖励模型，再用 RL（如 PPO）让模型输出更受偏好。
- **推理 RL（DeepSeek 的关键）**：对数学/代码这类**有标准答案**的任务，奖励可以「自动判分」（答对得分），于是连人工标注都省了——这叫 **RLVR（可验证奖励的强化学习）**。R1 的核心就在这。

## 3. MLA：多头潜在注意力（V2 的注意力创新）

> 解决的问题：标准 MHA 的 KV Cache 太大，长上下文/高并发推理时显存爆炸。

### 3.1 先看几种已有方案的取舍

```
方案对比（KV Cache 大小 vs 效果）

MHA  : 每个头独立K/V  ── KV最大  ── 效果最好
MQA  : 所有头共享1组K/V ── KV最小 ── 效果掉点
GQA  : 分组共享K/V     ── 折中    ── Llama用的就是它
MLA  : 压成"潜在向量"  ── KV很小  ── 效果≈MHA  ◀── DeepSeek
```

MQA/GQA 是「**减少 K/V 的份数**」来省。MLA 思路完全不同：「**把 K/V 压缩成一个低维潜在向量再缓存**」。

### 3.2 MLA 的核心机制：低秩联合压缩

直觉：K 和 V 里其实有很多冗余信息，可以先投影到一个**低维潜在空间** $c$，缓存时只存这个小小的 $c$，用的时候再「解压」回 K、V。

```
标准 MHA 缓存:
  h ─▶ W_K ─▶ K (大, 要缓存)
  h ─▶ W_V ─▶ V (大, 要缓存)        缓存 = K + V，很大

MLA 缓存:
            ┌─▶ (用 W_UK 解压) ─▶ K
  h ─▶ W_DKV ─▶ c_KV (小, 只缓存这个!)
            └─▶ (用 W_UV 解压) ─▶ V

  缓存 = c_KV（外加一个小的解耦RoPE向量），只有原来的几十分之一
```

- $W_{DKV}$：**下投影**（Down），把隐藏态压成低维潜在向量 $c_{KV}$（维度 $d_c \ll n_h d_h$）。
- $W_{UK}, W_{UV}$：**上投影**（Up），推理时把 $c_{KV}$ 解回 K、V。
- **关键技巧**：$W_{UK}$ 可「吸收」进 Query 投影矩阵，推理时**不用真的解压出完整 K**，进一步省算力。

### 3.3 RoPE 的小麻烦与「解耦 RoPE」

旋转位置编码（RoPE）是与位置相关的旋转，**不能**被简单吸收进上面的矩阵合并（旋转矩阵夹在中间破坏结合律）。解法是**解耦 RoPE**：额外留一小路专门携带位置信息、单独缓存。所以 MLA 实际缓存 = `压缩潜在向量 c_KV` + `一小段解耦RoPE的key`。

> 直觉总结：**MLA = 把 KV 压成一个小胶囊存起来，需要时再展开；位置信息单独走一条小路。** 既省显存又几乎不掉点。

数值感受见第 9 节。

## 4. DeepSeekMoE：细粒度 + 共享专家（V2/V3 的 FFN 创新）

> 解决的问题：传统 MoE 专家太「粗」，每个专家被迫学很杂的知识，且容易冗余。

### 4.1 两个核心想法

**想法一：细粒度切分（Fine-Grained Segmentation）**
把每个专家「切小」，专家数变多、每个变瘦，同时 Top-K 也按比例放大。

```
传统 MoE: 16 个胖专家，每 token 选 2 个
          ▮▮▮▮▮▮▮▮ ... (粗)

DeepSeek: 64 个瘦专家，每 token 选 6 个
          ▯▯▯▯▯▯▯▯▯▯▯▯ ... (细)

激活的总参数量相近，但"专家组合数"暴增 ⇒ 表达更灵活、分工更专。
```

为什么有用？专家越细，**可能的专家组合数**呈组合爆炸式增长，每个专家能更专注一个细分知识，减少「一个专家什么都得会」的浪费。

**想法二：共享专家（Shared Expert Isolation）**
拿出 1~几个专家当「**常驻共享专家**」，每个 token **都**经过它，用来承载「通用/公共知识」；剩下的路由专家则专注「专门知识」。

```
  token ─┬─▶ [共享专家] ──────────────┐  (人人都过)
         │                            ▼
         └─▶ Router ─选Top-K─▶ [路由专家i,j,...] ─▶ 加权和 ─▶ 输出
```

好处：**避免每个路由专家都重复学一遍通用知识**，让路由专家把容量省下来学专门知识，减少冗余。

### 4.2 一层 DeepSeekMoE 的数据流

```
              x (一个 token)
               │
      ┌────────┼─────────────────────────┐
      ▼                                   ▼
 [共享专家们]                      [Router 打分 → Top-K]
   全部参与                              │
      │                          选中的路由专家并行计算
      │                                  │
      └──────────── 加权求和 ◀───────────┘
                       │
                       ▼
                    输出 h'
```

V3 规模（约，以官方为准）：每层 1 个共享专家 + 256 个路由专家，每 token 激活共享 + 8 个路由专家。671B 总参数，**每 token 只激活约 37B**。

## 5. 无辅助损失的负载均衡（V3 的关键工程创新）

> 解决的问题：MoE 必须让专家负载均衡（否则有的专家累死、有的闲死），传统做法加一个「辅助损失（aux loss）」强行均衡，但**这个损失会干扰主任务、损害模型质量**。

### 5.1 传统 aux loss 的两难

不加 aux loss → 专家负载严重倾斜 → 部分专家废掉、训练不稳；加 aux loss → 均衡了，但梯度被「均衡目标」污染 → 模型变笨一点。

### 5.2 V3 的解法：可学习的偏置项（bias）

给每个专家的路由打分加一个**偏置 $b_i$**，这个偏置**只影响"谁被选中"，不进入最终权重计算，也不回传主梯度**。

```
路由打分:  s_i  (token 对专家 i 的亲和度)
选谁:      argTopK( s_i + b_i )   ◀── 偏置只在"挑人"时生效
权重:      用原始 s_i 算 (不含 b_i)，不污染主目标

均衡逻辑(每步动态调):
   某专家最近太忙(超载) ─▶ 调低它的 b_i ─▶ 下一步少被选
   某专家最近太闲(欠载) ─▶ 调高它的 b_i ─▶ 下一步多被选
```

效果：**用一个「不影响主损失的旋钮」实现动态均衡**，既均衡又不伤模型质量。这是 V3 相比 V2 在工程上的一个标志性改进。

## 6. MTP：多 Token 预测（V3 的训练 + 推理双赢）

标准语言模型每步只预测「下一个 token」。**MTP 让模型同时预测未来好几个 token**。

```
标准:   预测  t+1
MTP :   预测  t+1, t+2, t+3 ...（多个预测头串联）
```

- **训练时**：每个位置提供更密集的监督信号（一次学好几步），样本利用率更高，表征更前瞻。
- **推理时**：这些额外预测头可以直接当**投机解码（speculative decoding）**的草稿，一次验证多个 token，**显著加速生成**。

> 一句话：MTP 让「训练更省、推理更快」一举两得。

## 7. FP8 训练与工程极致：为什么 V3 这么便宜

DeepSeek-V3 公开的训练成本约 **557 万美元**（约 2.79M H800 GPU 小时，以官方为准）——这在同级别（GPT-4 级）模型里低得惊人。省钱不是靠单一魔法，而是一整套工程组合拳：

```
省钱拼图（V3）= 架构层 × 数值层 × 系统层

架构层: MLA压KV + 细粒度MoE(激活37B/671B) + 无aux均衡 + MTP
数值层: FP8 混合精度训练 (8位替16位, 显存/带宽减半, 关键处保高精度)
系统层: DualPipe(计算/通信重叠,打满GPU) + 定制 All-to-All 通信
          └──── 三层叠乘 ⇒ 同效果，零头价钱 ────┘
```

- **FP8 训练**：把大部分矩阵乘法用 8 位浮点做（更省显存、更快、通信量减半），并在累加、敏感算子等关键处保留高精度，配合细粒度量化避免数值崩。
- **DualPipe**：一种流水线并行调度，把前向/反向计算和跨卡通信**重叠**起来，几乎消除「等通信」的气泡。
- **定制通信内核**：MoE 的 All-to-All 跨节点通信是大瓶颈，DeepSeek 手写内核压榨带宽。

> 注意：精确数字以官方论文为准。这里的意义不是「记住 557 万」，而是理解**「架构创新 × 数值优化 × 系统优化」三层叠乘，才造就数量级的成本优势**。

## 8. DeepSeek-R1：纯 RL 激发推理

> 解决的问题：怎么让模型学会「长链条推理（先想后答）」，又不依赖海量昂贵的人工思维链标注？

### 8.1 训练基石：GRPO（来自 DeepSeekMath）

传统 PPO 需要训一个和策略模型一样大的**价值网络（Critic）**来估算优势，很贵。**GRPO（Group Relative Policy Optimization）** 把 Critic 干掉了：

```
GRPO 直觉:
  对同一个问题，让模型采样一组 G 个答案 {o_1,...,o_G}
  每个答案用"可验证奖励"打分 r_i (如:数学答对=1,错=0)
  组内做标准化当优势:  A_i = (r_i - mean(r)) / std(r)
       └─ 比组里平均好的答案 → 正优势 → 被强化
          比平均差的       → 负优势 → 被抑制

  ⇒ 不需要 Critic，用"组内相对好坏"代替绝对价值估计，省一半显存
```

奖励主要来自**规则可验证**的部分（答案正确、格式正确），这就是 RLVR：**无需奖励模型、无需人工标注，自动判分**。

### 8.2 R1-Zero：一个惊人的发现

**R1-Zero = 完全不做 SFT 冷启动，直接在基座模型上做 GRPO**。结果模型**自发**学会了：

```
R1-Zero 涌现行为:
  ✓ 越训越长的思维链 (自己学会"多想几步")
  ✓ 自我反思 / 回溯 ("等等，前面算错了，重来")
  ✓ "Aha moment" —— 训练曲线上推理能力突然跃升
```

这证明了一件大事：**推理能力可以靠纯 RL「激发」出来，而不是只能靠模仿人类示范学来。** 缺点是 R1-Zero 可读性差、语言混杂。

### 8.3 R1 完整管线：冷启动 + 多阶段

为修复可读性等问题，正式 R1 用多阶段流程（约，以官方为准）：

```
[基座] ─▶ ① 少量高质量冷启动CoT做SFT (修可读性/语言)
       ─▶ ② 面向推理的大规模 GRPO (数学/代码,可验证奖励)
       ─▶ ③ 拒绝采样 + 通用SFT (②的好样本 + 通用对齐数据)
       ─▶ ④ 全场景 RL (推理+通用偏好,兼顾有用/无害)
       ─▶ [DeepSeek-R1]
```

### 8.4 蒸馏：把推理能力「灌」进小模型

R1 还把大模型推理能力**蒸馏**到 Qwen / Llama 系列小模型（1.5B~70B）。关键结论：**「大模型 RL 出的推理样本蒸馏给小模型」比「直接对小模型做 RL」更有效**——小模型探索能力弱，站在大模型肩膀上学更省更强。

## 9. 数值例子 / 对照

### 9.1 MLA 到底省多少 KV Cache（手算）

假设：隐藏维 $d=5120$，头数 $n_h=128$，每头 $d_h=128$，FP16（2 字节）。

**标准 MHA，单 token、单层 KV Cache：**

$$2 \times n_h \times d_h \times 2\text{B} = 2 \times 128 \times 128 \times 2 = 65536 \text{ B} \approx 64\text{ KB}$$

**MLA，只缓存潜在向量**，设压缩维 $d_c=512$，外加解耦 RoPE 维 $d_r=64$：

$$(d_c + d_r) \times 2\text{B} = (512 + 64) \times 2 = 1152 \text{ B} \approx 1.1\text{ KB}$$

**压缩比** $\approx 64\text{KB} / 1.1\text{KB} \approx \mathbf{57\times}$。（数字为示意，具体配置以官方为准。）

放大到「长上下文 + 高并发」（序列 32K、并发 100、层数 60），MHA 的 KV Cache 比 MLA 大 ~57 倍——这就是 **MLA 让长上下文推理可行的根因**（实际还有更多优化，此处只体会数量级）。

### 9.2 MoE 激活率（手算）

V3：总参数约 671B，每 token 激活约 37B。

$$\text{激活率} = \frac{37}{671} \approx 5.5\%$$

意味着**每个 token 的前向计算只用了约 5.5% 的参数**。和同容量稠密模型相比，算力近似只花零头，却保留了「671B 大模型的知识容量」。

### 9.3 几种注意力的 KV Cache 量级对照

| 方案 | 缓存 | 单 token KV（示意） | 相对 MHA | 代表 |
|------|------|------|------|------|
| MHA | 每头独立 K/V | ≈64 KB | 1× | 早期 GPT |
| GQA | 分组共享 K/V | ≈8 KB | ~1/8 | Llama-3 |
| MQA | 全头共享 1 组 | ≈0.5 KB | ~1/128 | 部分模型 |
| **MLA** | 压缩潜在向量 | ≈1.1 KB | ~1/57 | **DeepSeek** |

> MLA 卖点：**接近 MQA 的省显存，却保住接近 MHA 的效果**——鱼与熊掌兼得。

### 9.4 成本直觉

GPT-4 级训练成本（坊间估算）约「1 亿美元数量级」，DeepSeek-V3 官方公开约 **557 万美元**——差约一个数量级。意义：**不是「中国便宜」，而是「架构+数值+系统」三重工程优化叠乘出的数量级效率**。精确数字以官方为准。

## 10. 常见问题

| 问题 | 简答 |
|------|------|
| MLA 和 GQA 谁好？ | MLA 在「省显存」和「保效果」之间更平衡：省到接近 MQA，效果接近 MHA。GQA 是更简单的折中。 |
| MoE 模型 671B，推理要 671B 显存吗？ | 权重要全放（或分布式放），但**每 token 计算只激活约 37B**，省的是算力/带宽，不是权重存储。 |
| 无 aux loss 怎么还能均衡？ | 给路由打分加一个「只影响选谁、不进主梯度」的可学习偏置 $b_i$，按专家忙闲动态调，绕开 aux loss 污染主目标的问题。 |
| R1-Zero 没做 SFT 也行？ | 行，且自发涌现长思维链与自我反思。代价是可读性差、语言混杂，所以正式 R1 加了冷启动 SFT 和多阶段流程。 |
| GRPO 和 PPO 区别？ | GRPO 去掉了 Critic，用「组内多个采样答案的相对好坏」当优势，省显存、训练更稳。 |
| 为什么 R1 要蒸馏？ | 让小模型也具备强推理。实测「大模型 RL 样本蒸馏小模型」优于「小模型直接 RL」。 |
| MTP 有什么用？ | 训练给更密监督信号；推理当投机解码草稿，加速生成。 |
| DeepSeek 为啥便宜？ | MLA+细粒度MoE（省显存算力）× FP8（省数值）× DualPipe/定制通信（省系统空转），三层叠乘；FP8 靠细粒度量化+关键处保高精度控误差。 |
| 这些创新哪代引入？ | MLA/细粒度MoE→V2；无aux均衡/FP8/MTP→V3；GRPO→DeepSeekMath；纯RL推理→R1。 |

**开源与影响（小结）**：V2/V3/R1 均开放权重（许可以官方仓库为准）并披露训练细节，极大降低复现门槛；MLA 成为长上下文高效推理的重要方向；R1 让「纯 RL 激发推理 + 蒸馏小模型」成为社区跟进范式；约 557 万美元训出 GPT-4 级模型，改变了「必须巨额资本才能做前沿模型」的业界认知。
