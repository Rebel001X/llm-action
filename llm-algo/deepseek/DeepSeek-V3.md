## 0. 一句话锚点

DeepSeek-V3 = **V2 的架构骨架(MLA + DeepSeekMoE)** + **三项新工程**：
1. **路由不再用辅助损失**，改用每个专家一个可学习偏置 $b_i$ 动态调平负载 → 不牺牲主任务性能。
2. **MTP**：训练时让模型一步预测**下两个** token，提升数据效率，并为推理期投机解码留接口。
3. **FP8 训练**：把绝大部分 GEMM 用 8-bit 浮点算，显存和通信带宽近乎减半，是它"便宜"的关键。

记住一个画面：**模型很大(671B)，但每个 token 只点亮一小撮专家(37B)**。

## 1. 地基/前置

### 1.1 为什么要 MoE(Mixture of Experts)

Dense 模型：每个 token 的前向都要走**全部** FFN 参数。参数量 $N$ → 每 token FLOPs ∝ $N$。想更聪明就得更大，但更大就更慢更贵。

MoE 的想法：把一个大 FFN 拆成很多个小 FFN(**专家**)，每个 token 只激活其中**几个**。于是：

```
Dense:   token ──► [ 一个巨大 FFN，全部参数都算 ]
                    总参 = 激活参 (全亮)

MoE:     token ──► [路由器] ──► 只点亮 8/256 个小专家
                    总参(671B) >> 激活参(37B)  (大部分熄灭)
```

**好处**：总参很大(知识容量大)，但单 token 计算量只跟激活参有关 → "大而快"。
**代价**：① 路由可能不均衡(某些专家被挤爆、某些饿死);② 显存要装下全部专家。V3 的"无辅助损失均衡"专治 ①。

### 1.2 为什么要 MLA(Multi-head Latent Attention)

标准多头注意力推理时要缓存每层每个 token 的 **K 和 V**（KV Cache）。序列越长、层数越多，KV Cache 越爆显存——它常常是长上下文推理的**第一瓶颈**。

MLA 的核心：不存完整 K/V，而是把它们**压到一个低维 latent 向量** $c^{KV}$，用时再投影回来。详见 [[llm-algo/deepseek/DeepSeek-V2]]，本文第 2 节给手算。

---

## 2. MLA 延续：低秩压缩 KV Cache

### 2.1 原理

设隐藏维 $d=7168$，注意力头数 $n_h=128$，每头维度 $d_h=128$。标准 MHA 每 token 每层要缓存 K、V 各 $n_h \times d_h = 128 \times 128 = 16384$ 维。

MLA 改成：对输入 $h_t$ 先**下投影**到一个小 latent：

$$c^{KV}_t = W^{DKV}\, h_t \quad (\text{维度仅 } d_c,\ \text{V3 中 } d_c=512)$$

缓存时**只存 $c^{KV}_t$(512 维) + 一个解耦的旋转位置键 $k^R_t$(64 维)**，用时再上投影还原 K、V：

$$k^C_t = W^{UK} c^{KV}_t,\qquad v^C_t = W^{UV} c^{KV}_t$$

```
标准MHA每token缓存:  K(16384) + V(16384)  = 32768 维
MLA每token缓存:      c^KV(512) + k^R(64)   =   576 维
                     ───────────────────────────────
                     压缩比 ≈ 32768 / 576 ≈ 57×  (概念示意)
```

### 2.2 手算：KV Cache 显存

V3 官方口径 **每 token 约 70 KB** KV Cache(FP8/BF16 混合存储下)。对比 Dense-67B 级别动辄数百 KB，节省巨大。

> 直觉公式：每 token KV 字节 ≈ 层数 × (压缩维 $d_c$ + 位置维 $d^R$) × 元素字节。
> $61 \times (512+64) \times 2\,\text{B} \approx 70{,}272\,\text{B} \approx 68.6\,\text{KB}$ ✅ 与官方"约 70KB"吻合。

**为什么省**：缓存的不是 $16384$ 维的 K/V，而是 $576$ 维的 latent，差一个数量级。长上下文、高并发推理直接受益。

## 3. DeepSeekMoE 延续：细粒度 + 共享专家

### 3.1 两个设计

V3 的 MoE FFN 由两类专家组成：

- **共享专家(shared)**：每个 token **必经**，承载通用知识(V3 用 **1 个**)。
- **路由专家(routed)**：每个 token 由路由器选 **Top-K 个**(V3 共 **256 个**，每 token 选 **8 个**)。

```
            ┌─────────────── 1 个共享专家 (恒定激活) ───────────┐
 token h_t ─┤                                                    ├─► 加和 ─► 输出
            └─ 路由器打分 ─► Top-8 / 256 路由专家 (各乘门控权重) ─┘
```

FFN 输出：

$$h'_t = h_t + \underbrace{\text{FFN}^{(shared)}(h_t)}_{\text{必经}} + \sum_{i \in \text{Top-}8} g_{i,t}\,\underbrace{\text{FFN}^{(routed)}_i(h_t)}_{\text{被选中}}$$

其中门控 $g_{i,t}$ 由专家亲和度 $s_{i,t}=\text{Sigmoid}(h_t^\top e_i)$ 归一化得到。

### 3.2 为什么"细粒度"

把专家切得更小、数量更多(256 个而非 8 个大专家)，等于给路由更细的"组合自由度"：8 选中专家从 256 里挑，组合数 $\binom{256}{8}$ 是天文数字，**专家分工更专、知识更不冗余**。这是 DeepSeekMoE 相比传统 MoE(GShard 式 8 大专家)的关键改进。

## 4. 无辅助损失负载均衡(核心创新)⭐

### 4.1 问题：传统 aux loss 的副作用

MoE 必须防止"路由塌缩"(所有 token 都涌向少数专家)。传统做法加一个**辅助损失(auxiliary loss)** 惩罚不均衡：

$$\mathcal{L} = \mathcal{L}_{\text{主任务}} + \alpha\,\mathcal{L}_{\text{balance}}$$

**痛点**：$\mathcal{L}_{\text{balance}}$ 是一个"为了均衡而强加"的梯度，会**和主任务目标打架**——$\alpha$ 太大伤性能，太小不均衡。这是个难调的跷跷板。

### 4.2 V3 的解法：每个专家一个 bias $b_i$

V3 **不在损失里加均衡项**，而是给每个路由专家配一个**可学习/可调的偏置 $b_i$**，只在**选 Top-K 时**加进去：

$$\text{选专家用}\quad s_{i,t} + b_i \quad\text{排序取 Top-8}$$

但**门控权重 $g_{i,t}$ 仍用原始 $s_{i,t}$**(不含 $b_i$)——即 $b_i$ **只影响"选谁"，不影响"加权多少"**，所以它**不进入主损失的梯度**。

### 4.3 bias 怎么更新(无梯度，规则式)

每个训练 step 后，统计各专家这一批被分到多少 token：

```
若某专家「过载」(分到的 token 太多)  →  b_i ← b_i − γ   (降低,使它更难被选中)
若某专家「饥饿」(分到的 token 太少)  →  b_i ← b_i + γ   (提高,使它更易被选中)
                                          γ 是很小的更新步长
```

```
ASCII 反馈环：
  ┌──► 统计每个专家的负载 ──► 与平均比较 ──┐
  │                                        ▼
  专家 8 ◄── 调整 b_i (过载↓ / 饥饿↑) ◄── 偏置控制器
```

**为什么妙**：均衡这件事被挪出了损失函数，变成一个**旁路控制器**。主损失只管"预测得准不准"，负载均衡由 $b_i$ 这个"调节阀"独立完成 → **均衡不再以牺牲性能为代价**。V3 在此基础上仅保留一个极小的 sequence 级辅助损失防止单序列内极端塌缩。

## 5. MTP：多 token 预测(Multi-Token Prediction)⭐

### 5.1 标准训练 vs MTP

标准自回归：第 $t$ 个位置只预测**下一个** token $x_{t+1}$。每个位置只产生一条监督信号。

MTP：在主模型之外挂 **$D$ 个 MTP 模块**(V3 用 $D=1$，即多预测一个)，让位置 $t$ 同时预测 $x_{t+1}$ **和** $x_{t+2}$。

```
主模型:        h_t ─► 预测 x_{t+1}
                │
MTP模块(深度1): │ 取主模型表示 + x_{t+1} 的 embedding
                └─► Transformer块 ─► 预测 x_{t+2}
```

与早期 MTP(Meta 2024，多个**并行**头)不同，V3 的 MTP 是**串行/因果链式**的：每个 MTP 模块复用主模型的隐状态，并**保持完整的因果链**(预测 $x_{t+2}$ 时已知 $x_{t+1}$)，预测质量更高。

### 5.2 损失

$$\mathcal{L}_{\text{MTP}} = \lambda \cdot \frac{1}{D}\sum_{k=1}^{D}\mathcal{L}^{(k)}_{\text{CE}},\qquad \mathcal{L} = \mathcal{L}_{\text{main}} + \mathcal{L}_{\text{MTP}}$$

$\lambda$ 是 MTP 权重(V3 训练中后期约 0.1，前期略大，**以官方为准**)。

### 5.3 两个收益

- **训练期**：每个位置多一条监督 → **样本利用率/数据效率提升**，token 表示被"逼"得更有前瞻性。
- **推理期**：MTP 模块可直接当**投机解码(speculative decoding)** 的草稿头，一步出多个候选 token。官方报告第二个 token 的**接受率约 85%~90%**，配合验证可带来约 **1.8× 解码加速**(以官方为准)。

> 注意：推理时 MTP 模块**可丢弃**(只用主模型)，也可保留做投机解码——它是"可选增益"，不影响主模型正确性。

## 6. FP8 混合精度训练⭐

### 6.1 浮点格式扫盲

8-bit 浮点(FP8)有两种常用排布：

| 格式 | 位分配(符号/指数/尾数) | 特点 | V3 用途 |
|------|----------------------|------|---------|
| **E4M3** | 1 / 4 / 3 | 尾数多→**精度高**，动态范围小 | 前向激活、权重 |
| **E5M2** | 1 / 5 / 2 | 指数多→**范围大**，精度低 | 反向梯度 |

对比 BF16(1/8/7) 和 FP32(1/8/23)：FP8 只有 8 位，**存储和通信带宽直接减半**，张量核(Tensor Core)的 FP8 GEMM 吞吐也更高。

### 6.2 难点与 V3 的对策

FP8 数值范围小，**最怕异常值(outlier)** 把 scale 撑爆导致大面积下溢。V3 的关键技巧：

- **细粒度分块量化(fine-grained quantization)**：
  - 激活按 **1×128 的 token-tile** 分组定 scale；
  - 权重按 **128×128 的 block** 分组定 scale。
  - → 一个离群值只污染它所在的小块，不拖累整张张量。
- **高精度累加**：FP8 做乘法，但部分和(accumulation)**提升到 FP32** 累加(在 CUDA core 上做 promotion)，避免长链累加的精度坍塌。
- **关键算子留高精度**：embedding、输出头、归一化、注意力的部分运算、MoE 门控等**保持 BF16/FP32**，只把"占比最大、最耐受误差"的 GEMM 放 FP8。

```
量化数据流(概念):
  激活(BF16) ─►[按1×128分块取scale]─► FP8 ─┐
                                            ├─► FP8 GEMM ─► FP32累加 ─► BF16
  权重(BF16) ─►[按128×128分块取scale]─► FP8┘
```

### 6.3 手算：FP8 的 scale 与误差直觉

设某 1×128 激活块的最大绝对值 $\max=240$，E4M3 可表示的最大值约 $448$。
缩放因子 $\text{scale} = 448/240 \approx 1.867$，量化时 $x_q = \text{round}(x \cdot \text{scale})$，反量化 $\hat{x}=x_q/\text{scale}$。
若该块还有个离群值 $1000$ 落在**另一个**块里，它**不会**逼着这个块用巨大的 scale → 这个块的小数值不被压成 0。这就是分块量化"隔离离群值"的价值。

## 8. 训练要点

- **数据**：约 **14.8T tokens** 预训练，强化代码与数学占比。
- **算力**：约 **2.788M H800 GPU 小时**(预训练≈2.664M)，官方折算训练成本约 **$5.576M**(仅 GPU 租用口径，不含前期研发)。
- **并行**：MoE 用专家并行(EP) + 数据/流水并行；自研 **DualPipe** 流水算法，让计算和"全互联通信(all-to-all)"**重叠**，几乎吃掉通信开销;手写高效 all-to-all 内核充分压榨 H800 的 NVLink/IB 带宽。
- **稳定性**：FP8 训练全程**无不可恢复的 loss spike、无回滚**——这是工程成熟度的硬指标。
- **后训练**：SFT + RL，并从 R1 系列**蒸馏推理能力**(详见 [[llm-algo/deepseek/DeepSeek-R1]])。

### 工程亮点速记

1. **算法-框架-硬件协同设计**：MLA/MoE/FP8/DualPipe 不是孤立 trick，而是为 H800(受限带宽)量身共设计。
2. **通信即瓶颈**：MoE 的 all-to-all 是大头，DualPipe + 重叠 + 受限节点路由把它压住。
3. **FP8 全流程跑通**且稳定，是当时开源大模型里少有的工业级实践 → 见 [[llm-train/fp8]]、[[llm-compression/quantization/fp8]]。

## 9. 数值示例 / 手算

### 9.1 激活比 37B / 671B 怎么来的

直觉拆解：每 token 激活 = 注意力(全激活) + 共享专家(全激活) + 8 个路由专家(稀疏)。
路由专家总参占 671B 的绝大部分，但每 token 只点 8/256 ≈ **3.1%**。把"注意力 + 共享 + 8 路由专家"加起来 ≈ **37B**。

$$\frac{37\text{B}}{671\text{B}} \approx 5.5\%\ \text{的参数被激活} \Rightarrow \text{算力≈37B Dense，知识容量≈671B}$$

### 9.2 单 token 前向 FLOPs 的量级

经验法则：Transformer 前向每 token FLOPs ≈ $2 \times N_{\text{激活}}$。
$$2 \times 37\times10^9 \approx 7.4\times10^{10} = 74\ \text{GFLOPs/token}$$
对比同等"智能"的 Dense-671B：$2\times671\times10^9 \approx 1.34\ \text{TFLOPs/token}$ → V3 省约 **18×** 计算。

### 9.3 长序列 KV Cache 对比(再算一遍)

10K token 序列：
- V3(MLA)：$10{,}000 \times 70\text{KB} \approx 700\ \text{MB}$。
- 若是 Dense-MHA 同规格(KV≈32768维/层×61层×2B≈4MB/token)：$10{,}000 \times 4\text{MB} = 40\ \text{GB}$。
→ MLA 在该例省约 **57×** KV 显存(概念量级)。这就是 V3 能高并发、长上下文还便宜的底气。

## 11. 常见问题 / 高频追问

| 高频问题 | 踩点答案 | 追问 & 陷阱 |
|----------|----------|-------------|
| V3 相对 V2 最大的新东西？ | 无辅助损失均衡、MTP、FP8 三件套(架构骨架沿用) | 追问：哪个最影响"性能不掉"? → bias 均衡 |
| 无辅助损失均衡怎么做到不伤性能？ | bias $b_i$ 只参与 Top-K 选择、不进门控权重/不进主损失梯度；按负载规则增减 | 陷阱：别说"完全没辅助损失"，仍有极小 sequence 级项 |
| bias 是靠梯度学的吗？ | 否，是**规则式**按批负载增减，无梯度 | 追问：和 aux loss 区别? → 旁路控制 vs 损失内惩罚 |
| MTP 推理时一定要用吗？ | 不必，可丢弃；保留则做投机解码加速 | 陷阱：MTP 不改变主模型正确性 |
| 为何敢用 FP8？ | 分块量化隔离离群值 + FP32 累加 + 关键算子留高精度 | 追问：哪些不放 FP8? → embedding/输出头/norm/门控 |
| MLA 缓存的是什么？ | 低维 latent $c^{KV}$(512) + 解耦位置键 $k^R$(64)，不是完整 K/V | 陷阱：不是直接量化 K/V，而是低秩压缩 |
| 671B 但只激活 37B，算力等于多大 Dense？ | 约 37B Dense 的算力，671B 的知识容量 | 追问：FLOPs≈2×激活参 |
| V3 便宜的根因？ | 稀疏激活 + FP8 + DualPipe 通信重叠 + MLA 省显存，四者叠加 | 陷阱：$5.5M 仅 GPU 租用口径 |
| 1 共享 + 256 路由的意义？ | 共享存通用知识防冗余，细粒度路由专家分工更专 | 追问：组合数 $\binom{256}{8}$ 极大 |
| V3 和 R1 关系？ | R1 以 V3-Base 为底做大规模 RL/推理；V3 也反向蒸馏 R1 推理能力 | 见 [[llm-algo/deepseek/DeepSeek-R1]] |
