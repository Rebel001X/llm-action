## 0. 这个库要回答什么

一句话：**如果你要自己写一个推理引擎，需要懂哪些原理、按什么顺序搭、用什么语言写。**

三个子问题，对应三块内容：

1. **需要懂什么** → `01-地基/`：自回归解码的成本结构、KV 缓存的第一性原理、数值与 GPU 执行模型。
2. **怎么一步步搭起来** → `02-最小可跑引擎/`：从朴素前向到 KV 缓存、分页、连续批处理、前缀缓存、HTTP 服务。
   **每一步都有 `_lab/` 里能跑的代码**。
3. **用什么语言写** → `03-语言选型/`：这是用户直接问的问题，本库用**12 个真实引擎的实测语言构成**来答，不靠意见。

## 1. 本库的诚实标准（与研究库不同，注意区别）

研究库的红线是「每条断言回到一行别人的源码」。本库是教学库，红线不一样：

1. **每个原理必须有可跑的代码**。讲 KV 缓存就要有 `_lab/minigpt.py` 里能跑的两条路径，
   并且**有测试证明它们输出一致**。**只有文字说明、没有可执行验证的原理，一律不许写。**
2. **引用本库自己的代码用 `_lab/xxx.py:行号`**，`_verify.py` 会逐条核。
3. **引用真实引擎的代码**（说明"vLLM 是怎么做的"）时，写成 `vllm:vllm/v1/core/...py:123` 这种带引擎前缀的形式，
   由 `_verify.py` 对着 `../VLLM-SGlang-研究-推进/_src/` 核。**没有那份 clone 时自动跳过并明说跳了多少条。**
4. **性能数字分两类，必须标清楚**：
   - **可以有**：本库自己的玩具引擎在 CPU 上的实测（它就是我们写的，测它天经地义）；
   - **绝不许有**：把玩具的数字外推到 vLLM/SGLang，或凭空给出真实引擎的吞吐/延迟。
     引上游 benchmark 必须带硬件/模型/长度/并发口径。
5. **每条设计决策配三样**：**为什么这么设计 / 不这样会怎样 / 什么时候可以不这样**。
   教学库尤其忌讳只讲"标准做法"不讲"什么时候不适用"。
6. **不编 URL、不编 PR 号、不编论文标题**。查不到写「未查证」。

| `flashattn.py` | 在线 softmax + 分块注意力 + decode 的 split-KV，**证明分块是重写不是近似** | `04-进阶主题/01` |
| `parallel.py` | TP（列切/行切）、PP（气泡公式）、EP（负载不均），**等价性与代价都可单机验证** | `04-进阶主题/02` |
| `spec_decode.py` | 投机解码 + **20 万次采样的分布检验** + 故意写错的验收版反例 | `04-进阶主题/03` |
| `structured.py` | 字符级文法 → BFS 枚举状态 → 状态×词表掩码索引 + jump-forward | `04-进阶主题/04` |
| `quantize.py` | 三档量化的误差、实际位宽、**量权重还是量 KV 的访存账** | `04-进阶主题/05` |
| `tests/test_lab.py` | 25 项：**输出恒等** | `01-地基/*`、`02/01-05` |
| `tests/test_serving.py` | 25 项：**可复现 + 批不变 + 不泄漏** | `02/06-07` |
| `tests/test_advanced.py` | 60 项：四种判据混合（文件头有对照表） | `04-进阶主题/*` |
| `tests/test_invariants.py` | 9 项：**退化情形 + 结构不变量**，补差分测试的盲区 | `05-工程与陷阱/01` |

规矩：
- 每个脚本都有 `--selftest`，不依赖任何外部模型/数据/框架（只要 numpy 与标准库）；
- **测试判据分四套，别混**（用错地方会得到"永远通过"或"永远失败"的无用测试）：

  | 判据 | 用在哪 | 抓不到什么 |
  |---|---|---|
  | **输出恒等**（算两遍逐位比） | KV 缓存 / 分页 / 批处理 / 前缀缓存 / FlashAttention / TP | **两侧同时犯的错** |
  | **分布恒等**（大量采样比全变差） | 投机解码 | 低于采样噪声的偏差 |
  | **约束恒成立** | 结构化输出（它**故意**改变分布） | 分布层面的偏移 |
  | **误差有界且单调** | 量化（它本来就是有损的） | 特定输入上的灾难性失效 |

  **"输出恒等"有一个结构性盲区**：4 处残差同时写错时，两条前向路径一起错，
  25 条差分断言全绿而 argmax 已从 36 变成 44。
  解药是 `tests/test_invariants.py`：**不比"实现和实现"，比"实现和它必须满足的性质"**
  （退化情形 + 结构不变量）。完整复现见 `05-工程与陷阱/01-正确性怎么保证.md`。
- **改 `_lab/` 里已有文件前先想一下**：正文用 `文件:行号` 引它们，
  在中间插行会让已落盘章节的引用集体失准。**优先用加法（新文件 / 追加在文件末尾）。**

## 3. 已经算出来的关键事实（写正文时直接用，但要复核）

### 3.1 算术强度（`_lab/minigpt.py` 的解析模型，非实测）

一步 decode 的 `算术强度 = FLOPs / Bytes`，fp32、默认小配置：

```
     ctx     bs=1     bs=4    bs=16    bs=64   bs=256    KV占访存(bs=64)
      16     0.50     1.89     6.21    14.50    21.74           54.7%
      64     0.50     1.65     3.85     5.80     6.64           82.8%
     256     0.50     1.17     1.76     2.02     2.10           95.1%
    1024     0.50     0.75     0.86     0.90     0.90           98.7%
    4096     0.50     0.57     0.59     0.60     0.60           99.7%
   16384     0.50     0.52     0.52     0.53     0.53           99.9%
```

三条读法（**本库最重要的一张表**）：
- **`bs=1` 恒为 0.50，与上下文长度无关。** 因为 fp32 下每个参数/每个 KV 元素都是「1 次乘加(2 FLOP) 读 4 字节」。
  **它一开始就在访存瓶颈的底，没有更低可去。**
- **只有增大 batch 能抬高它** —— 权重读一遍被整批共用。**这就是连续批处理的根本理由。**
- **但 ctx 越长，batch 抬得越少**：ctx=16 时 bs=256 能抬到 21.74，ctx=16384 时只能抬到 0.53，
  因为 KV 是每条请求私有的、占了 99.9% 的访存。**长上下文杀吞吐的机制就在这里。**

> ⚠️ 我第一版把这个模型算错过：把 embedding 的字节算进分母却没算 lm_head 的 FLOPs，
> 于是强度算出来是 0.43→0.50 一路上升，看着像"ctx 越长越受限"。
> 正确做法是把「矩阵乘用到的权重」和「只被 gather 的 embedding」分开算。见 `_lab/minigpt.py:197` 的注释。

## 7. 已知踩坑

1. **算术强度模型第一版算错**：embedding 字节进了分母、lm_head FLOPs 没进分子。
   教训：**任何 roofline 类的解析模型，先验证"退化情形下等于理论值"**
   （这里是 bs=1 应恒等于 `2/dtype_bytes`），再看趋势。
2. **测试用的 token id 必须小于 vocab**。第一版 selftest 里写了个 92 而 vocab=64，直接越界。
3. 本库 `_lab` **不装 torch**，全 numpy —— 目的是让每一步矩阵乘露在外面。
   代价是慢，但教学库不比性能。
