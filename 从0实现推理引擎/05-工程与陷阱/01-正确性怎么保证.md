# 01 · 正确性怎么保证

> 这一篇是整个库的脊椎。前面每一章都在做一件事：**给引擎加一层优化**。
> 而这一篇要回答：**你凭什么相信加完之后它还是对的？**

---

## 0. 这一篇要解决什么问题

推理引擎的 bug 有一个几乎统一的性状：

> **它们不崩，只是悄悄给出不一样的答案。**

KV 缓存写错位置、分页时块表越界、批处理时两条请求串了 KV、前缀缓存哈希撞了、
采样算子顺序反了 —— 这些**全都不会抛异常**。
张量形状是对的，没有 nan，服务正常返回 200，生成的文本读起来也通顺。
唯一的症状是：**答案变了，而你不知道**。

这一点和普通业务系统正好相反。业务系统的 bug 大多会以异常、错误码、
数据不一致的形式显形；推理引擎的 bug 则被模型本身的"合理性"掩盖掉了 ——
**模型总能给你一段像模像样的话，无论它中间读到的是不是别人的 KV。**

所以这一篇要讲的不是"写测试很重要"，而是三件具体的事：

1. **本库用哪几种判据**，它们各自能抓什么、不能抓什么；
2. **差分测试有一个结构性盲区**，我把它复现出来了，并给出解药；
3. **我自己在写这个库时被打脸的每一次**，以及每次纠正后加的那条断言。

第 3 点尤其要读。**这个库里所有"我以为是这样，结果不是"的记录都在这一篇。**

## 1. 先看现象：一个整套自检全绿的错误模型

先跑一遍正常的自检，确认基线：

```bash
cd _lab && python -m pytest tests -q
```

现在做一个实验。`minigpt.py` 里有 4 处残差连接，形如 `x = x + o @ lw["wo"]`。
把这 4 处的加号去掉，变成 `x = o @ lw["wo"]` —— 也就是**把"残差"写成了"替换"**。
这是一个真正的模型 bug：整个 Transformer 的残差结构没了。

注意：`forward_naive`（`_lab/minigpt.py:95`）和 `forward_cached`（`_lab/minigpt.py:139`）
里都有这样的写法，所以**两条前向路径会一起被改到**。

实测结果：

```
正常：  差分测试 allclose=True   argmax=36/36
注入：  把 4 处 `x = x + ` 改成 `x = `（两条前向路径都改到）
有bug：差分测试 allclose=True   argmax=44/44
       正常 argmax=36 vs 有bug argmax=44  → 输出确实变了
       但 selftest 会怎么说： 全过（抓不到）

对照：只在**一侧**注入同样的 bug（只改缓存前向）
       差分测试 allclose=False  → 立刻抓到
```

读一遍这几行：

- 模型的输出**确实变了**（argmax 从 36 变成 44）；
- `test_kv_cache_matches_naive`（`_lab/tests/test_lab.py:44`）**通过**；
- `test_generation_identical_with_and_without_cache`（`_lab/tests/test_lab.py:63`）**通过**；
- 换句话说，**本库当时那 25 条差分断言，一条都没响。**

而只在一侧注入同样的 bug，差分测试立刻抓到。

**这不是测试写得不够仔细，这是差分测试的定义决定的**：
它比的是"两个实现是否一致"，而不是"实现是否正确"。
**两侧一起错，就是一致的。**

## 2. 原理：四种判据，各管一段

本库到目前为止用了四种不同的正确性判据。**它们不是风格差异，是适用范围差异，
用错地方就会得到"永远通过"或"永远失败"的无用测试。**

| 判据 | 用在哪 | 长什么样 | 抓不到什么 |
|---|---|---|---|
| **输出恒等**（差分） | KV 缓存、分页、连续批处理、前缀缓存、FlashAttention、张量并行 | 算两遍，逐位比 | **两侧同时犯的错** |
| **分布恒等**（统计） | 投机解码 | 大量采样后比全变差 | 低于采样噪声的偏差 |
| **约束恒成立** | 结构化输出 | 每次输出都必须被解析器接受 | 分布层面的偏移（它**故意**改变分布） |
| **误差有界且单调** | 量化 | 误差落在解析预测附近，且随位宽单调 | 特定输入上的灾难性失效 |

三条容易搞错的对应关系，逐一说明：

**（a）拿"输出恒等"去测量化 —— 永远失败。**
量化本来就是有损的，要求逐位相等等于要求它什么都不做。
正确判据是"误差在解析预测的范围内"：
`_lab/tests/test_advanced.py:250` 那条断言先按
`(amax/qmax/√12)/std(w)` 算出**应有的**误差，再和实测比 ——
实测 0.01079、预测 0.01076，差 0.3%。**先算出来再对，不要拍脑袋定阈值。**

**（b）拿"跑起来没报错"去测投机解码 —— 永远通过。**
`_lab/spec_decode.py:65` 是一个**故意写错**的验收版：
「`p(x) ≥ q(x)` 就收，否则直接从 p 重采」。它跑起来完全正常，
生成的文本通顺，**没有任何异常**，只是分布错了。
20 万次采样测出来：正确版与目标分布的全变差 0.00232（采样噪声量级），
朴素版 0.12940 —— **56 倍**（`_lab/tests/test_advanced.py:158`）。
**这类 bug 不做统计检验根本发现不了。**

**（c）拿"分布恒等"去测结构化输出 —— 问错了问题。**
结构化输出**就是要**改变分布：把不合法的 token 剪掉再归一化
（`_lab/structured.py:164`）。它的判据是"约束恒成立"：
模型给纯噪声 logits，500 次采样必须 500 次都能被 `json.loads` 解析
（`_lab/tests/test_advanced.py:204`）。

> **一句话记法**：
> 投机解码**不改变**分布，是等价重写；结构化输出**故意改变**分布，是有意干预。
> **前者测分布恒等，后者测约束恒成立。判据跟着意图走，不跟着技术走。**

### 2.1 差分测试的盲区，以及解药

第 1 节那个实验说明：差分测试的能力边界是**"两个实现之间的差异"**。
要抓两侧同错，必须换一个参照系 ——

> **不比"实现和实现"，比"实现和它必须满足的性质"。**

这些性质来自数学，不来自另一份代码，所以两侧同错也躲不掉。
本库把这类断言单独收在 `_lab/tests/test_invariants.py:1`，分两类：

**退化情形**：把参数设成某个特殊值，让模型**必须**塌缩成一个已知的简单形式。
残差那个 bug 的解药就是这个 —— 把每层的 `wo` 与 `w2` 置零后，
两个子层的输出都是 0，于是 `x = x + 0` **必须**是恒等映射，
整个模型必须退化成 `lm_head(LayerNorm(embedding))`。实测：

```
正常实现： 退化情形测试 通过     最大差 2.372e-07
两侧同错： 退化情形测试 **失败**  最大差 3.264e+00
```

差分测试全绿的那个 bug，在这里**最大差从 2.4e-07 跳到 3.26**，立刻暴露。
断言在 `_lab/tests/test_invariants.py:43`。

**结构不变量**：不依赖具体数值的性质。本库收了这些 ——

- **单 token 时注意力输出恰好等于 V 本身**（softmax 只有一项，恒为 1）：
  `_lab/tests/test_invariants.py:70`。它与分数怎么算**完全无关**，
  所以能把"加权结构"和"分数计算"分开验。
- **所有 K 相同 ⇒ 输出是 V 的算术平均**：`_lab/tests/test_invariants.py:83`。
  抓"某个位置被漏算或重复算"这类权重分配错误。
- **因果性：未来的 token 不许改变过去的 logits**：`_lab/tests/test_invariants.py:112`。
  这是**输入空间**上的不变量，和"哪个实现"无关，掩码方向反了立刻挂。
- **反向断言：换了 token 顺序结果必须变**：`_lab/tests/test_invariants.py:131`。
  它抓的是"少做了一件事"—— 位置编码根本没起作用时，正向断言是发现不了的。

最后一条尤其值得记：**正向断言只能确认"做了的事做对了"，
确认不了"该做的事有没有做"。** 后者需要反向断言。

### 2.2 解析模型也要验退化情形

同一套方法论对**算式**同样适用，而且本库正是在这里栽过跟头。

`analytic_cost()`（`_lab/minigpt.py:197`）第一版算出来的算术强度是
0.43 一路上升到 0.50，看着像一条漂亮的趋势线，我还为它编了一套解释
（"上下文越长越受访存限制"）。
**真相是口径错了**：embedding 的字节进了分母，而 lm_head 的 FLOPs 没进分子。

抓住它的办法不是找到那行代码，是**先问这个模型在退化情形下应该等于几**。
fp32、batch=1 时，权重侧和 KV 侧都是"每元素 1 次乘加（2 FLOP）、读 4 字节"，
所以强度**必须恰好是 0.5**，与上下文长度**完全无关**。
一旦这么问，那条"上升的趋势"当场就站不住了。

现在这条被钉成断言：`_lab/tests/test_invariants.py:145`
对 dtype ∈ {1,2,4} 字节 × ctx ∈ {16, 1024, 65536} 全部验 `2/dtype`。
另一条 `_lab/tests/test_invariants.py:162` 验 KV 字节**同时**对 ctx 和 batch 线性 ——
**两个方向都要验**，只验一个方向时把 batch 写错位置也能蒙混过关。

> **规矩：任何 roofline / 成本模型，先验证退化情形等于理论值，再看趋势。**
> 趋势是最容易自圆其说的东西，而退化情形是硬的。

### 3.1 几条值得单独看的断言

**块不够时必须明确报错**（`_lab/tests/test_lab.py:155`）。
`_lab/paged.py` 在块耗尽时抛 `MemoryError`。
**静默乱写是推理引擎最危险的失败模式** —— 写到别人的块上，
两条请求都能正常返回，答案都是错的。
同理还有"没有任何合法 token 时必须抛异常"（`_lab/structured.py:164`）：
静默的话 softmax 变 nan、argmax 取 0，模型开始吐垃圾而毫无报错。

**引用计数守住共享块**（`_lab/tests/test_lab.py:163`）。
块共享成立的前提是"归零才归还"。少了它，
一条请求结束时会把还在被别人用的块还回去，
第三条请求分到这个块并覆写 —— **原持有者下一次 `gather()` 读到的是别人的 KV**。
形状合法、没有 nan、没有异常，只是答案错了。

**链式哈希防碰撞**（`_lab/tests/test_lab.py:217`）。
前缀缓存的块哈希必须是 `hash(父块哈希, 本块token)`。
只哈希本块 token 时，`"1,2|5,6"` 与 `"3,4|5,6"` 的第二块会撞成同一个 key，
而它们的 K/V 完全不同。**这条不加断言，错了没有任何迹象。**

**块不泄漏**（`_lab/tests/test_lab.py:238`、`_lab/tests/test_serving.py:258`）。
跑完一批请求后 `pool.alloc.n_used` 必须回到 0。
泄漏不会报错，只会表现为"内存只涨不跌"。

**批不变性**（`_lab/tests/test_serving.py:95`）。
一条请求的输出**不许**取决于同批里还有谁。
共用全局随机数发生器时这条会挂，线上表现是"同 seed 复现不出来"。

### 3.2 一条工程规矩：正文里的每个行号都会被打开核一遍

`_verify.py`（`_verify.py:86`）做的事很朴素：
把每篇 md 里形如 `` `_lab/minigpt.py:197` `` 的引用抓出来（`_verify.py:42` 的正则），
**真的打开那个文件数到那一行**；带引擎前缀的（`_verify.py:149`）
则对着隔壁 `../VLLM-SGlang-研究-推进/_src/` 核，
**那份 clone 不在时明说跳过了多少条，不伪装通过**。

这不是形式主义。**教学库最容易出的错就是"讲了一个原理，但指不到能跑的代码"**，
以及"引用的行号在某次重构后早就飘了"。
让机器每次都数一遍，是唯一可靠的办法。

顺带一条被这套机制逼出来的工程习惯，写在 `_PLAN.md` §2 里：
**改 `_lab/` 已有文件时优先用加法**（新文件，或追加在文件末尾），
因为在中间插行会让已落盘章节的引用集体失准。
本篇提到的 `test_invariants.py` 就是新开一个文件而不是往 `test_lab.py` 中间插。

## 4. 真实引擎是怎么做的

真实引擎面对的是同一个问题，而且更严重 —— 它们的优化更多、路径更多、
硬件后端更多，每一条都有"静默改变输出"的风险。可以去 clone 里核这几件事：

**（一）后端之间要能互相对照。**
vLLM 把注意力做成可插拔的后端（`vllm:vllm/attention/` 下），
SGLang 同样挂了多种。**多后端本身就是一种差分测试的机会**：
同一个模型同一段输入，换个后端结果必须一致。
这正是本库 `test_paging_is_output_preserving` 参数化 5 种块大小的放大版。

**（二）"确定性"是一个需要显式打开的开关，而不是默认属性。**
本库 `_lab/flashattn.py:166` 的第 10 条断言实测到：
不同块大小的分块注意力结果在 1e-5 内一致，但 `np.array_equal` 返回 **False** ——
**分块改变了浮点求和顺序，最后几位就可能不同**。
真实引擎里这件事被 batch 组成、kernel 选择、split-K 段数一起放大，
所以各家都提供了某种 deterministic 开关，代价是性能。
**这意味着"两次跑结果不完全一样"未必是 bug** ——
写测试时必须区分"数值噪声"和"逻辑错误"，用容差而不是相等。

**（三）不许静默降级。**
块不够、形状没被 CUDA Graph 捕获、某个后端不支持某个特性 ——
这些情况都必须**要么显式回退并可观测，要么明确报错**。
静默降级的危害不在于慢，在于**你以为在测的东西和实际跑的东西不是一回事**。

> `../VLLM-SGlang-研究-推进/_src/` 的快照为准自行 `grep` ——

## 5. 设计决策与代价

### 5.1 主力判据选"输出恒等"，而不是"评测分数不掉"

**为什么这样**：KV 缓存、分页、批处理、前缀缓存这四样在数学上**完全等价**，
所以可以要求逐位相同。这是一条**极强**的判据 —— 强到能在 0.14 秒内跑完并给出确定答案。

**不这样会怎样**：改用"评测分数不掉"当判据，你需要跑一整套评测（慢、贵、要 GPU），
而且**分数波动会掩盖真实 bug** —— 一个让答案错 3% 的 KV bug，在评测上可能只掉 0.5 分，
完全落在噪声里。**用弱判据测强命题，等于没测。**

**什么时候可以不这样**：当变换本来就不等价时（量化、剪枝、蒸馏），
恒等判据无意义，必须换成"误差有界"或真实评测。

### 5.2 每个模块自带 `--selftest`，而不是只有 pytest

**为什么这样**：教学库的读者可能只想跑一个文件看看。
`python paged.py --selftest` 不需要装 pytest、不需要懂 fixture、不需要知道项目结构。
而且自检的输出是**带解释的中文断言**，本身就是文档。

**不这样会怎样**：正确性验证的门槛变高，读者更可能选择"读一遍代码相信它"。

**什么时候可以不这样**：真实工程项目不该这么做 —— 自检和测试重复维护有成本，
统一到 pytest 更专业。**这是教学库特有的取舍。**

### 5.3 保留"故意写错的版本"作为反例

`_lab/sampling.py:75`（重复惩罚符号写反）和 `_lab/spec_decode.py:65`
（朴素验收）都是**故意留在仓库里的错误实现**，只被自检当反例调用。

**为什么这样**：**证明一条断言有意义的唯一办法，是给出一个能让它失败的实现。**
没有反例的断言，你不知道它是在守护什么，也不知道它会不会永远通过。

**不这样会怎样**：会出现"看起来很严格、其实永远通过"的断言。
本库就出过这种事 —— 见下一节第 3 条。

**什么时候可以不这样**：反例代码有被误用的风险时（比如它长得太像正确实现）。
本库的对策是给它们显眼的 docstring（"只留给自检当反例，不要在别处调用"）。

### 5.4 承认"我不知道"，而不是给一个数

本机没有 GPU，所以本库**一个真实引擎的性能数字都不产**。
玩具引擎在 CPU 上的实测可以有，但每次出现都要标注"不可外推"。

**为什么这样**：一个来路不明的性能数字比没有数字更糟 —— 它会被引用、被比较、被决策。

**不这样会怎样**：整个库的可信度归零。**读者没法验证的东西，就该写"未查证"。**

**什么时候可以不这样**：你真的有那台机器、真的跑了、并且写清了完整口径
（模型/精度/长度/并发/硬件/开了哪些特性）。见 `[[02-性能怎么测才不骗自己]]`。

## 6. 常见错误与踩坑

### 6.1 六次打脸清单（本库自己的）

这一节是本篇最该被读的部分。**每一条都是我先写下了一个结论，然后被自己的代码证伪。**

| # | 我以为 | 实际 | 现在钉住它的断言 |
|---|---|---|---|
| 1 | 算术强度随上下文变长而下降 | **batch=1 时恒为 `2/dtype字节`，与 ctx 无关**。第一版把 embedding 字节算进分母、lm_head 的 FLOPs 没算进分子，造出一条假趋势并配了一套解释 | `_lab/tests/test_invariants.py:145` |
| 2 | 差分测试足以守住模型正确性 | **两侧同错抓不到**。4 处残差一起写错，25 条差分断言全绿，argmax 已从 36 变成 44 | `_lab/tests/test_invariants.py:43` |

第 5 条还带一个尾巴：改成派生式随机之后，我用了 Python 内置的 `hash()`。
**它对字符串是逐进程加盐的**，于是"同 seed ⇒ 同轨迹"只在单次进程内成立，
换个进程就变了。换成 `zlib.crc32` 才真正确定（`_lab/structured.py:190` 的 docstring 记了这条）。

隔壁研究库还有两条同类的，一并记在这里当参照：
建模 vLLM 的块淘汰时把它当成"插入序 FIFO"，得出"SGLang 领先 8.72 个百分点"的假结论
（真相是 vLLM 的 `touch()` 让命中块离开空闲队列，实际是**近期使用序**，
修正后 vLLM 反而略高）；以及调度模拟只跑一个随机种子，
p90 在 58 个样本上的标准差约等于均值的一半，差点发表一个"非单调"的假发现。

**这八条的共同点**：错的不是代码，是**我对代码应该产出什么的预期**。
而抓住它们的，无一例外是"先算出应该是多少，再去对"这个动作。

### 6.2 五条测试反模式

1. **用弱判据测强命题。** 拿"生成的文本读起来正常"验投机解码 ——
   错误实现的文本也正常。**这类 bug 只有统计检验能发现。**
2. **只写正向断言。** "位置编码起作用了"没法用正向断言表达，
   只能用反向断言：**换了顺序结果必须变**（`_lab/tests/test_invariants.py:131`）。
3. **断言从来没失败过，也没人验证过它会失败。**
   本库的对策是给关键断言配一个**故意写错的实现**当反例。
   一条从未见过红灯的断言，和一条 `assert True` 是同一个东西。
4. **用相等测浮点。** 分块、批组成、后端切换都会改变求和顺序，
   **最后几位不同是正常的**。用容差；同时**不要把容差调到大得能盖住真 bug**。
   本库统一用 `atol=1e-4`（fp32、小模型下比数值噪声大两个量级，比任何逻辑错误小）。
5. **只测稳态，不测边界。** 块耗尽、合法集合为空、prompt 超长、
   客户端中途断开 —— 这些路径**恰恰是最容易静默出错**的地方，
   因为它们平时不走。本库把它们逐条写成了断言。

### 6.3 一条给读者的操作建议

如果你在给自己的引擎补测试，**顺序建议是**：

1. 先建**参照实现**（最朴素、最慢、最容易看懂的那个），并让它成为唯一真理；
2. 每加一个优化，立刻加一条"它不改变输出"的差分断言；
3. **再补一层退化情形与结构不变量**，防两侧同错；
4. 边界路径（资源耗尽、非法输入、中途取消）每条都要有断言，
   而且断言的内容是"**明确报错**"，不是"能跑过去"；
5. 每条关键断言配一个反例，确认它真的会红。
