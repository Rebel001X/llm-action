## 0. 一句话锚点

Transformer 每一层的计算本质上是几个**大矩阵乘法** $Y = XW$。当权重矩阵 $W$ 大到一张卡的显存装不下、或单卡算力跟不上延迟要求时，我们把 $W$ **沿某一个维度切成 $N$ 份**，第 $i$ 张卡只存第 $i$ 份权重、只算第 $i$ 份结果，最后用一次 **AllReduce / AllGather** 把 $N$ 张卡的部分结果合并。切权重的列还是行，决定了"合并"用哪种通信原语——这是 TP 的全部秘密。

## 1. 地基：为什么单卡放不下，TP 解决的是哪个问题

### 1.1 推理时显存花在哪

一次推理，GPU 显存主要被三块吃掉：

```
+------------------------------------------------------+
|  GPU 显存 (例如 A100 80GB)                            |
|  +--------------------+  +----------------+  +------+ |
|  |  模型权重 (静态)    |  |  KV Cache(动态) |  |激活 | |
|  |  ~ 2 * P 字节(fp16)|  |  随 seq/batch 长 |  |临时 | |
|  +--------------------+  +----------------+  +------+ |
+------------------------------------------------------+
```

- **权重**：参数量 $P$，fp16 下每个参数 2 字节，占 $2P$ 字节。
- **KV Cache**：每个 token 每层要缓存 K、V 两个向量，随序列长度和并发 batch 线性增长。
- **激活**：前向过程中的临时张量。

**为什么 TP 主要为了"权重放不下 + 算得慢"**：一个 70B 模型 fp16 权重就要 $2 \times 70 \times 10^9 = 140$ GB，单张 80GB 卡根本装不下。即使装得下(如 13B 约 26GB)，单卡算 prefill 也可能慢到不可接受。TP 让 **每张卡只存 $1/N$ 的权重、只算 $1/N$ 的矩阵乘**，同时缩小权重显存、缩短计算时间。

> 注意：TP 切的是"层内"的权重。另一种切法是把不同层放到不同卡(流水线并行 PP)，那是切"层间"。两者正交，见第 7 节。

### 1.2 为什么不只用更小的数据类型

量化(int8/int4)能压权重，但有精度损失上限；当模型本身就远超单卡，且要保 fp16/bf16 精度时，**必须靠多卡切分**。TP 是"把一个数学运算拆到多卡"的并行手段，量化是"压缩单个数"的正交手段，二者常叠加使用。

## 2. TP 的最小单位：一个矩阵乘怎么切

所有 TP 都建立在一个事实上：**矩阵乘法可以沿不同维度拆分而结果不变**。设输入 $X$ 形状 $[s, h]$($s$=token 数，$h$=隐藏维)，权重 $W$ 形状 $[h, o]$，输出 $Y = XW$ 形状 $[s, o]$。

### 2.1 列切(Column Parallel)：切输出维 $o$

把 $W$ 沿**列**(输出维 $o$)切成 $N$ 块：$W = [W_1 | W_2 | \dots | W_N]$，每块 $[h, o/N]$。每张卡拿完整的 $X$、自己的 $W_i$：

$$Y_i = X W_i,\quad Y = [Y_1 | Y_2 | \dots | Y_N]$$

```
列切：X 完整复制到每卡，W 按列切
   X[s,h]            W=[ W1 | W2 ]        Y=[ Y1 | Y2 ]
  ┌──────┐          ┌───┬───┐           ┌────┬────┐
  │      │   ×      │   │   │     =     │ Y1 │ Y2 │
  │ 全量 │          │W1 │W2 │           │卡0 │卡1 │
  └──────┘          └───┴───┘           └────┴────┘
   每卡都有          每卡存一列块         每卡得一列块(部分输出)
```

- **每卡输出**：$Y_i$ 是最终结果的**一部分列**，是"完整且正确的一块"，不需要相加。
- **合并方式**：若下游需要完整 $Y$，用 **AllGather** 把各列块拼起来；但若紧接着是一个行切矩阵乘，则**不用立刻合并**(见 2.2)。

### 2.2 行切(Row Parallel)：切输入维 $h$

把 $W$ 沿**行**(输入维 $h$)切成 $N$ 块：$W = [W_1; W_2; \dots; W_N]^{\text{(按行堆叠)}}$，每块 $[h/N, o]$。此时输入 $X$ 也要沿**列**切成 $X = [X_1 | X_2 | \dots | X_N]$，每块 $[s, h/N]$。每张卡算：

$$Y_i^{\text{partial}} = X_i W_i \quad(\text{形状 } [s, o])$$

每张卡都得到一个**完整形状但只算了一部分贡献**的 $Y$。根据分块矩阵乘法：

$$Y = X W = \sum_{i=1}^{N} X_i W_i = \sum_i Y_i^{\text{partial}}$$

```
行切：X 按列切，W 按行切，各卡得"部分和"，需相加
   X=[ X1 | X2 ]      W=[ W1 ]          Y_partial(卡i) , 求和=Y
  ┌────┬────┐        ┌──────┐ 卡0       ┌────────┐
  │ X1 │ X2 │   ×    │  W1  │      =    │ X1·W1  │ ← 卡0部分和
  └────┴────┘        ├──────┤ 卡1       │ X2·W2  │ ← 卡1部分和
   卡0   卡1          │  W2  │          └────────┘
                     └──────┘            AllReduce 求和 → Y
```

- **每卡输出**：是完整尺寸 $[s,o]$ 的**部分和**，必须把各卡相加才正确。
- **合并方式**：用 **AllReduce(sum)**。

### 2.3 关键设计：列切 + 行切配对，省掉中间通信

Megatron-LM 的精髓：把两个连续矩阵乘安排成**先列切、后行切**，中间不通信。

```
 列切MM(输出A按列分散在各卡) → 逐元素操作(GeLU等) → 行切MM → AllReduce
   每卡: A_i = X W1_i                      每卡: Y_i = A_i W2_i
   A_i 天然是行切MM需要的"X按列切"输入 ──┘   各卡求和才得 Y
```

列切的输出 $A_i$($[s, d/N]$)恰好就是行切矩阵乘所需的"$X$ 按列切"的输入！于是一对矩阵乘**只在最后做一次 AllReduce**，中间的逐元素激活(GeLU、ReLU)对每个元素独立，切了也不影响。这是 TP 把通信压到最少的核心技巧。

## 3. FFN(MLP) 块的 TP 切法

FFN 是 $Y = \text{GeLU}(X W_1) W_2$，其中 $W_1\in[h, 4h]$ 升维、$W_2\in[4h, h]$ 降维(经典 4 倍)。

```
        X[s,h]
          │ 复制到所有卡
   ┌──────┴───────┐
 卡0: W1 列切块     卡1: W1 列切块      ← W1[h,4h] 按列切 → 每卡[h,2h]
 A0=GeLU(X·W1_0)   A1=GeLU(X·W1_1)    ← GeLU 逐元素，安全
   │                 │
 卡0: W2 行切块     卡1: W2 行切块      ← W2[4h,h] 按行切 → 每卡[2h,h]
 Y0=A0·W2_0        Y1=A1·W2_1         ← 各卡得部分和[s,h]
   └────── AllReduce(sum) ───────┘    ← 唯一一次通信
              Y[s,h] 完整
```

- $W_1$ **列切**：每卡存 $[h, 4h/N]$，输出 $A_i$ 是中间激活的一段。
- 中间 GeLU 逐元素，切了无所谓。
- $W_2$ **行切**：每卡存 $[4h/N, h]$，输出部分和。
- 整个 FFN：**前向 1 次 AllReduce**(推理时反向不存在，只 1 次)。

## 4. 注意力(Attention)块的 TP 切法

多头注意力天然适合 TP：**不同的 head 之间计算完全独立**，所以按 head 分到各卡。

设 $a$ 个 head，每 head 维度 $d_k = h/a$。$Q=XW_Q$、$K=XW_K$、$V=XW_V$，每个 $W_\bullet\in[h,h]$；注意力后 $O=\text{Attn}\cdot W_O$，$W_O\in[h,h]$。

```
        X[s,h] 复制到所有卡
   ┌──────────┴───────────┐
 卡0: W_Q,W_K,W_V 列切      卡1: W_Q,W_K,W_V 列切    ← 每卡负责 a/N 个 head
 算 head 0..a/N-1          算 head a/N..a-1
   ↓ 各自做 softmax(QKᵀ/√dk)V  (head 内部完整，无需跨卡)
 卡0: head 子集的 attn 输出  卡1: head 子集的 attn 输出
   ↓ W_O 行切               ↓ W_O 行切              ← O[h,h]按行切
 卡0部分和 O0[s,h]          卡1部分和 O1[s,h]
   └────── AllReduce(sum) ──────┘                 ← 唯一一次通信
                O[s,h] 完整
```

- $W_Q, W_K, W_V$ **按列切**(等价按 head 切)：每卡拿 $a/N$ 个 head 的投影权重，形状 $[h, h/N]$。
- **注意力计算 head 内自洽**：每个 head 的 $\text{softmax}(QK^\top/\sqrt{d_k})V$ 只用该 head 自己的 Q/K/V，不跨卡，所以可以完整在一张卡上算完——这是 attention 适合 TP 的根本原因。
- $W_O$ **按行切**：每卡 $[h/N, h]$，输出部分和。
- 整个 Attention：**前向 1 次 AllReduce**。

> 约束：head 数 $a$ 必须能被 TP 度 $N$ 整除。GQA/MQA 下 KV head 更少，KV 投影的切分要单独考虑(KV head 数也要能被 $N$ 整除，或在卡间复制 KV)。

**所以一个 Transformer 层(Attn + FFN)前向只需要 2 次 AllReduce。**

## 5. 通信量到底有多大

每次 AllReduce 传输的数据，就是被规约的张量大小。设：批内 token 总数 $T = b \cdot s$、隐藏维 $h$、数据类型 fp16(2 字节)。

每次 AllReduce 的张量是 $[T, h]$，字节数：

$$V = T \cdot h \cdot 2 \ \text{字节}$$

Ring-AllReduce 实际跨链路传输量约为 $2V \cdot \frac{N-1}{N}$(每卡发送+接收)。一层有 2 次(Attn+FFN)，$L$ 层共 $2L$ 次。

**直觉**：通信量 $\propto T \cdot h$，与 TP 度 $N$ 几乎无关(只差 $\frac{N-1}{N}$ 系数)；而单卡计算量 $\propto 1/N$。所以 **TP 度越大，通信/计算比越高**，必须用高带宽互联(NVLink/NVSwitch)才划算——这就是为什么 TP 通常只在**单机内**(8 卡)做，跨机用 PP/DP。手算见第 9 节。

> 关键工程结论：TP 的瓶颈是 AllReduce 延迟，尤其 decode 阶段每生成 1 个 token 都要做 $2L$ 次小张量 AllReduce，**延迟敏感**。延迟主导时，NVLink 远好于 PCIe / 跨机 RoCE。

## 6. 那些"不是大矩阵乘"的部分怎么办

| 组件 | 处理方式 | 原因 |
|---|---|---|
| 词嵌入 Embedding | 按词表维切分(Vocab Parallel)，查表后 AllReduce | 词表 $V$ 很大，切了省显存；本卡没有的词输出 0，求和补齐 |
| LM Head(输出投影) | 按词表列切，算 logits 后视情况 AllGather；softmax/采样常配合并行 | 词表维大，可与 Embedding 共享切分 |
| LayerNorm / RMSNorm | **每卡复制完整**，各自算 | 参数极小($h$ 量级)，复制比通信便宜 |
| 残差连接 | 在 AllReduce 之后做，每卡持有完整结果再相加 | 保证每卡残差一致 |
| Dropout(推理一般关) | 推理时无 | — |

要点：**只有"大矩阵乘"值得切，小参数(LayerNorm)直接复制**。复制的代价是一点点冗余显存，换来零通信，划算。

## 7. TP 与 PP / DP / EP 的组合(多维并行)

单一并行常不够，大规模部署组合使用。各维度是正交的"切法"：

| 并行 | 切什么 | 通信 | 通信域大小 | 典型位置 |
|---|---|---|---|---|
| **TP** 张量 | 层内权重(矩阵乘) | 每层 2 次 AllReduce | 小(单机 8 卡) | 机内 NVLink |
| **PP** 流水线 | 层(不同层放不同卡) | 相邻 stage 间 P2P 传激活 | 点对点 | 跨机也可 |
| **DP** 数据 | batch(每副本一份完整模型) | 梯度 AllReduce(推理无) | 大 | 推理用于扩并发 |
| **EP** 专家 | MoE 的专家(不同 expert 放不同卡) | token 路由 All-to-All | 中 | MoE 层 |

```
3D 并行典型布局 (TP×PP×DP):  通信成本: TP > PP > DP (域内带宽要求)
┌──────────────── 数据并行 DP 复制 N_dp 份 ───────────────┐
│  ┌── 流水线 PP: layer0-7 │ layer8-15 │ layer16-23 ──┐  │
│  │   stage0          stage1         stage2          │  │
│  │  ┌TP: 8卡切每层┐  ┌TP: 8卡┐    ┌TP: 8卡┐         │  │
│  │  │g0 g1 ...  g7│  │ ...   │    │ ...   │         │  │
│  └──┴─────────────┴──┴───────┴────┴───────┴─────────┘  │
└─────────────────────────────────────────────────────────┘
原则: TP 放最内层(占满机内NVLink)，PP 跨机(只传激活,通信小)，DP 最外层
```

**与 EP 组合(MoE 推理)**：MoE 层把专家分到不同卡(EP)，非专家部分(Attention)仍用 TP。token 经 All-to-All 路由到对应专家卡。常见 `TP × EP`：注意力 TP 切、FFN 用 EP 切，是当前大 MoE 推理(如 DeepSeek 类)的主力布局。

**为什么 TP 放最内层**：TP 通信最频繁、张量最大、延迟最敏感，必须吃满机内 NVLink；PP 只在 stage 边界传一次激活，通信稀疏，适合跨机；DP 在推理里主要用来"复制整套模型扩并发"，副本间几乎不通信。

## 8. 推理 TP 与训练 TP 的差异

| 维度 | 训练 TP | 推理 TP |
|---|---|---|
| 反向传播 | 有，前向 AllReduce + 反向 AllReduce(每层共 4 次 $f/g$ 算子) | **无反向**，每层只 2 次 AllReduce |
| 计算特征 | 大 batch、长序列，算力受限 | prefill 算力受限 / decode **访存+通信受限** |
| 阶段 | 单一前向+反向 | **prefill(并行算全提示) 与 decode(逐 token) 两阶段** |
| KV Cache | 不长期保留 | 需驻留并随 TP 切分(每卡存自己 head 的 KV) |
| 通信容忍度 | 可被大计算掩盖 | decode 张量极小($T{=}1$)，AllReduce 延迟难掩盖，**更怕慢互联** |
| 优化器状态 | 需切分(配合 ZeRO 等) | 无优化器状态，显存只剩权重+KV+激活 |

**最重要的一点**：decode 阶段每步只处理 1 个新 token，$T=1$，AllReduce 的张量只有 $h \cdot 2$ 字节(几 KB),纯粹被**网络延迟**而非带宽支配。于是 TP 度越大、decode 单 token 延迟里通信占比越高。这就是为什么推理里 TP 度不会无脑往大开，且常配合 [[llm-inference/分离式推理架构]] 把 prefill(吃算力，TP 友好)和 decode(吃延迟)拆到不同资源池分别优化。

**KV Cache 随 TP 自动切分**：因为每卡只负责 $a/N$ 个 head，它也只缓存这些 head 的 K、V。所以 TP 不仅切权重，还把 KV Cache 显存也切成 $1/N$——这对长上下文推理是巨大收益。

## 9. 逐数手算：一个矩阵乘 TP 切分(全程小数字)

**设定**：FFN 第一层 $W_1$，隐藏维 $h = 8$，升维到 $4h = 32$，batch 内 token 数 $T = 2$，fp16(2 字节)，TP 度 $N = 4$。

### 9.1 形状与权重显存

- $X$ 形状 $[T, h] = [2, 8]$。
- $W_1$ 形状 $[h, 4h] = [8, 32]$，共 $8 \times 32 = 256$ 个参数。
- 单卡 fp16 权重显存 = $256 \times 2 = 512$ 字节。
- **列切到 4 卡**：每卡 $W_{1,i}$ 形状 $[8, 32/4] = [8, 8]$，参数 $8\times8=64$ 个，显存 $64 \times 2 = 128$ 字节 = 单卡的 $1/4$。✓ 切权重确实省 $1/N$ 显存。

### 9.2 计算量(FLOPs)

矩阵乘 $[T,h]\times[h,o]$ 的乘加 FLOPs $\approx 2 \cdot T \cdot h \cdot o$(每个输出元素 $h$ 次乘 + $h$ 次加)。

- 单卡(不切)：$2 \times 2 \times 8 \times 32 = 1024$ FLOPs。
- 每卡(列切，$o=8$)：$2 \times 2 \times 8 \times 8 = 256$ FLOPs = 总量 $1/4$。✓ 算力也摊薄到 $1/N$。

### 9.3 配上行切 $W_2$，算通信量

接 $W_2$ 形状 $[4h, h] = [32, 8]$，行切到每卡 $[8, 8]$。每卡算出部分和 $Y_i$ 形状 $[T, h] = [2, 8]$。

- 需 AllReduce 的张量 $= [2, 8]$，共 $16$ 个 fp16 数 $= 16 \times 2 = 32$ 字节。
- Ring-AllReduce 实际跨链路传输 $\approx 2 \times 32 \times \frac{N-1}{N} = 2\times32\times\frac{3}{4} = 48$ 字节(每卡收发合计)。
- **对比**：单卡省下的计算量是 $3/4$(从 1024 降到 256)，代价仅 48 字节通信。token 越多、$h$ 越大，这个"省计算 vs 付通信"的杠杆越划算。

### 9.4 一个具体数值验证"分块相加 = 整体"

取最小子例：$h=2$、$o=1$、$T=1$，行切 $N=2$。
$X = [3, 4]$，$W = \begin{bmatrix}2\\5\end{bmatrix}$。整体 $Y = 3\times2 + 4\times5 = 6 + 20 = 26$。

行切：卡0 拿 $X_0=[3]$、$W_0=[2]$ → 部分和 $3\times2=6$；卡1 拿 $X_1=[4]$、$W_1=[5]$ → 部分和 $4\times5=20$。
AllReduce(sum)：$6 + 20 = 26$。✓ 与整体完全一致——**这就是行切必须 AllReduce 的数学根据**。

### 9.5 把账放大到真实规模(70B, TP=8, decode)

- $h = 8192$，fp16，decode 时 $T=1$。
- 每次 AllReduce 张量 $= 1 \times 8192 \times 2 = 16384$ 字节 $\approx 16$ KB。
- 每层 2 次、设 $L=80$ 层 → 每生成 1 token 共 $160$ 次 AllReduce，总传输 $\approx 160 \times 16\text{KB} \times 2\times\frac{7}{8} \approx 4.5$ MB。
- NVLink(双向数百 GB/s 量级)传 4.5 MB 仅微秒级带宽时间，但 **160 次小消息的固定延迟累加**才是 decode 的真实痛点——印证第 8 节"decode 被延迟而非带宽支配"。

## 对照/复杂度表

| 维度 | 列切 Column Parallel | 行切 Row Parallel |
|---|---|---|
| 切 $W$ 的哪维 | 输出维(列) | 输入维(行) |
| 输入 $X$ | 完整复制到每卡 | 按列切 |
| 每卡输出 | 完整的一段列(正确块) | 完整尺寸的部分和 |
| 合并原语 | AllGather(若需完整) | AllReduce(sum) |
| 典型用处 | $W_1$、$W_Q/W_K/W_V$ | $W_2$、$W_O$ |
| 与谁配对 | 后接行切则免中间通信 | 接在列切之后 |

| 量 | 表达式 | 随 TP 度 $N$ |
|---|---|---|
| 单卡权重显存 | $2P/N$ | $\downarrow 1/N$ |
| 单卡计算量 | $\propto 1/N$ | $\downarrow 1/N$ |
| 单卡 KV Cache | $\propto 1/N$(按 head 切) | $\downarrow 1/N$ |
| 每次 AllReduce 字节 | $T \cdot h \cdot 2$ | 几乎不变 |
| 每层 AllReduce 次数(推理) | 2(Attn 1 + FFN 1) | 不变 |
| 通信/计算比 | $\uparrow$ | 随 $N$ 增大 |

## 常见问题

| 疑问 | 真相 |
|---|---|
| 列切之后一定要 AllGather 吗？ | 不。若紧接行切矩阵乘，列切输出正好是行切输入，中间不通信，最后一起 AllReduce。 |
| 为什么 attention 切 head 而不切别处？ | 不同 head 计算独立，head 内 softmax 自洽，切 head 不引入跨卡依赖，最自然。 |
| TP 度能随便设大吗？ | 不能。受 head 数整除约束 + 通信/计算比随 $N$ 升高，且 decode 延迟敏感，通常 $\le$ 单机卡数(如 8)。 |
| LayerNorm 也切吗？ | 不切，每卡复制。参数太小，复制零通信比切了再通信划算。 |
| 推理为何比训练每层少通信？ | 推理无反向，只前向；每层 2 次 AllReduce(训练前向+反向约 4 次)。 |
| TP 能省 KV Cache 吗？ | 能。每卡只存自己 head 的 KV，KV 显存降到 $1/N$，对长上下文极有价值。 |
| 为什么 TP 不爱跨机？ | AllReduce 频繁且 decode 张量极小，跨机延迟/带宽远不如 NVLink，通信会主导端到端延迟。 |
| TP 和量化冲突吗？ | 不冲突。量化压"单个数的位宽"，TP 切"运算到多卡"，正交，常叠加。 |
| MoE 推理 TP 还有用吗？ | 有。Attention 仍用 TP，专家用 EP，组合 `TP×EP` 是大 MoE 推理主流。 |
