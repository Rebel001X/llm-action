## 0. 一句话锚点

**TensorRT-LLM = 把 LLM 编译成一个针对你这块 GPU 量身定做的 TensorRT 引擎（`.engine`）。** 它不是"加载权重就能跑"的解释器（那是 vLLM/HF 的路子），而是一个**编译器**：先把模型图（attention、GEMM、KV-cache 管理）通过 plugin 融合、选择最优 kernel、做 FP16/FP8/INT8 量化，固化成一个二进制引擎，再用极薄的 runtime 执行。

> 一句话区别：vLLM 是"即装即用的解释器"，TensorRT-LLM 是"先编译后执行"。编译换来更低延迟，代价就是——**安装/编译这一步特别重**，这正是本文存在的原因。

```
       源码 + 权重                      面向单卡的二进制
   ┌──────────────────┐   build      ┌──────────────────┐  runtime  延迟更低
   │ HF model + .py    │ ───────────▶ │  XXX.engine       │ ────────▶  吞吐更高
   │ TensorRT-LLM 图   │  (本文最难)   │ (绑定 GPU 架构/精度)│           显存可控
   └──────────────────┘              └──────────────────┘
```

## 1. 地基：三层依赖，缺一层就编译失败

TensorRT-LLM 安装之所以难，是因为它**纵向压着三层强耦合的依赖**，每层版本都要对齐：

```
   ┌─────────────────────────────────────┐
   │  TensorRT-LLM (Python + C++ 本体)     │  ← scripts/build_wheel.py 编译
   ├─────────────────────────────────────┤
   │  TensorRT 9.1.0.4 (推理引擎/算子库)    │  ← 提供 plugin、kernel、量化
   ├─────────────────────────────────────┤
   │  CUDA 12.2 + cuDNN + PyTorch 2.1      │  ← 由 nvcr 镜像或源码提供
   ├─────────────────────────────────────┤
   │  NVIDIA Driver + GPU (SM 8.0/9.0)     │  ← 物理 GPU，Ampere/Hopper
   └─────────────────────────────────────┘
```

**为什么要对齐？** 三个高频版本约束：

- **`CUDA_VERSION="12.2"`**：TensorRT 的 tar 包是按 CUDA 小版本分别编译的（注意原文里还给了 cuda-12.1 和 cuda-12.2 两个下载链接），CUDA 12.1 的 TRT 包不能跑在 12.2 runtime 下，反之亦然。
- **`TORCH_CUDA_ARCH_LIST="8.0;9.0"`**：8.0 = Ampere（A100/A30），9.0 = Hopper（H100/H800）。这是 GPU 的 **Compute Capability（SM 架构号）**，编译时要为这些架构生成 PTX/SASS，否则你的卡跑不了。详见 [[ai-infra/算力/GPU工作原理]]、[[ai-infra/ai-hardware/硬件对比]]。
- **`_GLIBCXX_USE_CXX11_ABI`**：C++ ABI 标志，TensorRT-LLM 的 C++ 部分、TensorRT 库、和自编译的 PyTorch **三者 ABI 必须一致**，否则链接期符号对不上（见第 5 节）。

> 数值直觉：SM 8.0 的 `8.0` 写成 `TORCH_CUDA_ARCH_LIST` 里的 `8.0`；卡是 H100（Hopper, SM90）就必须含 `9.0`，否则引擎 build 出来在 H100 上启动直接报 "no kernel image"。

## 2. 基础镜像：为什么从 nvcr.io/nvidia/pytorch 起步

原文给定基础镜像：

```
基于镜像：nvcr.io/nvidia/pytorch:23.10-py3
```

**为什么用 NGC 的 pytorch 镜像而不是 ubuntu 裸镜像？** 因为它**预装好了 CUDA toolkit、cuDNN、NCCL、cuBLAS 和一个调过的 PyTorch**——这正好是地基的下两层。从裸 ubuntu 装 CUDA + cuDNN + NCCL 极易踩版本坑，NGC 镜像把这层一次性给齐。

但镜像自带的 TensorRT 是**旧版/不匹配**的，所以第一件事是卸载它，让位给我们要的 9.1.0.4：

```bash
# 卸载镜像中原来的 tensorrt（避免与即将安装的 9.1.0.4 冲突）
pip uninstall -y tensorrt
pip install mpi4py        # MPI 绑定：多卡 tensor/pipeline 并行通信要用
```

> `mpi4py` 为什么装在这一步？TensorRT-LLM 的多卡推理走 MPI 启动多进程（每卡一个 rank），底层依赖 [[ai-infra/网络/集合通信原语]]（all-reduce 等）。单卡也建议装好，免得后面跑多卡 demo 时缺包。

> 注意：原文后面的 `docker run` 示例用的是 `23.05-py3`，而顶部声明的是 `23.10-py3`。这是仓库作者在不同实验里用过的两个 tag，**镜像 tag 决定了内置 CUDA 版本**，换 tag 时要回头核对 TensorRT 的 `CUDA_VERSION` 是否还匹配。

## 3. 安装 CMake 3.24.4：为什么不用系统自带的

TensorRT-LLM 的 C++ 部分用 CMake 构建，且**要求较新的 CMake**（apt 源里的往往太旧，配置期就报 "CMake X.Y or higher is required"）。所以手动下官方 release：

```bash
ARCH=$(uname -m)                       # x86_64 或 aarch64，决定下载哪个包
CMAKE_VERSION="3.24.4"

PARSED_CMAKE_VERSION=$(echo $CMAKE_VERSION | sed 's/\.[0-9]*$//')   # 3.24.4 -> 3.24
CMAKE_FILE_NAME="cmake-${CMAKE_VERSION}-linux-${ARCH}"
RELEASE_URL_CMAKE=https://github.com/Kitware/CMake/releases/download/v${CMAKE_VERSION}/${CMAKE_FILE_NAME}.tar.gz
wget --no-verbose ${RELEASE_URL_CMAKE} -P /tmp
tar -xf /tmp/${CMAKE_FILE_NAME}.tar.gz -C /usr/local/
ln -s /usr/local/${CMAKE_FILE_NAME} /usr/local/cmake     # 软链到稳定路径，PATH 只认 /usr/local/cmake

echo 'export PATH=/usr/local/cmake/bin:$PATH' >> "${BASH_ENV}"   # 让 cmake 进 PATH
```

逐行原理：

```
uname -m ─▶ ARCH ─┐
                  ├─▶ 拼出官方下载 URL ─▶ wget ─▶ tar 解到 /usr/local
CMAKE_VERSION ────┘                                  │
                                                     ▼
                              ln -s ... /usr/local/cmake   ← 软链让升级时只改链接
                                                     │
                            export PATH=.../cmake/bin ◀┘   ← 优先于系统旧 cmake
```

- **`ln -s` 软链的意义**：把带版本号的真实目录映射到固定名 `/usr/local/cmake`。以后换 CMake 版本只改这条链接，PATH 配置不动。
- **`${BASH_ENV}`**：非交互式 shell（如 docker build 的 `RUN`）读取的环境文件，写进去保证后续构建步骤都能找到新 cmake。

## 4. 安装 TensorRT 9.1.0.4：推理引擎后端本体

这是地基的核心层。TensorRT 提供算子库、plugin、量化 kernel——[[llm-optimizer/FlashAttention]] 在这里以 fused MHA plugin 的形式出现，[[llm-optimizer/kv-cache]] 的分页管理也由 runtime 负责。

```bash
TENSOR_RT_VERSION="9.1.0.4"
CUDA_VERSION="12.2"

PY_VERSION=$(python -c 'import sys; print(".".join(map(str, sys.version_info[0:2])))')   # 3.10
PARSED_PY_VERSION=$(echo "${PY_VERSION//./}")     # 3.10 -> 310，用于匹配 cp310 的 whl

if [ -z "$RELEASE_URL_TRT" ];then
    ARCH=${TRT_TARGETARCH}
    if [ -z "$ARCH" ];then ARCH=$(uname -m);fi
    if [ "$ARCH" = "arm64" ];then ARCH="aarch64";fi          # 归一化架构名
    if [ "$ARCH" = "amd64" ];then ARCH="x86_64";fi
    if [ "$ARCH" = "x86_64" ];then DIR_NAME="x64-agnostic"; else DIR_NAME=${ARCH};fi
    if [ "$ARCH" = "aarch64" ];then OS="ubuntu-22.04"; else OS="linux";fi
    RELEASE_URL_TRT=https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/secure/9.1.0/tars/tensorrt-${TENSOR_RT_VERSION}.${OS}.${ARCH}-gnu.cuda-${CUDA_VERSION}.tar.gz;
fi
wget --no-verbose ${RELEASE_URL_TRT} -O /tmp/TensorRT.tar
tar -xf /tmp/TensorRT.tar -C /usr/local/
mv /usr/local/TensorRT-${TENSOR_RT_VERSION} /usr/local/tensorrt          # 软固定到无版本号路径
pip install /usr/local/tensorrt/python/tensorrt-*-cp${PARSED_PY_VERSION}-*.whl   # 装 Python 绑定
rm -rf /tmp/TensorRT.tar
```

装完必须把动态库目录加入链接路径，否则 `import tensorrt` 时找不到 `.so`：

```dockerfile
ENV LD_LIBRARY_PATH=/usr/local/tensorrt/lib:${LD_LIBRARY_PATH}
```

机制图——一个 TRT tar 包里有什么：

```
 tensorrt-9.1.0.4.linux.x86_64-gnu.cuda-12.2.tar.gz
 ├── lib/        *.so          ← C++ 运行库，必须进 LD_LIBRARY_PATH
 ├── include/    *.h           ← 编译 TensorRT-LLM C++ 时要 include
 └── python/     tensorrt-*-cp310-*.whl   ← Python 绑定，pip 装它
              ▲
              └ cp310 必须匹配解释器，所以前面要 PARSED_PY_VERSION
```

**为什么 cp 标签要匹配？** Python 的 wheel 文件名里 `cp310` 表示"为 CPython 3.10 编译"。装错（如 cp39 的 whl 装到 3.10 解释器）会直接 "not a supported wheel"。脚本用 `PARSED_PY_VERSION` 动态拼出 `cp310` 通配，正是为了自适应。

原文同时记录了两个**真实可用的官方下载直链**（按 CUDA 小版本区分）：

```
# CUDA 12.1 版本
https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/secure/9.1.0/tars/tensorrt-9.1.0.4.linux.x86_64-gnu.cuda-12.1.tar.gz
# CUDA 12.2 版本
https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/secure/9.1.0/tars/tensorrt-9.1.0.4.linux.x86_64-gnu.cuda-12.2.tar.gz
# Polygraphy
https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/secure/9.0.1/tars/polygraphy-0.48.1-py2.py3-none-any.whl
```

## 5. Polygraphy 与 PyTorch：调试工具 + ABI 对齐

### 5.1 Polygraphy（TensorRT 官方调试/验证工具）

```bash
RELEASE_URL_PG=https://developer.nvidia.com/downloads/compute/machine-learning/tensorrt/secure/9.0.1/tars/polygraphy-0.48.1-py2.py3-none-any.whl
pip uninstall -y polygraphy        # 先卸镜像自带的旧版
pip install ${RELEASE_URL_PG}
```

> Polygraphy 是 NVIDIA 提供的"引擎体检工具"：可对比 TensorRT 引擎与原始框架（PyTorch/ONNX）的逐层输出、定位精度漂移。量化（[[llm-compression/quantization/量化基础]]、[[llm-compression/quantization/fp8]]）出问题时，用它逐层比对找出是哪一层的 FP8/INT8 误差超标。

### 5.2 PyTorch 2.1：两条路，注意 ABI

原文给了**两种安装方式**，关键差异在 C++ ABI：

```dockerfile
ARG TORCH_INSTALL_TYPE="skip"     # 默认 skip：直接用镜像自带 torch
```

**方式 A：源码编译（需要控制 ABI 时用）**

```bash
export _GLIBCXX_USE_CXX11_ABI=$1          # ★ ABI 开关，必须与 TensorRT-LLM C++ 一致
export TORCH_CUDA_ARCH_LIST="8.0;9.0"     # ★ 只为 Ampere(8.0)/Hopper(9.0) 编译，省时间

pip uninstall -y torch
cd /tmp
git clone --depth 1 --branch v$TORCH_VERSION https://github.com/pytorch/pytorch
cd pytorch
git submodule sync && git submodule update --init --recursive
pip install -r requirements.txt
python setup.py install
cd /tmp && rm -rf /tmp/pytorch
```

**方式 B：直接 pip 装预编译轮子（图省事）**

```bash
TORCH_VERSION="2.1.0"
pip install torch==${TORCH_VERSION}
```

**为什么要源码编译 PyTorch？** 因为 C++11 ABI 不兼容问题：

```
   _GLIBCXX_USE_CXX11_ABI 必须三方一致
   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
   │ TensorRT-LLM  │ = │  TensorRT lib │ = │   PyTorch     │
   │  C++ 本体     │   │  (.so)        │   │   libtorch    │
   └──────────────┘   └──────────────┘   └──────────────┘
       ABI=0 ✗ 混搭 ABI=1  ─▶  链接期 undefined symbol / std::string 符号对不上
```

预编译 torch（方式 B）的 ABI 是 PyTorch 官方固定的；如果 TensorRT-LLM 的 C++ 端用了相反 ABI，链接就崩。这时只能源码编译 torch，用 `_GLIBCXX_USE_CXX11_ABI` 强制对齐。`TORCH_CUDA_ARCH_LIST="8.0;9.0"` 则把编译目标限定到目标 GPU，避免为所有架构编译（否则编译时间翻几倍）。PyTorch / Megatron 等训练侧依赖见 [[ai-framework/pytorch/README]]、[[ai-framework/megatron-lm/README]]、[[ai-framework/deepspeed/README]]。

> C++ 测试还依赖 googletest（原文记录了 v0.5.0 的 `cpp/tests/CMakeLists.txt` 引用 `https://github.com/google/googletest`），由 submodule 拉取，所以下一节强调 `git submodule update --init --recursive`。

## 6. 拉源码并 build wheel：编译 TensorRT-LLM 本体

地基齐了，开始编译本体。第一步拉全代码（含 submodule 与大文件）：

```bash
git clone https://github.com/NVIDIA/TensorRT-LLM.git
cd TensorRT-LLM
git submodule update --init --recursive    # ★ 必须！cutlass/googletest 等子模块
git lfs install
git lfs pull                                # ★ 拉 LFS 大文件（测试权重等），漏了会编译失败

docker pull nvcr.io/nvidia/pytorch:23.10-py3
```

> **为什么 submodule 和 lfs 都不能漏？** TensorRT-LLM 的高性能 GEMM 依赖 NVIDIA **CUTLASS**（以 git submodule 形式存在），漏拉 submodule 则 CMake 配置期就找不到 CUTLASS 头文件；而 `.engine`、测试权重等二进制走 **Git LFS**，漏 `git lfs pull` 会得到只有指针的占位文件，编译/测试随即报错。

进入容器后安装匹配的 transformers（注意版本钉死 4.31.0，并走清华源加速）：

```bash
apt-get update && apt-get -y install git git-lfs
mkdir -p /workspace/local/tensorrt

# 编译生成 wheel，--trt_root 指向第 4 节装好的 TensorRT
python3 ./scripts/build_wheel.py --trt_root /workspace/local/tensorrt
```

build_wheel 流程图：

```
 scripts/build_wheel.py --trt_root <TensorRT 路径>
        │
        ├─ 1) CMake configure  ── 用第 3 节的 cmake，找 TensorRT(第4节)/CUTLASS(submodule)
        ├─ 2) 编译 C++ runtime + plugin  ── 这里吃 ABI 一致性(第5节)
        ├─ 3) 编 Python 绑定
        └─ 4) 打包 ──▶ tensorrt_llm-*.whl  ◀ 最终产物，pip install 它即可用
```

> `--trt_root` 告诉构建脚本"TensorRT 头文件和库在哪"。如果第 4 节把 TRT 解到了 `/usr/local/tensorrt`，这里就该指向那个目录（原文用 `/workspace/local/tensorrt` 作示例路径，按你实际解压位置改）。

## 实操：可复用启动脚本（保留原文全部真料）

### 容器启动（原文 docker run，逐参数已注释）

```bash
docker rm -f tensorrt_llm        # 先删同名旧容器，幂等

docker run -dt --name tensorrt_llm \
  --restart=always \             # 宿主重启自动拉起
  --gpus all \                   # ★ 暴露所有 GPU 进容器
  --network=host \               # 用宿主网络，省去端口映射；多机 NCCL/MPI 直连
  --shm-size=4g \                # ★ 共享内存，PyTorch DataLoader / NCCL 要用，太小会 bus error
  -m 64G \                       # 容器内存上限 64G
  -v /home/gdong:/workspace \    # 挂载宿主目录到 /workspace
  -w /workspace \                # 工作目录
  nvcr.io/nvidia/pytorch:23.05-py3 \
  /bin/bash

docker exec -it tensorrt_llm bash   # 进入容器交互

# 装 transformers（钉死版本 + 清华源加速）
pip install transformers==4.31.0 -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
# 网络抖动时关进度条更稳
pip install transformers==4.31.0 --progress-bar off -i https://pypi.tuna.tsinghua.edu.cn/simple --trusted-host pypi.tuna.tsinghua.edu.cn
```

**几个 `docker run` 关键参数为什么这么设：**

| 参数 | 作用 | 不设的后果 |
| --- | --- | --- |
| `--gpus all` | 把 GPU 设备透传进容器 | 容器里 `nvidia-smi` 看不到卡，CUDA 不可用 |
| `--shm-size=4g` | 扩大 `/dev/shm` 共享内存 | NCCL/多进程通信报 "bus error" 或卡死 |
| `--network=host` | 容器直用宿主网卡 | 多机走 [[ai-infra/网络/InfiniBand]] 时端口/RDMA 受限 |
| `--restart=always` | 容器异常退出自动重启 | 宿主重启后服务不自动恢复 |
| `-v /home/gdong:/workspace` | 持久化代码/权重 | 容器删除即丢数据 |

### 完整命令清单（按顺序）

```bash

```

## 常见问题/坑

| 现象 / 报错 | 根因 | 解决（原文真料 + 解释） |
| --- | --- | --- |
| `RuntimeError: can't start new thread` | 旧 docker 镜像线程/进程数限制；nproc 受限 | **更新 docker 镜像**（原文方案）；必要时调宿主 `ulimit -u` / `--pids-limit` |
| apt 装包后被自动清缓存导致中途失败 | NGC 镜像的 `docker-clean` 钩子会删 apt 缓存 | 禁用清理钩子：`sed -i -e 's/^APT/# APT/' -e 's/^DPkg/# DPkg/' /etc/apt/apt.conf.d/docker-clean` |
| `import tensorrt` 找不到 .so | 没设 `LD_LIBRARY_PATH` | `export LD_LIBRARY_PATH=/usr/local/tensorrt/lib:$LD_LIBRARY_PATH` |
| `not a supported wheel` | TRT/torch 的 cp 标签与解释器 Python 版本不符 | 用 `PARSED_PY_VERSION` 自动匹配 `cp310` |
| 链接期 `undefined symbol`（std::string 等） | `_GLIBCXX_USE_CXX11_ABI` 三方不一致 | 源码编译 torch 并对齐 ABI（见 5.2） |
| CMake 配置报版本过低 | 系统自带 cmake 太旧 | 手装 3.24.4 并 `export PATH=/usr/local/cmake/bin:$PATH` |
| 编译报缺 CUTLASS / googletest 头文件 | 漏拉 submodule | `git submodule update --init --recursive` |
| LFS 文件是文本指针、测试失败 | 漏 `git lfs pull` | `git lfs install && git lfs pull` |
| 多卡通信 bus error / 卡死 | `--shm-size` 太小 | docker run 加 `--shm-size=4g`（或更大） |
| TRT 包与 CUDA runtime 不符 | 下错 cuda-12.1 / cuda-12.2 包 | 按镜像实际 CUDA 选对应 tar（两链接见第 4 节） |

禁用 apt 清理钩子（原文真料，配合上表第 2 行）：

```bash
sed -i -e 's/^APT/# APT/' -e 's/^DPkg/# DPkg/' /etc/apt/apt.conf.d/docker-clean
```
