## 0. 一句话锚点

**自回归语言模型每一步只做一件事：给词表里每个 token 打一个分数（logit），然后从这些分数里"选/抽"出下一个 token。** 解码策略 = 把"一排分数"变成"一个被选中的 token"的那套规则。模型权重不变，换解码策略，输出可以从机械复读变成天马行空。

```
                         一步推理产出
   隐状态 h  ──[ W_unembed ]──►  logits z  ──[ softmax/采样规则 ]──►  next token
  (d_model)      (V × d_model)     (V 维)        ← 本文主角 →         (1 个 id)
```

其中 V 是词表大小（典型 32k~150k）。**解码策略不碰矩阵乘，只碰最后那个 V 维向量。**

## 1. 地基：从 logit 到概率（softmax）

### 1.1 logit 是什么

模型主体（Transformer 堆叠）算完，得到当前位置的隐向量 $h\in\mathbb{R}^{d}$。再乘一个"反嵌入"矩阵 $W\in\mathbb{R}^{V\times d}$，得到 logits：

$$z = W h \in \mathbb{R}^{V}, \qquad z_i = \text{token } i \text{ 的原始分数}$$

logit **不是概率**：它可正可负、可大可小、加起来不等于 1。它只表示"相对偏好"。

### 1.2 为什么要 softmax

我们想要一个**合法概率分布**：每项 $\in[0,1]$，且总和为 1。softmax 是把任意实数向量变成概率分布的标准做法：

$$p_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}}$$

**为什么用指数 $e^{z}$ 而不是直接归一化 $z/\sum z$？** 三个原因：
1. logit 有负数，直接除会出现负概率，非法。
2. 指数把"分数差"变成"倍数差"：$z_i-z_j$ 增大，$p_i/p_j=e^{z_i-z_j}$ 指数级放大——拉开赢家与输家。
3. 数学上 softmax 是最大熵 / 逻辑回归的自然解，求导漂亮。

```
 logits z      e^z (放大差距)        归一化 → 概率 p
 ┌─────┐       ┌──────────┐         ┌──────────────┐
 │ 2.0 │  e^z  │  7.389   │  ÷Σ     │ 0.59  ████████│
 │ 1.0 │ ────► │  2.718   │ ──────► │ 0.22  ███     │  Σp = 1.00
 │ 0.0 │       │  1.000   │         │ 0.08  █       │
 │-1.0 │       │  0.368   │         │ 0.03  ▏       │
 └─────┘       └──────────┘         └──────────────┘
```

### 1.3 数值稳定性（工程必知）

$e^{z}$ 在 $z$ 大时会溢出（$e^{1000}=\infty$）。实现上先减去最大值再做指数，结果完全等价（分子分母同乘 $e^{-\max z}$）：

$$p_i = \frac{e^{z_i - \max_k z_k}}{\sum_j e^{z_j - \max_k z_k}}$$

这样最大的指数项变成 $e^0=1$，不会溢出。**所有框架内部都这么算**。

## 2. 贪心解码（greedy）

### 2.1 原理

每一步直接选概率最大的 token：$\;x_t = \arg\max_i p_i = \arg\max_i z_i$（softmax 单调，比 logit 即可，连指数都不用算）。

```
step1: logits→ pick argmax → "The"
step2: "The" 喂回 → logits→ argmax → "cat"
step3: "The cat"     → logits→ argmax → "sat"
   ... 确定性：同输入永远同输出
```

### 2.2 为什么会出问题

- **重复/退化**：贪心是"局部最优"。语言里高频词（the, and, 是, 的）单步概率高，模型容易陷入 "I love it. I love it. I love it." 这种自我强化的循环——一旦进入某个短语，下一个最大概率往往是把它再走一遍。
- **错失全局更优句**：第一步选了概率 0.6 的词，可能堵死了一条由 0.4 词开头、但整体更连贯的路。
- **零多样性**：温度为 0，永远同一句，不能用于"生成 5 个不同答案"。

**何时用**：要确定性、要复现、抽取式/分类式任务（如"输出 yes/no"、代码补全的确定模式）、贪心通常配合短输出。

## 3. 温度 T：一个标量调"尖锐 vs 平滑"

### 3.1 原理

在 softmax 前把 logits 除以温度 $T>0$：

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$

- $T=1$：原始分布，不变。
- $T<1$（如 0.5）：相当于把 logits 放大，差距被拉大 → 分布更**尖**（更接近贪心）。
- $T>1$（如 1.5）：logits 被压缩，差距变小 → 分布更**平**（更随机、更可能选冷门词）。
- $T\to 0$：退化为贪心（赢家通吃）。
- $T\to\infty$：退化为均匀分布（纯随机）。

### 3.2 为什么除 T 能控随机性

概率比 $p_i/p_j = e^{(z_i-z_j)/T}$。T 越小，指数里的 $1/T$ 越大，同样的 logit 差被指数放得越狠，赢家越独大；T 越大，差被摊薄，大家越接近。**温度调的是"分布的对比度"**。

```
 同一组 logits [2,1,0,-1] 在不同 T 下的形状

 T=0.5 (尖)        T=1.0 (原)        T=2.0 (平)
 ████████████ 0.87  ████████ 0.59   █████ 0.38
 ███ 0.12          ███ 0.22         ████ 0.23
 ▏ 0.016           █ 0.08           ███ 0.18
 ▏ 0.002           ▏ 0.03           ██ 0.14   ← 冷门词也有机会
```

## 4. top-k 截断

### 4.1 原理

只保留 logit 最大的 **k** 个 token，其余直接置为 $-\infty$（概率 0），在这 k 个里重新 softmax 后采样。

```
 V=5万词                只留前 k=3
 ┌─────────────┐        ┌──────────┐
 │ 概率长尾     │  top-k │ tok_A 0.5│
 │ 几万个 0.000x│ ─────► │ tok_B 0.3│ 重新归一 → 采样
 │ ...          │        │ tok_C 0.2│
 └─────────────┘        └──────────┘  其余概率清零
```

### 4.2 为什么需要它

softmax 永远给每个 token 非 0 概率，**几万个长尾词加起来可能占 10%+ 概率质量**——纯采样有不小机会抽到完全离谱的词。top-k 把长尾砍掉，只在"靠谱候选"里采。

### 4.3 它的弱点（引出 top-p）

k 是**固定**的，但分布的尖锐程度是**变化**的：
- 有些位置很确定（如 "United ___" 几乎必是 "States"），此时前 1 个就够，k=40 反而引入噪声。
- 有些位置很开放（如 "I like to ___"），合理候选可能有上百个，k=40 又砍太狠。

固定 k 无法自适应 → top-p 登场。

## 5. top-p / nucleus（核采样）

### 5.1 原理

按概率从大到小累加，**保留累积概率刚好 ≥ p 的最小 token 集合**（这个集合叫"核 nucleus"），其余清零，重新归一后采样。

```
 概率降序累加，p=0.9
 tok  prob  cumsum
 A    0.50  0.50
 B    0.25  0.75
 C    0.13  0.88   ← 还没到 0.9
 D    0.07  0.95   ← 累积越过 0.9，到此为止，纳入 D
 ─────────────── 截断线（核 = {A,B,C,D}）
 E    0.03  ...    清零
 F..  长尾         清零
```

### 5.2 为什么比 top-k 好

**核的大小是动态的**：分布尖时核小（可能就 1~2 个），分布平时核大（可能几十个）。它按"概率质量"而非"个数"截断，天然自适应当前这一步有多确定。这正是 Holtzman 等人在 *The Curious Case of Neural Text Degeneration* 里提出 nucleus 的动机：top-k 固定截断会么重复、么不连贯，核采样同时避开两坑。

典型组合：`temperature=0.7~1.0, top_p=0.9~0.95`，常配一个保险 `top_k`（如 50）兜底。

## 6. beam search（束搜索）

### 6.1 原理

贪心每步只留 1 条路；beam 每步同时保留**得分最高的 B 条**部分序列（B=束宽），扩展、再剪枝回 B 条，最后取整句**对数概率之和**最高的那条。

序列得分（取 log 避免连乘下溢）：

$$\log P(x_{1:T}) = \sum_{t=1}^{T} \log p(x_t \mid x_{<t})$$

```
 B=2 的展开（每框是一条候选序列及其累计 logP）
 step1        step2              step3
 "The"(-0.2) ┬► "The cat"(-0.5) ┬► "The cat sat"(-0.8) ★保留
             │                  └► "The cat ran"(-1.1)
 "A"(-0.9)   ┴► "A dog"(-1.3)   ──► 剪掉(分低)
       每步全展开后按 logP 只留前 B=2 条
```

### 6.2 为什么更"对"却更"闷"

- **更对**：搜的是近似全局最优序列，避免贪心因一步短视而走错。机器翻译、摘要这类"有标准答案、要忠实"的任务里 beam 强。
- **更闷**：它本质在最大化概率，而**高概率句往往是安全、平淡、重复的**（"谢谢""好的""我不知道"）。开放式聊天里 beam 反而无趣，且容易短句偏好/重复，所以闲聊创意场景几乎都用采样而非 beam。
- **更贵**：每步算 B 倍前向、维护 B 条 KV-Cache，显存与算力都 ×B（见 [[llm-inference/KV-Cache优化]]）。

## 7. repetition penalty（重复惩罚）

### 7.1 原理

解码到一半，对**已经出现过的 token**，在它们的 logit 上施加惩罚，降低再次被选中的概率。常见做法（CTRL 论文式）：对已出现 token i，

$$z_i \leftarrow \begin{cases} z_i / \theta & z_i > 0 \\ z_i \cdot \theta & z_i \le 0 \end{cases}, \quad \theta > 1$$

正 logit 除以 θ（变小）、负 logit 乘以 θ（更负），双向都把它往下压。$\theta=1$ 等于不惩罚，典型 1.1~1.3。

```
 已生成: "I love it"  → 惩罚集合 {I, love, it}
 下一步 logits:
   it    3.0  ─/1.2→ 2.50  ← 被压，没那么容易再来一次
   that  2.8  ─────→ 2.80  ← 未出现，不动
   the   2.5  ─────→ 2.50
 → 削弱"复读机"
```

相关变体：
- **no_repeat_ngram_size=n**：直接禁止任何已出现过的 n-gram 再次出现（硬约束，把对应 logit 设 $-\infty$）。
- **presence / frequency penalty**（OpenAI 式）：在 logit 上**减去**一个常数；presence 只看"出现过没"，frequency 按"出现次数"线性加重。
- **注意**：惩罚过猛会让模型为了躲词而变得不通顺，需要权衡，具体接口参数以官方文档为准。

## 8. 采样管线：T / top-k / top-p 同时开，谁先谁后

多数框架的标准顺序（理解机制即可，确切实现以官方文档为准）：

```
 logits z
   │
   ├─[1] repetition / presence / frequency penalty  (改 logit)
   │
   ├─[2] 温度缩放  z ← z / T
   │
   ├─[3] top-k 过滤  (只留前 k，其余 -∞)
   │
   ├─[4] top-p 过滤  (在剩下里按累积概率截到 p)
   │
   ├─[5] softmax  → 概率分布
   │
   └─[6] 多项式采样 (multinomial)  → 抽 1 个 token
```

**为什么这个顺序**：惩罚和温度都作用在"原始偏好"上，要先于截断；top-k 先做粗筛（限个数），top-p 再做细筛（限质量）；最后才归一化采样。先 softmax 再截断也能做，但通常框架是"先在 logit 域截断 / 置 $-\infty$，最后统一 softmax 一次"。

## 9. 数值大实战：一组 logits 走完全程（全部手算）

设词表只有 5 个 token，模型这一步给出 logits：

| token | A | B | C | D | E |
|-------|---|---|---|---|---|
| logit z | 3.0 | 2.0 | 1.0 | 0.0 | -1.0 |

### 9.1 基线 softmax（T=1）

先算 $e^{z}$（用 $e\approx2.718$）：

$$e^{3}=20.09,\;e^{2}=7.389,\;e^{1}=2.718,\;e^{0}=1.000,\;e^{-1}=0.368$$

总和 $Z = 20.09+7.389+2.718+1.000+0.368 = 31.565$。

$$p_A=\tfrac{20.09}{31.565}=0.636,\;p_B=0.234,\;p_C=0.086,\;p_D=0.032,\;p_E=0.012$$

校验：$0.636+0.234+0.086+0.032+0.012=1.000$ ✓

```
 A ████████████████ 0.636
 B ██████ 0.234
 C ██ 0.086
 D ▊ 0.032
 E ▎ 0.012
```

### 9.2 温度 T=0.5（更尖）

logits 先除 0.5（=乘 2）：$z'=[6,4,2,0,-2]$。

$e^{6}=403.4,\;e^{4}=54.60,\;e^{2}=7.389,\;e^{0}=1,\;e^{-2}=0.135$，$Z=466.5$。

$$p_A=\tfrac{403.4}{466.5}=0.865,\;p_B=0.117,\;p_C=0.0158,\;p_D=0.0021,\;p_E=0.0003$$

→ A 从 0.636 涨到 **0.865**，分布更"独裁"，几乎逼近贪心。

### 9.3 温度 T=2.0（更平）

logits 除 2：$z'=[1.5,1.0,0.5,0,-0.5]$。

$e^{1.5}=4.482,\;e^{1}=2.718,\;e^{0.5}=1.649,\;e^{0}=1,\;e^{-0.5}=0.607$，$Z=10.456$。

$$p_A=0.429,\;p_B=0.260,\;p_C=0.158,\;p_D=0.096,\;p_E=0.058$$

→ A 从 0.636 降到 **0.429**，冷门的 D、E 概率明显抬升，更敢探索。

| token | T=0.5 | T=1.0 | T=2.0 |
|-------|------:|------:|------:|
| A | 0.865 | 0.636 | 0.429 |
| B | 0.117 | 0.234 | 0.260 |
| C | 0.016 | 0.086 | 0.158 |
| D | 0.002 | 0.032 | 0.096 |
| E | 0.000 | 0.012 | 0.058 |

### 9.4 top-k（k=2，基于 T=1 分布）

只留 A、B（logit 最大的两个），C/D/E 清零，重新归一：

$$Z_k=0.636+0.234=0.870$$
$$p_A=\tfrac{0.636}{0.870}=0.731,\quad p_B=\tfrac{0.234}{0.870}=0.269$$

→ 现在只可能抽到 A 或 B，长尾彻底无机会。

### 9.5 top-p（p=0.9，基于 T=1 分布）

降序累加：
- A: cum=0.636（<0.9）
- B: cum=0.636+0.234=0.870（<0.9）
- C: cum=0.870+0.086=0.956（≥0.9，越线，纳入 C 后停）

核 = {A, B, C}，D/E 清零，重新归一（$Z_p=0.956$）：

$$p_A=\tfrac{0.636}{0.956}=0.665,\;p_B=\tfrac{0.234}{0.956}=0.245,\;p_C=\tfrac{0.086}{0.956}=0.090$$

**对比 top-k=2 vs top-p=0.9**：这一步分布较尖，top-p 自动只多放进一个 C；若换成很平的分布，top-p 会自动放进更多候选——这就是"动态自适应"。

### 9.6 组合：T=0.7 + top-p=0.9（最常用配方，定性）

先用 T=0.7 把分布稍微锐化（A 概率升到约 0.72），再 top-p=0.9 截断——核会比 T=1 时更小（因为分布更尖，少数 token 就吃满 0.9）。**温度先调对比度，top-p 再据此动态截尾**，两者配合而非冲突。

## 10. 对照与复杂度

| 策略 | 确定性 | 多样性 | 易重复 | 主要超参 | 典型场景 |
|------|:------:|:------:|:------:|----------|----------|
| greedy | 是 | 无 | 高 | — | 分类/抽取/要复现 |
| beam | 是 | 低 | 中 | 束宽 B | 翻译/摘要 |
| 温度采样 | 否 | T 越大越高 | 中 | T | 创意写作 |
| top-k | 否 | 中 | 中低 | k | 通用兜底 |
| top-p | 否 | 中高 | 低 | p | 开放对话（主流） |
| +rep penalty | — | — | 显著降 | θ / penalty | 长文防复读 |

**单步算力**（V=词表大小，B=束宽）：

| 步骤 | 复杂度 | 说明 |
|------|--------|------|
| softmax | $O(V)$ | 一遍指数+一遍归一 |
| top-k | $O(V\log k)$ 或部分选择 | 选前 k |
| top-p | $O(V\log V)$ | 需排序 |
| greedy/采样 | $O(V)$ | argmax / 多项式抽样 |
| beam | 上述 ×B，KV-Cache 显存 ×B | 见 [[llm-inference/KV-Cache优化]] |

注意：解码这一步是 $O(V)$ 级，**远小于** Transformer 前向那一大坨矩阵乘，所以解码策略几乎不影响吞吐瓶颈——瓶颈在于每步都要跑一次完整前向，这才是 KV-Cache 优化的战场。

## 11. 常见问题

| 疑问 | 真相 |
|------|------|
| 温度和 top-p 二选一？ | 不是。温度调"对比度"，top-p 调"截尾范围"，常一起用（T=0.7~1.0 + top_p=0.9）。 |
| top-k 和 top-p 冲突吗？ | 不冲突，常串联：top-k 限个数兜底，top-p 限质量自适应，取两者交集。 |
| T=0 是什么？ | 数学上退化为 greedy（argmax），多数框架把 `temperature=0` 直接当贪心处理。 |
| 为什么采样比贪心更不重复？ | 贪心步步选最大，易陷入高频自循环；采样给了跳出循环的随机性。 |
| beam 一定比贪心好？ | 概率上更优，但开放生成里"高概率=平淡/安全"，闲聊创意反而更差，且贵 ×B。 |
| repetition penalty 越大越好？ | 否。过猛会逼模型躲词导致语句别扭，1.1~1.3 之间权衡。 |
| logits 和概率能直接比大小判断采样结果？ | 排序一致（softmax 单调），但采样看的是归一化后的概率质量，不是 logit 本身。 |
| 同样 prompt 输出不一样正常吗？ | 只要 temperature>0 且采样，就有随机性；要复现需固定随机种子或用 greedy。 |
| top-p=1.0 等于关掉吗？ | 近似等于不截断（保留全分布），随机性最大；要收敛就调小 p 或降温度。 |
