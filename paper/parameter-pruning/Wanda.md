## 0. 一句话锚点

> **Wanda 把第 $j$ 个输入特征的激活范数 $\|x_j\|_2$ 乘进权重幅度里，用 $|w_{ij}|\cdot\|x_j\|_2$ 衡量每个权重该不该剪，并在「每个输出神经元（行）」内部独立比较、剪掉最小的 $s\%$。剪完不动剩余权重、不反传、不求 Hessian 逆。**

把它和两个邻居钉死：

- 比 **幅度剪枝**（Magnitude）准：因为多看了输入激活，不会误删「权重小但输入大」的连接。
- 比 **SparseGPT** 便宜：SparseGPT 要算并求逆 Hessian、还要回填补偿剩余权重；Wanda 一个范数统计就够，**复杂度近似于一次前向**。

论文：Sun, Liu, Bair, Kolter，*A Simple and Effective Pruning Approach for Large Language Models*，ICLR 2024。代码：https://github.com/locuslab/wanda ｜ 论文：https://arxiv.org/abs/2306.11695 （数字均标「约/见原文」，以原文为准）。

## 1. 地基：问题背景

### 1.1 为什么非剪 LLM 不可

LLM 自回归解码阶段是 **访存受限（memory-bound）**：每生成 1 个 token，都要把全部权重从显存搬到计算单元读一遍。瓶颈在「搬权重」而不是「算」。所以**把权重变稀疏/变小**对显存占用、访存带宽都有直接收益。

```
            一次矩阵乘 y = W·x 的三处成本
   ┌──────────────────────────────────────────────┐
   │ ① 显存：存 W = 行×列×字节                       │
   │ ② 算力(FLOPs)：行×列×2 次乘加                   │
   │ ③ 访存带宽：把 W 从 HBM 搬到 SM（解码瓶颈）     │
   └──────────────────────────────────────────────┘
        剪枝把 W 一半元素置零 → 三处都想省
```

### 1.2 已有路线，各卡在哪

```
路线A 幅度剪枝(Magnitude)
   按 |w| 排序剪最小 → 零成本、不要数据
   ✗ 只看权重，不看输入；LLM 高稀疏度直接塌

路线B 重训练式剪枝(迭代剪+微调)
   精度好  ✗ 对百亿模型，反传+再训成本爆炸、不现实

路线C SparseGPT(one-shot, 2023)
   一次前向 + 逐列重建，剪的同时补偿剩余权重
   精度好  ✗ 要算 Hessian H=XXᵀ 并求逆，实现复杂、较慢

Wanda 想要：A 的简单 + C 的精度
```

### 1.3 一个被 SparseGPT 揭示、被 Wanda 利用的关键现象——离群激活（outlier activations）

LLM（尤其 6.7B 以上）里存在**离群特征**：极少数输入维度（hidden 通道）的激活数值出奇地大，比其它维度大几个数量级，且对模型表现至关重要。这意味着：**权重重要不重要，不能只看权重本身，必须把「它接的那个输入通道平时有多大」算进去**。这正是 Wanda 立论的根基。

## 2. 核心洞察：幅度剪枝到底漏看了什么

一个线性层输出某个分量：

$$y_i = \sum_j w_{ij}\, x_j$$

某条连接 $w_{ij}$ 对输出的**实际贡献**是 $w_{ij}\,x_j$，不是 $w_{ij}$ 本身。

```
情形①  w 小、但 x_j 这个通道是离群点(常年很大)
        → w·x 实际不小 → 该连接重要 → 幅度剪枝会误删 ❌
情形②  w 大、但 x_j 这个通道几乎恒为 0
        → w·x 实际≈0 → 该连接没用 → 幅度剪枝却保留它 ❌

结论：只看 |w| 会"看走眼"。把输入尺度乘进来才公允。
```

所以 Wanda 把「输入通道的典型尺度」量化成 $\|x_j\|_2$（在一小批校准数据上该通道的 L2 范数），乘到权重幅度上。

---

## 3. Wanda 的重要度度量（拆到能懂）

### 3.1 度量公式

对线性层权重矩阵 $W\in\mathbb{R}^{C_{out}\times C_{in}}$（行=输出神经元，列=输入特征），第 $(i,j)$ 个权重的 Wanda 重要度：

$$\boxed{\;S_{ij} \;=\; |w_{ij}|\;\cdot\;\|\mathbf{x}_j\|_2\;}$$

逐项解释：

- $|w_{ij}|$：权重绝对值，沿用幅度剪枝。
- $\|\mathbf{x}_j\|_2$：第 $j$ 个**输入特征通道**的激活 L2 范数。设校准集共有 $N\times L$ 个 token（$N$ 条序列、每条长 $L$），把该通道在所有 token 上的激活拼成向量再取 L2：

$$\|\mathbf{x}_j\|_2 = \sqrt{\sum_{t=1}^{N\cdot L} x_{j,t}^2}$$

  它是一个**标量**，对整列 $j$ 共享（同一列所有权重乘同一个范数）。
- $S_{ij}$ 越小 → 该连接对输出影响越小 → 越该剪。

### 3.2 一张图理解「列范数广播到整列」

```
        输入通道范数(每列一个标量)
        ‖x1‖  ‖x2‖  ‖x3‖  ‖x4‖
         3.0   0.2   5.0   1.0
        ┌────┬────┬────┬────┐
 w行i → │.8  │.9  │.1  │.7  │   |w| 矩阵
        ├────┼────┼────┼────┤
        │.6  │.05 │.4  │.3  │
        └────┴────┴────┴────┘
                 │  逐元素 |w| × 该列范数
                 ▼
        ┌─────┬─────┬─────┬─────┐
 S行i → │2.40 │0.18 │0.50 │0.70 │  ← 在"这一行内部"比大小
        ├─────┼─────┼─────┼─────┤
        │1.80 │0.01 │2.00 │0.30 │
        └─────┴─────┴─────┴─────┘
          注意：列2虽 |w|=.9 不小，但 ‖x2‖=0.2 极小
                → S=0.18 反而最该剪（幅度剪枝会保留它！）
```

## 4. 比较分组（Comparison Group）：Wanda 的第二个关键设计

光有度量还不够，**「和谁比」决定了精度**。Wanda 不在整个矩阵里全局排序，而是**逐输出神经元（per-output / 逐行）独立排序**。

```
全局比较(Per-layer)：整张 W 拉平排序，剪全局最小 s%
   缺点：可能某一行被剪光、某一行几乎没剪 → 不均衡 → 掉点

Wanda 默认 per-output(逐行)：
   每一行(一个输出神经元的所有输入连接)内部排序，
   每行各自剪掉最小的 s% 个 → 每个输出神经元稀疏度一致
   ✓ 论文发现这种"局部公平"显著优于全局比较
```

为什么逐行更好？直觉：每个输出神经元 $y_i=\sum_j w_{ij}x_j$ 是一个**独立的加权和**，它的「最不重要连接」应该在**它自己的连接集合内部**评判，而不是和别的神经元抢配额。这点上 Wanda 与 SparseGPT 都采用了「局部分组」的思路。

```
逐行剪枝(s=50%, 每行4个连接剪2个)：
 行i: S=[2.40, 0.18, 0.50, 0.70] → 剪掉 0.18、0.50 → mask=[1,0,0,1]
 行k: S=[1.80, 0.01, 2.00, 0.30] → 剪掉 0.01、0.30 → mask=[1,0,1,0]
 每行恰好保留 50%，互不影响
```

## 5. 算法全流程

### 5.1 三步走（极简）

```
① 准备：取一小批校准数据(论文用 C4 的约 128 条样本，见原文)
        前向跑一遍，逐层记录每个线性层的输入激活
② 统计：对每层、每个输入通道 j，算 ‖x_j‖2（标量）
③ 剪枝：S_ij = |w_ij|·‖x_j‖2，逐行排最小 s% 置零 → 写回 mask
        【不更新剩余权重、不反传、不求逆】
```

### 5.2 逐层数据流（ASCII）

```
  校准样本 ─┐
            ▼
 ┌───────────────── Layer ℓ 的线性子层 ─────────────────┐
 │  输入 X (B·L × C_in)                                  │
 │     │① 按列求 L2 → 得 ‖x_j‖2 向量 (长度 C_in)         │
 │     ▼                                                 │
 │  S = |W| ⊙ (1 · ‖x‖ᵀ)   (列范数广播到整列)            │
 │     │② 逐行取最小 s% 的下标 → 置零 → 得 mask           │
 │     ▼                                                 │
 │  W ← W ⊙ mask          (剩余权重原封不动)             │
 └───────────────────────────────────────────────────────┘
            │  用"剪枝后的该层"前向，产生下一层输入
            ▼  （顺序逐层，后层看到的是前层剪枝后的激活）
        Layer ℓ+1 ...
```

注意一个工程细节：**逐层顺序进行**，第 $\ell$ 层剪完后，用「剪枝后的层」算出下一层的输入激活，所以后层统计到的 $\|x_j\|_2$ 已经包含前层剪枝带来的分布漂移——这让误差不至于盲目累积（与 SparseGPT 的顺序处理一致）。

### 5.3 伪代码

```python
# W: [C_out, C_in] 某线性层；X: [tokens, C_in] 该层校准输入
# s: 稀疏度比例(如 0.5)；nsamples ~ 128 (见原文)
def wanda_prune(W, X, s):
    # 1. 每个输入通道的 L2 范数（标量，长度 C_in）
    norm = X.norm(p=2, dim=0)                 # ‖x_j‖2
    # 2. 重要度：|w| 逐列乘以列范数（广播）
    S = W.abs() * norm[None, :]               # [C_out, C_in]
    # 3. 逐行(per-output)选最小 s% 置零
    k = int(s * W.shape[1])                    # 每行剪掉 k 个
    idx = S.argsort(dim=1)[:, :k]              # 每行最小 k 个的列下标
    mask = torch.ones_like(W, dtype=torch.bool)
    mask.scatter_(1, idx, False)               # 这些位置置 False
    return W * mask                            # 剩余权重不变
```

> 复杂度：只需一次前向收集激活 + 逐行排序，**没有反向传播、没有矩阵求逆**，故远比 SparseGPT 轻量；额外内存只是每层一个长度 $C_{in}$ 的范数向量。

## 6. 为什么有效：和 OBS / SparseGPT 的理论联系

经典 OBS（Optimal Brain Surgeon）用**二阶信息**（Hessian）衡量剪枝代价：剪掉 $w_q$ 的最优代价约为 $w_q^2/[H^{-1}]_{qq}$，其中 $H=XX^\top$。SparseGPT 正是高效近似这套二阶方案，并**回填补偿**剩余权重。

Wanda 可以看作 OBS 的一个**廉价近似**：

```
SparseGPT(2阶)：代价 ∝ w_q² / [H⁻¹]_qq  → 要 H 的逆，且要回补
Wanda(简化)   ：只取 H 的对角线近似 diag(H)_jj = ‖x_j‖²
              → 代价 ∝ w² · ‖x‖²  → 取根号即 |w|·‖x‖
              → 不求逆、不回补，但抓住了"输入尺度"这一主因
```

也就是说，Wanda **丢掉了 Hessian 的非对角项与权重回填**，只保留「权重幅度 × 输入通道能量」这个主导项。论文的核心论点：对 LLM 而言，**这个主导项已经足够好**，二阶细节带来的额外收益在中等稀疏度（如 50%、2:4）下并不大，但实现复杂度天差地别。

```
精度 ↑      SparseGPT ●（2阶+回补，最准但最重）
            Wanda     ●（对角近似，准且极简）   ← 甜点
            幅度剪枝   ●（连激活都不看，最简但最差）
计算成本 →  幅度 < Wanda ≪ SparseGPT
```

## 7. 结构化变体：N:M 半结构稀疏（2:4 / 4:8）

Wanda 的度量天然支持 **N:M 半结构化**（每 M 个连续权重里恰好 N 个为 0），从而吃到 NVIDIA Ampere 起的 **Sparse Tensor Core** 真加速。

```
做法：把每行按"每 M 个一组"切块，在每组内部用 S_ij 排序，
      剪掉组内最小的 N 个 → 满足 N:M 约束。

2:4 一组(4个)：S=[2.4, 0.18, 0.50, 0.70]
              剪最小 2 个(0.18,0.50) → [2.4, 0, 0, 0.70] ✓符合2:4

压缩存储：每组只存 2 个非零值 + 2-bit 索引(4选位置, log2(4)=2bit)
硬件：Sparse Tensor Core 用索引"跳过"那 50% 乘法 → 理论~2×峰值
```

注意：2:4 是把自由的非结构掩码**约束**到固定模式，精度通常略低于同稀疏度的非结构 Wanda，但换来**通用 GPU 上的真加速**（非结构稀疏在普通稠密 GEMM 上不加速）。

## 8. 关键公式 / 算法 / 数值手算

### 8.1 重要度排序——一行手算

某输出神经元的 4 条连接，FP16 权重与对应输入通道范数：

| 列 $j$ | $|w_{ij}|$ | $\|x_j\|_2$ | $S_{ij}=|w|\cdot\|x\|$ | 幅度剪枝排名 | Wanda 排名 |
|---|---|---|---|---|---|
| 1 | 0.80 | 3.0 | **2.40** | 1(最大,保) | 1(保) |
| 2 | 0.90 | 0.2 | **0.18** | 最大之一(保) | **最小→剪** |
| 3 | 0.10 | 5.0 | **0.50** | 最小(剪) | 次小→剪(50%时) |
| 4 | 0.70 | 1.0 | **0.70** | 中(保) | 保 |

> 关键对比：列 2 的 $|w|=0.9$ 很大，**幅度剪枝必然保留它**；但它接的输入通道范数只有 0.2，Wanda 判定其实际贡献最小，**优先剪掉**。这正是 Wanda 优于幅度剪枝的微观证据。

### 8.2 50% 非结构 vs 2:4 的显存账（手算）

设一层 $W$：$C_{out}=C_{in}=4096$，FP16（2 字节）。

- **稠密**：$4096\times4096\times2 = 33{,}554{,}432\,B \approx 32$ MiB。
- **非结构 50%**：值省一半 = 16 MiB；但要存「非零位置」索引，最朴素每权重 ~1 bit mask（$4096^2/8=2$ MiB），合计 ≈ **18 MiB**，**省不到一半**（索引开销）。
- **2:4 半结构**：值 16 MiB + 元数据每权重 0.5 bit（$4096^2\times0.5/8 = 1$ MiB），合计 ≈ **17 MiB**，**省约 47%** 且能硬件加速。

### 8.3 FLOPs 直觉

$y=Wx$（$n\times n$）稠密需 $2n^2$ 乘加。50% 稀疏理论跳过一半 → $\approx n^2$。但**只有硬件真跳过才兑现**：非结构在普通 GPU 上照样乘 0、FLOPs 没省；2:4 经 Sparse Tensor Core 才接近 2× 峰值（端到端因 LayerNorm/激活/KV-cache 等常见 1.3~1.7×）。

## 9. 实验结论（定性，数字标「约/见原文」）

> 以下为定性概括，具体数值以原文/官方仓库为准。

- **困惑度（WikiText 等）**：在 LLaMA / LLaMA-2 全系（7B~65B）上，50% 非结构稀疏时，Wanda 的困惑度**显著优于幅度剪枝**，**与 SparseGPT 大致相当**（互有胜负，差距很小，见原文）。
- **零样本任务**：多项常识/推理零样本基准上，Wanda 与 SparseGPT 接近，明显胜过幅度剪枝（约/见原文）。
- **结构化 2:4 / 4:8**：精度随约束变紧而略降（非结构 > 4:8 > 2:4），但 Wanda 在 2:4 下仍优于同模式的幅度剪枝（见原文）。
- **速度**：Wanda 的**剪枝过程**比 SparseGPT 快很多（无求逆/无回填），论文报告剪枝耗时大幅下降（约/见原文）；推理加速则取决于是否用 2:4 + Sparse Tensor Core。
- **鲁棒性**：对校准样本数量不敏感，**少量样本（约 128 条，见原文）即可**，且对随机种子稳定。
- **可叠加微调**：若允许少量 LoRA/微调，可进一步把精度补回，但 Wanda 主打的是**无再训练**场景。

## 10. 对工程的启示

```
✅ 想"零再训练 + 极简实现"快速得到 50% 稀疏 LLM → 首选 Wanda
✅ 没有 Hessian 求逆的工程预算/稳定性顾虑 → Wanda 比 SparseGPT 易落地
✅ 要硬件真加速 → Wanda 出 2:4 掩码 → cuSPARSELt/TensorRT 部署
✅ Wanda 可与 OWL(分层稀疏度) 叠加：OWL 决定"每层剪多少"，Wanda 决定"剪哪些"
✅ 可与量化叠加：先 Wanda 剪 2:4，再 INT8/INT4 量化，显存与带宽双收益
                 （注意误差累积，建议做敏感性分析）
⚠ 校准数据虽少但要"代表性"：分布偏移会让 ‖x_j‖2 统计失真
```

实操要点：

- 收集激活时按**输入通道**聚合 L2，注意是「逐列共享一个标量」，不要写成逐元素。
- 默认 **per-output（逐行）** 比较分组，别用全局排序。
- 逐层顺序处理，后层用前层剪枝后的激活统计。

## 11. 局限与后续

| 局限 | 说明 |
|---|---|
| 高稀疏度仍会塌 | 60%+ 或更激进稀疏时，因不回填补偿，精度落后于 SparseGPT；此时需要回填或微调 |
| 依赖校准数据 | 虽只需约 128 条，但需有代表性；分布偏移会让 $\|x_j\|_2$ 失真 |
| 非结构不直接加速 | 50% 非结构掩码在普通 GPU 上不提速，需 2:4 + Sparse Tensor Core 或专用稀疏 kernel |
| 只剪线性层权重 | 主要针对 Linear（attn 的 q/k/v/o、FFN），不直接处理 embedding/norm |
| 一阶对角近似 | 丢弃了 Hessian 非对角项，极端情形（强通道相关）下不如二阶方法 |

后续/相关方向：

- **OWL**（分层稀疏度分配，离群感知）：与 Wanda 正交，`OWL + Wanda` 在高稀疏度更稳。
- **Wanda + 轻量微调/LoRA**：少量训练把高稀疏度精度补回。
- **结构化方向**（LLM-Pruner / LLM-Shearing）：删整 head/维度/层，产物是稠密小模型，任意硬件加速，但需再训练。

## 评价 / 对照 / 局限（表格）

| 维度 | 幅度剪枝 | **Wanda** | SparseGPT |
|---|---|---|---|
| 重要度 | $|w|$ | $|w|\cdot\|x\|_2$ | 二阶 $w^2/[H^{-1}]_{qq}$ |
| 要校准数据 | 否 | 少量(约128) | 少量(约128) |
| 改剩余权重(回填) | 否 | **否** | **是** |
| 求 Hessian 逆 | 否 | **否** | 是 |
| 反向传播/再训练 | 否 | 否 | 否 |
| 比较分组 | 全局/逐行 | **逐行(per-output)** | 逐列局部 |
| 剪枝速度 | 最快 | **快** | 较慢 |
| 中等稀疏度精度(50%) | 差 | **好(≈SparseGPT)** | 好 |
| 高稀疏度精度(60%+) | 差 | 中 | **更好(有回填)** |
| 实现复杂度 | 极低 | **低** | 高 |
| 真加速硬件 | 2:4需Sparse TC | 2:4需Sparse TC | 2:4需Sparse TC |

> 一句话评价：**Wanda 用「一个范数」把幅度剪枝抬到接近 SparseGPT 的水平，却把实现成本压到几乎为零——「简单且有效」的范本。**
