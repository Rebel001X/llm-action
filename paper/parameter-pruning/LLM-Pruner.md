## 0. 一句话锚点

LLM-Pruner（NeurIPS 2023，Ma et al.，《LLM-Pruner: On the Structural Pruning of Large Language Models》）解决一个工程痛点：**已经训练好的开源大模型（LLaMA/Vicuna/BLOOM 等）太大，想压缩，但又不想重新训练、也拿不到原始预训练语料**。

它的回答是：
1. **结构化剪枝**（删整行/整列/整个注意力头，而不是把单个权重置零）——这样剪完是一个**更小的稠密模型**，普通硬件直接就能加速，不需要特殊稀疏库。
2. **自动依赖检测**——LLM 内部参数互相耦合（残差、注意力、MoE 的耦合），不能随便删一个就破坏结构，LLM-Pruner 自动找出"删一个就必须连带删的整组"。
3. **梯度重要性 + 50000 行内数据**——只用极少量（论文用约 10 个样本算梯度）通用文本估计每组的重要性，**task-agnostic**，不针对下游任务。
4. **LoRA 恢复**——剪完性能会掉，用少量数据（约 50k 样本、单卡几小时）做 LoRA 微调把性能拉回来。

> 一句话：**不重训、不要原始数据、自动找耦合、剪完即稠密、LoRA 救回**。

## 1. 地基：为什么 LLM 剪枝难，结构化 vs 非结构化

### 1.1 剪枝两大流派

```
                       剪枝 (Pruning)
                 ┌──────────┴───────────┐
       非结构化 (Unstructured)     结构化 (Structured)
       把单个权重置 0               删整行/列/头/通道
       w 矩阵变稀疏，形状不变        w 矩阵真的变小
   ┌──────┴──────┐               ┌──────┴──────┐
 SparseGPT     Wanda          LLM-Pruner    各种通道剪枝
 (高稀疏度,需   (无需重训,     (本篇:依赖图   (CV 时代经典)
  特殊kernel)   依赖激活)       +梯度打分)
```

- **非结构化**（[[paper/parameter-pruning/SparseGPT]]、[[paper/parameter-pruning/Wanda]]）：精度保持好，能到 50%~60% 稀疏，但矩阵**形状没变**，只是大量 0。要真加速，得靠 2:4 稀疏 + 特殊 Tensor Core kernel，或专用稀疏库，普通推理框架吃不到红利。
- **结构化**（本篇）：直接把权重矩阵的**维度变小**（hidden 维、中间维、注意力头数变少），剪完是个**标准稠密小模型**，任意框架（HF transformers、vLLM）开箱即用、显存与算力**真实下降**。

### 1.2 为什么 LLM 的结构化剪枝比 CV 难

CV 时代的通道剪枝（剪 CNN filter）相对独立。但 Transformer 里参数**高度耦合**：

- **残差连接**：`x + Attn(x) + MLP(x)`，要求每一层的输入输出维度（hidden size $d$）严格一致。你剪掉某一层 hidden 的某几维，**整条残差流上所有层的对应维度都得一起剪**，否则维度对不上、加不起来。
- **注意力头**：Q/K/V/O 四个投影是绑定的，剪一个头必须 Q、K、V 的对应列和 O 的对应行**同时剪**。
- **重训成本**：CV 里剪完可以拿原数据集重训。LLM 的原始预训练语料（万亿 token）你根本拿不到，重训也烧不起。

> LLM-Pruner 的两个核心贡献正好对应这两个难点：**自动依赖检测**（解决耦合）+ **LoRA 少数据恢复**（解决重训）。

## 2. 依赖检测：找出"必须一起剪"的耦合组

### 2.1 直觉

把模型看成一张**计算图**，每个神经元是节点。如果删掉神经元 $N_i$ 会使 $N_j$ "没有意义"（要么没输入、要么没输出），那 $N_i$ 和 $N_j$ 就**互相依赖**，必须分到同一组、要么全留要么全删。

LLM-Pruner 定义两条触发规则（沿计算图正/反向传播依赖）：

```
规则①  若 N_j ∈ Out(N_i)  且  Deg⁻(N_j) = 1  →  N_j 依赖 N_i
        （N_j 的唯一输入来自 N_i，删了 N_i，N_j 成孤儿）
规则②  若 N_i ∈ In(N_j)   且  Deg⁺(N_i) = 1  →  N_i 依赖 N_j
        （N_i 的唯一输出去向 N_j，删了 N_j，N_i 成废节点）
```

从任一"触发节点"出发，**反复套用这两条规则做图遍历**，把所有传染到的节点收进同一组——这就是一个**耦合组（coupled group / dependency group）**。

### 2.2 一个注意力 + MLP 的依赖组示意

```
          ┌──────── 残差流 hidden d ────────┐
   x ──┬─►│ Q_proj ─┐                       │
       │  │ K_proj ─┼─► Attn(head h) ─► O_proj ─►(+)─►
       │  │ V_proj ─┘                       │   │
       │  └─────────────────────────────────┘   │
       └────────────────────────────────────────┘
                                               同一残差维度 → 必须整条一起剪

   剪 1 个 head  ⇒  Q/K/V 对应的 head_dim 列 + O 对应行  全删
   剪 hidden 第 k 维 ⇒ 所有层 LayerNorm/残差/各 proj 的第 k 维 全删
   剪 MLP 中间维 j ⇒ up_proj/gate_proj 第 j 列 + down_proj 第 j 行 全删
```

**关键洞察**：MLP 的中间维（intermediate size）与注意力头数，是**层内局部耦合**，剪它们不会传染到整条残差流，是"廉价的剪枝目标"；而 hidden 维是**全局耦合**，牵一发动全身，剪它代价大、风险高。LLM-Pruner 因此**优先剪 MLP 中间维和注意力头**。

## 3. 重要性估计：哪些组该剪（梯度泰勒打分）

找到了"组"，接下来要判断**每组重要不重要**——重要的留，不重要的剪。

### 3.1 思想：删掉这组，loss 涨多少？

最理想的重要性 = "删掉这组权重后 loss 的增量 $\Delta\mathcal{L}$"。但对每组都真删一遍跑前向太贵。于是用**泰勒展开**近似 $\Delta\mathcal{L}$。

把权重 $W$ 中某组置零等价于扰动 $\Delta W = -W$。在数据 $\mathcal{D}$ 上对 loss 做泰勒展开：

$$
\Delta\mathcal{L} = \mathcal{L}(W{=}0) - \mathcal{L}(W) \approx -\,g^\top W + \tfrac{1}{2} W^\top H\, W
$$

- $g = \partial\mathcal{L}/\partial W$ 是梯度（一阶），$H$ 是 Hessian（二阶）。
- 由于不用原始任务、$\mathcal{L}$ 不是收敛点的训练损失，**一阶项 $g$ 不可忽略**（这点和经典 OBD/OBS 假设梯度≈0 不同，是 LLM-Pruner 的细节差别）。

逐元素地，对组内每个权重 $W_i$ 定义重要性：

$$
I_{W_i} = \left| \Delta\mathcal{L}_i \right| \approx \left| g_i\, W_i - \tfrac{1}{2} H_{ii}\, W_i^2 \right|
$$

Hessian 全量算不起，用**对角近似 + Fisher 信息**：$H_{ii}\approx \big(\partial\mathcal{L}/\partial W_i\big)^2$（梯度平方），只需一次反向传播即可拿到。

### 3.2 从"单个权重重要性"聚合到"整组重要性"

一组里有很多权重，要汇总成一个组分数 $I_{\mathcal{G}}$。论文给了几种聚合（Summation / Product / Max / Last-layer），实践常用**逐元素重要性求和或取该组在输出处的代表元素**：

$$
I_{\mathcal{G}} = \sum_{W_i \in \mathcal{G}} I_{W_i} \quad\text{或}\quad I_{\mathcal{G}} = \prod_{W_i \in \mathcal{G}} I_{W_i}
$$

只需要**约 10 条**公开通用文本（论文用很小一批校准样本）跑前向+反向，就能给所有组打分——**task-agnostic、不碰原始训练集**。

```
打分流程：
 校准样本(≈10条) ─► 前向 ─► loss ─► 反向 ─► 拿到每个权重的 g_i
        │                                        │
        └──────────────────────► g_i² 当 H_ii ◄──┘
                                        │
                 I_Wi = |g_i·W_i − ½·g_i²·W_i²|
                                        │
                 按依赖组聚合 → I_G  （组重要性排序）
```

## 4. 分组裁剪策略：剪哪些层、剪多少

### 4.1 哪些层不能碰

经验发现**首尾几层对性能极敏感**（首层贴近输入语义，尾层贴近输出预测）。LLM-Pruner 默认**保留首尾若干层不剪**，只在中间层做结构化剪枝。

```
 Layer 0  1  2  3 ........................... L-2  L-1
 [保留]  ┃        中间层：按 I_G 排序剪低分组      ┃ [保留]
         ▲                                      ▲
       首层敏感                              尾层敏感
```

### 4.2 两种粒度

- **Block-wise（块级）**：在 attention block / MLP block 内部，按组重要性排序，剪掉得分最低的一批组（剪头数、剪 MLP 中间维）。**不动 hidden 维**，残差流维度不变 → 稳。这是论文主推、默认模式。
- **Channel-wise（通道级）**：连 hidden 维一起剪，压缩比更大，但因为是全局耦合、风险高、掉点多，谨慎使用。

### 4.3 剪枝率与"参数量 vs 速度"的取舍

剪 MLP 中间维 / 头数，参数量和 FLOPs 一起降，吞吐真实提升。整体目标剪枝率（论文常报约 20% 参数量）下，**先剪最不重要的组直到达到目标压缩比**。

## 5. LoRA 快速恢复：剪完掉点怎么救

剪枝后模型一定掉点（破坏了原有结构）。重训不可行（没数据、烧不起）。LLM-Pruner 用 **LoRA 低秩微调**：

- 只在剩下的权重上加 LoRA 适配器 $W' = W + BA$（$B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times k}, r\ll d$），**冻结原权重**，只训 $A,B$。
- 用约 **50k 条**公开指令/通用文本（论文用 Alpaca 等小集合），**单卡（约 1×A100/3 小时量级，见原文）** 即可。
- 因为只训低秩增量，**几乎不增加恢复成本**，却能把剪枝掉的点显著补回。

```
   剪枝(几分钟) ──► 模型掉点 ──► LoRA 微调(约 3h/单卡) ──► 性能回升
   ▲ 无需原始数据                 ▲ 仅训低秩 B、A，冻结原权重
   └──────────── 全流程不重训、单卡可跑 ────────────────┘
```

> 工程含义：整套"剪 + 救"在**单卡、几小时、无原始语料**下完成，这是它相对"重训式压缩"的最大卖点。

## 6. 关键公式 / 算法 / 数值示例

### 6.1 完整算法（伪代码）

```
输入: 预训练模型 M, 校准样本 D(≈10条), 目标剪枝率 p, 恢复数据 D_ft(≈50k)
1. 依赖检测:
   for 每个触发节点:
       用规则①②做图遍历 → 形成耦合组集合 {G}
2. 重要性估计:
   D 上前向+反向 → 每个权重 g_i, 用 g_i² 近似 H_ii
   I_Wi = |g_i·W_i − ½·g_i²·W_i²|
   I_G  = aggregate(I_Wi)   # sum / prod / max / last
3. 分组裁剪:
   固定首尾层; 中间层按 I_G 升序剪低分组, 直到达到剪枝率 p
4. 恢复:
   注入 LoRA(秩 r), 冻结原权重, 在 D_ft 上微调 A,B
输出: 压缩并恢复后的稠密小模型 M'
```

### 6.2 数值手算：剪 LLaMA-7B 的 MLP 中间维省多少

设单层 MLP（SwiGLU）：hidden $d=4096$，中间维 $d_{ff}=11008$，三个矩阵 gate/up/down。

- 单层 MLP 参数量 $\approx 3 \times d \times d_{ff} = 3\times4096\times11008 \approx 1.35\times10^8$（约 1.35 亿）。
- 若把中间维剪 25%：$d_{ff}: 11008 \to 8256$，单层 MLP 参数 $\approx 3\times4096\times8256 \approx 1.01\times10^8$，**单层省约 0.34 亿**。
- 32 层全剪：MLP 部分省约 $32\times0.34\times10^8 \approx 1.1\times10^9$（约 11 亿参数）。LLaMA-7B 约 67 亿参数，**仅靠剪 MLP 中间维 25% 就压掉约 16%**。
- 这部分是**真实稠密变小**：矩阵乘 FLOPs 与中间维成正比，FLOPs 同步降约 25%（MLP 部分），KV-Cache 不变（没动头数/hidden）。

> 对照：若改剪注意力头（如 32 头剪到 24 头），Q/K/V/O 同步变小，**KV-Cache 也随头数线性下降**，对长上下文推理显存收益更直接（参考 [[llm-optimizer/kv-cache]]）。

### 6.3 重要性打分一例

某权重 $W_i=0.8$，校准集上梯度 $g_i=0.05$：

$$
I_{W_i} = \big|\, g_i W_i - \tfrac12 g_i^2 W_i^2 \,\big| = \big|\,0.05\times0.8 - 0.5\times0.0025\times0.64\,\big| = |0.04 - 0.0008| \approx 0.039
$$

一阶项 $0.04$ 主导，二阶修正 $0.0008$ 很小——印证"未收敛时一阶不可忽略、二阶只是微调"。

## 7. 评价 / 对照 / 局限

| 维度 | LLM-Pruner | SparseGPT | Wanda |
|---|---|---|---|
| 剪枝类型 | **结构化**（删行/列/头） | 非结构化/半结构化 2:4 | 非结构化/半结构化 2:4 |
| 剪完是否稠密小模型 | **是**，任意框架直接加速 | 否，需稀疏 kernel 才加速 | 否，需稀疏 kernel |
| 重要性依据 | **梯度泰勒**（一阶+二阶对角） | 逐列 OBS（Hessian 逆 + 权重更新） | **权重×激活范数**（无梯度、无重训） |
| 是否需反向/梯度 | 需（少量样本算梯度） | 不需 | 不需 |
| 是否重训/微调 | **需 LoRA 恢复**（约 50k 样本/单卡） | 不需 | 不需 |
| 典型压缩 | 约 20% 参数（见原文） | 50%+ 稀疏 | 50%+ 稀疏 |
| 适用场景 | 想要**真小、真快**的稠密模型 | 高稀疏度且有稀疏算力 | 一键剪、零成本基线 |

**局限（务必清楚）**：
- **高剪枝率掉点明显**：压到 50% 以上，即便 LoRA 恢复也难追平原模型；论文主力区间是约 20% 左右（具体数字见原文）。
- **仍需少量数据 + 梯度**：相比 Wanda（完全无梯度无重训）门槛略高。
- **结构化粒度受耦合约束**：hidden 维剪枝风险高，主要红利在 MLP 中间维 / 头数。
- **依赖 LoRA 恢复**：恢复数据分布会影响结果（task-agnostic 但非完全无关）。
- **与量化正交**：可叠加量化（[[llm-compression/quantization/量化基础]]）进一步压缩，但本篇未联合优化。

**对工程的启示**：
1. 想在**已有推理栈（vLLM/HF）上零改造拿加速**，结构化剪枝优于非结构化——剪完就是个小稠密模型，[[llm-inference/vllm/README]] 直接能跑。
2. **依赖图思想可复用**：任何含残差/注意力耦合的网络做结构化剪枝，都要先建依赖组，避免维度对不齐。
3. **剪 + LoRA 恢复**是低成本压缩配方：在拿不到原始预训练语料时尤其实用。
4. 剪**头数**优先于剪中间维，能同时减 [[llm-inference/KV-Cache优化]] 显存，长上下文推理收益更大。
