## 0. 一句话锚点

剪枝 = 在"保住模型质量"的前提下,把一部分权重**置零或整块删除**,从而减小显存/算力。所有方法都在回答两个问题:

1. **删谁?** —— 给每个权重(或每组权重)算一个**重要性分数** $S_{ij}$,分数低的删。
2. **删了怎么办?** —— 删除会引入误差,要么**重训/微调恢复**(LLM-Pruner),要么**改剩余权重做误差补偿**(SparseGPT),要么**啥也不做、靠打分够准**(Wanda)。

$$\text{剪枝} = \underbrace{\text{重要性度量}}_{\text{删谁}} \;+\; \underbrace{\text{误差处理}}_{\text{删了怎么办}}$$

## 1. 地基:剪枝在解决什么问题

一个线性层做的是 $Y = XW$,其中 $W\in\mathbb{R}^{d_{in}\times d_{out}}$。LLM 里 $d$ 动辄 4096~8192,绝大多数 FLOPs/显存都耗在这些稠密矩阵上。剪枝就是把 $W$ 里一部分元素变成 0。

**稀疏度(sparsity)** $s$ = 被置零元素占比。$s=0.5$ 即删一半。

**三种结构粒度**(决定能不能真省钱):

```
非结构化 (unstructured)        半结构化 2:4 (semi-structured)     结构化 (structured)
每个元素独立删                  每4个里删2个,位置任意             整行/整列/整个头/整个通道删
┌─────────────┐               ┌─────────────┐                 ┌─────────────┐
│ W 0 W 0 W W │               │ W 0 W 0 │每4列 │ W W W W │  ← 删
│ 0 W 0 W W 0 │               │ 0 W W 0 │一组   │ W W W W │
│ W W 0 0 0 W │               │ W 0 0 W │      │ W W W W │  ← 删
└─────────────┘               └─────────────┘                 └─────────────┘
精度损失最小                    Ampere 稀疏Tensor Core可2×加速    维度真变小, 任意硬件直接加速
但通用GPU几乎不加速              规整, 既省又快(甜点)             但精度掉得最狠
```

- **非结构化**:压缩比最自由、精度最好,但稠密 GEMM 硬件跳不过 0,**实际不加速**(只省存储)。
- **半结构化 2:4**:每连续 4 个权重里恰好 2 个非零。NVIDIA Ampere+ 的 **Sparse Tensor Core** 能对 2:4 做 ~2× 加速,是工程甜点。SparseGPT/Wanda 都重点支持。
- **结构化**:删掉整个注意力头 / FFN 中间通道 / 维度,矩阵真的变小,**任意硬件直接加速**,但等于砍掉整条信息通路,精度最敏感。LLM-Pruner 走这条路。

> 关联:剪枝(让权重变 0)与[[llm-compression/quantization/量化基础]](让权重位宽变小)是压缩的两条正交主线,可叠加。

## 2. 最朴素判据:幅值剪枝(Magnitude Pruning)

直觉:绝对值小的权重对输出贡献小,先删。重要性分数:

$$S_{ij} = |W_{ij}|$$

按 $S$ 从小到大排序,删掉最小的那批直到达到目标稀疏度。

```
权重    |W|     排序删除(s=50%)
+0.8 →  0.8    保留
-0.1 →  0.1    删 ← 小
+0.6 →  0.6    保留
+0.05→  0.05   删 ← 最小
```

**为什么不够好(尤其对 LLM)**:幅值只看权重自身,**忽略了输入激活的尺度**。如果某列输入 $X_j$ 普遍很大,即使 $W_{ij}$ 不大,$W_{ij}X_j$ 对输出的贡献也可能很大。LLM 激活里存在著名的"离群特征(outlier features)",幅值剪枝会误删重要连接 → 这正是 Wanda 改进的出发点。

## 3. 经典理论:OBD / OBS —— 用二阶信息算"删了损失涨多少"

把"删某权重导致的损失增加量"叫**显著性(saliency)**。围绕已收敛点把损失 $\mathcal{L}$ 做泰勒展开:

$$\delta\mathcal{L} = \underbrace{\mathbf{g}^\top \delta\mathbf{w}}_{\approx 0\,(\text{已收敛})} + \tfrac{1}{2}\,\delta\mathbf{w}^\top \mathbf{H}\,\delta\mathbf{w} + O(\|\delta\mathbf{w}\|^3)$$

收敛点梯度 $\mathbf{g}\approx 0$,所以损失变化主导项是 **Hessian** 二次型。

- **OBD(Optimal Brain Damage)**:假设 Hessian 对角,删第 $i$ 个权重的显著性
$$S_i = \tfrac{1}{2} H_{ii}\, w_i^2$$
- **OBS(Optimal Brain Surgeon)**:不忽略非对角项。删第 $q$ 个权重时,**同时最优地更新其余权重**做补偿,得到闭式解:
$$S_q = \frac{w_q^2}{2\,[\mathbf{H}^{-1}]_{qq}},\qquad
\delta\mathbf{w} = -\frac{w_q}{[\mathbf{H}^{-1}]_{qq}}\,[\mathbf{H}^{-1}]_{:,q}$$

含义:删 $w_q$ 不仅按 $w_q^2/[\mathbf{H}^{-1}]_{qq}$ 选最该删的,还把这一删带来的误差**摊到剩余权重**上(沿 $\mathbf{H}^{-1}$ 的第 $q$ 列方向调整)。这就是"误差补偿"的鼻祖,SparseGPT 正是它在大模型上的可扩展近似。

> 难点:整层 $\mathbf{H}^{-1}$ 是 $d_{in}\times d_{in}$,LLM 里 $d_{in}=4096$ 量级,**逐个删权重 + 每次重算逆**是 $O(d^4)$,根本算不起。SparseGPT 的全部精巧都在于绕开这点。

## 4. SparseGPT:一次性(one-shot)、无需重训的逐列误差补偿

**层级重建目标**:不直接管全局损失,而是逐层最小化"剪枝后输出 vs 原输出"的差:

$$\min_{\widehat{W}}\; \big\| X W - X \widehat{W} \big\|_2^2 \quad\text{s.t. } \widehat{W}\text{ 满足稀疏约束}$$

其中 $X$ 是用一小批校准数据(calibration data)跑出来的该层输入。这是个**带掩码的最小二乘**,精确解需要对每个不同的掩码求一次 $(X^\top X)^{-1}$,组合爆炸。

**关键 Hessian**:$\mathbf{H} = X^\top X$(层输入的二阶矩,$+\lambda I$ 做阻尼)。

SparseGPT 的三个核心近似/技巧:

```
        逐列从左到右处理 W 的列 (j = 1,2,...,d)
        ┌───────────────────────────────────────────┐
   列j  │  ① 用对角线显著性选本列要删哪些权重         │
        │     S_ij = W_ij^2 / [H^-1]_jj               │
        │  ② 删除后, 把误差沿 H^-1 补偿到"右侧还没处理 │
        │     的列", 用 OBS 式更新                     │
        │  ③ Cholesky 分解一次性拿到所有 [H^-1] 信息   │
        └───────────────────────────────────────────┘
   已处理列(冻结) │ 当前列 │ 未处理列(吸收误差,后续再剪)
   ─────────────┼────────┼───────────────────────────→
```

1. **掩码与更新解耦**:先按对角近似的显著性 $S_{ij}=W_{ij}^2/[\mathbf{H}^{-1}]_{jj}$ 选掩码,再做权重更新,避免"每种掩码都求一次逆"。
2. **逐列 OBS 更新**:处理到第 $j$ 列时,把删除这些权重的误差,用 OBS 闭式更新**只补偿到尚未处理的右侧列**(误差"向右流"),所以只需 $\mathbf{H}^{-1}$ 的一部分。
3. **一次 Cholesky 拿全**:$\mathbf{H}^{-1}$ 的逐列信息可由一次 **Cholesky 分解**得到,把复杂度从 $O(d^4)$ 压到 $O(d^3)$,使 175B 模型也能在数小时内单次剪枝完成。

逐列误差补偿的更新式(概念形式,沿用 OBS):

$$W_{:,j+1:}\;\mathrel{-}=\; \frac{W_{:,j}\;\text{(被剪部分)}}{[\mathbf{H}^{-1}]_{jj}}\;\cdot\;[\mathbf{H}^{-1}]_{j,\,j+1:}$$

**结论(定性,数字见原文)**:SparseGPT 可在 **无任何重训** 下,把 OPT/BLOOM-175B 这类模型剪到约 50% 非结构化稀疏或 2:4,困惑度(perplexity)上升很小;模型越大越"抗剪"。是后续一票 one-shot 剪枝法的基线。

## 5. Wanda:Pruning by Weights AND Activations —— 不更新权重,只把"激活"乘进打分

Wanda 的洞见:SparseGPT 又算逆又改权重,太重;真正缺的其实只是**打分时考虑输入尺度**。重要性分数:

$$S_{ij} = |W_{ij}| \cdot \|X_j\|_2$$

- $|W_{ij}|$:权重幅值(沿用幅值剪枝)。
- $\|X_j\|_2$:第 $j$ 个输入特征在校准集上跨所有 token 的 **L2 范数**,即该输入维度的"能量/活跃度"。

```
          权重幅值      输入能量        Wanda 分数
W_ij = 0.1, ||X_j|| = 50  →  S = 0.1×50 = 5.0   保留(激活大, 贡献大!)
W_ij = 0.6, ||X_j|| = 2   →  S = 0.6×2  = 1.2   删(权重虽大但输入很小)
                  ↑ 纯幅值剪枝会做出相反的错误决定
```

**按输出逐行比较(per-output / per-row)**:Wanda 不在整个矩阵里全局排序,而是**对每个输出神经元(每一行)单独**按 $S_{ij}$ 排序删元素 —— 实践证明这种"比较组(comparison group)"划分对 LLM 更稳。

**三个工程优点**:
1. **不改剩余权重**(no weight update)—— 没有 OBS 补偿,没有反向传播。
2. **不需要求逆**—— 只要一次前向过校准数据收集 $\|X_j\|_2$,$O(d^2)$ 级别,比 SparseGPT 快很多、显存友好。
3. 同样支持非结构化 / 2:4 / 4:8 半结构化。

**结论(定性,数字见原文)**:Wanda 在约 50% 稀疏 / 2:4 下,质量与 SparseGPT 接近甚至持平,但**实现极简、剪枝速度快得多**。它把"是否要做昂贵的二阶补偿"这件事变成了可选项,证明对 LLM 而言"$|W|\cdot\|X\|$ 这个一阶代理打分已经很好"。

> 与离群特征的关系见 [[llm-compression/quantization/fp8]] / 量化里 outlier 处理思路同源:都在强调"激活尺度"才是 LLM 的关键变量。

## 6. LLM-Pruner:任务无关的**结构化**剪枝 + LoRA 快速恢复

前两者是非结构化/半结构化(省存储或靠特殊 Tensor Core)。LLM-Pruner 要的是**真·变小、任意硬件加速**,所以做结构化剪枝,三步走:

```
①Discover(发现): 构依赖图, 把"必须一起删"的权重归为耦合结构组(coupled group)
   例: 删一个注意力头 → 它的 Q/K/V 投影对应行列 + 输出投影对应列, 整组同删
       删 FFN 一个中间通道 → up/gate 的一列 + down 的一行, 整组同删
        ┌──────┐        ┌──────┐
   X →  │ W_up │→ act → │W_down│ → Y
        └──┬───┘        └───┬──┘
           └── 删第k个中间通道: up的第k列 + down的第k行 必须一起删 ──┘

②Estimate(估计): 给每个组算重要性 (基于梯度/一阶 Taylor)
   组重要性 = Σ_组内参数 |∂L/∂W · W|  (用少量校准数据反传一次)
   删重要性最低的若干组

③Recover(恢复): 用 LoRA 做轻量微调, 少量数据(数万样本/几小时)把性能拉回
```

**组重要性(一阶 Taylor / 梯度×权重)**:对结构组 $G$,
$$I_G = \sum_{w_k\in G}\Big|\,\frac{\partial \mathcal{L}}{\partial w_k}\, w_k\,\Big|
\quad\text{(亦可用二阶近似)}$$

这等价于"把这组权重一起置零会让损失大概涨多少"的一阶估计。删低 $I_G$ 的组。

**为什么必须按组(依赖图)**:Transformer 里维度是耦合的——你不能只删 Q 投影的一行而不动对应的 K/V 和后续 $W_O$,否则残差/拼接维度就对不上。依赖图自动找出这些"牵一发动全身"的耦合集合,保证剪完仍是合法网络。

**结论(定性,数字见原文)**:LLM-Pruner 可在剪掉约 20% 参数后,用 **LoRA 在几小时 / 数万样本**内恢复大部分能力,且**任务无关**(不依赖下游标签)。代价:结构化剪枝精度比非结构化更敏感,高稀疏下掉点明显,需要恢复阶段兜底。

## 关键公式 / 算法 / 数值示例(集中复盘)

**重要性打分一览**

| 方法 | 重要性分数 $S$ | 用到激活? | 用到Hessian/梯度? | 删后是否改权重 |
|------|---------------|-----------|------------------|---------------|
| 幅值 | $\|W_{ij}\|$ | 否 | 否 | 否 |
| OBD | $\tfrac12 H_{ii}w_i^2$ | — | 对角Hessian | 否 |
| OBS | $w_q^2/(2[\mathbf{H}^{-1}]_{qq})$ | — | 全Hessian逆 | 是(补偿) |
| SparseGPT | $W_{ij}^2/[\mathbf{H}^{-1}]_{jj}$,$\mathbf{H}=X^\top X$ | 是(经$X^\top X$) | 是(Cholesky近似) | 是(逐列补偿) |
| Wanda | $\|W_{ij}\|\cdot\|X_j\|_2$ | 是(L2能量) | 否 | **否** |
| LLM-Pruner | $I_G=\sum_G\|\partial\mathcal{L}/\partial w\cdot w\|$ | 经梯度 | 一阶梯度 | LoRA恢复 |

**🧮 数值手算 1:Wanda vs 幅值,谁该被删?**
设某输出行有 4 个权重与对应输入 L2 范数:

| j | $\|W_{ij}\|$ | $\|X_j\|_2$ | 幅值排序 | Wanda分数 $S$ |
|---|------|------|---------|--------|
| 1 | 0.10 | 50 | 最小(先删) | 0.10×50 = **5.0**(保) |
| 2 | 0.60 | 2  | 最大(保) | 0.60×2  = **1.2**(删) |
| 3 | 0.30 | 10 | 中 | 0.30×10 = 3.0 |
| 4 | 0.40 | 4  | 中 | 0.40×4  = 1.6 |

按 50% 稀疏(每行删 2 个):
- **幅值剪枝**删 j1、j3 → 误删了实际贡献最大的 j1。
- **Wanda**删 j2、j4 → 保住高激活的 j1。
说明:在激活尺度差异大的 LLM 上,引入 $\|X_j\|$ 能避免幅值剪枝的系统性误判。

**🧮 数值手算 2:2:4 稀疏的理论收益**
线性层 $W$:$d_{in}=d_{out}=4096$。
- 参数量 $=4096\times4096\approx 1.68\text{M}$,FP16 占 $\approx 3.36$ MB/层。
- 2:4 稀疏:非零元素占 50%,压缩存储约需 **元数据(2-bit 索引/4元素)+ 一半权重** ≈ 原来的 $0.5+\tfrac{2}{16}\approx 0.625$ 倍存储(粗算)。
- 算力:Ampere+ 稀疏 Tensor Core 对 2:4 GEMM 理论 **~2× 吞吐**。
- 对比非结构化 50%:存储省一半,但稠密 GEMM **不跳零 → 实测约 1×(不加速)**。
> 这解释了为何 SparseGPT/Wanda 都把 **2:4** 作为"能落地加速"的首选格式。

**🧮 数值手算 3:Hessian 求逆的不可行性**
逐权重 OBS 每删一个就重算 $\mathbf{H}^{-1}$($O(d^3)$),整层 $d^2$ 个权重 → $O(d^4)$。
$d=4096$:$d^4 = 4096^4 \approx 2.8\times10^{14}$ → 单层就 ~$10^{14}$ 量级运算,数百层模型完全不可行。
SparseGPT 用"一次 Cholesky + 逐列向右补偿"把它降到 $O(d^3)\approx 6.9\times10^{10}$/层,**约 4096 倍**的下降,这才让 175B one-shot 剪枝成为可能。

## 评价 / 对照 / 局限

| 维度 | LLM-Pruner | SparseGPT | Wanda |
|------|-----------|-----------|-------|
| 剪枝结构 | 结构化(组) | 非结构化 / 2:4 | 非结构化 / 2:4 / N:M |
| 真实加速 | ✅任意硬件 | 2:4才加速 | 2:4才加速 |
| 需校准数据 | 是(算梯度) | 是(算$X^\top X$) | 是(算$\|X\|_2$) |
| 是否改权重 | LoRA恢复 | ✅逐列补偿 | ❌不改 |
| 计算成本 | 中(需反传) | 高(Cholesky/求逆) | **低(只一次前向)** |
| 是否需重训 | 需LoRA恢复 | 不需 | 不需 |
| 一句话 | 真变小,需恢复 | 精打细算的OBS近似 | 极简但够好的代理打分 |

**共同局限 / 注意点(以原文为准)**:
- 都依赖**校准数据分布**,与下游分布偏差大时质量会变。
- 非结构化/2:4 在**通用 GPU 上很难拿到理论加速**,需要专门内核或 Ampere+ Sparse Tensor Core。
- 高稀疏度(如 >60~70%)下三者都明显掉点;结构化(LLM-Pruner)对稀疏度最敏感。
- 剪枝与 **量化** 叠加时存在相互影响,联合压缩需谨慎(见 [[llm-compression/quantization/量化基础]])。
- 这些是 **one-shot / 训练后(post-training)** 范式;若允许大规模重训,稀疏预训练可能更优但成本高。
