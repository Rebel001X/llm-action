## 0. 一句话锚点

> **SparseGPT = 把"剪哪些权重 + 怎么调剩下的权重"合并成一个逐层最小二乘问题，并用 Hessian 逆的增量更新把它做到千亿参数可解。**

- 论文：*SparseGPT: Massive Language Models Can Be Accurately Pruned in One-Shot*，Elias Frantar & Dan Alistarh，ICML 2023。
- 代码：https://github.com/IST-DASLab/sparsegpt （IST-DASLab，与 GPTQ 同一团队）。
- 一句对照：**GPTQ 之于量化 ≈ SparseGPT 之于剪枝**——同一套"逐层 + OBS/Hessian + 列分块"的方法论，一个把权重压到低 bit，一个把权重置零。

## 1. 地基 / 前置：为什么大模型剪枝这么难

### 1.1 什么是剪枝（pruning）

把权重矩阵中"不重要"的元素直接置 0。稀疏度 50% 就是一半权重变 0。好处：

- 存储/带宽减半（稀疏存储）；
- 配合硬件（如 NVIDIA Ampere 的 2:4 稀疏 Tensor Core）可拿到接近 2× 的算力。

### 1.2 传统剪枝的"重训依赖"

经典流程是 **剪枝 → 微调（fine-tune）恢复精度**，迭代很多轮。这在小模型上没问题，但在 GPT-175B 这种模型上：

- 重训一次的算力 = 重新训练一个大模型，**没人付得起**；
- 校准/训练数据可能拿不到。

所以大模型时代需要 **one-shot / post-training pruning**：只给一点点校准数据（如 128 条序列），**不做梯度训练**，直接把模型剪好。

### 1.3 已有 one-shot 方法的两难

```
            准  ┃   ● OBS/最优脑外科   ──→ 需要 Hessian 逆，O(d^4)，千亿规模算不动
   精度恢复     ┃
   能力         ┃   ● Magnitude(按幅值剪)──→ O(1) 超快，但大模型上一剪就崩
            差  ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
                  慢                            快
                          计算可行性 / 速度
```

- **Magnitude pruning**：删掉绝对值最小的权重。简单，但忽略输入分布，大模型上 50% 稀疏直接崩溃。
- **OBS（Optimal Brain Surgeon）/ OBD**：用二阶信息（Hessian）选删哪个权重并**补偿**其余权重。很准，但精确版对每一层是 $O(d_{\text{hidden}}^4)$，175B 模型根本跑不动。

> SparseGPT 的目标：**拿到 OBS 的精度，但把代价压到 Magnitude 那个量级的可行性。**

## 2. 核心思想：把剪枝变成"逐层重建"

### 2.1 逐层（layer-wise）解耦

不去管整个网络，而是**一层一层**地处理。对某个线性层，权重为 $W \in \mathbb{R}^{d_{\text{row}} \times d_{\text{col}}}$，给一批校准输入 $X$（该层实际看到的激活），目标是：

$$
\min_{\widehat{W}} \; \| W X - \widehat{W} X \|_2^2 \quad \text{s.t. } \widehat{W} \text{ 满足稀疏约束}
$$

直觉：**别管权重本身像不像，只要这一层的输出 $\widehat{W}X$ 尽量像原始输出 $WX$ 就行。** 把剪枝从"删权重"升级成"删权重 + 重建剩余权重让输出不变"。

```
原始层:   X ──[ W ]──→ Y = W X
                │  剪掉一些权重(掩码 M)，并调整剩下的
                ▼
稀疏层:   X ──[ Ŵ ]──→ Ŷ ≈ Y      目标:  ‖Y - Ŷ‖² 最小
          Ŵ 中被剪的位置=0，其余位置被"重建"过
```

### 2.2 为什么这等价于 OBS

如果稀疏掩码（剪哪些）已知，上面就是个**带等式约束的最小二乘**，闭式解依赖 **Hessian** $H = X X^\top$（更准确是 $2XX^\top$）。这正是 OBS 的二阶框架。难点从来不是"会不会解"，而是：

1. **选掩码**（删哪些）本身是组合爆炸；
2. 每删一个权重就要更新 Hessian 逆，朴素做法 $O(d^4)$。

SparseGPT 的全部技术贡献，就是把这两件事做得又准又快。

## 3. 关键招式一：行间共享 Hessian + 增量逆更新

### 3.1 观察：同一层所有"行"共享同一个 Hessian

线性层 $Y = WX$ 的每一**行**（输出神经元）是独立的回归问题，但它们的输入 $X$ 相同，所以 **Hessian $H = XX^\top$ 对所有行都一样**。

> 这意味着 $H$（以及它的逆）**整层只算一次**，被所有 $d_{\text{row}}$ 行复用。这是降复杂度的第一根支柱。

### 3.2 OBS 的"删一个、补一片"

OBS 给出：删掉权重 $w_q$ 时，

- 该删除带来的**误差代价**（用来决定删谁）；
- 对其余权重的**最优补偿更新**$\delta$。

二者都只依赖 $H^{-1}$。每删一个权重，理论上 $H^{-1}$ 要更新一次。朴素地反复求逆 → $O(d^3)$ 一次、删 $d$ 次 → $O(d^4)$。

### 3.3 SparseGPT 的破解：列分块 + Cholesky 复用

关键洞察：**如果我们固定一个"从左到右处理列"的顺序**，那么"删除第 $j$ 列权重时所需的 $H^{-1}$ 子块"可以由 **Hessian 的 Cholesky 分解**一次性提供，**所有行复用同一套逆信息序列**，不必每行各自做 $O(d^3)$ 的逆更新。

- 先对 $H$（加阻尼后）做一次 **Cholesky 分解**：$O(d_{\text{col}}^3)$。
- 之后按列从左到右扫，第 $j$ 步要用的 $(H^{-1})$ 相关量直接从 Cholesky 因子读取/更新。
- 误差补偿沿"未处理列"方向传播。

最终整层复杂度从 $O(d_{\text{col}}^4)$ 降到 **$O(d_{\text{col}}^3)$**，并且常数极小（一次分解 + 矩阵乘）。

```
列方向(从左到右逐块处理):

   col0 col1 col2 ... | colj ...   col_{d-1}
   [已处理: 已定掩码+已重建]  | [当前块] | [未处理: 接收误差补偿]
                                  │
                       删除/保留决策 + δ 误差
                                  └──── 沿未处理列传播 ───►
```

> 一句话：**Hessian 整层算一次、Cholesky 分解一次、按列单向扫一遍** —— 这就是它能跑 175B 的根本原因。

## 4. 关键招式二：自适应掩码选择（Adaptive Mask Selection）

精确选掩码是 NP 难。SparseGPT 用一个聪明的近似：

- **不一次性**对全层选掩码（那样后续重建无法纠偏），也**不逐权重贪心**（太慢）。
- 而是**按列分块（block，如 128 列一块）**：在每个块内部，用当前的 $H^{-1}$ 信息计算每个权重的 OBS 重要性分数，按**目标稀疏度**在块内选出要删的权重；
- 块处理完后，把误差补偿**传播到后续未处理的列**，于是下一块的掩码选择会"看到"前面剪枝造成的扰动 —— **掩码与重建相互耦合、自适应**。

```
全层 = [块1][块2][块3]...[块k]
  对每个块 b:
    1) 用当前 H^{-1} 给块内权重打分(OBS 重要性)
    2) 按稀疏度选掩码 M_b (块内删 p% )
    3) 对保留权重做最优重建 δ
    4) 误差 → 传播给 后续 块b+1..k 的权重
        (后续块据此调整，从而"补救"本块剪枝)
```

这就避免了"先全选掩码、后重建无法回头"的缺陷，又比逐权重快得多。块大小是精度/速度折中旋钮（论文用约 128）。

## 5. 关键招式三：半结构化(n:m) 与 量化 的统一

### 5.1 n:m 半结构化稀疏

NVIDIA Ampere+ 的稀疏 Tensor Core 要求 **2:4**（每连续 4 个权重里恰好 2 个非零）才能真正加速。SparseGPT 只需把"掩码选择"的约束从"全局 p%"改成"每 4 个里留 2 个"，**算法主体一字不改**，就能直接产出 2:4 / 4:8 这类硬件友好的稀疏模式。

```
非结构化 50%:  [w0  0  w2  0   0  w5 w6  0 ]  ← 灵活但需稀疏库才加速
2:4 半结构化:  [w0  0  w2  0 | 0  0 w6 w7 ]  ← 每4个留2个，Ampere 硬件直接 ~2×
```

### 5.2 与量化联合（SparseGPT + GPTQ）

因为底层都是"逐层 + Hessian + 列扫"的同一框架，**剪枝与量化可以在同一遍里联合做**：对保留下来的权重，在重建时顺便量化（GPTQ 那套），误差一起补偿。于是可得到"稀疏 + 低 bit"的双重压缩，几乎不额外掉点。这是 SparseGPT 与 GPTQ 同源的最大红利。

## 6. 实验结论（定性；数字标"约/见原文"）

> 以下为定性总结，精确数字以原论文表格为准。

- **几乎无损的 50% 非结构化稀疏**：在 OPT、BLOOM 等系列上，50% 稀疏度下困惑度（perplexity）相比稠密模型**几乎不退化**；模型越大，剪枝越"扛得住"（大模型冗余更多）。
- **碾压 Magnitude**：在高稀疏度（如 50%+）下，SparseGPT 与朴素幅值剪枝的差距**非常显著**（幅值剪枝往往直接崩，PPL 爆炸）。
- **千亿规模可行**：能在**单张 GPU、约数小时**内完成 OPT-175B / BLOOM-176B 的剪枝（见原文，约 4 小时量级），这是精确 OBS 类方法此前做不到的。
- **更高稀疏度**：可推到约 **60% 稀疏**仍保持可用精度；2:4 / 4:8 半结构化稀疏也只有温和退化。
- **可叠加量化**：与 GPTQ 联合得到稀疏 + 4bit，压缩比进一步放大，精度损失可控。

### 6.1 一个直观数值手算（量级感）

设某线性层 $d_{\text{col}} = 12288$（GPT-3 175B 的 hidden）：

- **精确 OBS** 每层 $\sim O(d^4) = 12288^4 \approx 2.3\times10^{16}$ 量级 → 单层就天文数字，全模型不可行。
- **SparseGPT** 每层 $\sim O(d^3) = 12288^3 \approx 1.85\times10^{12}$ → 比 OBS 少了约 $10^4$ 倍（一个 $d$ 因子）。

> 正是这"一个 $d$ 的因子"，把"几百年"变成了"几小时"。校准只需约 **128 条序列**，无梯度、无优化器状态，显存友好（逐层处理，不用同时放下整模型的反传图）。

## 关键公式 / 算法 / 数值示例

### (1) 逐层重建目标

$$
\widehat{W} = \arg\min_{\widehat{W}} \|WX - \widehat{W}X\|_2^2,\quad \text{s.t. } \operatorname{supp}(\widehat{W}) \subseteq M
$$

其中 $M$ 是稀疏掩码（保留位置集合）。

### (2) Hessian 与阻尼

$$
H = XX^\top + \lambda I
$$

$\lambda$（damping）保证可逆与数值稳定（如取对角均值的一个小比例）。$H$ 对该层所有行共享，只算一次。

### (3) OBS 删除代价与补偿（核心）

删除权重 $w_q$ 的**误差代价**：

$$
\varepsilon_q = \frac{w_q^2}{[H^{-1}]_{qq}}
$$

对其余权重的**最优补偿更新**：

$$
\delta = -\,\frac{w_q}{[H^{-1}]_{qq}}\,\cdot\,(H^{-1})_{:,q}
$$

> 读法：$[H^{-1}]_{qq}$ 越小（该方向越"敏感"），删它代价 $\varepsilon_q$ 越大 → 优先保留；删除后，沿 $H^{-1}$ 第 $q$ 列把误差"摊"给相关权重。

### (4) 算法骨架（伪代码）

```
输入: 权重 W(d_row×d_col), 校准激活 X, 稀疏度 p, 块大小 B
1. H ← X Xᵀ + λI
2. H⁻¹ ← Cholesky 分解得到的逆信息            # 整层一次, O(d_col³)
3. for 每个列块 b = [j, j+B):                  # 从左到右单向扫
4.     for 列块内每列 j:
5.         对所有行计算 OBS 分数 ε = w² / [H⁻¹]_jj
6.     在块内按稀疏度 p 选掩码 M_b (含 2:4 约束可选)
7.     对保留权重计算补偿 δ, 写回 W
8.     误差沿未处理列传播 (更新后续列的 W)
9. return 稀疏化(+可选量化) 后的 Ŵ
```

### (5) 复杂度对照（数值）

| 方法 | 每层复杂度 | $d=12288$ 时量级 | 175B 可行? |
|---|---|---|---|
| 精确 OBS | $O(d^4)$ | $\sim 2\times10^{16}$ | ✗ |
| **SparseGPT** | $O(d^3)$ | $\sim 1.9\times10^{12}$ | ✓（约数小时/单卡） |
| Magnitude | $O(d^2 \log d)$ | $\sim 10^9$ | ✓ 但精度崩 |

## 评价 / 对照 / 局限

| 维度 | SparseGPT | Magnitude | Wanda | LLM-Pruner |
|---|---|---|---|---|
| 用二阶信息(Hessian) | ✓ 完整 $H^{-1}$ | ✗ | 用激活范数近似(无逆) | 用梯度(一阶) |
| 权重重建/补偿 | ✓ 有 | ✗ | ✗(不更新权重) | 需少量微调恢复 |
| 计算量 | 中（$O(d^3)$） | 极低 | **极低**（无 $H^{-1}$） | 中 |
| 50% 稀疏精度 | 很强 | 崩 | 接近 SparseGPT | 依赖微调 |
| 结构/半结构化 | 非结构化 + n:m | 任意 | 非结构化 + n:m | **结构化**(整组/通道) |
| 是否需训练 | 否 | 否 | 否 | 通常需轻量微调 |

### 局限与后续

1. **非结构化稀疏 ≠ 真加速**：50% 非结构化稀疏在通用 GPU 上不一定快，要稀疏算子/库支持；只有 **2:4 半结构化**能直接吃到硬件 Tensor Core 红利。
2. **校准依赖**：重建质量依赖校准数据分布，分布漂移会损害精度。
3. **逐层贪心**：层间误差未全局联合优化，极高稀疏度（>60%）仍会明显掉点。
4. **后续工作**：**Wanda** 证明"用激活范数 × 权重幅值"就能逼近 SparseGPT 而几乎零额外计算（不解逆）；后续还有把 SparseGPT 思想与 LoRA 微调、稀疏 + 量化联合（如 SpQR、半结构化 + 4bit）结合的方向。

> 记忆锚：**SparseGPT = OBS 的精度 + GPTQ 的工程套路（逐层/Hessian/列扫/Cholesky 复用） → 让"精确剪枝"第一次在千亿规模成为现实。**
