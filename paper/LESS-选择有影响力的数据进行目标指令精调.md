## 0. 一句话锚点

**LESS = 用"训练样本梯度"和"目标任务梯度"的相似度来给每条数据打分，挑出对目标任务影响最大的少量样本来做指令微调。** 它把经典的"影响力函数(influence function)"工程化到了大模型 SFT 场景：用 LoRA 把梯度降维、用随机投影把梯度压缩成可存储可检索的"梯度指纹"，于是"我要做数学推理任务，去千万条混合指令里挑最该学的那几万条"变成了一次向量检索。

## 1. 地基：问题背景（为什么需要"挑数据"）

### 1.1 现实痛点

指令微调（SFT）的数据现在是"大杂烩"：FLAN、Dolly、Open-Assistant、CoT 集合……几百万条，覆盖翻译、对话、代码、数学、闲聊。但当你实际只关心**一个目标能力**（比如 MMLU 学科知识、或 BBH 推理、或 TyDiQA 多语问答）时：

- **不是数据越多越好**：海量数据里大部分和你的目标任务无关，甚至有害（风格冲突、噪声、错误答案）。
- **全量训练贵**：跑完几百万条要很多 GPU 小时。
- **"凭直觉选数据"不可靠**：按任务名字硬匹配（"我要数学就只留数学集"）会漏掉大量"看起来不像数学但其实有帮助"的样本（比如逻辑题、单位换算对话）。

> 核心诉求：给定**少量**目标任务的示例（几条验证样本就够），自动地、可量化地从大数据池里挑出"最该学的"子集。这就是 **targeted（有目标的）instruction tuning**。

### 1.2 已有方法的不足

| 方法 | 思路 | 问题 |
|---|---|---|
| 启发式/规则 | 按来源、长度、质量分挑 | 和"目标任务"无关，泛泛而选 |
| 表示相似度（embedding） | 选语义上像目标任务的数据 | "语义像" ≠ "训练有用"；表层相似可能学不到东西 |
| 经典影响力函数 | 用 Hessian 逆算每条数据对损失的影响 | 需要 Hessian 逆，大模型上**算不动也存不下** |

LESS 的定位：**保留影响力函数的"训练动力学"视角，但把它做到大模型上可计算、可存储、可检索。**

```
            数据池 D (几百万条混合指令)
   ┌──────────────────────────────────────────┐
   │ 翻译  对话  代码  数学  闲聊  CoT  问答 ... │
   └──────────────────────────────────────────┘
                      │  目标任务只给几条验证样本 (val)
                      ▼
        ┌───────────────────────────────┐
        │   LESS: 按"对目标任务的影响力"打分 │
        └───────────────────────────────┘
                      ▼
            只留 top-5% ──► 用这一小撮做 SFT
                      ▼
        目标任务上 ≈ 甚至 > 全量训练的效果
```

## 2. 直觉：什么叫"一条数据对目标任务有影响"

先抛公式，讲人话。

训练就是用一条样本 $z$ 算损失、求梯度、更新参数 $\theta$。更新一小步后，模型在**目标任务验证样本** $z'$ 上的损失会变好还是变坏？

- 如果用 $z$ 走一步后，$z'$ 的损失**下降** → $z$ 对目标任务**有正影响**，该选。
- 如果走一步后 $z'$ 的损失**上升** → $z$ **有害**，该丢。

而"走一步后 $z'$ 损失怎么变"，由一阶 Taylor 展开决定：**取决于两个梯度的内积（方向是否一致）**。

```
   参数空间里看：

   ∇L(z)  训练样本的梯度方向 ──►  (我往这边更新)
   ∇L(z') 目标样本的梯度方向 ──►  (它想往这边降损失)

   两个箭头夹角小(内积大)  ⇒ 学 z 顺便帮了 z'  ⇒ 影响力高，选！
   两个箭头垂直(内积≈0)   ⇒ 学 z 对 z' 无所谓   ⇒ 无关，可丢
   两个箭头反向(内积<0)   ⇒ 学 z 反而坑了 z'   ⇒ 有害，丢！
```

**一句话**：影响力 = 训练样本梯度 与 目标任务梯度 的"对齐程度"。LESS 把这个对齐程度变成可批量计算、可缓存的"梯度相似度检索"。

## 3. 影响力公式：从 SGD 一步推导

记目标任务验证集为 $\mathcal{D}_{\text{val}}$，单步 SGD 用训练样本 $z$、学习率 $\eta$ 更新：
$$\theta_{t+1} = \theta_t - \eta \, \nabla \ell(z; \theta_t)$$

目标任务损失 $\ell(z'; \theta)$ 在更新前后的变化，一阶 Taylor 展开：
$$\ell(z'; \theta_{t+1}) - \ell(z'; \theta_t) \approx \nabla \ell(z'; \theta_t)^\top (\theta_{t+1} - \theta_t) = -\,\eta \, \nabla \ell(z'; \theta_t)^\top \nabla \ell(z; \theta_t)$$

损失"下降量"就是 $\eta \cdot \langle \nabla\ell(z'),\, \nabla\ell(z)\rangle$。于是定义**单步影响力**：
$$\mathrm{Inf}(z, z') \;=\; \eta \,\big\langle \nabla \ell(z; \theta_t),\; \nabla \ell(z'; \theta_t)\big\rangle$$

**LESS 的关键工程化处理：用余弦相似度（cosine）而非原始内积。** 原始内积会被梯度范数（样本"信息量大小"）支配，长样本/难样本梯度大就被无脑高估。改成余弦：
$$\mathrm{Inf}_{\cos}(z, z') = \eta \cdot \frac{\big\langle \nabla \ell(z),\, \nabla \ell(z')\big\rangle}{\|\nabla \ell(z)\|\,\|\nabla \ell(z')\|}$$

只看"方向是否对齐"，剔除范数干扰，跨样本可比性更好。

### 3.1 从单步到整段训练

真实训练是多步、多个 epoch 的。LESS 在 **warmup 训练的多个 checkpoint** $\{\theta_1,\dots,\theta_N\}$ 上分别算梯度并累加（带每个 checkpoint 的学习率 $\bar\eta_i$）：
$$\mathrm{Inf}(z,\, \mathcal{D}_{\text{val}}) = \sum_{i=1}^{N} \bar\eta_i \cdot \frac{1}{|\mathcal{D}_{\text{val}}|}\sum_{z'\in\mathcal{D}_{\text{val}}} \cos\!\big(\Gamma(z;\theta_i),\, \Gamma(z';\theta_i)\big)$$

其中 $\Gamma(\cdot)$ 是下文要讲的"压缩后的梯度特征"。**对每条候选 $z$ 算出一个标量分数，排序取 top-k 即为选中的训练子集。**

## 4. 工程核心：LoRA 梯度 + 随机投影（让梯度存得下、检索得动）

### 4.1 为什么不能直接用全参数梯度

7B 模型有约 70 亿参数，**一条样本的梯度就是 70 亿维向量**。数据池几百万条，存梯度 = 几百万 × 70 亿 × 4字节 → 天文数字，存不下也算不动。两层降维：

**降维一：LoRA。** warmup 阶段只训 LoRA 适配器（每层加低秩 $A,B$，秩 $r$ 很小，如 8/16）。这样**可训练参数从 70 亿降到几百万**，梯度只取 LoRA 部分，维度骤降。同时 LoRA 梯度被论文论证为对"完整训练动力学"的良好近似。

**降维二：随机投影（Random Projection / Johnson–Lindenstrauss）。** 即便 LoRA 梯度仍有百万维，再乘一个固定的随机高斯矩阵 $R \in \mathbb{R}^{d \times k}$（$k$ 取几千，如 8192），投到低维：
$$\Gamma(z) = R^\top g(z), \qquad g(z)=\text{LoRA 梯度},\; k \ll d$$

JL 引理保证：随机投影**近似保持向量间的内积/距离**，所以低维上算的余弦相似度 ≈ 高维上的真实相似度。于是每条样本变成一个 ~几千维的"梯度指纹"，可以像 embedding 一样存进向量库、批量检索。

```
   全参数梯度 70亿维  ──LoRA──►  百万维(只训低秩适配器)
                                     │
                                ──随机投影 R──►  ~8192维 "梯度指纹"
                                     │
                       存入梯度库 (每条样本一个向量, 可检索)
```

### 4.2 显存/存储账（直观感受降维威力）

以 7B、float32 估算（数量级，非精确）：

| 表示 | 单条梯度维度 | 单条占用 | 100万条占用 |
|---|---|---|---|
| 全参数梯度 | ~7×10⁹ | ~28 GB | 不可行 |
| LoRA 梯度(r=8) | ~10⁶~10⁷ | ~数十 MB | ~数十 TB(仍大) |
| 随机投影后 | ~8192 | ~32 KB | ~32 GB(可存可检索) |

> 数字为数量级示意，实际取决于 LoRA 配置与投影维度，以原文/代码为准。关键是：**两级降维把"不可行"变成了"几十 GB 的向量库 + 一次检索"。**

## 5. 完整流程：四步走

```
┌─ Step 1: Warmup 训练 ──────────────────────────────┐
│ 用数据池的一个小随机子集，LoRA 训几个 epoch，         │
│ 沿途存若干 checkpoint θ₁..θ_N (拿到"训练动力学")      │
└────────────────────────────────────────────────────┘
                       │
┌─ Step 2: 建梯度库 ─────────────────────────────────┐
│ 对池中【每条】候选样本 z，在各 checkpoint 上算 LoRA   │
│ 梯度 → 随机投影 → 得"梯度指纹" Γ(z)，全部缓存         │
└────────────────────────────────────────────────────┘
                       │
┌─ Step 3: 算目标任务梯度 ──────────────────────────┐
│ 对目标任务的【少量验证样本】z'，同样算 LoRA 梯度→投影  │
│ → 得 Γ(z')。注意:这里用验证样本的【真实标签损失】梯度  │
└────────────────────────────────────────────────────┘
                       │
┌─ Step 4: 打分 + 选 top-k + 训练 ──────────────────┐
│ 对每条 z 算 cos(Γ(z), Γ(z')) 累加成影响力分数 →       │
│ 排序取 top-5% → 用这一小撮做最终 SFT(可全参或 LoRA)  │
└────────────────────────────────────────────────────┘
```

几个易踩的点：
- **Step 1 的 warmup 必须做**：没有训练动力学就没有"有意义的梯度方向"，直接用初始模型梯度选数据效果差。
- **Step 3 用的是验证样本梯度**：训练样本的损失是"预测下一个 token"，验证样本梯度同样如此，二者在同一参数空间可比。
- **梯度库一次建好可复用**：换目标任务只需重做 Step 3、4（重算验证梯度 + 检索），候选梯度库不用重建——这是 LESS 省钱的关键之一。

## 6. Adam 修正：为什么"原始梯度"不够

§3 的推导假设是 **SGD**（沿 $-\nabla\ell$ 更新）。但真实 SFT 几乎都用 **Adam**，Adam 的实际更新方向不是原始梯度，而是经过一阶矩 $m$、二阶矩 $v$ 修正后的方向：
$$\Delta\theta \;\propto\; -\,\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon}$$

如果还拿原始梯度算相似度，就和"模型真正怎么动"对不上了。LESS 的处理：**用 Adam 的实际更新方向（带 $m,v$ 修正）代替原始梯度** 来构造 $\Gamma(z)$，让影响力估计与真实优化器一致。这是论文一个重要的"对齐真实训练"的细节——直接用裸梯度会显著掉点。

```
   SGD 视角:   更新方向 = -∇ℓ            ← §3 的天真公式
   Adam 现实:  更新方向 = -m̂/(√v̂+ε)     ← 必须用这个算相似度
                 │
                 └─ 否则"算出来的影响力"和"实际训练效果"脱节
```

## 关键公式 / 算法 / 数值示例（汇总）

**核心打分公式**（每条候选 $z$ 得一个标量）：
$$\mathrm{Score}(z) = \sum_{i=1}^{N}\bar\eta_i \cdot \frac{1}{|\mathcal D_{\text{val}}|}\sum_{z'\in\mathcal D_{\text{val}}}\cos\big(\Gamma_i(z),\,\Gamma_i(z')\big)$$

**算法伪代码（精简）**：
```
输入: 数据池 D, 目标验证集 Val, checkpoint 数 N, 投影维 k, 选取比例 p
1. warmup: 在 D 的小子集上 LoRA 训练, 存 θ₁..θ_N 及各自学习率 η̄ᵢ
2. for 每个 z in D:               # 建梯度库 (一次性, 可复用)
     for i in 1..N:
        g ← Adam修正后的LoRA梯度(z; θᵢ)
        Γᵢ(z) ← Rᵀ g             # 随机投影到 k 维, 单位化
3. for 每个 z' in Val:            # 目标任务梯度
     for i in 1..N: Γᵢ(z') ← Rᵀ·Adam修正梯度(z'; θᵢ)
4. for 每个 z in D:
     Score(z) ← Σᵢ η̄ᵢ · mean_{z'} cos(Γᵢ(z), Γᵢ(z'))
5. 选 Score 最高的 p 比例样本 → 作为最终 SFT 训练集
```

**手算小例（理解余弦打分）**：设某 checkpoint 上
- 候选 A 的梯度指纹 $\Gamma(A)=(0.9, 0.1, 0.0)$，目标梯度 $\Gamma(z')=(1,0,0)$ → $\cos\approx 0.99$ → **高分，选**。
- 候选 B 的 $\Gamma(B)=(0.0, 0.0, 1.0)$ → $\cos = 0$ → **无关，丢**。
- 候选 C 的 $\Gamma(C)=(-1,0,0)$ → $\cos=-1$ → **有害，丢**。

即便 B、C 在文本上看起来都"像"目标任务（embedding 相似），梯度视角能识别出它们对训练**没用甚至有害**——这正是 LESS 胜过"表示相似度选数据"的根因。

**FLOPs 直觉账**：建梯度库要对 D 全过一遍前/反向（一次性成本，但可摊销到多个目标任务）；之后每个新目标任务只需对 Val（几条~几十条）算梯度 + 一次 top-k 检索，**几乎免费**。相比全量 SFT 重复跑数百万条数据，整体训练算力大幅下降。

## 评价 / 对照 / 局限

| 维度 | LESS 表现 | 说明 |
|---|---|---|
| 数据效率 | 仅用约 **5%** 数据，常追平甚至超过全量 SFT | 数字见原文；不同任务/模型有波动 |
| vs 随机选 / embedding 选 | 在 MMLU、BBH、TyDiQA 等目标任务上稳定更优 | 梯度对齐 > 语义相似 |
| 可迁移性 | 用**小模型**算出的数据选择，可迁移去训**大模型/不同模型** | 梯度特征跨模型有共性，省去为大模型重建梯度库 |
| 可解释性 | 选出的样本人工看常"确实和目标任务相关" | 定性观察，见原文 |

| 局限 / 注意 | 细节 |
|---|---|
| warmup 与梯度库有前置成本 | 一次性，但要算法力；目标任务越多越划算 |
| 依赖少量目标验证样本 | 验证样本要能代表目标任务，否则选偏 |
| 一阶近似 | Taylor 一阶 + 余弦近似，忽略高阶交互；是估计不是精确影响 |
| LoRA/投影是近似 | 用 LoRA 梯度近似全参动力学、JL 投影近似内积，均有误差 |
| 目标须明确 | 适合"我知道要做什么任务"的 targeted 场景；通用能力提升不一定是它的主场 |

### 对工程的启示

1. **"挑数据"是被低估的杠杆**：与其无脑堆数据/堆算力，不如花一次性成本做数据筛选，常常更省更好。
2. **梯度是通用的"数据画像"**：比 embedding 更贴近"训练是否有用"。这套思路可迁移到预训练数据筛选、毒性数据剔除、课程学习排序。
3. **降维三件套可复用**：LoRA 降参 + 随机投影降维 + 余弦去范数，是把"理论上算不动的影响力函数"工程化的通用配方。
4. **跨模型迁移省钱**：小模型选数据 → 大模型用，呼应了"代理模型(proxy model)"的实践范式。
