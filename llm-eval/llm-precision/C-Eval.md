## 0. 一句话锚点

**C-Eval 做的事**：给中文模型 N 道四选一选择题 → 模型选一个字母（A/B/C/D）→ 用「选对=1，选错=0」打分 → 求平均 = 一个百分数。

$$\text{Acc} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}\big[\hat{y}_i = y_i\big]$$

其中 $\hat{y}_i$ 是模型对第 $i$ 题给出的选项，$y_i$ 是标准答案，$\mathbb{1}[\cdot]$ 是「指示函数」（条件成立取 1，否则取 0）。

一切复杂性藏在三处：① **题怎么出**（中文、覆盖哪些学科）② $\hat{y}_i$ **怎么从模型掏出来**（看 logprob 还是解析文本）③ **怎么对比**（精确匹配字母）。看懂这三点，就知道「C-Eval 78 分」到底意味着什么。

## 1. 地基：为什么需要一个「中文版 MMLU」

### 1.1 问题的根源

早期英文评测霸主是 **MMLU**（Massive Multitask Language Understanding，5.7 万道英文四选一题，覆盖 57 学科）。但拿它评中文模型有两个硬伤：

- **语言不匹配**：MMLU 是英文题，评的是「模型用英文做题的能力」，不是中文能力。
- **知识不匹配**：英文题里没有「中国的行政法」「中医基础」「毛泽东思想」这类**中国语境专属知识**——而这恰恰是中文模型最该会、用户最常问的。

```
        英文题              中文题（C-Eval）
   ┌──────────────┐     ┌────────────────────┐
   │ US history    │ ❌  │ 中国近代史          │
   │ US law (bar)  │ ❌  │ 中国法律 / 注册会计师│
   │ Western phil. │ ❌  │ 马克思主义原理       │
   │ —            │     │ 中医 / 兽医 / 导游    │
   └──────────────┘     └────────────────────┘
   评「英文知识」          评「中文 + 中国语境知识」
```

### 1.2 C-Eval 的身份证

| 维度 | 取值（以官方为准） |
|------|------|
| 全称 | C-Eval: A Multi-Level Multi-Discipline Chinese Evaluation Suite |
| 发布 | 2023 年，清华 / 上交 / 爱丁堡大学等联合 |
| 题型 | 四选一单选题（single-choice MCQ） |
| 题量 | 约 **13948** 题 |
| 学科 | **52** 个学科 |
| 四大类 | STEM / 社会科学 / 人文 / 其他 |
| 难度档 | 中学 / 大学 / 专业（含研究生、职业资格考试） |
| 衍生 | **C-Eval Hard**：从理科里挑出最难的 8 个学科 |

> 一句话：**C-Eval 就是「用中国教育体系真题，给中文模型出的一张高考+考研+职业资格的混合卷子」**。

```
   │ 高等数学     │ 政治         │ 法学         │ 临床医学      │
   │ 大学物理     │ 经济学       │ 中国语言文学 │ 消防工程      │
   │ 大学化学     │ 教育学       │ 历史         │ 注册税务师    │
   │ 计算机       │ 地理         │ 逻辑学       │ 环境影响评价  │
   │ 电气工程     │ 工商管理     │ 艺术         │ 兽医 / 体育   │
   │ ...         │ ...         │ 思想道德修养 │ 导游 / 中医   │
   └─────────────┴─────────────┴─────────────┴──────────────┘
   STEM：科学、技术、工程、数学，强推理
   社科：政治/地理/教育/经济/工商管理 等
   人文：法律/艺术/逻辑/语文/历史 等
   其他：环境/消防/税务/体育/医学 等学科汇总
```

- **STEM**：科学、技术、工程和数学，包含计算机、电气工程、化学、数学、物理等——**最考推理**，也是 Hard 子集的来源。
- **Social Science（社会科学）**：政治、地理、教育学、经济学、工商管理等——**考中国制度/政策知识**。
- **Humanity（人文）**：法律、艺术、逻辑学、语文、历史等——**考中文语言与文化**。
- **Other（其他）**：环境、消防、税务、体育、医学等学科的汇总——**考职业资格 / 实务知识**。

### 2.2 难度梯度：从中学到职业资格

C-Eval 故意覆盖**三个难度层级**，这样一条曲线能拉开模型差距：

```
  难度  ┌─ 专业级（注会/律考/医师/考研）  ← 最难，C-Eval Hard 多在这
        │
        ├─ 大学级（高数/大学物理/专业课）
        │
        └─ 中学级（高中数理化/文综）       ← 最易
```

### 2.3 数据划分：dev / val / test

```
   每个学科都切成三块：
   ┌──────────┬──────────────────────────────────┐
   │ dev      │ 每科 5 题，且带「解析」           │
   │ (开发集) │  → 专门给 few-shot 当示例用        │
   ├──────────┼──────────────────────────────────┤
   │ val      │ 验证集，带答案，可本地调试         │
   │ (验证集) │  → 自己跑分、调 prompt            │
   ├──────────┼──────────────────────────────────┤
   │ test     │ 测试集，「答案不公开」            │
   │ (测试集) │  → 提交到官方榜单评分（防作弊）    │
   └──────────┴──────────────────────────────────┘
```

**为什么这样设计**：test 答案不公开 = 你**没法把测试题的答案塞进训练数据**去刷分（缓解数据污染）。dev 每科恰好 5 题 = 天然支持 **5-shot**。

## 3. 一条样本的生命周期：从题目到 0/1

一条 C-Eval 样本的原始结构约等于：

```
id       : 0
question : "下列关于氢原子光谱的说法，正确的是____"
A        : "巴尔末系属于可见光"
B        : "莱曼系属于红外光"
C        : "..."
D        : "..."
answer   : "A"          # test 集此字段对外隐藏
explanation : "氢原子……"   # 仅 dev 集有
```

评测框架把它「渲染」成模型能读的 prompt，再把模型输出「抽取」成可比对的字母：

```
┌──────────── 一条 C-Eval 样本的生命周期 ───────────┐
│                                                   │
│  原始 {question, A, B, C, D, answer}              │
│        │  ① 模板渲染（中文 prompt）               │
│        ▼                                          │
│  "以下是中国关于大学物理的单项选择题。            │
│   题目：下列关于氢原子光谱…                       │
│   A. 巴尔末系属于可见光                           │
│   B. 莱曼系属于红外光 … 答案："                   │
│        │  ② 模型前向 / 生成                        │
│        ▼                                          │
│  输出（logprob over A/B/C/D，或文本 "A"）         │
│        │  ③ 答案抽取                              │
│        ▼                                          │
│  ŷ = "A"  ──比对──  y = "A"  → 1（对）             │
└───────────────────────────────────────────────────┘
```

注意第①步那句**「以下是中国关于 X 的单项选择题」**——这是 C-Eval 官方约定的中文模板，明确告诉模型「这是中国语境」，能显著影响中文模型的表现。

## 4. few-shot 与 CoT：为什么影响分数

### 4.1 few-shot（少样本提示）是什么

**few-shot** = 在真正要答的题前面，先放 $k$ 道**已经带答案的例题**，让模型「照葫芦画瓢」。C-Eval 标准设定是 **5-shot**（正好用 dev 集每科的 5 道题）。

```
  0-shot（直接问）        5-shot（先给 5 个范例）
  ┌──────────┐          ┌────────────────────────┐
  │ 题目 X    │          │ 例题1 …答案A           │
  │ 答案：    │          │ 例题2 …答案C           │
  └──────────┘          │  …（共5个）            │
                        │ 题目 X                  │
                        │ 答案：                  │
                        └────────────────────────┘
```

**为什么 few-shot 抬分**：例题把「答案就输出一个字母」这个**格式**示范给了模型，模型更不容易跑偏（少输出「我认为应该是…」这种废话），答案抽取更干净 → 准确率上升。这是「能力没变、但分数变高」的典型——所以**比较模型必须固定同样的 shot 数**，否则不公平。

### 4.2 CoT（思维链）是什么

**CoT（Chain-of-Thought）** = 让模型「答案：」之前**先写推理过程**，最后才给字母。对 STEM 这类需要计算/推导的题，CoT 通常能涨分；对纯记忆题（如历史年代）几乎无用。

```
  Answer-only:  "答案：A"
  CoT:          "氢原子巴尔末系跃迁到 n=2，
                 波长在可见光区 …
                 故选 A。答案：A"
                 ↑ 中间过程帮模型「算对」
```

> 实践要点：C-Eval 官方榜单同时给 **answer-only** 和 **CoT** 两套分数。**比榜单时一定看是哪种模式**——拿你的 CoT 分去比别人的 answer-only 分，等于作弊。

## 5. 答案怎么抽取：选项字母 vs 生成文本

同一道题，**怎么从模型掏出 $\hat{y}$** 有两条主流路线，分数可能差好几个点：

```
   路线 A：logprob 打分（适合 base / 开源权重）
   ┌────────────────────────────────────────┐
   │ 把 prompt 末尾分别接 "A"/"B"/"C"/"D"     │
   │ 取模型对这 4 个字母的对数概率            │
   │ ŷ = argmax  →  天然只会落在 A~D，不跑偏 │
   └────────────────────────────────────────┘

   路线 B：生成 + 正则抽取（适合 chat / API）
   ┌────────────────────────────────────────┐
   │ 让模型自由生成文本，如 "我选 A 因为…"   │
   │ 用正则 / 规则从中扒出第一个 A~D          │
   │ 风险：模型不输出字母 → 抽取失败 → 判错  │
   └────────────────────────────────────────┘
```

- **路线 A（logprob）**：只能用于你**拿得到 logits** 的模型（本地开源权重）。优点是**永远落在 4 个选项内**，没有「格式跑偏」损失。
- **路线 B（生成抽取）**：闭源 API（只给文本）只能走这条。难点是**抽取规则**——模型若回「这道题应该选第二个」而不写字母，正则就抓瞎，可能误判为错。这也是为什么**同一个模型，不同评测框架跑出的 C-Eval 分会差 2~5 分**：差在抽取实现。

> 因此看分数要连**评测框架**一起看（如 OpenCompass、官方脚本、lm-eval-harness），见 [[llm-eval/大模型测评集]]。

## 6. C-Eval vs MMLU vs CMMLU

三者都是「四选一学科知识题」，但定位不同：

```
            语言    知识来源        与中国语境
  MMLU      英文    美国教育/考试    几乎无关
  C-Eval    中文    中国教育/考试    强（含思政/职业资格）
  CMMLU     中文    中国本土知识     强（更偏文化/常识/本土）
```

| 维度 | MMLU | C-Eval | CMMLU |
|------|------|--------|-------|
| 语言 | 英文 | 中文 | 中文 |
| 题量(约) | 57 学科 / 1.4万+ | 52 学科 / 1.4万 | 67 学科 / 1.1万+ |
| 答案是否公开 | 公开 | **test 不公开** | 公开 |
| 关键差异 | 英文知识基准 | 中国学科真题，难度分级 | 更强调**中国本土/文化常识**，无难度分级 |
| 翻译题? | — | **原生中文出题** | **原生中文出题** |

**关键认知**：

- C-Eval 与 CMMLU **不是翻译版 MMLU**，它们是**原生中文命题**——题目本身就是中文真题，不是把英文题机翻过来（机翻会丢中国专属知识）。
- C-Eval 和 CMMLU 经常**一起用**：C-Eval 偏「学术/职业资格的硬知识与推理」，CMMLU 偏「本土文化/生活常识」，两者互补，能更全面刻画中文能力。
- 一个中文模型常见的报告写法：**「MMLU xx / C-Eval xx / CMMLU xx」**三件套并列，分别代表「英文知识 / 中文学术知识 / 中文本土知识」。

## 7. 榜单怎么读：Avg / Hard / 子类

C-Eval 官方榜单（leaderboard）不止一个数，至少看四层：

```
   ┌─ Average（总平均）   ← 媒体最爱报的「C-Eval 78 分」
   │
   ├─ Avg(Hard)          ← C-Eval Hard 子集，理科最难 8 科
   │                        真正拉开强弱，远低于总分
   │
   ├─ 四大类分项          ← STEM / 社科 / 人文 / 其他
   │                        看模型「偏科」在哪
   │
   └─ 模式标注            ← answer-only 还是 CoT，5-shot 还是 0-shot
```

**读榜三原则**：

1. **总分高 ≠ 真强**：很多模型总分 70+，但 **Hard 子集可能只有 40 多**——说明它会的是「记忆型简单题」，一到要推理就崩。**Hard 才是分水岭**。
2. **看四大类是否均衡**：一个模型若 STEM 低、人文高，说明**强记忆弱推理**。
3. **对齐评测条件**：两个模型可比，前提是**同 shot 数、同模式（CoT/answer-only）、同框架**。榜单混排时务必看标注。

## 8. 局限：污染 / 偏科 / 单选天花板

C-Eval 强，但有四个必须知道的坑：

```
  ① 数据污染（contamination）
     题目源自公开教辅/真题 → 可能已被爬进预训练语料
     → 模型「背过答案」而非「会做」→ 虚高
     缓解：test 答案不公开，但题面仍可能被见过

  ② 单选题天花板
     只有 A/B/C/D，蒙也有 25% → 衡量「精确表达/生成」能力为 0
     真实场景要写代码/作文/对话，单选测不出来

  ③ 偏科与刷分
     针对榜单「应试微调」→ 选择题专精，泛化未必好
     （类似「只会做高考题的学生」）

  ④ 静态 + 中文知识时效
     题库固定，知识随时间过时；不评多轮对话/工具调用/安全
```

- **数据污染**：C-Eval 题来自真实考试/教辅，很可能已混进各家预训练语料；模型可能是「见过原题」而非真会。test 答案不公开只能挡住「直接训练答案」，挡不住「训练了题面」。
- **单选 ≠ 真实能力**：四选一只考「辨认正确选项」，**完全测不出生成、推理链条、表达、安全**。一个 C-Eval 90 分的模型，可能连一段通顺的中文摘要都写不好。
- **正确姿势**：C-Eval 只是「中文知识广度」的一把尺，**必须和生成类（MT-Bench/AlpacaEval）、推理类（GSM8K/MATH）、安全类一起看**，单看一个数会被骗。详见 [[llm-eval/大模型测评集]] 的「为什么榜单会骗人」。

## ★ 数值例子：准确率 + 随机基线手算

### 例 1：随机基线为什么是 25%

四选一题，乱蒙每题答对概率 $p=\frac{1}{4}=0.25$。所以**任何模型 C-Eval 低于 25% 都不正常**（说明答案抽取坏了或模型反着答）。

$$\text{随机基线} = \frac{1}{\text{选项数}} = \frac{1}{4} = 25\%$$

### 例 2：算一个学科的准确率

设「大学物理」共 200 题，模型答对 146 题：

$$\text{Acc}_{\text{物理}} = \frac{146}{200} = 0.73 = 73\%$$

### 例 3：四大类加权平均 → 总分

C-Eval 总分是**各题等权平均**（不是各类简单平均）。设四类题数与对数如下：

```
  类别    题数 Nᵢ   答对 cᵢ
  STEM     5000     3300
  社科     3000     2400
  人文     3000     2250
  其他     2948     2100
  ────────────────────────
  合计    13948     10050
```

$$\text{Acc}_{\text{Avg}} = \frac{\sum_i c_i}{\sum_i N_i} = \frac{10050}{13948} \approx 0.7206 = 72.1\%$$

> 注意：因为是**按题加权**，题多的 STEM 对总分影响更大。若改成「四类各占 25%」的简单平均，结果会不同——**看榜时要确认它用的是哪种平均**。

### 例 4：Hard 子集为什么暴露真实力

设总分 72.1%，但 C-Eval Hard（理科最难 8 科，约 N=2000 题）只答对 860：

$$\text{Acc}_{\text{Hard}} = \frac{860}{2000} = 43\%$$

总分 72 → Hard 43，**29 个点的落差**正是「记忆强、推理弱」的铁证。这就是为什么**专家只盯 Hard 看**。

| 最大局限 | 单选 + 可能污染，测不出生成/推理/安全 |

### 高频面试题

| 问 | 答 |
|----|----|
| C-Eval 和 MMLU 啥关系？ | 同为四选一学科基准；MMLU 英文、C-Eval 中文原生命题，不是翻译，且 C-Eval 含中国专属知识与难度分级。 |
| C-Eval 和 CMMLU 怎么选？ | 一起用：C-Eval 偏学术/职业资格硬知识，CMMLU 偏本土文化常识，互补。 |
| 为什么 5-shot 比 0-shot 高？ | 例题示范了「只输出字母」的格式，答案抽取更干净，能力没变但分数升。 |
| 为什么不同框架跑出的 C-Eval 分不一样？ | 主要差在**答案抽取**（logprob vs 生成正则）和 shot/模式设定。 |
| 为什么看 C-Eval 要看 Hard？ | 总分含大量简单题，易被记忆刷高；Hard（理科最难 8 科）才考真推理，落差暴露真实力。 |
| C-Eval 高就代表模型强吗？ | 不。单选测不出生成/对话/安全，且可能数据污染；须与生成类、推理类、安全类一起看。 |
| test 集为什么不公开答案？ | 防止把测试答案塞进训练数据刷分，缓解数据污染。 |
| C-Eval 随机基线多少？ | 25%（四选一），低于此说明评测实现出了问题。 |
