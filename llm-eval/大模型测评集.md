## 0. 一句话锚点

**测评集做的事**：给模型 N 道题 → 模型作答 → 用规则把答案变成 0/1（或分数）→ 求平均 = 一个百分数。

$$\text{Score} = \frac{1}{N}\sum_{i=1}^{N} \text{metric}(\hat{y}_i,\, y_i)$$

一切复杂性都藏在三个地方：① 题怎么出（覆盖什么能力）② $\hat{y}_i$ 怎么从模型「掏」出来 ③ `metric` 怎么判对错。看懂这三点，就不会被「90 分」唬住。

## 1. 地基：一条评测样本长什么样

最小单元是一条「样本（example）」。以 MMLU 一道题为例，原始数据约等于：

```
question : "What is the capital of France?"
choices  : ["Berlin", "Paris", "Rome", "Madrid"]
answer   : 1            # 下标，1=Paris
```

评测框架要把它「渲染」成模型能读的字符串（prompt），再把模型输出「抽取」成可比对的预测：

```
┌──────────── 一条样本的生命周期 ────────────┐
│                                            │
│  原始数据 {q, choices, answer}             │
│        │  ① 模板渲染 (prompt template)     │
│        ▼                                   │
│  "Question: ...\nA. Berlin\nB. Paris       │
│   C. Rome\nD. Madrid\nAnswer:"             │
│        │  ② 模型前向 / 生成                 │
│        ▼                                   │
│  模型输出 (logprobs 或 文本 "B")           │
│        │  ③ 答案抽取 (extract)             │
│        ▼                                   │
│  ŷ = "B"  ──比对──  y = "B"  → 1 (对)      │
└────────────────────────────────────────────┘
```

> 关键直觉：**同一个模型、同一道题，换一个模板或抽取规则，分数能差 5~15 个点**。所以「裸分」无意义，必须说清楚「在哪个框架、什么设置下」。

## 2. 评分机制：选择题到底怎么算对错

选择题（MMLU/C-Eval/CMMLU 等）有两条主流判分路线，结果可能不同，必须分清。

### 2.1 路线 A：logprob / likelihood（OpenCompass、lm-eval-harness 常用）

不让模型「写」答案，而是把 4 个选项分别拼到 prompt 后面，比较模型对每个完整句子的对数似然，谁高选谁。

设候选 token 为 `A B C D`，模型在 `Answer:` 处给出各自的对数概率：

```
choice   logprob
  A      -3.10
  B      -0.92   ← 最大 → 预测 B
  C      -4.40
  D      -2.85
```

为什么用 logprob：① 不依赖模型「肯不肯按格式输出字母」，base 模型也能测；② 完全确定性、可复现。代价：偏「填空式」，和真实对话场景脱节。

### 2.2 路线 B：生成 + 正则抽取（generation-based）

让模型真的生成文本，再用正则把字母抠出来：

```
模型输出: "The answer is B. Paris is the capital."
正则 r"answer is ([A-D])" → 抽到 "B" → 对
```

风险：模型若回答 "It's Paris"（没写字母）或格式跑偏，可能被判错——**这是「会但没说对格式」导致的分数损失**，不是能力问题。

### 2.3 两条路线对比

```
            logprob 路线          生成路线
能测 base?    ✅                   ❌(需指令跟随)
确定性        高(贪心也稳)         受采样/格式影响
贴近真实使用  低                   高
对格式敏感    无                   非常敏感
```

## 3. few-shot 与 CoT：为什么同一模型分数能差很多

### 3.1 few-shot（少样本/上下文示例）

在题目前先塞几道「带答案的范例」，让模型现学格式与套路。`5-shot` 就是塞 5 个示例：

```
[示例1: 题+答案]
[示例2: 题+答案]
 ... (共 5 个)
[真正要答的题]
Answer:
```

- **为什么有用**：示例锚定了输出格式（让答案更易抽取）+ 激活相关知识 + 校准答题风格。
- **为什么影响公平**：示例选哪几道、放什么顺序都会改变分数。所以报告必须写明 `k`-shot（如 MMLU 标准是 5-shot）。**0-shot 和 5-shot 不能直接比。**

### 3.2 CoT（Chain-of-Thought，思维链）

让模型先写推理过程再给答案（"Let's think step by step"）。对数学/多步推理（GSM8K、MATH、BBH）能大幅提分，对纯知识题（MMLU）提升有限甚至无。

```
无 CoT:  "Answer: 18"                        (错的概率高)
有 CoT:  "She has 5, buys 3 boxes×... = 18"  (中间步骤纠错)
```

> 面试陷阱：看到「GSM8K 80 分」要追问「CoT 还是直接答？few-shot 几个？」——设置不同，可比性归零。

## 4. 学科知识类：MMLU / C-Eval / CMMLU

**考什么**：背景知识 + 概念理解，覆盖广学科，4 选 1。

| 集 | 语言 | 规模/学科 | 标准设置 | 备注 |
|----|------|-----------|----------|------|
| **MMLU** | 英文 | 57 学科约 1.4 万题 | 5-shot | 事实上的英文知识基线 |
| **MMLU-Pro** | 英文 | 10 选 1、更难 | 5-shot CoT | 抗蒙、抗污染加强版 |
| **C-Eval** | 中文 | 52 学科约 1.3 万题 | 5-shot | 含 C-Eval Hard 子集 |
| **CMMLU** | 中文 | 67 学科 | 5-shot | 中国语境知识（法律/医学等） |
| **AGIEval** | 中英 | 人类考试（高考/法考/SAT） | 0/few-shot | 真实考试题 |

**C-Eval Hard**：从 C-Eval 选 8 个含复杂 LaTeX 公式、需多步推理的理科科目（高数、离散数学、概率统计、大学/高中物理化学），单独成基准，专测难推理。

为什么 4 选 1：随机猜的基线是 $1/4=25\%$。所以**任何 MMLU 分数都要减去 25 的「地板」来体会真实水平**——50 分其实只比瞎猜好一点。

```
能力轴示意:
 25 ─────── 60 ─────── 85 ──── 100
 瞎猜      及格线     强模型   满分
  ▲                    ▲
随机基线            当前一线大模型区间
```

## 5. 数学/通用推理类：GSM8K / MATH / BBH

**考什么**：多步数值/逻辑推理，答案唯一，靠 exact match（精确匹配）判分。

| 集 | 难度 | 形式 | 判分 |
|----|------|------|------|
| **GSM8K** | 小学应用题 | 8.5k 题，需 2~8 步算术 | 抽最终数字 == 标准答案 |
| **MATH** | 竞赛数学 | 含 LaTeX 表达式 | 表达式等价匹配 |
| **BBH** (Big-Bench Hard) | 23 类硬任务 | 逻辑/符号/时序 | exact match，常配 CoT |

GSM8K 判分细节：模型输出末尾常用 `#### 18` 标记答案，框架正则 `r"####\s*(-?\d+)"` 抽数字比对：

```
标准答案: "... #### 18"
模型输出: "...so the total is 18.\n#### 18"
抽取 → 18 == 18 → ✅
```

**陷阱**：若模型写 "18 dollars" 或 "eighteen"，正则抠不到纯数字 → 误判为错。这是「抽取规则」而非「数学能力」的失分，工业评测里需鲁棒的数值归一化。

## 6. 代码类：HumanEval / MBPP —— pass@k 全解

**考什么**：根据函数签名 + docstring 写出函数体，用**单元测试**判对错（不是比对文本！）。

```
┌── HumanEval 一题 ──┐
│ def add(a, b):     │  ← 给签名+注释
│   """返回 a+b"""    │
│   <模型补全这里>    │
└────────────────────┘
        │ 生成 n 个候选
        ▼
   逐个跑隐藏测试用例
        │
        ▼
   只要有用例不过 → 该候选 fail
```

| 集 | 规模 | 语言 | 判分 |
|----|------|------|------|
| **HumanEval** | 164 题 | Python | 跑测试用例 |
| **MBPP** | ~974 题 | Python（更基础） | 跑测试用例 |
| **HumanEval+/MBPP+** | 同上 | 加超多测试用例 | 抗「蒙混过关」 |

### pass@k 是什么、为什么这样算

`pass@k` = 「每题生成 k 个答案，只要有 1 个通过全部测试，就算这题对」的期望通过率。但直接采 k 个方差大，论文用**无偏估计**：每题先生成 $n$ 个（$n>k$），其中 $c$ 个正确，则

$$\text{pass@}k = \mathbb{E}\Big[\,1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}\,\Big]$$

含义：$\binom{n-c}{k}/\binom{n}{k}$ = 抽 k 个**全是错**的概率，1 减去它 = 至少有 1 个对。逐数手算见 ★。

## 7. 开放生成 + 裁判模型：MT-Bench / AlpacaEval

前面的题都有「唯一答案」。但「帮我写封道歉邮件」没有标准答案——这类**开放生成**靠 **LLM-as-Judge（裁判模型）** 打分。

| 集 | 形式 | 判分 |
|----|------|------|
| **MT-Bench** | 80 道多轮对话题 | 强模型（如 GPT-4）打 1~10 分 |
| **AlpacaEval** | 805 条指令 | 裁判判「比基准答案好/差」→ 胜率 |
| **Chatbot Arena** | 真人盲投 | 两两对战 → Elo 排名 |

```
┌──── LLM-as-Judge 流程 ────┐
│ 同一题 → 模型A答 / 模型B答 │
│            │              │
│            ▼              │
│   裁判模型(GPT-4)读两答    │
│   "哪个更好? 给分/选胜"    │
│            ▼              │
│   A 胜 / B 胜 / 平         │
└───────────────────────────┘
```

**为什么需要裁判**：开放任务无法 exact match，人工评太贵太慢。裁判模型快、便宜、可扩展。

**裁判模型的已知偏见（必背）**：
- **位置偏见**：倾向选「先出现」的答案 → 缓解：A/B 交换位置各跑一次取平均。
- **长度偏见**：倾向更长的回答（AlpacaEval 2.0 专门做了长度控制 LC）。
- **自我偏好**：裁判偏爱与自己同源/同风格的输出。
- **自洽/幻觉**：裁判自己可能判错，尤其专业领域。

> 结论：裁判分数适合「相对排序」，不适合当绝对真值；高风险场景仍需人工复核。

## 8. 长文本 / 工具调用 / 安全

| 维度 | 代表集 | 考什么 |
|------|--------|--------|
| 长文本检索 | **NeedleBench**（大海捞针） | 在百万级上下文里找一句话 |
| 长文本综合 | **LongBench / LV-Eval / LEval** | 长文 QA、摘要、多跳推理 |
| 工具调用 | **ToolBench / BFCL** | 选对 API、填对参数 |
| 指令跟随 | **IFEval** | 是否严格遵守格式约束 |
| 安全/对齐 | **TruthfulQA / 各类红队集** | 是否说真话、拒答有害请求 |

**NeedleBench / 大海捞针**：把一句无关「针」插进超长「干草堆」文本里，问模型那句话——专测长上下文的「真有效长度」。结果常画成「插入深度 × 上下文长度」的热力图，绿=找到、红=丢失：

```
深度↓ \ 长度→  4k   32k   128k
 浅(0%)        ✅    ✅    ✅
 中(50%)       ✅    ✅    ❌  ← 中间易丢("迷失在中间")
 深(100%)      ✅    ✅    ✅
```

**LV-Eval**：5 个长度等级最长 256k，每条样本带 `confusing_facts`（干扰事实）增加难度，字段含 `input/context/answers/length/dataset/answer_keywords`。

## 9. 数据污染（Data Contamination）

**定义**：测评集的题目（或答案）出现在了模型的训练数据里 → 模型是「背过答案」而非「会做」→ 分数虚高。

```
理想:  训练集  ∩  测试集  = ∅
现实:  训练语料爬全网，测试题也在网上
       ┌────────┐   ┌────────┐
       │训练数据│███│测试题  │  ← 重叠区 = 污染
       └────────┘   └────────┘
                 ▲
            模型「见过」这些题
```

**为什么难避免**：榜单题公开在 GitHub/HF，必然被下一代训练语料爬走。

**检测/缓解手段**：
- **n-gram 重叠**：扫训练语料里是否有测试题的连续片段。
- **持续更新题库**：用「发布日期晚于模型训练截止」的新题（如 LiveBench、定期刷新）。
- **私有 holdout**：保留不公开的测试子集。
- **改写/扰动**：把题目同义改写，若改写后分数暴跌，说明原来是背的。
- **MMLU-Pro 等**：增加选项数、加干扰，降低「蒙」和「背」的收益。

> 面试金句：「看到某模型某榜单分数异常高，第一反应是怀疑污染或过拟合该榜单，而非真能力。」

## 10. 局限与正确使用姿势

1. **单一数字会骗人**：一个 benchmark 只测一种能力的一个切片。要看一组（知识+推理+代码+对齐+长文+安全）。
2. **设置不报 = 不可比**：必须写清 `k`-shot、是否 CoT、logprob 还是生成、哪个评测框架。
3. **饱和（saturation）**：GSM8K、HumanEval 已被刷到很高，区分度下降 → 需更难的新集（MATH、SWE-bench、MMLU-Pro）。
4. **格式敏感**：分数可能丢在「抽取规则」而非能力上。
5. **裁判有偏见**：LLM-as-Judge 只宜相对排序。
6. **过拟合榜单（Goodhart）**：当一个指标变成目标，它就不再是好指标——刷榜行为让分数与真实可用性脱钩。
7. **离线 ≠ 在线**：榜单高不代表你的业务场景好，最终要靠**贴合自身任务的私有评测集 + 真实 A/B**。

```
评测可信度金字塔（自上而下越可信）:
        ┌───────────────┐
        │ 真实业务 A/B   │  ← 终极真理
        ├───────────────┤
        │ 私有 holdout   │  ← 抗污染
        ├───────────────┤
        │ 人工盲评/Arena │  ← 贴近偏好
        ├───────────────┤
        │ 公开 benchmark │  ← 方便但易被刷/污染
        └───────────────┘
```

## ★ 逐数手算合集

### 例1：准确率（MMLU 风格）
某模型在 200 题选择题答对 138 题：

$$\text{Acc} = \frac{138}{200} = 0.69 = 69\%$$

减去随机基线看真实水平：$\dfrac{0.69 - 0.25}{1 - 0.25} = \dfrac{0.44}{0.75} \approx 0.587$ —— 「校正后」仅约 59%，比裸的 69% 清醒得多。

### 例2：pass@1 与 pass@10（HumanEval）
某题生成 $n=20$ 个候选，其中 $c=4$ 个通过测试。

**pass@1**（直观）：随便抽 1 个能过的概率 $= c/n = 4/20 = 0.20$。代公式验证（$k=1$）：
$$1 - \frac{\binom{20-4}{1}}{\binom{20}{1}} = 1 - \frac{16}{20} = 0.20 \checkmark$$

**pass@10**：抽 10 个全错的概率 $= \dfrac{\binom{16}{10}}{\binom{20}{10}}$。

$$\binom{16}{10}=8008,\quad \binom{20}{10}=184756$$
$$\text{pass@}10 = 1 - \frac{8008}{184756} = 1 - 0.0433 = 0.957$$

直觉验证：只有 20% 单次成功率，但抽 10 次至少中一次的概率高达 ~96% —— 这正是「采样越多越可能蒙对」，所以 **pass@k 的 k 必须一并报告**。

### 例3：MT-Bench 平均分
10 道题，裁判给分 `[9,8,10,7,6,9,8,9,7,8]`，和 $=81$：

$$\overline{s} = 81/10 = 8.1 \;/\;10$$

### 例4：AlpacaEval 胜率
对手 805 条，模型胜 510、负 250、平 45（平局算 0.5）：

$$\text{WinRate} = \frac{510 + 0.5\times 45}{805} = \frac{532.5}{805} \approx 66.1\%$$

### 例5：位置偏见验证
A/B 不换位时 A 胜率 70%，换位后 A 胜率 52%，则去偏后估计

$$\text{真实胜率}_A \approx \frac{70\% + 52\%}{2} = 61\%$$

18 个百分点的差正是位置偏见的体现。

## ☰ 高频面试题（踩点答案 + 追问）

**Q1：MMLU 是怎么判分的？为什么 50 分不算高？**
踩点：57 学科 4 选 1，标准 5-shot；常用 logprob 比较 4 选项似然取最大。随机基线 25%，所以 50 分校正后仅 ~33%。
追问「logprob 和生成判分差别」→ logprob 能测 base、确定性高但脱离真实；生成贴近使用但对格式敏感。

**Q2：pass@k 公式为什么不是直接 c/n？**
踩点：直接采 k 个估计方差大，论文用 $n>k$ 生成、$c$ 个正确，按 $1-\binom{n-c}{k}/\binom{n}{k}$ 无偏估计。
追问「pass@1 ↔ c/n？」→ 当 $k=1$ 时公式退化为 $c/n$，一致。

**Q3：什么是数据污染，怎么检测？**
踩点：测试题进了训练集导致虚高。检测：n-gram 重叠扫描、用训练截止后的新题（LiveBench）、私有 holdout、改写后看是否掉分。

**Q4：裁判模型有哪些偏见，怎么缓解？**
踩点：位置偏见（A/B 换位平均）、长度偏见（长度控制 LC）、自我偏好、幻觉。结论：只宜做相对排序。

**Q5：few-shot 和 CoT 分别影响什么？**
踩点：few-shot 锚定格式+激活知识（影响可抽取性与公平性，必须报 k）；CoT 提供中间推理，显著提升数学/多步任务，对纯知识题增益小。

**Q6：HumanEval 和 MMLU 判分本质区别？**
踩点：HumanEval 跑**单元测试**（功能正确即可，文本可不同）；MMLU 比对**字母/似然**。前者是行为正确性，后者是符号匹配。

**Q7：为什么不能只看一个 benchmark？**
踩点：单集只测一个能力切片、可能饱和、可能被污染/过拟合（Goodhart）。要看一组 + 私有评测 + 真实 A/B。

**Q8：榜单分很高但实际不好用，可能原因？**
踩点：过拟合该榜单、数据污染、评测设置（shot/CoT）与真实场景不符、格式敏感导致离线指标失真、裁判偏见。
