## 0. 一句话锚点

**在昇腾上，镜像只打包了「用户态软件栈」（CANN/MindSpore/Python 包），而「内核态驱动」必须用宿主机的。** 所以跑昇腾容器永远是两件事缝在一起：

$$\text{可用环境} = \underbrace{\text{镜像（CANN + MindSpore）}}_{\text{docker pull}} + \underbrace{\text{宿主驱动 + 设备文件}}_{\text{--device / -v 挂进去}}$$

任何一边缺了，容器里 `npu-smi info` 就会报错。这一节是后面所有 `--device=/dev/davinci*` 和 `-v /usr/local/Ascend/driver` 的根因。

## 1. 地基：昇腾软件栈与设备文件

### 1.1 五层栈（自顶向下）

```
  你的代码  ┌─────────────────────────────┐
  ───────►  │  MindSpore / MindFormers     │  框架（在镜像里）
            ├─────────────────────────────┤
            │  CANN (acl / runtime / 算子库)│  异构计算架构（在镜像里）
            ├─────────────────────────────┤
            │  Ascend Driver (内核模块 .ko) │  ★必须用宿主机的★
            ├─────────────────────────────┤
            │  /dev/davinci0..7 设备文件    │  ★直通进容器★
            ├─────────────────────────────┤
            │  昇腾 910/310 NPU 硬件        │  达芬奇架构 (Da Vinci)
            └─────────────────────────────┘
```

- **镜像负责**：CANN（含算子库 / runtime / acl）+ MindSpore + Python 依赖 —— 纯用户态，可以打包搬运。
- **宿主负责**：Driver（内核 `.ko` 模块）+ 设备节点 —— 与内核版本绑定，**绝不能装进镜像**。这就是为什么所有启动命令都要把 `/usr/local/Ascend/driver` 挂进去。

### 1.2 设备文件对照表（`/dev/` 下那一堆 device）

| 设备文件 | 作用 | 缺了会怎样 |
| --- | --- | --- |
| `/dev/davinci0` ~ `davinci7` | 8 张 NPU 卡的计算设备节点，每张卡一个 | 看不到对应卡 |
| `/dev/davinci_manager` | 设备管理器，统一调度入口 | 一张卡都用不了 |
| `/dev/devmm_svm` | 共享虚拟内存（Shared Virtual Memory），CPU/NPU 统一寻址 | 内存映射失败 |
| `/dev/hisi_hdc` | 海思 Host-Device 通信通道 | host↔device 通信报错 |

> 记忆法：`davinci0~7` 是「八张卡」，后面三个 `manager / devmm_svm / hisi_hdc` 是「公共基础设施」，三件套缺一不可，所以模板里永远成对出现。

### 1.3 关键名词

| 名词 | 全称 / 含义 |
| --- | --- |
| NPU | Neural Processing Unit，昇腾的 AI 加速卡（如 910B） |
| CANN | Compute Architecture for Neural Networks，对标 CUDA 的异构计算软件栈 |
| 达芬奇架构 | 昇腾芯片的 Cube/Vector/Scalar 计算核心架构，故设备名叫 `davinci` |
| `npu-smi` | 昇腾版 `nvidia-smi`，查卡、查利用率、查温度 |
| AscendHub | 华为官方昇腾镜像仓库 `ascendhub.huawei.com` |
| SWR | 华为云容器镜像服务 `swr.*.myhuaweicloud.com` |

## 3. 设备直通：为什么必须 `--device=/dev/davinci*`

普通 Docker 容器看不到宿主机的硬件设备。`--device` 把宿主的字符设备节点「直通」进容器，让容器内进程能 `open()` 这些文件、发 ioctl 给驱动。

```
  宿主机                          容器
  ┌──────────────┐  --device     ┌──────────────┐
  │ /dev/davinci0│ ───────────►  │ /dev/davinci0│  ← 同一个 inode
  │ /dev/davinci1│ ───────────►  │ /dev/davinci1│
  │   ...        │               │   ...        │
  │ davinci_mgr  │ ───────────►  │ davinci_mgr  │
  └──────┬───────┘               └──────┬───────┘
         │ ioctl                        │ ioctl
         ▼                              ▼
   ┌─────────────────────────────────────────┐
   │      宿主内核里的 Ascend Driver (.ko)     │  ← 二者共用
   └─────────────────────────────────────────┘
```

8 卡全直通的标准写法（原文 SWR 镜像示例）：

```bash
docker run -it --ipc=host \
--device=/dev/davinci0 \
--device=/dev/davinci1 \
--device=/dev/davinci2 \
--device=/dev/davinci3 \
--device=/dev/davinci4 \
--device=/dev/davinci5 \
--device=/dev/davinci6 \
--device=/dev/davinci7 \
--device=/dev/davinci_manager \
--device=/dev/devmm_svm \
--device=/dev/hisi_hdc \
-v /usr/local/Ascend/driver:/usr/local/Ascend/driver \
-v /usr/local/Ascend/add-ons/:/usr/local/Ascend/add-ons/ \
-v /usr/local/sbin/npu-smi:/usr/local/sbin/npu-smi \
-v /var/log/npu/:/usr/slog \
ascendhub.huawei.com/public-ascendhub/mindspore-modelzoo:{tag} \
/bin/bash
```

- `--ipc=host`：共享宿主 IPC namespace，**让 `/dev/shm` 足够大**。多进程/多卡训练用共享内存传 tensor，默认 64MB 的 `/dev/shm` 一跑就 `Bus error`。等价的另一种写法是 `--shm-size 4G`（见第 7 节）。
- `{tag}` 是占位符，拉之前替换成真实 tag。

## 4. 驱动与工具挂载：那一排 `-v`

设备文件只是「门把手」，容器里还得有「钥匙」——驱动的用户态库和工具。靠 bind-mount 把宿主的几个目录挂进容器：

| `-v` 挂载 | 挂的是什么 | 为什么需要 |
| --- | --- | --- |
| `/usr/local/Ascend/driver` | 驱动用户态 `.so` + 固件 | 容器内 CANN 调驱动的接口 |
| `/usr/local/Ascend/add-ons/` | 驱动附加组件 | 部分算子/通信依赖 |
| `/usr/local/sbin/npu-smi`（或 `/usr/local/bin/npu-smi`） | `npu-smi` 工具 | 容器内查卡状态 |
| `/var/log/npu/` → `/usr/slog` | NPU 日志目录 | device 侧日志落盘，排障必备 |
| `/etc/localtime` | 宿主时区 | 容器日志时间对齐（见第 7 节） |

> 关键原则：**镜像里的 CANN 版本要和宿主 Driver 版本匹配**。版本错配是昇腾最常见翻车点——表现为 `npu-smi` 能跑但模型一加载就 `EI9999` / `aclrtMalloc failed`。先确认 `driver` 版本，再选镜像 tag。

## 5. Ascend Docker Runtime：更优雅的挂卡方式

裸写 11 行 `--device` 又臭又长，还容易漏。华为提供 **Ascend Docker Runtime**：装一次，之后用一个环境变量 `ASCEND_VISIBLE_DEVICES` 指定卡，runtime 自动注入所有设备和驱动挂载。

```bash
chmod +x Ascend-docker-runtime_{version}_linux-{arch}.run
./Ascend-docker-runtime_{version}_linux-{arch}.run  --install

# 安装后，挂 0 号卡只需一个 env，不用再写 --device 一长串
docker run -it -e ASCEND_VISIBLE_DEVICES=0 镜像id  /bin/bash

bash test_model.sh
```

对照（同样是「只用 0 号卡」）：

```
  裸 docker：  --device=/dev/davinci0  --device=/dev/davinci_manager
               --device=/dev/devmm_svm  --device=/dev/hisi_hdc
               -v /usr/local/Ascend/driver:...  -v ...  (一大坨)

  有 runtime： -e ASCEND_VISIBLE_DEVICES=0       (一行搞定)
```

`ASCEND_VISIBLE_DEVICES` 之于 NPU，等价于 `CUDA_VISIBLE_DEVICES` / `--gpus` 之于 GPU。`0` 选单卡，`0,1,2,3` 选多卡，`all` 选全部。

> 旁注：原文里有一处 `docker run -dt --name mindspore_env --restart=always --gpus all` 的写法——`--gpus all` 是 **NVIDIA** runtime 的参数，在纯昇腾环境里应换成 `-e ASCEND_VISIBLE_DEVICES=all`（装了 Ascend Docker Runtime 后）或第 3 节的裸 `--device` 写法。`--restart=always` 让容器随 Docker 守护进程自启，`-dt` 后台常驻、`-v /home/guodong/workspace:/workspace -w /workspace` 把工作区挂进来并设为默认目录，这些与昇腾无关、通用 Docker 技巧照搬即可。

## 6. 自建镜像：ChatGLM-6B 的 Dockerfile 解剖

光有基础镜像还跑不了具体模型——要把模型代码、工具、Python 依赖打进去。下面是基于昇腾 MindSpore 基础镜像构建 ChatGLM-6B 的完整 Dockerfile（原文逐行保留）：

```dockerfile
FROM ascendhub.huawei.com/public-ascendhub/ascend-mindspore:23.0.RC1-ubuntu18.04

USER root
COPY ./glm0609 /home/chatglm6b
COPY ./hccl_tools /home/hccl_tools
COPY ./mindpet /home/mindpet
COPY ./web_demo.gif /home/

WORKDIR /home

RUN pip3 install -i https://pypi.tuna.tsinghua.edu.cn/simple/ -U pip
RUN pip3 config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple/

RUN wget https://sqlite.org/2019/sqlite-autoconf-3290000.tar.gz
RUN tar zxvf sqlite-autoconf-3290000.tar.gz && cd sqlite-autoconf-3290000 && ./configure && make -j${proc} && make install

RUN wget https://www.python.org/ftp/python/3.7.5/Python-3.7.5.tgz
RUN tar xzvf Python-3.7.5.tgz && cd Python-3.7.5 && \
./configure LDFLAGS="-L/usr/local/lib" CPPFLAGS="-I/usr/local/include" --prefix=/usr/local/python3.7.5 && \
make -j${proc} && \
make install

RUN /usr/local/python3.7.5/bin/pip install torch transformers numpy sentencepiece ftfy regex tqdm \
pyyaml rouge_chinese nltk jieba datasets gradio==3.23.0 pandas openpyxl et-xmlfile mdtex2html

ENV LC_ALL='C.UTF-8'
ENV PYTHONPATH=/home/mindpet/:$PYTHONPATH
ENV LD_PRELOAD=/usr/local/python3.7.5/lib/python3.7/site-packages/torch/lib/libgomp-d22c30c5.so.1
```

逐段为什么：

| 行 | 做了什么 | 为什么这么做 |
| --- | --- | --- |
| `FROM ...ascend-mindspore:23.0.RC1-ubuntu18.04` | 选 ubuntu18.04 基础镜像 | 自带 CANN+MindSpore，省去手装昇腾栈 |
| `COPY ./mindpet /home/mindpet` | 拷贝 MindPet（昇腾 PEFT 微调工具） | 后面 `PYTHONPATH` 要指向它 |
| `pip config set index-url ...tuna...` | 换清华源 | 国内构建网络快、不超时 |
| 源码编译 `sqlite-3290000` | 先装新版 SQLite | Python 3.7.5 编译时依赖较新 SQLite |
| 源码编译 `Python-3.7.5` | 装指定 Python | **MindSpore 对 Python 版本敏感**，3.7.5 是当时官方支持版；`LDFLAGS/CPPFLAGS` 指向刚装的 SQLite |
| `pip install torch transformers gradio==3.23.0 ...` | 装推理/Web demo 依赖 | `gradio==3.23.0` 锁版本防 API 破坏 |
| `ENV LC_ALL='C.UTF-8'` | 设 UTF-8 locale | 防中文/分词报 `UnicodeDecodeError` |
| `ENV PYTHONPATH=/home/mindpet/:...` | 把 MindPet 加进搜索路径 | `import mindpet` 才找得到 |
| `ENV LD_PRELOAD=.../libgomp-...so.1` | 预加载 OpenMP 库 | **经典坑**：torch 自带 libgomp 与系统冲突，预加载固定版本解 `cannot allocate memory in static TLS block` |

构建好的镜像（如 tag `chatglm6b:v1`）这样起容器、挂模型权重：

```bash
docker run -itd --name mindspore_dev -u root --network=host --ipc=host \
            --device=/dev/davinci0 \
            --device=/dev/davinci1 \
            --device=/dev/davinci2 \
            --device=/dev/davinci3 \
            --device=/dev/davinci4 \
            --device=/dev/davinci5 \
            --device=/dev/davinci6 \
            --device=/dev/davinci7 \
            --device=/dev/davinci_manager \
            --device=/dev/devmm_svm \
            --device=/dev/hisi_hdc \
            -v /root/ChatGLM6B_MS_0613/huggingface-glm-6b:/home/huggingface-glm-6b \
            -v /usr/local/Ascend/driver:/usr/local/Ascend/driver \
            -v /usr/local/Ascend/add-ons/:/usr/local/Ascend/add-ons/ \
            -v /usr/local/sbin/npu-smi:/usr/local/sbin/npu-smi \
            -v /var/log/npu/:/usr/slog \
            chatglm6b:v1 \
            /bin/bash

docker exec -it  mindspore_dev bash
```

- `-itd`：交互(`i`) + 伪终端(`t`) + 后台(`d`)，容器常驻；用 `docker exec` 再进去。
- `-v /root/...huggingface-glm-6b:/home/huggingface-glm-6b`：**权重不打进镜像**，外挂进来。镜像只放代码/环境，权重几 GB 单独挂，镜像才能保持小、可复用。
- `--network=host`：容器直接用宿主网络栈，省端口映射，Web demo（gradio）直接可访问。

## 7. MindFormers 镜像（大模型套件，arm64）

MindFormers 是 MindSpore 的大模型全流程套件（预训练/微调/推理）。昇腾服务器多为 **鲲鹏 arm64** CPU，拉镜像要指定平台：

```bash
docker pull --platform=arm64 swr.cn-central-221.ovaijisuan.com/mindformers/mindformers0.8.0_mindspore2.2.0:aarch_20231025
```

> tag `mindformers0.8.0_mindspore2.2.0:aarch_20231025` 把三件事写死：MindFormers 0.8.0 + MindSpore 2.2.0 + aarch64 架构 + 2023-10-25 构建日。**MindFormers 与 MindSpore 版本强绑定**，不能随意混搭。

标准启动脚本（含注释，原文保留）：

```bash
# --device用于控制指定容器的运行NPU卡号和范围
# -v 用于映射容器外的目录
# --name 用于自定义容器名称

docker run -it -u root \
--ipc=host \
--network host \
--device=/dev/davinci0 \
--device=/dev/davinci1 \
--device=/dev/davinci2 \
--device=/dev/davinci3 \
--device=/dev/davinci4 \
--device=/dev/davinci5 \
--device=/dev/davinci6 \
--device=/dev/davinci7 \
--device=/dev/davinci_manager \
--device=/dev/devmm_svm \
--device=/dev/hisi_hdc \
-v /etc/localtime:/etc/localtime \
-v /usr/local/Ascend/driver:/usr/local/Ascend/driver \
-v /var/log/npu/:/usr/slog \
-v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi \
--name {请手动输入容器名称} \
swr.cn-central-221.ovaijisuan.com/mindformers/mindformers0.8.0_mindspore2.2.0:aarch_20231025 \
/bin/bash
```

注意这版 `npu-smi` 挂的是 `/usr/local/bin/npu-smi`（前面 SWR 版是 `/usr/local/sbin/`）——**以宿主实际路径为准**，先在宿主 `which npu-smi` 确认再挂。

## 常见问题 / 坑

| 症状 | 根因 | 解法 |
| --- | --- | --- |
| 容器内 `npu-smi: command not found` | 没挂 `npu-smi` 或路径不对 | 宿主 `which npu-smi` 后用 `-v` 挂正确路径（`/usr/local/bin` 或 `/sbin`） |
| `npu-smi` 能跑但模型加载报 `EI9999`/`aclrtMalloc failed` | 镜像 CANN 版本 ≠ 宿主 Driver 版本 | 查 driver 版本，换匹配 tag 的镜像 |
| 多卡训练 `Bus error (core dumped)` | `/dev/shm` 太小（默认 64MB） | 加 `--ipc=host` 或 `--shm-size 4G` |
| `cannot allocate memory in static TLS block` | torch 自带 libgomp 与系统冲突 | `ENV LD_PRELOAD=.../libgomp-*.so.1`（见 Dockerfile） |
| 中文/分词 `UnicodeDecodeError` | locale 不是 UTF-8 | `ENV LC_ALL='C.UTF-8'` |
| `import mindpet` 失败 | MindPet 不在搜索路径 | `ENV PYTHONPATH=/home/mindpet/:$PYTHONPATH` |
| arm64 机器拉到 amd64 镜像、跑不起 | 没指定平台 | `docker pull --platform=arm64 ...` |
| `--gpus all` 在昇腾上无效 | 那是 NVIDIA runtime 参数 | 换 `-e ASCEND_VISIBLE_DEVICES=all` 或裸 `--device` |
| 权重打进镜像导致镜像巨大 | 把几 GB 权重 `COPY` 进去了 | 权重用 `-v` 外挂，镜像只放代码/环境 |
