## 0. 一句话锚点

**ModelLink 是华为昇腾官方的大模型分布式训练套件**，对标英伟达世界的 **Megatron-LM**：它在 `torch_npu` 之上提供了 TP/PP/DP/SP 等并行能力、主流大模型（LLaMA、Qwen、GLM 等）的结构实现与权重转换脚本。

"装 ModelLink 环境"本质上不是装一个包，而是**搭一条完整的软件栈**：底层 NPU 驱动固件 → CANN（昇腾的"CUDA"）→ PyTorch + torch_npu（框架适配层）→ 加速库（apex/megatron 等价物）→ ModelLink 本体。任何一层版本错配，上层都会"看不见 NPU"或编译失败。

> ⚠️ 本文只讲**每一步在做什么、为什么要这步、依赖关系与常见坑**。所有具体命令、包名、版本号、镜像地址，请以**华为昇腾官方文档（Ascend 社区 / Gitee ascend 仓库）为准**——版本配套关系是昇腾栈最容易踩坑的地方，绝不能凭记忆拼。

## 1. 地基：在昇腾栈的定位 + 对标英伟达生态

### 昇腾软件栈分层（自底向上）

```
┌──────────────────────────────────────────────────────────┐
│  套件层   ModelLink(训练) / MindIE(推理) / msmodelslim(量化)  │  ← 本文目标在这层
├──────────────────────────────────────────────────────────┤
│  框架层   PyTorch + torch_npu  /  MindSpore                  │
├──────────────────────────────────────────────────────────┤
│  CANN     算子(AOL) + 图编译(GE) + 运行时(Runtime) + HCCL     │  ← 昇腾的"CUDA"
├──────────────────────────────────────────────────────────┤
│  驱动固件  Driver + Firmware (npu-smi 可见)                   │
├──────────────────────────────────────────────────────────┤
│  硬件     昇腾 NPU(达芬奇架构 Cube/Vector 单元)               │
└──────────────────────────────────────────────────────────┘
```

ModelLink 坐在最上层，但它能跑的前提是下面四层全部就位且版本互相配套。

### 昇腾 ↔ 英伟达生态对照表（迁移心智图）

| 能力 / 角色 | 英伟达世界 | 昇腾世界 | 说明 |
| --- | --- | --- | --- |
| 加速硬件 | GPU | NPU（昇腾 910 系列等） | 达芬奇架构，Cube 做矩阵、Vector 做逐元素 |
| 底层软件栈 | CUDA Toolkit | **CANN** | 编译器 + 运行时 + 算子库总集 |
| 深度学习算子库 | cuDNN / cuBLAS | CANN 算子（AOL/AscendCL） | 卷积、GEMM、归一化等高性能算子 |
| 集合通信 | NCCL | **HCCL** | AllReduce/AllGather 等分布式原语 |
| 设备管理工具 | `nvidia-smi` | `npu-smi` | 查看卡、显存/HBM、利用率、健康 |
| 深度学习框架 | PyTorch(CUDA 后端) | **PyTorch + torch_npu** | torch_npu 是 NPU 后端适配插件 |
| 国产原生框架 | （无直接对应） | MindSpore | 华为自研全场景框架 |
| 大模型训练套件 | **Megatron-LM** | **ModelLink** | TP/PP/DP/SP 并行训练 |
| 混合精度/优化扩展 | apex | CANN/torch_npu 内置等价能力 | 融合算子、混合精度 |
| 推理引擎 | TensorRT-LLM / vLLM | MindIE | 高性能推理服务 |
| 量化工具 | GPTQ / AWQ | msmodelslim | 权重/激活量化 |

**一句话记忆**：CANN≈CUDA，HCCL≈NCCL，torch_npu≈PyTorch 的 CUDA 后端，ModelLink≈Megatron-LM。掌握这张表，迁移的"心智地图"就有了。

## 2. 安装栈的依赖关系：为什么必须按顺序装

五层之间是**严格的自底向上依赖**，不能跳级、不能乱序：

```
驱动固件  ──能识别卡──▶  CANN  ──提供运行时/算子──▶  PyTorch+torch_npu
                                                          │
                                                  提供 NPU tensor 能力
                                                          ▼
                                          加速库(megatron 等价) ──▶ ModelLink
```

- **驱动固件**没装好 → `npu-smi` 看不到卡，后面全白搭。
- **CANN** 没装/版本不对 → torch_npu 加载时报找不到 `libascendcl` 之类运行时库。
- **torch_npu 版本必须与 CANN、与 torch 三方配套** → 这是最高频的坑，配套关系以官方"版本配套表"为准。
- **ModelLink** 依赖特定的 torch_npu / CANN / Megatron 分支版本 → 仓库 README 会给出"已验证组合"。

> 🔑 核心原则：**先确定 ModelLink 仓库要求的版本组合，再反推每一层装哪个版本**，而不是各自装最新。"装最新"是迁移者最容易犯的错误。

## 3. 驱动与固件层

### 这一步在做什么
让操作系统和上层软件**认识这块 NPU**。Firmware 跑在卡上的固件，Driver 是内核态驱动，二者配套。装完用设备管理工具确认卡可见、健康。

### 验证含义（对标 nvidia-smi）
执行昇腾的设备查询工具（功能等价于 `nvidia-smi`），应能看到每张 NPU 的编号、HBM/显存占用、温度、利用率与健康状态。**看到卡 = 地基合格**，看不到就别往上走。

### 常见坑
- 驱动与固件**版本不配套**，或与内核版本不兼容 → 加载失败。
- 多机训练时各节点驱动版本不一致 → HCCL 通信异常。
- 容器内要正确**透传设备**（davinci 设备、驱动目录挂载），否则容器里看不到卡。

> 具体安装包、命令与版本配套，以华为昇腾官方文档（Ascend 社区）为准。

## 4. CANN 层（昇腾的 CUDA）

### 这一步在做什么
CANN（Compute Architecture for Neural Networks）是昇腾的**异构计算架构总集**，相当于英伟达的 CUDA Toolkit + cuDNN + cuBLAS 合体，包含：

```
            ┌─────────── CANN ───────────┐
torch_npu ─▶│ 算子库(AOL)  GEMM/卷积/归一化 │ ≈ cuDNN/cuBLAS
            │ 图编译(GE)   计算图优化下沉    │ ≈ 图模式编译
            │ 运行时(Runtime) 任务下发/流管理 │ ≈ CUDA Runtime
            │ HCCL        集合通信           │ ≈ NCCL
            └────────────────────────────┘
                         ▼
                   达芬奇 Cube/Vector
```

### 关键动作：source set_env.sh 的含义
装完 CANN（ascend-toolkit）后，需要 `source` 它的环境脚本（如 `set_env.sh`）来**注入环境变量**：库搜索路径、可执行路径、算子路径等。其作用等价于 CUDA 里把 `CUDA_HOME/bin`、`LD_LIBRARY_PATH` 配好。**不 source，torch_npu 就找不到运行时库。** 建议把 source 写进登录脚本或训练启动脚本，多机时每个节点都要生效。

### 常见坑
- 装了 toolkit 但**忘记 source set_env** → import torch_npu 报缺库。
- CANN 版本与 torch_npu 版本**不配套** → 算子注册失败或运行时报错。
- 还可能需要装配套的 **kernels（算子包）/ nnal 加速库**等组件，缺组件会在跑特定算子时才暴露。

> 路径示例 `/usr/local/Ascend/ascend-toolkit/set_env.sh` 是默认路径，实际以你的安装路径和官方文档为准。

## 5. torch_npu 适配层（PyTorch 调用 NPU 的桥）

### 这一步在做什么
`torch_npu`（Ascend Adapter for PyTorch）是把 **PyTorch 的算子分发到昇腾 NPU** 的后端插件——让 PyTorch 框架的开发者直接用上昇腾算力，而几乎不改训练代码风格。

> 仓库：https://gitee.com/ascend/pytorch

### 安装的三件套与顺序
1. **先装原生 PyTorch**（CPU 版即可，torch_npu 提供 NPU 后端）。
2. **装依赖**（如 `pyyaml`、`setuptools` 等构建/运行依赖）。
3. **装 torch_npu**，其版本号通常形如 `<torch版本>.postX`，**必须与 torch 主版本、CANN 版本三方对齐**。

> 安装时可加 `--log <PATH>` 保存安装日志便于排查，并对该目录做好权限管控。

### 验证：最小冒烟测试
装完做一个"在 NPU 上算一次矩阵乘"的冒烟测试，把 tensor `.npu()` 搬到设备上跑一次 `mm`——**这一步同时验证了驱动、CANN、torch_npu 三层是否打通**：

```python
import torch
import torch_npu            # 关键：import 后 .npu() 才可用

x = torch.randn(2, 2).npu() # 把张量搬到 NPU，类比 .cuda()
y = torch.randn(2, 2).npu()
z = x.mm(y)                 # 在达芬奇 Cube 单元上做 GEMM
print(z)                    # 能打印出结果 = 三层全部打通
```

### 迁移心智：`.npu()` ↔ `.cuda()`
GPU 代码里的 `.cuda()`、`device='cuda'`、`torch.cuda.xxx` 在昇腾侧大多有对应物（`.npu()`、`device='npu'`、`torch.npu.xxx`）。大量 PyTorch 训练脚本只需做"设备字符串替换 + import torch_npu"即可跑起来，这正是 torch_npu 的价值。

### 常见坑
- **忘记 `import torch_npu`** → `.npu()` 不存在、NPU 后端没注册。
- torch / torch_npu / CANN **版本三方错配** → import 即崩。
- 直接 `pip install` 不看配套表装了最新 → 与 CANN 对不上。

## 6. 加速库与 ModelLink 本体

### 这一步在做什么
ModelLink 在 torch_npu 之上提供**大模型分布式训练能力**，对标 Megatron-LM：

- **并行策略**：张量并行(TP) / 流水线并行(PP) / 数据并行(DP) / 序列并行(SP) 等，底层集合通信走 **HCCL**（≈NCCL）。
- **模型库**：内置 LLaMA / Qwen / GLM 等主流结构实现。
- **权重转换**：HuggingFace 格式 ↔ ModelLink/Megatron 切分格式互转脚本，方便把社区权重搬上昇腾训练。

### 安装含义（流程，不是具体命令）
1. 准备好第 3~5 层（驱动、CANN、torch_npu）并**通过冒烟测试**。
2. 按 ModelLink 仓库 README 装其**依赖与配套的加速组件**（Megatron 等价物、融合算子库等）。
3. 拉取 ModelLink 源码，切到 README 指定的**已验证分支/版本**。
4. 跑官方给的最小训练样例验证多卡/多机链路（这一步顺带验证 HCCL 通信是否正常）。

```
HuggingFace 权重 ──转换脚本──▶ ModelLink 切分权重
                                    │
        ┌────────── 多卡训练 ───────┴───────────┐
        │   TP      PP      DP      SP           │
        │    └───────┴─── HCCL 集合通信 ──┘       │  ≈ Megatron over NCCL
        └────────────────────────────────────────┘
```

> 具体仓库地址、分支、依赖清单、转换命令，以 ModelLink 官方仓库与昇腾文档为准。

## 迁移要点 / 注意事项与坑

**从 GPU/Megatron 迁到昇腾/ModelLink，重点改这些：**

1. **版本配套先行**：先锁 ModelLink 要求的 CANN/torch/torch_npu 三方版本，再装每一层。这是头号坑，"各装最新"必崩。
2. **设备字符串与 import**：`cuda`→`npu`，并显式 `import torch_npu`；`nccl` 通信后端在昇腾侧对应 HCCL，初始化方式以官方为准。
3. **环境变量要 source**：每次新 shell / 每个节点都要 `source` CANN 的 set_env，否则缺库。容器/作业调度里尤其容易漏。
4. **算子覆盖度**：少数自定义/冷门算子可能在 NPU 上未实现或走回落路径，会拖慢性能——迁移后要 profiling 看是否有算子回落到 CPU。
5. **图模式 vs 单算子模式**：昇腾可走图编译(GE)把整图下沉优化（类比 CUDA Graph / 编译优化），吞吐更高但对动态 shape 更敏感；调优时关注是否触发频繁重编译。
6. **多机一致性**：各节点驱动/固件/CANN/torch_npu 版本必须完全一致，否则 HCCL 建链失败或精度漂移。
7. **HBM/显存与并行切分**：NPU 单卡内存与 GPU 不同，TP/PP 切分配置需按实际 HBM 重新调，不能照搬 GPU 配置。

**性能调优思路（机制层面）**：优先消除算子回落与 host 侧瓶颈 → 让 Cube 单元吃满 GEMM → 用融合算子减少 Vector/搬运开销 → 用图模式减少下发开销 → 检查 HCCL 通信是否与计算重叠。

## 常见问题

| 问题 | 原因 | 排查方向 |
| --- | --- | --- |
| `npu-smi` 看不到卡 | 驱动/固件没装好或容器没透传设备 | 重装配套驱动固件，检查容器设备挂载 |
| `import torch_npu` 报缺库 | 没 source CANN set_env，或 CANN 没装 | 先 source 环境脚本，确认 CANN 组件齐全 |
| import 即崩 / 算子注册失败 | torch / torch_npu / CANN 版本错配 | 对照官方版本配套表重装 |
| `.npu()` 不存在 | 忘了 `import torch_npu` | 在 import torch 后补上 import torch_npu |
| 多机 HCCL 建链失败 | 各节点版本不一致 / 网络配置 | 统一全节点软件版本，检查通信网络与 rank 配置 |
| 训练慢 / 利用率低 | 算子回落 CPU、host 瓶颈、频繁重编译 | profiling 看算子分布，固定 shape，开图模式 |
| 具体命令/版本不确定 | 配套关系随版本变化 | **一律以华为昇腾官方文档（Ascend 社区）为准** |
