## 0. 一句话锚点

**昇腾 NPU = 华为自研 AI 加速卡，对标 NVIDIA GPU；但它不认 CUDA，必须靠 CANN 软件栈 + `torch_npu` 适配层，把 PyTorch 的算子翻译成昇腾指令。** 本文记录的就是：在一台 8 卡 910 A2 机器上，把这套适配层装好，并跑通 Qwen1.5-7B/14B、Baichuan2-7B 的全参微调。

一句话区分三个名字：

- **昇腾 / Ascend**：硬件（芯片/卡），相当于 GPU。
- **CANN**：华为的“CUDA 等价物”（驱动 + 算子库 + 编译器），装在 `/usr/local/Ascend`。
- **torch-npu**：PyTorch 的设备插件，让 `tensor.npu()` 能用，相当于 NVIDIA 那边内置的 `tensor.cuda()`。

## 1. 地基/前置：昇腾软件栈与 CUDA 的对照

要理解后面每一条命令“为什么这么写”，先把昇腾的软件分层和你熟悉的 NVIDIA 栈对齐。

```
        NVIDIA (你熟悉的)              昇腾 Ascend (本文)
   ┌───────────────────────┐    ┌────────────────────────────┐
应用│ PyTorch + tensor.cuda │    │ PyTorch + torch_npu        │  ← 适配层
   ├───────────────────────┤    │   tensor.npu()             │
框架│ (CUDA 内置后端)        │    ├────────────────────────────┤
   ├───────────────────────┤    │ CANN ToolKit               │  ← 算子/编译
库  │ cuDNN / cuBLAS / NCCL  │    │   (AOL/算子库) + HCCL       │     集合通信
   ├───────────────────────┤    ├────────────────────────────┤
驱动│ CUDA Driver           │    │ Ascend Driver (npu-smi)    │  ← 内核驱动
   ├───────────────────────┤    ├────────────────────────────┤
硬件│ GPU (H100/A100)       │    │ NPU (910 A2)               │
   └───────────────────────┘    └────────────────────────────┘
```

对照表（面试常问，背下来）：

| NVIDIA | 昇腾 Ascend | 作用 |
|---|---|---|
| CUDA Toolkit | CANN ToolKit | 编译/算子运行时 |
| `nvidia-smi` | `npu-smi info` | 查卡 |
| `tensor.cuda()` | `tensor.npu()` | 张量上卡 |
| NCCL | **HCCL** | 多卡集合通信（AllReduce 等，见 [[ai-infra/网络/集合通信原语]]） |
| `CUDA_VISIBLE_DEVICES` | `ASCEND_RT_VISIBLE_DEVICES` / `ASCEND_VISIBLE_DEVICES` | 设备可见性 |
| 装好即用 | **必须 `source set_env.sh`** | 注入 CANN 环境变量 |

**最关键的“为什么”**：NVIDIA 的库路径由系统自动找到，而昇腾的 CANN 装在 `/usr/local/Ascend/ascend-toolkit/`，它的 `LD_LIBRARY_PATH`、`PATH`、`ASCEND_HOME` 等环境变量**不会自动生效**，必须每次手动执行：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
```

不 source 它，`import torch_npu` 会报 `libascend_hal.so` 找不到——这就是原文里那句 `find . -name libascend_hal.so` 的来由：用来定位 CANN 是否装好、路径是否进了 `LD_LIBRARY_PATH`。

## 2. 镜像与容器：为什么用官方镜像 + 8 设备直通

### 2.1 为什么用 AscendHub 官方镜像

昇腾的驱动版本、CANN 版本、torch-npu 版本必须**严格匹配**（version lock）。自己从裸 Ubuntu 装极易版本错配，所以直接拉华为官方镜像，CANN 已预装在 `/usr/local/Ascend`：

```bash
docker login -u 157xxx4031 ascendhub.huawei.com
docker pull ascendhub.huawei.com/public-ascendhub/ascend-mindspore:23.0.0-A2-ubuntu18.04
```

> 镜像 tag 里 `23.0.0-A2` 表示 CANN 23.0.0、面向 910 **A2** 芯片；`ubuntu18.04` 是基础系统。

### 2.2 容器启动：8 卡直通的每一行都有用

```bash
docker rm -f pytorch_ubuntu_dev
docker run -it -u root \
  --name pytorch_ubuntu_dev \
  --network host \
  -e ASCEND_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
  -v /etc/localtime:/etc/localtime \
  -v /var/log/npu/:/usr/slog \
  -v /usr/bin/hccn_tool:/usr/bin/hccn_tool \
  -v /data/containerd/workspace/:/workspace \
  ascendhub.huawei.com/public-ascendhub/ascend-mindspore:23.0.0-A2-ubuntu18.04 \
  /bin/bash
```

逐行说“为什么”：

```
--network host                  → 多机/多卡 HCCL 走主机网络，避免 NAT 影响集合通信带宽
-e ASCEND_VISIBLE_DEVICES=0..7  → 把 8 张 NPU 暴露进容器（等价于 GPU 的 --gpus all）
-v /var/log/npu/:/usr/slog      → 把 NPU 日志(slog)挂出来，崩了能在宿主机查
-v /usr/bin/hccn_tool:...       → hccn_tool 用来配/查 NPU 间 RoCE 网络(参见 InfiniBand 类比)
-v .../workspace:/workspace     → 代码/模型/数据持久化，容器删了不丢
```

> 注意原文有两个变量名：`ASCEND_VISIBLE_DEVICES`（注入容器时）与 `ASCEND_RT_VISIBLE_DEVICES`（运行时进程内选卡），二者层级不同，前者是容器级、后者是任务级。

容器复用（不必每次新建）：

```bash
docker start pytorch_ubuntu_dev
docker exec -it pytorch_ubuntu_dev bash
```

### 2.3 镜像的保存与跨机分发

把调好环境的容器固化成镜像，再传到第二台机器（`bms-dt-0009`），避免重复搭环境：

```bash
docker commit -m="ascend-pytorch" -a="liguodong" 842da08d1061 harbor.guodong.io/ascend-pytorch:v1

```

## 3. Conda 与 torch-npu：为什么不能“裸 pip torch”就用 NPU

### 3.1 装 Conda（注意 aarch64）

昇腾服务器 CPU 是 **ARM（鲲鹏）**，所以 Miniconda 必须下 `aarch64` 版本，下 x86 会直接装不上——这是国产化环境第一个高频坑：

```bash
wget -c https://repo.anaconda.com/miniconda/Miniconda3-py39_24.4.0-0-Linux-aarch64.sh
bash Miniconda3-py39_24.4.0-0-Linux-aarch64.sh -p /workspace/installs/conda
conda init
source ~/.bashrc
conda create -n llm-dev python=3.9
conda activate llm-dev
```

> 装到 `/workspace/installs/conda`（挂载卷里）而非 `/root`，这样容器重建后环境还在。

### 3.2 torch 与 torch-npu 必须**版本对齐**

```bash
pip3 install torch==2.1.0
pip3 install pyyaml setuptools
pip3 install torch-npu==2.1.0
pip3 install numpy attrs decorator psutil absl-py cloudpickle scipy synr tornado
```

**核心原理**：`torch_npu` 是一个“out-of-tree device backend”插件。它用 PyTorch 的 dispatcher 机制，把 `aten` 算子（如 `mm`、`add`）注册到一个新设备键 `PrivateUse1`（对外名字叫 `npu`）。所以：

- 版本号必须**严格相等**：`torch==2.1.0` ↔ `torch-npu==2.1.0`，差一个小版本就 ABI 不兼容直接崩。
- `import torch_npu` 这一句不能省——它执行时才完成算子注册，注册后 `.npu()` 才存在。

```
PyTorch dispatcher
   tensor.npu()  ──► 设备键 PrivateUse1 ("npu")
        │
   import torch_npu 注册的 kernel
        │
   CANN 算子库 (需 set_env.sh 注入路径)
        │
   910 A2 硬件执行
```

### 3.3 冒烟测试（必跑）

```python
import torch
import torch_npu                      # 必须，触发算子注册

x = torch.randn(2, 2).npu()
y = torch.randn(2, 2).npu()
z = x.mm(y)
print(z)
```

跑这段前一定先 `source /usr/local/Ascend/ascend-toolkit/set_env.sh`。能打印出 2×2 矩阵 = 驱动/CANN/torch-npu 三层贯通。

## 5. DeepSpeed ZeRO-3 微调 Qwen1.5-7B：显存怎么省

### 5.1 为什么 7B 全参要 ZeRO-3

一个参数在混合精度训练里，显存账（Adam）大致是：

$$M_{\text{state}} \approx \underbrace{2P}_{\text{fp16 权重}} + \underbrace{2P}_{\text{fp16 梯度}} + \underbrace{(4P+4P+4P)}_{\text{Adam: fp32 权重/动量/方差}} = 16P \ \text{字节}$$

对 $P=7\text{B}$：$16 \times 7\times10^9 \approx 112\,\text{GB}$，**远超单卡**（910 A2 单卡约 64GB）。ZeRO-3 把这 $16P$ 沿 8 张卡切分，每卡只存 $1/8$：

$$112\,\text{GB} / 8 \approx 14\,\text{GB/卡（仅状态）}$$

加上激活值也能塞进单卡——这就是必须 ZeRO-3 的原因。详见 [[ai-framework/deepspeed/README]] 与 [[docs/transformer内存估算]]。

```
单卡放不下 16P:        ZeRO-3 分片后:
┌──────────────┐       卡0  卡1  ...  卡7
│ 权重 2P      │       ┌──┐ ┌──┐     ┌──┐
│ 梯度 2P      │  ──►  │1/8│ │1/8│ ... │1/8│  权重
│ Adam  12P    │       │1/8│ │1/8│ ... │1/8│  梯度
└──────────────┘       │1/8│ │1/8│ ... │1/8│  优化器
  =112GB(7B)            前向时按需 all-gather 该层完整权重
```

### 5.2 训练命令（DeepSpeed ZeRO-3）

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
conda activate llm-dev
rm -rf /workspace/output/alpaca2/*

torchrun --nproc_per_node=8 --master_port=29001 train.py \
    --model_name_or_path /workspace/model/Qwen1.5-7B-Chat/ \
    --data_path /workspace/data/alpaca_gpt4_data_zh_5k.json \
    --fp16 True \
    --output_dir /workspace/output/alpaca2 \
    --per_device_train_batch_size 2 \
    --gradient_accumulation_steps=8 \
    --num_train_epochs 1 \
    --per_device_eval_batch_size 4 \
    --eval_strategy "no" \
    --save_strategy "steps" \
    --save_steps 2000 \
    --save_total_limit 1 \
    --learning_rate 2e-5 \
    --weight_decay 0. \
    --warmup_ratio 0.03 \
    --lr_scheduler_type "cosine" \
    --logging_steps 1 \
    --deepspeed ds_config_zero3.json
```

参数手算示例——**全局有效 batch size**：

$$\text{global bs} = \underbrace{2}_{\text{per\_device}} \times \underbrace{8}_{\text{grad\_accum}} \times \underbrace{8}_{\text{nproc(卡数)}} = 128$$

`--fp16 True`：910 A2 对 fp16 支持成熟；`warmup_ratio 0.03 + cosine`：前 3% step 线性升到 `2e-5` 再余弦衰减，稳住大模型微调早期。

## 6. FSDP + offload 微调 Qwen1.5-14B：放不下时的另一条路

14B 比 7B 又大一倍（$16P \approx 224\,\text{GB}$），即便 8 卡分片也吃紧，于是叠加 **CPU offload** + **gradient checkpointing**：

```bash
torchrun --nproc_per_node=8 --master_port=29001 train.py \
    --model_name_or_path /workspace/model/Qwen1.5-14B-Chat/ \
    --data_path ./alpaca_data_1k.json \
    --fp16 True \
    --output_dir /workspace/output/alpaca-qwen14 \
    --num_train_epochs 1 \
    --per_device_train_batch_size 1 \
    --per_device_eval_batch_size 4 \
    --gradient_accumulation_steps 8 \
    --gradient_checkpointing True \
    --eval_strategy "no" \
    --save_strategy "steps" \
    --save_steps 2000 --save_total_limit 1 \
    --learning_rate 2e-5 --weight_decay 0. \
    --warmup_ratio 0.03 --lr_scheduler_type "cosine" \
    --logging_steps 1 \
    --fsdp "full_shard offload auto_wrap" \
    --fsdp_transformer_layer_cls_to_wrap 'Qwen2DecoderLayer'
```

三个省显存开关的“为什么”：

| 开关 | 机制 | 代价 |
|---|---|---|
| `full_shard` | 参数/梯度/优化器全分片（=ZeRO-3 思路） | 多次 all-gather 通信 |
| `offload` | 把分片参数/优化器搬到 **CPU 内存** | PCIe/HCCS 来回拷，慢 |
| `gradient_checkpointing` | 前向不存激活，反向重算 | 多一次前向计算（约 +30% 算力） |

`--fsdp_transformer_layer_cls_to_wrap 'Qwen2DecoderLayer'`：告诉 FSDP **以哪个类为单位**做分片包裹。这必须对应模型源码里真实的 Decoder 层类名——Qwen1.5 是 `Qwen2DecoderLayer`，Baichuan2 是 `DecoderLayer`，**写错就不分片或直接报错**（这是 FSDP 最常见的坑）。

> 还出现过 `per_device_train_batch_size 2` 的 7B 版本，用纯 `--fsdp "full_shard auto_wrap"`（不 offload），说明：能放下就别开 offload，offload 是“用速度换显存”的最后手段。

### Baichuan2-7B 同款（注意层类名不同）

```bash
torchrun --nproc_per_node=8 --master_port=29001 train.py \
    --model_name_or_path /workspace/model/Baichuan2-7B-Chat \
    --data_path ./alpaca_data_1k.json \
    --fp16 True \
    --output_dir /workspace/output/baichuan2 \
    --num_train_epochs 1 \
    --per_device_train_batch_size 2 \
    --gradient_accumulation_steps 8 \
    --eval_strategy "no" --save_strategy "steps" \
    --save_steps 2000 --save_total_limit 1 \
    --learning_rate 2e-5 --weight_decay 0. \
    --warmup_ratio 0.03 --lr_scheduler_type "cosine" \
    --logging_steps 1 \
    --fsdp "full_shard auto_wrap" \
    --fsdp_transformer_layer_cls_to_wrap 'DecoderLayer'   # ← Baichuan 是 DecoderLayer
```

> 衡量训练效率别只看吞吐峰值，要看 **goodput（实际有效吞吐）**：扣掉通信等待、重算、offload 拷贝后真正推进训练的吞吐——offload 越多，goodput 通常越低。

## 7. ModelLink / Megatron：迈向大规模并行

Alpaca + DeepSpeed/FSDP 适合中小模型微调；更大规模（多机、TP/PP 并行）走华为 **ModelLink**（昇腾版 Megatron 适配）：

```bash
git clone https://gitee.com/ascend/apex.git          # 昇腾版混合精度 apex
git clone https://gitee.com/ascend/ModelLink.git     # 昇腾大模型套件
git clone https://github.com/NVIDIA/Megatron-LM.git  # 上游 Megatron
```

ModelLink 把 Megatron 的张量并行（TP）/流水并行（PP）算子替换为昇腾实现。原理与并行切分见 [[ai-framework/megatron-lm/README]]。从 FSDP/DeepSpeed 升到 Megatron 的动机：当模型大到**单层都放不下单卡**，就需要 TP 把单个矩阵乘也切开。

| 现象 / 报错 | 根因 | 解法 |
|---|---|---|
| `import torch_npu` 报 `libascend_hal.so` 找不到 | 没 source CANN 环境 | `source /usr/local/Ascend/ascend-toolkit/set_env.sh`；`find . -name libascend_hal.so` 验证 |
| `.npu()` 不存在 / 报错 | 漏写 `import torch_npu` | 必须先 import 才触发算子注册 |
| torch 与 torch-npu 版本不一致崩溃 | ABI 不兼容 | 严格 `torch==2.1.0` ↔ `torch-npu==2.1.0` |
| Conda 装不上 | 下了 x86 版 | 昇腾是 ARM，必须 `*-aarch64.sh` |
| `ck_decoderF/ckF is not supported: device=npu (supported: {'cuda'})` | xformers 只有 CUDA kernel，NPU 不支持 | `pip uninstall xformers`，改用原生 attention |
| `git lfs clone` 拉到的是几 KB 指针 | 没装 git-lfs | `git lfs install` 后重拉 |
| 访问 HuggingFace 超时 | 国产化机房无外网 | 走 ModelScope（魔搭）镜像源 |
| stanford_alpaca 运行报 openai 相关错 | utils.py 含 openai 调用 | 删除 utils.py 中 openai 代码 |
| FSDP 不分片 / 报 wrap 类找不到 | `..._cls_to_wrap` 类名写错 | Qwen1.5→`Qwen2DecoderLayer`，Baichuan2→`DecoderLayer` |
| 7B/14B 单卡 OOM | 全参状态 16P 超单卡 | 7B 用 DeepSpeed ZeRO-3；14B 叠加 `offload`+`gradient_checkpointing` |
| 多机训练通信慢/失败 | HCCL 走了 NAT 网络 | 容器加 `--network host`；用 `hccn_tool` 查 NPU 网络 |
