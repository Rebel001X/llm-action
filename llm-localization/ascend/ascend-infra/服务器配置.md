## 0. 一句话锚点

**一台昇腾 AI 服务器 = 8 张 NPU(达芬奇架构)+ 多颗鲲鹏/x86 CPU + 大内存 + 高速卡间互联(HCCS)+ 高速参数面网卡(RoCE)+ 分层存储。** "服务器配置"这件事的本质,是按"训练 / 推理"两种负载,把这几样东西**配成不短板的木桶**——任何一项拖后腿,贵几十万的 NPU 算力就被浪费。

本文示例配置(顶部已有)对应 **Atlas 800 训练服务器(型号 9000/9010 一类)+ 8 × Ascend 910B + 4 × 鲲鹏920**,这是当前国产大模型训练的主力机型之一。

> 护栏:本文不写精确型号尾缀/内存条数/固件版本/带宽确切数字,**凡涉及具体规格、命令、版本一律以华为昇腾官方文档(Ascend 社区)与服务器随机手册为准**。这里只讲"每一项为什么这么配、配比的逻辑、常见坑"。

## 1. 地基:在昇腾栈的定位 + 对标英伟达生态

服务器是整个昇腾软件栈的**最底层硬件载体**。软件栈自下而上:

```
        ┌─────────────────────────────────────────┐
        │  套件层  MindFormers / MindIE / ModelLink │  ← 训练/推理套件
        ├─────────────────────────────────────────┤
        │  框架层  MindSpore / PyTorch(+ torch_npu) │  ← 训练框架
        ├─────────────────────────────────────────┤
        │  CANN    算子库 + HCCL + Runtime + Driver │  ← 相当于 CUDA 全家桶
        ├─────────────────────────────────────────┤
        │  硬件层  Ascend NPU(达芬奇) + 鲲鹏 CPU    │  ← 本文:服务器配置
        │          ↑ 就是这一层 ↑                    │
        └─────────────────────────────────────────┘
```

"服务器配置"决定了上面所有层能跑多大模型、多快。配错了,再好的 MindFormers 也喂不饱。

### 昇腾 ↔ 英伟达 生态对照表(迁移心智图)

| 维度 | 昇腾(华为) | 英伟达 | 说明 |
|------|-----------|--------|------|
| 加速卡 | Ascend NPU(910B 训练 / 310P 推理) | GPU(H100/A100 训练 / L40 等推理) | 达芬奇架构 ↔ SIMT 架构 |
| 整机 | Atlas 800 训练/推理服务器 | DGX / HGX 服务器 | 8 卡一体机是行业默认形态 |
| 主机 CPU | 鲲鹏920(ARM,自研) | x86(Intel/AMD) | 昇腾常配鲲鹏构成"全栈国产" |
| 卡间互联 | HCCS / 华为 Cache 一致总线 | NVLink / NVSwitch | 板内 8 卡全互联,绕开 PCIe |
| 跨机网络 | RoCE(基于以太)参数面网卡 | InfiniBand / RoCE | 参数面专网,跑梯度同步 |
| 软件平台 | CANN | CUDA | 驱动+运行时+算子+通信 |
| 算子库 | CANN 算子(AOL/aclnn) | cuDNN / cuBLAS | 卷积/矩阵乘等高性能核 |
| 集合通信 | HCCL | NCCL | AllReduce/AllGather 等 |
| 训练框架 | MindSpore / PyTorch+torch_npu | PyTorch / TensorFlow | 昇腾两条腿走路 |
| 训练套件 | MindFormers / ModelLink | Megatron-LM / HF Trainer | 并行+大模型脚本 |
| 推理引擎 | MindIE | TensorRT-LLM / vLLM | 服务化推理 |
| 量化工具 | msModelSlim | GPTQ / AWQ 工具链 | 权重量化 |
| 监控/管理 | npu-smi | nvidia-smi | 查卡/温度/利用率 |

**一句话**:把脑中"DGX = 8×GPU + NVLink + IB + x86"这张图,平移成"Atlas 800 = 8×NPU + HCCS + RoCE + 鲲鹏",大部分系统设计直觉都能复用。

## 2. 一台服务器内部长什么样(物理拓扑)

理解配置前先看一台 8 卡机的内部结构。下面是逻辑拓扑(非精确接线,具体以手册为准):

```
        Atlas 800 训练服务器(单机)
 ┌──────────────────────────────────────────────────┐
 │  鲲鹏920 CPU ×4 (NUMA 多路)      内存 DDR ×N        │
 │     │           │                                  │
 │  ┌──┴───────────┴──────────────────────────────┐  │
 │  │   PCIe Switch / 主机总线                       │ │
 │  └──┬────┬────┬────┬────┬────┬────┬────┬────────┘  │
 │   NPU0 NPU1 NPU2 NPU3 NPU4 NPU5 NPU6 NPU7          │
 │    └────┴────┴────┴─ HCCS 全互联 ─┴────┴────┴─┘     │
 │    (8 张 NPU 之间走 HCCS,不经 PCIe,带宽远高)        │
 │                                                    │
 │   RoCE 参数面网卡 ×K ──────► 交换机 ──► 其它服务器   │
 │   业务面网卡(管理/数据加载) ──► 业务网              │
 │   本地盘:系统盘 SSD ×2 + 数据盘 NVMe SSD ×2          │
 └──────────────────────────────────────────────────┘
```

要点:
- **NPU 之间靠 HCCS 板内全互联**(对标 NVLink/NVSwitch),所以单机 8 卡做张量并行/序列并行时,卡间通信极快;
- **跨机靠 RoCE 参数面网卡**(对标 IB),梯度 AllReduce 走这张网;
- **CPU 是鲲鹏(ARM)**,有 NUMA 概念,数据预处理/HostToDevice 拷贝都经它;
- **存储分两层**:系统盘(SSD)+ 数据盘(大容量 NVMe)。

## 3. 训练 vs 推理:两套配置思路

这是"服务器配置"最核心的决策点——**先问负载是训练还是推理**,二者瓶颈完全不同。

### 3.1 训练型(顶部示例就是这一类)

目标:吃满算力 + 撑住大 batch + 多机不掉速。配置取向:

| 部件 | 取向 | 为什么 |
|------|------|--------|
| NPU | 910B 训练卡 ×8,优先大显存版本 | 显存决定能放多大模型/多长序列 |
| CPU | 鲲鹏920 多路(如 4 路) | 多进程 dataloader、HostToDevice 不卡 |
| 内存 | 大(示例给到 512G~1T) | ≥ NPU 总显存,做参数 offload/数据缓存 |
| 网络 | 高速 RoCE 参数面 + 业务面双网 | 跨机梯度同步是训练扩展性命门 |
| 存储 | 系统盘 SSD + 大容量 NVMe 数据盘 | 海量训练数据吞吐 |

顶部"最低/推荐配置"差异本质是:**910B4 vs 910B3 卡 + 512G vs 1T 内存 + 盘容量**——推荐配置内存翻倍、盘更大,为更大模型/更长训练数据流做余量。

### 3.2 推理型

目标:高吞吐 + 低时延 + 高卡密度/低成本。配置取向:

| 部件 | 取向 | 为什么 |
|------|------|--------|
| NPU | 多用 310P 推理卡(也可 910B 跑大模型) | 推理算力/功耗比更优,成本低 |
| CPU | 可适当降配 | 推理对 CPU 预处理压力小于训练 |
| 内存 | 中等即可 | 不需要大 batch 的海量缓存 |
| 网络 | 业务面为主,参数面可弱化 | 推理多为单机或小规模并行 |
| 存储 | 放得下权重即可 | 不需要训练级数据吞吐 |

**心智模型**:训练机是"全能型 + 强网络",推理机是"高密度 + 低成本"。别用训练配置去堆推理(浪费),也别用推理配置硬扛训练(网络/内存短板拖垮)。

## 4. 配比逻辑:每一项为什么这么配(木桶原理)

服务器配置最常见的错误是"NPU 堆满,其它将就",结果算力空转。逐项讲配比逻辑:

```
   算力被谁卡住?  ——  找最短那块木板
   ┌──────────────────────────────────────────┐
   │  NPU 显存  ── 放不下模型/序列 → OOM         │
   │  主机内存  ── < NPU 显存 → offload 失效     │
   │  CPU 核数  ── dataloader 喂不动 → NPU 饿着  │
   │  参数面网络 ── 慢 → 多机 AllReduce 等通信   │
   │  数据盘吞吐 ── 慢 → 每个 step 等读数据      │
   └──────────────────────────────────────────┘
       任何一块短,整桶水位(实际利用率)就在那
```

- **内存 ≥ NPU 总显存** 是经验底线:做优化器状态 offload、数据预取缓存都吃主机内存;示例从 512G 提到 1T 就是给这个余量。
- **CPU 核数对应 dataloader 并行度**:多路鲲鹏提供足够进程数把数据准备好,否则 NPU 等数据"饿着"。
- **参数面网络是多机训练的命门**:8 卡板内有 HCCS 很快,但**一旦跨机,梯度同步全靠 RoCE 参数面**;网卡慢 → 扩展效率(从 1 机到 N 机的加速比)直接崩。
- **存储分层**:系统盘求稳(SSD 双盘可做冗余),数据盘求吞吐(大容量 NVMe),训练数据通常还会挂**共享存储/并行文件系统**给多机共享读。

## 5. 多机组集群:双网络平面

单机配完,多机要组集群训大模型。关键是**两张网络平面分开**:

```
      ┌─ 参数面(RoCE 专网) ─┐    高速、低时延,只跑梯度/通信
  ┌───┴───┐   ┌───────┐   ┌───┴───┐
  │ 服务器1│──│ RoCE  │──│ 服务器2│  ... ×N
  └───┬───┘   │ 交换机 │   └───┬───┘
      │       └───────┘       │
      └─ 业务面(以太网) ───────┘     管理、数据加载、调度
```

- **参数面**:只跑 HCCL 的集合通信(AllReduce/AllGather),独享高速专网,不被业务流量干扰;对标 GPU 集群的 IB/RoCE 计算网。
- **业务面**:管理、镜像拉取、数据集加载、作业调度走这里。
- 两网分离是为了让**梯度同步永远不被业务流量挤占**——这是大规模训练线性加速比的工程前提。
- 集群规模上去后,**网络拓扑(轨道/Spine-Leaf)+ HCCL 的 ring/分层算法**共同决定 AllReduce 效率(原理见 [[ai-infra/网络/集合通信原语]])。

## 迁移要点 / 注意事项与坑

从 GPU 集群迁到昇腾,服务器层面要重新审视:

1. **CPU 架构变了(x86 → ARM 鲲鹏)**:很多预编译二进制、依赖库要 **ARM/aarch64 版本**;Docker 镜像必须拉 ARM 架构基础镜像,否则起不来。这是最常见的第一个坑。
2. **卡间互联换名(NVLink → HCCS)**:并行切分思路(TP/PP)不变,但拓扑亲和(哪几张卡互联更快)要按 HCCS 拓扑重排,别照搬 NVLink 的 group 划分。
3. **网卡是 RoCE 不是 IB**:参数面要确认 RoCE 配置(无损网络/PFC/ECN 等)正确,否则多机训练会出现莫名其妙的通信卡顿/掉速。具体配置以官方文档为准。
4. **`nvidia-smi` → `npu-smi`**:查卡、温度、利用率、亲和换工具;监控脚本要重写。
5. **NUMA 亲和**:鲲鹏多路 NUMA,进程/内存绑核没绑好,HostToDevice 拷贝会跨 NUMA 变慢。
6. **木桶别破**:迁移时最容易"只换卡不换网/内存",结果单机能跑、多机加速比上不去——一定按第 4 节逐项核配比。
7. **固件/驱动/CANN 版本要配套**:Driver、Firmware、CANN、torch_npu 之间有版本配套矩阵,**版本错配是装机阶段最高频故障**;具体配套关系与命令以华为昇腾官方文档(Ascend 社区)为准。

> 再次护栏:以上不给任何精确版本号/命令/带宽数字。装机、组网、Docker、驱动安装的**确切命令与版本,一律以华为昇腾官方文档(Ascend 社区)及服务器随机手册为准**。本文只负责把"为什么要这步、配比逻辑、坑在哪"讲清。

## 常见问题

| 问题 | 回答 |
|------|------|
| 训练就用 910B,推理也得用 910B 吗? | 不一定。推理常用 310P(更优功耗比/成本);大模型推理也可用 910B。按吞吐/时延/成本权衡。 |
| 内存为什么要 ≥ NPU 总显存? | 优化器状态 offload、数据预取缓存都吃主机内存;不够会 offload 失效或 dataloader 阻塞。 |
| 单机 8 卡靠什么互联? | HCCS 板内全互联(对标 NVLink),带宽远高于走 PCIe。 |
| 多机训练慢的最常见原因? | 参数面网络(RoCE)没配好或被业务流量挤占;务必双网分离。 |
| CPU 一定要鲲鹏吗? | 不强制,也有 x86 配置;鲲鹏(ARM)用于"全栈国产",但要注意软件包的 ARM 适配。 |
| 顶部"最低 vs 推荐"差在哪? | 主要是 NPU 型号(910B4/910B3)、内存(512G/1T)、盘容量——推荐配置留更大余量。 |
| 怎么查卡状态? | 用 `npu-smi`(对标 `nvidia-smi`),具体子命令以官方文档为准。 |
| 迁移第一个坑通常是什么? | CPU 是 ARM,镜像/依赖要拉 aarch64 版本,否则容器都起不来。 |
