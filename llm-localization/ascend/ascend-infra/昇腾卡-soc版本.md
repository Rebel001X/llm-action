## 0. 一句话锚点

**SOC 版本(SOC Version)是昇腾芯片对软件暴露的一个整数标识**，CANN(昇腾异构计算架构)用它来判断"我现在面对的是哪一代、哪一款 NPU"，进而决定：加载哪套算子二进制、走哪条编译路径、开放哪些硬件特性。

你打开本文件最上面看到的那张表，就是 **SOC 版本号(整数) → 设备类型(芯片型号字符串)** 的对照：

```
SOC版本：设备类型
100: "910PremiumA", 101: "910ProA", 102: "910A", 103: "910ProB", 104: "910B",
200: "310P1", 201: "310P2", 202: "310P3", 203: "310P4",
220: "910B1", 221: "910B2", 222: "910B3", 223: "910B4",
240: "310B1", 241: "310B2", 242: "310B3",
250: "910C1", 251: "910C2", 252: "910C3", 253: "910C4"
```

理解了这张表，你就能把"我手上插的是哪张卡 / CANN 报错说不支持的 soc_version 是什么"这类问题一眼看穿。

## 1. 地基：在昇腾栈的定位 + 对标英伟达生态

### 1.1 它在哪一层

昇腾软件栈自底向上大致是：**硬件(NPU 芯片) → 驱动/固件 → CANN(含 Runtime、GE 图引擎、算子库) → 训练/推理框架(MindSpore / PyTorch+torch_npu) → 套件(MindFormers / MindIE)**。

SOC 版本横跨"硬件 ↔ CANN"这道边界：它由**芯片固件**烧录、暴露，被 **CANN 运行时与编译器**读取消费。它不是一个软件版本号，而是**对硬件代次的编码**。

```
   你写的模型 / 套件 (MindFormers, MindIE)
        │  调用
        ▼
   框架层 (MindSpore / PyTorch+torch_npu)
        │  下发计算图 / 算子
        ▼
 ┌───────────── CANN ─────────────┐
 │  GE 图引擎   编译器   算子库     │  ← 读取 SOC 版本，决定：
 │  AscendCL / Runtime            │     · 选哪份算子 .o
 └───────────────┬────────────────┘     · 走哪条 Cube/Vector 路径
                 │  查询                  · 开放哪些指令/特性
                 ▼
        驱动 / 固件 (npu-smi 可见)
                 │  暴露
                 ▼
   昇腾 NPU 芯片 (达芬奇架构)  ←── SOC 版本就刻在这里
```

### 1.2 对标英伟达生态(迁移心智图)

把昇腾世界的概念逐一对到你熟悉的 CUDA 世界，是迁移时最省力的方式：

| 昇腾(Ascend) | 英伟达(NVIDIA) | 说明 |
| --- | --- | --- |
| **SOC 版本(soc_version)** | **Compute Capability / SM 架构(如 sm_90)** | 都是"芯片代次指纹"，决定编译目标与可用特性 |
| NPU(达芬奇架构) | GPU(SM 架构) | 加速器硬件本体 |
| CANN | CUDA Toolkit | 异构计算软件栈总称 |
| AscendCL / Runtime | CUDA Runtime / Driver API | 运行时与设备管理接口 |
| CANN 算子库(AOL/算子) | cuDNN / cuBLAS | 高性能算子/数学库 |
| GE(Graph Engine 图引擎) | TensorRT 图优化 / CUDA Graph | 图编译与优化 |
| HCCL | NCCL | 多卡集合通信 |
| MindSpore | PyTorch / TensorFlow | 深度学习框架 |
| torch_npu | (PyTorch 原生 CUDA 后端) | 让 PyTorch 跑在昇腾上的适配层 |
| MindFormers | Megatron-LM / HF Transformers | 大模型训练套件 |
| MindIE | TensorRT-LLM / vLLM | 大模型推理引擎 |
| msmodelslim | GPTQ / AWQ 量化工具 | 模型压缩工具 |
| **npu-smi** | **nvidia-smi** | 设备查询与监控；SOC 版本就从这里读 |

**关键对照——SOC 版本 ≈ CUDA 的 Compute Capability。** 你在英伟达上用 `sm_80`、`sm_90` 来告诉编译器"为这代架构生成代码"；在昇腾上，CANN 用 soc_version(如 `Ascend910B`、`Ascend310P3`)来选对应的算子二进制与编译目标。两者都不是"驱动版本"，而是"硬件能力标签"。

## 2. SOC 版本号映射表的来龙去脉

文件顶部那张表里的整数，是按"芯片家族 + 子型号"分段编排的。把它按段读，规律就出来了：

| 整数段 | 家族 | 典型用途 | 你该联想的英伟达定位 |
| --- | --- | --- | --- |
| 100–104 | 910 第一代(910A 系) | 训练主力(上一代) | 类比上一代训练卡 |
| 200–203 | 310P(310P1–P4) | 推理 / 边缘 | 类比推理/边缘加速卡 |
| 220–223 | 910B(910B1–B4) | 当前主流训练/推理 | 当前主力训练卡 |
| 240–242 | 310B(310B1–B3) | 边缘 / 端侧 | 端侧小算力 |
| 250–253 | 910C(910C1–C4) | 新一代训练 | 新一代训练卡 |

读法要点：

- **数字本身没有"性能高低"的连续含义**，它只是一个编码槽位。不要因为 104 < 220 就推断 910A 比 910B1 弱很多——要看家族,数字仅区分代次与子档。
- **同一家族内的子型号(B1/B2/B3/B4)** 往往对应不同的算力规格、内存配置或市场分档(整卡/模组),但对外暴露的 soc_version 字符串通常聚合到家族级(如统一识别为 `Ascend910B`),具体粒度以官方文档为准。
- **310 系偏推理/边缘,910 系偏训练**:首位数字就划了大类。

> ⚠️ 注意:**上面这张整数→型号的映射,是用于解读硬件上报的设备类型枚举,属于内部识别口径**。CANN 在编译/运行时真正消费的 soc_version 通常是**字符串形式**(如 `Ascend910B`)。两者是一一对应但表现层不同的东西,别混用。具体取值与对应关系以华为昇腾官方文档(Ascend 社区)为准。

## 3. 芯片命名拆解:把字面读懂

昇腾卡型号字符串里的每一段都有信息量。以表中出现的几类为例:

```
   910  B   2
    │   │   └── 子型号档位 (1/2/3/4):算力/规格/形态分档
    │   └────── 代次字母 (A→B→C):越靠后越新
    └────────── 家族数字 (910=训练系, 310=推理/边缘系)

   910  Premium A      910  Pro  B
    │      │     │       │    │   │
    │      │     └代次   │    │   └代次
    │      └规格档(高配)  │    └规格档(Pro)
    └家族                └家族
```

- **首位家族**:`910*` = 训练/高算力;`310*` = 推理/边缘;`310P*` = 推理增强(P = 推理增强档)。
- **代次字母**:`A → B → C`,字母越靠后代表越新的硬件代次(对标英伟达一代代架构演进)。
- **规格修饰**:`Premium / Pro` 是规格/市场分档修饰词;尾部 `A/B/...` 再叠一层代次,所以会出现 `910PremiumA`、`910ProB` 这种"修饰+代次"组合。
- **子型号数字**:`910B1/B2/B3/B4`、`310P1/P2/P3/P4` 中的数字区分具体硬件子档(整卡 vs 模组、算力/显存规格等)。

记忆口诀:**首位看用途(910 训练/310 推理),字母看新旧(A<B<C),后缀看分档**。

## 4. 软件栈如何使用 SOC 版本

理解这条链路,就理解了 SOC 版本为什么重要:

```
 ① npu-smi / 驱动接口
      │  读出芯片上报的设备类型 → 映射为 soc_version
      ▼
 ② CANN Runtime / 编译器拿到 soc_version
      │  作为"目标架构"标签
      ▼
 ③ 选择匹配的算子二进制 (.o) 与编译路径
      │  不同代次的 Cube/Vector 指令、特性不同
      ▼
 ④ 生成可在该代次 NPU 上执行的指令流
      │
      ▼
 ⑤ 在 NPU(达芬奇 Cube/Vector 单元)上跑起来
```

类比英伟达:这就像 `nvcc` 拿到 `-arch=sm_90` 后,为 Hopper 生成 SASS;换一代卡,目标不同,生成的机器码就不同。**SOC 版本错配的后果**,等价于"用 sm_80 的二进制去 sm_90 上跑、或反过来"——轻则性能不优,重则算子找不到 / 不支持而直接报错。

## 5. 怎么查 SOC 版本(讲含义,不背命令)

实操中你会用到三条途径,这里只讲**每条途径"在查什么、为什么"**,具体命令与参数以华为昇腾官方文档(Ascend 社区)为准:

1. **设备侧命令行工具(对标 nvidia-smi)**
   通过昇腾的设备管理命令行(npu-smi 一类)查看插了哪些卡、是什么型号。这是最直接的"我手上是什么卡"。它读的是驱动/固件上报的设备类型。

2. **CANN 运行时 / AscendCL 接口查询**
   程序里通过 CANN 提供的运行时接口获取当前设备的 soc_version 字符串。框架(torch_npu / MindSpore)和套件初始化时常这样拿到目标架构,用于后续编译。

3. **框架 / 套件的环境与日志**
   训练/推理框架启动时,通常会在日志里打印识别到的 soc_version。当报错"不支持的 soc_version"或"算子未找到"时,第一件事就是看这里识别出来的值,和你期望的卡对不对得上。

> 反复强调:以上三条只描述**做这件事的意图与依赖关系**。任何精确命令、参数、包名、版本号,一律以**华为昇腾官方文档(Ascend 社区)**为准,切勿照本文凭记忆敲。

## 迁移要点 / 注意事项与坑

从 CUDA/GPU 世界迁过来,围绕 SOC 版本最容易踩的坑:

- **别把 SOC 版本当成驱动版本或 CANN 版本。** 它是**硬件代次指纹**,类比 `sm_90` 而非 `CUDA 12.x`。驱动/CANN 升级不会改变芯片的 SOC 版本。
- **整数枚举 ≠ 字符串 soc_version。** 顶部那张表是设备类型整数枚举;CANN 编译用的是字符串(如 `Ascend910B`)。两套表现层别混。
- **soc_version 错配 = 算子找不到。** 拿到为某代次预编译的算子包/模型,放到不同代次的卡上跑,可能直接报"不支持"。迁移前先确认**目标卡的 soc_version 与软件包/编译目标一致**。
- **同家族不同子档,行为可能不同。** 910B1/B2/B3/B4 虽聚合为同一家族识别,但算力/显存不同,**性能与可跑的最大模型规模会有差异**;做容量规划时按真实子型号看规格。
- **310 系不是"小一号的 910"。** 它面向推理/边缘,架构取向不同;把训练脚本原样搬到 310 上往往不合适。先看用途家族再谈迁移。
- **版本对齐是部署第一关。** 卡的 SOC 版本 ↔ CANN 版本 ↔ 框架/套件版本之间存在配套矩阵。任何一环错配都会在编译/加载阶段暴雷。**配套关系以官方版本配套表为准**。
- **性能调优从"选对算子路径"开始。** 因为 SOC 版本决定了走哪套 Cube/Vector 实现,调优时确认算子确实命中了该代次的高性能实现,而非回退到通用慢路径(这与英伟达"是否命中 Tensor Core 路径"同理)。

## 常见问题

| 问题 | 解答 |
| --- | --- |
| SOC 版本和 CANN 版本是一回事吗? | 不是。SOC 版本是硬件代次指纹(类比 sm_90),CANN 版本是软件栈版本(类比 CUDA Toolkit 版本)。 |
| 表里整数 104 < 220,是说 910A 比 910B1 差吗? | 整数只是编码槽位,不表示连续性能高低;要按家族(910A 系 vs 910B 系)和代次理解。 |
| 它对标英伟达的什么? | 最贴切的是 Compute Capability / SM 架构(如 sm_80/sm_90),都决定编译目标与可用特性。 |
| 整数枚举和字符串 soc_version 怎么对应? | 一一对应、表现层不同。整数是设备类型枚举,字符串是 CANN 编译消费的目标架构标签;确切对应以官方文档为准。 |
| 报错"unsupported soc_version"怎么排查? | 先确认卡的真实 soc_version,再核对软件包/模型/算子是否为该代次编译,以及 CANN/框架版本是否配套。 |
| 怎么查我这张卡的 SOC 版本? | 用设备命令行(npu-smi 一类)、CANN 运行时接口、或框架启动日志三选一;具体命令以官方文档为准。 |
| 310 和 910 能互换跑吗? | 不建议。310 偏推理/边缘,910 偏训练,定位与架构取向不同。 |
