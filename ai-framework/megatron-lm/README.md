## 0. 一句话锚点

**Megatron-LM = "把一个 Transformer 沿着不同维度切开，分给很多 GPU，并保证切完之后数学上等价于没切"的一套工程。**

它本身不是新模型，而是一套**并行策略 + 高效 kernel + 通信编排**的训练代码库。核心贡献是提出了 Transformer 的**张量并行 (Tensor Parallelism)** 切法，后来又加了**序列并行**、与流水并行/数据并行的组合，成为业界训练 GPT 类大模型的事实标准实现。

记住一个总纲：

```
   想训一个超大模型，三件事会爆：
   ┌─────────────┬──────────────────────────┬───────────────────────┐
   │  参数装不下  │   激活值(activation)装不下 │   单卡算太慢/通信太多   │
   ├─────────────┼──────────────────────────┼───────────────────────┤
   │  → 张量并行  │   → 流水并行 + 序列并行    │   → 数据并行 + 重叠通信 │
   │    (TP)     │      (PP + SP)            │      (DP + overlap)   │
   └─────────────┴──────────────────────────┴───────────────────────┘
   Megatron 的全部技巧，都是在这三件事上做文章。
```

## 1. 地基/前置：单卡到底卡在哪

### 1.1 先把"一张 GPU 的预算"摆出来

一张 GPU（比如 80GB 显存）训练时，显存被四样东西吃掉：

$$
\text{显存} = \underbrace{P}_{\text{参数}} + \underbrace{G}_{\text{梯度}} + \underbrace{O}_{\text{优化器状态}} + \underbrace{A}_{\text{激活值}}
$$

用 Adam + 混合精度 (fp16/bf16) 训练时，对每个参数：

- 参数本体 fp16：2 字节
- 梯度 fp16：2 字节
- 优化器：fp32 主参数 4 + 一阶动量 4 + 二阶动量 4 = 12 字节

所以**每个参数约 16 字节**（不含激活）。

**手算**：一个 175B（1750 亿）参数的模型：

$$
175 \times 10^9 \times 16 \text{ B} = 2.8 \times 10^{12}\,\text{B} \approx 2800\,\text{GB}
$$

一张 80GB 的卡？连参数+优化器状态的零头都装不下，需要 $\lceil 2800/80\rceil = 35$ 张卡**仅仅为了放下静态状态**，激活还没算。这就是必须并行的根因。

### 1.2 两类"装不下"，对应两类切法

```
   ┌──────────────────────────────────────────────────────┐
   │ A. 模型状态 (参数/梯度/优化器) 装不下                  │
   │    特点: 静态, 大小固定, 与 batch 无关                 │
   │    → 沿"模型结构"切: 张量并行(切矩阵) / 流水并行(切层) │
   ├──────────────────────────────────────────────────────┤
   │ B. 激活值装不下                                        │
   │    特点: 动态, ∝ batch×seq×hidden×层数               │
   │    → 重计算 / 流水并行(每卡只存自己层的激活) / 序列并行 │
   └──────────────────────────────────────────────────────┘
```

Megatron 的价值就在于：**A 和 B 它都管，而且把切法做到了"通信量最小、kernel 最快"。**

## 2. 三/四种并行总览：它们各切什么维度

一个 Transformer 的"计算"可以想象成一个三维盒子：**(层数 L) × (隐藏维 H) × (批×序列 B×S)**。四种并行各沿一个维度切：

```
                  ┌─────────────────────────────────────────┐
                  │              一个 Transformer            │
                  └─────────────────────────────────────────┘
   维度           切法            一组 GPU 干的事
   ───────────────────────────────────────────────────────────
   层 L      流水并行 PP    GPU0 管第1-8层, GPU1 管第9-16层...
   隐藏 H    张量并行 TP    同一层的大矩阵, 每张卡只算一片列/行
   批 B      数据并行 DP    每卡跑不同样本, 最后 all-reduce 梯度
   序列 S    序列并行 SP    LN/Dropout 那段沿 seq 切, 配合 TP
```

**关键直觉**：这四种并行**互相正交**，可以同时叠加。Megatron 用一个"并行网格 (mesh)"来表达：

$$
\text{总GPU数} = \text{TP} \times \text{PP} \times \text{DP}
$$

```
   例: 64 卡 = TP=8 × PP=2 × DP=4
   ┌── DP 组0 ──┐ ┌── DP 组1 ──┐ ... (共4个DP副本)
   │ PP段0: [TP0..TP7]  ← 8卡张量并行算前半部分层
   │ PP段1: [TP0..TP7]  ← 8卡张量并行算后半部分层
   └────────────┘ └────────────┘
```

记一条经验法则（后面会解释为什么）：

> **TP 优先放在一台机器内（NVLink 域内），PP 跨机器，DP 最外层。**
> 因为 TP 通信最频繁、最重，必须走最快的链路。

## 3. 张量并行 (Tensor Parallelism)：把矩阵切开

这是 Megatron 的招牌。核心问题：一个 $Y = XW$ 的大矩阵乘法，$W$ 太大单卡装不下，怎么切才能**既省显存、又少通信、又数学等价**？

有两种切法：

```
   按列切 (column-parallel):  W = [W1 | W2]
      → Y = X·[W1|W2] = [X·W1 | X·W2]    每卡算一片输出列, 输出天然分块
   按行切 (row-parallel):     W = [W1; W2],  X = [X1 | X2]
      → Y = X1·W1 + X2·W2                每卡算一部分, 结果需相加(all-reduce)
```

Megatron 的精髓：**把这两种切法巧妙搭配，让中间的激活不需要通信，只在每个 block 末尾做一次 all-reduce。**

### 3.1 FFN（MLP）怎么切

FFN 是两层：$Z = \text{GeLU}(X W_1)\, W_2$。

```
   X ──► [W1 按列切] ──► GeLU ──► [W2 按行切] ──► all-reduce ──► 输出
        (column-parallel)        (row-parallel)
   ┌─────────────────────────────────────────────────────────┐
   │ GPU0:  X·W1_a → GeLU → ·W2_a ┐                          │
   │ GPU1:  X·W1_b → GeLU → ·W2_b ┼─► all-reduce 求和 = Z    │
   └─────────────────────────────────────────────────────────┘
```

**为什么 W1 按列、W2 按行？** 因为 GeLU 是逐元素非线性，$\text{GeLU}(XW_1)$ 必须在"完整的一列输出"上做才正确。按列切后，每卡拿到的是**完整的若干列**，GeLU 可以独立做、不需通信。然后 W2 按行切，正好和上一步的列切对齐（行号=上一步列号），两片各自算完后相加即可。

> 整个 FFN **前向只需 1 次 all-reduce**（在最后），中间的 GeLU 零通信。这就是切法选择的全部目的。

### 3.2 自注意力 (Self-Attention) 怎么切

注意力天然就是**多头**的，每个 head 独立计算，所以**按 head 切**是最自然的张量并行：

```
   输入 X
     │
     ├──► QKV 投影 [按列切] : 每卡负责一部分 head 的 Q,K,V
     │       GPU0: head 0..h/2-1      GPU1: head h/2..h-1
     ├──► 每卡独立算 softmax(QKᵀ/√d)·V  ← head 间本就独立, 零通信!
     │
     └──► 输出投影 Wo [按行切] ──► all-reduce ──► 输出
```

**为什么这样切零浪费？** 多头注意力的数学本质就是"每个 head 各算各的，最后拼接"。按 head 把 Q/K/V 投影按列切，每卡拿到完整的几个 head，注意力计算 (QKᵀ、softmax、加权 V) **完全独立无需通信**。最后输出投影 $W_o$ 按行切，再 all-reduce 求和。

> 注意力块同样：**前向 1 次 all-reduce，反向 1 次 all-reduce**。

### 3.3 一个 Transformer 层的 TP 通信账

每个 Transformer 层 = 1 个注意力块 + 1 个 FFN 块。所以：

```
   前向: 注意力 all-reduce ×1 + FFN all-reduce ×1 = 2 次
   反向: 同样 2 次
   ───────────────────────────────────────────────
   每层每次迭代: 4 次 all-reduce   (这就是 TP 通信"重"的原因)
```

正因为每层都要 all-reduce，且 all-reduce 在前向反向路径的**关键路径上**（不能被计算掩盖），**TP 必须放在 NVLink/NVSwitch 这种超高带宽域内**，通常 TP size ≤ 单机 GPU 数（如 8）。跨机做 TP 会被 PCIe/网络拖死。

## 4. 流水并行 (Pipeline Parallelism)：把层切开

TP 切到 8 卡就到顶了（受单机限制）。模型还更大？那就**按层切**：GPU0 放第 1-8 层，GPU1 放第 9-16 层……数据像流水线一样从前往后流。

### 4.1 朴素流水的"气泡"问题

```
   朴素流水 (一个 batch 走完才进下一个):
   时间 ──────────────────────────────────►
   GPU0: [F0]              [B0]
   GPU1:     [F1]      [B1]
   GPU2:         [F2][B2]
   GPU3:           [F3][B3]
            ↑空闲↑      ↑空闲↑     ← 这些空白就是"气泡 bubble"
```

**气泡 = GPU 等着上游/下游、闲着没事干的时间**。流水级数越多，气泡占比越大。

### 4.2 微批 + 1F1B 调度：把气泡压小

办法：把一个大 batch 拆成 $m$ 个**微批 (micro-batch)**，让它们在流水线里"错峰"流动。理想气泡占比：

$$
\text{bubble ratio} = \frac{p - 1}{m}
$$

其中 $p$ 是流水级数，$m$ 是微批数。**微批越多，气泡越小。**

Megatron 用 **1F1B (one-forward-one-backward)** 调度：稳定期每个 GPU 交替做"一次前向、一次反向"，让**每张卡同时只需缓存少量微批的激活**，显存友好。

```
   1F1B 稳定段 (以 GPU1 为例):
   ... F F B F B F B B ...   前向反向交错, 激活及时释放
   对比"全前向再全反向": 要存下所有微批激活 → 显存爆炸
```

### 4.3 交错式流水 (interleaved / virtual pipeline)

Megatron 还支持把每张卡的层**再切成多个"虚拟阶段"**交错排布，进一步把气泡压到：

$$
\text{bubble ratio} = \frac{1}{v}\cdot\frac{p-1}{m}
$$

$v$ 是每卡虚拟阶段数。代价是通信次数变多。

> PP 的通信是**点对点 (P2P / send-recv)**：只在相邻流水级之间传"边界激活"，通信量小但有顺序依赖，所以 PP 可以跨机器（带宽要求远低于 TP）。

## 5. 序列并行 (Sequence Parallelism)：再省一刀激活

TP 切了矩阵，但 Transformer 层里还有 **LayerNorm 和 Dropout** 这些**逐元素/逐 token** 的操作。这些操作 TP 切不了（它们不是大矩阵乘法），于是**每张 TP 卡都得保留完整的激活** $[b, s, h]$ —— 这部分激活是冗余存储的，很浪费。

序列并行的洞察：**LN/Dropout 沿 hidden 维不可切，但沿 sequence 维可以切！**

```
   一个 TP 区域内:
   ┌─ LN/Dropout 段 ──┐   ┌─── 注意力/FFN 段 (TP) ───┐
   │ 沿 seq 切 (SP):  │   │ 沿 hidden 切 (TP):       │
   │ GPU0: token0..s/2│   │ GPU0: 一半 head/列        │
   │ GPU1: tokens/2..s│   │ GPU1: 另一半             │
   └──────────────────┘   └─────────────────────────┘
        ↑ all-gather/reduce-scatter 在两段交界处转换布局
```

**关键工程点**：SP 和 TP 在同一组 GPU 上交替——LN 段沿 seq 切、注意力/FFN 段沿 hidden 切。两段交界处需要转换数据布局。Megatron 的巧思是：把原来 TP 的 **all-reduce 拆成 reduce-scatter + all-gather**，通信总量**不变**，但顺带完成了布局转换，所以 SP **几乎不增加通信**，却省下大量冗余激活显存。

$$
\text{all-reduce} = \text{reduce-scatter} + \text{all-gather} \quad(\text{通信量相同})
$$

> 一句话：**序列并行用"零额外通信成本"把 LN/Dropout 段的激活也分摊到了多卡上。** 对长序列训练尤其重要。

## 6. 数据并行 + 通信全景：谁跑哪种原语

最外层是**数据并行 (DP)**：每个 TP×PP 组成的"模型副本"喂不同的数据，反向后把梯度 all-reduce 同步。Megatron 通常配合 **分布式优化器 (distributed optimizer / 类 ZeRO-1)**：把优化器状态沿 DP 维切开，用 reduce-scatter + all-gather 代替 all-reduce，省显存。

把四种并行的通信原语放一张表（原语细节见 [[ai-infra/网络/集合通信原语]]）：

```
   并行    通信原语              频率/位置          带宽要求  放哪
   ───────────────────────────────────────────────────────────────
   TP   all-reduce (或 RS+AG)  每层4次, 关键路径   极高     机内 NVLink
   SP   reduce-scatter+all-gather  TP段交界      极高     机内 NVLink
   PP   send/recv (P2P)         相邻级, 每微批     中       可跨机
   DP   all-reduce (或 RS+AG)   每步1次, 可重叠     中       最外层
```

```
   通信"热度"金字塔 (越上越频繁越重):
                  ┌──────────┐
                  │  TP/SP   │  机内, NVLink, 每层都跑
                  ├──────────┤
                  │    PP    │  相邻级 P2P
                  ├──────────┤
                  │    DP    │  每步一次, 可与反向重叠隐藏
                  └──────────┘
```

这就解释了开头的法则：**TP 在最内（机内），DP 在最外（跨机也能忍，且能 overlap）。**

## 7. Megatron-DeepSpeed：两个框架为什么要缝在一起

[[ai-framework/deepspeed/README|DeepSpeed]] 的看家本领是 **ZeRO**（把参数/梯度/优化器状态沿 DP 维切碎，甚至 offload 到 CPU/NVMe），擅长**省显存**和**易用的数据并行扩展**；Megatron 的看家本领是 **TP/PP/SP** 这套**高效模型并行 + 快 kernel**。两者**互补不冲突**：

```
   ┌────────────────── Megatron-DeepSpeed ──────────────────┐
   │                                                         │
   │  Megatron 负责:                DeepSpeed 负责:          │
   │  ┌─────────────┐               ┌─────────────────────┐ │
   │  │ 张量并行 TP │               │ ZeRO (1/2/3) 切状态 │ │
   │  │ 流水并行 PP │   ←── DP 维 ──►│ offload CPU/NVMe    │ │
   │  │ 序列并行 SP │               │ 训练引擎/ckpt/调度   │ │
   │  │ 融合 kernel │               │ 通信重叠优化         │ │
   │  └─────────────┘               └─────────────────────┘ │
   └─────────────────────────────────────────────────────────┘
   分工: Megatron 管"模型内部怎么切(TP/PP/SP)",
        DeepSpeed 管"数据并行那一维怎么省(ZeRO/offload)"。
```

典型组合：**3D 并行 = Megatron 的 TP×PP + DeepSpeed ZeRO 管的 DP**。BLOOM-176B、部分 GPT 类大模型就是用 Megatron-DeepSpeed 训的。

> 选择直觉：单纯想要"加机器就扩展、少改代码、省显存"→ DeepSpeed ZeRO 起步；模型大到必须做模型并行、要榨干 GPU 利用率 → 上 Megatron 的 TP/PP；两者都要 → Megatron-DeepSpeed。具体 API/配置以官方文档为准。

## 8. 大规模训练标准：工程红线

这些是"训大模型时大家默认都开"的东西，理解它们才算懂 Megatron 的工程价值：

- **混合精度 (bf16/fp16 + fp32 主权重)**：算得快、省一半显存；用 fp32 主权重和 loss scaling 防数值下溢。
- **激活重计算 (activation recomputation / checkpointing)**：前向时**不存**中间激活，反向时**重算**一遍。用约 1/3 的额外算力，换激活显存从 $O(L)$ 降到 $O(\sqrt{L})$ 甚至更省。长序列/深模型几乎必开。
- **融合 kernel (fused kernels)**：把 LayerNorm、softmax、bias+GeLU、dropout 等融成一个 CUDA kernel，减少显存读写往返，提速明显。
- **梯度累积**：用多个微批累加梯度模拟大 batch，配合流水并行的微批切分天然契合。
- **MFU (Model FLOPs Utilization)**：衡量"实际算力利用率"的核心指标——

$$
\text{MFU} = \frac{\text{模型理论所需 FLOPs/step}}{\text{硬件峰值 FLOPs} \times \text{step 时间}}
$$

大规模训练把 MFU 做到 **40%~55%** 就算很好了（Megatron 论文中千卡级别能稳定到这个区间）。剩下的损耗主要是通信、气泡、kernel 启动开销——前面所有切法和调度的目的，就是把 MFU 往上抬。

## 数值例子：175B 模型一层的显存与通信手算

设定一个具体场景，用 GPT-175B 的典型超参：

| 符号 | 含义 | 取值 |
|------|------|------|
| $h$ | 隐藏维 | 12288 |
| $L$ | 层数 | 96 |
| $b$ | 微批大小 | 1 |
| $s$ | 序列长度 | 2048 |
| TP | 张量并行度 | 8 |

**(1) 一层参数量**（注意力 $4h^2$ + FFN $8h^2$ = $12h^2$）：

$$
12 h^2 = 12 \times 12288^2 \approx 1.81 \times 10^9 \text{ 参数/层}
$$

TP=8 切开后，每卡每层只放 $1.81\times10^9 / 8 \approx 2.26\times10^8$ 参数。

**(2) 一层 TP 前向通信量**（FFN 末尾 1 次 all-reduce，传的是激活 $[b,s,h]$）：

$$
b \times s \times h \times 2\text{B} = 1 \times 2048 \times 12288 \times 2 \approx 50\,\text{MB}
$$

all-reduce 的实际传输量约为数据量的 $2(N-1)/N \approx 1.75$ 倍（N=8），即每次约 **88MB**。注意力块再来一次，**每层前向约 176MB 走 NVLink**——所以为什么 TP 必须 NVLink：96 层 × 前向反向，累计是 TB 级机内流量，PCIe 根本扛不住。

**(3) 一层激活显存（开重计算前 vs 后）**：

朴素存全部中间激活，单层激活峰值正比于 $s \cdot b \cdot h \cdot (\text{常数}\sim 34)$；全模型 96 层会达数百 GB。开**激活重计算**后只存每层边界，显存大降——这就是为什么千亿模型训练**激活重计算几乎是标配**。

> 结论：**TP 解决"参数装不下"，PP 解决"层太多装不下"，SP+重计算解决"激活装不下"，DP 解决"算得不够快"**——四件事一一对应，这就是 Megatron 全部设计的骨架。

## 对照表：与同类方案对比

| 维度 | Megatron-LM (TP/PP/SP) | DeepSpeed ZeRO | FSDP (PyTorch 原生) |
|------|----------------------|----------------|---------------------|
| 核心思路 | 切模型结构(矩阵/层/序列) | 沿 DP 维切状态 | 沿 DP 维切参数(类 ZeRO-3) |
| 最擅长 | 模型并行, 榨 GPU 利用率 | 省显存, 易扩展 DP | PyTorch 生态原生易用 |
| 通信特征 | TP 重(机内 NVLink) | all-gather 参数 | all-gather 参数 |
| 代码侵入 | 较高(需改模型结构) | 低(包一层) | 低(包一层) |
| 何时选 | 必须做 TP/PP 的超大模型 | 想简单省显存扩 DP | 想用原生方案、规模中等 |
| 组合 | 可与 DeepSpeed 缝 | 可与 Megatron 缝 | 可叠 TP(实验性) |

**一句话选型**：模型大到一台机器都放不下一份 → 一定要 Megatron 的 TP/PP；只是想省显存、加机器扩 DP → DeepSpeed/FSDP 起步；两者都要 → Megatron-DeepSpeed。

## 常见问题

| 问题 | 回答 |
|------|------|
| TP 和 PP 啥区别？ | TP 切**同一层内的矩阵**(机内, 通信重)；PP 切**不同层**(可跨机, P2P 通信轻)。 |
| 为什么 TP 不能跨机器？ | 每层 4 次 all-reduce 在关键路径上，必须 NVLink；跨机走网络会成瓶颈。 |
| TP size 一般设多少？ | 通常 ≤ 单机 GPU 数(如 8)，让 TP 通信全留在 NVLink 域内。 |
| 流水气泡怎么消？ | 多分微批(增大 $m$) + 1F1B 调度 + 交错式虚拟流水。气泡 $\approx (p-1)/m$。 |
| 序列并行额外通信多吗？ | 几乎为零。它把 all-reduce 拆成 reduce-scatter+all-gather，总量不变还顺带省激活。 |
| 激活重计算值得吗？ | 大模型基本必开：约 1/3 额外算力换大幅激活显存下降，常常是"能不能训"的分界。 |
| Megatron 和 DeepSpeed 二选一吗？ | 不是。它俩互补：Megatron 管模型并行(TP/PP/SP)，DeepSpeed 管 DP 维(ZeRO/offload)，常缝成一个。 |
| MFU 多少算好？ | 千卡规模 40%~55% 已属优秀，损耗主要来自通信/气泡/kernel 开销。 |
