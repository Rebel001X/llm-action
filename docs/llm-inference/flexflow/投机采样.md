## 0. 一句话锚点

> **投机采样是一种可以从根本上改善解码计算访存比的方法，保证和使用原始模型的采样分布完全相同。**

- 它使用两个模型：一个是**原始目标模型（大模型 Mp）**，另一个是**比原始模型小得多的近似模型（草稿模型 Mq）**。
- 近似模型用于进行**自回归串行采样**，而大型模型则用于**评估**采样结果。
- 直觉：解码中**某些 token 容易、某些 token 困难**。简单 token 交给小模型，困难 token 交给大模型。小模型可以是同结构少参数版，也可以干脆是 **n-gram 模型**。小模型不仅计算量小，**更重要的是减少了内存访问需求**。

参考：大模型推理妙招—投机采样（Speculative Decoding）: https://zhuanlan.zhihu.com/p/651359908

## 1. 地基：为什么自回归解码是"访存受限"的

先科普 LLM 解码时采用的**自回归采样（autoregressive sampling）**，其过程如下：

1. 模型使用前缀作为输入，将输出 logits 处理 + 归一化成概率分布后，采样生成下一个 token。
2. 将生成的 token 和前缀拼接成新的前缀，重复执行第 1 步，直到生成 EOS 或达到最大 token 数目。

第 1 步中，将 logits 转换成概率有几种常用采样方法：**argmax、top-k、top-p（原文写 top-n）** 等。

**核心痛点**：自回归生成的 token 一个一个地蹦出来，因为每次只对**序列长度为 1** 的部分做有效计算，但却需要访问**全部前缀对应位置的 activations（即 KV Cache）**，因此**计算访存比（arithmetic intensity）很低**。

```
自回归一步的"账本"：
  有效计算量  ≈ 1 个 token 过一遍权重           ← 很小
  内存搬运量  ≈ 读全部权重(W) + 读全部 KV Cache  ← 很大
  ----------------------------------------------
  计算访存比 = 计算 / 访存  →  极低  →  GPU 算力闲置、被显存带宽卡住
```

| 瓶颈类型 | 表现 | 谁来救 |
| --- | --- | --- |
| compute-bound（算力受限） | 大 batch 训练 | 上更强算力/并行 |
| **memory-bound（访存受限）** | **单条 decode** | **提高每次访存的"产出"** |

之前许多工程优化（改进计算核心、多卡并行、批处理）**并没有从根本上解决** decode 受制于访存带宽的问题——它们摊薄的是权重读取，**单序列每生成 1 个 token 仍要把权重+KV 全读一遍**。投机采样换了思路：**一次大模型前向，吐出多个被接受的 token**，等于把"读一遍权重"的成本摊到多个 token 上。

## 2. 投机采样流程（三步法）

**投机采样过程如下（原文保留）：**

1. 用小模型 **Mq** 做自回归采样，连续生成 **y 个 tokens**（草稿，draft）。
2. 把生成的 y 个 tokens 和前缀拼接一起，送进大模型 **Mp 执行一次 forward**。
3. 使用大、小模型 logits 结果做比对：
   - 如果发现某个 token 小模型生成得不好，**重新采样**这个 token，然后回到步骤 1。
   - 如果小模型生成结果都满意，则用大模型**采样下一个 token**，然后回到步骤 1。

> 第 2 步：将 y 个 tokens 和前缀拼成一起作为大模型输入。和自回归相比，**尽管计算量一样，但 y 个 tokens 可以同时参与计算**，计算访存比显著提升——因为大模型的权重只读了一遍，却"验证"了 y 个位置。

**ASCII 时序图（小模型草拟 4 个，大模型并行验证）：**

```
前缀: "我 爱"

[Mq 串行草拟 y=4]   北 → 京 → 的 → 天     (小模型 4 次便宜的前向)
                     │    │    │    │
                     ▼    ▼    ▼    ▼
拼成一条送进 Mp 一次前向（并行算 4 个位置的 p 分布）：
   位置:  [我 爱] [我爱北] [我爱北京] [我爱北京的]
   Mp 给出:  p(北)   p(京)    p(的)      p(天) ……还顺手算出"接受后下一个"的分布
                     │    │    │    │
       接受/拒绝准则 ✔    ✔    ✔    ✘(京 OK 但'的'被拒？示意)
                     └────┴────┘  接受 "北京" + 在被拒处重采 1 个
=> 一次 Mp 前向，最好情况吐出 (接受数 + 1) 个 token
```

关键不对称：**Mq 是串行的（便宜），Mp 是并行验证的（一次贵的前向顶 y+1 个 token 的产出）**。只要小模型猜得准，大模型的"贵前向"次数就被大幅压缩。

## 3. 接受-拒绝准则（核心机制）

第 3 步——**如何评价一个 token 生成得不好？**（原文公式保留）

记 $p(x)$、$q(x)$ 分别为**大模型、小模型**在某 token 上的采样概率（即 logits 归一化后的概率分布）。对小模型采出的 token $x$：

- **接受**概率为 $\min\!\left(1,\dfrac{p(x)}{q(x)}\right)$。
- 即：若 $q(x) > p(x)$，则以 $\,1-\dfrac{p(x)}{q(x)}\,$ 的概率**拒绝**这个 token；一旦拒绝，从一个新的概率分布
$$
p'(x) = \mathrm{norm}\big(\max(0,\; p(x) - q(x))\big)
$$
中**重新采样**一个 token（$\mathrm{norm}$ 表示归一化使其求和为 1）。

**一句话直觉**：

| 情形 | 含义 | 动作 |
| --- | --- | --- |
| $p(x) \ge q(x)$ | 大模型也认这个 token（甚至更看好） | **直接接受**（接受概率 = 1） |
| $p(x) < q(x)$ | 小模型过于自信、大模型没那么看好 | 以 $1-p/q$ 概率**拒绝**，从残差分布 $p'$ 重采 |

**数值手算示例**（词表只有 3 个词 A/B/C）：

```
小模型 q = [0.6, 0.3, 0.1]   (A, B, C)
大模型 p = [0.5, 0.2, 0.3]

小模型采到 A：接受概率 = min(1, p/q) = min(1, 0.5/0.6) = 0.833  → 多半接受
小模型采到 B：接受概率 = min(1, 0.2/0.3) = 0.667
小模型采到 C：接受概率 = min(1, 0.3/0.1) = 1.0   (p>q, 直接接受)

若某次被拒，残差分布:
  max(0, p-q) = [max(0,-0.1), max(0,-0.1), max(0,0.2)] = [0, 0, 0.2]
  归一化      = [0, 0, 1.0]   → 重采必出 C
  (拒绝多发生在 q 偏高的位置，故重采偏向 p 偏高的位置，刚好补回差额)
```

## 4. 为什么投机采样和自回归采样等价

这是投机采样"免费午餐"的根基：**最终产出的 token 分布严格等于直接用大模型 $p(x)$ 采样**，没有任何近似损失（与温度、top-p 等设置无关，只要验证用同一分布）。

原文的直觉解释（保留）：

- $p(x') > q(x')$ 说明大模型在 token $x'$ 上概率大于小模型，大模型对生成 $x'$ 更有把握，说明小模型生成的问题不大，**可以保留 $x'$**。
- 如果 $p(x') \le q(x')$ 则小模型更"自信"，大模型就以 $1-\dfrac{p(x')}{q(x')}$ 为概率**拒绝并重新采样**。因为接受的概率更偏向 $q$ 大的位置，所以重采的概率应更偏向 $p$ 大的位置，于是用 $\mathrm{norm}(\max(0,\,p(x)-q(x)))$。

**一行半的严格证明**（最终接受得到某个 token $x$ 的总概率 = $p(x)$）：

```
P(最终输出 = x)
  = P(草稿采到 x 且被接受)         +  P(发生一次拒绝后从残差分布重采到 x)

第一项 = q(x) · min(1, p(x)/q(x)) = min(q(x), p(x))

第二项 = P(拒绝) · p'(x)
   总拒绝概率 = Σ_z q(z)·(1 - min(1,p(z)/q(z))) = Σ_z (q(z)-min(q(z),p(z)))
             = Σ_z max(0, q(z)-p(z))
   p'(x) = max(0, p(x)-q(x)) / Σ_z max(0, p(z)-q(z))
   而 Σ_z max(0,p-q) = Σ_z max(0,q-p)  (因为 Σp=Σq=1)
   ⇒ 第二项 = max(0, p(x)-q(x))

合计 = min(p,q) + max(0, p-q) = p(x)   ✔  与大模型直接采样完全一致
```

这就是"保证和使用原始模型的采样分布完全相同"的来历——它本质是一种**重要性采样 / 拒绝采样**的精巧组合。

## 5. 加速效果

> 投机采样相比自回归采样之所以有加速效果，因为它**减少了对原始模型串行调用的次数**。这里规定一次迭代可以接收小模型的 tokens 数为 **#generated tokens**。

设草稿长度 $\gamma$（原文的 y），每个位置的**接受率**为 $\alpha$（接受是否独立的简化假设下），则**一次大模型前向期望产出的 token 数**为：

$$
\mathbb{E}[\#\text{tokens}] = \frac{1-\alpha^{\gamma+1}}{1-\alpha}
$$

（接受 0..γ 个草稿，再 +1 个由大模型/残差分布补出的 token）。

**数值示例**（手算几组，直观感受）：

| 接受率 $\alpha$ | 草稿 $\gamma$ | 期望产出 token/前向 | 理想提速（忽略 Mq 开销） |
| --- | --- | --- | --- |
| 0.5 | 4 | $\frac{1-0.5^5}{0.5}=1.94$ | ≈ 1.9× |
| 0.7 | 4 | $\frac{1-0.7^5}{0.3}=2.78$ | ≈ 2.8× |
| 0.8 | 5 | $\frac{1-0.8^6}{0.2}=3.69$ | ≈ 3.7× |
| 0.9 | 5 | $\frac{1-0.9^6}{0.1}=4.69$ | ≈ 4.7× |

```
提速关键：γ 不是越大越好
  α 高 → 大 γ 才划算（草稿大多被接受）
  α 低 → 大 γ 浪费（后面草稿基本被拒，Mq 白跑）
  实际还要减去：Mq 的 γ 次前向 + 一次 Mp 验证前向的额外开销
  ⇒ 真实提速 ≈ 1.5×~3× 常见，强相关于 (1) 草稿质量 α、(2) Mq/Mp 体量比
```

## 6. 工程实现：草稿模型怎么选 / 主流变体

| 方案 | 草稿来源 | 特点 |
| --- | --- | --- |
| 独立小模型 | 同系列小参数模型（如 7B 草拟 70B） | 经典，需**词表对齐** |
| n-gram / 检索 | 直接从上下文/语料里"抄" | 零额外模型，长文复读场景超有效 |
| **Medusa** | 在大模型上加多个轻量预测头 | 无需独立小模型，单模型自投机 |
| **EAGLE** | 在特征层（hidden state）自回归草拟 | 接受率高，目前 SOTA 级 |
| **Lookahead / 自投机** | 模型自己生成草稿 | 省去对齐麻烦 |

**与 KV Cache 的关系**：验证阶段大模型对草稿 token 做一次"类 prefill"的并行前向（见 [[llm-inference/PD分离]] 的 prefill 思想），被接受的 token 的 KV 直接留用，被拒绝位置之后的 KV 需丢弃回滚——这是实现里最容易写错的地方。

## 实操：原文真料（流程 + 公式原样汇总）

**自回归采样**：前缀 → 模型输出 logits → 归一化为概率 → 采样（argmax/top-k/top-p）→ 拼接 → 重复，直到 EOS 或达最大长度。瓶颈：每步只算长度 1，却访问全部前缀 activations，**计算访存比很低**。

**投机采样三步**：
1. 小模型 Mq 自回归连续生成 y 个 tokens。
2. y 个 tokens + 前缀 → 大模型 Mp 一次 forward（y 个 token 同时参与计算，计算访存比显著提升）。
3. 比对大小模型 logits：
   - 若 $q(x) > p(x)$，以 $1-\dfrac{p(x)}{q(x)}$ 概率拒绝，从 $p'(x)=\mathrm{norm}(\max(0,p(x)-q(x)))$ 重采；
   - 全部满意则用大模型采下一个 token；之后回到步骤 1。

**加速度量**：一次迭代接收的小模型 token 数记为 #generated tokens；减少了对原始模型的串行调用次数。

## 常见问题 / 坑

| 现象 / 坑 | 原因 | 应对 |
| --- | --- | --- |
| 加速不明显甚至变慢 | Mq 太大/接受率 $\alpha$ 太低，草稿全被拒 | 选更小更准的草稿，调小 γ |
| 输出分布"看起来变了" | 验证用了和草稿**不同的温度/采样设置** | 验证准则里 $p,q$ 必须是**同一目标分布**下的概率 |
| 词表不匹配报错/乱码 | 小模型与大模型 tokenizer/词表不同 | 选同词表草稿，或用 logits 映射对齐 |
| γ 设很大反而更慢 | 后段草稿期望接受率指数衰减，Mq 白跑 | 用上表 $\frac{1-\alpha^{\gamma+1}}{1-\alpha}$ 估最优 γ（常 3~5） |
| KV Cache 状态错乱 | 被拒位置之后的 KV 没回滚 | 验证后按"最长接受前缀"截断 KV |
| 误以为是"近似/有损" | 把它当成蒸馏 | 它**无损**：分布严格等于大模型直采（见第 4 节证明） |
| 贪心解码下还要重采吗 | greedy 时只需校验 token 是否一致 | 不一致即截断、用大模型该位 argmax，无需残差分布 |
