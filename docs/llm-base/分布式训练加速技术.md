## 0. 一句话锚点

大模型训不动，本质是撞了**三堵墙**：

```
        ┌──────────────────────────────────────────────┐
        │  显存墙：单卡 HBM 装不下 参数+梯度+优化器+激活    │ → ZeRO / TP / PP / 重计算 / Offload
        │  算力墙：单卡 FLOPs 太慢，一步要几秒            │ → DP 并发 / FP8 / FlashAttention
        │  通信墙：卡多了，同步梯度/激活的带宽成为瓶颈      │ → NVLink/IB / 计算通信重叠 / 减少同步
        └──────────────────────────────────────────────┘
```

所有加速技术都是在这三堵墙之间**权衡**：省显存常常多通信，省通信常常多显存。没有银弹，只有组合拳。

## 1. 地基：训练一步，显存和算力花在哪

一次训练迭代 = **前向 → 反向 → 优化器更新**。先把显存账算清楚，这是理解所有并行技术的前提。

```
 单卡显存 = 模型状态(Model States) + 激活(Activations) + 临时缓冲(Buffer/碎片)
            │                          │
   ┌────────┴─────────┐                └─ 前向中间结果，反向要用，随 batch×seq 线性增长
   参数 W   梯度 G   优化器状态 O
```

**模型状态（与 batch 无关，只与参数量 Ψ 有关）**，以 Adam + 混合精度为例：

| 部分 | 精度 | 字节/参数 | 说明 |
| --- | --- | --- | --- |
| FP16 参数副本 | FP16 | 2 | 前向/反向用 |
| FP16 梯度 | FP16 | 2 | 反向产出 |
| FP32 参数主副本 | FP32 | 4 | 优化器维护，防精度损失 |
| FP32 momentum (m) | FP32 | 4 | Adam 一阶矩 |
| FP32 variance (v) | FP32 | 4 | Adam 二阶矩 |
| **合计** | | **16 Ψ** | 经典 "16 倍参数量" 显存 |

> 记住这条黄金公式：**Adam 混合精度下，模型状态显存 ≈ $16\Psi$ 字节**（Ψ 为参数个数）。7B 模型 → $16 \times 7\times10^9 = 112\text{ GB}$，单张 80GB 卡根本放不下，这就是为什么必须分布式。

**激活显存（与 batch×seq 强相关）**，Transformer 单层近似：

$$M_{act}^{layer} \approx s \cdot b \cdot h \cdot (34 + 5\cdot\frac{a\cdot s}{h})\ \text{字节（FP16，含 attention 中间量）}$$

其中 $s$=序列长，$b$=micro-batch，$h$=hidden，$a$=注意力头数。详见 [[transformer内存估算]]。激活是**重计算/序列并行**主要攻击的对象。

**算力（FLOPs）**：训练一个 token 的浮点运算量 ≈ $6\Psi$（前向 2Ψ + 反向 4Ψ），详见 [[llm-algo/FLOPs]]。总 FLOPs = $6 \cdot \Psi \cdot D$（D 为训练 token 总数）。

## 2. 数据并行 DP / DDP：复制模型，切分数据

最朴素的并行：每张卡都存**一份完整模型**，喂不同的数据子批，反向后把梯度求平均同步，保证各卡模型一致。

```
   GPU0          GPU1          GPU2          GPU3
 ┌──────┐     ┌──────┐     ┌──────┐     ┌──────┐
 │ 全模型│     │ 全模型│     │ 全模型│     │ 全模型│   ← 每卡都有完整 W,G,O（冗余！）
 └──┬───┘     └──┬───┘     └──┬───┘     └──┬───┘
  data0        data1        data2        data3        ← 不同数据
    │            │            │            │
    └──── AllReduce(梯度求和/N) ───────────┘           ← 唯一通信点
              ↓
         各卡梯度一致 → 各自更新 → 模型仍一致
```

- **PyTorch DDP** 用 **Ring-AllReduce** 同步梯度，并把梯度分桶（bucket）与反向计算重叠（见 [[llm-optimizer/计算通信重叠]]）。
- **优点**：实现简单，扩展性好，几乎线性加速吞吐。
- **致命缺点**：每卡都存完整 $16\Psi$ 模型状态，**完全没省显存**。7B 模型 DP 仍要 112GB/卡 → 装不下。这正是 ZeRO 要解决的。

**DP 通信量**（每步、每卡）：Ring-AllReduce 收发各 $\frac{N-1}{N}\cdot 2\Psi$ 字节（梯度 FP16），与卡数 N 几乎无关——这是 Ring 算法的精髓，详见第 11 节与 [[ai-infra/网络/集合通信原语]]。

## 3. ZeRO：把"复制的冗余"切成片，再换到 CPU/NVMe

DP 的浪费在于**每卡重复存模型状态**。ZeRO（Zero Redundancy Optimizer，DeepSpeed 提出）把这三块按卡数 N 切片，每卡只存 $1/N$，用时再 AllGather 回来。详见 [[ai-framework/deepspeed/README]]。

```
 单卡模型状态显存（参数 Ψ，N 张卡）：
                            参数P     梯度G    优化器O
 baseline DP   每卡: 2Ψ  +  2Ψ   +  12Ψ        = 16Ψ
 ZeRO-1        每卡: 2Ψ  +  2Ψ   +  12Ψ/N       ← 只切优化器
 ZeRO-2        每卡: 2Ψ  +  2Ψ/N +  12Ψ/N       ← 再切梯度
 ZeRO-3        每卡: 2Ψ/N + 2Ψ/N +  12Ψ/N = 16Ψ/N ← 全切，近线性下降
```

```
ZeRO-3 前向某层时的"临时聚拢"：
  需要用到 layer-i 的参数
        │ AllGather: 从各卡拉回完整 W_i（多了通信）
        ▼
  ┌───────────────┐
  │ 临时完整 W_i   │ → 算完前向立刻丢弃 → 反向时再 AllGather 一次
  └───────────────┘
```

- **代价**：ZeRO-3 比 ZeRO-1/2 多了参数的 AllGather 通信（约 1.5 倍通信量），换来显存近线性下降。
- **ZeRO-Offload**：把优化器状态 + FP32 主参数卸到 **CPU 内存**，CPU 做 Adam 更新——用通信和 CPU 算力换 GPU 显存。
- **ZeRO-Infinity**：进一步卸到 **NVMe SSD**，理论上单机也能训万亿参数（但带宽受限，慢）。
- **关键区分**：ZeRO 本质仍是数据并行（不切单层算子），与张量并行正交，可叠加。

## 4. 张量并行 TP：切开单层矩阵，层内并行

当**单层都大到放不下/算不快**时，把一个矩阵乘法（GEMM）按行或列切到多卡，每卡算一部分，再通信拼起来。Megatron-LM 的经典做法。详见 [[llm-inference/大模型推理张量并行]]、[[ai-framework/megatron-lm/README]]、[[llm-algo/mlp]]。

**MLP 块**（两层：$Y=\text{GeLU}(XA)$，$Z=YB$）——A 按**列切**，B 按**行切**，使中间非线性无需通信：

```
   X (复制到每卡)
    │
    ├─ GPU0: X·A₁ → GeLU → Y₁ ─┐
    └─ GPU1: X·A₂ → GeLU → Y₂ ─┤   A=[A₁|A₂] 列切，GeLU 逐元素无需通信
                                │
       Y₁·B₁ + Y₂·B₂  ←─ AllReduce ─┘   B=[B₁;B₂] 行切，结果相加
            │
            Z (前向 1 次 AllReduce，反向 1 次，共 2 次/块)
```

**Attention 块**：天然按**注意力头**切分，每卡算若干个 head，输出投影行切后 AllReduce。详见 [[llm-algo/transformer/模型架构]]。

- **特点**：通信频繁（每层 2 次 AllReduce 前向 + 2 次反向），**必须放在 NVLink 高带宽域内**（同机 8 卡），跨机做 TP 会被通信拖死。
- **TP 通信量**（每层前向）：AllReduce 一个 $[b,s,h]$ 激活，约 $2\cdot\frac{N-1}{N}\cdot(b\cdot s\cdot h\cdot 2)$ 字节，**随 batch×seq 增长**——与 DP 同步梯度不同，TP 同步的是激活。

## 5. 流水线并行 PP：切层，micro-batch 填气泡

把模型**按层纵向切成若干 stage**，每张卡负责连续几层，像工厂流水线一样把数据一段段传下去。

```
朴素流水线（GPipe 之前的问题：气泡巨大）：
 GPU0 |F0|              |B0|
 GPU1 |  |F0|        |B0|  |
 GPU2 |  |  |F0|  |B0|  |  |        ← 大量空闲(bubble)！

GPipe：把 batch 拆成 micro-batch，填满流水线：
 GPU0 |F0|F1|F2|F3|         |B3|B2|B1|B0|
 GPU1 |  |F0|F1|F2|F3|   |B3|B2|B1|B0|  |
 GPU2 |  |  |F0|F1|F2|F3|B3|B2|B1|B0|  |  |   气泡缩小
```

- **气泡占比** ≈ $\frac{p-1}{m+p-1}$（p=stage 数，m=micro-batch 数）。**m 越大气泡越小**，所以 PP 要配大的梯度累积步数。
- **1F1B（PipeDream）**：交替前向反向，**降低激活显存峰值**（不必同时存所有 micro-batch 的激活），是 Megatron 默认调度。
- **Interleaved 1F1B**：一卡放多个不连续 stage，进一步压气泡，代价是更多 P2P 通信。
- **通信特点**：只在 stage 边界做 **P2P send/recv**（点对点，非集合通信），通信量小，**适合跨机**。

## 6. 序列并行 SP / 上下文并行 CP：切序列维

TP 切了 GEMM，但 **LayerNorm 和 Dropout** 这类沿 hidden 维归约的算子没被切，每卡仍要完整序列的激活。序列并行把它们沿**序列维 $s$** 切到各卡：

```
TP 域内，一个 Transformer 层：
  [SP] LayerNorm/Dropout  ── 沿 seq 切，激活 = s/N · b · h（省了！）
        │ AllGather(seq)
  [TP] Attention / MLP     ── 沿 hidden 切（标准张量并行）
        │ ReduceScatter(seq)
  [SP] Dropout/residual    ── 沿 seq 切
```

- **核心收益**：原文所述——*LayerNorm 和 Dropout 的计算与激活值被平摊到各设备，降低显存与计算浪费*。TP+SP 把激活显存从 $\propto s$ 降到 $\propto s/N$。
- **关键技巧**：用 **AllGather + ReduceScatter 替代单次 AllReduce**，两者通信量等于一次 AllReduce，**所以 SP 几乎不增加通信**，是"白嫖"的显存优化。
- **上下文并行 CP / Ring-Attention**：处理超长上下文（百万 token），把序列切片后用 Ring 方式在卡间传 KV 块做注意力，配合 [[llm-optimizer/FlashAttention]] 的分块思想。

## 7. MoE 专家并行 EP：稀疏激活，All-to-All 路由

MoE（混合专家）用 Gating 网络为每个 token 选 top-k 个专家，只激活一小部分参数——**参数量大但单 token 计算量小**。详见 [[llm-algo/moe/README]]。专家并行把不同专家放到不同卡：

```
  tokens (各卡本地一批)
       │  Gating 决定每个 token 去哪些专家
       ▼
  ┌─ All-to-All (dispatch) ─┐   把 token 发到专家所在卡
  GPU0:专家E0,E1   GPU1:专家E2,E3   ...
       │  各专家算 FFN
  └─ All-to-All (combine) ──┘   把结果发回 token 原来的卡
       ▼
  加权合并 top-k 专家输出
```

- **两次 All-to-All** 是 EP 的标志性通信，开销大且不规则，对网络拓扑敏感。
- **负载均衡**：Gating 可能把 token 都路由到少数热门专家 → 需 auxiliary load-balance loss + capacity factor（超出容量的 token 被丢弃/溢出）。
- EP 通常与 DP/TP 混合：专家维 EP，非专家层用 TP+DP。

## 8. 3D / 4D 混合并行：怎么把维度配起来

实际训练千亿模型，几种并行**叠加**使用，形成多维设备网格：

```
   设备网格示例：64 卡 = DP(2) × PP(4) × TP(8)
   ┌────────────────────────────────────────┐
   │ TP=8  : 同机 8 卡 NVLink 内，切单层      │ ← 带宽最敏感，放最快互联
   │ PP=4  : 跨机切层，stage 间 P2P           │ ← 通信少，可跨机
   │ DP=2  : 复制 + AllGather/Reduce 梯度     │ ← ZeRO 进一步省显存
   └────────────────────────────────────────┘
```

**配置黄金法则**（经验）：

1. **TP 优先填满单机 NVLink 域**（一般 TP ≤ 8，等于单机卡数），不跨机。
2. **PP 跨机切层**，micro-batch 数取大以压气泡。
3. **DP/ZeRO 在最外层**做数据并行扩展吞吐。
4. EP 单独管 MoE 层。
5. 通信量排序：TP（每层激活）> EP（All-to-All）> DP（每步梯度）> PP（边界 P2P），所以越频繁的并行放越快的互联。

## 9. 混合精度 + FP8：用低精度换速度与显存

```
 FP32 ████████████████████████████████  32 位，慢，主权重/优化器用
 BF16 ████████████████                  16 位，动态范围大(8位指数)，训练首选
 FP16 ████████████████                  16 位，精度高(10位尾数)但易溢出，需 loss scaling
 FP8  ████████                          8 位，H 系列起支持，GEMM 提速，需精细缩放
```

- **混合精度（BF16/FP16）**：前向/反向用 16 位算（快 2–4 倍，省一半激活显存），但保留 **FP32 主权重**做参数更新，避免小梯度被吞掉。FP16 还需 **loss scaling** 防梯度下溢；BF16 指数位与 FP32 相同，通常无需 scaling，更稳，是当前主流。
- **FP8**（详见 [[llm-compression/quantization/fp8]]）：H100 等起支持。NVIDIA **Transformer Engine** 主要用 FP8 做 **GEMM**，同时以 FP16/FP32 保持**主权重和梯度**的高精度。**MS-AMP** 框架用 FP8 训练，相比 BF16 内存降 27%–42%、权重梯度通信降 63%–65%、比 BF16 框架（如 Megatron-LM）快约 64%、比 TE 快约 17%。
- FP8 有 E4M3（精度优，前向）和 E5M2（范围优，反向梯度）两种格式，需 per-tensor/per-block 缩放因子动态校准。具体收益**以官方为准**。

## 10. 重计算 / 梯度累积 / Offload：三种"换"的艺术

**重计算（Recomputation / 梯度检查点 gradient checkpointing）——用算力换显存**：

```
 普通：前向存所有层激活 ──────────► 反向直接读      显存大，算力省
 重计算：前向只存"检查点"            反向时重算中间    显存小，多算一次前向(约多 1/3 算力)
 ┌──┐    ┌──┐    ┌──┐    ┌──┐
 │ck│····│  │····│ck│····│  │   仅 ck 处存激活，其余反向时重算
 └──┘    └──┘    └──┘    └──┘
```

激活显存从 $O(L)$ 降到 $O(\sqrt{L})$（L=层数，选 $\sqrt{L}$ 个检查点），代价是反向多一次前向（FLOPs 约从 $6\Psi$ 升到 $8\Psi$/token）。

**梯度累积——用迭代次数换大 batch**：

```
 micro-batch 1 → 反向 → 梯度累加  ┐
 micro-batch 2 → 反向 → 梯度累加  ├ 累加 k 次（不更新）
 ...                              │
 micro-batch k → 反向 → 梯度累加  ┘
                  ↓
            梯度/k → 优化器更新一次   ← 等效 batch = k × micro-batch
```

显存只需放下一个 micro-batch 的激活，却得到大 batch 的稳定梯度。累积梯度 = 多个 batch 梯度的平均值。**也是 PP 压气泡所必需**（k 即 micro-batch 数）。

**Offload——用通信换显存**：让参数/优化器/激活在 CPU 内存（甚至 NVMe）与 GPU 显存之间"左右横跳"。ZeRO-Offload / ZeRO-Infinity 是代表。带宽（PCIe ~ 数十 GB/s）远低于 HBM，故慢，适合"装不下宁可慢"的场景。

## 11. 通信原语与硬件：通信墙怎么破

并行的本质是**通信**，理解集合通信原语是关键，详见 [[ai-infra/网络/集合通信原语]]。

```
 AllReduce  = ReduceScatter + AllGather   （DP 同步梯度、TP 同步激活）
 ┌─ ReduceScatter：各卡得到结果的一部分(求和后切片)
 └─ AllGather   ：再把各片广播回所有卡
 All-to-All ：每卡给每卡发不同数据（MoE 路由）
 P2P send/recv：点对点（PP stage 边界）
```

**Ring-AllReduce 通信量**（N 卡，数据量 V 字节）：每卡总收发 $2\cdot\frac{N-1}{N}\cdot V$，**与 N 几乎无关**，这是 NCCL 高效扩展的根本。

**硬件层级**（带宽决定该把哪种并行放哪）：

```
 服务器内：NVLink(数百 GB/s~TB/s) ≫ PCIe(数十 GB/s)
 服务器间：NVLink(NVSwitch 全互联) > InfiniBand(数百 Gb/s) > TCP/IP(慢)
 芯片代际：H200 > H100 > A100   （HBM 带宽与 FP8 算力逐代提升）
```

→ **TP 放 NVLink 域内，PP/DP 可走 IB 跨机**。计算与通信重叠（[[llm-optimizer/计算通信重叠]]）是榨干带宽的核心手段。

## 数值手算

**例 1：7B 模型，Adam 混合精度，单卡放得下吗？**
模型状态 = $16 \times 7\times10^9 = 112$ GB。单张 80GB A100/H100 **放不下**。
- 上 8 卡 **ZeRO-3**：每卡模型状态 $= 112/8 = 14$ GB ✓ 富余出空间给激活。
- 或 8 卡 **TP**：每卡参数 $2\times7/8 = 1.75$ GB（FP16），但激活与通信另算。

**例 2：175B（GPT-3 级）模型状态显存。**
$16 \times 175\times10^9 = 2800$ GB $= 2.8$ TB。需 $2800/80 \approx 35$ 张 80GB 卡**仅存模型状态**，加激活/碎片，实际混合并行常用 数百~上千 卡。

**例 3：DP 每步梯度同步通信量（7B，FP16 梯度）。**
梯度 V $= 2 \times 7\times10^9 = 14$ GB。Ring-AllReduce 每卡收发 $\approx 2\times\frac{N-1}{N}\times 14 \approx 28$ GB（N 大时）。在 200 Gb/s（=25 GB/s）IB 上 $\approx 28/25 \approx 1.1$ s/步纯通信——**所以要计算通信重叠，否则通信墙吃掉一半时间**。

**例 4：重计算省多少激活？**
设某模型激活 60 GB（不重计算），层数 L=80。选 $\sqrt{80}\approx 9$ 个检查点，激活峰值约降到 $60\times\frac{9}{80}\approx 7$ GB（量级估算），代价是反向多约 1/3 前向算力（每 token FLOPs 从 $6\Psi$ → $8\Psi$）。

**例 5：训练总算力估算（[[llm-algo/FLOPs]]）。**
7B 模型训 1T token：$6\Psi D = 6\times 7\times10^9 \times 10^{12} = 4.2\times10^{22}$ FLOPs。
单 H100 BF16 峰值 $\approx 10^{15}$ FLOPs/s，按 40% MFU：$4.2\times10^{22}/(10^{15}\times0.4) \approx 1.05\times10^8$ s $\approx$ 1215 天单卡 → 需 ~256 卡并行才能 ~5 天，可见并行是刚需。

## 常见问题

| 问题 | 解答 |
| --- | --- |
| DP 和 ZeRO 什么关系？ | ZeRO 是不浪费显存的 DP；切片模型状态，逻辑上仍是数据并行 |
| TP 为什么不能跨机？ | 每层多次 AllReduce 激活，跨机带宽低会成瓶颈，几乎只放 NVLink 域 |
| PP 的气泡怎么消？ | 增大 micro-batch 数 m，用 1F1B/Interleaved 调度，气泡 ≈ (p-1)/(m+p-1) |
| 序列并行额外多少通信？ | 几乎不增加：AllGather+ReduceScatter 通信量 = 一次 AllReduce |
| BF16 vs FP16 选哪个？ | 大模型选 BF16（动态范围大、无需 loss scaling、更稳） |
| 重计算总值得吗？ | 长序列/大模型值得（显存是硬约束），多约 1/3 算力换 √L 显存 |
| 梯度累积为何配 PP？ | 累积步数 = micro-batch 数，直接决定 PP 气泡大小 |
| MoE 为啥慢？ | 两次 All-to-All 不规则通信 + 负载不均，对网络拓扑敏感 |
| 这些技术能叠加吗？ | 能。典型 DP(ZeRO)×TP×PP(×EP) 多维混合并行 |
| FP8 真能快这么多吗？ | GEMM 提速明显，整体收益依框架/模型而定，**以官方为准** |
