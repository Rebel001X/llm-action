## 0. 一句话锚点

浮点数 = $(-1)^{\text{sign}} \times 1.\text{尾数} \times 2^{\text{指数}}$。

- **指数位**决定能表示多大/多小的数（**动态范围**）。
- **尾数位**决定每个数附近有多细的刻度（**相对精度**）。

16 位预算下只能二选一侧重：

```
            指数位(范围)   尾数位(精度)
 FP32(32b)      8           23      ← 基准：范围大、精度高
 FP16(16b)      5           10      ← 砍范围 → 容易溢出/下溢
 BF16(16b)      8           7       ← 保范围(同FP32)，砍精度
```

**记忆口诀**：FP16 "精度够、范围窄、要靠 Loss Scaling 救"；BF16 "范围同 FP32、精度粗、训练更省心"。

## 1. 地基：一个浮点数是怎么由比特拼出来的

IEEE-754 把浮点数切成三段：符号 S、指数 E、尾数 M（也叫 mantissa / fraction / significand）。

```
 ┌─┬───────────┬────────────────────────┐
 │S│  Exponent │       Fraction (M)     │   一个浮点数
 └─┴───────────┴────────────────────────┘
  1     Ew bits          Mw bits
```

实际数值（规格化数 normalized）：

$$x = (-1)^{S}\times \big(1 + \tfrac{M}{2^{Mw}}\big)\times 2^{(E - \text{bias})}$$

其中：
- **bias（偏置）** $= 2^{Ew-1}-1$，让指数能表示正负幂（存的是无符号 E，减去 bias 才是真指数）。
- 尾数前面那个**隐含的 1.**（hidden bit）：规格化数尾数总是 $1.xxxx$，省一位存储。
- $E=0$（全 0）是**非规格化数 subnormal**，隐含位变 0，专门用来表示比最小规格化数还小的数（gradual underflow，渐进下溢）。
- $E$ 全 1 表示 $\pm\infty$（M=0）或 NaN（M≠0）。

**两件最重要的事，全由比特数决定：**

1. **范围**由指数位 $Ew$ 决定 → 最大可表示数 $\approx 2^{2^{Ew-1}}$。
2. **相对精度**由尾数位 $Mw$ 决定 → 相邻两个浮点数的相对间隔（机器精度）$\approx 2^{-Mw}$。

```
 数轴上浮点的刻度（非均匀！指数越大刻度越粗）
 0   0.5   1        2              4                  8
 |‖‖‖|‖‖‖|‖‖‖‖|‖‖‖‖‖‖‖‖|‖‖‖‖‖‖‖‖‖‖‖‖‖‖‖‖|
   密     ←—— 每跨一个2的幂，刻度宽度翻倍 ——→  疏
```

> 关键直觉：浮点不是均匀网格。**同样的尾数位数，在大数附近刻度大、在小数附近刻度细**。这正是梯度（很小）容易"掉进缝里"被舍掉的原因。

## 2. FP32 / FP16 / BF16 逐比特对比

```
 FP32 (单精度, 32 bit, bias=127)
 ┌─┬────────┬───────────────────────┐
 │S│ 8 exp  │     23 fraction       │
 └─┴────────┴───────────────────────┘
   范围 ~±3.4e38   最小正规格化 ~1.18e-38   相对精度 2^-23≈1.2e-7

 FP16 (半精度, 16 bit, bias=15)        IEEE binary16
 ┌─┬─────┬──────────┐
 │S│5 exp│10 fraction│
 └─┴─────┴──────────┘
   范围 ~±65504      最小正规格化 ~6.1e-5    相对精度 2^-10≈9.8e-4

 BF16 (bfloat16, 16 bit, bias=127)    Google Brain Float
 ┌─┬────────┬───────┐
 │S│ 8 exp  │7 frac │
 └─┴────────┴───────┘
   范围 ~±3.4e38     最小正规格化 ~1.18e-38   相对精度 2^-7≈7.8e-3
```

**一张表看穿三者：**

| 格式 | 总位 | 指数位 | 尾数位 | bias | 最大正数 | 最小正规格化数 | 机器精度 $2^{-Mw}$ |
|------|------|--------|--------|------|----------|----------------|---------------------|
| FP32 | 32 | 8 | 23 | 127 | ≈3.40e38 | ≈1.18e-38 | ≈1.19e-7 |
| FP16 | 16 | 5 | 10 | 15 | ≈65504 | ≈6.10e-5 | ≈9.77e-4 |
| BF16 | 16 | 8 | 7 | 127 | ≈3.40e38 | ≈1.18e-38 | ≈7.81e-3 |

**核心洞察（务必记住）：**

- BF16 把 FP32 的 8 位指数**原封不动**搬过来 → **范围和 FP32 几乎一样**（不会溢出/下溢）。代价是尾数只剩 7 位 → 精度比 FP16 还粗。
- FP16 只有 5 位指数 → **范围窄到 ±65504、下界 6.1e-5**，深度学习里的小梯度极易下溢。但 10 位尾数 → 精度比 BF16 细约 8 倍。
- **FP32 → BF16 转换=直接砍掉尾数低 16 位**（高 16 位即 BF16）。指数对齐，转换极简，这也是 BF16 工程友好的原因之一。

```
 FP32  : S | EEEEEEEE | MMMMMMM MMMMMMMM MMMMMMM   (1+8+23)
                        └────── 砍掉低 16 位 ──────┘
 BF16  : S | EEEEEEEE | MMMMMMM                     (1+8+7)
          └── 高 16 位 ──┘   直接截断即可！
```

## 3. FP16 的两大坑：溢出 与 舍入误差

深度学习里 FP16 的麻烦几乎都来自它**范围太窄**。

### 3.1 数值上溢 / 下溢

- **上溢 Overflow**：量级很大的数（如某些激活、Attention logits、loss）超过 65504 → 变成 $\pm\infty$ → 再运算变 NaN，训练直接崩。
- **下溢 Underflow**：接近 0 的数小于最小可表示量 → 被舍成 0。**梯度（一阶导）通常比权重小一两个数量级**，最容易下溢。一旦梯度变 0，对应参数就停止更新。

```
 FP16 可表示区间（对数轴）
  下溢区        正常区              上溢区
 ┄┄0┄┄┊■■■■■■■■■■■■■■■■■■■■■■┊┄∞┄
      6.1e-5                 65504
        ↑                      ↑
   小梯度掉这里→0        大激活/loss冲这里→inf
```

### 3.2 舍入误差 Rounding Error

即使一个数落在 FP16 范围内，也可能小于"当前刻度宽度"而被舍掉。

> 原文例：0.00006666666 在 FP32 能正常表示，转 FP16 后约表示成 0.000067（被强制对齐到 FP16 在该量级的最近刻度）。

更要命的是"**大数吃小数**"：当 $a \gg b$，$a+b$ 在 FP16 里可能等于 $a$，因为 $b$ 比 $a$ 的刻度还小。这在**梯度累加 / 优化器状态更新**（权重大、更新量小）中频繁发生 → 累加越多丢得越多。

```
 大数吃小数 (FP16, 假设刻度在 a 附近 = 0.5)
   a = 1024.0
   b =    0.03   ← 远小于 a 附近的刻度 0.5
   a + b  = 1024.0   (b 整个被吃掉！)
```

这正是混合精度里**主权重必须用 FP32 维护**、**累加必须 FP32** 的根本原因（见第 5 节）。

## 4. BF16 如何对症下药

FP16 的病根是"范围窄"。BF16 把指数位补回 8 位 → **范围 = FP32**，于是：

- 上溢/下溢**基本消失**（梯度、激活极少越界）。
- 很多场景**不再需要 Loss Scaling**（FP16 几乎必须配；BF16 常可省略或只用很小的缩放）。

代价：尾数只有 7 位，**精度更粗**。但深度学习对"单步数值的相对精度"其实不敏感（SGD 本身带噪声），对"范围/不溢出"却极敏感——所以 BF16 在大模型训练里反而**更稳更省心**。

```
 同一个梯度 g = 1.5e-5
   FP16 : 6.1e-5 是下界 → g < 下界 → 下溢成 0   ✗ 参数不更新
   BF16 : 下界 1.18e-38 → g 正常表示(精度略粗) ✓ 仍能更新
```

| 维度 | FP16 | BF16 |
|------|------|------|
| 动态范围 | 窄 (易溢出/下溢) | 宽 (=FP32) |
| 单值精度 | 较高 (10 尾数) | 较低 (7 尾数) |
| Loss Scaling | 几乎必须 | 常可省略 |
| 工程稳定性 | 需调缩放因子 | 开箱即稳 |
| 典型场景 | 早期混合精度/部分推理 | 大模型预训练主流 |

> 经验法则：**训练大模型优先 BF16**（需硬件支持，如 Ampere/Hopper、TPU、部分国产 NPU，具体以官方为准）；显存敏感且范围可控的推理可用 FP16。

## 5. 混合精度训练（AMP）全链路——为什么不能纯 16 位

直接用 16 位存所有东西会因为第 3 节的舍入/溢出而训不动。工程上采用 **混合精度 Mixed Precision**：算得快的地方用 16 位，怕丢精度的地方用 FP32。三大支柱：

### 5.1 FP32 主权重（Master Weights）

优化器维护一份 **FP32 的权重副本**。前向/反向时临时转 16 位算（快），但更新 $w \leftarrow w - \eta g$ 在 FP32 上做，避免"大权重吃小更新"。

### 5.2 Loss Scaling（仅 FP16 强需要）

反向前把 loss 乘一个大因子 $S$（如 $2^{15}$），梯度同比放大 → 把会下溢的小梯度"抬"进 FP16 可表示区；更新前再除回 $S$。

```
 forward(FP16) ─► loss ─×S─► backward ─► grad(FP16, 已放大不再下溢)
                                              │ ÷S
                                              ▼
                              更新到 FP32 主权重(精确)
   动态 Loss Scaling：遇到 inf/NaN → S 减半且跳过本步；连续N步无溢出 → S 翻倍
```

### 5.3 关键算子 FP32 累加 / 计算

- **梯度累加、BatchNorm/LayerNorm 统计量、Softmax、求和归约**等用 FP32，避免"大数吃小数"。
- Tensor Core 做 16×16 矩阵乘时**内部用 FP32 累加**（见第 7 节），输出再转回 16 位。

```
 一步混合精度训练数据流
 ┌────────────┐  cast↓  ┌──────────┐
 │FP32 主权重 │ ──────► │FP16/BF16 │ ──► 前向(16b, Tensor Core, FP32累加)
 └────────────┘         │ 权重副本 │           │
       ▲                └──────────┘           ▼ loss(FP32)
       │ 优化器更新(FP32)            ×S(仅FP16) │
       │                                        ▼
       └──────── grad(FP32) ◄─ ÷S ◄─ 反向(16b grad) ◄┘
```

> BF16 因范围足够，**5.2 常可省略**；5.1、5.3 仍建议保留以保收敛质量。详见 [[llm-base/distribution-training/自动混合精度]]。

## 6. 收益从哪来：显存 / 带宽 / 算力（手算见下节）

16 位相对 32 位：

- **激活/权重/梯度显存减半**（每个数 4 字节 → 2 字节）。
- **访存带宽翻倍**（同样字节搬一半数量、或同时间搬两倍数据）——很多训练/推理是**带宽瓶颈**，这是主要提速来源。
- **算力翻倍以上**：GPU 的 Tensor Core 对 FP16/BF16 吞吐通常是 FP32 的数倍（具体倍数以硬件官方手册为准）。

```
 同一块卡，同一个张量 [1024,1024]
 FP32: 1024*1024*4 = 4 MiB   一次搬完需 X 时间
 FP16: 1024*1024*2 = 2 MiB   带宽不变 → 约 X/2 时间，理论2倍吞吐
```

与 FLOPs/显存的系统估算联动见 [[llm-algo/FLOPs]] 与 [[transformer内存估算]]。

## 数值手算 / 示例

### 例 1：手工把 0.1 转成各格式，看精度差异

十进制 0.1 在二进制是无限循环 $0.0001100110011\ldots_2 = 1.100110011\ldots_2 \times 2^{-4}$。

- **FP16**（尾数 10 位）：保留 10 位尾数后舍入，误差量级 $\approx 0.1\times 2^{-11}\approx 4.9\times10^{-5}$。
- **BF16**（尾数 7 位）：误差量级 $\approx 0.1\times 2^{-8}\approx 3.9\times10^{-4}$，约为 FP16 的 8 倍。
- **FP32**（尾数 23 位）：误差 $\approx 0.1\times 2^{-24}\approx 6\times10^{-9}$。

结论：BF16 表示同一个数比 FP16 粗约 8 倍（尾数差 3 位，$2^3=8$）。

### 例 2：FP16 下溢——一个真实小梯度

设梯度 $g = 1.5\times10^{-5}$。FP16 最小**规格化**正数 $\approx 6.1\times10^{-5}$。

$$g = 1.5\times10^{-5} < 6.1\times10^{-5} \Rightarrow \text{进入非规格化区，精度骤降甚至舍成 }0$$

加 Loss Scaling $S=2^{15}=32768$：

$$g\times S = 1.5\times10^{-5}\times 32768 \approx 0.49$$

0.49 远在 FP16 正常区 → 不再下溢；更新前 $\div S$ 还原。**BF16 则因下界 1.18e-38，根本不触发下溢**，故常可免 Loss Scaling。

### 例 3：大数吃小数（为什么主权重要 FP32）

权重 $w=2.0$，单步更新 $\Delta=3.0\times10^{-4}$。FP16 在 2.0 附近的刻度约为 $2^{1}\times2^{-10}=2^{-9}\approx 1.95\times10^{-3}$。

$$\Delta = 3.0\times10^{-4} < \tfrac{1}{2}\times1.95\times10^{-3}\approx 9.8\times10^{-4}$$

更新量小于半个刻度 → **FP16 里 $w+\Delta$ 仍等于 2.0**，参数永远不动。改在 FP32 主权重上更新（刻度 $\approx 2.4\times10^{-7}$）则正常生效。

### 例 4：7B 模型混合精度显存估算（粗算）

参数量 $P = 7\times10^9$。Adam 优化器经典显存账（单卡、未切分）：

| 项 | 精度 | 字节/参数 | 显存 |
|----|------|-----------|------|
| 权重 16 位副本 | BF16/FP16 | 2 | 14 GB |
| 梯度 16 位 | BF16/FP16 | 2 | 14 GB |
| FP32 主权重 | FP32 | 4 | 28 GB |
| Adam 一阶动量 $m$ | FP32 | 4 | 28 GB |
| Adam 二阶动量 $v$ | FP32 | 4 | 28 GB |

合计 $\approx (2+2+4+4+4)\times P = 16\times 7\times10^9 \approx 112$ GB（**不含激活**）。

对比：纯 FP32 训练光权重+梯度+主权重+m+v $= (4+4+4+4+4)P=20P\approx140$ GB。混合精度把"权重+梯度"那部分从 8 字节降到 4 字节/参数，省下 $\approx 28$ GB。其余优化器状态省显存要靠 ZeRO 切分，见 [[ai-framework/deepspeed/README]]。

> 注：这是经典"16 字节/参数"口径；不同实现（如优化器状态也半精度、是否含 16 位主梯度）会有出入，以框架实际为准。

## 7. 硬件与累加精度（一句到位的底层）

- **Tensor Core**：Volta 起的矩阵乘加单元，吃 FP16/BF16 输入，**累加用 FP32**——所以单次 GEMM 的累加误差受控，输出再降回 16 位。
- **BF16 硬件**：Ampere(A100)/Hopper(H100)、TPU、部分国产加速卡原生支持（具体型号/吞吐以官方为准）。早期 Pascal/Volta 仅 FP16 无原生 BF16。
- **为什么 BF16 在新硬件成主流**：范围安全 + 转换简单（截断 FP32 高 16 位）+ 累加 FP32 兜底，训练几乎无需调 Loss Scaling。

```
 Tensor Core GEMM 内部精度
   A(16b) ──┐
            ├─► 乘 ──► FP32 累加器 ─► 输出(可转回16b)
   B(16b) ──┘            ↑
                    误差在这里被 FP32 吸收
```

更细的 GPU 计算/访存机制见 [[ai-infra/算力/GPU工作原理]] 与 [[ai-infra/ai-hardware/CUDA]]。

## 常见问题

| 问题 | 答 |
|------|----|
| FP16 和 BF16 都 16 位，差别核心？ | 指数/尾数位分配不同：FP16 是 5/10（范围窄精度高），BF16 是 8/7（范围=FP32 精度低）。 |
| 训练大模型选哪个？ | 优先 BF16（硬件支持下）：范围安全、常免 Loss Scaling、更稳。 |
| BF16 还需要 Loss Scaling 吗？ | 通常不需要或只需很小缩放，因为范围已和 FP32 一致。FP16 几乎必须。 |
| 为什么主权重要 FP32？ | 防"大数吃小数"——小更新量在 16 位里会被权重的粗刻度吃掉，参数不更新。 |
| FP16 上溢/下溢分别发生在哪？ | 上溢：大激活/logits/loss > 65504 → inf。下溢：小梯度 < 6.1e-5 → 0。 |
| 16 位为什么能加速？ | 显存减半、带宽翻倍（多为带宽瓶颈）、Tensor Core 吞吐数倍。 |
| FP32→BF16 怎么转？ | 直接截断 FP32 低 16 位（高 16 位即 BF16），指数对齐，无需缩放。 |
| 比 FP16 更激进有吗？ | 有 FP8（E4M3/E5M2），需更细的 per-tensor/per-block 缩放，见量化笔记。 |
| 累加为什么不会爆精度？ | Tensor Core 内部用 FP32 累加器，关键归约/统计也走 FP32。 |
| Apex 还需要吗？ | PyTorch 1.6+ 内置 `torch.cuda.amp`，一般无需第三方 Apex，见自动混合精度笔记。 |
