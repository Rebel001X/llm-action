## 0. 一句话锚点

> **模型的大小由其参数量及其精度决定，精度通常为 float32、float16 或 bfloat16 之一。**

一个数值格式 = 用多少个二进制位、怎么分配这些位。分配方式决定了三件事：

```
            ┌───────── 占多少显存 ── 总位数 / 8 = 字节数
数值格式 ───┼───────── 能表示多大/多小 ── "指数位"的数量
            └───────── 表示得多精确 ── "尾数位"的数量
```

记住一句口诀：**指数管范围（动态范围），尾数管精度（有效数字）。** 后面所有格式的取舍，都是在"范围"和"精度"之间用有限的位数做权衡。

## 1. 地基：IEEE 754 浮点数的三段结构

任何浮点格式都把位分成三段：**符号位 (Sign) + 指数位 (Exponent) + 尾数位 (Mantissa/Fraction)**。

```
 ┌─┬───────────┬─────────────────────────┐
 │S│  Exponent │        Mantissa         │
 └─┴───────────┴─────────────────────────┘
  1     E 位              M 位
```

数值还原公式（规格化数，简化版）：

$$值 = (-1)^{S} \times (1 + 尾数) \times 2^{(指数 - 偏置)}$$

- **符号位 S**：0 正 1 负。
- **指数位**：决定能跳多大、多小（$2^{指数}$ 的范围）。指数位越多 → 动态范围越大。
- **尾数位**：决定两个相邻可表示数之间有多密（有效数字位数）。尾数位越多 → 越精确。

**关键直觉**：总位数固定时，多给指数就得从尾数里抠位，反之亦然。BF16 和 FP16 都是 16 位，区别就是这 15 个非符号位怎么切（5+10 还是 8+7）。

整型（INT8）则没有指数尾数之分，就是普通二进制补码整数，均匀地铺满一个固定区间。

## 2. FP32（全精度，4 字节）

> Float32 (FP32) 是标准的 IEEE 32 位浮点表示。使用该数据类型，可以表示大范围的浮点数。在 FP32 中，为"指数"保留了 8 位，为"尾数"保留了 23 位，为符号保留了 1 位。因为是标准数据类型，所以大部分硬件都支持 FP32 运算指令。

```
FP32:  S │ EEEEEEEE │ MMMMMMMMMMMMMMMMMMMMMMM
       1 │    8     │           23
       └─────────── 32 位 = 4 字节 ───────────┘
```

- 动态范围约 $1.4\times10^{-45} \sim 3.4\times10^{38}$。
- 在机器学习术语中，**FP32 称为全精度（4 字节）**，是数值正确性的"金标准"。
- 所有 GPU/CPU 都有原生 FP32 指令，但算得最慢、最占显存。

---

## 3. FP16（半精度，2 字节，范围小）

> 而在 Float16 (FP16) 数据类型中，指数保留 5 位，尾数保留 10 位。这使得 FP16 数字的数值范围远低于 FP32。因此 FP16 存在上溢（当用于表示非常大的数时）和下溢（当用于表示非常小的数时）的风险。

```
FP16:  S │ EEEEE │ MMMMMMMMMM
       1 │   5   │     10
       └──── 16 位 = 2 字节 ────┘
```

只有 5 位指数 → 动态范围被压缩到约 $6\times10^{-8} \sim 65504$（即约 64k）。

**经典溢出例子（原文真料）**：

> 例如，当你执行 10k * 10k 时，最终结果应为 100M，FP16 无法表示该数，因为 FP16 能表示的最大数是 64k。因此你最终会得到 NaN（Not a Number，不是数字）。在神经网络的计算中，因为计算是按层和 batch 顺序进行的，因此一旦出现 NaN，之前的所有计算就全毁了。

NaN 传染机制图：

```
  层1 ──→ 层2 ──→ [溢出→NaN] ──→ 层4 ──→ 层5
                       │
                       └─ NaN × 任何数 = NaN，向后污染整条链路
```

> 一般情况下，我们可以通过缩放损失（loss scaling）来缓解这个问题，但该方法并非总能奏效。

**loss scaling 的本质**：FP16 下溢区（极小梯度被舍入成 0）才是训练真正的痛点。把 loss 乘一个大常数 $S$（如 1024），反传时梯度同步放大 $S$ 倍，原本会下溢成 0 的小梯度被"抬"进 FP16 可表示区间；更新权重前再除回 $S$。

---

## 4. BF16（半精度，2 字节，范围大）

> 于是我们发明了一种新格式 Bfloat16 (BF16) 来规避这些限制。BF16 为指数保留了 8 位（与 FP32 相同），为小数保留了 7 位。这意味着使用 BF16 我们可以保留与 FP32 相同的动态范围。但是相对于 FP16，我们损失了 3 位精度。因此，在使用 BF16 精度时，大数值绝对没有问题，但是精度会比 FP16 差。

```
BF16:  S │ EEEEEEEE │ MMMMMMM
       1 │    8     │    7
       └──── 16 位 = 2 字节 ────┘
       注意：指数 8 位与 FP32 完全一致，相当于"砍掉 FP32 的低 16 位尾数"
```

**FP16 vs BF16 一图看懂取舍**（同样 16 位，分法不同）：

```
范围 ←─────────────────────────→ 大          精度 ←──────────→ 高
FP16  指数5  ▓▓                  小范围        尾数10 ▓▓▓▓▓▓▓  高精度
BF16  指数8  ▓▓▓▓▓               大范围        尾数 7 ▓▓▓▓     低精度
```

- BF16 动态范围 ≈ FP32（$\sim 3.4\times10^{38}$），所以大模型训练里"几乎不溢出"。
- 代价：尾数只有 7 位，相邻数之间间隙大，**不需要 loss scaling**（范围够大），但单点精度不如 FP16。
- 因此当代大模型训练（LLaMA、GPT 系）几乎都首选 BF16。

---

## 5. TF32（Ampere 计算格式，19 位）

> 在 Ampere 架构中，NVIDIA 还引入了 TensorFloat-32(TF32) 精度格式，它使用 19 位表示，结合了 BF16 的范围和 FP16 的精度。目前，它仅在某些操作的内部使用 [即 TF32 是一个计算数据类型而不是存储数据类型]。

```
TF32:  S │ EEEEEEEE │ MMMMMMMMMM        ← 取 BF16 的指数(8) + FP16 的尾数(10)
       1 │    8     │     10
       └──── 19 位（存储仍按 FP32 占 4 字节）────┘
```

**关键区分（原文强调）**：TF32 是**计算数据类型，不是存储数据类型**。

```
   FP32 输入 ──[Tensor Core 内部截成 TF32 做乘加]──→ FP32 累加输出
                        ↑
            范围用 BF16 的 8 位指数，精度用 FP16 的 10 位尾数
```

也就是说权重在显存里仍按 FP32 存（4 字节），只是 Tensor Core 在做矩阵乘时把输入临时截断到 TF32 来加速——省时间不省显存。

## 6. INT8 与 FP8（8 位）

### INT8（整型量化）

> 除此以外，还有 Int8 (INT8) 数据类型，它是一个 8 位的整型数据表示，可以存储 $2^8$ 个不同的值（对于有符号整数，区间为 [-128, 127]，而对于无符号整数，区间为 [0, 255]）。

INT8 没有指数尾数，是**均匀间隔**的整数刻度。要表示浮点权重，需要"量化"——找一个缩放因子 $s$ 把浮点映射到整数：

$$q = \text{round}(x / s), \qquad \hat{x} = q \times s$$

```
浮点权重分布 (FP32):   ─────●──●─●────●──●────────→
INT8 刻度 (256 个桶):  |--|--|--|--|--|--|--|--|--   ← 均匀切 256 份
                       -128            0          127
```

数值示例：设一层权重最大绝对值为 $|x|_{max}=2.0$，对称量化 $s = 2.0/127 \approx 0.0157$。权重 $0.5$ 量化为 $q=\text{round}(0.5/0.0157)=32$，反量化回 $\hat{x}=32\times0.0157=0.502$，误差 0.002。

### FP8（两种排布：E4M3 / E5M2）

FP8 是 8 位浮点，在 Hopper（H100）等架构上原生支持，常见两种切法：

```
E4M3:  S │ EEEE │ MMM      精度优先（尾数3位），多用于前向/权重激活
       1 │  4   │  3

E5M2:  S │ EEEEE │ MM       范围优先（指数5位），多用于反向梯度
       1 │   5   │  2
```

直觉：同 8 位，E4M3 像"小 FP16"重精度，E5M2 像"小 BF16/更小"重范围。详见 [[llm-compression/quantization/fp8]]。

## 7. FP4 与 NF4（4 位，极致压缩）

4 位只有 16 个可表示值，是 QLoRA 等方法把大模型压进消费级显卡的核心。

- **FP4**：4 位浮点（如 1 符号 + 2 指数 + 1 尾数），16 个非均匀刻度，指数让它在 0 附近密、远端疏。
- **NF4（NormalFloat4）**：针对神经网络权重近似服从**正态分布**这一事实设计——把 16 个刻度按标准正态分布的分位点放置，使每个桶里落入的权重数量大致相等（信息论上的最优分桶）。

```
权重直方图 (近似正态):        ▁▂▄██▄▂▁
均匀 4-bit (FP4 等距):       | | | | | | | |   ← 两端桶几乎空，浪费
NF4 (按分位点放刻度):        ||| | |  |  | |||  ← 中间密两端疏，桶利用率高
```

NF4 不存权重本身，而是存"权重落在哪个桶（4 位索引）"+ 一张共享的刻度表，反量化时查表还原。

## 8. 混合精度训练：为什么训练要混着用

> 在机器学习术语中，FP32 称为全精度（4 字节），而 BF16 和 FP16 称为半精度（2 字节）。
>
> 虽然理想情况下训练和推理都应该在 FP32 中完成，但 FP32 比 FP16/BF16 慢两倍，因此实践中常常使用混合精度方法，其中，使用 FP32 权重作为精确的"主权重（master weight）"，而使用 FP16/BF16 权重进行前向和后向传播计算以提高训练速度，最后在梯度更新阶段再使用 FP16/BF16 梯度更新 FP32 主权重。

混合精度训练数据流：

```
  FP32 主权重 ──拷贝/截断──→ 半精度权重
       ▲                         │
       │                    前向传播 (半精度，快)
       │                         ▼
       │                      损失 loss
       │                         │
   优化器更新                后向传播 (半精度梯度)
   (FP32 高精度累加)              │
       │                         ▼
       └────── 半精度梯度 ───────┘
```

**为什么主权重必须 FP32**：权重更新量 $\Delta w = lr \times grad$ 往往非常小（如 $10^{-7}$），若直接累加到半精度权重上会被舍入吞掉（"大数吃小数"），训练停滞。FP32 主权重保证这些微小更新能被累积下来。

> 在训练期间，主权重始终为 FP32。而在实践中，在推理时，半精度权重通常能提供与 FP32 相似的精度——因为只有在模型梯度更新时才需要精确的 FP32 权重。这意味着在推理时我们可以使用半精度权重，这样我们仅需一半 GPU 显存就能获得相同的结果。

## 实操：显存占用手算（核心公式）

**单份权重显存 = 参数量 × 每参数字节数**：

| 精度 | 每参数字节 | 7B 模型权重 | 70B 模型权重 |
|------|----------|-----------|------------|
| FP32 | 4 | ≈ 28 GB | ≈ 280 GB |
| FP16 / BF16 | 2 | ≈ 14 GB | ≈ 140 GB |
| FP8 / INT8 | 1 | ≈ 7 GB | ≈ 70 GB |
| FP4 / NF4 | 0.5 | ≈ 3.5 GB | ≈ 35 GB |

手算示例：7B = $7\times10^9$ 参数，BF16 = 2 字节/参数 → $7\times10^9 \times 2 = 1.4\times10^{10}$ B ≈ 13 GB（按 1024 进制 ≈ 13.0 GiB，工程上常说 ~14 GB）。

> 注意：这只是"权重"。训练时还要叠加梯度（同精度一份）+ 优化器状态（Adam 通常 FP32 的一阶/二阶动量，约 8 字节/参数）+ 激活值。完整估算见 [[docs/transformer内存估算]]。

## 常见问题 / 坑

| 现象 / 误区 | 原因 | 应对 |
|-----------|------|------|
| FP16 训练突然 loss = NaN | 大数超过 64k 上溢，NaN 沿计算链传染 | 改用 BF16；或加 loss scaling 防下溢 |
| BF16 还要不要 loss scaling | BF16 范围 ≈ FP32，下溢风险小 | 一般不需要 |
| "TF32 能省显存" | 误解——TF32 是计算格式，权重仍按 FP32 存 | 它省的是算力/时间，不是显存 |
| FP16 与 BF16 哪个精度高 | 同 16 位，FP16 尾数 10 位 > BF16 尾数 7 位 | 比精度 FP16 胜；比范围/稳定性 BF16 胜 |
| 推理直接 FP32 才"准" | 推理不更新梯度，半精度精度足够 | 推理用半精度，显存减半结果相近 |
| 主权重也用半精度 | 微小更新量被半精度舍入吞掉，训练停滞 | 主权重必须 FP32 |
| INT8 量化掉点严重 | 离群值（outlier）撑大缩放因子，普通值精度被牺牲 | 分通道/分组量化，离群值单独处理 |
| FP4 直接等距切 | 神经网络权重近似正态，等距浪费两端桶 | 用 NF4 按分位点分桶 |
