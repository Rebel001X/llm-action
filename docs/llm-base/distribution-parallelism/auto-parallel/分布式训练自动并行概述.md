## 0. 一句话锚点

**自动并行 = 给计算图里每个张量找一个"切分方案"，再为相邻算子之间不匹配的切分自动插入通信，目标是最小化"逐迭代时间"且满足"每卡显存 ≤ 容量"。**

两个原子操作：
- **放置（Placement / Sharding）**：一个张量沿哪个维度切、切成几份、放在哪些设备上。
- **重分布（Reshard / 通信）**：上游产出的切分 ≠ 下游需要的切分时，自动插 All-Gather / All-Reduce / All-to-All / Reduce-Scatter。

```
   手动并行：人写代码决定每层怎么切  ──► 易错、不可移植、调参地狱
   自动并行：编译器/搜索器决定怎么切 ──► 输入(计算图, 集群) → 输出(并行执行计划)
```

## 1. 地基：先把"手动并行"的四个基础维度讲清

自动并行不是凭空发明并行方式，它是在**已知的基础并行维度的组合空间**里搜索。先把维度列清。

```
 模型一层 Linear:  Y = X · W           X:[B,S,H]  W:[H,4H]
 ┌─────────────┬───────────────────────────────────────────────┐
 │ 数据并行 DP  │ 切 batch 维 B；每卡整份 W；梯度 All-Reduce      │
 │ 张量并行 TP  │ 切 W 的列/行；每卡算一片；前后 All-Gather/Reduce│
 │ 流水并行 PP  │ 按"层"切；卡间只传激活；用 micro-batch 填气泡   │
 │ 序列并行 SP  │ 切 S 维(配合 TP 切 LayerNorm/Dropout 的激活)    │
 │ 专家并行 EP  │ MoE 把不同 expert 放不同卡；token 用 All-to-All │
 └─────────────┴───────────────────────────────────────────────┘
 ZeRO/FSDP：本质是 DP 上再切"优化器状态/梯度/参数"以省显存
```

关键直觉：**没有任何一种维度永远最优**。卷积层"数据 ≫ 参数"宜 DP；全连接/注意力"参数 ≫ 数据"宜 TP——这正是 Krizhevsky《One weird trick》的观察，也是自动并行的最初动机。

> 详见 [[llm-base/distribution-parallelism/data-parallelism/README]] · [[llm-base/distribution-parallelism/tensor-parallel/tensor-parallel]] · [[llm-base/distribution-parallelism/pipeline-parallelism/README]] · [[llm-base/distribution-parallelism/moe-parallel/README]]

## 2. 为什么必须"自动"——自动并行三难

仓库 README 的三难总结，用一张图固化：

```
        ┌──────────────┐
        │  ① 多样性    │  并行方式百花齐放 × 模型架构层出 × 硬件差异化
        ├──────────────┤      → 没有"银弹"并行策略
        │  ② 复杂性    │  同一算子可叠多种基础并行 → 混合并行
        ├──────────────┤      → 计算图巨大 → 组合空间爆炸 → 难求解
        ├──────────────┤
        │  ③ 实用性    │  需精确代价模型(显存/通信/计算)
        │              │  且搜索本身的额外开销要可接受
        └──────────────┘
```

- **多样性**：DP/TP/PP/SP/EP/ZeRO 各有不同的显存、通信、计算特征；模型有不同 $S,L,H$；集群有不同带宽/显存。
- **复杂性**：一个算子可同时 TP+SP，一张图上千算子，组合数随算子数指数增长（见 §4 手算）。
- **实用性**：代价模型不准 → 搜出"次优解甚至跑不起来"；搜索太慢 → 比手动调还费时间。

## 3. 把"并行"表示成可搜索的形式——分布式张量的类型系统

要让机器搜索，必须先给"一个张量怎么切"一个**形式化表示**。三套等价表示：

### 3.1 设备网格 Device Mesh

把 $N$ 张卡逻辑排成多维网格，每个维度对应一类并行。

```
 8 卡排成 2×4 mesh:
              axis-1 (size 4) →
   axis-0   ┌────┬────┬────┬────┐
   (size2)  │ g0 │ g1 │ g2 │ g3 │   ← 行内做 TP(4路)
      │     ├────┼────┼────┼────┤
      ▼     │ g4 │ g5 │ g6 │ g7 │   ← 列间做 DP(2路)
            └────┴────┴────┴────┘
```

### 3.2 SBP / Sharding Spec（每个张量的"切分签名"）

对张量的**每个并行轴**标注一种状态（OneFlow 称 SBP）：

| 记号 | 含义 | 还原全量的代价 |
|------|------|----------------|
| $S(i)$ Split | 沿第 $i$ 维切分，每卡持一片 | All-Gather |
| $B$ Broadcast | 每卡持完整副本 | 0（已完整） |
| $P$ Partial | 每卡持"部分和"，求和才完整 | All-Reduce / Reduce-Scatter |

> 例：列并行 Linear 的输出是 $S(\text{col})$；行并行 Linear 的输出是 $P$（partial sum），需 All-Reduce 才得最终 $B$。GSPMD 的 sharding spec、Alpa 的 intra-op、PyTorch DTensor 的 `Shard/Replicate/Partial` 都是同一思想的不同皮肤。

### 3.3 重分布 = 类型转换

相邻算子签名不匹配，编译器按"转换表"自动插通信：

```
 上游产出   下游需要   自动插入的集合通信
 ───────    ───────    ──────────────────────
  S(0)       B          All-Gather
  P          B          All-Reduce
  P          S(0)       Reduce-Scatter
  S(0)       S(1)       All-to-All
  B          S(0)       本地切片(无通信)
```

> 集合通信原语与其代价见 [[ai-infra/网络/集合通信原语]]。

## 4. 搜索空间为什么会"爆炸"——逐数手算

设计算图有 $M$ 个算子，每个算子可选 $k$ 种"切分签名"（intra-op 选择）。**朴素搜索空间** $= k^{M}$。

```
 取 k=4(对每个算子有4种切法), 一个 GPT 层约 M≈20 个主要算子:
   单层组合数 = 4^20 ≈ 1.1 × 10^12
   24 层 ⇒ (4^20)^24 = 4^480 ≈ 10^289   ← 远超宇宙原子数(~10^80)
```

更糟的是：相邻算子之间还要为"签名不匹配"付通信代价，所以**不能逐算子独立贪心**——这是一个带"边代价"的全局优化问题。这就是为什么必须用**代价模型 + 结构化搜索**，而不是穷举。

降维三招（几乎所有系统都用）：
1. **分层/分级**：Alpa 把问题拆成"算子内并行（intra-op）"+"算子间并行（inter-op，即 PP）"两级，分而治之。
2. **图划分/分组**：把整图切成 stage 或 sub-graph，组内 ILP/DP，组间动态规划。
3. **对称性假设**：假设同构集群、同构层，只对"一层"求解再复制，把 $4^{480}$ 压回 $4^{20}$。

## 5. 代价模型——自动并行的"准星"

搜索器每评估一个候选方案，都要快速估出三类代价。代价不准 = 搜索全白搭。

### 5.1 通信代价：$\alpha$-$\beta$ 模型

一次集合通信的时间近似
$$ T_{comm} = \alpha + \frac{n_{bytes}}{B_{eff}} $$
其中 $\alpha$ 是固定启动延迟（latency），$B_{eff}$ 是有效带宽。对 $p$ 卡 **Ring All-Reduce**，每卡收发的数据量是
$$ V_{ring} = 2\cdot\frac{p-1}{p}\cdot |M| \;\approx\; 2|M|\quad(p\text{ 大}) $$
其中 $|M|$ 是待规约张量字节数。**关键结论**：Ring All-Reduce 的单卡通信量与卡数 $p$ 几乎无关（趋于 $2|M|$）——所以 DP 的梯度同步可扩展性好。

### 5.2 显存代价

每卡峰值显存 ≈ 参数 + 梯度 + 优化器状态 + 激活：
$$ \text{Mem} \approx \underbrace{\Phi\cdot b_p}_{参数} + \underbrace{\Phi\cdot b_g}_{梯度} + \underbrace{\Phi\cdot b_{os}}_{优化器} + \underbrace{A}_{激活} $$
混合精度 + Adam 时常用 $b_p{=}2,\,b_g{=}2,\,b_{os}{=}12$（fp32 master + m + v），即每个参数 **≈16 字节**。
- TP 把参数/梯度/激活都按 $1/t$ 切；
- ZeRO/FSDP 把 $b_g,b_{os},b_p$ 按 DP 度切；
- 激活检查点（recompute）用计算换激活显存。

> 显存与 FLOPs 估算细节见 [[llm-algo/FLOPs]] 与 [[transformer内存估算]]。

### 5.3 计算代价

按算子 FLOPs / 设备峰值算力估时间，再乘利用率（MFU）。代价模型可以是**解析式**（Mesh-TF/GSPMD/Galvatron）或**profile 实测后拟合**（Alpa 对部分代价实测）。

## 6. 搜索算法谱系

```
 表达 → 代价模型 → 在巨大空间里"搜" 
                       │
   ┌──────────┬────────┼─────────┬──────────────┐
   ▼          ▼        ▼         ▼              ▼
 动态规划   整数规划   图划分   随机/进化搜索   强化学习
  (DP)       (ILP)    (min-cut)  (MCMC/EA)       (RL)
   │           │         │          │            │
 PP切stage  intra-op  Tofu划分   FlexFlow      Device
 Galvatron  Alpa      算子图     的MCMC搜索    Placement(早期)
```

| 方法 | 代表 | 思想 | 优点 / 痛点 |
|------|------|------|-------------|
| 动态规划 | Alpa(inter-op)、Galvatron | 把"切 stage / 选层并行"建成最优子结构 | 多项式时间；需问题可分解 |
| 整数线性规划 ILP | Alpa(intra-op) | 变量=每算子选哪种 sharding，约束=显存/通信 | 全局最优；规模大时慢，需剪枝 |
| 图划分 / min-cut | Tofu | 把"切分"转成图上最小割 | 经典、快；表达力有限 |
| 随机/进化搜索 | FlexFlow(MCMC) | SOAP 空间随机游走 + 模拟器评估 | 通用；收敛慢、靠模拟器准度 |
| 强化学习 | 早期 Device Placement | 用 RNN 策略放置算子 | 通用；样本效率低、训练贵 |

**Alpa 两级是当下范式**：外层用 DP 在"算子间（PP）"切 stage，内层用 ILP 在每个 stage 内求"算子内（TP/DP）"最优 sharding，二者交替——把 $4^{480}$ 的整体问题降成若干可解子问题。

```
 Alpa 分级:
   计算图 ──[inter-op DP]──► 切成若干 stage(流水段)
                                 │ 每个 stage
                                 ▼
                       [intra-op ILP] 求段内每算子的 sharding
                                 │
                                 ▼
                    组合得到全图并行计划 + 自动插入通信
```

```
 时间线(思想演进)：
 Mesh-TF ──► GShard/GSPMD ──► FlexFlow/Tofu ──► Alpa ──► Galvatron ──► 飞桨/MindSpore/Unity
 (手注网格)   (XLA自动补全)    (随机/割搜索)    (两级最优)  (含显存约束)   (工程化产品)
```

## 数值手算总演练

### 演练 A：TP 一层的通信量该不该切？

GPT 层隐藏维 $H=12288$，序列 $S=2048$，micro-batch $b=1$，fp16（2 字节）。Megatron 风格 TP 每层前向有 **2 次 All-Reduce**（注意力后、MLP 后），反向再 2 次，共 **4 次**，每次规约的是激活 $[b,S,H]$。

- 单个激活字节数：$|M| = b\cdot S\cdot H\cdot 2 = 1\times2048\times12288\times2 \approx 5.03\times10^7$ B ≈ **48 MB**。
- 8 路 TP 的 Ring All-Reduce 单卡通信量：$2\cdot\frac{p-1}{p}|M| = 2\times\frac{7}{8}\times48 \approx$ **84 MB/次**。
- 一层前后向 4 次 ⇒ 约 **336 MB/层**；24 层 ⇒ 约 **8 GB/迭代**仅 TP 激活通信。

**结论**：TP 通信发生在**每层内部、关键路径上**，所以只在**机内 NVLink（高带宽）**做 TP；跨机低带宽改用 DP/PP。自动并行器正是靠把这个 84MB×带宽 算进代价模型，才会"自动把 TP 限制在机内"。

### 演练 B：DP 梯度同步 vs TP 激活同步谁更省

参数量 $\Phi=7$B，fp16 梯度 $|G|=2\Phi=14$ GB。DP 每迭代**只同步 1 次**梯度（Ring All-Reduce）：单卡 $2\cdot\frac{p-1}{p}|G|\approx 28$ GB，但**只发生 1 次**且可与反向计算重叠（见 [[llm-optimizer/计算通信重叠]]）。

对比演练 A：TP 每迭代发 8 GB 但分散在**每层关键路径**、难完全重叠。→ 自动并行的代价模型据此判断："参数大但同步少 → DP 友好；激活大且在关键路径 → TP 仅限机内"。

### 演练 C：搜索规模估计（要不要上 ILP）

一层 $M=20$ 算子、每算子 $k=4$ 种 sharding：
- 朴素枚举：$4^{20}\approx1.1\times10^{12}$，单层就不可枚举。
- 转 ILP：变量 $\approx M\times k=80$ 个 0/1，约束 $\approx O(M)$（显存）+ $O(\text{edges}\times k^2)$（重分布代价）。现代 ILP 求解器秒级可解 → **这就是 Alpa 用 ILP 而非穷举的原因**。

## 常见问题

| 问题 | 答案 |
|------|------|
| 自动并行 = 自动调参吗？ | 不是。它在**形式化的切分空间**里用代价模型 + 优化算法求解，不是黑盒试错 |
| 为什么不直接贪心逐算子选最优？ | 相邻算子签名不匹配会引入重分布通信，**局部最优 ≠ 全局最优** |
| 代价模型一定要 profile 实测吗？ | 不一定。解析式（FLOPs/带宽）快但有误差；profile 准但慢。多数系统二者混合 |
| 自动一定比手动好吗？ | 大多数场景接近/超过专家手调，但对**全新架构/异构集群**仍可能次优；搜索本身也有开销（实用性约束） |
| ZeRO/FSDP 算自动并行吗？ | 算"自动显存优化"的一类，但它固定在 DP 维切状态，**不搜索 TP/PP 拓扑**，属于子问题 |
| 显存约束怎么进搜索？ | 作为硬约束（Galvatron）：任何使某卡 Mem > 容量的方案直接剪掉 |
| 搜出的计划能跨集群迁移吗？ | 不能直接迁移——换带宽/显存/卡数需**重新搜索**，因为代价模型变了 |
