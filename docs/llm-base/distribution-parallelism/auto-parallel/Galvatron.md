## 0. 一句话锚点

**自动并行 = 给定(模型结构, 集群拓扑, 显存预算)，自动搜出"每一层用哪种并行 + 用几路"的执行计划，使端到端吞吐最大。** 人手调的是「我猜一个并行配置」，Galvatron 调的是「把所有合理配置都建模、剪枝、求解，给你证明意义上的近最优」。

## 1. 地基：四种主流并行(Galvatron 的"积木")

Galvatron 是业界**首个同时考虑 4 种主流并行**的自动并行系统。先把积木认清，否则后面的决策树看不懂。

| 并行 | 切什么 | 每步通信 | 显存收益 | 通信量(相对) |
|---|---|---|---|---|
| **DP** 数据并行 | 切 batch，每卡全量参数 | 梯度 all-reduce | 不省参数显存 | 中 |
| **SDP** 分片数据并行(ZeRO) | 切 batch + 切参数/优化器状态 | all-gather 参数 + reduce-scatter 梯度 | 省参数/优化器显存 | 较高 |
| **TP** 张量并行 | 切单个算子的权重矩阵 | 每层 2 次 all-reduce | 省单层权重显存 | **高**(逐层) |
| **PP** 流水并行 | 切层(把模型纵向切成 stage) | 仅 stage 边界传 activation | 省整段层的显存 | **低**(显著最少) |

> 关键直觉：**PP 通信量最小、TP 通信量最大**。这个差异是后面 Takeaway#1 的物理根源。

```
一个 Transformer 的并行"维度"：

      ┌─────────── 层方向(纵向)：PP 在这里切 ───────────┐
      L1   L2   L3  ...  Ln
      │    │    │         │
      ▼    ▼    ▼         ▼   ← 每一层内部还能选 DP / SDP / TP
   [W 切片]  ← TP 在层内横向切权重矩阵
   [batch 切片] ← DP/SDP 在样本维切
```

**显存账本(为什么并行能塞下大模型)。** 设单层参数量 $\phi$、混合精度 Adam 训练，则每参数显存约为：权重 fp16 $2\phi$ + 梯度 fp16 $2\phi$ + Adam 状态 fp32(动量+方差+主权重) $12\phi$ = **$16\phi$**。三种切法对这 $16\phi$ 的影响完全不同：

| 并行 | 权重 $2\phi$ | 梯度 $2\phi$ | 优化器 $12\phi$ | 激活 |
|---|---|---|---|---|
| DP($d$ 路) | 不切 | 不切 | 不切 | 切 $1/d$(batch) |
| SDP/ZeRO($d$ 路) | 切 $1/d$ | 切 $1/d$ | **切 $1/d$** | 切 $1/d$ |
| TP($t$ 路) | 切 $1/t$ | 切 $1/t$ | 切 $1/t$ | 部分切 |
| PP($p$ 段) | 整段省(只持有本 stage 层) | 同左 | 同左 | 持有 in-flight micro-batch |

这张表解释了 Takeaway#3：SDP 在显存维度严格优于 DP(优化器状态那 $12\phi$ 也切了)，所以"能 SDP 就别 DP"。

### 与现有自动并行工作的关系(原文综述)

Galvatron 属于"混合并行自动搜索"领域，相比前作扩展了维度：

```
 同时考虑 DP + 模型并行的搜索 ──► FlexFlow, Tofu
 流水并行 + 数据并行的结合   ──► PipeDream, DAPPLE
 进一步扩展自动并行范围      ──► Unity, Alpa
 ─────────────────────────────────────────────
 Galvatron(惊破天)：首个同时纳入 DP/SDP/TP/PP 四维
```

相比现有工作，Galvatron 自陈三方面优势：

- **多样性**：支持更多并行维度，能对差异化 Transformer 结构精准建模，并在不同集群硬件上验证自适应调优能力。
- **复杂性**：维度多 → 搜索空间空前庞大 → 用经验/理论验证过的"重要观察"作剪枝准则，实现高效执行计划优化。
- **实用性**：理论建模 + 实验测量结合，精确估计内存/通信/计算开销，甚至考虑计算与通信重叠导致的 GPU 执行效率下降。

## 2. 为什么需要自动搜索：搜索空间会爆炸

混合并行 = 上面四种的**任意组合**。组合数随 GPU 数和层数**指数增长**：

- 双机四卡，举两个可行解就完全不同：
  - 方案 A：机内 2-way **TP** + 机间 2-way **PP**
  - 方案 B：机内 2-way **PP** + 机间 2-way **DP**
- 节点内扩到 **8 卡** 时，**模型每一层的候选策略多达上百种**。
- 模型有 $L$ 层，朴素地每层独立选，则总空间 $\approx (\text{每层候选数})^{L}$，指数爆炸，无法穷举。

数值感受：若每层 100 种候选、模型 40 层，朴素空间 $=100^{40}=10^{80}$ —— 比可观测宇宙原子数还多。**所以必须先剪枝，再求解。**

手算一下"为什么双机四卡就已经分叉"：4 卡的并行因子分解 $4 = 2\times 2$，可以把这两个"2"分配给 {DP, SDP, TP, PP} 中的任意维度，且还要决定哪个 2 放机内、哪个放机间。光是"两台机器之间放哪种并行、机器内部放哪种并行"就有 $4\times 4 = 16$ 种粗组合，再叠加每种并行的具体路数与层间不一致性，单层就轻松上百。**这正是 §3 三条 Takeaway 要砍掉的部分。**

## 3. 三条剪枝观察(Takeaway)：把"上百种"砍成"几十种"

Galvatron 的核心贡献之一，是从大规模分布式训练实践中提炼出三条**经实验/理论验证的观察**，作为搜索空间剪枝准则。

**Takeaway#1：PP 倾向被放在"跨设备岛"之间。**
"设备岛"= 内部带宽很高的一组设备(如同一台机器内的 8 卡 NVLink)。因为 PP 通信量显著少于其它并行(见 §1 表)，所以应优先用 PP 把模型切开、跨越**低带宽的机间链路**，把高通信的 TP/DP 留在岛内高带宽处。

```
机间(低带宽 InfiniBand) ←─ 放 PP(通信少，扛得住低带宽)
   ┌─────────────┐      ┌─────────────┐
   │ 机器0(设备岛)│      │ 机器1(设备岛)│
   │ 岛内 NVLink  │      │ 岛内 NVLink  │
   │ 放 TP/DP/SDP │      │ 放 TP/DP/SDP │ ← 高通信留在高带宽
   └─────────────┘      └─────────────┘
```

**Takeaway#2：同构设备下，并行策略倾向"均匀切分"。**
4 卡的 2-way DP 应切成两组各 2 卡，而不是 (1 卡, 3 卡)。推论很重要：**一个设备组内的最优混合策略，与其它对称组内的最优策略一致** —— 这把"为每组单独搜"降为"搜一组、复制到其它组"。

**Takeaway#3：能混用 DP 和 SDP 时，只用 SDP 理论上更优。**
SDP(ZeRO 式分片)在省显存的同时通信开销并不比 DP+额外冗余差，因此把"同一棵树里 DP 和 SDP 同时出现"的情形直接剪掉。

## 4. 关键技术一：基于决策树的搜索空间分解

有了三条观察，Galvatron 把"组合爆炸"重构成**一组决策树**，每棵树是一个子搜索空间。

构建规则：

1. **先用 PP 分层、均匀切设备组**(依据 Takeaway#1 + #2)。8 卡场景下，模型被切成 **1 / 2 / 4 / 8-way PP**，分别对应设备组大小 **8 / 4 / 2 / 1**。
2. **每种 PP 切分对应一棵决策树**。
   - 决策树**叶结点总数 = 设备组大小**；
   - 决策树**高度 = 可用并行方法数**(每一层应用一种并行策略 DP/SDP/TP)；
3. **同一并行策略在树的不同层间不可重复使用**(避免重复计数)。
4. **非叶结点的度数**默认在 2 的幂 $\{2,4,8,\dots\}$ 中选(依据 Takeaway#2 均匀切分)。

```
8 卡、某一种 PP 切分(设备组大小=4)的一棵决策树：

           根(4 卡设备组)
           度数∈{2,4}  ← 选一种并行先切
          /        \
     [DP 2-way]   [TP 2-way]   ← 树的第1层选一种策略
        |             |
     [TP 2-way]    [SDP 2-way] ← 第2层选另一种(不可重复)
        |             |
      叶          叶   ← 叶子=最终的 1 卡

  一条根→叶的路径 = 一种具体混合并行组合
```

为什么这能覆盖所有合理组合？因为"先 PP 选 stage 数 → 再在每组里逐层选 DP/SDP/TP 的嵌套"，恰好枚举了**符合 Takeaway 约束**的所有混合策略，又自动排除了非均匀、PP 放岛内等低效组合。

**8 卡的 4 棵决策树长什么样(全景)：**

```
PP=1(设备组=8)          PP=2(设备组=4)        PP=4(设备组=2)     PP=8(组=1)
  树高=3，叶=8             树高=3，叶=4           树高=2，叶=2        平凡
  3 层各选 DP/SDP/TP       2~3 层选并行          1~2 层选并行       无层内并行
  组合数最多               组合数中等            组合数少           仅 1 种
        \                      |                    /                 /
         └──────── 4 棵树并集 = 8 卡单层全部 34 种候选 ───────────┘
                              │ 应用 Takeaway#3(DP/SDP 不同树共现)
                              ▼
                          剪到 22 种
```

每棵树的一条"根→叶路径"读出来就是一条具体策略，例如 PP=2 树里 `[根 4卡 → TP 2-way → DP 2-way → 叶]` 表示：先 2-way PP 切两段，每段 4 卡里再 2-way TP、再 2-way DP。度数都取自 $\{2,4,8\}$ 保证均匀切分。

**剪枝效果(真实数值)：**

| 场景 | 候选混合并行策略数 |
|---|---|
| 8 卡训练一层模型(规则产出) | **34 种** |
| 再用 Takeaway#3 剪掉"DP 与 SDP 同树共现" | **22 种** |

> 从"每层上百种"降到 22 种 —— 这就是剪枝把指数空间压成可搜空间的关键。

## 5. 关键技术二：基于动态规划的并行优化算法

剪枝后每层仍有 ~22 种候选，逐层独立选会割裂层间的显存/通信耦合。Galvatron 用**动态规划(DP 算法，注意此处是算法不是数据并行)**在层维上求全局最优：

- 子问题：在显存预算约束下，前 $i$ 层使用某种状态(并行配置)时的最小代价。
- 状态转移：从第 $i$ 层的配置转移到第 $i{+}1$ 层，叠加该层在 §6 估出的计算/通信/显存代价。
- 复杂度从朴素的 $O(\text{候选数}^{L})$ 降为关于 $L$ **线性**的多项式级，使全局搜索可行。

形式化一点，记 $C[i][s]$ 为"前 $i$ 层、第 $i$ 层采用策略 $s$ 时"的最小代价，显存上界为 $M$：

$$C[i][s] = \min_{s' \in \text{候选}} \Big( C[i{-}1][s'] + \text{cost}(i, s) + \text{switch}(s', s) \Big),\quad \text{s.t. } \text{mem} \le M$$

其中 $\text{switch}(s',s)$ 是相邻层并行方式切换带来的重切分(reshard)开销 —— 这正是"不能各层独立贪心"的原因：贪心会忽略层间切换代价。

```
层:   L1     L2     L3   ...   Ln
      ┌──┐   ┌──┐   ┌──┐       ┌──┐
状态: │22│──►│22│──►│22│──►...─►│22│  ← 每层 22 个候选状态
      └──┘   └──┘   └──┘       └──┘
       └ 转移时加 cost(层) + switch(层间) + 检查显存 ≤ M
   DP 表沿层方向一遍扫，回溯得最优策略序列(每层用什么并行)
```

> 直觉：因为 Takeaway#2 保证"对称设备组最优解一致"，DP 只需在一个代表性维度上推进，而不必对每个物理组重复求解。

## 6. 关键技术三：基于混合建模的执行代价估计

自动并行的成败取决于**代价估计准不准**。Galvatron 结合两条腿：

- **理论建模**：根据并行方式推导通信量、显存占用的解析式(如 TP 每层 2 次 all-reduce 的字节数)。
- **实验测量**：真机跑微基准，校准理论模型与实际硬件的差异。
- **重叠惩罚**：特别建模了"**计算与通信重叠会导致 GPU 执行效率下降**"的现象 —— 通信和计算抢 SM/带宽时，二者都变慢，不能简单 $\max(\text{compute},\text{comm})$。这一点是很多代价模型估不准的根因。

```
朴素估计(乐观)：  time ≈ max(compute, comm)         ← 高估了重叠收益
Galvatron 估计：  time ≈ max(compute, comm) × (1+惩罚) ← 贴近真机
```

三项(显存 / 通信 / 计算)都估准后，喂给 §5 的动态规划，才能得到"足够准确"的自动并行结果。

## 实操：如何接入(保留原文真实使用方式)

Galvatron 的工程特性(原文要点，逐条保留)：

- **底层执行引擎选 PyTorch**：不给 PyTorch 用户带来额外使用负担。
- **兼容 HuggingFace 等主流 Transformer 实现**：常见模型可直接用。
- **无需额外系统安装或调试代价**。
- **使用时只需添加几行代码**，即可走完"自动并行搜索 → 生成执行计划 → 分布式训练"整个流程。

> 工作流心智模型：
> ```
> 1) 给模型(HF Transformer) + 集群信息(GPU 数/拓扑) + 显存预算
> 2) Galvatron 用 §6 代价模型对每层每种候选打分
> 3) §4 决策树生成候选 → §3 三条 Takeaway 剪枝(34→22)
> 4) §5 动态规划求全局最优混合并行计划
> 5) 落到 PyTorch 上执行训练
> ```

## 常见问题 / 坑

| 现象 / 误区 | 原因 | 应对 |
|---|---|---|
| 把 TP 放到机间 | TP 逐层 2 次 all-reduce，通信量最大，机间低带宽扛不住 | 遵循 Takeaway#1：机间放 PP，机内放 TP/DP |
| 设备非均匀切分(如 1+3) | 破坏 Takeaway#2，对称组最优一致的前提失效，求解既慢又次优 | 度数限制在 2 的幂、均匀连续切设备 |
| DP 与 SDP 在同棵树共现 | 冗余且理论次优 | Takeaway#3 直接剪掉(34→22) |
| 代价模型用 max(compute,comm) | 忽略了通信/计算重叠时的效率下降 | 加重叠惩罚项，并用真机实测校准 |
| 以为"层数多就只能手调" | 朴素空间是指数 $(候选)^L$ | 决策树剪枝 + 层维动态规划把它降到可搜规模 |
| 异构集群直接套用 | 三条 Takeaway 假设**同构设备**(设备岛、均匀切分) | 异构需重新建模设备带宽/算力差异 |
