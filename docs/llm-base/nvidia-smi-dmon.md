## 0. 一句话锚点

> **`nvidia-smi dmon` = 设备监控命令，以滚动条形式逐行刷新显示 GPU 设备统计信息。**

- GPU 统计以**一行滚动格式**显示；要监控哪些指标可基于终端窗口宽度调整。
- **不指定任何 GPU 时，默认监控所有 GPU**（每个采样周期，每块卡打印一行）。
- 与裸 `nvidia-smi`（每次全屏快照、需配 `-l` 循环刷屏）相比，`dmon` 是**面向时间序列**的：每行一个时刻，天然适合粘进日志、grep、画曲线。

```
nvidia-smi（快照）            nvidia-smi dmon（时间序列）
┌───────────────────┐        t0  gpu0  pwr sm mem ...
│   全屏表格         │        t1  gpu0  pwr sm mem ...   ← 一行一时刻
│   覆盖刷新         │   vs   t2  gpu0  pwr sm mem ...      向下滚动
└───────────────────┘        t3  gpu0  pwr sm mem ...
```

## 1. 地基：dmon 的数据是从哪来的

`nvidia-smi` 只是命令行外壳，真正读数的是它底层链接的 **NVML（NVIDIA Management Library）**，NVML 再通过内核态 **驱动** 去问 GPU 上的传感器/计数器。

```
你的命令          用户态库           内核 & 硬件
nvidia-smi dmon ─► NVML(libnvidia-ml) ─► nvidia 驱动 ─► GPU 传感器/计数器
                                                         (功耗ADC/温度二极管/
                                                          SM活动计数器/时钟域)
```

要点（为什么重要）：
- **数值是采样得到的瞬时/近瞬时值**，不是积分平均，所以同一指标相邻两行可能跳得很大（见第 6 节 rxpci 抖动）。
- dmon 读取**设备级**（device-level）聚合指标，不区分是哪个进程贡献的——要看"哪个进程吃了多少显存"得用 `nvidia-smi`（pmon 子命令或主表）。
- 监控本身**几乎不占 GPU 算力**，但默认会持续运行直到 Ctrl-C。

## 2. 输出每一列在说什么

默认表头（电源组 p + 利用率组 u + 时钟组 c，即默认 `puc`）：

```
# gpu   pwr gtemp mtemp    sm   mem   enc   dec  mclk  pclk
# Idx     W     C     C     %     %     %     %   MHz   MHz
```

| 列 | 单位 | 含义 | 物理直觉 |
|---|---|---|---|
| `gpu/Idx` | — | GPU 索引号 | 第几块卡 |
| `pwr` | W | 当前板卡功耗 | 越接近 TDP 越满载 |
| `gtemp` | °C | GPU 核心温度 | 触发降频的关键 |
| `mtemp` | °C | 显存温度 | HBM/GDDR 热点 |
| `sm` | % | **SM（流多处理器）活动占比** | ≈"算力被用了多少时间" |
| `mem` | % | **显存控制器带宽占用率** | 注意：**不是**显存容量占用！ |
| `enc` | % | 视频编码引擎利用率 | NVENC，训练通常 0 |
| `dec` | % | 视频解码引擎利用率 | NVDEC，训练通常 0 |
| `mclk` | MHz | 显存时钟 | 内存频率 |
| `pclk` | MHz | 处理器（SM）时钟 | 核心频率 |

**最关键的一对易混字段**（第 6 节会用到）：

```
sm  = 计算单元忙不忙（时间占比）        ← 算力维度
mem = 显存"带宽"通道忙不忙（读写吞吐）  ← 内存带宽维度
                  ↑ 都和"显存用了多少 GB"无关！
```

> 显存容量占用要看 `-s m`（FB/Bar1 内存）或主表的 `Memory-Usage`。

## 3. `-d`：采样周期与"滚动"的本质

`-d <秒>` 设置刷新（采样）间隔，默认 1 秒。**每过一个周期，dmon 就把当前快照追加一行**（多 GPU 则一次追加多行）。

```
-d 5：每 5 秒一拍
t=0s  ┃ 打印 gpu0..7 各一行   ← 第 1 帧（8 卡 = 8 行）
t=5s  ┃ 打印 gpu0..7 各一行   ← 第 2 帧
t=10s ┃ 打印 gpu0..7 各一行   ← 第 3 帧
```

**数值手算（理解时间分辨率）**：若一次训练 step 耗时约 0.3s，而你用 `-d 5`，那么这 5 秒里跑了约 $5 / 0.3 \approx 16$ 个 step，dmon 给你的是这 16 步"混在一起"的一个瞬时采样点——所以想抓"单步级"尖刺要把周期调小（如 `-d 1`），想看长期趋势才用大周期。**周期越小，行数越密、I/O 越多**。

## 4. `-i`：只盯指定的 GPU

不加 `-i` = 监控全部。`-i` 后跟索引（逗号分隔多卡）。

- `-i 3`：只看 3 号卡。
- `-i 3,6`：同时看 3、6 号卡（每帧打印这两行）。

为什么需要它：8 卡机默认每帧 8 行，刷屏快、噪声大；定位"某张卡掉频/过热/带宽异常"时，锁定单卡能让滚动可读、便于肉眼比对相邻帧。

## 5. `-s`：选择显示哪些指标组（默认 `puc`）

`-s` 用一组字母拼出你要的列。**字母 = 指标组**：

| 字母 | 指标组 | 展开的列 |
|---|---|---|
| `p` | 电源与温度 | pwr（功耗）、gtemp/mtemp（温度） |
| `u` | 利用率 | sm（流处理器）、mem（显存带宽）、enc（编码）、dec（解码） |
| `c` | 时钟频率 | mclk（显存频率）、pclk（处理器频率） |
| `v` | 电源 & 热力异常 | power/thermal violation |
| `m` | 内存 | FB 内存、Bar1 内存（这是**容量**） |
| `e` | 错误计数 | ECC 错误、PCIe replay（重显）错误个数 |
| `t` | PCIe 带宽 | rxpci/txpci（读/写带宽） |

组合即拼列：`-s put` = 电源组 + 利用率组 + PCIe 带宽组，于是 `mclk/pclk` 被换成 `rxpci/txpci`：

```
默认 puc:  ... sm mem enc dec | mclk pclk
-s put :   ... sm mem enc dec | rxpci txpci   ← c(时钟)换成 t(PCIe带宽)
```

记忆口诀：**p 看热、u 看忙、c 看频、m 看容量、e 看错、t 看搬运、v 看违规**。

## 6. 读数实战：从样例反推 GPU 在干什么

拿原文 `-d 5` 的第一帧（空闲态）对比后面（压满态）：

```
空闲:  0  123W ... sm  5%  mem 0%   ← 功耗低、SM几乎不动 → 卡在等数据/没任务
满载:  0  191W ... sm 100% mem 3%   ← SM打满、功耗升 → 计算密集（compute-bound）
异常:  4  300W ... sm 73% mem 39%   ← 功耗冲到300W、显存带宽39% → 内存压力上来了
```

判读心法：

| 现象 | sm | mem(带宽) | pwr | 多半是 |
|---|---|---|---|---|
| 计算密集（理想训练态） | 高(≈100) | 低 | 高(近TDP) | GPU 吃满，健康 |
| 访存密集 | 中高 | 高 | 高 | 带宽瓶颈，考虑算子融合/量化 |
| 喂不饱 | 低 | 低 | 低 | 数据加载/CPU/通信瓶颈 |
| 掉频降速 | 任意 | 任意 | — + gtemp 高 | 散热/功耗墙触发，看 `-s v` |

对 `-s put` 那段数据，注意 `rxpci/txpci` 列出现 `2016001 / 1765799`、`1910283` 这类**百万级 MB/s 的尖峰**——这是采样瞬时计数差被放大的典型抖动（见常见坑），相邻行又回落到三位数，说明 PCIe 实际平均带宽并没那么夸张，别被单点吓到，要看连续多帧的趋势。

### 指定显示哪些监控指标（`-s`，默认 `puc`）

- `p`：电源使用情况和温度（pwr：功耗，temp：温度）
- `u`：GPU 使用率（sm：流处理器，mem：显存，enc：编码资源，dec：解码资源）
- `c`：GPU 处理器和 GPU 内存时钟频率（mclk：显存频率，pclk：处理器频率）
- `v`：电源和热力异常
- `m`：FB 内存和 Bar1 内存
- `e`：ECC 错误和 PCIe 重显错误个数

## 常见问题 / 坑

| 坑 | 现象 | 解释 / 规避 |
|---|---|---|
| `mem` 当成显存容量 | 训练明明吃了 70GB，dmon 里 `mem` 才 3% | `mem` 是**显存带宽利用率**，不是容量；看容量用 `-s m`（FB 内存）或主表 `Memory-Usage` |
| rxpci/txpci 突然百万级 | 一行 `2016001` 下一行 `775` | PCIe 带宽是采样差分值，瞬时抖动正常；看连续多帧趋势，别信单点 |
| 周期太大漏掉尖峰 | `-d 5` 看不到瞬时掉频 | 想抓单步级毛刺改 `-d 1`；看长期趋势才用大周期 |
| 8 卡刷屏看不清 | 默认全卡、滚动飞快 | 用 `-i` 锁定目标卡；或 `-c N` 只采 N 帧后退出 |
| sm 高但训练慢 | sm≈100 却吞吐低 | sm 只表示"SM 有活动的时间占比"，不等于真实算力利用率（可能 occupancy 低）；结合 profiler 看 |
| enc/dec 永远 0 | 训练场景两列都 0 | 正常，那是视频编解码引擎（NVENC/NVDEC），LLM 训练/推理用不到 |
| 当成进程级工具 | 想知道哪个进程吃卡 | dmon 是**设备级**聚合；按进程要用 `nvidia-smi`（主表/pmon） |
| gtemp 高伴随 pclk 下降 | 温度上去后频率掉 | 触发热/功耗墙降频，加 `-s v` 看 violation 计数确认 |
