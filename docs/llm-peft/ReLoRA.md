# ReLoRA：用反复合并的低秩更新逼近高秩训练

> 一句话定位：**ReLoRA = 多轮 LoRA + 周期性合并 + 优化器部分重置 + 锯齿学习率**，让"一直只训低秩矩阵"的累积效果逼近"训练一个高秩增量"，把 LoRA 从"只能微调"推向"也能省显存地预训练"。

## 0. 一句话锚点

LoRA 把权重更新约束在**秩 $\le r$ 的低秩子空间**里：$\Delta W = BA$，秩最多 $r$（通常 $r=8\sim64$，而 $d$ 是几千）。
微调时这够用——下游适配本就"改动小"。但**从零预训练**需要的有效更新秩远高于几十。

ReLoRA 的核心洞察来自一条线性代数事实：

$$\operatorname{rank}(M_1 + M_2) \le \operatorname{rank}(M_1) + \operatorname{rank}(M_2)$$

把它**反过来用**：若我把多个"秩 $\le r$"的低秩增量**先后训练、再依次加进主权重**，它们的**和**就可能达到秩 $rk$（$k$ 是轮数）。于是：

> **一直只训低秩矩阵，但通过"训一段→合并→再训新的一段"，累积出一个高秩的总更新。** 这就是 ReLoRA。

```
LoRA  : W0 ──+ B A──► 总更新秩 ≤ r          (只够微调)
ReLoRA: W0 ─+B1A1─merge─+B2A2─merge─+B3A3─► 总更新秩 ≤ 3r (够预训练)
              第1轮        第2轮       第3轮
```

## 1. 地基/前置：先把 LoRA 钉死

ReLoRA 是 LoRA 的"外循环包装"，必须先把 LoRA 这层理解到原子级。

LoRA 给一个被冻结的权重 $W_0\in\mathbb{R}^{d_{out}\times d_{in}}$ 旁挂一条低秩支路：

$$h = W_0 x + \underbrace{B A}_{\Delta W}\, x,\qquad A\in\mathbb{R}^{r\times d_{in}},\ B\in\mathbb{R}^{d_{out}\times r},\ r\ll \min(d_{in},d_{out})$$

- $A$ 通常用高斯随机初始化，$B$ **初始化为 0** ⇒ 训练起点 $\Delta W = BA = 0$，不破坏预训练权重。
- 训练时**只更新 $A,B$**，$W_0$ 冻结。可训参数从 $d_{out}d_{in}$ 降到 $r(d_{out}+d_{in})$。
- 常带一个缩放：$h = W_0x + \frac{\alpha}{r}BAx$。

```
        x ──────────────► [ W0  冻结 ] ──┐
        │                                ├─► h = W0 x + (α/r)·B A x
        └─► [A r×d] ─► [B d×r 初始0] ──► (低秩旁路，可训)
```

> 关键账（来自 [[llm-peft/README]] 的手算）：$d=4096,\ r=8$ 时单矩阵可训参数 $2dr\approx 6.5$ 万，仅是 $d^2\approx1678$ 万的 **0.4%**。这就是单卡能 LoRA 微调大模型的根本原因。

🔗 LoRA 家族的另一支省显存方向见 [[llm-peft/LoRA-FA]]（冻结 $A$ 只训 $B$，省的是**激活显存**而非参数）。

## 2. 秩瓶颈：LoRA 为什么不能直接拿来"预训练"

微调 ≠ 预训练，差别就在**需要的更新秩**。

| 场景 | 权重要走多远 | 有效更新秩 | LoRA 够不够 |
| --- | --- | --- | --- |
| 下游微调 | 从一个好起点小步挪 | 很低（几十） | 够，$r=8\sim64$ 即可 |
| 从零预训练 | 从随机权重学到全部知识 | 很高（接近满秩 $d$） | **不够**，$r$ 提到几百也追不上全参 |

经验现象：在预训练上直接用单次 LoRA，损失会明显落后于全参训练——因为**整个训练过程的总更新被永久锁在一个 $\le r$ 维子空间里**，表达力天花板太低。

```
全参预训练:  更新可在 d 维空间任意走（满秩）
单次 LoRA :  更新永远困在固定的 r 维平面里
            ┌───────────────── d 维空间 ─────────────────┐
            │   ·全参轨迹可达任意角落·                    │
            │        ╱╲                                   │
            │  ┌────┴──┴──── r 维平面(LoRA 被困在这) ──┐  │
            │  └──────────────────────────────────────┘  │
            └────────────────────────────────────────────┘
```

ReLoRA 要解决的就是：**怎样在不破坏"每次只训低秩"省显存优势的前提下，让总更新逃出单个低秩平面。**

## 3. 核心定理：秩的次可加性怎么被"反用"

数学地基只有一行：

$$\operatorname{rank}(M_1 + M_2) \le \operatorname{rank}(M_1) + \operatorname{rank}(M_2)\quad(\text{次可加性})$$

直观：两个秩-1 矩阵相加，一般得到秩-2；除非它们恰好共线才退化。所以"一堆低秩矩阵之和"**通常**能撑起较高的秩。

ReLoRA 把训练过程拆成 $k$ 段。第 $t$ 段训练出一个低秩增量 $\Delta W_t = B_t A_t$（秩 $\le r$），训完就**合并进主权重**。$k$ 段全部合并后：

$$W_{\text{final}} = W_0 + \sum_{t=1}^{k} B_t A_t,\qquad \operatorname{rank}\!\Big(\sum_{t=1}^{k} B_t A_t\Big)\ \le\ kr$$

只要各段的低秩子空间方向**不重合**，总更新的有效秩就能远超 $r$，逼近全参所需的高秩。关键在于"不重合"——这要靠 §5 的优化器重置和 §6 的学习率重启来**强制让每一段去探索新方向**。

```
段1: 学到方向集合 {v1..vr}  ──merge──►  并入 W
段2: 在新的优化器/学习率状态下，倾向学新方向 {v_{r+1}..v_{2r}}
...
合并后总方向 ≈ {v1 .. v_{kr}}  ⇒ 有效高秩
```

## 4. 训练主循环：训一段→合并→重置→再训一段

ReLoRA 不是一次性训练，而是把训练切成若干"重启周期"（每周期 $T$ 步）。一个周期内的动作：

```
═══════════ ReLoRA 外循环（重复 k 次）═══════════
 [初始化] A 随机, B=0  （旁路从 0 起步，不扰动 W）
   │
   ├─(1) 内层正常训练 T 步：只更新 A,B，W 冻结
   │        h = W x + (α/r) B A x
   │
   ├─(2) 合并 merge:  W ← W + (α/r) · B A
   │        低秩增量"沉淀"进主权重，永久保留
   │
   ├─(3) 重置旁路:    A ← 新随机, B ← 0
   │        下一段从 ΔW=0 重新出发，去探索新的 r 维子空间
   │
   ├─(4) 部分重置优化器状态(见 §5)
   │
   └─(5) 学习率 warmup 重启(见 §6 锯齿)
 ════════════════════════════════════════════════
 训练全程显存 ≈ 只够存一份 W + 一对很小的 A,B 的优化器状态
```

要点：
- **合并是无损的代数恒等**：$Wx + BAx = (W+BA)x$，合并不改变当前函数，只是把增量"固化"。
- 合并后 $W$ 不再冻结意义上的"原始预训练权重"，而是**累积权重**；但对每一段来说，$W$ 始终是冻结的常量，省显存的性质保持不变。
- 整个外循环里，**任意时刻显存中只有一对小的 $A,B$ 在被优化**，所以优化器状态（动量/方差）只对这一对小矩阵存在——这是省显存的命门（见 §7）。

---

## 5. 为什么必须"部分重置优化器"——而不是全置零、也不是不动

合并完、换上新的 $A,B$ 后，优化器（Adam）里还残留着**上一段 $A,B$ 的动量 $m$ 和方差 $v$**。直接沿用会出大问题：

- 旧的 $m$（一阶动量）记着**上一个低秩方向**的惯性。若全盘继承，新一段会被"拽回"老方向 ⇒ 各段方向重合 ⇒ 总秩上不去（退化回单次 LoRA）。
- 但若**全部清零**，相当于每段都冷启动，前期不稳、浪费步数。

ReLoRA 的折中是**部分重置（pruning/部分置零优化器状态）**：把优化器状态中**一部分**（论文里按比例，如随机/按幅值置零约 90%~99%）清掉，保留一小部分作为"软惯性"。

```
合并后优化器状态处理:
 全继承 ✗  → 新段被旧方向绑架, 方向重合, 秩不增
 全清零 ✗  → 每段冷启动, 不稳, 收敛慢
 部分重置 ✓ → 大比例清空 m,v 解除惯性, 留小部分稳过渡
              ┌── m,v ──┐
              │▓▓░░░░░░░│  ▓=保留(少)  ░=清空(多)
              └─────────┘
```

> 直觉：**重置是为了"逼着新一段去学新方向"**，从而让 §3 的"方向不重合"成立，秩才真正叠加。这一步是 ReLoRA 区别于"反复 LoRA"的灵魂。

---

## 6. 锯齿形（重启）学习率：让每一段都重新热身

合并 + 重置优化器后，新一段的 $B=0$、动量被清，相当于**一次小的冷启动**。若直接用周期末那个已经衰减到很小的学习率，新段几乎学不动；若用很大的学习率，又会因为 $m,v$ 被清而震荡。

解法：**每个重启周期都做一次 warmup → decay 的小三角**，整体学习率曲线呈**锯齿状（jagged schedule）**。

```
lr
 │   ╱╲        ╱╲        ╱╲         ← 每段: 短warmup 爬升, 再衰减
 │  ╱  ╲      ╱  ╲      ╱  ╲
 │ ╱    ╲    ╱    ╲    ╱    ╲
 └─┴────┴────┴────┴────┴────┴──► step
   │warm│     合并点(reset)在谷底
   段1       段2        段3
```

- **谷底对齐合并点**：在学习率最低时合并/重置，扰动最小，过渡最平滑。
- **每段重新 warmup**：给被清零的动量一个重新建立惯性的缓冲，避免重置瞬间梯度爆。
- 周期长度 $T$、warmup 步数是关键超参；$T$ 太短则每段没学透、合并太频繁；$T$ 太长则退化为少数几次 LoRA，秩不够。

> 三件套是**强耦合**的：合并（§4）让增量沉淀、优化器部分重置（§5）解除方向惯性、锯齿 lr（§6）让新段安全热身。缺一个，ReLoRA 就退化回"效果有限的反复 LoRA"。

## 7. 数值手算：ReLoRA 到底省了什么

设隐藏维 $d=4096$，被改的方阵 $W\in\mathbb{R}^{d\times d}$，秩 $r=128$，训练采用 Adam 混合精度。回顾 [[llm-train/README]] 与 [[llm-peft/README]]：**全参 Adam 混精每参数 16 字节**（权重2+梯度2+master4+动量4+方差4）。

**① 单个 $d\times d$ 矩阵：可训参数对比**

| 方案 | 可训参数 | 数值 | 占全参比 |
| --- | --- | --- | --- |
| 全参 | $d^2$ | $4096^2=1677.7$ 万 | 100% |
| LoRA / ReLoRA（每段） | $2dr$ | $2\times4096\times128=104.9$ 万 | **6.25%** |

> 注意 $r=128$ 比微调常用的 8 大很多——因为预训练要更高秩，但**单段仍只有 6.25% 可训参数**。

**② 优化器+梯度显存：省在哪**

显存大头是**优化器状态 + 梯度**，它们只对**可训参数**存在。主权重 $W$ 这一份谁都要存（FP16 共 $2d^2$ 字节）。

- 全参：可训 = $d^2$。Adam 状态+梯度+master = $14\times d^2$ 字节（除 FP16 权重 2 字节外的 14）。
  $14\times4096^2 = 14\times1677.7\text{万} \approx 2.35\times10^{8}$ 字节 $\approx \mathbf{224\ MB}$（单矩阵）。
- ReLoRA：可训 = $2dr=104.9$ 万。同样口径 $14\times104.9\text{万}\approx1.47\times10^{7}$ 字节 $\approx \mathbf{14\ MB}$（单矩阵）。

> **优化器相关显存降到约 1/16**（与可训参数比 6.25% 对应）。模型越大、层数越多，这块绝对值越夸张——这正是 ReLoRA 让"低显存预训练"成为可能的原因。

**③ 合并是免费的吗？**

合并 $W \leftarrow W + \frac{\alpha}{r}BA$ 需要一次 $d\times d$ 的矩阵乘加：FLOPs $\approx 2d^2r$（这里是把 $B(d\times r)\cdot A(r\times d)$ 乘出来）。

> $2\times4096\times4096\times128\approx 4.3\times10^{9}$ FLOPs/矩阵。但它**每 $T$ 步才发生一次**（$T$ 常是几千步），平摊到每步可忽略——相比每步前反向 $\approx 6N$/token（见 [[llm-algo/FLOPs]]）的开销，合并是"白送"的。

**④ 推理零额外开销**

训练结束后所有低秩增量已合并进 $W$，**最终就是一个普通稠密模型**，推理时没有任何旁路、没有额外延迟——这点和 LoRA 合并后一致，优于需要保留旁路结构的部分 Adapter 方法。

## 8. 横向对比：ReLoRA vs LoRA / LoRA-FA / 全参

```
全参      : W 直接训，满秩更新，显存最大(16N)，效果上限最高
   │
LoRA      : 冻W，单次低秩旁路，秩≤r，省显存，主打"微调"
   │  └─ LoRA-FA: 再冻A只训B，进一步省"激活"显存(见 [[llm-peft/LoRA-FA]])
   │
ReLoRA    : 冻W，多次低秩旁路+合并+重置，总秩≤kr，省显存，能"预训练"
```

| 维度 | 全参 | LoRA | LoRA-FA | **ReLoRA** |
| --- | --- | --- | --- | --- |
| 可训参数 | $d^2$ | $2dr$ | $dr$（只训 $B$） | $2dr$（每段） |
| 总更新秩 | 满秩 $d$ | $\le r$ | $\le r$ | $\le kr$（叠加） |
| 主要省的资源 | — | 优化器+梯度显存 | 再省**激活**显存 | 优化器+梯度显存 |
| 典型用途 | 预训练/全微调 | 下游微调 | 下游微调(更省) | **省显存预训练**/大改 |
| 关键独有机制 | — | 低秩旁路 | 冻 $A$ | **合并+优化器重置+锯齿 lr** |
| 推理额外开销 | 无 | 合并后无 | 合并后无 | 合并后无 |

> 一句话记忆：**LoRA 让你"微调"得起，LoRA-FA 让你微调时"激活"也省，ReLoRA 让低秩方法第一次够格做"预训练"。** 三者都属 [[llm-peft/README]] 的 LoRA 家族，省显存逻辑同源——核心都是"把昂贵的优化器状态压到极少的可训参数上"（对照 [[llm-train/README]] 的 16N 全参账）。

## 9. 常见问题

| 问题 | 答 |
| --- | --- |
| ReLoRA 和"重复跑很多次 LoRA"有何不同？ | 多了**优化器部分重置**和**锯齿学习率重启**两个强制项。没有它们，各段方向会重合，总秩上不去，退化成普通 LoRA。 |
| 合并会破坏已学到的东西吗？ | 不会。$Wx+BAx=(W+BA)x$ 是恒等式，合并瞬间函数不变，只是把增量"固化"进主权重。 |
| 为什么不一次性用很大的 $r$ 代替多段？ | 大 $r$ 直接抬高了每段的优化器/显存开销，违背省显存初衷；ReLoRA 用"小 $r$ × 多段"在低显存下凑高秩。 |
| 优化器状态为什么"部分"重置而非全清？ | 全清每段冷启动不稳；全留旧惯性绑架新方向。大比例清空+留少量是稳定性与"探索新方向"的折中。 |
| 锯齿学习率能省吗？ | 不建议。合并+重置后 $B=0$、动量被清，等于小冷启动，必须 warmup，否则要么学不动要么震荡。 |
| 周期长度 $T$ 怎么选？ | 太短每段没学透、合并过频；太长退化成几次 LoRA、秩不够。需按数据量/总步数调，属关键超参。 |
| 推理时有额外延迟吗？ | 没有。训完所有增量已合并，最终是普通稠密模型。 |
| 它能完全替代全参预训练吗？ | 是"省显存的近似"，在相同算力/数据下通常仍略逊全参，但在显存受限时是高性价比方案。**具体配方/超参以官方实现为准**。 |
