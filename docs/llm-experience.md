## 0. 一句话锚点

- **微调**：不是把模型推到一个"新的数据分布"，而是**用极少量参数，把模型本就具备的表征能力"激发/对齐"到你的任务上**。
- **量化**：把权重/激活从 FP16（16 bit）压到 INT8/INT4（8/4 bit），用**更少的比特表达近似相同的数值**，省显存、提带宽利用率；难点是**离群值（outlier）**会撑大量化区间导致掉点。

```
          能力来源                       工程手段
   ┌──────────────────┐          ┌──────────────────────┐
   │  预训练（万亿token）│  ──激发──▶│  微调 PEFT (改 <1% 参数)│
   │  ⇒ 通用表征/世界知识│          └──────────────────────┘
   └──────────────────┘                     │
            │                               │ 部署
            ▼                               ▼
   ┌──────────────────┐          ┌──────────────────────┐
   │  FP16 权重 (大显存) │  ──压缩──▶│  量化 INT8/INT4 (省显存)│
   └──────────────────┘          └──────────────────────┘
```

## 1. 地基：表征能力 vs 数据分布

一个关键经验（也是本文的"锚句"）：

> **微调的过程不是让模型适应另外的数据分布，而是让模型更好地激发出本身的表征能力。**

为什么这么说？把语言模型看成一个巨大的**函数 $f_\theta$**，预训练已经在 $\theta$ 里"长出"了语法、事实、推理链路等子能力。微调要做的，是在**已有表征空间里挑一条通往目标行为的路径**，而不是重建这个空间。

```
预训练学到的表征空间（高维，已铺满"能力子区域"）
   ┌───────────────────────────────────────┐
   │   ·翻译   ·代码   ·数学   ·对话   ·摘要   │
   │        ╲        │        ╱              │
   │         ╲   微调只是把"门"打开/指路        │
   │          ▼      ▼      ▼                │
   │       任务A     任务B    任务C            │
   └───────────────────────────────────────┘
   微调 = 在既有空间里"激发+对齐"，不是"重铺空间"
```

推论（重要）：
- 任务越**贴近预训练分布**（同语言、同领域、常见格式）→ 微调越省、越稳、PEFT 足矣。
- 任务越**远离预训练分布**（跨语言、专有符号体系、全新模态/格式）→ 表征里"没有现成的门"，只调极少参数**激发不出来**，这时 PEFT 会失效（见 §4）。

## 2. PEFT 全景：每种方法"动哪一块"

PEFT（Parameter-Efficient Fine-Tuning）的共同思路：**冻结绝大部分预训练权重，只训练一小撮新增/旁路参数**。区别在于"插在 Transformer 的哪个位置"。

```
            一个 Transformer Block 的注入点
   x ──▶[ +Prefix/Prompt 拼到输入 ]──▶ ┌─────────────┐
                                       │  Self-Attn  │◀── LoRA 注入 ΔW 到 W_q,W_v
                                       └─────┬───────┘
                                             ▼
                                    [ +Adapter 串在子层后 ]
                                             ▼
                                       ┌─────────────┐
                                       │   FFN/MLP   │◀── LoRA 也可注入到 MLP
                                       └─────┬───────┘
                                             ▼
                                          输出 h
```

| 方法 | 注入位置 | 训练参数量级 | 一句话本质 |
|------|---------|------------|-----------|
| Prompt-Tuning | 输入端拼可学 soft token | 极小 | 学一段"虚拟提示词" |
| Prefix-Tuning | 每层 KV 前拼可学前缀 | 小 | 给每层 attention 一个可学上下文 |
| Adapter | 子层后串小瓶颈 MLP | 中 | 串行加一个降维-升维残差模块 |
| **LoRA** | 旁路并联低秩 $BA$ 到 $W$ | 小 | **用低秩矩阵近似权重增量 ΔW** |

> 细节：Prompt/Prefix 见 [[llm-train/peft/Prompt-Tuning]]、[[llm-train/peft/Prefix-Tuning]]；下面重点拆 LoRA（工程上最常用）。

## 3. LoRA 原理 + 显存手算

### 3.1 核心假设：权重增量是低秩的

全量微调学的是 $W \leftarrow W + \Delta W$，其中 $W \in \mathbb{R}^{d\times k}$。LoRA 假设 $\Delta W$ **本征秩很低**，于是用两个瘦矩阵相乘来表示：

$$\Delta W = \frac{\alpha}{r}\, B A,\quad B\in\mathbb{R}^{d\times r},\; A\in\mathbb{R}^{r\times k},\; r\ll \min(d,k)$$

前向变成：

$$h = Wx + \Delta W x = Wx + \frac{\alpha}{r}\,B(Ax)$$

```
        x
        │
   ┌────┴─────┐
   │          │  旁路(可训练)
   ▼          ▼
 [ W ]      [ A ] r×k   ← 先降维到 r
 冻结        │
   │         ▼
   │       [ B ] d×r   ← 再升维回 d
   │         │  ×(α/r)
   └────►(+)◄┘
        │
        ▼  h = Wx + (α/r)·B·A·x
```

- 初始化：$A\sim\mathcal N(0,\sigma^2)$，$B=0$ ⇒ 训练开始时 $\Delta W=0$，**不破坏预训练权重**（关键！保证起点等于原模型）。
- $\alpha/r$ 是缩放因子，解耦"学习率敏感度"与 rank。

### 3.2 为什么省：参数量对比（手算）

设 $d=k=4096$（典型 7B 模型隐藏维），一个权重矩阵全量参数：

$$d\times k = 4096\times4096 = 16{,}777{,}216 \approx 1.68\times10^7$$

LoRA（取 $r=8$）：

$$d\times r + r\times k = 4096\times8 + 8\times4096 = 32{,}768 + 32{,}768 = 65{,}536$$

压缩比：$\dfrac{65{,}536}{16{,}777{,}216}\approx 0.39\%$ —— **只训练 0.39% 的参数**。

### 3.3 为什么省**显存**：优化器状态才是大头

训练显存 ≈ 参数 + 梯度 + 优化器状态（Adam 要存一阶 m、二阶 v）。**冻结权重没有梯度、没有优化器状态**，省的不只是权重本身。

以一个 4096×4096 层、FP16 权重 + Adam(FP32 状态) 估算"可训练部分"显存：

| 项 | 全量微调 | LoRA(r=8) |
|----|---------|-----------|
| 权重(冻结/FP16) | 33.6 MB（要算梯度） | 33.6 MB（冻结，无梯度） |
| 梯度(FP16) | 33.6 MB | 0.13 MB |
| Adam m+v(FP32×2) | 134 MB | 0.5 MB |
| **可训练开销合计** | **≈201 MB/层** | **≈0.63 MB/层** |

> 单层就省 ~300×。这正是"用一张 24G 卡微调 7B"成为可能的原因。完整训练显存账见 [[transformer内存估算]] 与 [[llm-train/README]]。

### 3.4 推理零开销：合并回原权重

部署时把旁路**合并**：$W' = W + \frac{\alpha}{r}BA$，得到一个和原模型同形状的权重，**推理时不增加任何延迟/显存**。这是 LoRA 相对 Adapter（串行、增延迟）的工程优势。

## 4. LoRA 的局限（核心实践经验）

> **PEFT 总是有局限性**，基于低秩的微调**并不 always work**。典型失效场景：**finetune 与 pretrain 的 gap 过大**，比如中英差异（跨语言迁移）。

### 4.1 为什么 gap 大就失效——从秩的角度

LoRA 的容量上限被 $r$ 卡死：$\text{rank}(\Delta W)\le r$。如果任务要求的真实权重改变是**高秩的**（需要重塑大量方向），低秩近似就"装不下"。

```
  需要的 ΔW 真实秩
   小 ┃                           大
      ┃  ●LoRA 够用                ✗LoRA 不够
      ┃  (同语言/同领域微调)        (跨语言/全新符号体系)
      ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━▶
  pretrain↔finetune 分布 gap
```

- **中→英 / 英→中**：词表激活模式、子词切分、语序都和预训练主分布差异大，"门"在表征空间里很弱甚至没有，低秩旁路激发不出来。
- **专有符号体系**（如全新 DSL、罕见领域术语）：预训练几乎没见过，表征里没有对应子区域 ⇒ 需要的改变是高秩的。

### 4.2 经验判据与对策

| 现象 | 诊断 | 对策 |
|------|------|------|
| LoRA loss 下不去、验证不涨 | gap 太大 / rank 太小 | ↑ rank；扩大注入层（不止 q,v，加 k,o,MLP）；继续做"二次预训练"(继续 pretrain) 缩小 gap |
| 学会格式但知识错 | 数据是"激发"不了的新知识 | 先增量预训练注入知识，再 PEFT 对齐格式 |
| 灾难性遗忘 | 数据太窄、lr 太大 | 混入通用数据；↓ lr；↓ epoch |

一句话经验：**当 gap 大到"激发不出来"时，正确顺序是"先继续预训练补表征，再 PEFT 对齐"，而不是硬调 LoRA。**

## 5. 微调调参经验清单

```
   数据(质量>数量) ──▶ 选注入层 ──▶ 定 r/α ──▶ 定 lr/epoch ──▶ 防遗忘
```

| 旋钮 | 经验起点 | 调整方向 |
|------|---------|---------|
| rank $r$ | 8 / 16 | 任务难、gap 大 → 32/64 |
| $\alpha$ | $2r$（即 α/r=2） | 想更"激进"学习 → ↑α |
| 注入层 | q,v | 不够 → 加 k,o,gate,up,down(全 linear) |
| 学习率 | 1e-4 ~ 3e-4 | 比全量微调可大一个量级 |
| epoch | 1~3 | 小数据易过拟合，宁少勿多 |
| dropout | 0.05~0.1 | 过拟合 → ↑ |

> 数据是第一生产力：**几百条高质量样本 > 几万条噪声样本**。微调"激发"的前提是样本能清晰指出"该走哪条已有路径"。

## 6. 量化地基：定点表示与 scale/zero-point

量化 = 把浮点 $x$ 映射到低比特整数 $q$。**对称量化**（常用于权重，分布近似零均值）：

$$q = \text{round}\!\left(\frac{x}{s}\right),\quad s=\frac{\max|x|}{2^{b-1}-1},\quad \hat x = s\cdot q$$

**非对称量化**（常用于激活，分布偏向一侧）：

$$s=\frac{x_{\max}-x_{\min}}{2^b-1},\quad z=\text{round}\!\left(-\frac{x_{\min}}{s}\right),\quad q=\text{round}\!\left(\frac{x}{s}\right)+z$$

```
 FP16 实数轴            INT8 网格(256格)
  ──┼────┼────┼──   ⇒   0  1  2 ... 255
   xmin   0   xmax        每格宽度 = s(scale)
  量化=把实数"吸附"到最近格点；反量化=格点×s 还原
```

误差来源：**舍入误差**（round 到最近格点，最大 $s/2$）+ **截断误差**（超出 $[x_{\min},x_{\max}]$ 被 clip）。格子越少（比特越低）→ $s$ 越大 → 误差越大。

> 数据类型/对称非对称细节见 [[llm-compression/quantization/量化基础]]；FP8 这种"浮点低精度"见 [[llm-compression/quantization/fp8]] 与 [[机器学习中常用的数据类型]]。

## 7. PTQ 与离群值：为什么 LLM 量化比 CNN 难

PTQ（Post-Training Quantization，训练后量化）不重训，直接拿少量校准数据统计 scale。LLM 上的核心难题：**激活离群值（activation outliers）**。

```
   普通通道激活分布            含离群值的激活分布
   |▁▂▅█▅▂▁|                |▁▂▅█▅▂▁ ............ ●|
   范围小，s 小，量化细        几个离群值把范围撑爆 ⇒ s 巨大
                              ⇒ 99% 的正常值挤进极少格点 ⇒ 掉点
```

直觉手算：若 99% 的值落在 $[-1,1]$，但有个离群值 $=60$，对称 INT8（127 格点）：

$$s=\frac{60}{127}\approx0.47$$

那么 $[-1,1]$ 内的值只能用约 $\frac{1}{0.47}\approx 2$ 个格点表示 ⇒ **几乎全被压成 0/±1，信息全丢**。

主流对策（机制层面）：
- **逐通道 / 逐组量化（per-channel / per-group）**：每个通道单独算 scale，隔离离群通道的影响。
- **混合精度保离群**（如 LLM.int8()）：把离群通道留 FP16，其余走 INT8。
- **平滑迁移**（如 SmoothQuant）：把激活的"难"按比例搬到权重上，让两边都好量化。
- **GPTQ/AWQ**：用二阶信息或激活感知，逐列/逐通道最优化舍入，4bit 也能稳。

| 量化粒度 | scale 数量 | 精度 | 开销 |
|---------|-----------|------|------|
| per-tensor | 1 | 低 | 最省 |
| per-channel | 每列 1 个 | 高 | 中 |
| per-group(如128) | 每组 1 个 | 最高 | 略大 |

## 8. QLoRA：量化 + 微调合体

QLoRA = **把基座权重量化到 4bit 冻结，只训练 FP16 的 LoRA 旁路**。让"在一张消费级卡上微调 65B"成为可能。三件套机制：

```
   基座权重 ──NF4 4bit量化──▶ [冻结, 4bit 存储]
        │ 反量化(临时,逐块)
        ▼
   前向计算 h = dequant(W)·x + (α/r)·B·A·x
                                  └─ LoRA 旁路(FP16, 可训练, 有梯度)
```

1. **NF4（4-bit NormalFloat）**：针对"权重近似正态分布"设计的非均匀量化格点，格点按正态分位数排布，比普通 INT4 更贴合权重分布。
2. **双重量化（Double Quantization）**：连"量化用的 scale 常数"也再量化一次，进一步省内存（每参数再省 ~0.4 bit）。
3. **分页优化器（Paged Optimizer）**：用 NVIDIA 统一内存，显存峰值溢出时把优化器状态分页到 CPU，避免 OOM。

关键点：**梯度只流向 LoRA 旁路**；4bit 基座只在前向被"临时反量化"参与矩阵乘，不存梯度、不存优化器状态 ⇒ 省显存的根在这里（同 §3.3 的逻辑）。

## 9. 数值手算合集

### 9.1 LoRA 可训练参数占比（7B 量级）

注入 q,v 两个 4096×4096 层、共 32 个 Transformer 层、$r=8$：

$$\underbrace{2}_{q,v}\times \underbrace{32}_{\text{层}}\times \underbrace{(4096\cdot8+8\cdot4096)}_{65{,}536}=4{,}194{,}304\approx4.2\text{M}$$

占 7B 的比例：$\dfrac{4.2\times10^6}{7\times10^9}\approx 0.06\%$。只训练万分之六的参数。

### 9.2 量化掉点的"格点饥饿"手算

无离群值，正常值范围 $[-4,4]$，对称 INT8：$s=4/127\approx0.0315$，可分辨步长 0.03，精细。
有离群值把范围撑到 $[-60,60]$：$s=60/127\approx0.47$，步长变 0.47 ⇒ 分辨率劣化 **15 倍** ⇒ 这就是必须隔离离群值的量化账。

### 9.3 QLoRA 基座显存（65B）

FP16 基座：$65\times10^9 \times 2\,\text{B} = 130\,\text{GB}$（单卡放不下）。
NF4 4bit 基座：$65\times10^9 \times 0.5\,\text{B} = 32.5\,\text{GB}$ ＋ LoRA/激活/优化器若干 ⇒ **可塞进一张 48G/80G 卡**。压缩比正好 4×（16bit→4bit）。

### 9.4 INT8 推理带宽收益（直觉）

LLM 解码是**访存瓶颈**（每生成 1 token 要把全部权重读一遍）。权重 FP16→INT8，单 token 需读的字节数减半 ⇒ 理论带宽受限吞吐 ~2×。这也是量化对**推理**最直接的收益（解码访存模型见 [[llm-inference/KV-Cache优化]]、[[llm-optimizer/kv-cache]]）。

## 常见问题

| 问题 | 答案 |
|------|------|
| LoRA 一定比全量微调差吗？ | 同分布任务上常接近；gap 大的高秩任务上明显差（§4）。 |
| α 调大等于学习率调大吗？ | 等效缩放 $\Delta W$ 幅度，方向上类似，但解耦了 rank 的影响。 |
| 该注入哪些层？ | 起步 q,v；不够就加到全部 linear（k,o + MLP 的 gate/up/down）。 |
| 跨语言（中↔英）LoRA 老学不会？ | 典型 gap 过大，先继续预训练补表征，再 PEFT（§4.2）。 |
| 量化为什么 LLM 比 CNN 难？ | 激活离群值撑爆量化区间（§7），需 per-channel / 混合精度 / 平滑。 |
| INT4 一定掉点很多吗？ | 朴素 INT4 会；GPTQ/AWQ/NF4 等激活/分布感知方法可把掉点压到很小。 |
| QLoRA 训出来的精度算 4bit 吗？ | 训练时 LoRA 是 FP16；部署可合并后再整体量化，按需选精度。 |
| 量化对训练和推理收益一样吗？ | 推理收益最大（访存减半≈吞吐翻倍）；训练主要靠 QLoRA 省显存。 |
| 工具/框架的具体参数默认值？ | 各框架不同且会变，**以官方文档为准**，本文只讲稳定机制。 |
