## 0. 一句话锚点

金融大模型 = 通用底座 + 金融知识注入 + 时效性数据管道 + 合规对齐。可以写成一条"能力等式"：

$$\text{FinLLM} = \underbrace{f_\theta}_{\text{通用底座}} \;\xrightarrow{\;\text{CPT}\;}\; \underbrace{f_{\theta'}}_{\text{懂金融语料}} \;\xrightarrow{\;\text{SFT}\;}\; \underbrace{f_{\theta''}}_{\text{会做金融任务}} \;\xrightarrow{\;\text{RLHF/DPO}\;}\; \underbrace{f_{\theta'''}}_{\text{安全合规}}$$

- **CPT**（Continue PreTrain，继续预训练）：灌入财报、研报、技术标准，让模型"读过金融的书"。
- **SFT**（监督微调）：教会"情绪分析 / 摘要 / 抽取 / 问答"这些具体任务格式。
- **对齐**：让输出不乱给投资建议、不编造数字、符合监管口径。

```
通用 LLM ──知识不够──> 金融问题答非所问 / 编造财报数字
   │
   ├─(A) 从头预训练(BloombergGPT)  ── 贵、强、数据要海量
   ├─(B) 继续预训练 + SFT(轩辕/国产) ── 性价比主流
   ├─(C) 仅 LoRA-SFT(FinGPT)        ── 最省、可频繁更新
   └─(D) RAG 检索增强               ── 不改权重、解决时效与可溯源
```

## 1. 地基：金融数据为什么"难"

通用 LLM 直接上金融场景，会踩三个坑。理解这三点，后面所有设计都顺理成章。

**特性一：时间敏感（Time-sensitive）。** 一条"美联储加息"新闻，10 分钟后价值衰减大半。模型权重是"冻结的过去"，无法知道今天的行情 → 需要**实时数据管道**或 **RAG**。

**特性二：低信噪比（Low signal-to-noise）。** 金融文本里真正影响价格的信息密度极低，大量是噪声（重复公告、模板化措辞）。

**特性三：高专业度 + 高合规性。** "久期""对冲""LPR""可转债强赎"等术语，错一个数字可能造成真金白银损失；且投资建议受监管。

```
通用文本世界                金融文本世界
┌──────────────┐          ┌──────────────┐
│ 信噪比 高     │          │ 信噪比 低 ▼   │  → 需要更强的数据清洗/去重
│ 时效 弱       │          │ 时效 极强 ▲   │  → 需要实时管道/RAG
│ 容错 高       │          │ 容错 极低 ✗   │  → 需要数值不可幻觉 + 合规对齐
└──────────────┘          └──────────────┘
```

> 数据质量结论（与 [[llm-summarize/领域大模型]] 一致）：**领域技术标准文档、财报、研报是 CPT 的关键**——质量高、知识密度大、领域强相关。

## 2. 四种"造模"路线与决策树

| 路线 | 代表 | 改权重? | 成本 | 适用 |
|------|------|---------|------|------|
| A 从头预训练 | BloombergGPT | 全部 | 极高（百万美元级） | 数据+算力都海量，要最强底座 |
| B 继续预训练+SFT | 轩辕、ChatHome | 全部/部分 | 高 | 有领域语料，要深度注入知识 |
| C 仅 LoRA-SFT | FinGPT | <1% | 低 | 任务明确、要频繁更新 |
| D RAG 检索增强 | 各家"金融助手" | 0 | 低 | 时效强、要可溯源、防幻觉 |

```
要不要改模型权重?
        │
   ┌────┴────┐
  否          是
   │           │
  RAG(D)   有海量预训练数据+算力?
            ┌───┴───┐
           是        否
            │         │
       从头训(A)   有领域语料要灌知识?
                    ┌───┴───┐
                   是        否
                    │         │
                 CPT+SFT(B)  仅SFT
                            ┌─┴─┐
                          资源少 资源多
                            │     │
                        Chat上(C) Base上
```

> 资源决策（沿用领域模型经验）：**资源有限（数据少+卡少）→ 在 Chat 模型上 LoRA 微调；资源充足 → 在 Base 模型上训练。** 在 Chat 上 SFT 务必遵循其原有系统指令与输入格式，且不建议全参，否则原能力遗忘严重。

## 3. 数据：分层与配比

金融语料典型分层（FinGPT 的 FinLLM 全栈框架，自下而上四层）：

```
┌─────────────────────────────────────────┐
│ 应用层  情绪分析/研报摘要/问答/量化信号    │ ← Demo & 落地
├─────────────────────────────────────────┤
│ LLMs层  LoRA等微调，应对金融高动态性       │ ← 模型
├─────────────────────────────────────────┤
│ 数据工程层  实时NLP清洗，治低信噪比/高时效  │ ← 管道
├─────────────────────────────────────────┤
│ 数据源层  新闻/公告/财报/社媒/行情，实时捕获 │ ← 原料
└─────────────────────────────────────────┘
```

**领域:通用 配比**——CPT 的核心超参，决定"专业度 vs 灾难性遗忘"的平衡：

| 方案 | 领域:通用 | 来源 |
|------|-----------|------|
| BloombergGPT（从头） | ≈ 1:1（金融 363B : 通用 345B token） | 论文 |
| ChatHome（继续预训练） | 1:5 最优 | 论文 |
| 经验法则（数据量小时） | 1:5 ~ 1:10 | 社区共识 |

> 直觉：**领域数据越少，越要掺更多通用数据"稀释"，防止模型过拟合领域、遗忘通用能力。** 还可在 CPT 阶段同步加入 SFT 数据（MIP，Multi-Task Instruction PreTraining），让模型预训练就学到任务知识。

```
领域占比 ↑  ──> 专业度 ↑ 但 通用能力遗忘 ↑（灾难性遗忘）
   ◄─────────── 甜点区(数据少时1:5~1:10) ───────────►
领域占比 ↓  ──> 通用能力保留 但 没学到金融知识
```

## 4. BloombergGPT 拆解（路线 A 的标杆）

**定位**：彭博 2023 年发布，**从头预训练**的 50B 参数金融专用 LLM。亮点是用了彭博 40 年专有金融数据（FinPile）+ 通用数据，约 1:1 混合。

**关键配置（用于手算）**：
- 参数量 $P \approx 50\text{B} = 5\times10^{10}$
- 训练 token 数 $D \approx 569\text{B} \approx 5.69\times10^{11}$（金融 363B + 通用 345B 去重后）
- 架构：BLOOM 风格 Decoder-only（详见 [[llm-algo/transformer/模型架构]]）

**训练 FLOPs 手算**（经典近似 $C \approx 6PD$，推导见 [[llm-algo/FLOPs]]）：

$$C \approx 6 \times P \times D = 6 \times 5\times10^{10} \times 5.69\times10^{11} \approx 1.71\times10^{23}\ \text{FLOPs}$$

折算成 A100（BF16 峰值 $\approx 312$ TFLOP/s，按 MFU=40% 实际利用）所需卡时：

$$\text{有效算力} = 312\times10^{12} \times 0.40 \approx 1.25\times10^{14}\ \text{FLOP/s}$$
$$t = \frac{1.71\times10^{23}}{1.25\times10^{14}} \approx 1.37\times10^{9}\ \text{s} \approx 3.8\times10^{5}\ \text{卡时} \approx 16{,}000\ \text{卡·天}$$

```
单卡跑完 ≈ 16000 天(43年) ──不可能──> 必须并行
512 张 A100:  16000 / 512 ≈ 31 天   ✓ 接近论文公开的训练周期量级
```

> 这就是"从头预训练"为什么贵：**$1.7\times10^{23}$ FLOPs 是 FinGPT-LoRA 路线的成百上千倍**。所以多数团队选路线 B/C。

## 5. FinGPT 拆解（路线 C：LoRA 全栈，最省）

**定位**：AI4Finance 开源，强调**数据民主化 + 轻量微调 + 频繁更新**。不重训底座，只在开源底座上做 **LoRA** 微调（LoRA 原理见 [[llm-train/peft/Prompt-Tuning]] 与 PEFT 家族）。

**版本谱系**：

| 版本 | 底座 | 市场/语言 | 方法 |
|------|------|-----------|------|
| FinGPT v1 | ChatGLM | 中国市场 | LoRA |
| FinGPT v2 | LLaMA | 美国市场 | LoRA |
| FinGPT v3.1 | ChatGLM2-6B | 情绪分析 | LoRA |
| FinGPT v3.2 | LLaMA2-7B | 情绪分析 | LoRA |

v3 系列在新闻+微博情绪数据上用 LoRA 微调，在多数金融情绪基准上取得 SOTA。

**LoRA 可训练参数手算**——这是 FinGPT 省钱的核心。LoRA 把权重更新 $\Delta W \in \mathbb{R}^{d\times k}$ 分解为低秩 $\Delta W = BA$，$B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times k}$：

```
原权重 W (冻结)          LoRA 旁路 (可训练)
┌──────────┐           ┌──┐   ┌──────────┐
│  d × k   │     +     │d×r│ × │  r × k   │   r ≪ d,k
│ (冻结❄)  │           └──┘   └──────────┘
└──────────┘            B          A
```

以 LLaMA2-7B 为例，$d=k=4096$，秩 $r=8$，只对 $q,v$ 两个投影加 LoRA，共 32 层：

- 单个 LoRA 模块参数：$r\times(d+k) = 8\times(4096+4096) = 65{,}536$
- 每层 2 个（q、v）：$2\times65{,}536 = 131{,}072$
- 32 层：$32\times131{,}072 \approx 4.19\times10^{6} \approx 4.2\text{M}$

占全模型比例：

$$\frac{4.2\times10^{6}}{7\times10^{9}} \approx 0.06\%$$

> **只训 0.06% 的参数**，就能让 7B 模型适配金融情绪任务——这就是"个人/机构可民主化、可频繁更新"的算力基础。

## 6. 轩辕 2.0 与国产金融模型（路线 B 主流）

**轩辕（XuanYuan）2.0**：度小满发布的中文金融对话大模型，基于 BLOOM-176B 路线，采用**混合微调（Hybrid-tuning）**——把通用对话数据与金融领域数据混合，在一个训练阶段同时做"通用指令 + 金融指令"，缓解灾难性遗忘。

```
传统两阶段           轩辕 Hybrid-tuning
通用SFT → 金融SFT     [通用 + 金融] 一起SFT
   ↑遗忘通用            ↑同批混合,遗忘更轻
```

**国产金融 LLM 的典型落地链路**（路线 B）：

```
中文通用底座(Qwen/ChatGLM/Baichuan)
        │ CPT: 财报+研报+公告+监管文件  (领域:通用 ≈ 1:5)
        ▼
  金融知识底座
        │ SFT: 情绪/摘要/合规问答/事件抽取  (+MIP)
        ▼
  金融指令模型
        │ RLHF/DPO: 安全合规、不乱给投资建议
        ▼
  可上线金融助手  ──挂──> RAG(实时行情/最新公告) ──> 用户
```

> 词表扩增的取舍：金融领域词表扩充主要解决**解码效率**（专业术语少切几个 token），对效果提升有限（同语言扩词表场景）。

## 7. 微调显存账（LoRA vs 全参，逐项相加）

以 **7B 模型、Adam 优化器、BF16 混合精度** 为例。显存四大件（详见 [[llm-train/README]]）：

| 项 | 全参微调 | LoRA 微调 |
|----|----------|-----------|
| 参数（权重，BF16，2B/参数） | $7\text{B}\times2 = 14$ GB | $14$ GB（冻结，仍要存） |
| 梯度（2B/参数） | $7\text{B}\times2 = 14$ GB | 仅 4.2M：$\approx 0.008$ GB |
| Adam 优化器状态（m,v，FP32，8B/参数） | $7\text{B}\times8 = 56$ GB | 仅 4.2M：$\approx 0.034$ GB |
| 激活值（与 batch/seq 有关，粗估） | ~10–20 GB | ~10–20 GB |
| **静态合计（不含激活）** | **84 GB** | **≈ 14 GB** |

```
全参微调静态显存:   ████████████████████████  84 GB  → 单张80G放不下,要张量并行
LoRA  微调静态显存:  ████                       14 GB  → 单卡轻松,这就是FinGPT能跑的原因
```

**为什么差这么多？** 全参的梯度(14G)+优化器(56G)=70G 全省了，因为 LoRA 只对 4.2M 旁路参数求梯度、存优化器状态。**省下的 70GB ≈ 一整张 A100。**

> 进一步省：把冻结底座做 4-bit 量化（QLoRA），$14\text{GB}\to\approx 4\text{GB}$，加上 LoRA 旁路，7B 微调可塞进单张消费级 24G 卡。量化原理见 [[llm-compression/quantization/量化基础]]。

## 8. 推理成本（KV-Cache + 量化）

金融助手要长上下文（贴一整份财报）→ **KV-Cache 是显存大头**（原理见 [[llm-inference/KV-Cache优化]]）。

**KV-Cache 显存公式**：

$$M_{kv} = 2 \times L \times n_{layer} \times d_{model} \times b_{dtype} \times \text{batch}$$

以 7B（$n_{layer}=32, d_{model}=4096$）、序列长 $L=8192$、BF16（$b=2$ 字节）、batch=1：

$$M_{kv} = 2 \times 8192 \times 32 \times 4096 \times 2 \times 1 \approx 8.6\times10^{9}\ \text{Byte} \approx 8\ \text{GB}$$

```
推理显存 = 权重(14G) + KV-Cache(8G) + 其余 ≈ 22+ GB  (单请求,8K上下文)
batch=8 时 KV-Cache → 64GB,直接爆 → 必须 PagedAttention/量化KV
```

**量化省多少**（权重 INT8）：

$$14\text{GB} \xrightarrow{\text{INT8}} 7\text{GB},\quad \text{省 50\%}\ \Rightarrow\ 单卡可塞下更长上下文或更大 batch$$

> 金融场景长上下文 + 高并发 → KV-Cache 优化（PagedAttention、量化 KV、解码策略）是降本关键，见 [[llm-inference/解码策略]]。

## 9. 评测与风控护栏

金融的"低容错"决定了评测必须双轨，且要有合规护栏。

```
模型输出 ─┬─> [事实层] 数字是否编造? ──RAG溯源/工具计算──> 拒绝幻觉
          ├─> [合规层] 是否乱给投资建议? ──对齐+规则过滤──> 加免责声明
          └─> [时效层] 是否用了过期数据? ──RAG接实时源──> 标注数据时间
```

**评测集建议两份**（沿用领域模型经验）：
- **选择题形式**（金融知识/CFA 题库）→ 自动评测，方便初筛 checkpoint。
- **开放问答 + 人工**（研报摘要质量、情绪判断）→ 精筛，贴近真实场景。

| 风险 | 表现 | 缓解 |
|------|------|------|
| 数值幻觉 | 编造营收/PE | 数字交给工具/RAG，不让模型"心算" |
| 时效失真 | 报旧行情 | RAG 接实时数据源，标注时间戳 |
| 合规越界 | 直接荐股 | 对齐 + 规则层 + 免责声明 |
| 灾难性遗忘 | 通用能力崩 | CPT 掺通用数据（1:5~1:10）+ Hybrid-tuning |

## 10. 数值手算合集（一次算透）

把全文关键数字串起来，建立量级直觉。

**① 从头预训练 FLOPs（BloombergGPT，§4）**
$$C = 6PD = 6\times5\times10^{10}\times5.69\times10^{11} \approx 1.71\times10^{23}\ \text{FLOPs}$$
$$\Rightarrow\ \approx 512\ \text{A100} \times 31\ \text{天}\quad(\text{MFU}=40\%)$$

**② LoRA 可训练参数（FinGPT-7B，r=8，q/v，§5）**
$$32\times2\times r(d+k) = 32\times2\times8\times8192 \approx 4.2\text{M}\ (\,0.06\%\,)$$

**③ 全参 vs LoRA 静态显存（7B，Adam，§7）**
$$\text{全参} = 14+14+56 = 84\ \text{GB};\quad \text{LoRA} \approx 14\ \text{GB}\ (\text{省}\ 70\ \text{GB})$$

**④ KV-Cache（7B，8K，BF16，batch=1，§8）**
$$M_{kv} = 2\times8192\times32\times4096\times2 \approx 8\ \text{GB}$$

```
量级地图(7B 模型):
从头预训练 FLOPs    1.7e23   ████████████████████████  天文级
LoRA-SFT  FLOPs    ~1e18    ▏                          十万分之一量级
全参显存            84 GB    ████████████
LoRA  显存          14 GB    ██
KV-Cache(8K)        8 GB     █
```

**结论**：绝大多数团队的最优解是 **B/C/D 组合**——通用底座 + （LoRA-）SFT 注入金融任务 + RAG 接实时数据；只有彭博这类"数据+算力都顶配"的玩家才走从头预训练（A）。

## 常见问题

| 问题 | 回答 |
|------|------|
| 金融 LLM 一定要从头训吗？ | 否。从头训（BloombergGPT）成本 $\sim10^{23}$ FLOPs，多数团队选 CPT+SFT 或纯 LoRA-SFT + RAG。 |
| 领域:通用 配多少？ | 数据多时可 1:1（BloombergGPT）；数据少时 1:5~1:10 防遗忘；ChatHome 实测 1:5 最优。 |
| 时效问题怎么解？ | 权重是冻结的过去，靠 RAG 接实时行情/公告，并标注数据时间戳。 |
| 为什么 FinGPT 用 LoRA？ | 只训 ~0.06% 参数、显存从 84G 降到 14G，可频繁更新、个人也能跑（数据民主化）。 |
| 数值幻觉怎么防？ | 别让模型"心算"金融数字，交给工具/RAG，模型只做语言组织。 |
| 在 Base 还是 Chat 上 SFT？ | 资源少（数据<5k+卡少）→ Chat 上 LoRA 且遵循其输入格式；资源多（数据 10w+）→ Base 上训。 |
| 词表扩增有必要吗？ | 主要提升解码效率（专业术语省 token），对效果提升有限。 |
| 长上下文推理瓶颈？ | KV-Cache（8K≈8GB/请求），用 PagedAttention/量化 KV/合理解码策略降本。 |
