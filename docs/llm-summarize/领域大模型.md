## 0. 一句话锚点

> 做领域大模型的本质：**在一个已经"会说话"的通用模型上，用知识密度最高的领域语料做继续预训练（让它"懂行"），再用领域指令数据做 SFT（让它"听话"），全程靠混入通用数据防止灾难性遗忘，最后用自建的领域评测集挑出最好的 checkpoint。**

四个关键决策，对应本文 4 条主线：

```
        领域语料           防遗忘            训练姿势            质量验收
        (选什么)          (怎么配)          (在哪练)            (怎么测)
          │                 │                 │                 │
     书籍/技术标准      领域:通用配比      Base vs Chat       选择题+开放题
     知识密度高        1:1 ~ 1:10        看资源(数据/卡)    自动筛+人工筛
          │                 │                 │                 │
          └──────────► Continue PreTrain (+MIP) ──► SFT ──► Eval ──┘
```

## 1. 地基 / 前置：四个必须先分清的概念

**① Base 模型 vs Chat 模型。**
- **Base（基座）**：只做过预训练（next-token 预测），没做过指令对齐。会"续写"但不会"对话"。可塑性强，适合大数据量灌注。
- **Chat / Instruct**：在 Base 上做过 SFT + 对齐（RLHF/DPO），已经会按指令回答、遵守对话格式。原始能力已被"调教"过，再训容易破坏。

**② Continue PreTrain（CPT，继续预训练 / 增量预训练）。**
在已有 Base（或 Chat）权重上，继续用 next-token 目标喂**无标注领域语料**。目标是把领域知识"压"进参数里。学习率通常远小于从头预训练（常见 1e-5 ~ 5e-5 量级），且要带 warmup，否则一上来大梯度会冲垮已有能力。

**③ SFT（Supervised Fine-Tuning，指令微调）。**
用 `(指令, 回答)` 成对数据，让模型学会"按要求输出"。CPT 教知识，SFT 教格式与任务能力。

**④ 灾难性遗忘（Catastrophic Forgetting）。**
神经网络在新分布数据上训练时，旧分布上学到的能力会被覆盖。直观理解：参数 $\theta$ 沿领域数据的梯度方向移动，把原来支撑通用能力的"位置"挤走了。

```
通用能力损失景观             只灌领域数据后
   θ*                          θ' (跑偏了)
    \    /  ← 通用最优盆地        \  /     原盆地
     \__/                         \/  ●←现在在这, 通用能力塌了
                              领域数据把 θ 拽出了通用盆地
```

防遗忘的核心手段就是第 3 节的**通用数据混合**——让梯度同时受通用分布约束，把 θ 拉回盆地附近。

## 2. 领域语料选择：技术标准文档 / 领域数据是 Continue PreTrain 的关键

> 原文要点：**领域技术标准文档或领域相关数据是领域模型 Continue PreTrain 的关键。**

现有通用大模型预训练时本就大量使用书籍、论文。做领域 CPT 时，这两类数据**同样必不可少**，原因在于它们同时满足三个"高"：

| 维度 | 书籍 / 技术标准 | 网站 / 新闻 |
|------|----------------|-------------|
| 数据质量 | 高（经过编辑、审校） | 参差（噪声、广告、口水） |
| 领域相关性 | 强相关 | 弱~中 |
| 知识密度（覆盖率） | 大（系统化、成体系） | 稀疏（碎片化） |

**为什么知识密度是关键？** CPT 是用固定的算力预算（token 数）去"填知识"。同样 1B token，书籍/标准里每个 token 携带的领域信息量远高于新闻口水文。可以粗略类比"每 token 的信息熵"：高密度语料让模型在相同步数内吸收更多领域事实，也更"适应考试"（领域评测往往考的就是这些标准化知识）。

> 不是说网站/新闻无用——它们带来时效性与口语表达，是重要补充；只是在"知识密度"这个排序上，**书籍/技术标准 > 论文 > 高质量网站 > 新闻**。

**数值直觉：** 若领域语料只有 3B token，而通用底座见过 ~2T token，领域数据占比不足 0.2%。这正是为什么要靠"高密度 + CPT 反复多 epoch"来放大领域信号，同时（见下节）混通用数据防遗忘。

## 3. 防遗忘：领域数据训练后通用能力会下降，需混入通用数据

> 原文要点：**领域数据训练后，往往通用能力会有所下降，需要混合通用数据以缓解模型遗忘通用能力。**

仅用领域数据训练 → 灾难性遗忘（第 1 节④）。解决办法：CPT 时按比例掺入通用数据。**领域:通用 该配多少？目前没有公认标准答案**，但有可参考的经验点：

| 来源 | 训练方式 | 领域:通用 配比 | 备注 |
|------|---------|---------------|------|
| BloombergGPT | 从头预训练 | ≈ **1:1**（金融:通用） | 从零训，需大量通用打底 |
| ChatHome | 继续预训练(CPT) | **1:5 时最优** | 在已有底座上增量 |
| 经验法则 | CPT | **1:5 ~ 1:10** | 领域数据量不大时较合适 |

**为什么从头训(1:1) 和 CPT(1:5) 配比差这么多？**
- 从头预训练：模型一张白纸，通用能力要现训，所以通用数据得占一半。
- 继续预训练：底座已经"通用很强"，此时通用数据的角色从"教会"退化为"复习防忘"——只需少量复习就能锚住已有能力，于是领域数据可以占大头。

```
配比与两种能力的权衡（示意）

领域能力↑                通用能力↓(遗忘)
   │  ●1:10                 │ ●1:1   稳
   │ ● 1:5  ← 多数人甜点    │  ● 1:5
   │● 1:1                   │   ● 1:10 开始遗忘
   └──────────► 领域占比    └──────────► 领域占比
   领域占比越高，领域涨、通用塌 —— 取交叉点
```

**经验判据：领域数据越少，越要往 1:5~1:10 走**（少量领域数据若不稀释，几个 epoch 就过拟合 + 重度遗忘）。

## 4. MIP：Continue PreTrain 时同步加入 SFT 数据

> 原文要点：**领域模型 Continue PreTrain 时可以同步加入 SFT 数据，即 MIP（Multi-Task Instruction PreTraining，多任务指令预训练）。**

常规流程是 `CPT → 再 SFT` 两段式。MIP 的思路是**在预训练阶段就把下游 SFT 数据（带指令的多任务数据）混进去**，让模型在"学知识"的同时就"学任务"。

```
传统两段式:    [ CPT 无标注语料 ] ──► [ SFT 指令数据 ]
MIP 混合式:    [ CPT 无标注语料 + 指令/多任务数据 ] ──► (可再轻量 SFT)
                         ▲ 预训练阶段就见过任务格式
```

**为什么 MIP 往往更强？** T5、ExT5、GLM-130B 等工作发现：**多任务学习在预训练阶段可能比单独微调更有帮助**——指令数据在大规模无标注语料的"陪伴"下学习，既学到任务能力又不丢通用泛化。ChatHome 实验进一步发现 **MIP 在领域评测集上"绝群"（显著领先）**。

直觉：把"考试题型"提前在预训练里见一遍，模型对题型分布的先验更好，下游 SFT 只需少量数据就能对齐输出格式。

## 5. 仅用 SFT 做领域模型：资源有限用 Chat，资源充足用 Base

> 原文要点：**资源有限就在 Chat 模型基础上训练，资源充足就在 Base 模型上训练。（资源 = 数据 + 显卡）**

这是"在 Base 还是 Chat 上 SFT"的经典抉择，判据非常实用：

| 你的数据量 | 在哪个模型上 SFT | 为什么 |
|-----------|-----------------|--------|
| ~5k 条 | **Chat 模型** | Chat 已具备指令遵循能力，你只需小数据"点拨"，不必从零教会对话 |
| ~10w 条 | **Base 模型** | 数据足够自己把对话能力训出来；不依赖别人 SFT 数据的未知质量 |

**核心逻辑：** "你不知道 Chat 模型在 SFT 时用的数据质量如何——当自己有能力（数据充足）时，靠人不如靠己。"

- 数据少 + 在 Base 上练：教不会对话格式，输出散乱 → 选 Chat 借力。
- 数据多 + 在 Chat 上练：被别人的 SFT 风格"框住"，且可能继承其数据缺陷 → 选 Base 自主可控。

```
            数据量轴
  5k ─────────────────────────── 10w
  │                                │
 [Chat 借力]                   [Base 自主]
 站在巨人肩上                 自己训出全部能力
 (担心其数据质量未知)         (质量自己把控)
```

## 6. 在 Chat 模型上 SFT：必须遵循原 Chat 的系统指令 & 输入格式

> 原文要点：**在 Chat 模型上 SFT 时，请一定遵循 Chat 模型原有的系统指令 & 数据输入格式；建议不采用全量参数训练。**

**为什么格式必须一致？** Chat 模型在对齐阶段学到的是"特定模板下"的行为。这个模板包括角色标记、系统提示、轮次分隔符等。比如（不同模型模板不同，下面只是示意结构）：

```
<|system|>
你是一个金融领域助手。
<|user|>
{用户问题}
<|assistant|>
{模型回答}
```

如果你 SFT 时把数据拼成另一套格式（比如裸文本 `问：… 答：…`），模型会处在"训练分布之外"，原有的指令遵循能力对不上号。**数据量充足时还能硬掰回来；数据量不足时，效果会明显不出来——白练。**

**为什么建议不要全量参数训练（推荐 PEFT，如 LoRA）？**
- 全量微调（更新所有 $\theta$）在小数据上极易**重度遗忘**——Chat 模型辛苦训出来的原始能力被冲掉。
- PEFT（如 LoRA）只在原权重旁加低秩增量 $\Delta W = BA$（$B\in\mathbb{R}^{d\times r}, A\in\mathbb{R}^{r\times d}, r\ll d$），原权重冻结，遗忘风险天然小，显存/存储也省。参见 [[llm-train/peft/PEFT-API]]。

```
全量 SFT:  更新整个 W (d×d 个参数) → 易遗忘、占显存
LoRA SFT:  冻结 W, 只训 B(d×r)+A(r×d) → 原能力保留, r 可取 8/16/32
           输出 = W·x + (B·A)·x·(α/r)
```

## 7. 领域词表扩增：到底有没有必要？

> 原文要点：**领域词表扩增真正解决的是解码效率问题，对效果的提升可能不大。**（这里指"同语言模型上扩词表"，不是英文模型的中文汉化）

**为什么主要影响的是效率而非效果？**
- Tokenizer 把文本切成 token。若某领域高频专有词（如药名、法条号、化学式）被切成很多碎片 token，则同样一句话需要更多 token → 更长序列 → 推理更慢、上下文更"贵"。
- 扩词表把这些高频词收为单 token，**序列变短 → 解码步数变少 → 吞吐/延迟改善**。这是"解码效率"收益。

**数值示例：** 假设领域专有名词原本平均被切成 4 个 token，扩词表后变 1 个 token。一篇 1000 词文档若其中 30% 是专有词：
- 扩前：$700\times1 + 300\times4 = 1900$ token
- 扩后：$700\times1 + 300\times1 = 1000$ token → token 数降约 **47%**，解码步数同比下降。

但**对"答得准不准"提升有限**：知识在参数里，不在词表里；新加 token 的 embedding 还是随机初始化的，需要足够 CPT 才能学好，否则反而可能短期变差。所以——除非解码效率是硬瓶颈，**同语言扩词表通常优先级不高**。（英文模型做中文"汉化"扩词表是另一回事，那是为了根本上的中文表示能力。）

## 8. 领域评测集：必备，建议两份

> 原文要点：**建议有两份——一份选择题形式自动评测、一份开放形式人工评测。**

**为什么一定要自建领域评测集？** 通用 benchmark（MMLU 等）测不出你领域的真实能力；而且你需要它来**在多个 checkpoint 里选最好的那个**（CPT/SFT 过程中会存很多 ckpt）。

| 形式 | 评测方式 | 用途 | 优缺点 |
|------|---------|------|--------|
| 选择题（如 ABCD） | 自动（比对答案/取 logits 最大项） | **初筛**：快速横扫所有 ckpt | 客观、可批量、便宜；但离真实场景远 |
| 开放问答 | 人工打分 | **精筛**：从初筛幸存者里定终选 | 贴近真实使用；但慢、贵、主观 |

```
所有 checkpoint
      │  选择题·自动评测(便宜快)
      ▼
   Top-K 候选     ← 初筛淘汰大多数
      │  开放题·人工评测(贵慢准)
      ▼
   最终模型        ← 精筛定终选
```

漏斗式两段评测：用便宜的自动评测把候选从几十个砍到 Top-3~5，再用昂贵的人工评测在小集合上定胜负。**选择题保证可重复、可比较；开放题保证贴近线上真实任务形式。**

## 实操：把上面策略落成一条流水线

下面把原文经验点编排成可执行顺序（参数为经验量级，按你的数据/卡调整）：

**Step 1 — 备料（第 2 节）**
- 优先级收集：领域**书籍 / 技术标准 > 论文 > 高质量网站 > 新闻**。
- 清洗去重，按知识密度排序。

**Step 2 — Continue PreTrain + MIP（第 3、4 节）**
- 配比：领域:通用 ≈ **1:5**（数据少则 1:5~1:10；从头训才用 1:1）。
- 混入下游**指令/多任务数据（MIP）**一起喂。
- 关键超参（经验量级）：小学习率 + warmup（CPT 典型 lr 比从头训小一个量级），按显存设序列长度与梯度累积。
- 多存 checkpoint 备评测。

**Step 3 — SFT（第 5、6 节）**
- 选底座：**数据 ~5k → 在 Chat 上**；**数据 ~10w → 在 Base 上**。
- 在 Chat 上练：**严格复用该 Chat 的对话模板/系统提示**；**优先 PEFT（LoRA）**，避免全量微调导致遗忘。

**Step 4 —（可选）词表（第 7 节）**
- 仅当**解码效率**是瓶颈时，对高频领域词扩词表；扩后新 embedding 需经 CPT 充分训练。

**Step 5 — 评测选优（第 8 节）**
- 选择题自动评测 → 初筛 Top-K；开放题人工评测 → 精筛定终选 → 选出最佳 ckpt。

## 常见问题 / 坑

| 现象 / 坑 | 根因 | 对策 |
|----------|------|------|
| 领域涨了但通用能力崩 | 只灌领域数据，灾难性遗忘 | 混通用数据，领域:通用 1:5~1:10；从头训用 1:1 |
| 配比拍脑袋导致两头不讨好 | 无公认标准、未按数据量调 | 数据少→更高通用占比；用领域评测集试不同配比 |
| CPT 一上来 loss 爆/能力塌 | 学习率过大、无 warmup | 用远小于从头训的 lr + warmup |
| 小数据在 Base 上 SFT，输出散乱 | Base 不会对话，小数据教不会 | ~5k 数据改在 Chat 上 SFT |
| 在 Chat 上 SFT 没效果 | 没遵循原 Chat 对话模板 | 严格复用系统提示/角色标记/分隔符 |
| 在 Chat 上全量 SFT 后原能力大退 | 全量微调重度遗忘 | 改 PEFT(LoRA)，冻结原权重 |
| 扩了词表效果没涨反而抖 | 新 token embedding 随机初始化未训好 | 扩词表后必须充分 CPT；非效果瓶颈别盲目扩 |
| 选不出最好的 ckpt | 没有自建领域评测集 | 选择题自动初筛 + 开放题人工精筛 |
| MIP 没用上 | 把指令数据全留到 SFT 阶段 | CPT 阶段就混入指令/多任务数据(MIP) |
