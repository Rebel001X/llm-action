## 0. 一句话锚点

> **训练 = 在分布式硬件上，反复地"前向算 loss → 反向算梯度 → 优化器更新参数"，直到模型在数据上表现足够好。** 难点不在"算"，而在**模型和中间结果太大，一张卡装不下、一台机跑不动**——于是有了并行与显存优化这两大主线。

## 1. 地基：一次训练迭代到底在算什么

不假设你记得任何公式。一次迭代（一个 step）做四件事：

```
 ┌─────────┐   forward    ┌─────────┐   loss     ┌──────────┐
 │ 输入数据 │ ───────────► │ 模型前向 │ ────────► │ 计算损失L │
 └─────────┘  (存激活值)   └─────────┘            └────┬─────┘
                                                       │ backward
                                                       ▼
 ┌──────────────┐  optimizer.step  ┌─────────┐   ┌──────────┐
 │ 更新后的参数  │ ◄─────────────── │ 优化器   │◄──│ 反向算梯度 │
 └──────────────┘                  │(Adam等) │   │ ∂L/∂θ    │
                                   └─────────┘   └──────────┘
```

- **前向 (forward)**：把输入逐层算到输出，得到 loss $L$。中间每层的输出（**激活值 activation**）要**存下来**，因为反向要用。
- **反向 (backward)**：用链式法则从 $L$ 倒着算每个参数的梯度 $g=\partial L/\partial \theta$。这一步要读激活值，所以前向才必须存它们。
- **优化器更新**：用梯度更新参数。Adam 不只是 $\theta \leftarrow \theta - \eta g$，它还维护一阶动量 $m$ 和二阶动量 $v$：

$$m \leftarrow \beta_1 m + (1-\beta_1)g,\quad v \leftarrow \beta_2 v + (1-\beta_2)g^2,\quad \theta \leftarrow \theta - \eta\,\frac{\hat m}{\sqrt{\hat v}+\epsilon}$$

**为什么这关系到显存？** 显存里同时住着**四大件**（这是理解一切并行的钥匙）：

| 住户 | 是什么 | 大小（FP16 训练，N=参数量） |
|------|--------|------------------------|
| 参数 (Parameters) | $\theta$ 本身 | 2N 字节 |
| 梯度 (Gradients) | $g=\partial L/\partial\theta$ | 2N 字节 |
| 优化器状态 (Optimizer) | Adam 的 $m,v$ + FP32 主权重 | 12N 字节（4+4+4） |
| 激活值 (Activations) | 前向存下的中间结果 | 随 batch×序列长×层数 变化，**可能比上面三者还大** |

前三项合计 **16N 字节/参数**（混合精度 + Adam 的经典账本）。激活值单独算，是显存优化的主战场。

## 2. 三阶段流程：预训练 → SFT → 对齐

```
  海量无标注文本            少量高质量(指令,回答)        人类偏好(A好于B)
  (网页/书/代码)                  对              ┌──────────┐
       │                          │              │ 偏好数据  │
       ▼                          ▼              └────┬─────┘
 ┌───────────┐  权重   ┌───────────┐  权重   ┌─────────────┐
 │  预训练    │ ──────► │    SFT    │ ──────► │ 对齐 RLHF/DPO │ ──► 可用模型
 │ Pretrain  │ 接着学   │指令微调    │ 接着学   │            │
 └───────────┘         └───────────┘         └─────────────┘
  学"语言+世界知识"      学"听指令、按格式答"     学"答得让人更满意/更安全"
  next-token 预测        next-token(只算回答)    奖励/偏好优化
```

**阶段 1：预训练 (Pretraining)**
- 目标：在海量文本上学**语言规律与世界知识**。任务就一个——**预测下一个 token**（自回归）。损失是交叉熵：$L=-\sum_t \log p_\theta(x_t\mid x_{<t})$。
- 特点：数据量万亿 token 级，算力占整个流程 **>95%**，是分布式并行的主舞台。
- 产物：**base 模型**（会续写、但不一定听指令）。

**阶段 2：SFT (Supervised Fine-Tuning，监督微调)**
- 目标：教模型**听人话、按格式回答**。数据是 `(指令, 理想回答)` 对。
- 机制：仍是 next-token 预测，但 loss **只在"回答"部分计算**（指令部分 mask 掉）。
- 量级：几万~几百万条；可全参微调，也可 **LoRA/QLoRA** 只训低秩增量（详见 [[llm-algo/训练范式]]）。

**阶段 3：对齐 (Alignment)**——让回答"更符合人类偏好/更安全"
- **RLHF** 经典三步：① 训**奖励模型 RM**（学人类"哪个答案更好"）；② 用 **PPO** 让策略模型在 RM 打分下做强化学习；③ 加 KL 惩罚防止跑偏。流程重、需同时跑 4 个模型（actor/critic/RM/ref）。
- **DPO (Direct Preference Optimization)**：跳过 RM 和 RL，直接用偏好对做一个分类式损失，**工程简单很多**，是当前主流轻量方案。
- 概念关系（细节见 [[llm-algo/训练范式]]）：

$$\text{RLHF}=\text{RM}+\text{PPO}+\text{KL}\quad\text{vs}\quad\text{DPO}=\text{一个闭式偏好损失，无需独立 RM}$$

## 3. 为什么单卡装不下：先把账算清

拿 **GPT-3 175B** 直观感受一下（FP16 + Adam，先不算激活）：

$$16N = 16 \times 175\times10^9 = 2.8\times10^{12}\ \text{字节} \approx 2800\ \text{GB}$$

一张 A100/H100 才 **80 GB**。光参数+梯度+优化器就要 **≈35 张卡**才放得下，激活还没算。**这就是一切并行的起点**：必须把模型/数据/状态**切开摊到多卡**。

切的维度无非三个，下面逐个拆。

```
      切什么？                     对应技术
 ┌────────────────────────────────────────────┐
 │ 切「数据」(每卡完整模型,不同数据)  → DP / ZeRO  │
 │ 切「单层矩阵」(一层拆到多卡)       → TP (张量并行)│
 │ 切「层」(不同层放不同卡,接力跑)    → PP (流水线)  │
 └────────────────────────────────────────────┘
        三者正交，可叠加 → 3D 并行
```

## 4. 数据并行 DP 与 ZeRO

**朴素数据并行 (DDP)**：每张卡放**一份完整模型**，喂**不同的数据子批**，各自算梯度，再用 **All-Reduce** 把梯度求平均后同步，保证所有卡参数一致。

```
 卡0[完整模型]  卡1[完整模型]  卡2[完整模型]
   数据片A        数据片B        数据片C
     │ 各算梯度     │             │
     └──────► All-Reduce 求平均 ◄──┘   (通信量 ≈ 2N，与卡数无关)
            所有卡拿到相同的平均梯度 → 各自更新
```

- **优点**：实现简单、扩展线性、计算/通信可重叠。
- **致命缺点**：每张卡都存**全套 16N**——模型大了根本放不下。这正是 **ZeRO** 要解的。

**ZeRO (Zero Redundancy Optimizer)**：DP 里"每卡存全套"是**冗余**的。ZeRO 把那三大件**切开分到各卡**，按切的程度分三级：

```
            参数  梯度  优化器状态     每卡显存(以参数N、并行度d为例)
 ZeRO-1     复制  复制   ✂️切分        2N + 2N + 12N/d
 ZeRO-2     复制  ✂️切分 ✂️切分        2N + 2N/d + 12N/d
 ZeRO-3     ✂️切分 ✂️切分 ✂️切分        (2N+2N+12N)/d  ≈ 16N/d
 (FSDP 等价于 ZeRO-3 的思路)
```

- **代价**：ZeRO-3 算到某层时，该层参数被切走了，要**临时 All-Gather 收回来**再算，通信变多。**省显存 ↔ 加通信**，是核心权衡。
- DeepSpeed 是 ZeRO 的代表实现，细节见 [[ai-framework/deepspeed/README]]。**ZeRO-Offload/Infinity** 还能把状态甩到 CPU/NVMe，用速度换容量。

## 5. 张量并行 TP（切单层矩阵）

当**单独一层**都大到一张卡装不下时，就得把这一层的**矩阵乘法本身**切开。以 MLP 里的 $Y=XA$ 为例，把权重 $A$ 按列切成 $[A_1, A_2]$，分到两张卡：

```
        X (广播到两卡)
      ┌────┴────┐
   卡0│ A_1     │卡1│ A_2 │
   Y_1=X·A_1    Y_2=X·A_2     (各算一半,无需通信)
      └────┬────┘
        All-Reduce / All-Gather 拼回 Y   (每层都要通信!)
```

- **粒度最细**：切到单个矩阵内部，Megatron-LM 是代表实现。
- **关键约束**：每层前向/反向都要 All-Reduce，**通信极频繁、对带宽极敏感**。所以 TP 几乎只在**单机内部用 NVLink**（机内带宽高），**很少跨机**。
- **典型 TP size = 8**（一台 8 卡机内），再大就靠 PP/DP 往外扩。

## 6. 流水线并行 PP（切层）

把模型的**不同层**放到**不同卡**上，数据像流水线一样逐 stage 流过。

```
 stage0: 层0-7  ──► stage1: 层8-15 ──► stage2: 层16-23 ──► stage3...
   卡0              卡1                 卡2
```

朴素切法有个大问题——**气泡 (bubble)**：stage1 要等 stage0 算完才有活干，大家轮流闲置。

```
 朴素(串行):  卡0[████....]  卡1[....████]   ← 一半时间在发呆
 micro-batch(1F1B): 把大批拆成小微批,像流水线灌进去
   卡0: F1 F2 F3 F4 B1 B2 ...
   卡1:    F1 F2 F3 F4 B1 ...   ← 气泡变小,利用率↑
```

- **解法**：把 batch 切成多个 **micro-batch** 流水灌入（GPipe / 1F1B 调度），气泡占比 $\approx \frac{p-1}{m+p-1}$（$p$=stage 数，$m$=micro-batch 数）。**$m$ 越大气泡越小**。
- **优点**：**通信量小**（只在 stage 边界传激活），适合跨机扩展。
- **缺点**：调度复杂，需要小心平衡每个 stage 的层数（**负载均衡**）。

## 7. 3D 并行：把三者叠起来

三个维度正交，可同时用。千卡训练的经典配方：

```
  ┌─────────────────── 总卡数 = DP × TP × PP ───────────────────┐
  │                                                              │
  │  TP=8   (机内 NVLink, 切单层)      ← 带宽最贵,放最里层         │
  │  PP=8   (跨机, 切层, 通信少)        ← 往外扩                  │
  │  DP=16  (复制+ZeRO, 切数据/状态)    ← 最外层,加吞吐            │
  │                                                              │
  │  例: 8 × 8 × 16 = 1024 卡                                    │
  └──────────────────────────────────────────────────────────────┘
  选型直觉:
    TP 放「带宽最高的域」(机内)   —— 因为它通信最频繁
    PP 放「跨机」                —— 因为它通信最省
    DP/ZeRO 最外层加吞吐与省显存
```

**Megatron-DeepSpeed** 正是把 Megatron 的 TP/PP 与 DeepSpeed 的 ZeRO-DP 缝在一起的工程，见 [[llm-train/megatron-deepspeed/README]]。

## 8. 显存优化：把激活和状态再压一压

并行解决"摊开"，显存优化解决"每卡再省一点"。三大主力：

**(1) 激活重计算 (Activation/Gradient Checkpointing)**
- 痛点：激活值常是显存最大头。
- 思路：前向时**不全存激活**，只存少数"检查点"；反向需要时**重新前向算一遍**。
- 权衡：**省显存 ↔ 多约 1/3 算力**（多一次前向）。典型能把激活显存从 $O(\text{层数})$ 降到 $O(\sqrt{\text{层数}})$。

```
 普通:  前向存所有激活 ─────────────► 反向直接读   (省算力,费显存)
 重计算: 前向只存检查点 ─► 反向时重算中间激活 ──►   (省显存,费算力)
```

**(2) 混合精度 (Mixed Precision)**
- 用 **FP16/BF16** 算前向反向（快、省一半激活/梯度显存），但保留一份 **FP32 主权重**做精确更新。
- **BF16 vs FP16**：BF16 指数位多、**动态范围大、不易溢出**，大模型更稳；FP16 精度高但范围窄，需 **loss scaling**（把 loss 放大避免小梯度被舍成 0）。
- **FP8**（H100 起）：进一步压，但需更精细的缩放管理。

**(3) Offload / CPU-NVMe**
- 把暂时不用的优化器状态/参数甩到 **CPU 内存甚至 NVMe**（ZeRO-Offload/Infinity）。
- 权衡：用 **PCIe/磁盘带宽**换显存，吞吐下降，**单卡跑大模型**时的救命手段。

**其它常用**：FlashAttention（把注意力中间矩阵融合，**省激活+提速**）、梯度累积（用多个小 micro-batch 攒一个大 effective batch，省显存换步数）。

## 9. 框架地图：谁负责什么

```
 ┌───────────────── 训练框架分层 ─────────────────┐
 │ 上层(易用/微调): LLaMA-Factory, Firefly, trl   │  ← 配置即训,LoRA/SFT/DPO
 │ 中层(对齐/RL):   trl, OpenRLHF                  │  ← RLHF/PPO/DPO 流水线
 │ 并行引擎(底座):  Megatron-LM, DeepSpeed, FSDP   │  ← 3D并行/ZeRO/显存优化
 │ 计算/通信底座:   PyTorch, NCCL, CUDA, Triton    │  ← 算子与集合通信
 └────────────────────────────────────────────────┘
```

| 框架 | 定位 | 强在哪 | 何时选 |
|------|------|--------|--------|
| **Megatron-LM** | 大规模预训练引擎 | TP/PP 做到极致，高效算子 | 从零训百亿~千亿，追极致吞吐 |
| **DeepSpeed** | ZeRO-DP + 显存优化 | ZeRO-1/2/3、Offload、易接入 | 想省显存、单/少机跑大模型 |
| **Megatron-DeepSpeed** | 两者缝合 | 3D 并行 + ZeRO 全家桶 | 千卡 3D 并行预训练 |
| **PyTorch FSDP** | 原生 ZeRO-3 思路 | 官方、与生态无缝 | 用纯 PyTorch、不想引重依赖 |
| **LLaMA-Factory / Firefly** | 微调一条龙 | 配置化 SFT/LoRA/DPO | 快速做指令微调/对齐 |
| **trl / OpenRLHF** | 对齐训练 | PPO/DPO/RM 流水线 | 做 RLHF/偏好对齐 |

> 选型一句话：**预训练看并行引擎（Megatron/DeepSpeed），微调对齐看上层框架（LLaMA-Factory/trl）。** 具体版本号/CLI 参数以官方文档为准。

## 10. 稳定性与容错（千卡训练的真问题）

跑得越大，"训练崩了"越贵。核心问题与对策：

- **Loss spike（损失突然飙升）**：大模型常见。诱因有学习率过大、坏数据、FP16 溢出。对策：**warmup + 余弦衰减**、**梯度裁剪**（限制梯度范数）、用 **BF16** 减少溢出、**跳过异常 batch**、**从最近 checkpoint 回滚**。
- **数值稳定**：loss scaling（FP16）、合适的初始化、Pre-LN/归一化位置选择。
- **硬件故障**：千卡训练单卡/单机故障是**常态**而非意外。对策：**定期存 checkpoint（断点续训）**、**弹性容错**（坏节点剔除后重组继续）、健康检查与自动重启。
- **吞吐监控**：盯 **MFU（模型算力利用率）**——实际有效算力 / 理论峰值，常见 30%~60%。掉点往往意味着通信瓶颈或负载不均。
- **可复现性**：固定随机种子、保存数据顺序/数据加载状态，断点续训才能"接得上"。

```
 训练日志该盯的几条线:
   loss   ─╲      ╱╲  ← spike! 立刻查LR/数据/溢出,必要时回滚checkpoint
            ╲____╱  ╲___
   grad_norm ───┐ ┌──   ← 突刺常先于loss spike出现
   MFU/吞吐  ────────    ← 掉了说明有卡/通信在拖后腿
```

## 数值例子：7B 与 70B 的容量与并行手算

**例 1：7B 全参训练能塞进一张 80GB 卡吗？**
- 参数+梯度+优化器 = $16N = 16\times7\times10^9 = 1.12\times10^{11}$ 字节 ≈ **104 GB**。
- 结论：**单卡放不下**（光状态就 104 GB > 80 GB），还没算激活。
- 救法：用 **ZeRO-3 + 2 张卡**，每卡状态 ≈ $104/2=52$ GB，留出空间给激活，可行；或上 **LoRA/QLoRA** 只训增量，状态降到几 GB，单卡轻松。

**例 2：70B 预训练并行配方估算**
- 状态显存 $16N = 16\times70\times10^9 \approx 1120$ GB，需 **≥14 张 80GB 卡**才放得下状态。
- 实际配方（示意）：**TP=4（机内切层）× PP=4（跨机切层）× DP=8（ZeRO-2）= 128 卡**。TP 把单层摊开，PP 把层摊开，ZeRO 再切优化器状态并加吞吐，激活靠**重计算 + BF16** 压住。

**例 3：流水线气泡占比**
- $p=4$ 个 stage、$m=32$ 个 micro-batch：气泡 $\approx \frac{p-1}{m+p-1}=\frac{3}{35}\approx 8.6\%$。把 $m$ 提到 64，气泡降到 $\frac{3}{67}\approx 4.5\%$——**多塞 micro-batch 是压气泡最直接的旋钮**。

## 对照表

**三种并行怎么选**

| 维度 | DP / ZeRO | TP 张量并行 | PP 流水线并行 |
|------|-----------|-------------|--------------|
| 切什么 | 数据 + 状态 | 单层矩阵 | 层 |
| 每卡是否完整模型 | DP 是 / ZeRO 否 | 否（半层） | 否（部分层） |
| 通信频率 | 每 step 一次 All-Reduce | **每层都通信(最频)** | 仅 stage 边界(最省) |
| 通信量 | ≈2N | 大 | 小 |
| 适合放在 | 最外层 | **机内 NVLink** | **跨机** |
| 主要省什么 | 状态显存 + 加吞吐 | 单层显存 | 层显存 |
| 主要代价 | All-Gather 通信(ZeRO-3) | 带宽敏感 | 气泡 + 负载均衡 |

**三阶段对比**

| 阶段 | 数据 | 任务/损失 | 算力占比 | 产物 |
|------|------|----------|---------|------|
| 预训练 | 万亿 token 无标注 | next-token 交叉熵 | >95% | base 模型 |
| SFT | (指令,回答)对 | next-token(只算回答) | 小 | 听指令的模型 |
| 对齐 | 偏好对/人类反馈 | RLHF(PPO+KL) 或 DPO | 中小 | 对齐模型 |

## 常见问题

| 问题 | 答案 |
|------|------|
| 模型能装下单卡，只想训快点？ | 上 **DDP/DP**，最简单线性扩展 |
| 状态装不下、但单层能装？ | 上 **ZeRO-2/3**，切优化器/梯度/参数 |
| 单独一层都装不下？ | 上 **TP**，且只在机内 NVLink 用 |
| 层太多、想跨机扩？ | 上 **PP**，micro-batch 拉满压气泡 |
| 千卡预训练？ | **3D 并行 = DP×TP×PP**，TP 机内、PP 跨机 |
| 激活爆显存？ | **重计算 + FlashAttention + BF16** |
| 用 FP16 还是 BF16？ | 大模型优先 **BF16**（范围大不易溢出）；FP16 需 loss scaling |
| 单卡想跑超大模型？ | **ZeRO-Offload/Infinity** 甩到 CPU/NVMe，用带宽换容量 |
| Loss 突然飙升？ | 查 LR/坏数据/溢出，**梯度裁剪 + 回滚 checkpoint** |
| 只是想做指令微调？ | **LoRA/QLoRA + LLaMA-Factory**，无需重型并行 |
