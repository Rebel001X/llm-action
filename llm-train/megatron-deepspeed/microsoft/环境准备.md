## 0. 一句话锚点

**Megatron-DeepSpeed 的"环境准备"= 把一条从硬件到 Python 库层层咬合的依赖链对齐**：GPU 驱动 ↔ CUDA ↔ PyTorch（自带 cuDNN/NCCL）↔ 用 nvcc 现场编译的 C++/CUDA 扩展（apex、flash-attn、deepspeed 算子）↔ Megatron-DeepSpeed 框架本身。链条上任意一环版本错位，轻则导入报错，重则训练时静默出错。所以正确姿势是**先在容器里把链条对齐，再 `docker commit` 固化成镜像**，避免下次重装。

## 1. 地基：它到底解决什么问题

Microsoft 的 [Megatron-DeepSpeed](https://github.com/microsoft/Megatron-DeepSpeed) 是把 NVIDIA 的 **Megatron-LM**（提供张量并行 TP、流水线并行 PP 的模型实现）和微软的 **DeepSpeed**（提供 ZeRO 显存优化、3D 并行调度、混合精度、offload）缝合在一起的大模型训练框架。它能跑 GPT / LLaMA / BLOOM 这类百亿~千亿参数模型。

为什么"装环境"反而是第一道坎？因为它**严重依赖现场编译的本地扩展**：

- apex 的融合优化器、fused layernorm 是 CUDA C++ 写的，要用本机 `nvcc` 编译。
- flash-attn 也是 CUDA kernel，要编译。
- deepspeed 的部分算子（如 fused adam）在安装或首次运行时 JIT 编译。

编译要求"**编译期的 CUDA 版本 == PyTorch 运行期看到的 CUDA 版本**"，还要求一个**足够新的 C++ 编译器**（CentOS 7 自带 gcc 4.8 太老，C++17 支持不全，所以下文要装 devtoolset-9）。这就是环境准备的核心矛盾。

```
        想跑 Megatron-DeepSpeed
                 │
                 ▼
   ┌──── 需要现场编译 C++/CUDA 扩展 ────┐
   │                                    │
   ▼                                    ▼
版本必须对齐                      编译器必须够新
(驱动/CUDA/PyTorch)              (gcc/g++ ≥ C++17)
   │                                    │
   └──────────► 对齐失败 = 导入/编译报错 ◄──┘
```

## 2. 软件栈分层：从硅片到训练脚本

把整条链画出来，理解"谁依赖谁、谁不能乱动"：

```
┌─────────────────────────────────────────────────────────┐
│  L7  训练脚本 pretrain_gpt.py / 启动器 deepspeed/torchrun │  ← 你写/改的
├─────────────────────────────────────────────────────────┤
│  L6  Megatron-DeepSpeed 框架代码（TP/PP/ZeRO 调度）       │
├─────────────────────────────────────────────────────────┤
│  L5  Python 依赖：transformers / sentencepiece / einops  │
│      本地扩展：apex · flash-attn · deepspeed 算子         │  ← 要编译
├─────────────────────────────────────────────────────────┤
│  L4  PyTorch（内含 cuDNN、NCCL、CUDA runtime 的 wheel）   │
├─────────────────────────────────────────────────────────┤
│  L3  CUDA Toolkit（nvcc 编译器，devel 镜像才有）          │
├─────────────────────────────────────────────────────────┤
│  L2  GPU 驱动（宿主机装，--gpus all 透传进容器）          │
├─────────────────────────────────────────────────────────┤
│  L1  OS / glibc / 编译工具链（CentOS7 + devtoolset-9）    │
├─────────────────────────────────────────────────────────┤
│  L0  GPU 硬件（A100/H800 …）+ IB/RoCE 网卡（多机才需）    │
└─────────────────────────────────────────────────────────┘
```

记住三条"对齐铁律"：

1. **驱动只装在宿主机**，容器靠 `--gpus all`（NVIDIA Container Toolkit）把驱动透传进来。容器里不要装驱动。
2. **CUDA runtime 由 PyTorch wheel 自带**；但**编译扩展需要 nvcc**，nvcc 来自基础镜像里的 CUDA Toolkit（要用 `*-devel` 而非 `*-runtime` 镜像）。
3. **编译期 CUDA 主版本要与 PyTorch 的 CUDA 主版本一致**（例如都是 11.8），否则编出来的 `.so` 链接不上。

> 上面这条 `pytorch:2.0.1-py310-11.8-cudnn8-devel-centos7` 镜像名就是把"PyTorch 2.0.1 / Python 3.10 / CUDA 11.8 / cuDNN8 / devel（含 nvcc）/ CentOS7"全写在 tag 里。这是私有 harbor 的镜像，**具体可用 tag 以你们镜像仓库为准**。

## 3. 各依赖在干什么（理解了才知道装不上时去查哪里）

| 依赖 | 作用 | 为什么这么装 / 注意点 |
| --- | --- | --- |
| `devtoolset-9` + `source enable` | 提供新版 gcc/g++（CentOS7 默认 4.8 太老） | **必须 source enable 后再编译**，否则用回旧 gcc 编不过 C++17 |
| `ninja-build` | 加速本地扩展并行编译 | 没它编译会很慢甚至串行 |
| `apex` | NVIDIA 混合精度 + 融合算子（fused layernorm/optimizer） | Megatron 强依赖；需带 CUDA 扩展编译安装，**不是简单 pip apex** |
| `flash-attn` | FlashAttention，省显存、加速注意力 | 要编 CUDA kernel；版本要与 PyTorch/CUDA 匹配 |
| `deepspeed` | ZeRO、3D 并行、offload 的核心 | 部分算子安装或首次运行 JIT 编译，需 nvcc 在线 |
| `transformers` | 模型/分词器/权重格式 | 数据预处理与权重转换常用 |
| `sentencepiece` | 子词分词器（LLaMA 等用） | 训练前 tokenize 语料需要 |
| `einops` | 张量重排，代码可读性 | 框架内部用 |
| `pybind11` | C++↔Python 绑定，编扩展时的头文件 | 编译某些扩展的前置 |
| `py-cpuinfo` / `psutil` | DeepSpeed 探测 CPU/内存拓扑 | DeepSpeed 运行期依赖 |
| `libibverbs` | InfiniBand 用户态库 | **多机训练**走 IB 时 NCCL 需要，单机可不装 |

一句话理解三层依赖：**纯 Python 包**（transformers/einops…）直接 pip 就行；**带 CUDA 扩展的包**（apex/flash-attn/deepspeed）才是真正的难点，它们决定了为什么要 devel 镜像 + 新 gcc。

## 4. 方式一：Docker（推荐，便于固化复现）

整体流程是"**起一个 devel 容器 → 装编译器和依赖 → commit 成新镜像 → 之后都用这个新镜像起训练容器**"。

```
docker run(devel基础镜像)
        │  装 devtoolset-9 / ninja / apex / flash-attn / deepspeed …
        ▼
   容器内环境就绪并自检
        │  docker commit  ← 把"装好的状态"冻成新镜像 megatron-deepspeed:v2
        ▼
docker run(megatron-deepspeed:v2)  ← 下次直接用，无需重装
```

### 4.1 启动基础容器并安装依赖

```bash
docker run -it --gpus all --network=host \
  --shm-size 4G \
  -v /data/hpc/home/guodong.li/:/workspaces \
  -w /workspace/stanford_alpaca/ \
  harbor.aip.io/base/pytorch:2.0.1-py310-11.8-cudnn8-devel-centos7 \
  /bin/bash

# 1) 新编译器与构建工具
yum install ninja-build
yum install which
yum -y install devtoolset-9
source /opt/rh/devtoolset-9/enable   # 关键：本 shell 启用新 gcc

# 2) 安装 apex（带 CUDA 扩展，按官方说明源码编译，别只 pip install apex）

# 3) 纯 Python 依赖
pip install sentencepiece
pip install transformers
pip install deepspeed
pip install einops==0.6.1

# 4) 带编译的扩展
yum install git
pip install flash-attn==1.0.4
pip install pybind11

# 5) 多机 IB 用户态库（单机可跳过）
yum -y install libibverbs
```

关键参数为什么这么给（**讲含义，不背死默认值，确切名以 docker 文档为准**）：

| 参数 | 作用 | 权衡 |
| --- | --- | --- |
| `--gpus all` | 把宿主所有 GPU 透传进容器 | 想限定卡可用 `--gpus '"device=0,1"'` |
| `--network=host` | 容器直接用宿主网络栈 | 多机/IB 通信常这么配，省去端口映射；牺牲网络隔离 |
| `--shm-size` | 共享内存大小，DataLoader 多 worker 走 /dev/shm | **给小了会报 "bus error / 共享内存不足"**；训练时建议 ≥16G |
| `-v 宿主:容器` | 挂载代码/数据，避免装在容器内丢失 | 路径写错会挂空目录 |
| `-w` | 容器内工作目录 | 与挂载路径对应 |

> ⚠️ 注意上面的 `-w /workspace/...` 和挂载点 `/workspaces`（多了个 s）不一致——这类**路径拼写不一致**是常见坑，自己的环境要对齐。

### 4.2 固化成镜像

装好、自检通过后，**另开一个宿主终端**把当前容器提交为镜像：

```bash
# 8bcb92d326cb 是容器ID（docker ps 查），下次直接用 :v2 起容器
docker commit -m="megatron-deepspeed" -a="liguodong" \
  8bcb92d326cb harbor.maip.io/base/megatron-deepspeed:v2
```

为什么要 commit？因为 apex/flash-attn 编译动辄十几分钟，依赖又脆弱；**把"已装好"的状态冻成镜像，等于一次对齐、永久复用**，也方便分发到多机集群（每台机器 `docker pull` 同一个 tag，保证环境一致——这对多机训练尤其重要）。

> 生产更规范的做法是写 **Dockerfile** 而非手动 commit（可审计、可重建）。commit 适合快速打样，Dockerfile 适合长期维护。

### 4.3 用固化镜像起训练容器

```bash
docker run -it --gpus all --network=host \
  --shm-size 16G \
  -v /data/hpc/home/guodong.li/workspace:/workspace \
  -w /workspace/code/Megatron-DeepSpeed-llama-20230815 \
  harbor.aip.io/base/megatron-deepspeed:v2 \
  /bin/bash
```

注意这里 `--shm-size` 提到了 **16G**（训练阶段 DataLoader 并发更高），工作目录切到真正的训练代码目录。

> Docker 里 `/etc/profile` 环境变量不生效的问题，可参考：docker 环境变量配置（具体方案以官方/可信文档为准）。根因通常是 `docker run` 默认非 login shell，不会自动 source `/etc/profile`；可在 `~/.bashrc` 里显式 source，或用 `ENV`/`docker run -e` 传入。

## 5. 方式二：本地 conda（极简，适合小规模/调试）

如果不用容器（例如裸机调试、CI），用 conda 建一个干净环境：

```bash
conda create -n megatron-deepspeed-venv python=3.9 -y
conda activate megatron-deepspeed-venv

pip install torch          # 建议带上与本机 CUDA 匹配的 index-url
pip install numpy
pip install py-cpuinfo      # DeepSpeed 探测 CPU 拓扑
pip install psutil          # DeepSpeed 探测内存
pip install deepspeed       # 编译期需要本机 nvcc 与新版 gcc
```

本地方式的**隐患**：依赖宿主机自身的 CUDA Toolkit / gcc 是否够新、是否与 `torch` 的 CUDA 版本一致。一旦不一致，apex/deepspeed 编译就会失败。所以**生产/多机首选 Docker**；本地 conda 适合单卡快速验证逻辑。

## 6. 装完怎么自检（务必做，比训练报错再排查省事）

按"从底层往上"逐层验证，定位问题更快：

```bash
# L2 驱动：能看到 GPU 吗
nvidia-smi

# L3 编译器：nvcc 在不在、版本对不对
nvcc --version
gcc --version          # 应是 devtoolset-9 的新版而非 4.8

# L4 PyTorch ↔ CUDA：能用 GPU、CUDA 版本匹配吗
python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.device_count())"

# L5 扩展：能 import 且不报符号错误吗
python -c "import deepspeed; print(deepspeed.__version__)"
python -c "import flash_attn; print('flash-attn ok')"
python -c "from apex import amp; print('apex ok')"
ds_report               # DeepSpeed 自带环境体检，看各算子是否可用

# L0/L2 多卡通信（多机才需要）：NCCL 是否走对网卡
# 训练启动时设 NCCL_DEBUG=INFO 观察日志即可
```

自检通过的标志：`torch.cuda.is_available()` 为 True、各扩展 import 无 `undefined symbol`、`ds_report` 中关键算子显示已编译/可用。

```
自检顺序（出错就停在该层往下查）
nvidia-smi ──ok──► nvcc/gcc ──ok──► torch.cuda ──ok──► import 扩展 ──ok──► ds_report ──ok──► 开训
   │失败            │失败             │失败              │失败                │失败
   ▼               ▼                 ▼                 ▼                   ▼
驱动/透传问题    devel镜像/gcc      torch装错版本     编译期版本错位      算子未编译/缺依赖
```

## 常见问题 / 坑

| 现象 | 根因 | 处理方向 |
| --- | --- | --- |
| `import apex` 报 `undefined symbol` | 编译期 CUDA 与 PyTorch CUDA 不一致 | 用 devel 镜像，确保编译期与运行期 CUDA 主版本一致后重装 |
| apex 编译失败、报 C++ 标准/语法错误 | 用了 CentOS7 自带 gcc 4.8 | 先 `source /opt/rh/devtoolset-9/enable` 再编译 |
| flash-attn 装不上 | 版本与 torch/CUDA 不匹配，或缺 nvcc | 选与本机匹配的版本；确认 `nvcc --version` 正常 |
| 训练报 "bus error" / 共享内存不足 | `--shm-size` 太小 | 调大到 16G 以上 |
| 多机 NCCL 卡住 / 走错网卡 | 没装 libibverbs，或 NCCL 未指定 IB 网卡 | 装 `libibverbs`，用 `NCCL_SOCKET_IFNAME`/`NCCL_IB_HCA` 指定 |
| 容器里环境变量不生效 | 非 login shell 未 source `/etc/profile` | 写进 `~/.bashrc` 或用 `docker run -e` 传入 |
| 重装一次依赖巨慢 | 没固化镜像 | `docker commit` 或写 Dockerfile，一次对齐永久复用 |
| `nvidia-smi` 在容器里找不到 GPU | 缺 NVIDIA Container Toolkit 或没加 `--gpus all` | 宿主装好 toolkit，run 时带 `--gpus all` |

> 凡涉及精确版本号、CLI 参数确切默认值、apex/flash-attn 的安装命令细节，**一律以对应官方仓库 README 和你们镜像仓库的可用 tag 为准**，本文只讲机制与权衡，不背死数字。
