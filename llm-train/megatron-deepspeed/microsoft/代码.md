## 0. 一句话锚点

**Microsoft Megatron-DeepSpeed = NVIDIA Megatron-LM 的模型并行内核（TP/PP）＋ DeepSpeed 的显存与并行扩展（ZeRO / pipeline / activation checkpointing / MoE）**，缝合成一套能在多机多卡上预训练 GPT / LLaMA 级别大模型的代码。你跑的 `pretrain_gpt.py`，本质是"Megatron 搭骨架、DeepSpeed 管显存和通信"。

> 具体类名、函数签名、参数默认值请以你 clone 的那个 commit 的源码与官方文档为准；本文讲**机制与结构**，不背死细节。

## 1. 地基：它到底解决什么问题

训练一个百亿/千亿参数模型，单卡放不下，三个维度都顶到天花板：

```
单卡瓶颈            谁来解决
────────────────────────────────────────────
模型参数放不下   →  张量并行 TP (Megatron)  把一层切到多卡
层数太多放不下   →  流水线并行 PP (DeepSpeed/Megatron) 把不同层放不同卡
优化器状态太大   →  ZeRO / 数据并行 DP (DeepSpeed) 切优化器状态
激活值太大       →  activation checkpointing 用算力换显存
```

- **Megatron-LM**（NVIDIA）擅长 **TP**：把单个 Transformer 层的矩阵乘法按行/列切到多卡，靠 `all-reduce` 拼回来。但它原生的 DP/ZeRO 能力有限。
- **DeepSpeed**（Microsoft）擅长 **ZeRO / PP / MoE / 通信优化**，但缺一个成熟的 TP 内核。
- **Megatron-DeepSpeed** = 把两者拼起来，于是得到完整的 **3D 并行**（TP × PP × DP）。微软在自己 fork 里维护这套缝合层，还加了 LLaMA、RoPE、SwiGLU、RMSNorm、GQA 等支持（见同目录 `pretrain_llama2_distributed.sh`）。

## 2. 仓库结构：源码地图

只列你最常打交道的（具体文件名以仓库为准）：

```
Megatron-DeepSpeed/
├── pretrain_gpt.py            ← 训练入口（你 torchrun 的就是它）
├── pretrain_bert.py / t5.py   ← 其它模型入口
├── megatron/                  ← 核心库（大部分逻辑在这）
│   ├── arguments.py           ← 解析所有 --xxx 命令行参数
│   ├── initialize.py          ← 初始化分布式、随机种子、并行 group
│   ├── training.py            ← 训练主循环 train() / train_step()
│   ├── model/                 ← Transformer / GPTModel / 各层实现
│   │   ├── transformer.py     ← attention + MLP
│   │   ├── language_model.py
│   │   └── ...
│   ├── core/ 或 mpu/          ← model-parallel utilities（并行 group 管理）
│   ├── optimizer/             ← fused Adam、梯度裁剪、loss scaler
│   ├── data/                  ← dataset、数据加载、indexed dataset
│   └── checkpointing.py       ← 存/读 checkpoint（含并行切分逻辑）
├── examples/                  ← 原版 Megatron 的示例脚本
├── examples_deepspeed/        ← DeepSpeed 特性示例（MoE / 压缩 / 课程学习 / Azure）
└── tools/                     ← checkpoint 转换、数据预处理
```

记忆口诀：**入口在根目录的 `pretrain_*.py`，干活的在 `megatron/`，DeepSpeed 特性示例在 `examples_deepspeed/`。**

## 3. 一次启动的完整调用链

从你敲下命令到第一个 loss 打印，链路是这样的（对照 `pretrain_llama2_distributed.sh`）：

```
你的 .sh 脚本
  │  设置 TP/PP/ZERO_STAGE、模型超参、DS_CONFIG(json)
  ▼
torchrun --nproc_per_node 8 --nnodes N ... pretrain_gpt.py --tensor-model-parallel-size 2 ...
  │  torchrun 拉起 N×8 个进程，每个进程拿到自己的 RANK/LOCAL_RANK
  ▼
pretrain_gpt.py : main()
  │
  ├─ pretrain(train_valid_test_dataset_provider,   ← megatron/training.py 提供的总入口
  │           model_provider,                      ← 你给的"怎么造模型"回调
  │           forward_step_func)                   ← 你给的"一步前向怎么算 loss"回调
  │
  ▼
initialize_megatron()              ← megatron/initialize.py
  │  ① 解析参数 (arguments.py)
  │  ② init_process_group(nccl)    ← 建立全局通信
  │  ③ 划分并行 group：TP group / PP group / DP group（关键！见 §5）
  │  ④ 设置随机种子（保证 TP 各 rank 的初始化协调一致）
  ▼
setup_model_and_optimizer()
  │  ① model_provider() 造出本 rank 负责的那部分层
  │  ② 若开启 --deepspeed → deepspeed.initialize() 包住 model+optimizer（见 §6）
  ▼
train()  ── 循环 ──► train_step() ──► forward → backward → optimizer.step()
                         每隔 log-interval 打印 loss / 每隔 save-interval 存 ckpt
```

**关键理解：`pretrain_gpt.py` 只是把三个"回调"塞给 `megatron/training.py:pretrain()`，真正的循环骨架在 Megatron 里，而每一步的显存/通信细节被 DeepSpeed 接管。**

## 4. 核心抽象：`get_accelerator()` 那行代码

你看到的那个片段：

```python
from deepspeed.accelerator import get_accelerator
get_accelerator().device_name() == 'cuda'
```

这是 **DeepSpeed 的"加速器抽象层"（Accelerator Abstraction）**。它解决的问题是：代码里到处写死 `torch.cuda.xxx` 会把训练绑死在 NVIDIA GPU 上。DeepSpeed 引入一个统一接口，让同一份代码能跑在不同后端（CUDA / 其它厂商加速器 / CPU）。

```
   业务代码（Megatron-DeepSpeed）
        │ 只调用抽象接口
        ▼
   get_accelerator()  ← 运行时探测当前硬件，返回对应实现
        │
   ┌────┼─────────────┬───────────┐
   ▼    ▼             ▼           ▼
 CUDA  其它厂商NPU/GPU  CPU      ...（按后端实现）
device_name()  返回 'cuda' / 厂商名 / 'cpu'
```

常见用法（语义层面，**具体方法名以 DeepSpeed 版本为准**）：

| 你想做的事 | 写死的 CUDA 写法 | 抽象写法（可移植） |
|---|---|---|
| 取设备名判断后端 | `'cuda'` 硬编码 | `get_accelerator().device_name()` |
| 当前设备 | `torch.cuda.current_device()` | `get_accelerator().current_device()` |
| 同步 | `torch.cuda.synchronize()` | `get_accelerator().synchronize()` |
| 取显存占用 | `torch.cuda.memory_allocated()` | 对应 accelerator 方法 |

所以那行 `device_name() == 'cuda'` 通常出现在**需要按后端分支**的地方（比如某些 kernel 只在 CUDA 下可用，要 fallback）。理解它的意义：**这是一层"硬件可移植性"的薄封装，不是业务逻辑核心。**

## 5. 3D 并行在源码里怎么落地

这是整套代码最硬核的部分。设想 16 卡，配置 `TP=2, PP=2, DP=4`（2×2×4=16）。`megatron/initialize.py` 会把 16 个 rank 切成三套互相正交的通信 group：

```
              DP 维度（数据并行，4 份相同模型副本，ZeRO 在这切优化器状态）
              ┌───────────────────────────────────────────────┐
   PP stage0  │  [r0 r1]   [r4 r5]   [r8 r9]   [r12 r13]       │  ← TP group = 中括号内 2 卡
   (前半层)   │   ↑TP       ↑TP       ↑TP        ↑TP           │
              ├───────────────────────────────────────────────┤
   PP stage1  │  [r2 r3]   [r6 r7]   [r10 r11] [r14 r15]       │
   (后半层)   └───────────────────────────────────────────────┘
                 副本0       副本1      副本2       副本3
```

三种 group 各管一种通信：

| 并行维度 | 切的是什么 | 通信原语 | 在源码里 |
|---|---|---|---|
| **TP** 张量并行 | 单层内的权重矩阵（按列/行切） | 层内 `all-reduce` | `megatron/model/transformer.py` 的 ColumnParallel / RowParallelLinear |
| **PP** 流水线并行 | 不同 Transformer 层放不同 stage | stage 间 `send/recv` 激活值 | DeepSpeed `PipelineEngine` 或 Megatron schedule |
| **DP** 数据并行 | 同一模型的多份副本，喂不同 micro-batch | 梯度 `all-reduce` / ZeRO `reduce-scatter` | DeepSpeed ZeRO（`zero-stage`） |

**为什么要正交切分？** 因为 TP 通信量大、必须在最快的 NVLink 内（同机），PP 通信量小可跨机，DP 在最外层。group 划分决定了 NCCL 通信落在哪条物理链路上 —— 切错了，TP 的 all-reduce 跑到慢速 IB 上，吞吐直接腰斩。

数值直觉：LLaMA-13B，`hidden=5120`。TP=2 时，每张卡只存一半的 attention/MLP 权重，单层 all-reduce 的数据量 ∝ `batch × seq × hidden`。这就是为什么 `TP` 通常 ≤ 单机 GPU 数（8），不跨机。

## 6. DeepSpeed 如何"接管"训练循环

脚本里这几行就是开关：

```bash
ds_args=" --deepspeed --deepspeed_config=$DS_CONFIG --zero-stage=$ZERO_STAGE \
          --deepspeed-activation-checkpointing"
```

配上一个 `deepspeed.json`：

```json
{
  "train_batch_size": 32,
  "train_micro_batch_size_per_gpu": 4,
  "zero_optimization": { "stage": 0 },
  "bf16": { "enabled": true }
}
```

接管过程：

```
普通 PyTorch:  model -> loss.backward() -> optimizer.step()
                                │
DeepSpeed 把 model+optimizer 包成 engine：
   model_engine, optimizer, _, _ = deepspeed.initialize(model, ds_config)
                                │
   于是循环变成：
       model_engine(batch)         # 前向（内部按 ZeRO 切分参数）
       model_engine.backward(loss)  # 反向（reduce-scatter 梯度）
       model_engine.step()          # 更新（各 rank 只更新自己那片优化器状态）
```

DeepSpeed 在 engine 里干的三件大事：

1. **ZeRO 切优化器状态**：`stage` 决定切多狠 —— stage 1 切优化器状态、stage 2 再切梯度、stage 3 连参数也切。`zero-stage=0` 等于关掉 ZeRO，纯靠 TP/PP 省显存（脚本里 LLaMA 例子就是 0，因为 TP×PP 已经把模型切开了）。
2. **混合精度**：`bf16`/`fp16` 开关、loss scaling、master 权重维护。
3. **activation checkpointing**：`--deepspeed-activation-checkpointing` 让前向不保存中间激活，反向时重算，用算力换显存。

关键参数关系（一定要自洽，否则启动即报错）：

```
train_batch_size = micro_batch_size × gradient_accumulation_steps × DP_size
       32        =        4          ×            ?                 ×   DP
```

DP_size 由总卡数 / (TP×PP) 推出。这条等式不成立，DeepSpeed 会直接拒绝启动。

## 7. 一个训练 step 的数据流拆解

```
  原始 token (indexed dataset, mmap)
        │  megatron/data/  按 --split 900,50,50 切 train/valid/test
        ▼
  DataLoader (只在每个 DP 副本的 PP stage0 + TP rank0 真正读盘，其余广播)
        ▼
  forward_step_func(batch, model):          ← pretrain_gpt.py 里你定义的
        embedding → N×TransformerLayer → final norm → output layer
        每层内部：TP all-reduce 把切开的 attention/MLP 结果拼回
        跨 stage：PP send/recv 把激活传到下一 stage
        ▼
  loss（只在最后一个 PP stage 算 cross-entropy）
        ▼
  backward：DeepSpeed engine 触发，梯度 reduce-scatter / all-reduce
        ▼
  optimizer.step()：fused Adam，梯度裁剪 (--clip-grad)，lr 调度 (cosine + warmup)
        ▼
  每 log-interval 打印；每 save-interval 调 checkpointing.py 存（按并行切分分文件存）
```

**checkpoint 的隐藏复杂度**：因为模型被 TP×PP 切碎了，存盘时每个 rank 只存自己那片，目录里会有一堆 `mp_rank_xx`。换并行度（比如从 TP=2 跑到 TP=1）就得用 `tools/convert_checkpoint/` 重新切分合并 —— 这正是同目录 README 里 `deepspeed_to_megatron.py` 做的事。

## 8. 微软版 vs 其它版本

| 版本 | 维护者 | 定位 | 特点 |
|---|---|---|---|
| **Megatron-LM** | NVIDIA | TP/PP 内核，性能基线 | 最纯净，DP 靠自身实现 |
| **Microsoft Megatron-DeepSpeed**（本目录） | Microsoft | Megatron + DeepSpeed 缝合 | ZeRO/MoE/课程学习/压缩齐全，加了 LLaMA/RoPE/GQA |
| **BigScience Megatron-DeepSpeed** | BigScience | 训 BLOOM 用的分支 | 见同级 `bloom-megatron-deepspeed.md`，工程化补丁多 |

选型直觉：要 **ZeRO + 3D 并行 + 国产/异构后端可移植性** → 微软版；只要极致 TP/PP 性能、用 NVIDIA 全家桶 → 原版 Megatron-LM（甚至更新的 Megatron-Core）。

## 常见问题 / 坑

| 现象 | 根因 | 排查方向 |
|---|---|---|
| 启动即 `assert` batch size 不匹配 | `train_batch_size ≠ micro × accum × DP` | 重算 DP_size = 总卡数/(TP×PP)，对齐 ds_config |
| TP 通信极慢、吞吐腰斩 | TP group 跨机跑到 IB 上 | 保证 `TP ≤ 单机卡数`，group 落在 NVLink 内 |
| 换并行度后 ckpt 加载失败 | ckpt 按旧 TP×PP 切分存盘 | 用 `tools/convert_checkpoint` 重切，别直接 load |
| LLaMA 训出来发散/loss 异常 | 漏了 LLaMA 专属 flag | RoPE/SwiGLU/RMSNorm/`disable-bias-linear`/`no-query-key-layer-scaling` 都要带（见脚本注释） |
| 显存仍爆 | 只开了 TP/PP 没省优化器状态 | 提高 `zero-stage`、开 activation checkpointing |
| 非 CUDA 后端报 kernel 缺失 | 代码走了 `device_name()=='cuda'` 专属分支 | 确认该 fused kernel 在目标后端是否有实现，必要时 fallback |
| `bf16` 开了但精度怪 | 部分硬件 bf16 支持/数值不一致 | 核对硬件支持，必要时换 fp16+loss scaling |

> 再次强调：本文聚焦**结构与机制**。具体类/函数/参数默认值，请以你所用 commit 的源码与 DeepSpeed/Megatron 官方文档为准。
