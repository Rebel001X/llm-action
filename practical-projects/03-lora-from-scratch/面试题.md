# LoRA 微调 · 面试题库

> 本题库覆盖 LoRA 的核心原理（低秩分解、秩选择、alpha/r 缩放、B=0 初始化）、与 full-FT / Adapter / Prefix-Tuning 的工程权衡、推理合并与显存估算，以及"能否动手手撕"的实现细节。面 **大模型训练/微调、AI-Infra、算法工程师** 岗几乎必问，PEFT 是高频开场题。答案均结合本项目 `lora.py`（从零实现 + frozen/lora/full 三方对比 demo）作答，可直接背诵应试。

## 一、基础题（概念是否懂）

### Q1. 用一句话说清 LoRA 是什么，核心公式是什么？

**参考答案：** LoRA（Low-Rank Adaptation，论文 arXiv:2106.09685）是一种参数高效微调（PEFT）方法。它**冻结预训练权重 $W_0$，旁路加一个低秩增量 $\Delta W$ 来适配下游任务**：

$$ W_{eff} = W_0 + \Delta W = W_0 + \frac{\alpha}{r} B A,\quad A\in\mathbb{R}^{r\times d_{in}},\ B\in\mathbb{R}^{d_{out}\times r},\ r\ll\min(d_{in},d_{out}) $$

前向写成 $y = xW_0^\top + \frac{\alpha}{r}(xA^\top)B^\top$。本项目 `LoRALinear` 就是这个：冻结 `self.base`，只训练 `lora_A`、`lora_B` 两个小矩阵。

> **追问：** 为什么叫"低秩"适配？
> 因为 $\Delta W = BA$ 的秩至多是 $r$（两个矩阵相乘的秩不超过较小那个的维度）。LoRA 的核心假设是"微调所需的权重更新本身就是低秩的"，所以用一个秩 $\le r$ 的矩阵就能近似它。

### Q2. LoRA 相比全量微调（full fine-tune）省了什么？

**参考答案：** 省的是**可训练参数量**，进而省**显存（梯度 + 优化器状态）**和**存储**：

- 参数量：从 $d_{out}\times d_{in}$ 降到 $r(d_{in}+d_{out})$。本项目 `fc1`(in=64,out=256,r=4)：全量 $256\times64=16384$，LoRA 只有 $4\times(64+256)=1280$。
- demo 整体：full 训 **18696** 个参数，LoRA 只训 **2336** 个，约 **8× fewer**（README 实测）。
- Adam 下每个可训练参数还要存动量 `m`、二阶矩 `v`，所以"参数 + 梯度 + m + v"约 4 份显存——可训练参数少，这部分线性下降。
- 存储：每个下游任务只需保存一份几 MB 的 LoRA 权重，base 共享。10 个任务存 10 份小 adapter，而不是 10 份完整大模型。

> **追问：** LoRA 省的是激活显存吗？
> 不是主要省激活。前向激活仍要为冻结层保留（反传 LoRA 旁路时需要输入 $x$）。LoRA 主要省的是**优化器状态 + 梯度**那部分；激活显存要靠 gradient checkpointing 等正交手段。

### Q3. 本项目里 `lora_A`、`lora_B` 分别怎么初始化？为什么这么初始化？

**参考答案：** 代码里：

```python
self.lora_A = nn.Parameter(torch.empty(r, in_features))
self.lora_B = nn.Parameter(torch.zeros(out_features, r))
nn.init.kaiming_uniform_(self.lora_A, a=math.sqrt(5))
```

- **A 用 kaiming 小高斯随机**（与 HuggingFace PEFT 一致），**B 初始化为全 0**。
- 这样训练起点 $\Delta W = BA = B\cdot A = 0\cdot A = 0$，即 $W_{eff}=W_0$，**模型起点行为与原预训练模型完全一致**，稳定、安全，不会一上来就破坏预训练知识。
- 同时不能两个都置 0：那样梯度恒为 0，旁路永远学不动。一随机一 0 是"既起点等于 base、又训得动"的经典搭配。

> **追问：** 反向传播第一步，A 和 B 谁先动？
> $B$ 先动。$B$ 的梯度 $\propto A$（非零），所以第一步就更新；$A$ 的梯度 $\propto B$（初始为 0），所以 $A$ 第一步几乎不更新，要等 $B$ 离开 0 后才开始学。

### Q4. alpha 和 r 各是什么？scaling 怎么算？

**参考答案：**
- `r`（rank）：低秩旁路的秩，控制旁路**容量**和参数量。
- `alpha`：缩放系数分子，控制旁路相对主干的**强弱（更新幅度）**。
- `scaling = alpha / r`，实际增量是 $\frac{\alpha}{r}BA$。本项目 `alpha=8, r=4 → scaling=2.0`。

设计意图是**解耦"秩大小"与"更新幅度"**：改 $r$ 会改 $BA$ 的数值规模，除以 $r$ 后改 $r$ 时更新幅度大致稳定，不必每次都重调学习率；alpha 则是独立旋钮专调旁路强弱。

> **追问：** 如果想"只改容量不改更新幅度"，怎么调？
> 让 `alpha/r` 保持不变。比如 r 从 4 改到 8，同时把 alpha 从 8 改到 16，scaling 都是 2.0。

### Q5. LoRA 通常注入到模型的哪些层？

**参考答案：** 真实工程（如 PEFT）通常只注入 **attention 的投影矩阵**，最经典是 **q、v**（原论文实验表明只调 q、v 性价比最高），有时也加 k、o 和 FFN 的 up/down/gate。由 `target_modules` 控制。

本项目为最小演示，把 `MLP` 的**所有 `nn.Linear`（fc1、fc2）都注入**了（`inject_lora` 就地把 `nn.Linear` 替换成 `LoRALinear`），这也是 demo 里 `%trainable` 高达 ~11% 的原因之一——真实深层 transformer 只注入部分层、矩阵又大，占比会摊薄到 <1%。

> **追问：** 为什么只调 q、v 就够，而不是每层每矩阵都加？
> 经验上 attention 的低秩更新最能影响表示，q/v 边际收益最高；全注入参数多、收益边际递减。这是容量与成本的权衡，可按任务难度增减 target_modules。

### Q6. 训练完后 LoRA 怎么部署？有额外推理开销吗？

**参考答案：** 部署时可**把旁路合并回主干**，得到一个普通权重：

$$ W_{eff} = W_0 + \frac{\alpha}{r}BA $$

之后就是一个标准 `nn.Linear`，**零额外推理开销**。本项目 `merged_weight()` 实现了这步，并在 main 里数值验证："合并前的 forward" 与 "用 $W_{eff}$ 重算" 的最大逐元素误差 ≈ **3.8e-5**（纯浮点舍入），证明合并数值等价。

> **追问：** 什么情况下不合并、保留旁路？
> 需要"一份 base + 多个 adapter 动态切换"时（多任务/多租户）。合并后就锁死成单一权重，无法热切换；不合并则推理时多一条小矩阵旁路，开销很小但可随时换 adapter。

### Q7. 本项目 demo 跑出来的核心结论是什么？

**参考答案：** 在一个有"分布漂移"的下游任务 B 上对比三种方式（README 实测）：

| method | trainable | %trainable | acc |
|---|---|---|---|
| frozen | 0 | 0% | 0.156 |
| lora | 2336 | 11.11% | 0.994 |
| full | 18696 | 100% | 1.000 |

结论：**LoRA 用比 full 少 8 倍的可训练参数，把准确率从 frozen 基线 0.156 拉到 0.994，补回了 frozen→full 差距的 99.3%**。这就直观验证了 LoRA "用极少参数逼近全量微调效果"的核心卖点。

> **追问：** 为什么 frozen 的 acc 只有 0.156，接近瞎猜？
> 8 分类瞎猜是 0.125。任务 B 对特征做了线性漂移（`Xb = Xb + Xb@drift + 0.8`，旋转+平移），在 A 上训好的 base 直接用就失效，所以接近瞎猜——这正是"需要适配"的剧本设定。

### Q8. LoRA 属于哪一类微调方法？和 prompt/in-context learning 区别？

**参考答案：** LoRA 属于 **PEFT（Parameter-Efficient Fine-Tuning）** 里的"加性/重参数化"一类（往权重旁加可训练增量）。它**改变模型权重**（训练出 A、B），是真训练。

而 prompt engineering / in-context learning **不改任何权重**，靠上下文示例引导，零训练成本但效果上限受限、占用 context 长度。LoRA 是"轻量训练"，prompt 是"不训练"。

## 二、进阶题（原理与权衡）

### Q9. 秩 r 怎么选？大了小了各有什么问题？

**参考答案：** r 是容量-成本的权衡旋钮：

- **r 太小**：旁路容量不足，欠拟合，难表达复杂的下游适配；但若下游任务的"真实更新"本就低秩，小 r（甚至 r=1）也够。
- **r 太大**：参数/显存上升，逼近 full 的成本而失去 PEFT 意义，且大 r 在小数据上易过拟合，收益边际递减。
- **实践**：常用 r=8/16/32；任务越接近预训练分布、数据越少，用越小 r。本项目用 r=4，且 README 练习指出 r=1 在这个 toy 任务上仍能学（因为漂移本身可能是低秩的）。
- **建议**：从小 r 起步，看验证集是否欠拟合再加；改 r 同步考虑是否调 alpha 以稳住 scaling。

> **追问：** 有没有"自动选秩"的方法？
> 有，如 AdaLoRA（按重要性动态分配各层的秩预算）、用 SVD 谱分析估计内在秩。但工程上多数仍靠少量网格搜索 r。

### Q10. LoRA 的"低秩假设"为什么成立？它的理论依据是什么？

**参考答案：** 论文的观察是：**大模型适配下游任务时，权重更新 $\Delta W$ 具有很低的"内在秩（intrinsic rank）"**。即虽然 $\Delta W$ 维度是 $d_{out}\times d_{in}$，但它真正需要的自由度远小于此，可用秩 $r$ 的矩阵很好近似。

直觉支撑：预训练模型已学到通用表示，下游适配往往只是在一个**低维子空间里做调整**（旋转/缩放少数方向），不需要重写整个权重矩阵。本项目刻意构造的任务 B 漂移是低秩线性变换，正好契合该假设，所以 r=4 就能补回 99.3% 的差距。

> **追问：** 如果下游任务和预训练差异极大（高秩更新），LoRA 会怎样？
> 低秩假设变弱，固定小 r 会欠拟合、追不上 full。此时要么加大 r、要么扩 target_modules、要么干脆用 full-FT。LoRA 不是万能的，它赌的是"更新低秩"。

### Q11. 对比 LoRA、Adapter、Prefix/Prompt-Tuning 的优缺点。

**参考答案：**

| 方法 | 机制 | 推理开销 | 可合并 | 特点 |
|---|---|---|---|---|
| **LoRA** | 权重旁加低秩 $BA$ | 合并后**零**额外开销 | ✅ | 效果好、可合并、不占 context；主流首选 |
| **Adapter** | 层间插入小 MLP（瓶颈结构） | **增加**串行层 → 推理变慢/延迟↑ | ❌ 不可合并 | 改变前向结构，增加深度 |
| **Prefix-Tuning** | 给每层 KV 加可训练前缀向量 | 占用 KV、略增计算 | ❌ | 训练参数少，但效果与稳定性不如 LoRA |
| **Prompt-Tuning** | 仅输入端加可训练软 prompt | 占用 context 长度 | ❌ | 最省参数，但表达力弱、对规模敏感 |

LoRA 的关键优势：**可合并 → 推理零开销**，这是 Adapter 最大的痛点（Adapter 串行插层，永远有推理延迟）。

> **追问：** Prefix-Tuning 为什么不能合并回权重？
> 它作用在 attention 的 KV 缓存（每层加可训练前缀 token 的 K、V），是改变"输入序列"而非"权重矩阵"，没有等价的权重合并形式；LoRA 直接加在 $W$ 上，所以能合并。参见本仓库 `../../llm-train/peft/Prefix-Tuning.md`。

### Q12. LoRA 通常需要比 full-FT 更大的学习率，为什么？

**参考答案：** 本项目里 LoRA 用 `lr=5e-2`，full 用 `lr=1e-2`。原因：

1. **可训练参数极少**，每个参数承载更多"适配责任"，需要更大步长才能在有限步数内充分调整。
2. **B 从 0 起步**，前期更新慢（A 要等 B 离 0），需要更激进的 lr 推动。
3. **有 scaling 放大旁路**，但学习率仍是收敛速度的主导旋钮。

README 练习 3 验证：把 LoRA 的 lr 降到 1e-2（和 full 一样），300 步内 acc 达不到 0.994，需把 steps 加到 1000 才追回——直接说明"LoRA 需要更大 lr"不是随便设的。

> **追问：** alpha 调大和学习率调大，效果一样吗？
> 方向类似（都放大有效更新幅度），但不等价。alpha 改 scaling 是对旁路输出的固定线性放大，影响前向与梯度尺度；lr 是优化器步长。实践中常固定 alpha（或 alpha=2r 之类经验比例），主调 lr。

### Q13. 估算：一个 7B 模型用 LoRA 微调，相比 full-FT 大致省多少显存？

**参考答案：** 关键在"可训练参数"那部分的显存（梯度 + Adam 的 m/v）：

- **full-FT**：70 亿参数全可训练。混合精度下粗算每参数约需"权重(fp16,2B) + 梯度(2B) + Adam m/v(fp32, 4+4=8B)"≈ 12–16 字节/参数 → 仅优化器+梯度就要 ~70–110 GB，单卡放不下。
- **LoRA**：base 70 亿只读（fp16，~14GB，无梯度无优化器状态），只有 LoRA 参数（典型 0.1%–1%，几百万到几千万）需要梯度和优化器状态 → 这部分只占几百 MB。
- **结论**：LoRA 把"梯度 + 优化器状态"从几十~上百 GB 砍到 ~GB 级，使 7B 微调能塞进单张消费级卡。**省的核心是优化器状态那 4× 的开销**。

> **追问：** 那为什么还有 QLoRA？LoRA 已经省了优化器状态。
> 因为 base 权重本身（7B fp16 ~14GB，更大模型更多）仍占大头。QLoRA 把 base **4-bit NF4 量化**（~3.5GB），在量化权重上挂 LoRA 旁路，进一步把"冻结主干"的显存砍掉 4×，让单卡能微调 33B/65B。参见 `../../llm-train/qlora` 与 QLoRA 论文 arXiv:2305.14314。

### Q14. 为什么本项目前向写成 `(x @ A.t()) @ B.t() * scaling`，而不是先算 $\Delta W$ 再乘 x？

**参考答案：** 利用矩阵乘法结合律，**永远不显式构造 $d_{out}\times d_{in}$ 的大矩阵**：

- 天真做法：先算 $\Delta W=\frac{\alpha}{r}BA$（和原权重一样大），再 $x(W_0+\Delta W)^\top$ —— 白白构造一个大矩阵，没省内存。
- 本项目做法：$x A^\top$ 先把输入投到 $r$ 维（中间产物只有 `batch×r`，极小），再 $\cdot B^\top$ 升回 $d_{out}$ 维，最后乘 scaling。

中间张量最大只是 `(batch × r)`，计算量也从 $O(d_{out}d_{in})$ 降到 $O(r(d_{in}+d_{out}))$。**只有合并部署时（`merged_weight`）才显式算 $BA$**，因为那时是一次性的。

> **追问：** 那训练时为什么不也合并成大矩阵图省事？
> 合并后梯度会直接作用在 $W_{eff}$ 上，破坏"只训低秩 A、B、冻结 $W_0$"的结构，可训练参数又变回 $d_{out}d_{in}$，失去 PEFT 意义。训练必须保持 A、B 分开。

### Q15. 多个 LoRA adapter 能不能叠加/组合？合并多个会有什么问题？

**参考答案：** 可以叠加，因为增量是线性可加的：$W_0 + \sum_i \frac{\alpha_i}{r_i}B_iA_i$。常见用法：

- **动态切换**：一份 base + 多个未合并 adapter，按请求切换（多任务/多租户）。
- **加权融合**：把多个 adapter 加权相加（如 LoRA 风格融合）。

风险：多个 adapter 的低秩更新可能**相互干扰**（它们在重叠子空间里学的方向冲突），融合后效果不一定是各自之和；且一旦合并就无法再单独卸载。生产里"合并 vs 保留旁路"是延迟 vs 灵活性的权衡。

> **追问：** 服务端要同时服务很多用户的不同 LoRA，怎么高效？
> 用 multi-LoRA 批处理（如 S-LoRA/Punica 思路）：base 共享，不合并，把不同请求的 LoRA 旁路用分组 GEMM 批量算，避免为每个用户存一份完整合并权重。

### Q16. LoRA 会不会带来灾难性遗忘？相比 full-FT 如何？

**参考答案：** LoRA **缓解但不消除**遗忘。机制上：

- base 权重被冻结，预训练知识"物理上"被保留在 $W_0$ 里；适配只通过小幅低秩增量叠加，比 full-FT 大改全部权重更不容易抹掉通用能力。
- 起点 $\Delta W=0$（B=0）等于原模型，训练是从"无害"渐进偏离，比随机扰动安全。
- 但若 r 大、lr 高、数据偏、训练步数多，旁路仍可能把表示拉偏，导致下游过拟合 + 通用能力下降。

所以 LoRA 通常**比 full-FT 更稳、更抗遗忘**，是其受欢迎原因之一，但不是免疫。

> **追问：** 怎么进一步防遗忘？
> 小 r、低 lr、早停；混入少量通用数据（replay）；只注入 q/v 等少数层；评估时同时跑下游指标和通用 benchmark 看是否退化。

## 三、深入 / 手撕题（能否动手 / 追问到底）

### Q17.【手撕】请从零写一个 `LoRALinear`，包装已有 `nn.Linear`、冻结主干、只训低秩旁路。

**参考答案（思路 + 结合本项目实现）：** 关键四步：① 存 base 并冻结；② 建可训练 A（随机）、B（0）；③ forward 走"主干 + 高效低秩旁路"；④ 提供合并接口。

```python
import math, torch
import torch.nn as nn

class LoRALinear(nn.Module):
    def __init__(self, base_linear: nn.Linear, r=4, alpha=8):
        super().__init__()
        assert r > 0
        self.r, self.alpha = r, alpha
        self.scaling = alpha / r                 # 解耦秩大小与更新幅度
        self.base = base_linear
        for p in self.base.parameters():         # ① 冻结主干 W0、bias
            p.requires_grad = False
        d_in, d_out = base_linear.in_features, base_linear.out_features
        self.lora_A = nn.Parameter(torch.empty(r, d_in))   # ② A: (r, in)
        self.lora_B = nn.Parameter(torch.zeros(d_out, r))  #    B: (out, r) 置 0
        nn.init.kaiming_uniform_(self.lora_A, a=math.sqrt(5))

    def forward(self, x):                         # ③ 高效前向，不构造大矩阵
        return self.base(x) + (x @ self.lora_A.t()) @ self.lora_B.t() * self.scaling

    def merged_weight(self):                       # ④ 合并: W_eff = W0 + (a/r)BA
        return self.base.weight.data + self.scaling * (self.lora_B @ self.lora_A)
```

要点能复述：B=0 保证起点 $\Delta W=0$；A、B 用 `nn.Parameter` 默认可训练，base 关掉 `requires_grad`；`.t()` 是因为 `nn.Linear` 权重是 `(out,in)`、前向用右乘。

> **追问：** 如何只把可训练参数交给优化器？
> `torch.optim.Adam((p for p in model.parameters() if p.requires_grad), lr=lr)`。本项目 `train()` 正是这样写——三种方法（frozen/lora/full）共用同一 `train`，区别仅在"哪些参数 requires_grad=True"，这体现了"冻结 vs 训练"的本质就是 `requires_grad` 一个开关。

### Q18.【手撕/验证】怎么用代码证明"合并后的权重"与"未合并前向"数值等价？

**参考答案：** 取一批输入，分别走两条路径，比最大逐元素误差应 ~0：

```python
with torch.no_grad():
    x = X[:8]
    unmerged = layer(x)                          # 走 forward: 主干 + 旁路
    W_eff = layer.merged_weight()                # W0 + (a/r)BA
    merged = x @ W_eff.t() + layer.base.bias     # 用合并权重当普通线性层
    err = (unmerged - merged).abs().max().item()
assert err < 1e-4
```

本项目 main 里这段实测 `err ≈ 3.81e-5`，远小于阈值 `1e-4`，是纯浮点舍入误差。这证明部署时"把旁路合并回主干"前后输出一致 → 合并部署零额外推理开销。

> **追问：** 误差为什么不是恰好 0？
> 两条路径浮点运算的次序/中间精度不同（一条是 `(xA^T)B^T`，一条是 `x(W0+BA)^T`），舍入累积不同，必然有 ~1e-5 量级差异，属正常数值等价。

### Q19.【追问到底】B 如果不初始化为 0，或 A、B 都初始化为 0，分别会怎样？

**参考答案：**
- **B 用随机（非 0）**：起点 $\Delta W = BA \ne 0$，模型一开训就偏离 base，破坏预训练状态，**训练前期可能不稳定/损失抖动**，丧失"安全起点"的好处。
- **A、B 都置 0**：$\Delta W=0$ 没问题，但此时 A 的梯度 $\propto B=0$、B 的梯度 $\propto A=0$，**两者梯度恒为 0，旁路永远学不动**，LoRA 等于没注入。

所以必须 **一个随机、一个 0**：A 随机保证有梯度流，B=0 保证起点等于 base。这是兼顾"稳定起点"和"可训练"的唯一可行搭配。

> **追问：** 能不能反过来 A=0、B 随机？
> 理论上对称——只要保证 $BA=0$ 起步且不全 0 即可。实践中 PEFT 约定 A 随机、B=0（A 是"读出/降维"先有信息，B 是"写入/升维"从 0 渐进），本项目遵循此约定，与 HuggingFace PEFT 一致。

### Q20.【场景题】给你一个 7B 模型 + 单张 24GB 卡，要在自有数据上微调，你怎么设计方案？

**参考答案：** 分层决策：

1. **方法选型**：单卡 24GB 放不下 7B 的 full-FT（光优化器状态就几十 GB），首选 **LoRA**；若 base fp16(~14GB)+激活仍紧张，用 **QLoRA**（4-bit NF4 量化 base → ~3.5GB，腾出空间放更长序列/更大 batch）。
2. **注入层**：先只注入 **q、v**（性价比最高），不够再加 k、o 和 FFN。
3. **超参**：r 从 8/16 起步，alpha 取 ~2r，lr 比 full 大（如 1e-4~3e-4 量级，比预训练大），配 cosine/warmup。
4. **省显存正交手段**：gradient checkpointing、混合精度、合适的 batch + 梯度累积。
5. **评估与部署**：验证集看是否欠拟合（欠拟合则加 r 或 target_modules）；部署时把 adapter `merge` 回权重做零开销推理，或保留旁路以支持多 adapter 切换。

> **追问：** 怎么判断该加大 r 还是该上 full-FT？
> 看 LoRA 是否欠拟合：若训练/验证 loss 都降不下去、与小规模 full-FT 探针差距大，说明低秩假设不够，先加大 r / 扩 target_modules；若加到很大 r（接近 full 成本）才追平，那不如直接 full-FT。

### Q21.【追问到底】本项目 demo 的 `%trainable` 是 11.11%，但论文说 LoRA <1%，矛盾吗？

**参考答案：** 不矛盾，是**规模差异**导致的：

- 占比公式：可训练 / 总参数 = $\frac{\sum r(d_{in}+d_{out})}{\sum d_{in}d_{out}}$。base 矩阵越大、层越多，分母涨得比分子快，占比越低。
- demo 只有 **2 个小线性层**（fc1 64×256、fc2 256×8），且**全注入**，分母小，所以占比天然 ~11%（fc1 旁路 1280 + fc2 旁路 1056 = 2336，base 18696 → 11.11%）。
- 真实 7B：几十~上百个**大**矩阵，且常只注入 q/v 少数层，分母巨大，同样 rank-r 旁路占比摊薄到 **0.1%~1%**。

结论"用极少参数逼近全量"在两个尺度上一致，只是数字尺度不同。**别拿 toy demo 的占比去对标论文**（README 局限第 1 条明确说明）。

> **追问：** 那 demo 为什么把 HIDDEN 设到 256 这么大？
> 故意的——让 base 主干参数更多，使 LoRA 旁路相对显小，复现"base 越大、旁路占比越低"这一真实大模型的优势来源，让 demo 的趋势更接近真实场景。

### Q22.【手撕思路】如果让你把本项目的 `inject_lora` 改成"只注入指定层（如 q/v）"，怎么改？

**参考答案：** 把"无条件替换所有 `nn.Linear`"改成"按名字/类型筛选后替换"，对应 PEFT 的 `target_modules`：

```python
def inject_lora(model, r, alpha, target_names=("fc1",)):
    for name, module in model.named_children():
        if isinstance(module, nn.Linear) and name in target_names:
            setattr(model, name, LoRALinear(module, r=r, alpha=alpha))
        # 未命中的 nn.Linear 要显式冻结，避免被 train 当可训练参数
        elif isinstance(module, nn.Linear):
            for p in module.parameters():
                p.requires_grad = False
    return model
```

要点（结合 README 练习 5）：**未注入的普通 `nn.Linear` 默认 `requires_grad=True`，会被 `train` 当可训练参数误训**，所以必须手动 `requires_grad=False` 冻结它，才是干净的"只注入部分层"对照。真实模型里要递归遍历 `named_modules` 并按模块名匹配（如包含 `q_proj`/`v_proj`）。

> **追问：** 只注入 fc1、冻结 fc2，效果预期如何？
> 可训练参数进一步减少，但 acc 通常下降——因为分类头（fc2）没法适配漂移。这正是真实工程"注入哪些层"的取舍：注入越多越能适配但越贵，要按任务找平衡。

## 高频追问速答清单

1. **LoRA 一句话？** 冻结主干 $W_0$，旁加低秩可训练增量 $\frac{\alpha}{r}BA$ 来适配下游。
2. **为什么省显存？** 可训练参数少 → 梯度 + Adam 优化器状态（m/v，约 4×）大幅下降。
3. **B 为什么置 0？** 保证起点 $\Delta W=0$，模型等于原 base，稳定安全。
4. **A、B 能都置 0 吗？** 不能，梯度恒 0 学不动；必须一随机一 0。
5. **scaling 公式？** $\alpha/r$，解耦"秩大小"与"更新幅度"，改 r 不必重调 lr。
6. **注入哪些层？** 经典只注入 attention 的 q、v，由 target_modules 控制。
7. **推理开销？** 合并 $W_{eff}=W_0+\frac{\alpha}{r}BA$ 后零额外开销；不合并则可多 adapter 切换。
8. **r 怎么选？** 小起步看是否欠拟合再加，常用 8/16/32；越接近预训练用越小。
9. **LoRA vs Adapter？** Adapter 串行插层、推理变慢且不可合并；LoRA 可合并、零开销。
10. **LoRA vs QLoRA？** QLoRA = base 4-bit NF4 量化 + LoRA，再省冻结主干那部分显存。
11. **前向为何 (xA^T)B^T？** 用结合律避免构造 $d_{out}\times d_{in}$ 大矩阵，省算省存。
12. **低秩假设？** 下游适配的权重更新内在秩很低，能被秩 r 矩阵近似。
