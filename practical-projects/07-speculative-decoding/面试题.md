# 投机采样 / 投机解码（Speculative Decoding）· 面试题库

> 本题库覆盖投机采样的全链路考点：draft + verify 两阶段、接受准则 `min(1, p/q)` 与回退重采、无损性（lossless）的数学证明、平均接受长度与加速比、draft 模型选型、加速来源（memory-bound 本质）、以及内存/算力代价与工程难点（KV-Cache 回滚、batch 验证）。**面向 LLM 推理加速 / AI-Infra / 大模型工程岗**（vLLM/SGLang/TensorRT-LLM 方向尤其高频），也是大模型算法岗推理优化部分的常考题。答案均可结合本目录 `speculative_decoding.py`（纯 numpy toy 实现）作答。

## 一、基础题（概念是否懂）

### Q1. 一句话说清投机采样在解决什么问题，核心思路是什么？

**参考答案：**
LLM 自回归解码是**严格串行**的——一次 target 前向只产出 1 个 token，而大模型推理是 **memory-bound（访存受限）** 的：把上百亿权重从显存搬到计算单元的代价，跟你这次前向算 1 个位置还是算 100 个位置几乎一样。所以"每次前向只出 1 token"严重浪费了带宽。

投机采样的思路：用一个便宜的小模型 **draft** 一口气串行猜 `k` 个 token，再让大模型 **target 并行地一次前向验证**这 k 个候选；被接受的直接采纳，第一个被拒的位置用一个修正分布重采。**关键收益：一次 target 前向能确认多个 token**，从而把 target 前向次数从 `n` 降到约 `n / 平均接受长度`。

本项目 `speculative_decoding.py` 用字符级 n-gram 当 target/draft，实测 200 个 token 的 target 前向从 200 次降到 ~84 次，加速约 2.38x，而输出分布与纯 target 采样统计上不可区分。

### Q2. "无损（lossless）"具体指什么？投机采样无损是指 draft 也很准吗？

**参考答案：**
无损指的是**最终产出的 token 序列服从的概率分布，与"纯 target 自回归采样"逐 token 完全一致**。它**与 draft 质量无关**：哪怕 draft 是个瞎猜的均匀分布，输出分布也不偏，draft 只影响**速度（接受率）**，不影响**分布**。这正是它优于"直接用小模型生成"或"不确定时才让大模型介入"的地方——后两者都会改变分布、没有数学保证。

本项目用蒙特卡洛验证这点：固定 prompt，基线和投机各采 8000 次"下一个 token"，比经验分布的总变差 TV。结果 `TV(投机, 真分布)=0.0036` 甚至**小于** `TV(基线, 真分布)=0.0056`——投机的偏差完全淹没在采样噪声里。

> **追问：那为什么还要 draft 越准越好？** 因为接受率 α 决定平均接受长度，进而决定加速比；draft 越接近 target，α 越高、每轮确认的 token 越多。准不准影响**快不快**，不影响**对不对**。

### Q3. 写出接受准则的公式，并解释两种情形的直觉。

**参考答案：**
draft 给分布 $q$、target 给分布 $p$，draft 已从 $q$ 采出候选 token $x$，则以概率
$$\alpha(x)=\min\!\Big(1,\ \frac{p(x)}{q(x)}\Big)$$
接受 $x$。

- 若 $p(x)\ge q(x)$（target 比 draft 更看好 $x$）：$\alpha=1$，**必接受**——draft 没"过度自信"，没问题。
- 若 $p(x)<q(x)$（draft 比 target 更看好 $x$，可能瞎猜）：以比例 $p(x)/q(x)$ **打折接受**，把 draft 多采的那部分概率质量退回去。

对应本项目代码：`accept_prob = min(1.0, p[x] / q[x]); if rng.random() < accept_prob: accept`。

### Q4. 一个候选被"拒绝"后怎么办？为什么不能直接结束这一轮？

**参考答案：**
拒绝后这个位置**还没产出 token**，不能空着。要从**修正分布（residual / corrected distribution）**重采一个：
$$p_{\text{res}}(\cdot)=\frac{\big(p(\cdot)-q(\cdot)\big)_+}{\sum_y\big(p(y)-q(y)\big)_+},\qquad (z)_+\triangleq\max(z,0).$$
直觉：`(p-q)_+` 只保留"target 比 draft 更想要、但 draft 给少了"的那些 token 上的概率缺口，归一化后采样，正好把漏掉的质量补回来。

重采出 `x_fix` 之后**必须 break、丢弃这个位置之后的所有 draft 候选**——因为后面的 `proposals[j+1]` 是基于"前面都被接受"生成的，一旦第 j 位被改掉，后面提议的上下文就失效了，必须从新位置开始下一轮。

> **追问：修正分布会不会出现分母为 0？** 当 $p\equiv q$ 时 `(p-q)_+` 全为 0。本项目用加性平滑保证概率全 >0，并加了兜底 `if s <= 0: residual = p`。自己实现时务必处理。

### Q5. 加速到底来自哪里？是"少跑了前向"吗？

**参考答案：**
**不是少跑前向，而是"一次 target 前向产出了多个 token"。** 本质上是把"串行 N 步"压成"并行验证 + 串行 N/L 轮"（L=平均接受长度）。每一轮无论接受几个 token，**target 只算 1 次前向**（代码里 `target_forwards += 1` 在整轮 while 里只出现一次）。

利用的是 memory-bound 特性：一次前向把权重搬上来，顺便多算几个位置的代价很低（算力本来就没吃满），却能确认多个 token。本项目里 `tokens per target forward = n_new / target_forwards = 200/84 ≈ 2.38`，就是"每次大模型前向平均吐 2.38 个 token"。

### Q6. 什么是"平均接受长度（average acceptance length）"？它和加速比什么关系？

**参考答案：**
平均接受长度 = 平均每轮被接受的 draft 提议数（本项目 `avg_accept_len`，实测约 1.393，1-gram draft 较糙所以不高）。

加速比定义为"产出同样多 token 时 target 前向减少多少倍"：
$$\text{speedup}=\frac{\text{target forwards (纯 AR)}}{\text{target forwards (投机)}}.$$
近似地 speedup ≈ 每次 target 前向产出的 token 数。本项目里 `tokens per forward (2.38)` 比 `avg_accept_len (1.39)` 大约多 1，那个 ≈1 来自"全接受时的免费 bonus 一步"（见 Q12）。

> **追问：是不是接受长度越高越好？** 趋势是。但还要权衡 draft 本身的成本——真实工程里 draft 也要花时间/显存，接受长度不够高时 draft 开销可能吃掉收益甚至净亏。

### Q7. draft 模型一般怎么选？有哪些路线？

**参考答案：**
核心要求：draft 要**和 target 足够对齐（猜得准 → 接受率高）**且**自身足够便宜**，二者权衡。常见路线：

1. **独立小模型**：同系列的更小模型（如 7B 当 13B/70B 的 draft），共享 tokenizer。最直接，但要额外加载一个模型、占显存。
2. **n-gram / 检索式 draft**（prompt lookup）：从已生成文本或 prompt 里检索续写，零模型成本，对重复性强的文本（代码、长引用）很有效。
3. **自蒸馏的解码头**：**Medusa**（在 target 上加多个并行预测头）、**EAGLE**（在特征层做自回归 draft，对齐度更高）——省掉独立 draft 模型，接受率通常更高。

选型看场景：通用对话常用同族小模型或 EAGLE；高重复场景用 n-gram。本项目用 1-gram 当 draft、3-gram 当 target，正是"独立小模型"思路的极简版。

> **追问：draft 和 target 必须同 tokenizer 吗？** 经典投机采样需要逐 token 比较 `p[x]/q[x]`，所以**词表/tokenizer 必须一致**。跨 tokenizer 需要额外对齐技巧（如近年的 token 对齐方案），是工程难点之一。

### Q8. 投机采样和贪心解码（greedy）下的"验证"有什么区别？

**参考答案：**
- **采样模式（temperature>0）**：用上面的 `min(1,p/q)` 接受 + `(p-q)_+` 回退，保证采样分布无损。本项目验证无损用的就是 `rng.choice(p=...)` 而非 argmax——无损保证的是**采样分布**，不是单点。
- **贪心 / 近似 argmax**：可退化为简单的"逐位比对 target 的 argmax 是否等于 draft 提议"——相等则接受。这本质是采样准则在 temperature→0 时的特例。

易错点：拿 argmax 去验证"无损"是错的——必须用采样来比经验分布。

## 二、进阶题（原理与权衡）

### Q9. 证明：经过"从 q 采、按 α 接受、否则从修正分布重采"后，产出 token = x 的总概率恰为 p(x)。

**参考答案：**
产出 $x$ 有两条路径：

**(1) 接受路径**：draft 采到 $x$（概率 $q(x)$）且被接受（概率 $\alpha(x)=\min(1,p(x)/q(x))$）：
$$q(x)\cdot\min\!\Big(1,\tfrac{p(x)}{q(x)}\Big)=\min\big(q(x),p(x)\big).$$

**(2) 回退路径**：发生一次拒绝（任意 token 被拒），再从 $p_{\text{res}}$ 采到 $x$。一次拒绝总概率：
$$\beta=\sum_y q(y)\big(1-\alpha(y)\big)=\sum_y\big(q(y)-\min(q(y),p(y))\big)=\sum_y\big(p(y)-q(y)\big)_+,$$
（因 $\sum p=\sum q=1$，正负缺口绝对值相等）。从 $p_{\text{res}}$ 采到 $x$ 的概率为 $\frac{(p(x)-q(x))_+}{\beta}$，相乘 $\beta$ 约掉，得 $\big(p(x)-q(x)\big)_+$。

两路径相加：
$$\min\big(q(x),p(x)\big)+\big(p(x)-q(x)\big)_+=p(x).$$
（若 $p(x)\le q(x)$：$p(x)+0$；若 $p(x)>q(x)$：$q(x)+(p(x)-q(x))$，均 $=p(x)$。）∎

这就是 Leviathan et al. 2022（arXiv:2211.17192）定理 1。结论：**无论 draft 多烂，分布都不偏。**

> **追问：这个 β 还有什么含义？** $\beta$ 正是单个位置的**拒绝概率**，$1-\beta=\sum_y\min(p(y),q(y))$ 是接受率，等于 $p,q$ 的"重叠面积"（$1-\frac12\|p-q\|_1=1-\mathrm{TV}(p,q)$）。**接受率 = 1 − TV(p,q)**，这把"draft 多接近 target"直接量化成了"加速多少"。

### Q10. 推导：给定单步接受率 α，提议数 k，一轮期望产出多少 token？最优 k 怎么定？

**参考答案：**
假设各位置独立、接受率均为 α。一轮里"连续接受直到第一次失败"，**期望被接受数**为
$$\mathbb{E}[\#\text{accepted}]=\sum_{i=1}^{k}\alpha^{i}=\frac{\alpha(1-\alpha^{k})}{1-\alpha}.$$
加上"第一次拒绝处的回退 token"或"全接受的 bonus token"，一轮**期望产出**约为
$$\mathbb{E}[\#\text{produced per round}]=\frac{1-\alpha^{k+1}}{1-\alpha}.$$
α→1 时趋于 k+1（全确认）；α 小时趋于 1（基本退化成普通解码）。

**最优 k**：增大 k，初期产出上升但**收益递减**——因为一旦中途某位被拒，后面提议全废，多猜的部分白费；而真实工程里每多猜一个 draft 还要花成本。所以存在权衡，需结合 draft/target 的相对成本 c=draft 前向耗时/target 前向耗时 来求每"墙钟时间"产出最大的 k*，通常是个小整数（4~8）。本项目练习 3 就是扫 k 观察收益递减。

> **追问：α 与 k 哪个对加速影响更大？** α 更"硬"——它是指数底，α 接近 1 时收益爆发式增长；k 是边际递减的。所以工程上提升 draft 对齐度（EAGLE/蒸馏）通常比单纯加大 k 更值。

### Q11. 投机采样对"延迟"和"吞吐"分别是什么影响？大 batch 下为什么收益会缩水？

**参考答案：**
- **低并发/单请求（延迟敏感）**：收益最大。此时系统是 memory-bound，GPU 算力闲置，投机用闲置算力换 token，延迟显著下降。
- **大 batch / 高吞吐**：收益缩水甚至变负。大 batch 时系统已逼近 **compute-bound**，并行验证 k 个位置不再"白嫖"——它实实在在消耗算力（验证的 FLOPs 约放大 k 倍），而被拒的 token 是纯浪费。同时 draft 阶段也占资源。所以投机采样**最适合低延迟/小 batch 场景**，serving 系统常按负载动态开关或调 k。

一句话总结取舍：**投机采样用 FLOPs 换 latency**——算力富余时是净赚，算力紧张时是赔本。

> **追问：能不能让被拒的 token 不浪费？** 一定程度可以——multi-candidate / tree attention（Medusa、SpecInfer）一次验证多条候选分支组成的树，提高单次前向的命中期望，部分对冲被拒浪费。

### Q12. 解释本项目里的"免费 bonus 一步"，它为什么不破坏无损？

**参考答案：**
当一轮里 k 个提议**全部接受**时，target 在验证时其实已经顺便算出了"第 k+1 个位置"的分布 `p_extra`（代码里多算一位）。既然这个分布是 target 自己的、且不额外花前向，就直接从 `p_extra` 免费采 1 个 token。于是**一轮最多前进 k+1 个 token**，而仍只算 1 次 target 前向。

不破坏无损：因为 bonus token 是**直接从 target 真分布 `p_extra` 采样**的，本就服从 target 分布，无需接受/回退。本项目里 `tokens per forward (2.38) ≈ avg_accept_len (1.39) + 1`，那个 +1 主要就是 bonus 贡献。

### Q13. 投机采样的内存/算力代价有哪些？工程上最难的是什么？

**参考答案：**
**代价：**
- **显存**：要额外驻留 draft 模型（独立小模型路线）及其 KV-Cache；tree/multi-candidate 还要更多。
- **算力（FLOPs）**：验证阶段把 k+1 个位置一起算，FLOPs 约放大 (k+1) 倍；被拒的 token 是浪费。draft 阶段也消耗算力。
- **调度复杂度**：draft 串行 k 步 + target 验证,流水线编排比普通解码复杂。

**最难的工程点：KV-Cache 的回滚/复用。** 验证后接受了前 m 个、拒了第 m+1 个，必须：保留接受前缀对应的 target KV、**丢弃被拒位置及其之后的 KV**，并在下一轮基于正确前缀重建。draft 模型的 KV 同理。本项目作为 toy 实现**故意没做 KV-Cache 回滚**（每步重算分布），手把手教学第 6 节明确指出这才是真实系统最难处。参见 `../../llm-inference/KV-Cache优化.md`。

> **追问：tree attention 的 KV 管理为什么更难？** 树形多候选时，不同分支共享前缀但分叉后各有 KV，需要带 mask 的 attention 让每个节点只看自己祖先，接受一条路径后还要裁剪掉其它分支的 KV，内存与 mask 管理都更复杂。

### Q14. 为什么本项目用 n-gram 而不是 Transformer？这会影响结论的普适性吗？

**参考答案：**
因为**投机采样的接受准则与修正分布是"与具体模型无关"的纯概率算法**——只要 draft/target 都能吐出"下一 token 的完整分布"，算法一字不改。用可枚举的字符级 n-gram，能在 CPU 上几秒内**严格验证分布等价**（枚举整个长度~28 的词表算 TV），教学信号最干净。真实工程把 draft/target 换成两个 Transformer 即可，结论完全普适。

唯一不普适的是"成本模型"：toy 实现把 target 验证计为 1 次前向是**概念上的**，没有真正的 batch kernel、没有 KV-Cache，所以加速数字只反映"前向次数比",不代表真实墙钟加速。

### Q15. 平滑（smoothing）在这里为什么是必须的？去掉会怎样？

**参考答案：**
加性平滑 `counts + smoothing` 保证每个 token 概率严格 >0。两个地方会因 0 概率崩掉：
1. 接受准则 `p[x]/q[x]`：若 `q[x]=0`（draft 给某 token 0 概率却又采到了，或数值问题）会除零/inf。
2. 修正分布 `(p-q)_+/Z`：若 p≡q 则分母 Z=0。

平滑让 p、q 处处为正，避免上述病态；`smoothing` 还充当"模型糙细"旋钮——越大分布越糊、模型越像瞎猜。真实 Transformer 输出经 softmax 天然处处 >0，但工程上仍要对 `q[x]` 加 epsilon 或用 `log` 域算比值防数值问题。

> **追问：smoothing 影响无损吗？** 不影响无损（无损对任意合法 q 都成立），只影响接受率/加速。这正是练习 2"把 draft 调到接近均匀仍 PASS"想让人亲眼看到的。

### Q16. 如果 draft 和 target 用不同温度（temperature）/ top-p 采样，准则要怎么调整？

**参考答案：**
关键：**接受/回退准则比较的 p、q 必须是各自实际采样所用的、经过相同后处理的分布。** 也就是说 target 的目标分布 p 应是"target 施加了目标 temperature/top-p 之后"的分布；draft 的 q 是"draft 实际采提议时所用"的分布。只要 p、q 定义一致，`min(1,p/q)` + `(p-q)_+` 的无损证明照样成立（证明只依赖 p、q 是两个合法分布）。

实践注意：top-p/top-k 截断会把分布置零,又回到平滑/数值兜底问题;且 draft 与 target 截断集合不同会降低接受率。常见做法是验证时用 target 的目标分布 p,draft 提议分布 q 不必与 p 同截断,准则会自动纠偏。

## 三、深入 / 手撕题（能否动手 / 追问到底）

### Q17.【手撕思路】请写出投机采样一轮的核心伪代码（结合本项目结构）。

**参考答案：** 对应 `speculative_sample` 的一轮 while：

```python
# 1) draft 串行猜 k 个, 记录每个位置的 draft 分布 q
draft_seq = list(ids); proposals, q_list = [], []
for _ in range(k):
    q = draft_lm.dist(draft_seq)          # 便宜的小模型前向
    x = rng.choice(len(q), p=q)
    proposals.append(x); q_list.append(q); draft_seq.append(x)

# 2) target 并行验证: 给 k 个位置打分 (概念上 1 次前向)
p_list, ctx = [], list(ids)
for j in range(k):
    p_list.append(target_lm.dist(ctx)); ctx.append(proposals[j])
p_extra = target_lm.dist(ctx)             # 全接受后那一位, 给 bonus
target_forwards += 1                      # 整轮只 +1 !!

# 3) 逐 token 接受 / 拒绝
rejected = False; n_accept = 0
for j in range(k):
    x, p, q = proposals[j], p_list[j], q_list[j]
    if rng.random() < min(1.0, p[x] / q[x]):
        ids.append(x); n_accept += 1                  # 接受
    else:
        res = np.clip(p - q, 0.0, None); res /= res.sum()  # (p-q)_+ 归一
        ids.append(rng.choice(len(res), p=res))       # 回退重采
        rejected = True; break                         # 丢弃后续候选

# 4) 全接受则 bonus: 用 target 自己的分布免费再采 1 个
if (not rejected) and n_accept == k:
    ids.append(rng.choice(len(p_extra), p=p_extra))
```

**面试官关注的踩坑点**：(a) `target_forwards += 1` 必须在整轮只出现一次（否则加速比算错）；(b) 拒绝后必须 `break` 丢弃后续；(c) 修正分布要归一并做 0 兜底；(d) 验证用 `rng.choice(p=...)` 而非 argmax。

> **追问：真实 Transformer 里"target 并行验证"具体怎么实现？** 把 `[ids 末位, proposal_1, ..., proposal_k]` 拼成长度 k+1 的输入，配 causal mask 做**一次** forward,一次拿到 k+1 个位置的 logits。这才是"1 次前向"的物理含义,toy 用循环逐位算只是为了好懂。

### Q18.【手撕思路】如何用蒙特卡洛**验证无损**？请说明判定标准。

**参考答案：** 思路（对应 `verify_distribution`）：固定同一 prompt，分别用基线 AR 与投机各采 `n_trials`（本项目 8000）次"下一个 token"，统计两个**经验分布** `emp_ar`、`emp_sp`，再算总变差
$$\mathrm{TV}(P,Q)=\tfrac12\sum_x|P(x)-Q(x)|.$$
同时把它们都和 target 的**理论真分布** `true_p` 比。

**判定标准不是 TV=0**（经验分布永远有采样噪声），而是
```python
ok_lossless = tv_sp_true <= tv_ar_true + 0.02
```
即"投机 vs 真分布的偏差 ≤ 基线 vs 真分布的偏差 + 容差"——投机的偏差和**基线自己的采样噪声同量级**就算无损。本项目实测 `tv_sp_true=0.0036 < tv_ar_true=0.0056`,甚至比基线还小,判定 PASS。

> **追问：为什么验证只看"下一个 token"而不是整条序列？** 因为只要单步无损,由链式法则整条自回归序列就无损;单步边缘分布是可枚举、可统计的最小充分检验单元,验证最干净。

### Q19. 给定一组实验现象，让你定位/调优。

**场景**：把 draft 的 `smoothing` 从 0.30 提到 1.0 后，`avg_accept_len` 掉到接近 1，`speedup` ≈ 1x，但无损判定仍 PASS。请解释每个现象，并说该怎么救加速。

**参考答案：**
- `smoothing=1.0` 使 draft 分布趋近**均匀**（更糙、更像瞎猜），与 target 的重叠 `1-TV(p,q)` 变小 → **接受率 α 暴跌** → 平均接受长度趋近 1 → 每次 target 前向基本只确认 1 个 token → speedup≈1x。
- **无损仍 PASS** 是预期内的——无损对任意合法 q 成立，draft 烂**只伤速度不伤分布**。这恰恰是该亲眼看到的核心结论。
- **救加速的正路是提升 draft 与 target 的对齐度**：调小 draft 的 smoothing、加大 draft 的 order（练习 1：order=2, smoothing=0.05），或换更强 draft（蒸馏/EAGLE）。盲目加大 k 帮助有限,因为 α 太低时收益被指数压制。

> **追问：如果 draft 改强后 speedup 上去了但墙钟反而变慢，可能是什么？** toy 不计 draft 成本,但真实系统 draft 也花时间——draft 变大若耗时增长超过接受率带来的收益,墙钟净亏;要按 c=draft/target 耗时比重新权衡 draft 规模与 k。

### Q20. 投机采样 vs Medusa vs EAGLE，核心区别与各自取舍？

**参考答案：**
- **经典投机采样（Leviathan/Chen）**：独立 draft 模型串行猜 + target 接受/回退。优点：无损、即插即用、draft 可换；缺点：需额外加载/对齐一个模型、串行 draft 有延迟、跨 tokenizer 难。
- **Medusa**：在 target 顶部加多个**并行预测头**，一次性预测后续多个位置，配 tree attention 验证多候选。优点：不需独立 draft、省显存；缺点：原始版用接受策略可能非严格无损（需 typical acceptance），头之间独立预测对齐度有限。
- **EAGLE**：在 target 的**特征/隐层**上做轻量自回归 draft（而非在 token 上），对齐度高、接受率显著优于独立小模型;EAGLE-2/3 进一步用动态草稿树。优点：接受率高、加速大;缺点：与具体模型耦合、需训练 draft 头。

一句话取舍：要**通用无损+可插拔**选经典投机；要**省显存+高接受率**选 EAGLE 系;Medusa 是早期"自带头"思路的代表。本项目实现的是最经典、最便于理解无损证明的版本。

### Q21.【追问到底】真实 serving 系统里，投机采样和连续批处理（continuous batching）、PagedAttention 如何共存？有哪些冲突？

**参考答案：**
- **与 continuous batching**：batch 内不同请求的接受长度不同 → 每步前进的 token 数参差不齐,调度器要处理"变长前进"、动态拼批,复杂度高于普通解码。大 batch 下投机收益缩水(Q11),所以 vLLM/SGLang 常按负载动态决定是否启用或调 k。
- **与 PagedAttention / KV 分页**：接受/回退要在分页 KV 上正确地"提交接受前缀、回收被拒页",draft 与 target 各有一套 KV;tree 投机还要管共享前缀分页 + 分支裁剪。这是工程上最易出 bug 的地方(KV 没回滚干净 → 分布错/越界)。
- **与目标无损**：要确保接受准则用的 p 是经过该请求实际 temperature/top-p 后处理的分布,batch 内逐请求参数不同时尤其要小心。

落到本项目:它故意不碰这些(无 KV-Cache、无批处理),把无损算法本身讲透;`../../llm-inference/` 下 vLLM/SGLang/TensorRT-LLM 各分区才是这些工程问题的去处。

> **追问：n-gram / prompt-lookup draft 为什么在 serving 里很受欢迎？** 零模型成本、零额外显存、无 tokenizer 对齐问题,对代码补全、RAG 长引用、改写等"输出大量复用输入"的场景接受率极高,性价比最好,常作为默认 proposer 之一。

## 高频追问速答清单

1. **加速来自哪？** 一次 target 前向产出多个 token（memory-bound 富余算力换 token），不是少跑前向。
2. **无损靠什么？** `min(1,p/q)` 接受 + `(p-q)_+` 修正分布重采，可证产出概率恰为 p(x)。
3. **draft 烂会怎样？** 只降速度（接受率），不破坏分布——无损与 draft 无关。
4. **接受率 = ?** `1 − TV(p,q)` = p、q 重叠面积，draft 越像 target 越高。
5. **平均接受长度 ≈ ?** $\frac{1-\alpha^{k+1}}{1-\alpha}$，α→1 趋于 k+1。
6. **拒绝后必须做什么？** 从 `(p-q)_+` 重采 1 个并 break 丢弃后续候选。
7. **bonus 一步为何无损？** 直接从 target 真分布采，本就服从 p。
8. **最适合什么场景？** 低延迟 / 小 batch；大 batch（compute-bound）收益缩水。
9. **最大工程难点？** KV-Cache 的接受提交 / 回退回收，draft+target 双份 KV。
10. **draft 选型？** 同族小模型 / n-gram(prompt-lookup) / Medusa / EAGLE。
11. **必须同 tokenizer 吗？** 经典版必须（要逐 token 比 p/q），跨 tokenizer 需额外对齐。
12. **怎么证无损？** 蒙特卡洛比经验分布 TV，判定标准是"投机偏差 ≤ 基线采样噪声 + 容差"，非 TV=0。
