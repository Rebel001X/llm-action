# DPO 对齐 · 面试题库

> 本题库覆盖 DPO（Direct Preference Optimization）的推导、隐式奖励、beta、参考模型、与 RLHF/PPO 的对比、以及过拟合/reward hacking 等高频考点。适合面 **大模型对齐/RLHF 工程师、LLM Infra、算法研究** 岗，也常作为"看你 RLHF 链路是否真懂"的追问入口。答案均可结合本项目 `dpo.py` 的最小实现作答。

---

## 一、基础题（概念是否懂）

### Q1. 一句话说清 DPO 是什么？它解决了 RLHF 的什么痛点？
**参考答案**：DPO 是一种**绕过显式奖励模型（RM）和 PPO 强化学习**的偏好对齐方法。传统 RLHF 链路是 `SFT → 训 RM → PPO 最大化 RM 奖励`，三段式又重又脆。DPO 的洞察是：对"Bradley-Terry 偏好模型 + KL 正则的 RLHF 目标"，其最优策略有**解析解**，反解可把奖励重参数化为"策略与参考模型的对数概率比"，于是整个对齐**坍缩成一个 sigmoid 二分类监督损失**，直接在偏好对 `(prompt, chosen, rejected)` 上做梯度下降即可。痛点：省掉训 RM、省掉 PPO 的不稳定与在线采样开销、KL 约束被隐式编码进损失。

### Q2. DPO 的训练数据长什么样？为什么说它"只要相对偏好、不要绝对分数"？
**参考答案**：每条样本是 `(prompt x, chosen y_w, rejected y_l)`——同一 prompt 下 $y_w \succ y_l$。它**不需要**"这句 8 分那句 3 分"这种绝对奖励标注，只要"哪个更好"的相对关系。本项目里就是同一 `PROMPTS` 配 `POSITIVE`（chosen）和 `NEGATIVE`（rejected）。相对偏好比绝对评分更易标、标注者一致性更高，这也是偏好数据相对奖励标注更廉价的根本原因。

### Q3. 写出 DPO 损失，并解释每一项。
**参考答案**：
$$\mathcal{L}_{\text{DPO}}=-\mathbb{E}_{(x,y_w,y_l)}\Big[\log\sigma\Big(\beta\big(\log\tfrac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)}-\log\tfrac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\big)\Big)\Big]$$
- $\pi_\theta$：待训练策略；$\pi_{\text{ref}}$：冻结的参考模型（通常 SFT 权重拷贝）。
- 括号内是 chosen 的对数比减 rejected 的对数比，乘 $\beta$ 就是 sigmoid 的 logit。
- $-\log\sigma(\cdot)$ 是逻辑回归式的负对数似然：**logit 越大 → loss 越小 → chosen 越受偏好**。
本项目 `dpo_loss()` 就是这一行：`logits = beta*(pi_logratio_chosen - pi_logratio_rejected); loss = -F.logsigmoid(logits)`。

### Q4. 什么是"隐式奖励"（implicit reward）？
**参考答案**：$\hat r(x,y)=\beta\big(\log\pi_\theta(y|x)-\log\pi_{\text{ref}}(y|x)\big)$。它不是某个独立 RM 算出来的，而是**策略与参考模型对数概率之差乘 $\beta$**，所以叫"隐式"。它来自 2.4 节的重参数化：$r(x,y)=\beta\log\frac{\pi^*}{\pi_{\text{ref}}}+\beta\log Z(x)$。DPO 的目标就是让 chosen 的隐式奖励 > rejected 的隐式奖励，二者之差叫 **reward margin**。本项目 `chosen_reward / rejected_reward` 就是这个量，并 `.detach()` 掉只用于监控。

### Q5. 参考模型（reference model）是什么？为什么必须冻结？
**参考答案**：参考模型一般是 SFT 后的权重拷贝，DPO 训练时**全程冻结、不更新、不计梯度**。它的作用是**锚点**：损失里用"策略相对参考的对数比"度量偏移，等价于隐式 KL 约束——防止策略偏离太远、丢掉语言能力。若不冻结，对数比失去基准、约束失效，训练会发散。本项目用三重保险冻结：`ref.eval()` + `for p in ref.parameters(): p.requires_grad_(False)` + 前向包在 `with torch.no_grad()` 里。

### Q6. beta 是什么？调大调小分别有什么影响？
**参考答案**：$\beta$ 是隐式 KL 强度，**DPO 最重要的超参**（本项目默认 `0.1`）。它出现在 KL 正则项 $-\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$ 里。直觉上：$\beta$ **越小 → 越保守、越贴着参考模型**（约束越强）；$\beta$ **越大 → 越敢偏离参考**（约束越弱）。注意 reward margin 的数值本身含 $\beta$ 因子，所以"$\beta$ 调大→margin 变大"不等于"对齐更好"，要结合采样质量一起看。

### Q7. DPO 为什么不需要单独训练奖励模型？
**参考答案**：因为奖励被**重参数化**进了策略。从 KL 正则 RLHF 最优解反解出 $r(x,y)=\beta\log\frac{\pi}{\pi_{\text{ref}}}+\beta\log Z(x)$，奖励就"藏在"策略相对参考的对数比里。代入 Bradley-Terry 后只剩 $r(x,y_w)-r(x,y_l)$ 的差，配分函数 $Z(x)$ 与 $y$ 无关、一减抵消。于是不需要一个独立网络去拟合 $r$——策略本身就是"秘密的奖励模型"（论文副标题：Your Language Model is Secretly a Reward Model）。

### Q8. 为什么计算 $\log\pi(y|x)$ 时要屏蔽 prompt，只对续写算？
**参考答案**：DPO 需要的是**条件似然** $\log\pi(y|x)$——"给定 prompt 后续写"的对数概率，不是 $\log\pi(x,y)$。prompt 是给定的、chosen/rejected 两边完全一样，把它算进去毫无意义还会污染偏好信号。本项目 `sequence_logprob()` 用 `mask = (positions >= response_start)` 屏蔽 prompt 段，`response_start` 传 `prompt_len + 1`（+1 跳过 BOS）。各续写 token 的 logp 求和即整条续写的对数概率（对数相加=概率相乘）。

> **追问 1**：DPO 是 on-policy 还是 off-policy？
> 答：标准 DPO 是 **off-policy / offline**——直接在静态偏好数据集上优化，训练中不从当前策略采样。这是它比 PPO 简单的关键，但也带来"训练分布与策略分布不匹配（distribution shift）"的隐患，是 online-DPO 等变体要补的点。
>
> **追问 2**：DPO 训练前 reward margin 为什么恰好是 0？
> 答：因为 `policy` 和 `ref` 都是同一个 `base` 的 `deepcopy`，初始完全相同，对数比处处为 0，所以 margin 严格 = `+0.0000`。这是一个很好的 sanity check：若你改了初始化让两者不同，初始 margin 就不会是 0。

## 二、进阶题（原理与权衡）

### Q9. 完整推导：从"KL 正则 RLHF 目标"到 DPO 损失。
**参考答案**：四步。
1. **目标**：$\max_{\pi_\theta}\mathbb{E}_{y\sim\pi_\theta}[r(x,y)]-\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$。
2. **最优解**（变分推导，可记结论）：$\pi^*(y|x)=\frac{1}{Z(x)}\pi_{\text{ref}}(y|x)\exp(\tfrac1\beta r(x,y))$，其中 $Z(x)=\sum_y\pi_{\text{ref}}\exp(\tfrac1\beta r)$。直觉：最优策略=参考模型按奖励做指数级重加权。
3. **反解奖励**：两边取对数移项，$r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)}+\beta\log Z(x)$。把 $\pi^*$ 当作待训练 $\pi_\theta$。
4. **代入 Bradley-Terry**：$P(y_w\succ y_l)=\sigma(r(x,y_w)-r(x,y_l))$，差里 $\beta\log Z(x)$ 与 $y$ 无关、抵消，得 $P=\sigma\big(\beta\log\frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)}-\beta\log\frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}\big)$。对偏好数据取负对数似然即 $\mathcal{L}_{\text{DPO}}$。
**关键点**：配分函数 $Z(x)$ 因"只出现奖励之差"而消去——这是 DPO 能落地的核心，否则 $Z(x)$ 要对全部 $y$ 求和，不可算。

### Q10. DPO vs RLHF(PPO) 全面对比。
**参考答案**：
| 维度 | RLHF (PPO) | DPO |
| --- | --- | --- |
| 是否需要 RM | 需单独训练 RM | 无独立 RM，奖励重参数化进策略 |
| 优化方式 | PPO 在线采样+强化学习 | 静态偏好数据上的监督式梯度下降 |
| KL 约束 | PPO 显式加惩罚项 | 通过 $\beta$+参考对数比隐式编码 |
| 稳定性/速度 | 不稳、慢、超参敏感 | 像分类一样稳、快 |
| 数据利用 | 可在线生成新样本 | 只用固定偏好集（off-policy） |
| 上限/灵活性 | RM+在线探索上限可能更高、更鲁棒 | 受限于偏好集覆盖，易在集内过拟合 |
**取舍判断**：DPO 工程简单、复现性好、首选 baseline；但 PPO 的在线探索能纠正"偏好集没覆盖到"的分布，规模化/对抗 reward hacking 上仍有价值。两者不是非此即彼。

### Q11. DPO 的梯度长什么样？它解释了什么直觉？
**参考答案**：对 $\theta$ 求导，
$$\nabla_\theta\mathcal{L}=-\beta\,\mathbb{E}\Big[\underbrace{\sigma\big(\hat r(x,y_l)-\hat r(x,y_w)\big)}_{\text{加权:当前判错的程度}}\big(\nabla_\theta\log\pi_\theta(y_w|x)-\nabla_\theta\log\pi_\theta(y_l|x)\big)\Big]$$
直觉：**抬高 chosen 的对数概率、压低 rejected 的对数概率**；权重 $\sigma(\hat r_l-\hat r_w)$ 是"模型当前把偏好搞错的程度"——已经判对的样本权重趋近 0，**难/错样本权重大**，自带难例加权。这也解释了 reward margin 为何持续上升。

### Q12. DPO 训练里观察到 chosen 和 rejected 的 logp **同时下降**，正常吗？
**参考答案**：很常见且常被误解。DPO 只约束**对数比之差**，不约束绝对 logp。实践中经常出现 $\log\pi_\theta(y_w)$ 和 $\log\pi_\theta(y_l)$ **双双下降**，只要 rejected 降得更多、margin 仍上升即可。隐患是：若 chosen 的概率也被一起压低，模型可能整体变得不爱输出该类回答，甚至语言流畅度退化。这正是 DPO 易出现"likelihood displacement / 过度优化"的征兆，需配合验证集和生成质量监控。

### Q13. DPO 为什么容易过拟合？本项目里如何体现？
**参考答案**：DPO 是在**固定偏好集**上做监督优化，没有在线探索，模型很容易"记住"训练集里的相对关系而非学到泛化偏好。本项目只有 **24 条偏好对**，几十步 `pref_acc` 就冲到 1.0、reward margin 一路涨到 ~9.5——这是**典型过拟合而非泛化**。真实 DPO 必须：大数据、验证集监控、early stop，否则会 reward over-optimization（策略偏离参考过远、KL 失控、语言能力退化）。

### Q14. DPO 也会 reward hacking 吗？和 PPO 的 reward hacking 一样吗？
**参考答案**：会，但形态不同。PPO 的 reward hacking 是"策略钻 RM 的空子刷高分"。DPO 没有独立 RM，但有**隐式奖励**，仍会"过度优化隐式奖励"：表现为 margin 无限增大、KL 失控、对数概率坍塌（如把 chosen/rejected 都压低）、生成退化（重复、变短、迎合表面特征如长度/格式）。缓解：合适的 $\beta$、early stop、cDPO（label smoothing）应对噪声标签、长度归一化/IPO 抑制长度偏置、保留对参考的 KL 监控。

### Q15. DPO 有"长度偏置（length bias）"问题吗？根因是什么？
**参考答案**：有。本项目 `sequence_logprob` 对续写 token 的 logp **求和**，序列越长 logp 越小（每个 token logp 为负）。若 chosen 普遍比 rejected 长（或反之），损失会被长度差带偏，模型可能学到"偏好更长/更短的回答"这种伪信号。缓解：对 logp 做**长度归一化**（除以续写 token 数），这正是 IPO 等变体和工程实践的常见做法。本项目"练习 4"就是让你给 `sequence_logprob` 加长度归一化。

### Q16. 列举几个 DPO 的重要变体，分别解决什么问题？
**参考答案**：
- **IPO**：用平方损失替代对数 sigmoid，缓解 DPO 在可分数据上"margin 无限增大→过拟合"的倾向，并隐式做长度/正则控制。
- **cDPO（label smoothing DPO）**：假设偏好标签有一定噪声率 $\epsilon$，对损失做平滑，更鲁棒于错标偏好。
- **KTO**：基于前景理论，**只需单条样本的 good/bad 二元标签**，不需要成对偏好，标注更省。
- **reference-free / SimPO**：去掉参考模型（用长度归一化的平均 logp + margin 项），省一份模型显存。
- **ORPO**：把 SFT 和偏好对齐合到一个阶段、无参考模型。
取舍：去参考模型省显存但失去 KL 锚点、更易退化；IPO/cDPO 更稳但可能上限略低。

> **追问 1**：$\beta\to 0$ 和 $\beta\to\infty$ 极限下 DPO 各退化成什么？
> 答：$\beta\to\infty$（KL 罚极轻）时约束几乎消失，策略可任意偏离参考去满足偏好，最易退化/过拟合；$\beta\to 0$（KL 罚极重）时 logit 趋近 0、梯度极小，策略几乎不动、贴死参考模型，学不到偏好。实践取中间值（本项目 0.1，工业常见 0.1~0.5）。
>
> **追问 2**：DPO 一定需要先做 SFT 吗？参考模型一定是 SFT 模型吗？
> 答：强烈建议先 SFT。参考模型若没"会说话"，对数比全是噪声、信号弱（本项目特意先 `pretrain_sft` 造中性参考）。参考模型通常取 SFT 权重；也有 reference-free 变体去掉它，但会失去 KL 锚点。

## 三、深入/手撕题（能否动手 / 追问到底）

### Q17.【手撕思路】从零实现 DPO 损失与序列对数概率，关键步骤是什么？（结合本项目）
**参考答案**：核心两个函数。
1. **`sequence_logprob(model, token_ids, response_start)`**——算 $\log\pi(y|x)$：
   - 前向 `logits = model(x)`，`log_softmax` 得每位置全词表对数概率；
   - 自回归对齐：用 `logits[:-1]` 预测 `token_ids[1:]`，`gather` 取出"真实下一 token"的 logp，得 `(T-1,)`；
   - **屏蔽 prompt**：`mask = (positions >= response_start)`，只对续写求和；`response_start = prompt_len + 1`（+1 跳 BOS）。
2. **`dpo_loss(...)`**：
```python
pi_logratio_c = pi_logp_chosen   - ref_logp_chosen
pi_logratio_r = pi_logp_rejected - ref_logp_rejected
logits = beta * (pi_logratio_c - pi_logratio_r)
loss   = -F.logsigmoid(logits)          # 数值稳定，别写 log(sigmoid(.))
```
**易错点**：参考模型前向必须 `no_grad` 且冻结；用 `F.logsigmoid` 而非 `torch.log(torch.sigmoid())`（避免 sigmoid→0 时 log 爆 `-inf`）；`prompt_len + 1` 的 +1 不能漏；loss 是带计算图的标量，`reward` 监控量要 `.detach()`。

### Q18.【追问到底】把本项目"逐样本 Python 循环"改成 batch 张量一次前向，要注意什么？
**参考答案**：本项目为可读性逐条算 logp 再累加，工程实现要批处理：
- 把 chosen/rejected **padding 到同一长度**，拼成 `(B, T)` 张量一次前向；
- **padding 位置的 logp 必须用 mask 清零**，不能算进 loss（否则污染对数概率）；
- prompt 屏蔽 mask 与 padding mask 要**叠加**：只保留"既是续写、又非 padding"的位置；
- 注意 chosen/rejected 可分别 batch，再算对数比之差。
这正是本项目"练习 5"，是从玩具走向工程的关键一步，能显著提速、结果应基本一致。

### Q19.【概念辨析】DPO 损失里"梯度只流向策略"是怎么保证的？若误更新了参考模型会怎样？
**参考答案**：保证手段：参考模型 `eval()` + `requires_grad_(False)`，且其前向包在 `with torch.no_grad()` 里，所以 `ref_logp_*` 是计算图里的**常数**，反传只更新 $\pi_\theta$。若误更新参考模型：对数比失去固定锚点，KL 约束失效，"chosen 抬高/rejected 压低"的相对参照漂移，训练易发散或学不到稳定偏好——本项目"常见坑 3"明确指出这点。

### Q20.【实验现象解读】本项目跑完 `pref_acc 0.583→1.000`、`reward_margin +0→+9.53`，你怎么向面试官解读？
**参考答案**：
- `pref_acc=0.583`（训练前）：policy=ref，对 chosen/rejected 中性，约一半多判对，接近碰运气。
- `reward_margin=+0.0000`（训练前）：policy 与 ref 同源拷贝，对数比恒 0，sanity check 通过。
- 训练后 `pref_acc=1.0`、margin 升到 ~9.5、采样明显偏礼貌正向（`thank`/`of course`/`happy`）：DPO 成功把策略推向 chosen。
- **关键判断**：这是 **24 条玩具数据上的过拟合**，不是泛化能力。margin 一路涨说明在不断偏离参考；真实场景需大数据 + early stop + 验证集，否则 reward over-optimization。这个"会读现象、还能指出局限"是面试加分点。

### Q21.【对齐链路】给定一个真实业务（如客服助手要更礼貌），你会选 DPO 还是 RLHF(PPO)？怎么搭数据与评估？
**参考答案**：
- **首选 DPO 作为 baseline**：工程简单、稳定、复现好。流程：先 SFT → 收集成对偏好（同一 prompt 下人工/模型挑 chosen vs rejected）→ DPO，$\beta$ 从 0.1 起调。
- **数据**：保证 chosen/rejected 长度尽量均衡（防长度偏置）、覆盖真实分布、清洗错标（或上 cDPO）。
- **评估**：不能只看 pref_acc/margin（会过拟合），要有**独立验证集 + 生成质量人评/LLM-as-judge + 对参考的 KL 监控 + 语言能力回归测试**（防退化）。
- **何时上 PPO**：当偏好集覆盖不足、需要在线探索纠偏、或出现严重 hacking 时，引入 RM+PPO 或 online-DPO/迭代式 DPO。

> **追问 1**：如果你的偏好数据有 ~10% 是标错的，怎么办？
> 答：用 **cDPO（label smoothing）**，给标签引入噪声率 $\epsilon$ 做平滑，对错标更鲁棒；同时清洗数据、降低 $\beta$ 提升正则、加 early stop 防过拟合到噪声。
>
> **追问 2**：怎么定量监控 DPO 有没有"偏离参考太远"？
> 答：监控**策略相对参考的 KL/对数比**、chosen 与 rejected 的**绝对 logp 是否双双坍塌**、reward margin 是否异常飙升，以及验证集生成质量是否回退。任一指标失控就 early stop 或调大正则（减小 $\beta$）。

## 高频追问速答清单

1. **DPO 全称？** Direct Preference Optimization（arXiv:2305.18290）。
2. **DPO 损失本质是什么？** 一个 sigmoid 二分类（逻辑回归）的负对数似然。
3. **DPO 需要几个模型？** 训练时 2 个：可训策略 + 冻结参考；不需要独立 RM。
4. **配分函数 $Z(x)$ 为什么不用算？** 它与 $y$ 无关，在奖励之差里抵消。
5. **隐式奖励公式？** $\hat r=\beta(\log\pi_\theta-\log\pi_{\text{ref}})$。
6. **beta 越大意味着？** KL 罚越轻、越敢偏离参考模型。
7. **reward margin 是什么？** chosen 与 rejected 隐式奖励之差，训练中盯它上升。
8. **DPO 是 on-policy 吗？** 否，标准 DPO 是 offline/off-policy。
9. **为什么屏蔽 prompt？** 只要条件似然 $\log\pi(y|x)$，prompt 两边相同算了污染信号。
10. **DPO 最大风险？** 在固定偏好集上过拟合 / reward over-optimization / logp 坍塌退化。
11. **去掉参考模型的变体？** SimPO / ORPO（reference-free），省显存但失 KL 锚点。
12. **`F.logsigmoid` 而非 `log(sigmoid)`？** 数值稳定，避免 log 爆 `-inf`。
