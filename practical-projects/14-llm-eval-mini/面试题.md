## 一、基础题（概念是否懂）

### Q1. 什么是困惑度 Perplexity（PPL）？它和交叉熵是什么关系？
**参考答案：** PPL 是语言建模最核心的**内在指标（intrinsic metric）**，定义为平均交叉熵取指数：

$$\text{PPL} = \exp(\overline{\text{CE}}),\quad \overline{\text{CE}} = \frac{1}{N}\sum_{t=1}^{N}\big(-\log p_{y_t}\big)$$

其中 $p_{y_t}$ 是模型在位置 $t$ 给「真实下一个 token」的概率。交叉熵衡量「模型对真实文本有多意外」，单位是 nat（自然对数）；PPL 把它还原成「等效有效分支数」。本项目 `evaluate_perplexity` 就是 `avg_ce = total_loss / total_tokens; ppl = math.exp(avg_ce)`——训练用的 `F.cross_entropy` 损失和 PPL 算的是**同一个交叉熵**，所以「降低训练 loss」就等价于「降低 PPL」。

**追问：为什么取 exp？这个数有什么物理意义？**
因为 $\exp(-\log p)=1/p$，所以 PPL ≈「模型平均给真实 token 概率的倒数」，即「平均要在多少个等可能选项里猜」。PPL=1 表示完全确定，PPL=V（词表大小）表示均匀瞎猜。

**追问：PPL 用 `math.exp` 还是 `2**x`？**
取决于交叉熵的对数底。本项目用自然对数（nat），所以配 `math.exp`；若用 $\log_2$（bit），就该用 `2**avg_ce`。底和指数必须配套，否则数值会错（脚本踩坑：用 $\log_2$ 却仍 `math.exp` 会算出比词表还大的 PPL）。

---

### Q2. 随机未训练的模型，PPL 大约是多少？为什么？
**参考答案：** 约等于**词表大小 V**。随机模型对 V 个 token 近似均匀分配概率，每个 $p=1/V$，则 $\text{CE}=-\log(1/V)=\log V$，于是 $\text{PPL}=\exp(\log V)=V$。本项目 `vocab_size=24`，README 真实跑通的 step=0 基线 `val_ppl=24.14`，几乎正好等于 24——这是评测里极有用的 **sanity baseline（理智检查基线）**：跑出来的 PPL 应介于 1（完美）到 V（瞎猜）之间，超出这个范围说明指标算错了。

**追问：那 PPL 的真实下界是 1 吗？**
不是。真实文本本身有不可消除的熵（语言的固有不确定性），PPL 下界是文本的真实熵，恒 > 1。本项目语料规律性极强，PPL 能逼近 1.07；换成随机/多样语料，final PPL 会停在更高值——这正解释了为什么真实 LLM 的 PPL 永远到不了 1。

---

### Q3. 内在指标和外在指标有什么区别？为什么不能只看 PPL？
**参考答案：**
- **内在指标（intrinsic）**：只看模型对文本分布的拟合，如 PPL。不需要外部任务、计算便宜，但**低 PPL ≠ 任务好用**。
- **外在指标（extrinsic / 下游）**：把模型放到具体任务上看对错，如本项目的 next-char 准确率（给真实前缀让模型 greedy 预测下一字符，与语料真值比对）。真实世界对应 MMLU / GSM8K / HumanEval / C-Eval。

一个模型可能语言流畅度高（PPL 低）但一到算术、问答就翻车。所以本项目最后判 PASS 的条件是**两者同向改善**：`(final_ppl < base_ppl) and (final_acc > base_acc)`，单看一个都可能片面。

**追问：PPL 还有什么局限？**
（1）跨模型/跨 tokenizer 不可比——不同分词粒度下「每 token 的熵」含义不同；（2）只反映分布拟合，不反映指令遵循、事实性、安全性；（3）对评测语料分布敏感。

---

### Q4. greedy / temperature / top-k 三种解码策略分别是什么？
**参考答案：** 训练好后「生成」时，每步模型给一个概率分布，**怎么从分布里挑下一个 token** 就是解码策略：
- **greedy（贪心）**：每步取 $\arg\max_j P(x_t=j)$。确定性最高、最稳，但易陷入重复。**与温度无关**（argmax 不需要采样）。
- **temperature（温度采样）**：$P_T(j)\propto e^{z_j/T}$。T<1 放大 logits 差距、分布更尖锐更保守；T>1 压缩差距、分布更平坦更发散、易采到低概率噪声；T=1 为原始分布。
- **top-k**：温度缩放后只保留概率最高的 k 个候选（其余置 $-\infty$ 再 softmax），在这 k 个里采样。截断长尾，平衡多样性与质量。

本项目 `generate` 完整实现了三者：greedy 走 `torch.argmax`；其余走 `scaled = logits / max(T, 1e-6)`（`max` 防 T=0 除零）→ softmax → `torch.multinomial` 采样；top-k 额外用 `torch.topk` 取第 k 大值作阈值，把更小的 logit 设 `-inf`。

**追问：本项目 README 里 `temperature=1.3` 输出出现了 `rdat g` 这种噪声，为什么？**
高温把分布压平，采到了低概率字符。这是「温度越高越发散」的直观证据。对比 greedy / top_k=5 输出都连贯无噪声。

---

### Q5. 评测生成质量时为什么必须固定解码策略？
**参考答案：** 因为同一个模型换不同采样方式输出差异巨大（本项目同 prompt `"the "`、同模型，greedy / T=0.5 / T=1.3 / top_k=5 四种输出明显不同）。如果不固定解码，你比较的就不是「模型本身」，而是「模型 + 一套随机采样配置」的混合物——明天换个温度结论就翻了。固定解码（含 temperature、top-k/top-p、seed）才能让生成结果**可比、可复现、可回归测试**。

**追问：除了解码策略，评测可复现还要固定什么？**
所有随机源。本项目固定了 Python `random`、`numpy`、`torch` 三个种子（`SEED=1234`），下游探针还用独立的 `random.Random(SEED)` 保证每次抽到**同一批探针**。固定种子 ≠ 关掉随机性——温度采样仍随机，只是轨迹被锁定。

---

### Q6. 训练 batch 里输入 x 和目标 y 为什么错开一位？
**参考答案：** 这是 **next-token prediction** 的标准做法：位置 $t$ 的输入要预测位置 $t+1$ 的 token，所以 `y` 是 `x` 整体右移一位（本项目 `get_batch`：`x = data[s:s+L]`, `y = data[s+1:s+1+L]`）。模型在每个位置学的都是「看到当前及之前，猜下一个」。这同时也是 PPL 评测依赖的东西——PPL 算的就是「对每个真实下一个 token 给了多大概率」。

**追问：评测 PPL 时遍历验证集为什么要「不重叠」切片？**
本项目 `evaluate_perplexity` 用 `step = seq_len` 不重叠遍历，保证每个 token 只被算一次，得到平均交叉熵的**无偏稳定估计**；重叠会重复计数、扭曲平均。

---

### Q7. 训练损失和 PPL 是同一回事吗？训练前为什么先评一次基线？
**参考答案：** 本质同源。训练损失就是 `F.cross_entropy`（next-token），PPL = `exp(平均交叉熵)`，所以「降 train loss」和「降 PPL」是一回事，二者同步下降（README 里 `train_loss` 与 `val_ce` 都在降且彼此接近）。训练前先评一次（step=0）是为了拿到**随机初始化基线**：PPL 应 ≈ V、下游 acc 应 ≈ 1/V，后面所有改善都拿它当参照，才能量化「进步了多少倍」（本项目 22.5×）。

## 二、进阶题（原理与权衡）

### Q8. top-k 和 top-p（nucleus sampling）有什么区别？各自的优劣？
**参考答案：**
- **top-k**：固定保留概率最高的 k 个候选。缺点是 k 是**固定数量**——当分布很尖（某 token 概率 0.99）时 k 个里混入很多垃圾；当分布很平时又可能截掉合理候选。
- **top-p（nucleus）**：保留**累积概率达到 p** 的最小候选集合（动态数量）。分布尖时集合小、分布平时集合大，更自适应。出自 Holtzman et al. 2019《The Curious Case of Neural Text Degeneration》，该文也解释了 greedy/beam 为何会退化重复、采样为何要截断长尾。

本项目只实现了 greedy/temperature/top-k（教学最小集），README 也明说真实工程还有 top-p / beam search。实践中常 top-p + temperature 组合使用。

**追问：beam search 为什么在开放式生成里反而不流行？**
beam search 倾向高概率序列，在开放式生成中导致重复、乏味、退化（degeneration），且多样性差。它更适合机器翻译、摘要等「有较确定正确答案」的任务。

---

### Q9. 为什么 PPL 不能用来比较两个不同 tokenizer 的模型？
**参考答案：** PPL 是「每 token 的几何平均意外度」，而**每 token 的语义量取决于分词粒度**。字符级 tokenizer 一个 token 信息少、PPL 天然偏低；BPE/子词一个 token 信息多、PPL 偏高——即使两模型语言能力相同，PPL 也不可比。要跨 tokenizer 比较，应换成 **bits-per-byte（BPB）或 bits-per-character（BPC）**，把熵归一化到「每字节/每字符」这个与分词无关的单位上。本项目是字符级（一字符=一 token），所以其 PPL 只在同设定内可比。

**追问：同一模型，验证集换了 PPL 也变，说明什么？**
PPL 对评测语料分布高度敏感。域内文本 PPL 低、域外高。所以报告 PPL 必须注明数据集，跨数据集比较无意义。

---

### Q10. 什么是数据污染（data contamination / leakage）？为什么是评测最大的坑之一？
**参考答案：** 数据污染指**测试集（或其变体）出现在了训练数据里**。LLM 在万亿级网络语料上预训练，MMLU/GSM8K/HumanEval 等公开 benchmark 极易被爬进训练集，导致模型其实是「背过答案」而非「真会做」，评测分虚高、不反映泛化。这是为什么 benchmark 榜单常与实际体验脱节的核心原因。

**缓解手段：**（1）用**发布时间晚于模型训练截止**的新题（如 LiveBench、新一期竞赛题）；（2）n-gram / 子串重叠检测做去污染；（3）私有/holdout 测试集；（4）题目改写、加扰动看分数是否崩塌；（5）canary string 检测。本项目的下游 toy 任务故意用训练语料本身的前缀，所以 acc 能冲到 1.0——这本身就是「测试题来自训练分布」的极端演示，恰好说明污染会让指标失真。

**追问：怎么快速判断一个高分模型是否吃了污染？**
对题目做语义保持的扰动（换数字、换措辞、改选项顺序）。真会的模型分数稳定；背过的模型分数显著下降。

---

### Q11. 为什么说评测对 prompt 高度敏感？怎么缓解？
**参考答案：** 同一模型、同一题，仅换 prompt 模板（few-shot 示例、措辞、选项排序、答案抽取方式）就能让分数波动好几个点。原因：LLM 是 prompt 的条件分布，prompt 即「输入分布」的一部分。缓解：（1）固定并公开 prompt 模板与 few-shot 数；（2）报告多模板的均值±方差而非单点；（3）规范答案抽取（log-likelihood 打分 vs 生成后正则提取，两种口径分数可能差很多）；（4）选项排序去偏（循环移位取平均，对抗位置偏好）。这也是为什么不同评测框架对同一模型报出的 MMLU 会差几个点——口径不同。

**追问：选择题用「生成答案字母」打分和用「对各选项算 log-likelihood」打分，哪个更稳？**
log-likelihood 打分更稳、抗 prompt 敏感（不依赖模型恰好吐出格式正确的字母），是 lm-evaluation-harness 等框架默认口径之一；生成式抽取更贴近真实使用但对抽取正则和格式遵循敏感。报告时必须注明用了哪种。

---

### Q12. 温度 T 对分布做了什么？T→0 和 T→∞ 的极限分别是什么？
**参考答案：** 温度缩放 $P_T(j)\propto e^{z_j/T}$ 调节分布的「尖锐度」：
- **T→0**：logits 差距被无限放大，概率质量全集中到最大 logit，退化为 **greedy（argmax）**，确定但易重复；
- **T→∞**：logits 差距被压没，趋于 **均匀分布**，完全随机、无意义；
- **T=1**：原始 softmax 分布。

本项目 `generate` 用 `max(temperature, 1e-6)` 防 T=0 除零；若绕过这层保护设 T=0 会触发 `probability tensor contains inf/nan`。实践中 T∈[0.7, 1.0] 是创意/对话常用区间，T 低做确定性任务（代码、抽取），T 高做发散创作。

**追问：top-k=1 和 greedy 等价吗？**
是。top-k=1 只剩最大那个 logit，softmax 后概率为 1，采样必中它，等价于 argmax；而 top-k≥V（≥词表）等于不截断，退化为纯温度采样。

### Q13. 一个完整、可信的 LLM 评测应该具备哪些要素？
**参考答案：** 用本项目的「评测三件套+」清单回答：
1. **可复现**：固定所有随机种子、解码配置、prompt 模板、评测代码版本；
2. **内在指标**：PPL（注明数据集、tokenizer/单位），带 sanity baseline（≈V）；
3. **外在指标**：下游任务准确率（MMLU/GSM8K/HumanEval…），覆盖目标能力维度；
4. **基线对照**：随机基线 + 训练前 baseline + SOTA 对照，量化「提升多少」而非孤立数字；
5. **解码固定**：生成类评测固定 greedy 或固定采样配置；
6. **抗污染 / 抗敏感**：去污染检查、多 prompt 方差、新题验证；
7. **判据明确**：本项目要求 PPL 下降 **且** 下游 acc 上升才判 PASS，避免单指标误导。

**追问：内在和外在指标方向相反（PPL 降但下游降）说明什么？**
要么过拟合验证语料、要么下游任务与训练分布脱节、要么评测代码有 bug（如下游探针的 vocab/corpus 与训练不一致）。本项目排错清单专门提醒：分叉时先确认 `vocab`/`corpus` 一致且 `rng=random.Random(SEED)` 没被改成无种子。

---

### Q14. PPL 低但人觉得生成「很烂」，可能是什么原因？
**参考答案：** 多种可能：（1）**PPL 衡量分布拟合，不衡量生成质量**——它只看模型对「持有真实文本」的概率，不看自由生成时的连贯性/事实性；（2）**解码策略不当**——greedy 易重复退化、高温易出噪声，与 PPL 无关；（3）**曝光偏差（exposure bias）**——训练时看的是 teacher forcing 的真实前缀，推理时看的是自己生成的前缀，误差累积；（4）**评测集与使用场景不匹配**。所以生成质量要靠外在指标 + 人工/LLM-as-judge 评，不能只信 PPL。

## 三、深入 / 手撕题（能否动手、追问到底）

### Q15.【手撕思路·结合本项目】请实现「计算一段文本困惑度」的函数，说清每个关键点。
**参考答案：** 核心五步（对应本项目 `evaluate_perplexity`）：

```python
@torch.no_grad()
def perplexity(model, ids, seq_len):
    model.eval()
    total_loss, total_tokens = 0.0, 0
    for s in range(0, len(ids) - seq_len - 1, seq_len):   # 不重叠遍历
        x = ids[s:s+seq_len].unsqueeze(0)
        y = ids[s+1:s+1+seq_len].unsqueeze(0)             # 目标右移一位
        logits, _ = model(x)
        loss = F.cross_entropy(
            logits.reshape(-1, logits.size(-1)),
            y.reshape(-1), reduction="sum")               # sum 便于按 token 加权
        total_loss += loss.item(); total_tokens += y.numel()
    avg_ce = total_loss / max(total_tokens, 1)            # 平均交叉熵 (nat)
    return math.exp(avg_ce)                               # PPL = exp(CE)
```

必须讲清的点：（1）`@torch.no_grad()`+`eval()` 关梯度省内存；（2）`y` 右移一位是 next-token 目标；（3）**`reduction="sum"` 而非 mean**——因为末段可能不满 seq_len，直接平均各 batch 的 mean 会算错权重，必须按真实 token 数手动加权；（4）`reshape(-1, V)` / `reshape(-1)` 摊平成 cross_entropy 要求的形状；（5）`math.exp` 对应 nat 单位，换 bit 要换 `2**(ce/log2)`。

**追问：如果序列很长、显存放不下整段，怎么算 PPL？**
滑窗（sliding window）+ stride：分块前向，块间用重叠上下文减小边界 token 缺乏前文的偏差，但只对「非重叠部分的新 token」累计 loss，避免重复计数（GPT-2 论文的 strided PPL 做法）。

### Q16.【手撕思路】请实现 top-k 采样的核心逻辑（含温度），并说明边界处理。
**参考答案：** 对应本项目 `generate` 的 else 分支：

```python
scaled = last_logits / max(temperature, 1e-6)   # 温度缩放，防 T=0 除零
if top_k is not None:
    v, _ = torch.topk(scaled, min(top_k, scaled.size(-1)))  # k 不超过词表
    thresh = v[:, -1].unsqueeze(-1)             # 第 k 大的值作阈值
    scaled = torch.where(scaled < thresh,
                         torch.full_like(scaled, float("-inf")),  # 截断
                         scaled)
probs = F.softmax(scaled, dim=-1)               # -inf -> 概率 0
next_id = torch.multinomial(probs, 1)           # 按概率采样
```

边界点：（1）`max(temperature, 1e-6)` 防除零；（2）`min(top_k, vocab)` 防 k 超过词表；（3）截断用 `-inf` 而非 0，让 softmax 后自然归零；（4）`multinomial` 是真随机采样，区别于 greedy 的 argmax；（5）温度和 top-k 可叠加（先缩放再截断）。

**追问：top-k 截断后概率要不要重新归一化？**
本项目做法是把非 top-k 的 logit 设 `-inf`，再对全词表 softmax——`-inf` 经 softmax 自动变 0，剩余 top-k 概率自动归一化，无需手动 renormalize。这比「先取 k 个再单独 softmax」更简洁且数值等价。

### Q17.【追问到底】本项目下游 next-char 准确率为什么用 greedy 而不是采样？换成采样会怎样？
**参考答案：** 外在准确率衡量「模型最可能给出的答案对不对」，所以取 **argmax（greedy）**，不引入采样随机性——否则同一题多次评分数会抖，准确率不可比。换成采样会让 acc 带方差、需多次平均，且低估「模型其实知道答案」的能力（它可能采到了第二高的错误 token）。这呼应 Q5：外在指标也要固定解码，且用确定性解码最干净。

**追问：那为什么这个 toy 任务能冲到 acc=1.0，真实 MMLU 却不行？**
本项目探针前缀**来自训练语料本身**（污染的极端形式），模型见过分布，所以打满。真实 MMLU 用模型没见过的题，且需要推理/知识，难度高得多。这恰好是 Q10 数据污染的活教材。

### Q18.【设计题】给你一个新训好的 LLM，从零设计评测方案，你会怎么做？
**参考答案：** 分四层，逐层加严：
1. **Sanity / 内在层**：先算 held-out PPL，对照随机基线（≈V）确认指标算对、模型确实在拟合；画 PPL-随训练曲线确认收敛。
2. **能力 / 外在层**：选覆盖目标能力的 benchmark——知识 MMLU/C-Eval、推理 GSM8K、代码 HumanEval/MBPP、长文 等；统一用成熟框架（lm-evaluation-harness）跑，固定 prompt 与口径。
3. **生成 / 主观层**：固定解码（如 top-p=0.9, T=0.7），用 LLM-as-judge + 人工抽检评连贯性/事实性/指令遵循/安全。
4. **可信度层**：去污染检查（新题、n-gram 重叠）、多 prompt 报方差、对抗扰动测稳健性、与已知 SOTA 对照。

贯穿始终：**固定一切随机源与配置保证可复现**，**报告带基线和方差而非孤立数字**，**多指标同向才下结论**（本项目 PASS 判据的放大版）。

**追问：只有一块消费级 GPU/CPU，怎么快速迭代评测？**
像本项目一样先用「小代理（proxy）」——小验证集 + 少量代表性任务 + 快指标（PPL/少量 next-token acc）做快速回归，确认方向对了再上全量 benchmark，省算力。

### Q19.【追问到底】训练 loss 一直降，但验证 PPL 不降甚至升，怎么排查？
**参考答案：** 典型**过拟合**信号，排查顺序：（1）确认 train/val 是否真正划分干净（本项目 90/10 切分、val 不参与训练）；（2）看 train_loss 与 val_ce 的 gap，gap 持续扩大即过拟合 → 早停、加正则/dropout、减容量、加数据；（3）确认 PPL 计算本身没 bug（reduction、底/exp 配套、y 是否仍右移一位——本项目排错清单提醒：误把 y 改成没右移会让 PPL 停在 24 附近）；（4）lr 太大导致 val 抖 → 调度/裁剪（本项目 `clip_grad_norm_(1.0)` 稳 LSTM）；（5）val 集太小导致估计噪声大 → 扩大或多次评取均值。

**追问：为什么 RNN/LSTM 训练常配梯度裁剪？**
RNN 沿时间步反传易梯度爆炸，`clip_grad_norm_` 把梯度范数截到阈值（本项目 1.0）保证稳定，是 RNN 类模型的标配技巧。

## 高频追问速答清单

1. **PPL 公式？** `PPL = exp(平均交叉熵)`，CE 用自然对数则配 exp，用 log2 则配 `2**`。
2. **随机模型 PPL ≈？** 词表大小 V；本项目 V=24，baseline≈24.14。
3. **PPL 下界是 1 吗？** 不是，是文本真实熵，恒 >1（除非语料完全确定）。
4. **内在 vs 外在？** PPL 是内在（拟合分布），下游准确率是外在（任务对错），需同向改善。
5. **greedy 受温度影响吗？** 不受，argmax 与采样无关。
6. **T<1 vs T>1？** T<1 更尖锐保守（近 greedy），T>1 更平更发散更易出噪声。
7. **top-k=1 ＝？** greedy；top-k≥V ＝ 纯温度采样。
8. **top-k vs top-p？** top-k 固定个数，top-p（nucleus）按累积概率动态取，更自适应。
9. **评测生成为什么固定解码？** 否则比的是「模型+采样配置」，不可比不可复现。
10. **跨 tokenizer 能比 PPL 吗？** 不能，要用 bits-per-byte/char 归一化。
11. **数据污染怎么防？** 新题/holdout、n-gram 去重、扰动测稳健、canary。
12. **评测可复现要固定啥？** 所有随机源（random/numpy/torch seed）+ 解码 + prompt + 代码版本。
