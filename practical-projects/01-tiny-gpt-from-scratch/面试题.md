## 一、基础题(概念是否懂)

### Q1. 什么是 decoder-only Transformer?它和 encoder-only(BERT)、encoder-decoder(T5)的本质区别?

**参考答案**:
- **decoder-only(GPT 类)**:只有解码器堆叠,核心是**带 causal mask 的 self-attention**——每个位置只能看到自己及左侧历史,训练目标是 next-token prediction(自回归语言建模)。本项目就是这一类。
- **encoder-only(BERT)**:**双向** attention(无 mask,每个 token 能看全文),训练目标是 MLM(masked language modeling)。擅长理解/分类,不能直接自回归生成。
- **encoder-decoder(T5/原始 Transformer)**:encoder 双向编码源序列,decoder 带 causal mask + cross-attention 看 encoder 输出。适合翻译、摘要这类 seq2seq。
- 一句话本质:**区别在于"能看到哪些位置(mask 形态)"和"训练目标"**。GPT 之所以能边训边生成,正是因为 causal mask 让每个位置的预测都是合法的自回归目标。

> **追问**:为什么现在主流大模型都收敛到 decoder-only?
> 答:训练目标单一(next-token)且能无监督吃海量文本;causal mask 使一次 forward 就给出每个位置的训练信号(并行 teacher forcing);推理时配 KV-cache 天然增量生成;scaling 表现好、架构最简洁。

### Q2. 在本项目里,一个 token 进入网络的初始表示是怎么来的?

**参考答案**:`x_t = TokenEmbedding(c_t) + PositionalEmbedding(t)`。
- `token_emb = nn.Embedding(vocab_size, n_embd)`:把字符 id 查表成语义向量。
- `pos_emb = nn.Embedding(block_size, n_embd)`:**可学习的绝对位置嵌入**(GPT-2 风格),给每个位置一个向量。
- 两者**逐元素相加**(代码 `self.token_emb(idx) + self.pos_emb(pos)`,靠广播把 `(T,C)` 的位置嵌入加到 `(B,T,C)` 的每条序列上)。
- 为什么要加位置:self-attention 是**置换等变(permutation-equivariant)**的,打乱输入顺序注意力输出只是跟着重排,模型本身分不清"第几个",所以必须显式注入位置信息。

### Q3. 字符级(character-level)和子词(BPE/subword)tokenization 各有什么取舍?

**参考答案**:
- **字符级(本项目)**:词表极小(就是文本里出现过的字符);零依赖、不需要训练分词器、不会 OOV;缺点是序列变长(同样内容 token 数多 → 计算/显存随 $T$、注意力随 $T^2$ 上涨),且单个 token 信息量低,模型要花容量去拼字。
- **子词 BPE**:序列短、单 token 语义密度高、是真实 LLM 的主流;代价是要预先训练 merges、有词表/编码逻辑、可能 OOV→回退到 byte。
- 本项目选字符级是为了**教学与 CI 冒烟**:自包含、CPU 几十秒跑完。

### Q4. 自回归语言建模的训练信号是什么?为什么本项目里 `y` 是 `x` 右移一位?

**参考答案**:目标是建模 $P(c_{1:n})=\prod_t P(c_t\mid c_{<t})$,即在每个位置预测"下一个字符"。
- `get_batch()` 里 `x = data[i:i+block_size]`,`y = data[i+1:i+1+block_size]`,**整段错开一位**。
- 含义:位置 $t$ 的输入能看到 `x[:t+1]`,要预测的答案是 `y[t]=x[t+1]`。一个 `(B, block_size)` 的 batch 因此**同时**提供了 `block_size` 个监督样本(每个位置一个),这就是 teacher forcing 的并行训练。

### Q5. 为什么 GPT 需要 causal mask?代码里怎么实现的?

**参考答案**:预测第 $t$ 个 token 时绝不能看到 $t+1$ 及以后,否则就是"抄答案",训练出的模型在推理(看不到未来)时会崩。
- 实现:对得分矩阵 $(T,T)$ 用**下三角 mask**,把"未来位置"($j>i$)的得分填成 $-\infty$,softmax 后 $e^{-\infty}=0$,未来权重恰好为 0。
- 代码:`register_buffer("mask", torch.tril(torch.ones(block_size, block_size))...)`,forward 里 `att.masked_fill(self.mask[:,:,:T,:T]==0, float("-inf"))`。`[:T,:T]` 是为了支持 $T<block\_size$(比如生成早期序列还短)。
- 用 `register_buffer` 而非 Parameter:它不是可训练参数,但会随 `.to(device)`/保存一起搬移。

> **追问**:mask 填 `-inf` 而不是填一个很大的负数(如 -1e9)有什么坑?
> 答:`-inf` 经 softmax 严格得 0,数值干净;但若**整行全是 -inf**(本项目不会出现,causal 下每行至少对角线可见),softmax 会出 NaN。工程上常用 `-1e9` 或 dtype 最小值规避这种边界(如 padding 全屏蔽 + causal 叠加时)。

### Q6. Multi-head 里 Q/K/V 的物理含义?为什么要多头?

**参考答案**:
- **Q(Query)**:我想找什么;**K(Key)**:我能被什么匹配;**V(Value)**:被选中后我贡献的内容。$QK^\top$ 算相关性得分,softmax 成权重,加权求和 $V$ 得新表示。
- **多头**:把 $d_{model}$ 切成 `n_head` 份(本项目 96/4 → head_size=24),每个子空间独立做一次注意力再拼回。直觉:不同头学不同关系(有的头"找冒号",有的头"找上一个角色名");单头只能用一种相似度模式,多头是低成本的"集成不同子空间"。
- 注意:多头**不增加总计算量**(切分而非复制),只是把同样的 $d$ 分给多个头。

### Q7. FFN(前馈层)在 Transformer 里做什么?为什么中间维度通常 ×4?

**参考答案**:
- FFN 是 **position-wise** 的 `Linear(d→4d) → GELU → Linear(4d→d)`,对每个位置**独立**做非线性变换(不跨位置交换信息)。
- 一句话分工:**attention 负责"在序列内交换信息",FFN 负责"逐位置加工特征"**。
- ×4:经验上的容量甜点,给模型足够非线性表达力(可理解为升维到更宽空间做特征重组再压回)。本项目 96→384→96。FFN 通常占模型参数的大头(约 2/3)。

### Q8. 解释 `forward` 末尾 `cross_entropy(logits.view(-1, vocab_size), targets.view(-1))` 在干什么。

**参考答案**:logits 形状 `(B, T, vocab_size)`,targets 形状 `(B, T)`。
- `view(-1, vocab_size)` 把前两维拍平成 `(B*T, vocab_size)`,`targets.view(-1)` 拍成 `(B*T,)`。
- 等价于:把 batch 里**每个位置**都当一个独立的"下一个字符是哪个"的多分类样本,算交叉熵再平均。
- `F.cross_entropy` 内部已含 `log_softmax + NLL`,所以模型 head 直接输出 raw logits,不要自己再 softmax。

## 二、进阶题(原理与权衡)

### Q9. self-attention 的时间和空间复杂度是多少?它是大模型长上下文的瓶颈吗?为什么?

**参考答案**:设序列长 $T$、维度 $d$。
- $QK^\top$ 得到 $(T,T)$ 矩阵:时间 $O(T^2 d)$,**显存 $O(T^2)$**(注意力矩阵)。FFN 是 $O(T d^2)$。
- 当 $T$ 远大于 $d$ 时,$T^2$ 项主导 → 这是**长上下文的核心瓶颈**(本项目 block_size 仅 64,所以无感;放大就会明显变慢,教学文档"常见坑"里也提到注意力是 $O(T^2)$)。
- 缓解方向:FlashAttention(不省复杂度但省 HBM 读写、不显式存 $T\times T$ 矩阵)、稀疏/滑窗注意力、线性注意力、MQA/GQA(省 KV)。

> **追问**:为什么要除以 $\sqrt{d_k}$?
> 答:$q\cdot k=\sum_{i=1}^{d_k} q_i k_i$,若各分量独立、方差为 1,点积方差约为 $d_k$。$d_k$ 大时得分数值大 → softmax 进入饱和区(一个值接近 1 其余近 0),梯度趋近 0、训练困难。除以 $\sqrt{d_k}$ 把方差拉回 ~1,softmax 不饱和。代码 `(q @ k.transpose(-2,-1)) / math.sqrt(head_size)`。

### Q10. 对比绝对位置嵌入(本项目)、RoPE、ALiBi 三种位置编码。

**参考答案**:
- **可学习绝对位置嵌入(本项目 / GPT-2)**:每个位置一个可学习向量,加到 token 嵌入上。简单有效;**致命短板:外推差**——位置表只有 `block_size` 行,推理超过训练长度就没有对应嵌入(本项目超过 64 直接越界,所以 generate 里 `idx_cond = idx[:, -block_size:]` 强制截断)。
- **RoPE(旋转位置编码)**:不加到嵌入,而是在每个头里对 Q、K 按位置做**旋转**,使 $q_m\cdot k_n$ 只依赖**相对位置 $m-n$**。优点:相对位置感、外推较好、可配 NTK/插值扩展上下文;是 LLaMA/Qwen 等主流选择。
- **ALiBi**:不加位置嵌入,直接在注意力得分上加一个**随距离线性衰减的偏置**($-\text{slope}\cdot(i-j)$)。极简、外推非常好(训练短、推理长),代价是位置信息表达较"硬"。
- 取舍:要外推/长上下文 → RoPE 或 ALiBi;教学/短上下文 → 绝对嵌入够用。本项目用绝对嵌入,文档也明确指出"RoPE 是更现代的替代"。

### Q11. Pre-LN vs Post-LN 区别是什么?本项目用哪个、为什么?

**参考答案**:
- **Post-LN(原始 Transformer)**:`x = LN(x + Sublayer(x))`,LayerNorm 在残差**之后**。表达力可能更强,但深层时训练不稳,通常**需要 learning-rate warmup**,否则容易发散。
- **Pre-LN(GPT-2 / 本项目)**:`x = x + Sublayer(LN(x))`,LayerNorm 在子层**里面**、残差加法在**外面**。残差路径是一条"干净的恒等高速公路",梯度直达,深层更稳、对 warmup 不敏感、好调。
- 本项目用 Pre-LN(`x = x + self.attn(self.ln1(x)); x = x + self.ffn(self.ln2(x))`),并在所有 block 之后有一个最终的 `ln_f`——这正是 Pre-LN 架构的标配(否则残差累加后的输出未归一化)。
- 代价:Pre-LN 各层输出方差随深度累积,极深时表征会"被残差主导";有 DeepNorm、Sandwich-LN 等折中方案。

> **追问**:为什么 Pre-LN 末尾必须再加一个 `ln_f`?
> 答:Pre-LN 下最后一个 block 的输出是 `... + Sublayer(LN(...))`,这条残差和从未被归一化过,数值尺度随层数累积。送进输出 head 前用 `ln_f` 归一化能稳定 logits 尺度,这是 GPT-2 的标准做法。

### Q12. 估算本项目模型的参数量(约 35 万),各部分占比怎么来的?

**参考答案**(本项目实际打印 `parameters: 349870`,约 0.35M):
- token_emb:`vocab_size × n_embd`;pos_emb:`block_size × n_embd = 64×96`。
- 每个 Block:
  - attention:`qkv` 是 `n_embd×3n_embd`(无 bias)≈ 96×288;`proj` 是 `n_embd×n_embd + bias`。
  - FFN:`n_embd×4n_embd + 4n_embd×n_embd` ≈ 2×96×384,**FFN 是单层参数大头**。
  - 两个 LayerNorm:各 `2×n_embd`(γ、β),很小。
- 乘 `n_layer=3`,再加 `ln_f` 和 `head`(`n_embd×vocab_size + bias`)。
- 抓手结论:**忽略嵌入和 LN,Transformer 主体参数 ≈ $12\,n_{layer}\,d^2$**(attention 的 QKVO 约 $4d^2$ + FFN 约 $8d^2$)。这是面试常考的"心算公式"。

> **追问**:如果把 `n_embd` 翻倍,参数量大约怎么变?
> 答:主体参数随 $d^2$ 走,翻倍 → 约 ×4;同时 FLOPs 也约 ×4(对固定 $T$)。

### Q13. 给定模型参数量 $N$、训练 token 数 $D$,训练所需 FLOPs 怎么估?推理一步呢?

**参考答案**:
- 经典近似:**训练 FLOPs ≈ $6ND$**(前向 2N + 反向 4N,每个参数每 token)。
- **推理(单 token 前向)≈ $2N$ FLOPs**(忽略注意力的 $T^2$ 项,在 $T \ll d$ 或短上下文时成立)。
- 长上下文要补上注意力项 ~ $O(T^2 d)$。
- Chinchilla 给出"算力最优"经验:$D \approx 20N$(token 数约为参数量 20 倍)时性价比最佳。
- 本项目:$N≈0.35\text{M}$,每步 $B\times T=32\times64=2048$ token,$max\_iters=600$ → 量级上能用 $6ND$ 心算,但 toy 规模不必精确。

### Q14. 训练循环为什么是 `zero_grad → backward → step` 这个顺序?`zero_grad` 放 `backward` 前的原因?

**参考答案**:
- PyTorch 的 `.grad` **默认累加**(为支持梯度累积、RNN 等)。所以每步必须先清零,否则这步会带上上步残留梯度,更新方向错。
- 顺序:`get_batch → forward(算 loss) → zero_grad → loss.backward()(算梯度) → optimizer.step()(更新)`。
- 本项目用 `optimizer.zero_grad(set_to_none=True)`:把 `.grad` 设为 `None` 而非全 0,省一次写显存、略快。
- 引申:**梯度累积**正是利用这个累加特性——多个小 batch backward 累加后再 step 一次,等效大 batch。

### Q15. dropout 在本项目哪里用?为什么评估/生成时要 `model.eval()`?

**参考答案**:
- 三处:嵌入后 `self.drop`、注意力权重上 `attn_dropout`、子层输出残差前 `resid_dropout`(以及 FFN 末尾)。作用是轻度正则、防过拟合。
- `model.eval()` 关闭 dropout(并切换 BatchNorm 等的行为,本项目无 BN);`model.train()` 打开。
- 本项目 `estimate_loss` 里先 `model.eval()` 再评估、之后 `model.train()` 切回:**保证评估确定、可复现**(否则 dropout 随机性让 loss 抖动);`generate` 用 `@torch.no_grad()` 且也应在 eval 语义下,避免采样受 dropout 干扰。

> **追问**:`@torch.no_grad()` 和 `model.eval()` 是一回事吗?
> 答:不是。`eval()` 改的是**模块行为**(dropout/BN);`no_grad()` 改的是**是否建反向图**(省显存/加速,但不关 dropout)。推理时通常两者都要。

### Q16. 本项目最终 loss 降到 ~0.08,远低于随机基线 ~3.83,这说明模型很强吗?

**参考答案**:**不能这么说,这恰恰是过拟合。**
- 随机基线 `random_baseline = math.log(vocab_size)`:对每个字符给均匀分布时的交叉熵 $\ln(\text{vocab\_size})$,是"啥也没学"的标尺。
- 数据集只有 ~1KB,模型把训练文本几乎**背下来**了,所以 train loss 能极低——文档明确指出这是 toy demo 的预期,不代表泛化。
- 正确做法:划**验证集**,看 val loss 是否同步下降;val 不降甚至上升就是过拟合。本项目为简化没分验证集,`estimate_loss` 评估的也是训练分布上的 batch。
- 面试加分:能指出"用 train loss 衡量能力是错的""应看 held-out perplexity"。

## 三、深入 / 手撕题(能否动手 / 追问到底)

### Q17.【手撕思路】不看代码,口述实现一个 causal multi-head self-attention 的 forward,并标注每步张量形状。

**参考答案**(对照本项目 `MultiHeadSelfAttention.forward`):
1. 输入 `x: (B, T, C)`,`C = n_embd`。
2. `qkv = Linear(C, 3C)(x)`,`split` 成 `q,k,v` 各 `(B, T, C)`。
3. reshape 成多头:`view(B, T, n_head, head_size).transpose(1,2)` → `(B, n_head, T, head_size)`。
4. 得分:`att = q @ k.transpose(-2,-1) / sqrt(head_size)` → `(B, n_head, T, T)`。
5. **causal mask**:`att.masked_fill(tril_mask[:,:,:T,:T]==0, -inf)`。
6. `att = softmax(att, dim=-1)`(对最后一维),可接 `attn_dropout`。
7. `out = att @ v` → `(B, n_head, T, head_size)`。
8. 合并头:`out.transpose(1,2).contiguous().view(B, T, C)`。**`.contiguous()` 必加**——transpose 后内存不连续,直接 view 会报错。
9. 输出投影 `proj(out)` + `resid_dropout`,返回 `(B, T, C)`。
- 关键易错点:mask 在 softmax **之前**;softmax 在 `dim=-1`(每个 query 行归一化);合并头前 `contiguous`。

> **追问**:把 `softmax` 错写成 `dim=-2` 会怎样?
> 答:会沿"被关注的位置(key)"维度而非"query 行"做归一化,语义全错——每个 key 被瓜分成和为 1,而不是每个 query 的注意力权重和为 1,模型基本学不动。

### Q18.【手撕思路】给本项目的 `generate` 加 **temperature + top-k** 采样,写出关键改动并解释温度的作用。

**参考答案**:在取到 `logits[:, -1, :]` 之后、softmax 之前:
```python
logits = logits[:, -1, :] / temperature          # 1) 温度缩放
if top_k is not None:
    v, _ = torch.topk(logits, top_k)              # 2) 取最高 top_k
    logits[logits < v[:, [-1]]] = float("-inf")   # 其余置 -inf
probs = F.softmax(logits, dim=-1)
next_id = torch.multinomial(probs, num_samples=1)
```
- **temperature $\tau$**:logits 先除以 $\tau$ 再 softmax。$\tau<1$(如 0.5)放大 logits 差距 → 分布更尖、更"确定"、更像背书;$\tau>1$(如 1.5)拉平分布 → 更随机、更有创意但易出错;$\tau\to 0$ 退化为 **greedy/argmax**;$\tau\to\infty$ 退化为均匀采样。
- **top-k**:只在概率最高的 k 个候选里采样,砍掉长尾"低概率烂字符",生成更干净(文档练习 4/5 正是这两题)。
- 本项目原始 `generate` 等价于 `temperature=1` 且不截断(`multinomial` 全词表采样)。

> **追问**:top-k 和 top-p(nucleus)区别?
> 答:top-k 固定保留 k 个;top-p 保留**累计概率达 p** 的最小集合(候选数随分布尖锐度动态变化)。分布很尖时 top-p 自动只留少数候选,更自适应。

### Q19.【手撕思路】本项目推理是每生成一个 token 就把整段 `idx_cond` 重新 forward 一遍。怎么改成 **KV-cache** 增量解码?有什么收益与代价?

**参考答案**:
- 现状:`generate` 每步 `idx_cond = idx[:, -block_size:]` 再整段 forward,前面已算过的 K、V **被重复计算**,单步成本 $O(T^2)$,生成 n 个 token 总成本 $O(n\cdot T^2)$。
- KV-cache:缓存每层每个历史位置的 K、V;新 token 只算自己的 q/k/v,把新 k、v **append** 进 cache,新 q 对"cache 中所有 K"做注意力。单步降到 $O(T)$。
- 收益:推理大幅加速(尤其长序列),是所有 LLM 推理引擎(vLLM 等)的基础。
- 代价:**显存换时间**——KV-cache 占用 $\propto$ `2 × n_layer × T × n_kv_head × head_size`,长上下文/大 batch 下成为显存瓶颈 → 催生 MQA/GQA、PagedAttention。
- 本项目为教学清晰**故意不做** cache(短上下文、CPU、几十秒),但能讲清这一步是 infra 岗加分项。

> **追问**:用了 causal mask 才能 KV-cache,为什么?
> 答:causal 保证位置 $t$ 的表示只依赖 $\le t$ 的 K、V,历史一旦算出就**不会因为后续 token 而改变**,因此可安全缓存复用。双向(BERT)注意力下每个位置依赖全序列,加新 token 会改变旧位置表示,无法这样增量缓存。

### Q20. 残差连接为什么能让深层网络训得动?从梯度角度解释。

**参考答案**:
- 残差 `y = x + F(x)`,反向时 $\frac{\partial y}{\partial x} = I + \frac{\partial F}{\partial x}$。那个**恒等项 $I$** 提供一条梯度"高速公路":即使子层 $F$ 的 Jacobian 很小,梯度也能近乎无损地直接传到浅层,极大缓解深层的梯度消失。
- 同时残差让每层只需学习"相对上一层的增量"(易优化),配合 Pre-LN(把 LN 放进子层、残差路径保持干净恒等)效果更好。
- 本项目 `x = x + self.attn(self.ln1(x))` 就是这条高速公路;去掉残差、堆 3 层以上很容易训不动或退化。

### Q21. 如果训练时 loss 突然变成 NaN 或不下降,你会怎么排查?(结合本项目超参)

**参考答案**(分层排查):
1. **学习率太大**:最常见。本项目 `learning_rate=3e-3` 对 toy 可以,放大模型/数据后需调小(如 1e-3),文档"常见坑"也指明"loss 变 NaN 多半是学习率太大"。加 **grad clipping**(`clip_grad_norm_`)。
2. **数值溢出**:mask 全 `-inf` 行 → softmax NaN;混合精度(fp16)下 attention 溢出 → 用 fp32 softmax 或 bf16。
3. **数据/标签错位**:检查 `y` 是否真的右移一位、cross_entropy 的 view 维度是否对齐。
4. **初始化/warmup**:Post-LN 缺 warmup 易发散(本项目 Pre-LN 规避了);检查是否漏了 `ln_f`。
5. **梯度没清零**:漏 `zero_grad` 会梯度叠加爆炸。
6. **loss 不降但不 NaN**:lr 太小、模型容量不足(`n_layer/n_embd` 太小)、或数据没 shuffle。

> **追问**:本项目用 AdamW 而不是 SGD,差别在哪?
> 答:Adam/AdamW 用一阶+二阶动量做**逐参数自适应学习率**,对 Transformer 这种各参数尺度差异大的网络收敛快、好调;AdamW 把 **weight decay 从梯度里解耦**(直接作用在参数上),正则更正确。Transformer 训练几乎默认 AdamW。

### Q22. 本项目 `pos_emb` 只有 `block_size=64` 行,这对推理有什么硬约束?怎么突破?

**参考答案**:
- 硬约束:**绝对位置嵌入表只有 64 行**,序列超过 64 就没有对应的位置向量(直接索引越界)。所以 `generate` 里必须 `idx_cond = idx[:, -block_size:]`——只能"滑窗"看最近 64 个字符,**无法真正扩展上下文**。
- 突破方向:
  - 换成 **RoPE/ALiBi**:不依赖固定大小的位置表,支持外推(配 NTK 插值还能进一步拉长)。
  - 训练更长 `block_size`(代价:注意力 $O(T^2)$ 显存/算力上涨)。
  - 长度插值(position interpolation)等后训练扩展技巧。
- 这是绝对位置嵌入的本质短板,也是现代 LLM 改用 RoPE 的核心动因之一。

## 高频追问速答清单

- **为什么除以 $\sqrt{d_k}$?** → 控制点积方差 ~1,防 softmax 饱和、梯度消失。
- **causal mask 加在 softmax 前还是后?** → 前(填 -inf,softmax 后权重为 0)。
- **softmax 在哪个维度?** → `dim=-1`(每个 query 行的注意力权重和为 1)。
- **多头会增加计算量吗?** → 不会,是把 $d$ 切分并行,总量不变。
- **attention 复杂度?** → 时间 $O(T^2 d)$,显存 $O(T^2)$;长上下文瓶颈。
- **训练 FLOPs 心算?** → $\approx 6ND$;推理单 token $\approx 2N$。
- **Transformer 主体参数心算?** → $\approx 12\,n_{layer}\,d^2$。
- **Pre-LN 比 Post-LN 好在哪?** → 残差路径干净、深层稳、不依赖 warmup;但末尾要补 `ln_f`。
- **temperature 趋于 0 / 无穷?** → 0 → greedy/argmax;无穷 → 均匀随机。
- **train loss 极低代表模型强?** → 不一定,可能过拟合,要看 held-out / val loss。
- **`zero_grad` 为何在 `backward` 前?** → PyTorch 梯度默认累加,不清零会叠加出错。
- **`view` 前为何 `.contiguous()`?** → transpose 后内存不连续,view 需连续内存。
- **KV-cache 为什么需要 causal?** → 历史 K/V 不随新 token 改变,才能安全缓存复用。
