## 0. 一句话锚点

**集合通信（Collective Communication）= 一组进程在同一时刻，按某种「全员参与」的固定模式互相搬运数据。** 区别于「一个发一个收」的点对点通信（Send/Recv），集合操作里 **每个进程既是参与者也是受益者**，比如 AllReduce 之后「人人手里都是全员求和的结果」。深度学习里 99% 的多卡通信都能归结为下面 5～6 个原语。

## 1. 地基 / 前置（从最底层讲起）

在看任何原语之前，先把几个最原子的概念钉死，否则后面图都看不懂。

**进程（rank）。** 分布式作业里每张 GPU 通常对应一个进程。给每个进程编号 $0,1,\dots,N-1$，这个号叫 **rank**。`world_size = N` 是进程总数。所有原语都是「这 $N$ 个 rank 一起做一件事」。

**通信子 / 进程组（communicator / process group）。** 一个原语作用在「哪些 rank 上」由进程组界定。全局组包含所有卡；也可以建子组（比如只在「同一台机器的 8 张卡」上做）。MPI 叫 communicator，PyTorch 叫 process group。

**缓冲区（buffer）。** 每个 rank 在显存里有一块 **发送缓冲区**（要拿出去的数据）和一块 **接收缓冲区**（用来装结果）。原语本质就是「按规则在这些 buffer 之间搬字节」。

**归约操作（reduce op）。** 有些原语会把多份数据「合并成一份」，合并方式就是归约算子：`SUM`（求和，梯度同步最常用）、`MAX`、`MIN`、`PROD`、`AVG`。归约必须满足结合律+交换律，这样才能任意分组并行算。

**同步语义。** 集合操作是 **隐式同步点**：所有 rank 都得调用同一个原语、参数一致，否则会卡死（一个在等，另一个没来）。这就是为什么分布式 bug 经常表现为「hang 住」。

```
一台 8 卡机器上的进程组（world_size = 8）
 GPU0   GPU1   GPU2   GPU3   GPU4   GPU5   GPU6   GPU7
 rank0  rank1  rank2  rank3  rank4  rank5  rank6  rank7
  └──────┴──────┴──────┴───NVLink/NVSwitch 互联────┴────┘
        所有 rank 在同一个 communicator 里
```

**记号约定（后面通篇用）。** 设有 $N$ 个 rank，每个 rank 持有大小为 $S$ 字节的数据（或被切成 $N$ 块、每块 $S/N$）。我们关心两个量：**每个 rank 收发的总字节数** 和 **通信轮数**。

## 2. Broadcast（广播）

**语义。** 指定一个 **根 rank（root）**，把它 buffer 里的数据原样复制给所有其它 rank。结束后人人持有一份相同的数据。

**为什么需要。** 训练开始时，要保证所有卡的初始模型参数完全一致 → 由 rank0 加载好权重，Broadcast 给全员。

```
Broadcast(root = 0)            ─────────►  结果
 rank0: [A]                    rank0: [A]
 rank1: [ ]                    rank1: [A]
 rank2: [ ]                    rank2: [A]
 rank3: [ ]                    rank3: [A]
        └── root 的 A 复制到所有人 ──┘
```

**通信量直觉。** 朴素实现 root 发 $N-1$ 份，root 出口带宽是瓶颈；高效实现用 **树形/流水线**（root→2 个→4 个…）把延迟降到 $O(\log N)$。

## 3. Scatter（散播）

**语义。** root 把自己的数据 **切成 $N$ 块**，第 $i$ 块发给 rank $i$（自己留第 0 块）。和 Broadcast 的区别：Broadcast 是「人人拿到完整副本」，Scatter 是「每人只拿到自己那一片」。

```
Scatter(root = 0)             ─────────►  结果
 rank0: [A0|A1|A2|A3]         rank0: [A0]
 rank1: [ ]                   rank1: [A1]
 rank2: [ ]                   rank2: [A2]
 rank3: [ ]                   rank3: [A3]
        └── 第 i 块发给 rank i ──┘
```

## 4. Gather（收集）

**语义。** Scatter 的逆操作。每个 rank 把自己的一小块发给 root，root 把 $N$ 块拼成完整数据。只有 root 拿到全部结果。

```
Gather(root = 0)              ─────────►  结果
 rank0: [A0]                  rank0: [A0|A1|A2|A3]
 rank1: [A1]                  rank1: [A1]
 rank2: [A2]                  rank2: [A2]
 rank3: [A3]                  rank3: [A3]
        └── 每人的块汇到 root ──┘
```

## 5. AllGather（全收集）

**语义。** Gather + Broadcast 的组合效果：每个 rank 持有一块，操作后 **每个 rank 都拿到「全员拼起来的完整数据」**。注意：只拼接、**不归约**（不求和），数据总量从 $S/N \times N$ 变成每人 $S$。

**为什么需要。** ZeRO / FSDP 里参数被切片存在不同卡上，前向计算前需要把完整一层参数「拼回来」→ AllGather。

```
AllGather                     ─────────►  结果（人人完整）
 rank0: [A0]                  rank0: [A0|A1|A2|A3]
 rank1: [A1]                  rank1: [A0|A1|A2|A3]
 rank2: [A2]                  rank2: [A0|A1|A2|A3]
 rank3: [A3]                  rank3: [A0|A1|A2|A3]
        └─ 把各自的块互相补全 ─┘
```

**通信量。** 每个 rank 最终持有 $S$ 字节，但其中 $S/N$ 是自己原有的，需要 **收进** 其余 $(N-1)$ 块即 $\frac{N-1}{N}S$ 字节；环形实现下每个 rank 收发各约 $\frac{N-1}{N}S$。

## 6. ReduceScatter（归约-散播）

**语义。** AllGather 的「对偶」。输入：每个 rank 持有一份完整的 $N$ 块数据；操作：把所有 rank 对应的块 **逐块归约（求和）**，然后把第 $i$ 块归约结果 **只留给 rank $i$**。结果是「归约后切片分发」。

**为什么需要。** 它是 Ring-AllReduce 的前半程；也是 ZeRO 切分梯度的关键——梯度求和后，每张卡只需保留自己负责的那一片。

```
ReduceScatter（op = SUM）     ─────────►  结果（归约后每人一片）
 rank0: [a0|a1|a2|a3]         rank0: [a0+b0+c0+d0]
 rank1: [b0|b1|b2|b3]         rank1: [a1+b1+c1+d1]
 rank2: [c0|c1|c2|c3]         rank2: [a2+b2+c2+d2]
 rank3: [d0|d1|d2|d3]         rank3: [a3+b3+c3+d3]
   └ 第 i 列跨 rank 求和 → 结果归 rank i ┘
```

## 7. AllReduce（全归约）—— 主角

**语义。** 每个 rank 持有一份数据（同样 shape）；操作后 **每个 rank 都拿到「所有 rank 数据按 op 归约后的结果」**。最常见是 `SUM`：所有卡的梯度逐元素相加，人人拿到全局梯度和。

**等价拆解（关键认知）。**
$$\text{AllReduce} \;=\; \text{ReduceScatter} \;+\; \text{AllGather}$$
先把数据切片、跨卡归约（每人拿到一片归约结果），再把这些片互相补全（人人拿到完整归约结果）。Ring-AllReduce 正是这么实现的。

```
AllReduce（op = SUM, 标量示意）
 rank0: [3]                   rank0: [3+1+4+2 = 10]
 rank1: [1]      ───────►     rank1: [10]
 rank2: [4]                   rank2: [10]
 rank3: [2]                   rank3: [10]
        └── 全员求和后人人相同 ──┘
```

**为什么 AllReduce 是数据并行的命脉。** 数据并行里每张卡用不同 minibatch 算出 **不同的梯度**，要更新出一致的模型，必须先把梯度求和（或求平均）再更新。这一步就是对梯度张量做 AllReduce(SUM)。

## 8. Ring-AllReduce 算法（带宽最优）

朴素 AllReduce（所有卡把数据发给一个 root 求和再广播回去）会让 root 的带宽成为瓶颈，且与 $N$ 无关地浪费。**Ring-AllReduce** 把 $N$ 张卡组成一个 **逻辑环**，让 **每条链路同时双向满负荷工作**，做到通信量与 $N$ 几乎无关——这是 NCCL 的默认主力算法之一。

### 8.1 环形拓扑

```
   ┌──► rank0 ──► rank1 ──► rank2 ──► rank3 ──┐
   └──────────────────（环回到 rank0）────────┘
   每个 rank 只和「右邻居」发、从「左邻居」收
```

每个 rank 把自己的数据切成 $N$ 个 **chunk**（块）。整个算法分两大阶段，每阶段 $N-1$ 步。

### 8.2 两个阶段

**阶段一：Reduce-Scatter（$N-1$ 步）。** 每一步，每个 rank 向右邻居发一个 chunk、从左邻居收一个 chunk 并 **累加** 到本地对应位置。$N-1$ 步后，每个 rank 上「恰好有一个 chunk」是全员求和的完整结果（不同 rank 负责不同 chunk）。

**阶段二：All-Gather（$N-1$ 步）。** 现在每个 rank 各持有一个「已完成归约」的 chunk，再沿环传 $N-1$ 步，把这些完成块互相复制（这次是 **覆盖**，不是累加），$N-1$ 步后人人持有全部 $N$ 个完成块 → 完整的 AllReduce 结果。

### 8.3 通信量推导 $\dfrac{2(N-1)}{N}S$

设每个 rank 总数据 $S$ 字节，切成 $N$ 个 chunk，**每个 chunk = $S/N$ 字节**。

- **阶段一**共 $N-1$ 步，每步每个 rank 发送恰好 1 个 chunk → 发送 $(N-1)\cdot\dfrac{S}{N}$ 字节。
- **阶段二**同样 $N-1$ 步，每步发送 1 个 chunk → 又发送 $(N-1)\cdot\dfrac{S}{N}$ 字节。

把两阶段相加，**每个 rank 发送（接收同理）的总字节数**：
$$
V \;=\; \underbrace{(N-1)\frac{S}{N}}_{\text{ReduceScatter}} \;+\; \underbrace{(N-1)\frac{S}{N}}_{\text{AllGather}} \;=\; \frac{2(N-1)}{N}\,S.
$$

**为什么这叫「带宽最优」。** 当 $N$ 很大时，$\dfrac{2(N-1)}{N}\to 2$，即每个 rank 的传输量趋于 **常数 $2S$**，与卡数 $N$ 无关！朴素方案中 root 要收 $N{-}1$ 份（量随 $N$ 线性涨），而 Ring 把负载均摊到每条链路，因此扩展性极好。代价是 **步数 $2(N-1)$ 随 $N$ 线性增长**——所以小数据、超多卡时延迟敏感，NCCL 会改用 Tree/Double-Binary-Tree 算法降延迟（详见 [[ai-infra/网络/NCCL]]）。

```
两阶段字节账本（每 rank 视角）
 ReduceScatter: (N-1) 步 × (S/N) = (N-1)/N · S  发出
 AllGather    : (N-1) 步 × (S/N) = (N-1)/N · S  发出
 ─────────────────────────────────────────────
 合计                              2(N-1)/N · S
```

## 9. 在 DP / TP / PP 里各用哪个原语

这是面试高频题：不同并行策略的通信「形状」完全不同，对应不同原语。

| 并行策略 | 通信发生在 | 主用原语 | 为什么 |
| --- | --- | --- | --- |
| **数据并行 DP**（DDP） | 反向后同步梯度 | **AllReduce(SUM)** | 各卡梯度不同，需全局求和再更新；人人都要拿到完整梯度 |
| **ZeRO / FSDP** | 梯度切分 + 参数重组 | **ReduceScatter**（同步梯度）+ **AllGather**（前向取参数） | 梯度求和后每卡只留自己那片（省显存）；用参数前再拼回完整层 |
| **张量并行 TP** | 层内矩阵切分的前/反向 | **AllReduce** 或 **AllGather** | 列切分后各卡算部分和，需 AllReduce 合并；行/列切换处用 AllGather 拼接激活 |
| **流水并行 PP** | 相邻 stage 间传激活/梯度 | **Send/Recv**（点对点，非集合） | 只在前后两个 stage 之间传，不是全员，故用 P2P |
| **专家并行 MoE** | token 路由到不同专家卡 | **All2All** | 每卡要把不同 token 发到不同专家所在卡，是「全员对全员」的重排 |

**TP 细看（以 Megatron 为例的直觉）。** 一个 $Y = XA$，按列把 $A$ 切给各卡，各卡算出 $Y$ 的不同列分块——这步不用通信（AllGather 在需要完整 $Y$ 时才做）；紧接着 $Z = YB$ 按行切 $B$，各卡算出 $Z$ 的 **部分和**，要把这些部分和相加得到完整 $Z$ → 这一步就是 **AllReduce**。所以 TP 一个 transformer 层前向通常 2 次 AllReduce（attention 1 次 + MLP 1 次），反向再 2 次。

## 10. 数值示例 / 手算 Ring-AllReduce

用 $N=4$ 张卡，每卡一个长度为 4 的向量（即切成 4 个 chunk，每 chunk 是 1 个标量）。目标：AllReduce(SUM)，人人拿到逐元素和。

**初始数据**（行=rank，列=chunk 索引 c0..c3）：

```
        c0   c1   c2   c3
 rank0 [ 1    2    3    4 ]
 rank1 [ 5    6    7    8 ]
 rank2 [ 9   10   11   12 ]
 rank3 [13   14   15   16 ]
```

正确答案应为每列求和：c0=28, c1=32, c2=36, c3=40。我们看 Ring 怎么算出来。

**阶段一 ReduceScatter（3 步，每 rank 发右邻、收左邻并累加）。** 约定：第 $k$ 步 rank $r$ 发出 chunk 索引 $(r-k)\bmod 4$。最终 rank $r$ 负责攒齐 chunk $(r+1)\bmod 4$。

```
步1：rank0→c0给r1, r1→c1给r2, r2→c2给r3, r3→c3给r0（收到即累加）
  r0.c3 += 16 → 4+16 = 20
  r1.c0 += 1  → 5+1  = 6
  r2.c1 += 6  → 10+6 = 16
  r3.c2 += 11 → 15+11= 26

步2：继续沿环传「正在长大的那个 chunk」
  r1.c0 收到 r0 的 13(=rank3.c0?) ... 累加链推进
  关键结果：每条链上有一个 chunk 在不断 += 邻居贡献

步3 结束后（每 rank 恰好有 1 个 chunk 是全列和）：
  rank0 攒齐 c1 = 2+6+10+14 = 32   ✔
  rank1 攒齐 c2 = 3+7+11+15 = 36   ✔
  rank2 攒齐 c3 = 4+8+12+16 = 40   ✔
  rank3 攒齐 c0 = 1+5+9+13  = 28   ✔
```

阶段一结束，4 个列和分散在 4 张卡上（每卡一个完整结果块）。**校验**：28+32+36+40 与逐列直接相加完全一致。

**阶段二 AllGather（3 步，把完成块沿环复制，覆盖不累加）。**

```
起点：r0持c1=32, r1持c2=36, r2持c3=40, r3持c0=28
步1：每 rank 把「自己刚完成的块」发右邻 → 右邻覆盖写入
步2：把「上一步收到的块」继续右传
步3：再传一轮
结束：每个 rank 都集齐 4 个完成块
  rank0/1/2/3 都 = [c0=28, c1=32, c2=36, c3=40]
```

**通信量核对（手算公式）。** $N=4,\ S=4$ 个标量（每 chunk $S/N=1$）：
$$
V = \frac{2(N-1)}{N}S = \frac{2\times 3}{4}\times 4 = 6 \text{ 个标量 / rank}.
$$
逐步数：阶段一发 3 个 + 阶段二发 3 个 = **6 个**，与公式吻合。对比朴素「全发 root」方案，root 要收 $3\times4=12$ 个再广播 12 个，瓶颈链路压力远大于 Ring 的均摊 6 个。

## 11. 对照 / 复杂度表

记 $N$=rank 数，$S$=每 rank 数据量（字节），$\alpha$=单次延迟，$\beta$=每字节传输时间。

| 原语 | 结束后每 rank 持有 | 是否归约 | 每 rank 收发量（Ring/高效实现） | 典型用途 |
| --- | --- | --- | --- | --- |
| Broadcast | root 的完整数据 | 否 | $\approx S$ | 初始权重同步 |
| Scatter | 自己那 1 片 | 否 | $\approx \frac{N-1}{N}S$（root 侧） | 分发数据分片 |
| Gather | root 得完整 | 否 | $\approx \frac{N-1}{N}S$（root 侧） | 汇总结果 |
| AllGather | 全员完整拼接 | 否 | $\frac{N-1}{N}S$ | FSDP 参数重组 |
| ReduceScatter | 归约后自己那 1 片 | 是 | $\frac{N-1}{N}S$ | ZeRO 梯度切分 |
| **AllReduce** | 全员完整归约结果 | 是 | $\frac{2(N-1)}{N}S$ | **DP 梯度同步** |
| All2All | 重排后的他人数据 | 否 | $\approx \frac{N-1}{N}S$ | MoE token 路由 |

**Ring-AllReduce 时间模型：** $T \approx 2(N-1)\alpha + \dfrac{2(N-1)}{N}S\beta$。前项延迟随 $N$ 涨（大 $N$ 小数据用 Tree 更优），后项带宽项随 $N$ 趋于常数 $2S\beta$（大数据 Ring 最优）。

## 12. 常见问题（疑问 → 真相）

| 疑问 | 真相 |
| --- | --- |
| AllReduce 和 AllGather 区别？ | AllReduce **归约**（求和/取最值），数据量不变、人人同值；AllGather **拼接不归约**，数据量变 $N$ 倍 |
| 为什么 AllReduce = ReduceScatter + AllGather？ | 先切片归约（每人一片结果），再把片互相补全，刚好得到完整归约结果；Ring 就这么实现 |
| $2(N-1)/N$ 里的 2 从哪来？ | 两个阶段各跑 $N-1$ 步、各发 $\frac{N-1}{N}S$，相加得 2 倍 |
| 为何说 Ring「带宽最优、延迟不优」？ | 带宽项 $\to 2S$ 与 $N$ 无关；但步数 $2(N-1)$ 随 $N$ 线性增长，故超多卡/小张量延迟高，改用 Tree |
| DP 一定用 AllReduce 吗？ | DDP 用 AllReduce(SUM)；ZeRO/FSDP 拆成 ReduceScatter+AllGather 以省显存，本质等价 |
| 流水并行 PP 为啥不用集合通信？ | PP 只在相邻 stage 间传激活，是两点之间的事，用 P2P Send/Recv 而非全员原语 |
| 所有 rank 必须调用同一原语吗？ | 是。参数/顺序不一致会死锁 hang，分布式排错第一嫌疑 |
| 求平均怎么做？ | AllReduce(SUM) 后各卡本地除以 $N$；或直接用 op=AVG（NCCL 支持） |
| NCCL 怎么选 Ring 还是 Tree？ | 按数据量、卡数、拓扑自动选；大数据 Ring，小数据多机 Tree，细节见 [[ai-infra/网络/NCCL]] |
| 这些字节最终走什么物理链路？ | 机内走 NVLink/NVSwitch，机间走 [[ai-infra/网络/InfiniBand]]/RoCE；带宽与拓扑决定 $\beta$ |
