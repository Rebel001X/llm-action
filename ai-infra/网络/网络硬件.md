## 0. 一句话锚点

**单张 GPU 再快，算不完一个大模型；几千张 GPU 必须靠网络"对齐梯度"，于是网络的带宽和延迟直接决定了集群能跑多大、多快。** 训练里 GPU 每跑完一步就要做一次 **AllReduce**（把各卡梯度求和再广播回去），这一步走的是网络。网络慢一点，几千张昂贵的 GPU 就一起"等"。所以 AI 数据中心把网络当成一等公民来设计——这就是本文要拆的硬件。

## 1. 地基：先把单位和概念钉死

不假设你记得这些，全部拆到最原子。

### 1.1 bit 与 Byte（最容易踩的坑）

- **bit（位，b）**：0 或 1，信息的最小单位。
- **Byte（字节，B）**：$1\text{ B} = 8\text{ bit}$。
- 网络速率几乎都用 **bit**：`400G` = $400\text{ Gbps}$ = 每秒 4000 亿 bit。
- 内存/存储/张量大小几乎都用 **Byte**：一个 FP16 数 = 2 B。

换算：$400\text{ Gbps} = 400/8 = 50\text{ GB/s}$。**记不住就记"除以 8"。** 工程师互相说话时一定要确认是 Gbps 还是 GB/s，差 8 倍。

### 1.2 带宽 vs 延迟（两个不同的东西）

```
      带宽 Bandwidth = 管子有多粗（每秒能灌多少数据）
      延迟 Latency   = 水从这头到那头要多久（哪怕只滴一滴）

   ┌─────────────────────────────┐
   │  小消息(梯度桶很小) → 延迟主导  │  ← 启动开销、排队
   │  大消息(梯度桶很大) → 带宽主导  │  ← 灌满管子
   └─────────────────────────────┘
```

- **带宽**：单位 GB/s。决定大块梯度传完要多久。
- **延迟**：单位 μs（微秒）。决定一次通信"启动"要多久。IB 端到端 ~1–2 μs，以太网 RoCE ~3–5 μs（约，以实测为准）。
- 训练里两者都重要：AllReduce 既有大块数据（吃带宽），又有很多次小同步（吃延迟）。

### 1.3 Serdes 与 lane（理解 400G/800G 的钥匙）

- **Serdes**（Serializer/Deserializer）：把芯片内部的并行信号"串行化"成一根线上的高速电/光信号。
- **lane（通道）**：一条物理收发对。一个端口由若干 lane 组成。
- 当前主流单 lane = **100G（PAM4 调制）**。所以：
  - 400G = $4 \times 100\text{G}$（4 lane）
  - 800G = $8 \times 100\text{G}$（8 lane）
- **PAM4**：一个符号编码 2 bit（4 个电平），相比 NRZ（1 bit/符号）翻倍速率，但信噪容限更小、更易误码——这就是为什么高速光模块越来越贵、越来越"娇气"。

## 2. 网卡 NIC / HCA：GPU 通向网络的"出口"

### 2.1 它是什么

- **NIC**（Network Interface Card，网卡）：把服务器接入网络的板卡。
- IB 世界里叫 **HCA**（Host Channel Adapter，主机通道适配器），本质同类。
- AI 集群代表产品：NVIDIA（Mellanox）**ConnectX** 系列、**BlueField** DPU。

### 2.2 关键能力：RDMA（这是 AI 网卡的灵魂）

普通 TCP/IP 收发数据要 CPU 一路搬运、拷贝多次、走内核协议栈，延迟高、占 CPU。**RDMA（Remote Direct Memory Access，远程直接内存访问）** 让一台机器的网卡**直接读写另一台机器的内存**，绕过远端 CPU 和内核。

```
   普通 TCP/IP：
   App → 内核协议栈 → 多次内存拷贝 → CPU 中断 → NIC → 网络 → ……（反向同样繁琐）

   RDMA：
   App 注册一块内存 → NIC 直接 DMA 搬运 → 网络 → 远端 NIC 直接写入远端内存
                         ↑ CPU 几乎不参与，零拷贝，延迟低
```

- IB 原生支持 RDMA；以太网上用 **RoCE**（RDMA over Converged Ethernet）实现，详见 [[ai-infra/网络/roce]]。

### 2.3 GPUDirect RDMA：让网卡直接喂 GPU

- 没有它：GPU 显存 → 拷到主机内存 → 网卡发出去（多一次 PCIe 往返）。
- 有它：**网卡直接通过 PCIe 读写 GPU 显存**，数据不经过 CPU/主机内存。
- 这是 NCCL 在多机训练里跑满带宽的前提，详见 [[ai-infra/网络/NCCL]]。

```
   ┌────────┐  PCIe   ┌────────┐
   │  GPU   │◄───────►│  NIC   │──► 网络（直奔远端 GPU）
   │ 显存   │ GPUDirect│ (HCA) │
   └────────┘  RDMA    └────────┘
      （CPU / 主机内存 被绕过）
```

### 2.4 典型规格（约，以官方为准）

| 网卡 | 单口速率 | 接口 | 备注 |
|---|---|---|---|
| ConnectX-6 | 200 Gbps (HDR) | PCIe 4.0 | A100 时代常见 |
| ConnectX-7 | 400 Gbps (NDR) | PCIe 5.0 | H100 时代主流 |
| ConnectX-8 | 800 Gbps (XDR) | PCIe 6.0 | 新一代 |

注意：**网卡速率要和 PCIe 带宽匹配**。PCIe 5.0 x16 单向约 $\approx 64\text{ GB/s} \approx 512\text{ Gbps}$，刚好喂得动 400G 网卡；800G 网卡需要 PCIe 6.0 或双 x16。这是常见的"瓶颈对齐"问题。

## 3. 交换机：把许多机器连起来

交换机（Switch）是端口很多的"集线盒"，把成百上千条线汇聚、转发。AI 集群里分两大阵营。

### 3.1 InfiniBand 交换机 vs 以太网交换机

```
        ┌──────────────────────┬──────────────────────┐
        │   InfiniBand 交换机     │    以太网交换机          │
        ├──────────────────────┼──────────────────────┤
   代表   │ NVIDIA Quantum 系列    │ Spectrum / Broadcom    │
        │ Quantum-2 = 400G      │ Tomahawk / Trident     │
   协议   │ IB 原生 RDMA          │ TCP/RoCE(需调优)       │
   流控   │ 信用(Credit)-based    │ PFC + ECN (易丢包/抖动)│
        │ 链路层"无损"天生        │ 需精细配置才"无损"      │
   延迟   │ 极低 ~1μs/跳          │ 略高 ~3-5μs/跳          │
   生态   │ 封闭(主要 NVIDIA)      │ 开放(多厂商/便宜)       │
   运维   │ SM 子网管理器统一管理   │ 标准网络团队就会         │
        └──────────────────────┴──────────────────────┘
```

**核心差异在"流控"——这决定了为什么 IB 在训练上更稳：**

- **IB 信用流控（credit-based）**：发送方只有在收到接收方"我还有缓冲区"的信用额度时才发包，**从源头不会发生缓冲区溢出 → 天生不丢包（无损）**。
- **以太网**默认会丢包（缓冲满了就扔），靠上层重传。为做"无损"要靠 **PFC**（优先级流控：缓冲快满就发暂停帧）+ **ECN**（拥塞标记，让发送端降速）。配置稍有不慎就会出现 PFC 死锁、拥塞扩散、尾延迟暴涨——这是 RoCE 部署最头疼的地方（详见 [[ai-infra/网络/roce]]）。

**选型一句话**：要极致稳定/低延迟、预算够、接受被 NVIDIA 绑定 → **IB**；要开放生态、复用现有以太网团队、规模超大想省钱 → **RoCE 以太网**（但要养得起会调 PFC/ECN 的人）。详细对比见 [[ai-infra/网络/InfiniBand]] 与 [[ai-infra/网络/Spine-Leaf和InfiniBand网络架构区别简述]]。

### 3.2 交换机的"基数"(radix) 与交换容量

- **radix（基数）**：一颗交换芯片有多少个端口。Quantum-2 约 64 个 400G 口（也可拆成更多低速口）。
- **交换容量**：$\text{容量} = \text{端口数} \times \text{单口速率}$。如 $64 \times 400\text{G} = 25.6\text{ Tbps}$。
- radix 越大，**搭同样规模集群需要的交换机层数越少 → 跳数少、延迟低、成本省**。这是为什么大家追求高 radix 芯片。

## 4. 光模块与线缆：信号怎么真正跑过去

端口之间靠什么物理连接？三种主力。

```
   短距(<3m, 机柜内)          中距(<30m, 机柜间)        长距(机房/楼间)
   ┌──────────────┐          ┌──────────────┐        ┌──────────────┐
   │  DAC 铜缆      │          │  AOC 有源光缆  │        │ 光模块+光纤跳线│
   │ 直连铜线无光电  │          │ 两端集成光模块  │        │ 可插拔模块分体  │
   │ 便宜/省电/低延  │          │ 比DAC贵/能拉长 │        │ 最贵/最灵活/最远│
   └──────────────┘          └──────────────┘        └──────────────┘
```

### 4.1 三种连接方式

- **DAC（Direct Attach Cable，直连铜缆）**：纯铜线，两端是固定的连接头。最便宜、几乎不耗电、延迟最低，但**距离短**（无源 DAC 一般 <2–3 m）。机柜内 GPU 服务器到 Leaf 交换机常用。
- **AOC（Active Optical Cable，有源光缆）**：两端**焊死了光模块**的一根光纤线，做了光电转换，能拉到几十米；比 DAC 贵、耗电，但比"模块+裸纤"灵活度低（坏了整根换）。
- **可插拔光模块（Optical Transceiver）+ 光纤跳线**：光模块（如 QSFP-DD、OSFP 封装）插在交换机/网卡笼子里，中间用 **MPO/MTP 多芯光纤**或 LC 单芯连接。最贵、最耗电、但距离最远、最灵活（模块和线分别可换）。大集群 Spine 层、跨机房必用。

### 4.2 封装与接口名词（不被名字吓到）

- **QSFP**（Quad SFP）：4 lane 封装；**QSFP-DD**（Double Density）= 8 lane → 撑 400G/800G。
- **OSFP**（Octal SFP）：8 lane，体积稍大、散热更好，800G/1.6T 常用。
- **MPO/MTP**：一个接头里塞 8/12/16 根光纤的多芯连接器，给多 lane 光模块用。

### 4.3 一个容易忽视的现实：光模块是耗电和故障大户

- 一个 800G 光模块功耗约 **13–16 W**（约，以官方为准）。一个万卡集群可能有**几万个光模块**，光这一项就是百千瓦级功耗 + 高故障率（光模块是数据中心常见故障源）。这催生了 **LPO（线性直驱）/CPO（共封装光学）** 等省电方向。

## 5. 速率代际：100G → 400G → 800G → 1.6T

为什么这些数字总是 4 倍、8 倍跳？因为速率 = **lane 速率 × lane 数**。

```
   单 lane 速率演进：  25G(NRZ) → 50G(PAM4) → 100G(PAM4) → 200G(PAM4) ...

   端口速率 = lane速率 × lane数
   ┌─────────┬──────────┬─────────────────────────┐
   │ 端口     │ 组成      │ 对应换算(GB/s, ÷8)        │
   ├─────────┼──────────┼─────────────────────────┤
   │ 100G    │ 1×100G   │ 12.5 GB/s               │
   │ 400G    │ 4×100G   │ 50  GB/s                │
   │ 800G    │ 8×100G   │ 100 GB/s                │
   │ 1.6T    │ 8×200G   │ 200 GB/s                │
   └─────────┴──────────┴─────────────────────────┘
```

- **400G（NDR）**：H100 时代主力。ConnectX-7 单口 400G。
- **800G（XDR）**：当前新一代，靠 8×100G 或 4×200G。一台 8 卡服务器配 8 张网卡可达 $8 \times 400/800\text{G}$ 的对外总带宽。
- **1.6T**：下一代，靠 200G/lane × 8。
- 每提一代，PAM4 信号更难、布线更短、光模块更贵更热——这是带宽提升的**代价**，不是免费午餐。

## 6. 拓扑：胖树（Fat-Tree）与多轨（Rail）

有了网卡、交换机、线缆，怎么"连"才能让任意两张 GPU 都快速通信？答案是拓扑设计。

### 6.1 为什么不能"一台大交换机连所有"

一台交换机端口有限（radix ~64）。要连几千张卡，必须**多台交换机分层组网**。目标：**无阻塞（non-blocking）**——任意两台机器全速通信时，中间不堵车。

### 6.2 胖树 / Spine-Leaf

```
                      ┌──────── Spine 脊交换机 ────────┐
                      │   S1     S2     S3     S4      │   ← 上层：汇聚
                      └──┬───┬───┬───┬───┬───┬───┬──┘
              ┌──────────┼───┼───┼───┼───┼───┼───┼──────────┐
              │ 每个 Leaf 都连到每个 Spine（全连接），上下行带宽相等 │
           ┌──┴──┐   ┌──┴──┐   ┌──┴──┐   ┌──┴──┐
           │Leaf1│   │Leaf2│   │Leaf3│   │Leaf4│   ← 下层：接入(ToR)
           └┬┬┬┬─┘   └┬┬┬┬─┘   └┬┬┬┬─┘   └┬┬┬┬─┘
            ││││       ││││       ││││       ││││
          GPU服务器   GPU服务器   GPU服务器   GPU服务器
```

- **Leaf（叶/ToR，Top-of-Rack）**：直接连服务器的交换机，每个机柜一台。
- **Spine（脊）**：把所有 Leaf 互联。
- **胖树的精髓**：每个 Leaf **上行带宽 = 下行带宽**（"上粗下粗"，不是普通树的"上细下粗"），从而**任意两台机器之间都有全速无阻塞路径**。这就是为什么叫"胖"树。
- **超额订阅比（oversubscription）**：上行:下行。$1{:}1$ = 全无阻塞（最贵）；训练集群通常要求 $1{:}1$。存储/不那么吃带宽的可用 $2{:}1$、$3{:}1$ 省钱。

### 6.3 多轨（Rail-optimized）：AI 集群的精髓拓扑

一台 GPU 服务器有 8 张 GPU，每张 GPU 配一张专属网卡。**多轨**的做法是：把**所有服务器的第 0 号 GPU 的网卡连到同一组 Leaf（第 0 轨），第 1 号连到第 1 轨**……8 个 GPU = 8 条独立的"轨道"。

```
   服务器A                          服务器B
   GPU0─NIC0 ─┐                  ┌─ NIC0─GPU0
   GPU1─NIC1 ─┼─► Rail0 Leaf ◄──┼─ NIC1?  错！
   ...        │                  │
   GPU7─NIC7  │   每条 rail 独立成网，同号 GPU 走同一 rail

   正确：
   所有服务器的 GPU0→Rail0   所有服务器的 GPU1→Rail1  ...  GPU7→Rail7
   ┌───────────────────────────────────────────────┐
   │ Rail0交换机组 ─ 连所有机器的 GPU0                 │
   │ Rail1交换机组 ─ 连所有机器的 GPU1                 │
   │ ...                                            │
   │ Rail7交换机组 ─ 连所有机器的 GPU7                 │
   └───────────────────────────────────────────────┘
```

**为什么这么连？** NCCL 的 AllReduce 中，同号 GPU（rank 在同一组）之间通信最频繁。把同号 GPU 放进**同一条 rail 的同一组交换机**，让最热的流量**只在本 rail 内、最少跳数**完成；跨 rail 的少量流量再由机内 **NVLink** 在 8 张卡间搬运。这样既省交换机又降延迟。**Rail-optimized + Fat-Tree** 是当下大规模 GPU 集群（如 DGX SuperPOD）的标准做法，详见 [[ai-infra/ai-cluster/README]]。

## 7. 为什么网络是训练瓶颈

这是本文的"灵魂问题"。

### 7.1 训练每一步都要全集群同步梯度

数据并行（Data Parallel）下，每张 GPU 拿不同数据算出**自己的梯度**，但更新模型前必须把所有 GPU 的梯度**求平均**——这就是 **AllReduce**。模型有 $P$ 个参数（FP16 每个 2 B），AllReduce 要搬运的数据量与 $P$ 同量级。

### 7.2 Amdahl 式的"短板效应"

一步的时间 $\approx \max(\text{计算时间}, \text{通信时间})$（理想重叠）或两者之和（不重叠）。

$$
T_{\text{step}} \approx T_{\text{compute}} + T_{\text{comm}}(1 - \text{overlap})
$$

- GPU 算力每代翻倍（计算时间在缩短）。
- 模型越来越大 → 梯度越来越多 → 通信量在增大。
- **结果：通信占比越来越高**，网络稍慢，几千张 GPU 一起空等 → **利用率（MFU）暴跌**。

```
   理想：    [计算][计算][计算]   GPU 几乎不闲
   通信慢：  [计算]......[等网络]......[计算]......[等网络]
            ↑ 几千张昂贵 GPU 在这里"罚站"
```

### 7.3 Ring-AllReduce 的带宽需求（为什么要 400G/800G）

NCCL 用 **Ring-AllReduce**：$N$ 张卡排成环，数据分 $N$ 块，转 $2(N-1)$ 步。其每卡需搬运的数据量约为 $2\frac{N-1}{N}\times M$（$M$=梯度总字节，详见 [[ai-infra/网络/集合通信原语]] 与 [[ai-infra/网络/ringallreduce]]）。关键：**通信时间 ≈ 数据量 / 网络带宽**。带宽翻倍 → 通信时间减半 → GPU 等待减半。这就是把网卡/交换机推到 400G、800G 的根本动力。

### 7.4 通信与计算重叠（软件侧的"救命稻草"）

框架会把**反向传播算出的梯度边算边发**（梯度还没全算完就先 AllReduce 已算好的层），让通信"藏"在计算后面。但**重叠是有上限的**：通信量超过计算时间能掩盖的部分，网络就重新成为瓶颈。所以硬件（带宽）+ 软件（重叠 + 拓扑感知的 NCCL）必须一起上。

## 8. GPU 内部互联与 `nvidia-smi topo`（保留并展开原有内容）

机内 8 张 GPU 之间也要通信，走的不是网卡，而是 **NVLink**（GPU 直连高速总线，单卡聚合带宽可达数百 GB/s，远高于 PCIe）。`nvidia-smi topo -m` 会打印两两 GPU 之间的"连接质量"，从好到差：

```
   GPU 间通讯速度（从快到慢）：
   NV#  >  PIX  >  PXB  >  PHB  >  NODE  >  SYS
   越靠左越快（NVLink 直连），越靠右越慢（要绕远、跨 NUMA）
```

- **NV#**：穿越一组 `#` 条 **NVLink**（最快，GPU 直连，训练最希望走这条）。
- **PIX**：最多穿越**单个 PCIe 交换机**的连接。
- **PXB**：穿过**多个 PCIe 交换机**的连接（不穿过 PCIe 主机桥）。
- **PHB**：穿越 PCIe 以及 **PCIe 主机桥**（通常是 CPU）的连接。
- **NODE**：穿越 PCIe 以及 **NUMA 节点内** PCIe 主机桥之间的互连。
- **SYS**：穿越 PCIe 以及 **NUMA 节点之间** 的 SMP 互连（例如 QPI/UPI），最慢。

**为什么重要**：NCCL 会读这张拓扑表，自动把通信路径**优先排到 NVLink（NV#）上**，避免走慢的 SYS/PHB。机内 NVLink + 机间 Rail 网卡，构成"两级带宽体系"。

## 数值例子：1024 卡集群手算 + 成本对照

### 例 1：一步 AllReduce 要多久？

设 70B 参数模型，FP16 梯度：$M = 70\times10^9 \times 2\text{ B} = 140\text{ GB}$。
Ring-AllReduce 每卡搬运约 $2\times M = 280\text{ GB}$（取 $N$ 大时 $2(N-1)/N \approx 2$）。
单卡网卡 400G = 50 GB/s：

$$
T_{\text{comm}} \approx \frac{280\text{ GB}}{50\text{ GB/s}} = 5.6\text{ s}
$$

若换 800G（100 GB/s）：$T_{\text{comm}} \approx 2.8\text{ s}$，**直接砍半**。这就是 800G 的价值。（实际有重叠、分桶、效率因子，此为量级估算。）

### 例 2：1024 卡胖树要多少交换机和光模块？

- 1024 GPU，每卡 1 网卡 → 1024 个网卡端口。
- 设 Leaf 交换机 64 口（32 下行接服务器 + 32 上行接 Spine，做 1:1 无阻塞）。
- Leaf 数：$1024 / 32 = 32$ 台。
- Spine 数：每台 Leaf 32 个上行，要全连接 → 约 **32 台 Spine**（数量级）。
- 链路数（光模块要成对）：下行 1024 + 上行 $32\times32=1024$，合计约 2048 条链路 ≈ **4096 个光模块/线缆头**。

```
   规模放大效应：卡数翻倍 → Leaf/Spine/光模块大体线性翻倍
   万卡集群 → 几十万个光模块 → 光模块成本可占网络 BOM 的一大块
```

### 例 3：成本量级对照（公开口径量级，约，以实际报价为准）

| 项目 | 单价量级 | 说明 |
|---|---|---|
| 400G HCA 网卡 | 千美元级 | 每卡一张 |
| 400G 交换机(64口) | 数万美元级 | Leaf/Spine |
| 800G 光模块 | 数百~上千美元级/个 | **数量巨大→总额惊人** |
| DAC 铜缆 | 几十~上百美元 | 短距，最省 |
| AOC 有源光缆 | 数百美元 | 中距 |

**经验结论**：在大规模 GPU 集群里，网络（交换机+网卡+光模块+线缆）成本常占**总投资的 10–20%**（约，随设计而变）；其中**光模块数量随规模平方/线性膨胀**，是省钱的关键战场——这也是 IB 与 RoCE 之争里"成本"维度的核心。

## 常见问题

| 问题 | 答案 |
|---|---|
| IB 和以太网到底选哪个？ | 求极致稳定/低延迟、预算足 → IB；求开放/省钱/复用以太网团队 → RoCE，但要会调 PFC/ECN（见 [[ai-infra/网络/roce]]） |
| 400G 和 50GB/s 是一回事吗？ | 是。400 Gbps ÷ 8 = 50 GB/s。bit 与 Byte 差 8 倍 |
| 为什么训练要 400G/800G？普通服务器 25G 不够？ | 梯度同步搬运几十上百 GB，带宽翻倍直接砍掉一半通信时间，GPU 少空等 |
| 多轨（Rail）解决什么问题？ | 让最热的同号 GPU 流量只在本 rail 内最少跳数完成，省交换机、降延迟 |
| 为什么网络是瓶颈而不是 GPU？ | GPU 算力每代翻倍，模型/梯度也在涨，通信占比上升；网络慢则几千卡一起空等 |
| DAC、AOC、光模块怎么选？ | 机柜内短距用 DAC(便宜省电)；几十米用 AOC；远距/Spine 层用可插拔光模块+光纤 |
| NVLink 和网卡什么关系？ | NVLink 管机内 8 卡直连(最快)；网卡管机间通信。两级带宽体系，NCCL 自动择优(见第 8 节) |
| 光模块为什么是大坑？ | 数量巨大、功耗高(800G~15W)、是常见故障源；催生 LPO/CPO 省电方向 |
| 网卡 400G 配 PCIe 4.0 行不行？ | 不行，会被 PCIe 卡脖子。400G 要 PCIe 5.0 x16，800G 要 PCIe 6.0 |
