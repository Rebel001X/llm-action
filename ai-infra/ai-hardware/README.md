## 0. 一句话锚点

> **AI 加速器的核心矛盾，是"算得快"和"喂得饱"之间的矛盾。**

芯片能做多少次乘加（算力）和能多快地把数据搬进算力单元（访存带宽），这两者必须匹配。
大模型训练/推理几乎总是被**访存或互联**卡脖子，而不是被纯算力卡脖子。
所以看一张卡，不能只看 TFLOPS，要同时看**显存容量、显存带宽、卡间互联带宽**这"四件套"。

```
            ┌──────────── AI 硬件四要素 ────────────┐
            │                                        │
   算力 ───►│  TFLOPS  (FP16/BF16/FP8 Tensor Core)   │ 决定"算多快"
   显存 ───►│  Capacity(HBM 40/80/141/192 GB)        │ 决定"装多大"
   带宽 ───►│  Bandwidth(1.5~8 TB/s)                 │ 决定"喂多快"
   互联 ───►│  NVLink/IB (0.9~1.8 TB/s 双向)          │ 决定"几张卡协同多快"
            └────────────────────────────────────────┘
```

## 1. 地基/前置：四个最原子的概念

在任何卡的规格表里，反复出现四个词。先把它们拆到最底层。

### 1.1 FLOPS：每秒浮点运算次数

- FLOP = **F**loating-point **OP**eration，一次浮点加法或乘法算一次。
- FLOPS = FLOP **per S**econd，每秒能做多少次。
- 大模型最核心的运算是**矩阵乘法**（GEMM），一次"乘加"（FMA, $a\times b + c$）通常记为 **2 FLOP**。
- 单位换算：$1\ \text{TFLOPS} = 10^{12}\ \text{FLOP/s}$，$1\ \text{PFLOPS} = 10^{15}\ \text{FLOP/s}$。

> 为什么矩阵乘是主角？Transformer 的注意力、前馈层、嵌入全是大矩阵相乘。一个 $m\times k$ 乘 $k\times n$ 的矩阵乘法要做约 $2mnk$ 次浮点运算。

### 1.2 显存（VRAM / HBM）：模型住的地方

- GPU 自带的高速内存，权重、激活值、梯度、优化器状态、KV Cache 都放这里。
- 现代 AI 卡用 **HBM**（High Bandwidth Memory，高带宽显存），3D 堆叠贴在 GPU 旁边。
- 两个独立维度：**容量**（能装多大模型，GB）和**带宽**（能多快读写，TB/s）。

### 1.3 带宽：数据搬运的高速公路宽度

- **显存带宽**：HBM ↔ 计算核心，单位 TB/s。决定"喂数据"的速度。
- **互联带宽**：卡 ↔ 卡 / 机 ↔ 机，决定多卡并行时通信的速度。
- 一条经验法则：$\text{有效算力} \le \dfrac{\text{显存带宽}}{\text{每个 FLOP 需要的字节数}}$，这就是后面要讲的 Roofline。

### 1.4 互联：让 N 张卡像一张卡

单卡装不下千亿模型，必须多卡。卡之间用 **NVLink / PCIe / InfiniBand / RoCE** 连起来，互联带宽往往是大规模训练的真正瓶颈。

```
  概念关系图：
                ┌─────────────────────────────┐
                │           AI 加速器          │
                │  ┌──────────┐   ┌─────────┐  │
   计算 ◄──────►│  │ 计算核心  │◄─►│  HBM    │  │◄──── 显存带宽(内部高速路)
                │  │(Tensor)  │   │ 显存    │  │
                │  └────┬─────┘   └─────────┘  │
                └───────┼─────────────────────┘
                        │ 互联(NVLink/PCIe)
                ┌───────┴─────────┐
                ▼                 ▼
            另一张卡           另一台机器(IB/RoCE)
```

## 2. GPU / NPU / TPU：三种设计哲学

三类芯片都为"大规模并行的矩阵运算"而生，但出发点不同。

| 维度 | GPU（图形处理器→通用并行） | NPU（神经网络处理器） | TPU（张量处理器） |
|------|------|------|------|
| 代表 | NVIDIA A100/H100、AMD MI300 | 华为昇腾、寒武纪、高通 Hexagon | Google TPU v4/v5/Trillium |
| 出身 | 从图形渲染演化，通用性强 | 专为 NN 推理/训练定制 | 专为 TF/JAX 矩阵运算定制 |
| 计算核心 | SM + CUDA Core + Tensor Core | Cube/达芬奇 等 MAC 阵列 | 脉动阵列 (Systolic Array) |
| 编程 | CUDA 生态最成熟 | CANN / 厂商 SDK | XLA 编译器 |
| 灵活性 | 高（通用） | 中（偏 NN） | 低（偏 TF/JAX，但效率高） |
| 主战场 | 通吃训练+推理，事实标准 | 端侧+数据中心，国产主力 | Google 云内部+对外租用 |

### 2.1 为什么 GPU 适合 AI？

CPU 为"低延迟、复杂控制流"优化，核少但每核强；GPU 反过来——**核多、控制简单、吞吐为王**。

```
   CPU: 少数强核(为延迟优化)        GPU: 海量弱核(为吞吐优化)
   ┌────┐┌────┐                    ┌┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┬┐
   │ 大 ││ 大 │  4~64 核            ├┼┼┼┼┼┼┼┼┼┼┼┼┼┼┼┼┤  数千 CUDA Core
   │ 核 ││ 核 │  大 Cache          ├┼┼┼┼┼┼┼┼┼┼┼┼┼┼┼┼┤  + 专用 Tensor Core
   └────┘└────┘                    └┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┴┘
   适合: if/else, 串行              适合: 同一指令算海量数据(SIMT)
```

### 2.2 Tensor Core / 脉动阵列：矩阵乘的硬件直觉

普通核一次算一个乘加；**Tensor Core / 脉动阵列**一个时钟周期算一整块小矩阵的乘累加（如 $4\times4$ 或更大），这是 AI 算力暴涨的关键。

```
   脉动阵列(Systolic Array)做 C = A×B 的直觉：
   数据像"心跳"一样在网格里逐拍流动，每个 PE 做一次乘加并传给邻居
        B0  B1  B2
         ↓   ↓   ↓
   A0 → [×+]→[×+]→[×+]    每个格子: acc += a*b, 然后把 a 右传、b 下传
         ↓   ↓   ↓        N×N 阵列 → 一拍完成 N×N 规模的部分积
   A1 → [×+]→[×+]→[×+]    数据复用极高 → 省显存带宽 → 能效比高
```

## 3. 数据精度：算力为什么随精度翻倍

同一张卡，标 FP16 是 X TFLOPS，FP8 可能是 2X，INT8 又翻倍。原因：**位数越少，单位时间能塞进计算单元的数越多，且乘法器更省晶体管**。

| 精度 | 位宽 | 指数/尾数 | 动态范围 | 精度 | 典型用途 |
|------|------|-----------|----------|------|----------|
| FP32 | 32 | 8 / 23 | 大 | 高 | 老式训练、对精度敏感的累加 |
| TF32 | 19* | 8 / 10 | =FP32 | 中 | A100+ 默认矩阵乘（范围同 FP32，尾数砍） |
| FP16 | 16 | 5 / 10 | 小 | 中 | 混合精度训练（需 loss scaling） |
| BF16 | 16 | 8 / 7 | =FP32 | 低 | 训练首选（范围大、不易溢出） |
| FP8(E4M3/E5M2) | 8 | 4或5 / 3或2 | 小~中 | 低 | H100+ 训练/推理，需精细缩放 |
| INT8 | 8 | 整数 | — | 量化 | 推理量化主力 |
| INT4/FP4 | 4 | — | — | 极低 | 极致推理压缩（Blackwell 支持 FP4） |

> *TF32 在存储上仍占 32 位寄存器，但乘法只用 19 位有效，故常写作 TF32。

**FP16 vs BF16 的关键区别**（最常被问）：

```
  FP16:  [S][EEEEE][MMMMMMMMMM]   5位指数 → 范围小(~6e4), 易上溢/下溢, 但尾数多→更精确
  BF16:  [S][EEEEEEEE][MMMMMMM]   8位指数 → 范围=FP32, 训练稳定, 尾数少→精度低
         ↑ 训练里"范围比精度更重要"，所以 BF16 成为大模型训练事实标准
```

经验：算力 TFLOPS 数字通常按 **FP32 < TF32 < FP16/BF16 < FP8 < INT4** 大致逐档翻倍。**带稀疏（Sparsity）的标称值要再打对折看，实际稠密计算用不到。**

## 4. 训练卡 vs 推理卡：为什么分两类

训练和推理对硬件的需求侧重点不同，于是产品线分化。

| 需求 | 训练卡 | 推理卡 |
|------|--------|--------|
| 显存容量 | 大（要存梯度+优化器状态，约权重的 4~6 倍） | 中（只需权重+KV Cache） |
| 显存带宽 | 高 | 高（解码阶段 memory-bound） |
| 高精度算力 | 强（FP16/BF16/FP8 大算力） | 中（INT8/FP8 够用） |
| 卡间互联 | 必须强（NVLink/IB，多卡并行） | 可弱（单卡或少卡） |
| 功耗/散热 | 高（350~1000W） | 较低（70~350W） |
| 代表 | A100/H100/H200/B200、昇腾910 | L4/L40S/T4、4090、昇腾310 |

```
  训练一步的显存占用(混合精度, 以参数量 P 计):
  ┌────────────┬──────────────────────────────────────────┐
  │ 权重 FP16  │ 2P bytes                                  │
  │ 梯度 FP16  │ 2P bytes                                  │
  │ Adam 状态  │ FP32 权重 4P + 一阶动量 4P + 二阶动量 4P  │
  │ 激活值     │ 随 batch/seq 变化(可重计算换显存)         │
  └────────────┴──────────────────────────────────────────┘
   → 静态部分约 16P bytes。训练比纯推理(约 2P) 贵 ~8 倍显存。
```

> 所以"7B 模型推理 16GB 卡能跑，但全量训练要 8×80GB 起步"——差距正来自这张表。

## 5. 显存与内存墙：Roofline 的直觉

### 5.1 内存墙问题

算力涨得比带宽快得多。结果：很多算子算力空着，卡在等数据。衡量指标是**算术强度**（Arithmetic Intensity）：

$$
I = \frac{\text{计算量(FLOP)}}{\text{访存量(Byte)}} \quad (\text{单位：FLOP/Byte})
$$

- $I$ 大 → **compute-bound**（被算力限制，如大 batch 的 GEMM）。
- $I$ 小 → **memory-bound**（被带宽限制，如逐 token 解码、向量加、Softmax、LayerNorm）。

### 5.2 Roofline 模型

```
  实际可达性能(FLOPS)
   ▲
   │            ┌─────────────  峰值算力屋顶(compute-bound)
   │           /
   │          /  斜率 = 显存带宽
   │         /
   │        /  ← memory-bound 区
   │       /
   └──────────────────────────► 算术强度 I (FLOP/Byte)
          拐点 I* = 峰值算力 / 显存带宽
```

拐点 $I^* = \dfrac{\text{峰值算力}}{\text{显存带宽}}$。
若你的算子 $I < I^*$，加算力没用，得想办法**提高数据复用**（融合算子、FlashAttention、更大 batch）。

### 5.3 LLM 推理的两个阶段

```
  Prefill(处理 prompt)        Decode(逐 token 生成)
  ─ 大矩阵乘, I 大            ─ 一次一个 token, I 小
  ─ compute-bound            ─ memory-bound(反复读全部权重+KV)
  ─ 算力越强越快             ─ 显存带宽越高越快
  → 这就是为什么推理优化里 KV Cache、量化、带宽是关键词
```

## 6. 互联与拓扑：多卡如何协同

单卡装不下，就要并行（数据并行 / 张量并行 / 流水线并行），并行就要通信。

| 互联 | 位置 | 双向带宽(约) | 用途 |
|------|------|--------------|------|
| PCIe 4.0 ×16 | 卡↔CPU/卡 | ~32 GB/s | 通用，但对训练偏慢 |
| PCIe 5.0 ×16 | 卡↔CPU/卡 | ~64 GB/s | 新平台 |
| NVLink (Hopper 第4代) | 卡↔卡 | 单卡约 900 GB/s | 节点内高速互联 |
| NVLink (Blackwell 第5代) | 卡↔卡 | 单卡约 1.8 TB/s | 节点内，更快 |
| NVSwitch | 节点内全互联 | — | 让 8 卡两两满速 |
| InfiniBand NDR | 机↔机 | ~400 Gb/s/口 | 跨节点 RDMA |
| RoCE | 机↔机 | 以以太网为底 | IB 的以太网替代 |

> 数字均为"约/以官方为准"，不同代际差异大。

```
  典型 8 卡训练节点拓扑(NVSwitch 全互联):

      GPU0 ─┐                          ┌─ GPU4
      GPU1 ─┤                          ├─ GPU5
      GPU2 ─┼──[ NVSwitch 全互联 ]──────┼─ GPU6
      GPU3 ─┘     任意两卡满速 NVLink   └─ GPU7
                       │
                  ┌────┴────┐
                  │  CPU /   │ ── PCIe
                  │  NIC(IB) │ ── 跨节点 RDMA → 其他节点
                  └─────────┘

  跨节点用 IB/RoCE，通过 GPUDirect RDMA 让网卡直接读写显存，
  绕过 CPU 拷贝，降低延迟。(NVIDIA GPUDirect)
```

并行通信原语：**All-Reduce**（数据并行同步梯度）、**All-Gather / Reduce-Scatter**（ZeRO/张量并行）。通信量大时，互联带宽直接决定训练扩展效率（Scaling Efficiency）。

### 7.1 Google TPU

脉动阵列代表作，与 XLA 编译器深度绑定，按 **Pod** 组织（数千芯片用专用光互联组成超大集群）。v4/v5e/v5p/Trillium 等迭代，主打 Google 云内训练与对外租用，能效与规模化是卖点。

特斯拉自研训练芯片，采用 **D1 计算单元 + Tile 拼接**的晶圆级思路（类似 Cerebras 的"用整片晶圆做一颗大芯片"理念），目标是自动驾驶视频数据的大规模训练。属自用定制路线。

## 8. 国产 AI 芯片

在出口管制背景下，国产替代是 AI-Infra 必修课。生态（编译器/算子/框架适配）往往比单卡纸面算力更关键。

| 厂商/芯片 | 类型 | 定位 | 生态/软件栈 |
|-----------|------|------|-------------|
| 华为昇腾 910/910B | NPU(达芬奇) | 训练+推理主力 | CANN + MindSpore/PyTorch 适配 |
| 华为昇腾 310 | NPU | 端侧/推理 | CANN |
| 百度昆仑芯 | XPU | 训练+推理 | 自有 SDK + 飞桨 |
| 寒武纪 思元 | MLU | 训练+推理 | Cambricon NeuWare |
| 壁仞 BR | GPGPU | 训练 | 类 CUDA 生态对标 |
| 燧原 邃思 | GCU | 训练+推理 | 自有栈 |
| 阿里含光 800 | NPU | 推理 | 平头哥(T-Head) |
| 沐曦/天数智芯 | GPGPU | 训练+推理 | 兼容 CUDA 生态 |

```
  国产芯片的"双壁垒"：
   ┌─ 硬件壁垒 ─┐        ┌─ 软件壁垒(更难) ─┐
   │ 制程/HBM   │   <    │ 算子库完整度      │
   │ 互联带宽   │        │ 框架/编译器适配   │
   │ 良率/产能  │        │ 大模型生态迁移成本 │
   └────────────┘        └───────────────────┘
   → 选型时务必验证"你的模型/框架能否开箱跑通"，而非只看 TFLOPS。
```

## 9. 选型方法论

```
  从需求出发的决策树：
  问1: 是训练还是推理?
   ├─ 训练 ──► 问2: 模型多大?
   │           ├─ ≤13B 微调 → 单机 8×A100/H100, 或 LoRA + 24~48GB 卡
   │           └─ ≥70B 全量 → 多机 H100/H200 + IB/NVLink, 看互联
   └─ 推理 ──► 问3: 看显存还是看吞吐?
               ├─ 大模型装得下优先 → H200(141G)/B200/多卡张量并行
               └─ 高并发性价比     → L40S/L4 + 量化(INT8/FP8)
```

选型四步：
1. **算显存**：能否装下（权重+KV/优化器状态），不够就量化或多卡并行。
2. **算带宽**：解码阶段吞吐 ≈ 显存带宽 ÷ 单 token 需读字节数。
3. **算互联**：多卡时通信会不会成瓶颈，看 NVLink/IB。
4. **算总拥有成本**：单卡价 + 功耗 + 机房 + 生态迁移成本（国产尤其要算）。

## 数值例子 / 对照（手算）

**例 1：7B 模型推理显存**
- 权重 FP16：$7\times10^9 \times 2\,\text{B} = 14\,\text{GB}$。
- 加 KV Cache、激活、碎片，实际约需 **16~18 GB** → 一张 24GB 卡轻松，16GB 卡需量化。
- INT8 量化后权重：$7\times10^9 \times 1 = 7\,\text{GB}$ → 显著省一半。

**例 2：7B 全量训练显存（混合精度 + Adam）**
- 按第 4 节 $16P$ 估：$16 \times 7\times10^9 = 112\,\text{GB}$（仅静态部分，未含激活）。
- → 单张 80GB 卡装不下，需要张量/流水线并行或 ZeRO 分片。

**例 3：解码吞吐受带宽限制（Roofline 直觉）**
- 设 7B 模型权重 FP16 共 14 GB，每生成 1 个 token 大致要把权重读一遍。
- H100 带宽约 3.35 TB/s：理论上限 $\dfrac{3350\,\text{GB/s}}{14\,\text{GB}} \approx 239\ \text{tok/s}$（单序列、理想情况）。
- 这解释了为什么解码"显存带宽 > 纸面算力"，以及 batch 化能摊薄权重读取、提升总吞吐。

**例 4：算术强度判断 memory-bound**
- 逐 token 解码：算 $2\times14\times10^9 \approx 2.8\times10^{10}$ FLOP，读 $\approx 1.4\times10^{10}$ B。
- $I \approx 2$ FLOP/Byte。而 H100 拐点 $I^* = \dfrac{990\,\text{TFLOPS}}{3.35\,\text{TB/s}} \approx 295$。
- $I \ll I^*$ → 严重 memory-bound，印证了"解码靠带宽"。

## 常见问题

| 问题 | 答案 |
|------|------|
| 看一张卡先看什么？ | 显存容量→显存带宽→算力→互联，别只盯 TFLOPS。 |
| FP16 和 BF16 训练选哪个？ | 大模型选 BF16（动态范围大、稳定，无需 loss scaling）。 |
| TFLOPS 标得很高怎么辨真假？ | 看是否含 sparsity（稀疏），稠密实际常为标称一半。 |
| 为什么推理卡不需要很强算力？ | 解码阶段是 memory-bound，瓶颈在带宽不在算力。 |
| 训练为什么比推理贵这么多显存？ | 要存梯度+Adam 优化器状态，约权重的 8 倍（$16P$ vs $2P$）。 |
| 4090 能不能商用训练？ | 算力强但无 NVLink、显存 24G、且有数据中心许可限制，须看协议。 |
| 国产芯片选型最大坑？ | 算子/框架生态适配，不是纸面算力——务必先验证能否跑通你的模型。 |
| NVLink 和 PCIe 差多少？ | NVLink 单卡可达 ~900 GB/s 甚至 ~1.8 TB/s，PCIe 仅几十 GB/s，多卡训练差距巨大。 |
| H100 和 H200 主要差别？ | 算力相近，H200 显存更大(141G HBM3e)、带宽更高，更利于大模型推理。 |
