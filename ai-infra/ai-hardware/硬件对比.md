## 0. 一句话锚点

大模型的训练和推理，本质是把海量参数和激活值在"算"和"搬"之间反复倒腾。一块 GPU 的价值由三件事决定：

1. **算得多快**——Tensor Core 的 FLOPS（每秒浮点运算次数）。
2. **喂得多快**——HBM 显存带宽（每秒能从显存搬多少字节进计算单元）。
3. **多卡协作多快**——NVLink/NVSwitch 卡间互联带宽（千亿参数模型一张卡装不下，必须切开分布到多卡，卡间通信就成了瓶颈）。

```
        ┌────────── 一块 GPU 的三个"水管" ──────────┐
        │                                            │
  算力 FLOPS ───→ [ Tensor Core 计算 ]               │
        │              ↑↓  (读写激活/权重)            │
  HBM 带宽 ───→ [ HBM 显存 ]                          │
        │              ↑↓  (跨卡 All-Reduce / 切分)   │
  NVLink ───→ [ 其它 GPU ]                            │
        └────────────────────────────────────────────┘
   任何一根水管细了，整体吞吐就被它卡住（木桶效应）
```

**记住这句话**：训练通常卡在"算力 + 互联"，推理（尤其是大 batch 解码）常常卡在"显存容量 + 带宽"。看懂一张卡先看它在这三件事上各是什么水平。

## 1. 地基/前置：把规格表里的词拆到最原子

不假设你记得这些定义，逐个拆开。

### 1.1 FLOPS 与精度

- **FLOP** = 一次浮点运算（一次乘或一次加）。**FLOPS** = 每秒多少次。GPU 规格里通常写 **TFLOPS**（万亿次/秒）或 **PFLOPS**（千万亿次/秒）。
- 同一块卡，**精度越低，算力数字越大**。因为低精度的数占的位数少，同样的硅片面积能塞更多乘加单元，且数据搬运量减半。常见精度：
  - **FP64**（双精度，64 位）：科学计算用，AI 几乎不用。
  - **FP32 / TF32**：传统训练精度 / NVIDIA 的"省力 32 位"。
  - **FP16 / BF16**（16 位）：现代大模型训练主力。
  - **FP8**（8 位）：Hopper 起支持，训练/推理新主力。
  - **INT8 / FP4**：推理量化、Blackwell 新增。
- 经验关系：在 Tensor Core 上，**8-bit 算力 ≈ 16-bit 的 2 倍**，FP4 又约为 FP8 的 2 倍。这就是为什么厂商爱拿低精度数字做宣传——同一块卡 FP4 的 PFLOPS 看着很唬人，但能不能用得看模型能否量化到那个精度。

> 补充背景：大多数大模型 16-bit 权重可以量化到 8-bit 而精度损失很小；压到 4-bit 一般损失明显（需要 AWQ/GPTQ 等技巧才勉强可用）。所以"FP4 算力"是营销上限，实战往往跑在 FP8/BF16。

### 1.2 稠密 vs 稀疏（Dense / Sparse）

规格表里常有两个算力数字，大的那个标着"with sparsity（2:4 结构化稀疏）"。它假设每 4 个权重里有 2 个是 0，硬件跳过零值，算力翻倍。**真实模型很少满足 2:4 稀疏**，所以对比时一律看**稠密（Dense）**数字才公平。

### 1.3 HBM 显存与带宽

- **HBM**（High Bandwidth Memory，高带宽显存）：堆叠在 GPU 旁边的 3D 内存，靠超宽总线（数千 bit）实现极高带宽。代际：HBM2e → HBM3 → HBM3e。
- **显存容量**（GB）：决定一张卡能装多大的模型/多长的上下文/多大的 KV Cache。
- **显存带宽**（TB/s）：决定每秒能把多少数据喂进计算单元。**推理的解码阶段几乎纯粹由带宽决定速度**（每生成一个 token 要把整个模型权重读一遍）。

### 1.4 NVLink / NVSwitch / PCIe

- **PCIe**：GPU 插主板的通用总线，PCIe 5.0 双向约 128 GB/s。慢，是多卡通信的"小路"。
- **NVLink**：NVIDIA 私有的 GPU 直连高速通道，比 PCIe 快一个数量级（H100 的 NVLink4 约 900 GB/s 双向聚合）。
- **NVSwitch**：把多块 GPU 的 NVLink 全连成一张交换网，让 8 卡（甚至 NVL72 的 72 卡）彼此满速通信。
- 为什么互联这么关键：千亿/万亿参数模型必须用**张量并行 / 流水线并行 / 专家并行**切到多卡，每一层前向/反向都要做 All-Reduce 等集合通信。互联慢，多卡就"算得快但等得久"。

### 1.5 TDP（功耗）与封装

- **TDP**（Thermal Design Power，热设计功耗，单位 W）：满载发热/耗电的上限，决定供电、散热、机房密度、电费。
- **封装形态**：**SXM**（专用插槽模组，带满速 NVLink，功耗高性能强）vs **PCIe**（插卡，功耗低、NVLink 弱或无）。同型号 SXM 一般比 PCIe 强。

```
封装形态对吞吐的影响
  SXM 模组  ──NVLink全互联──  适合 8 卡训练，性能拉满
  PCIe 插卡 ──PCIe/桥接──     适合推理/单卡，互联弱
```

## 2.~N. 逐步拆解

### 2. 怎么读一张规格表（看数的方法）

拿到任意一张卡，按这个顺序看五个数，每个数问"为什么"：

```
  ① 算力(稠密 FP16/FP8 TFLOPS) → 训练快不快
  ② 显存容量(GB)              → 装得下多大模型
  ③ 显存带宽(TB/s)            → 推理解码快不快
  ④ NVLink 带宽(GB/s)         → 多卡协作快不快
  ⑤ TDP(W)                    → 多少电、多少热、机房密度
```

口诀：**算力看训练、带宽看推理、互联看规模、显存看上限、功耗看成本。**

### 3. A100（Ampere，2020）——理解后续的基准

上一代数据中心王者，现在仍大量在役。关键创新：第三代 Tensor Core、引入 **TF32**（让 FP32 训练几乎免费提速）、**MIG**（把一张卡切成最多 7 个独立小 GPU，给推理多租户用）。

典型公开规格（约，以官方为准）：

| 指标 | A100 80GB SXM |
|------|---------------|
| FP16 Tensor（稠密） | 约 312 TFLOPS |
| 显存 | 80 GB HBM2e |
| 显存带宽 | 约 2.0 TB/s |
| NVLink | 第 3 代，约 600 GB/s |
| TDP | 约 400 W |
| FP8 | 不支持 |

A100 没有 FP8、没有 Transformer Engine，这是它与 Hopper 代最大的分水岭。

### 4. H100（Hopper，2022）——跨代飞跃

H100 是当前训练的事实标准。三大关键创新：

1. **第四代 Tensor Core + FP8**：新增 FP8 精度，算力相对 A100 的 FP16 翻了几倍。
2. **Transformer Engine**：硬件+软件协同，在 FP8 与 FP16 之间逐层自动选精度，让大模型用 FP8 训练而不掉精度——这是为大模型量身定做的。
3. **NVLink4 + HBM3**：互联和带宽双双大涨。

典型公开规格（约，以官方为准）：

| 指标 | H100 SXM |
|------|----------|
| FP16 Tensor（稠密） | 约 990+ TFLOPS（约 1 PFLOPS） |
| FP8 Tensor（稠密） | 约 1979 TFLOPS（约 2 PFLOPS） |
| 显存 | 80 GB HBM3（H100 NVL/H200 更大） |
| 显存带宽 | 约 3.35 TB/s |
| NVLink | 第 4 代，约 900 GB/s |
| TDP | 约 700 W |

> 衍生型号：**H200** = H100 算力 + 升级到 141 GB HBM3e、约 4.8 TB/s 带宽，专为大模型推理的"显存/带宽"瓶颈而生（算力没变，喂数能力大涨）。

```
A100 → H100 的跨代提升示意（FP16 稠密，归一化）
 A100 |████████              | ~312 TFLOPS
 H100 |████████████████████  | ~990 TFLOPS  + 新增 FP8 翻倍
        互联 600 → 900 GB/s   带宽 2.0 → 3.35 TB/s
```

### 5. H800——为什么"砍互联不砍算力"

H800 是 H100 的**对华特供版**（应对美国 2022 年出口管制）。核心特征：**单卡算力和显存基本与 H100 相同，但 NVLink 卡间互联带宽被砍**（约从 900 GB/s 降到约 400 GB/s 量级，以官方为准）。

**为什么砍互联而不砍单卡算力？** 这是理解出口管制的关键：

```
   单卡很强，但卡间"路"被收窄
   ┌────┐  细管(NVLink减半) ┌────┐
   │H800│════════════════════│H800│
   └────┘                    └────┘
   单卡算力 ≈ H100        但 8 卡协作时通信变慢
```

- 当时的管制以"算力 + 互联带宽"作为综合指标设线。厂商的设计目标是：**让单卡可用、但削弱大规模集群扩展能力**。
- 大模型训练的瓶颈高度依赖**多卡集合通信**。互联减半后，单卡跑小任务几乎无感，但把成百上千张卡组成超大集群训练超大模型时，通信开销显著上升，**整集群的有效训练吞吐被压低**。
- 这正是管制的意图：不是让单卡不能用，而是**抬高"组超大集群训练前沿大模型"的成本和难度**。
- 工程影响：用 H800 集群训练时，更需要靠通信优化（如计算/通信重叠、降低 All-Reduce 频率、FP8 通信压缩）来对冲互联损失——DeepSeek 等团队的工程报告里大量篇幅就在做这件事。

### 6. H20（2024）——第二轮管制下的"推理特化卡"

2023 年管制收紧（改用"总算力 + 算力密度"等指标），H800 也被禁。NVIDIA 推出 **H20** 作为新的合规特供卡，特征非常反直觉：**算力被大幅砍低，但显存容量和带宽反而很大**。

典型公开规格（约，以官方为准）：

| 指标 | H20 | 对比 H100 |
|------|-----|-----------|
| FP16/FP8 算力 | 大幅低于 H100（约为其几分之一） | ↓↓ 砍很多 |
| 显存 | 约 96 GB HBM3 | ↑ 比 H100 80GB 还大 |
| 显存带宽 | 约 4.0 TB/s | ↑ 接近/超过 H100 |
| NVLink | 约 900 GB/s（互联未砍） | ≈ 保留 |

**为什么是这种"低算力高带宽"组合？** 管制盯的是算力指标，于是把算力压到线下；而显存容量/带宽不受同等限制，就保留甚至加强。结果是：

- **训练**：算力低，做大模型预训练性价比差。
- **推理**：解码阶段瓶颈在显存带宽和容量（见第★节手算），H20 的大显存 + 高带宽反而让它**单卡推理体验意外地好**，尤其适合部署中大模型和长上下文 KV Cache。所以业界把它当"推理卡"用。

```
 同价位三张卡的"性格"对比（示意）
            算力   显存   带宽   互联
  H100      ★★★★  ★★★   ★★★    ★★★★   训练全能
  H800      ★★★★  ★★★   ★★★    ★★     单卡强、集群弱
  H20       ★      ★★★★  ★★★★   ★★★★   推理特化
```

### 7. B200 / GB200（Blackwell，2024–2025）——最新一代

Blackwell 是 Hopper 的继任者，关键创新：

1. **双 die 设计**：一颗 B200 由两块计算 die 用超高带宽（约 10 TB/s）拼成，对软件呈现为单一 GPU——突破单颗光罩面积上限。
2. **第二代 Transformer Engine + FP4**：新增 **FP4** 微缩放精度，把推理算力数字再翻一档。
3. **HBM3e 大显存**：单卡约 192 GB。
4. **NVLink5**：单卡约 1.8 TB/s（约为 H100 的 2 倍）。
5. **GB200 = Grace CPU + 2×B200**；**NVL72** 用 NVSwitch 把 72 块 GPU 连成一个"巨型单 GPU"域，专为万亿参数 MoE 训练/推理。

典型公开规格（约，以官方为准）：

| 指标 | B200 |
|------|------|
| FP4（稠密，营销峰值） | 约 9–10 PFLOPS 量级 |
| FP8（稠密） | 约 4.5 PFLOPS 量级 |
| 显存 | 约 192 GB HBM3e |
| 显存带宽 | 约 8 TB/s |
| NVLink | 第 5 代，约 1.8 TB/s |
| TDP | 约 1000 W 量级 |

> 注意：B200 同样有对华合规衍生型号（如 B30/B40 系列等说法），规格以官方为准，思路与 H800→H20 一脉相承——围绕当期管制指标做裁剪。

### 8. 国产对照与 ASIC/FPGA 的位置

在管制背景下，国产替代是 AI-Infra 选型绕不开的话题（规格演进快，具体数字以官方为准）：

- **华为昇腾 910B/910C**：对标 A100/H100 区间，配套 CANN 软件栈与 MindSpore；集群层面有 CloudMatrix 等方案以"堆规模"对冲单卡差距。
- 其它如壁仞、寒武纪、海光等亦在追赶，主要差距常在**软件生态成熟度**与**互联/集群扩展**而非单卡纸面算力。

关于 ASIC/FPGA 的定位（沿用本目录已有结论）：

- **FPGA** 相比同等面积/工艺的 ASIC，算力差着数量级；FPGA 更适合**智能网卡、存储编码、压缩、加密**等特定算法加速，不适合通用大模型计算。
- **ASIC**（如 TPU、各家自研推理芯片）在固定负载上能效最佳，AI 大模型加速 **ASIC 更在行**；NVIDIA 的 Tensor Core 本质就是 GPU 里的矩阵乘 ASIC 单元，高效执行 16-bit/8-bit，8-bit 算力约为 16-bit 两倍。

```
  通用性 ←──────────────────────────→ 能效/单负载
  CPU  >  GPU  >  FPGA  >  ASIC(TPU/Tensor Core)
                ↑用于网卡/编解码    ↑大模型首选(固定负载)
```

### 9. 选型决策树（实践要点）

```
你的主要负载是什么？
│
├─ 前沿大模型预训练（千卡集群）
│     → 首选 H100/B200 SXM（算力+互联+生态全要）
│     → 受管制只能买特供：H800（补通信优化）/ 国产集群堆量
│
├─ 微调 / 中等规模训练（几卡~几十卡）
│     → H100 / A100 80GB 性价比好；显存吃紧上 H200
│
├─ 大模型推理 / 长上下文部署
│     → 看显存容量 + 带宽：H200 / H20 / B200 都很合适
│     → H20 在合规前提下是"高带宽推理卡"的实惠选择
│
└─ 多租户 / 小模型并发推理
      → A100/H100 开 MIG 切分，或用 PCIe 卡降本
```

实践提醒：

- **别被低精度峰值忽悠**：宣传爱用 FP4/带稀疏的数字，落地先确认你的模型能否跑那个精度、是否真有 2:4 稀疏，否则按稠密 FP16/FP8 看。
- **SXM vs PCIe 要分清**：同名 PCIe 版往往算力、互联、功耗都更低。
- **互联是集群隐形瓶颈**：买卡也要看能否组 NVSwitch 全互联，否则多卡线性度差。
- **总拥有成本**：TDP × 电价 × 时长 + 散热改造，往往比卡价更影响长期成本。

## ★ 数值例子：三道手算，把直觉钉死

### 例 1：显存够不够装一个 70B 模型？

参数量 $N = 70 \times 10^9$，权重精度决定每参数字节数：

$$
\text{显存(权重)} = N \times \text{字节/参数}
$$

- FP16（2 字节）：$70\text{B} \times 2 = 140\text{ GB}$ → 一张 80GB 卡**装不下**，需 2 张或量化。
- INT8（1 字节）：$70\text{B} \times 1 = 70\text{ GB}$ → 勉强塞进一张 80GB（再留点给 KV Cache/激活就紧张）。
- INT4（0.5 字节）：$70\text{B} \times 0.5 = 35\text{ GB}$ → 单张卡轻松，这就是 4-bit 量化推理的意义。

> 结论：H20/H200 的大显存（96/141 GB）让"单卡跑 70B FP16/INT8"成为可能，而 80GB 卡必须量化或多卡。

### 例 2：推理解码速度，是带宽说了算

自回归解码时，每生成 **1 个 token**，需把**整个模型权重读一遍**（这是 memory-bound 的核心）。理论上限 token/s：

$$
\text{tokens/s} \le \frac{\text{显存带宽}}{\text{模型字节数}}
$$

以 70B 模型、FP16（140 GB）为例：

- A100（2.0 TB/s）：$\dfrac{2000}{140} \approx 14$ tokens/s（单卡上限）。
- H100（3.35 TB/s）：$\dfrac{3350}{140} \approx 24$ tokens/s。
- H20（4.0 TB/s）：$\dfrac{4000}{140} \approx 28$ tokens/s。

> 看见没？解码阶段 **H20 反超 H100**——尽管 H20 算力被砍得很惨。这就是它被当"推理卡"的硬道理：**解码是带宽活，不是算力活**。（真实值还要打折，受 batch、KV Cache、实现效率影响。）

### 例 3：多卡训练，互联减半损失多少？

设某层反向需做一次 All-Reduce，通信量 $D$ 字节。通信时间约：

$$
t_{\text{comm}} \approx \frac{2(n-1)}{n} \cdot \frac{D}{B_{\text{NVLink}}}
$$

其中 $B_{\text{NVLink}}$ 是互联带宽。H800 把 $B$ 从约 900 砍到约 400 GB/s：

$$
\frac{t_{\text{H800}}}{t_{\text{H100}}} \approx \frac{900}{400} \approx 2.25
$$

即**通信耗时翻 2 倍多**。若某训练步里通信占比原本 30%，互联减半后通信膨胀到约 $30\% \times 2.25 \approx 67\%$ 的等效开销，整步吞吐明显下降——这正是"砍互联"卡集群训练的数学原因，也解释了为何 H800 用户要拼命做计算/通信重叠。

## 常见问题

| 问题 | 答案 |
|------|------|
| H800 比 H100 弱在哪？ | 单卡算力/显存几乎一样，**NVLink 互联被砍约一半**，集群训练吞吐受损。 |
| H20 算力那么低还买它干嘛？ | 显存大、带宽高，**推理（尤其解码/长上下文）瓶颈在带宽不在算力**，性价比好。 |
| 为什么管制砍互联/算力而不砍显存？ | 管制指标盯算力与集群扩展能力；显存容量/带宽多用于推理，限制相对宽松。 |
| FP4 的 9 PFLOPS 能信吗？ | 那是低精度+稀疏的营销峰值；实战看**稠密 FP16/FP8**，且模型要能量化到该精度。 |
| 训练该看哪个数？ | 稠密 FP16/FP8 算力 + NVLink 互联 + 生态（CUDA）。 |
| 推理该看哪个数？ | 显存容量 + 显存带宽（解码 memory-bound），其次算力。 |
| SXM 和 PCIe 同名为何不同？ | SXM 互联满速、功耗高、性能强；PCIe 互联弱、功耗低，多用于推理/单卡。 |
| A100 和 H100 最大代差？ | H100 新增 **FP8 + Transformer Engine**，算力、带宽、互联全面跨代。 |
| 国产卡能替代吗？ | 单卡纸面在追赶，主要差距在**软件生态成熟度**与**大规模互联/集群扩展**。 |
| MIG 是什么？ | 把一张物理 GPU 切成多个隔离小 GPU，适合多租户小模型并发推理。 |
