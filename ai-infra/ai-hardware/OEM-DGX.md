## 0. 一句话锚点

> **HGX 是"主板"，DGX 是"NVIDIA 牌的整机"，OEM 服务器是"别家牌子但用同一块主板的整机"。**

把一台 8 卡 GPU 服务器拆开，最核心的不是 8 张 GPU 卡，而是它们插在上面的那块 **HGX 基板（baseboard）**：8 颗 GPU 焊在板上，板上还焊着 **NVSwitch** 芯片，把 8 颗 GPU 用 **NVLink** 全互联。这块板子是 NVIDIA 卖给所有人的"标准件"。

- **NVIDIA 自己**把这块板子装进机箱、配好 CPU/网卡/电源/散热、刷好软件栈，整机叫 **DGX**。
- **其他服务器厂商（OEM）** 买同一块 HGX 板，配自家的机箱/CPU/网卡，整机叫各自的型号（如 H3C R5500、浪潮 NF5688、戴尔 XE9680、超微 SYS-821GE 等）。

所以三者关系是"**同一颗心脏，不同的身体**"。

```
        ┌──────────────────────────────────────────────┐
        │                NVIDIA GPU 芯片                 │  ← 算力来源(A100/H100/H200/B200)
        └───────────────────────┬──────────────────────┘
                                 │ 焊在
        ┌───────────────────────▼──────────────────────┐
        │   HGX 基板 = 8×GPU + 4~6×NVSwitch + NVLink     │  ← NVIDIA 标准件,卖给所有人
        └──────────┬───────────────────────┬───────────┘
                   │ 装进NVIDIA机箱          │ 装进OEM机箱
        ┌──────────▼─────────┐   ┌──────────▼──────────────┐
        │   DGX (NVIDIA牌)    │   │ OEM 服务器(H3C/浪潮/戴尔) │
        │  整机+软件栈+支持    │   │  整机,自配CPU/网卡/散热    │
        └────────────────────┘   └─────────────────────────┘
```

## 1. 地基：为什么要"整机"，而不是自己攒卡？

训练大模型时，8 张 GPU 必须以接近"一张大卡"的方式协同：做 AllReduce/AllGather 时数据要在卡间高速流动（见 [[ai-infra/网络/集合通信原语]]）。要让 8 卡高速互联，靠普通 PCIe 是不够的——PCIe Gen5 x16 单向也就约 64 GB/s，而 NVLink 一代代把卡间双向带宽推到了 **数百 GB/s 到 1.8 TB/s** 量级。

要用满 NVLink，就需要 **NVSwitch**（一颗交叉开关芯片）把每张卡都连到每张卡。这套东西布线极其密集、信号完整性要求高，**没法在普通主板上 DIY**。于是 NVIDIA 把"8 GPU + NVSwitch + NVLink 布线"做成一块出厂即焊死的 **HGX 基板**，整机厂只需把它装进服务器。

整机（DGX 或 OEM）相比"自己攒卡"解决了三件事：

| 问题 | 自己攒散卡 | 用 HGX 整机 |
|------|-----------|-------------|
| 卡间互联 | 只能走 PCIe，慢且无全互联 | 板载 NVSwitch + NVLink 全互联 |
| 供电散热 | 8×700W 风冷/液冷难搞定 | 整机厂已做电源/风道/液冷设计 |
| 软件与兼容性 | 自己踩驱动/固件/拓扑坑 | 出厂校验过，配套软件栈 |
| 售后与稳定性 | 自担风险 | 厂商整机质保 |

> 直觉：HGX 整机就像"主板厂把 CPU、内存、互联都焊好的一体板"，你不需要也不能在芯片级别上 DIY，只能选整机。

## 2. HGX 基板：一台节点的"心脏"

HGX 是一代代演进的（HGX A100 8-GPU、HGX H100/H800 8-GPU、HGX H200、HGX B200 等，对应不同 GPU 代次）。核心结构在每一代都类似：

```
          ┌──────────────── HGX 8-GPU 基板 ────────────────┐
          │                                                 │
          │   GPU0   GPU1   GPU2   GPU3                      │
          │    │      │      │      │                        │
          │    └──────┴──┬───┴──────┘   每张GPU都拉NVLink    │
          │              │              到下面的NVSwitch     │
          │        ┌─────▼─────┐                             │
          │        │ NVSwitch  │ ×(4~6颗)  做"全互联交叉开关"  │
          │        └─────▲─────┘                             │
          │    ┌──────┬──┴───┬──────┐                        │
          │    │      │      │      │                        │
          │   GPU4   GPU5   GPU6   GPU7                      │
          │                                                 │
          └─────────────────────────────────────────────────┘
            结果: 任意两张GPU间都有满NVLink带宽,无"远近之分"
```

关键点：

- **NVSwitch 让 8 张卡"全互联"**：不是 GPU0 只能直连邻居，而是任意两卡之间都走 NVSwitch，带宽对称。这对 AllReduce 这类"人人对人人"的通信至关重要。
- **NVLink 代次决定带宽**：每代 NVLink 提升单链路速率和链路数，整卡双向带宽随之提升（A100 约 600 GB/s 级、H100 约 900 GB/s 级、Blackwell 进一步翻倍——**具体数值以官方规格为准**）。
- **HGX 是"半成品"**：它只管 GPU 子系统，不含 CPU、系统内存、启动盘、网卡。这些由 DGX 或 OEM 厂商在外面配。

文件开头提到的 H3C 例子正是这个逻辑：

> "8 块 A800 GPU 通过 6 个 NVSWITCH 实现全互联"——这就是一块 **HGX A800 8-GPU** 基板；H3C 只是把它装进 R5500LC 机箱并做了液冷。

> 注：**A800/H800** 是为满足出口管制而对 A100/H100 做了互联带宽等限制的版本，GPU 算力相近但 NVLink 互联带宽被削减，因此在大规模多卡训练时通信会更吃紧。

## 3. DGX：NVIDIA 在 HGX 之上又加了什么

DGX = HGX 基板 + NVIDIA 精心配好的"身体"+ 软件栈 + 整机支持。相比一块裸 HGX 板，DGX 通常额外定义/集成了：

| 部分 | DGX 提供的东西 | 作用 |
|------|----------------|------|
| CPU 子系统 | 双路服务器 CPU + 大容量系统内存 | 喂数据、跑数据加载/预处理 |
| 后端网卡 | 多张高速网卡(InfiniBand/以太) | 跨节点 GPU 通信(GPUDirect RDMA) |
| 网络拓扑 | "每 GPU 配一张后端网卡"的规划 | 让多机训练的跨节点带宽匹配卡间带宽 |
| 存储/管理网 | 独立的存储网与带外管理(BMC) | 数据读写与远程运维分离 |
| 软件栈 | DGX OS、驱动、容器、NGC 镜像 | 开箱即用，少踩驱动/固件坑 |
| 散热/电源 | 风冷或液冷整机设计 | 稳定喂满 8×数百瓦的功耗 |

DGX 也有"代次"：从早期 DGX-1/DGX-2，到 DGX A100、DGX H100/H200、DGX B200，以及把多机柜整合成机架级一体的 **DGX GB200 NVL72**（用 NVLink 把更多 GPU 跨机箱连成一个大域）。**具体型号的卡数、显存、网卡数量、功耗以 NVIDIA 官方规格为准，切勿记死。**

> 一句话：DGX 卖的不只是硬件，更是"一套被 NVIDIA 验证过的最佳实践 + 软件栈 + 售后"，代价是溢价更高、灵活性更低。

## 4. 一台 8 卡节点内部到底怎么连？（最关键的一张图）

无论是 DGX 还是 OEM HGX 服务器，一台 8 卡节点内部大致是这样的两层互联：

```
   ┌───────────────────── 一台 8-GPU 服务器节点 ─────────────────────┐
   │                                                                  │
   │   ┌── CPU0 ──┐                          ┌── CPU1 ──┐             │
   │   │  内存DDR │                          │  内存DDR │             │
   │   └────┬─────┘   (CPU间: UPI/xGMI)       └────┬─────┘             │
   │        │ PCIe                                  │ PCIe            │
   │   ┌────▼──────────────────────────────────────▼────┐            │
   │   │     PCIe Switch 层 (GPU↔CPU↔网卡↔NVMe)           │            │
   │   └─┬────┬────┬────┬──────────┬────┬────┬────┬──────┘            │
   │     │GPU0│GPU1│...                       ...│GPU7│               │
   │     └─┬──┴─┬──┴───┘  ↑ 控制面/数据加载走PCIe                       │
   │       │    │                                                     │
   │   ┌───▼────▼─────────────────────────────────┐                  │
   │   │  NVLink + NVSwitch 全互联 (GPU↔GPU 高速面) │ ← 训练通信主战场  │
   │   └────────────────────────────────────────────┘                │
   │                                                                  │
   │   后端网络: 每GPU≈1张 IB/RoCE 网卡 ──► 交换机 ──► 其他节点         │
   │            (GPUDirect RDMA: 网卡直读GPU显存,绕过CPU)               │
   └──────────────────────────────────────────────────────────────────┘
```

读图要点（这是面试与排障的核心）：

1. **两个互联平面要分清**：
   - **PCIe 平面**：连 CPU、网卡、NVMe，用于喂数据、控制、跨节点网卡走向。带宽相对低。
   - **NVLink/NVSwitch 平面**：只连 GPU↔GPU，是训练时 AllReduce/AllGather 的"高速公路"，带宽高一个量级。
2. **跨节点要靠后端网卡**：节点内 8 卡靠 NVLink，节点之间靠 InfiniBand/RoCE。理想配置是"**每张 GPU 配一张后端网卡**"，让跨节点带宽尽量匹配卡间带宽（见 [[ai-infra/网络/InfiniBand]]）。
3. **GPUDirect RDMA**：网卡可直接读写 GPU 显存，绕过 CPU 和系统内存拷贝，降低跨节点通信延迟（见 [[ai-infra/ai-hardware/gpudirect]]）。
4. **NCCL 会探测这张拓扑**：跑训练时 NCCL 自动发现 NVLink/NVSwitch/PCIe/网卡拓扑并选最优通信路径（见 [[ai-infra/网络/NCCL]]）。拓扑配错（比如 GPU 与网卡跨了 NUMA、PCIe Switch 走向不对）会直接掉带宽。

> 数值直觉（量级，非精确值）：节点内 NVLink 双向带宽常在 **数百 GB/s ~ 1.8 TB/s** 量级；单张后端 IB 网卡常在 **几十 ~ 数百 GB/s** 量级。所以"节点内 > 节点间"是固定规律，分布式并行策略（数据/张量/流水线并行的切分）就是围着这条规律设计的。

## 5. OEM HGX 服务器：H3C / 浪潮 / 戴尔 / 超微等

OEM 厂商买同一块 HGX 基板，自己配机箱、CPU、网卡、电源、散热，做出"等价整机"。常见玩家与代表型号（型号会随代次更新，**以厂商官网为准**）：

| 厂商 | 代表型号(示例) | 特点 |
|------|----------------|------|
| H3C | UniServer R5500 系列(如 R5500LC G5/R5500 G6) | 国内主力之一，LC=液冷型支持 A800/H800 HGX 模组 |
| 浪潮 Inspur | NF5688 系列 | 国内出货量大的 8 卡 HGX 整机 |
| 戴尔 Dell | PowerEdge XE9680 等 | 海外主流 8 卡 HGX 平台 |
| 超微 Supermicro | SYS-8U GPU 系列 | 配置灵活，液冷/风冷选择多 |
| 联想/HPE 等 | 各自 HGX 平台 | 企业市场 |

OEM 整机与 DGX 的 **GPU 子系统完全相同**（同一块 HGX 板），差异主要在"身体"和"服务"：

```
   相同(因为都是同一块HGX板):
     8×GPU、NVSwitch全互联、NVLink带宽、GPU显存 → 训练算力基本一致

   不同(各家自定义):
     CPU型号 / 系统内存 / 后端网卡数量与型号 /
     PCIe拓扑(网卡与GPU的NUMA对齐) / 散热(风冷vs液冷) /
     电源冗余 / BMC管理 / 软件栈与售后 / 价格
```

实践含义：选 OEM 机器时，**别只看"8 张 H100"这一行**，要追问：
- 后端网卡几张、什么速率、是否每卡一网卡、和 GPU 是否同 NUMA 域；
- PCIe Switch 拓扑（影响 GPUDirect 与 NCCL 实测带宽）；
- 散热是风冷还是液冷（决定能否长期满频不降频）；
- 是否预装并验证过驱动/固件/NCCL（决定上手踩坑量）。

> 性价比上，OEM HGX 整机通常比同代 DGX 便宜、配置更灵活；代价是软件栈与"最佳实践"要自己把关。

## 6. 把整机堆成集群：DGX SuperPOD 思路

单台 8 卡顶天 8 张 GPU，训练大模型要几十上百台节点。NVIDIA 给出的参考集群方案叫 **DGX SuperPOD**，OEM 也有各自对标的集群方案。其核心思想（见 [[ai-infra/ai-cluster/README]]）：

```
   节点内:  8×GPU ── NVSwitch全互联(NVLink域)
                         │
   计算网(后端): 每节点多张IB/RoCE网卡 ── Spine-Leaf无阻塞交换网 ── 其他节点
                         │
   存储网:      高性能并行文件系统(喂数据,避免GPU饿肚子)
                         │
   管理网:      带外管理/调度(Slurm/K8s),监控,故障隔离
```

要点：

- **三张网分开**：计算网（GPU 通信）、存储网（数据读写）、管理网（运维调度）物理或逻辑隔离，互不抢带宽。
- **无阻塞(non-blocking)拓扑**：计算网常用 Spine-Leaf（胖树），保证任意两节点都有满带宽（见 [[ai-infra/网络/Spine-Leaf和InfiniBand网络架构区别简述]]）。
- **可扩展单元(SU)**：SuperPOD 以"若干节点 + 一组交换机"为可复制的扩展单元，按 SU 倍增规模，布线和拓扑标准化。
- **GB200 NVL72 等机架级方案**：把 NVLink 域从"节点内 8 卡"扩展到"整机架几十卡",让更多 GPU 享受 NVLink 级互联,进一步缓解跨节点瓶颈。

## 7. 选型方法论：DGX / OEM-HGX / 自建

| 维度 | DGX(NVIDIA牌) | OEM HGX 整机 | 自己攒散卡 |
|------|---------------|--------------|-----------|
| GPU 互联 | 满 NVLink+NVSwitch | 满 NVLink+NVSwitch(同一块板) | 通常只有 PCIe，差一档 |
| 上手难度 | 最低(软件栈齐) | 中(自己把关软件) | 高(自己踩坑) |
| 灵活性 | 低(固定配置) | 高(CPU/网卡/散热可选) | 最高但风险大 |
| 价格 | 最高(品牌溢价) | 中 | 单卡便宜但隐性成本高 |
| 售后/稳定性 | 最好 | 看厂商 | 自担 |
| 适合谁 | 要省心、要 NVIDIA 背书的大客户 | 多数预算敏感的训练/推理团队 | 小规模/推理/预算极紧 |

经验法则：

- **做大规模训练**（多机数据/张量并行）：必须要 NVLink 全互联的整机（DGX 或 OEM HGX），别用纯 PCIe 散卡。
- **预算敏感但要 8 卡全互联**：选 OEM HGX 整机，重点验拓扑/网卡/散热。
- **只做推理或小规模微调**：未必需要 HGX 全互联，PCIe 平台 + 单/双卡甚至更划算（推理通信压力远小于训练）。

## 典型规格清单：看 spec 时盯哪几个数

拿到一台 DGX/OEM 整机的规格表，按这个顺序看（**这些是"类别"，具体数值以官方 spec 为准**）：

1. **GPU 型号与代次**：A100/H100/H200/B200 还是 A800/H800（互联受限版）。决定算力与显存。
2. **GPU 数量与显存**：是不是标准 8 卡、单卡显存多大（决定能装多大模型）。
3. **卡间互联**：是 NVLink+NVSwitch 全互联，还是仅 PCIe？带宽量级多少？（决定多卡训练效率）
4. **后端网卡**：几张、速率、是否每卡一网卡、是否支持 GPUDirect RDMA。（决定多机扩展性）
5. **PCIe 拓扑/NUMA**：GPU 与网卡是否同 NUMA、PCIe Switch 走向。（决定实测带宽，spec 上常不写，要问/实测）
6. **散热**：风冷 vs 液冷。（决定能否长期满频）
7. **CPU/内存/存储**：喂数据能力，避免 GPU 饿肚子。
8. **功耗/供电**：整机功耗常达数千瓦至万瓦级，机房供电/制冷要匹配。

## 常见问题 / 坑

| 现象 / 误区 | 真相 / 解释 | 处理 |
|------------|------------|------|
| "DGX 和 OEM 机器算力差很多" | GPU 子系统是同一块 HGX 板，训练算力基本一致 | 差异在网卡/拓扑/散热/软件，逐项核对 |
| 多机训练带宽上不去 | 后端网卡少、非每卡一网卡，或网卡与 GPU 跨 NUMA | 核对网卡数与 NUMA 对齐，用 nccl-test 实测 |
| 买了 A800/H800 以为等于 A100/H100 | 算力近似但 NVLink 互联带宽被削减 | 大规模多卡训练通信会更吃紧，并行策略要调整 |
| 只比 GPU 型号，不看拓扑 | PCIe Switch/NUMA 走向直接决定实测带宽 | 上线前用 nvbandwidth / nccl-test 验真实带宽 |
| 满载就降频 | 8×数百瓦风冷压不住，热降频 | 选液冷型号或确认机房散热足够 |
| 以为整机=不用配网络 | HGX 只管节点内，跨节点要自建 IB/RoCE 网 | 按"每卡一网卡 + 无阻塞胖树"规划计算网 |
| 把数值记死 | NVLink 带宽、卡数、网卡数随代次变 | 以官方规格/厂商 spec 为准，本文只讲机制 |
