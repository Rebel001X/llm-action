## 0. 一句话锚点

把三个词彻底分开，永远别混：

- **SSD(Solid State Drive，固态盘)**：存储**介质**，里面是 NAND 闪存颗粒，没有机械臂。
- **NVMe(Non-Volatile Memory express)**：**软件协议**，规定 CPU 怎么给盘下命令。
- **PCIe(PCI express)**：**物理公路**，盘插在主板的 PCIe 插槽/M.2 槽上，直连 CPU。

> 一句话：**NVMe SSD = 用 NVMe 协议、走 PCIe 公路的固态盘**。
> 对比："SATA SSD" 是同样的 NAND 介质，却走老旧的 SATA 公路 + AHCI 协议——介质一样，公路和协议拖了后腿。

## 1. 地基：闪存 / 接口 / 协议三件套

不假设你记得这些，逐个拆到最原子。

### 1.1 介质层：NAND 闪存

- 数据存在**浮栅晶体管**里，断电不丢(non-volatile，非易失)。
- 一个颗粒内部分成很多 **die(裸片)→ plane → block → page**，可以**很多 die 同时读写**——这是后面"为什么快"的物理根源。
- SLC/MLC/TLC/QLC = 每个单元存 1/2/3/4 bit，越多越便宜但越慢越短命。

### 1.2 接口层：盘怎么物理连到机器

```
        机械硬盘时代              SSD 过渡期              NVMe 时代
   ┌──────────────┐        ┌──────────────┐      ┌──────────────┐
   │   HDD 盘片    │        │  SATA SSD    │      │  NVMe SSD    │
   └──────┬───────┘        └──────┬───────┘      └──────┬───────┘
          │ SATA 线              │ SATA 线              │ PCIe lane
   ┌──────┴───────┐        ┌──────┴───────┐      ┌──────┴───────┐
   │  SATA 控制器  │        │  SATA 控制器  │      │   CPU/PCH    │
   │  (AHCI 协议)  │        │  (AHCI 协议)  │      │  (NVMe 协议) │
   └──────┬───────┘        └──────┬───────┘      └──────────────┘
          │                       │              直连 CPU，无中间控制器
        CPU                     CPU
```

NVMe 盘**直接挂在 CPU 的 PCIe 总线上**，没有 SATA 控制器这个中间商。物理形态常见三种：

- **M.2**：一根口香糖大小的卡，插主板 M.2 槽(消费 / 笔记本最常见)。
- **U.2 / U.3**：2.5 寸盘外形，前面板可热插拔(服务器最常见)。
- **AIC**：直接做成 PCIe 插卡(早期 / 高端)。
- **EDSFF(E1.S / E3.S)**：新一代服务器密集部署的"标尺"形态。

### 1.3 协议层：CPU 怎么和盘说话

协议规定"命令长什么样、放哪里、谁通知谁"。NVMe 用**内存里的环形队列(submission/completion queue)** + **门铃寄存器(doorbell)** 通信，下面第 2、5 节会拆开讲。

## 2. NVMe vs SATA：到底差在哪

很多人以为"NVMe 快是因为闪存快"——**错**。同样的 NAND 颗粒，换协议就慢一半。差距在**协议和接口**。

```
            SATA + AHCI                      PCIe + NVMe
   ┌────────────────────────┐      ┌────────────────────────┐
   │ 队列数:    1 条         │      │ 队列数:    最多 65535 条│
   │ 每队列深度:32           │      │ 每队列深度:最多 65536   │
   │ 最大并发:  1×32 = 32    │      │ 最大并发:  天文数字     │
   │ 一次 IO 需:多次寄存器读 │      │ 一次 IO 需:1 次门铃写   │
   │ 中断:      共享中断     │      │ 中断:      MSI-X 每队列 │
   │ 链路带宽:  6 Gbps(SATA3)│      │ 链路带宽:  PCIe x4 起   │
   └────────────────────────┘      └────────────────────────┘
```

### 2.1 队列：单车道 vs 多车道高速公路

- **AHCI(SATA 用的协议)**：只有 **1 条命令队列，深度 32**。再多的 CPU 核、再多的并发请求，都要排成一条队。
- **NVMe**：设计时就瞄准多核 + 闪存的并行性，允许**最多 65535 条队列，每条深度最多 65536**。**每个 CPU 核可以拥有自己独立的提交/完成队列对**，互不抢锁。

> 类比：SATA 是单车道收费站，NVMe 是几万条车道、每个核走自己那条，不用排队。

### 2.2 一次 IO 的"沟通成本"

- AHCI 下发一个命令要**读写多个寄存器**，每次都可能让 CPU 等待(慢)。
- NVMe 把命令直接写进内存里的提交队列，然后**只敲一下门铃寄存器(doorbell)** 告诉盘"有新活了"，盘做完往完成队列写结果并发 MSI-X 中断。**几乎零寄存器往返**。

| 维度 | SATA SSD (AHCI) | NVMe SSD |
|------|------|------|
| 公路 | SATA 3.0，6 Gbps ≈ 600 MB/s 上限 | PCIe x4，逐代翻倍(见第 3 节) |
| 协议 | AHCI(为机械盘设计) | NVMe(为闪存+多核设计) |
| 队列 | 1 × 32 | 65535 × 65536 |
| 典型随机 4K 延迟 | 约 100 µs 量级 | 约 10–20 µs 量级 |
| 典型随机读 IOPS | 约 10 万 | 约 50 万–150 万+ |
| CPU 每 IO 开销 | 高(寄存器往返) | 低(门铃机制) |

> 数字均为"约"，以具体型号官方规格为准。

## 3. PCIe 通道(lane)与带宽怎么算

NVMe 的"公路宽度"由 **PCIe 代数(Gen)** 和 **通道数(lane, 记作 ×N)** 共同决定。这是理解带宽上限的关键，必须会算。

### 3.1 lane 是什么

一条 **lane(通道)** = 一对差分收发线，能同时双向传数据。`x4` 表示用了 4 条 lane。NVMe SSD 绝大多数是 **x4**(M.2 槽通常给 4 条 lane)。

```
   CPU ════ x4 链路 ════ NVMe SSD
        lane0 ─────────►
        lane1 ─────────►   (4 条并行，带宽 ×4)
        lane2 ─────────►
        lane3 ─────────►
```

### 3.2 每代单 lane 速率(单向，近似有效带宽)

| PCIe 代 | 每 lane 原始速率 | 每 lane 有效带宽(约) | x4 有效带宽(约) |
|--------|------|------|------|
| Gen3 | 8 GT/s | ~1.0 GB/s | ~4 GB/s |
| Gen4 | 16 GT/s | ~2.0 GB/s | ~8 GB/s |
| Gen5 | 32 GT/s | ~4.0 GB/s | ~16 GB/s |
| Gen6 | 64 GT/s | ~8.0 GB/s | ~32 GB/s |

> GT/s = Giga-Transfers/s(每秒十亿次传输)。Gen1–5 用 128b/130b 编码，编码损耗≈1.5%，所以 16 GT/s 约等于 16×(128/130)/8 ≈ 1.97 GB/s。Gen6 改用 PAM4 + FLIT，算法不同。以上为工程速记值，精确以 PCIe 规范为准。

### 3.3 手算公式

$$\text{单向带宽} \approx \text{lane 数} \times \text{每 lane GT/s} \times \frac{128}{130} \div 8 \ (\text{GB/s})$$

例：Gen4 x4 → $4 \times 16 \times \frac{128}{130} \div 8 \approx 7.9$ GB/s。这就是为什么常说"PCIe 4.0 NVMe 盘顺序读 ~7 GB/s"。

> 注意：**全双工**，读和写各有这么多带宽。但实际还受盘内 NAND 并行度、控制器、散热限速。

## 4. 三大性能指标：IOPS / 带宽 / 延迟

存储不能只看一个数，三个指标各管一类场景。

### 4.1 三者定义

- **带宽(Throughput / Bandwidth)**：每秒搬多少字节，单位 GB/s。**顺序大块**读写(如加载一个大文件)看它。
- **IOPS(Input/Output Per Second)**：每秒完成多少次独立 IO 操作。**随机小块**(如 4KB 随机读)看它。
- **延迟(Latency)**：单次 IO 从发出到完成的时间，单位 µs。**对单次响应敏感**(如同步 checkpoint、KV 命中)看它。

### 4.2 三者的换算关系

$$\text{带宽} = \text{IOPS} \times \text{单次 IO 大小}$$

```
   ┌─ 大块顺序 (1 MB IO) ─┐         ┌─ 小块随机 (4 KB IO) ─┐
   │ IOPS 不高(几千)      │         │ IOPS 极高(百万级)     │
   │ 但带宽打满(~7 GB/s)  │         │ 但带宽不一定满        │
   │ 看"带宽"             │         │ 看"IOPS"+"延迟"       │
   └─────────────────────┘         └──────────────────────┘
```

验证：$1.5\text{M IOPS} \times 4\text{KB} = 1.5\times10^6 \times 4096 \approx 6.1\ \text{GB/s}$，正好吃满 Gen4 x4。

### 4.3 延迟的层级感(数量级，要刻进脑子)

```
   寄存器     ~1 ns
   L1 缓存    ~1 ns
   DRAM 内存  ~100 ns         ← 1 µs = 1000 ns
   NVMe SSD   ~10–100 µs      ← 比内存慢 ~100–1000 倍
   SATA SSD   ~100 µs
   网络(RDMA) ~1–10 µs (集群内)
   机械硬盘    ~5–10 ms        ← 比 NVMe 慢 ~100 倍
```

> 记忆锚：NVMe 比内存慢约**两到三个数量级**，比机械盘快约**两个数量级**。AI offload 的全部权衡都建立在这条阶梯上。

## 5. 为什么 NVMe 快(底层 6 个原因)

每个都说"为什么"，不是背结论。

1. **没有机械寻道**：机械盘要等磁头移动 + 盘片转到位(毫秒级)。SSD 是电信号寻址，随机访问和顺序访问代价几乎一样。

2. **海量内部并行**：盘内有几十个 NAND die，控制器把一个请求**条带化(striping)** 拆到多 die 并发执行，类似存储内部的"RAID0"。

3. **多队列 + 多核无锁**：第 2 节讲过，每个 CPU 核独占队列，**不抢全局锁**，多线程压测时线性扩展。

4. **门铃机制省 CPU**：下命令只敲一次 doorbell 寄存器，避免 AHCI 那种多次寄存器往返。

5. **直连 PCIe，少一跳**：不经过 SATA 控制器(HBA)，物理路径短、带宽宽。

6. **可轮询(polling)代替中断**：极低延迟场景下，CPU 可以**主动轮询完成队列**而不是等中断，省掉中断处理开销——SPDK(用户态 NVMe 驱动)正是靠这招把延迟压到极致。

```
   一次 NVMe 读的生命周期:
   ① 软件把命令写入"提交队列(SQ)"(在主机内存里)
   ② 写"门铃寄存器"告知盘:SQ 有新命令         ─┐ 几乎零开销
   ③ 盘 DMA 读取命令 → 内部多 die 并行读 NAND  │
   ④ 数据 DMA 直接写回主机内存                 │
   ⑤ 盘往"完成队列(CQ)"写结果 + 发 MSI-X 中断  │
   ⑥ 软件处理完成项,更新 CQ 门铃              ─┘
   全程主机内存↔盘 走 DMA,CPU 只在 ②⑥ 轻点一下
```

## 6. 在 AI 里的三个角色

NVMe SSD 在 AI 集群里通常是**第三层**：HBM/DRAM(快、贵、小) → NVMe(中、便宜、大) → 网络/对象存储(慢、最便宜、最大)。它专门接 GPU 显存和内存装不下的东西。

```
   容量 ↑ 慢                        ┌──────────────┐
            对象存储/HDD 集群       │ TB~PB,~ms    │
                ▲                   └──────────────┘
            NVMe SSD 本地           │ TB,~10–100µs │ ← 本文主角
                ▲                   └──────────────┘
            DRAM 主机内存           │ 百GB,~100ns  │
                ▲                   └──────────────┘
   容量 ↓ 快   GPU HBM 显存         │ 几十GB,~ns   │
                                    └──────────────┘
```

### 角色 A：数据加载(DataLoader)

训练时，海量样本(图片/文本/token 化数据集)放在 NVMe 上，DataLoader 用多 worker 随机读 → 喂给 GPU。

- **看什么指标**：随机读 **IOPS** + 带宽。数据集打散后是大量随机小读。
- **为什么要 NVMe**：机械盘随机读会成为瓶颈，GPU 饿死(GPU 利用率掉到个位数)。NVMe 的百万级 IOPS 才能喂饱多卡。
- **优化**：`webdataset`/`tar` 分片把随机读转顺序读、`O_DIRECT` 绕过 page cache、预取(prefetch)。

### 角色 B：Checkpoint 落盘

大模型训练每隔 N 步要把**模型权重 + 优化器状态**存盘，防止崩溃重训。

- **看什么指标**：顺序写 **带宽**(checkpoint 是大块连续写)。
- **痛点**：百亿/千亿参数的优化器状态可达数百 GB ~ TB，写一次几十秒到几分钟，期间训练**阻塞**(同步 checkpoint)。
- **为什么要 NVMe**：高顺序写带宽把这段停顿压到最短；配合**异步 checkpoint**(先 copy 到内存/NVMe，后台再持久化)进一步隐藏延迟。

### 角色 C：KV-Cache / 权重 offload(推理 & 训练)

显存装不下时，把暂时不用的数据"卸载"到 NVMe，用时再换回。详见第 7 节，也见 [[llm-inference/offload]]。

## 7. KV-Cache / 权重 offload 深讲

这是 NVMe 在 LLM 时代最"硬核"的角色，单独展开。

### 7.1 为什么要 offload

- **训练侧**：模型参数 + 梯度 + 优化器状态(Adam 要存一阶/二阶动量，约为参数量 ×12 字节)远超单卡显存。
- **推理侧**：**KV-Cache** 随上下文长度和并发线性膨胀；长上下文(几十万 token)、高并发时显存先爆。

### 7.2 三套代表性方案

```
   ┌─────────────────────────────────────────────────────┐
   │ ZeRO-Infinity (DeepSpeed,训练)                       │
   │   参数/梯度/优化器状态 分层放 GPU→CPU内存→NVMe       │
   │   需要时按层 prefetch 回 GPU,算完再 offload          │
   ├─────────────────────────────────────────────────────┤
   │ FlexGen (推理)                                        │
   │   权重+KV+激活 在 GPU/CPU/NVMe 间调度,吞吐优先       │
   │   适合离线批量推理,单卡跑大模型                       │
   ├─────────────────────────────────────────────────────┤
   │ KV-Cache offload (vLLM/LMCache/Mooncake 等)          │
   │   把冷的 KV block 换出到 CPU 内存,再溢出到 NVMe      │
   │   命中可复用(prefix caching),省重算                  │
   └─────────────────────────────────────────────────────┘
```

### 7.3 关键技术：GPUDirect Storage(GDS)

普通路径：NVMe → CPU bounce buffer(内存中转) → GPU 显存，CPU 和内存都被占用一遍。

```
   传统路径:  NVMe ──► 主机内存(bounce) ──► GPU 显存   (CPU 参与,多一跳)
   GDS 路径:  NVMe ════════ DMA 直达 ════════► GPU 显存 (绕开 CPU,省一次拷贝)
```

**GPUDirect Storage(`cuFile` API)** 让 NVMe 的数据**经 DMA 直接进 GPU 显存**，绕过 CPU 中转，降低延迟、省 CPU、提带宽。是 offload 能不拖垮性能的关键。

### 7.4 offload 的根本权衡

offload 把"显存不够"换成了"延迟变高 + 占用 PCIe 带宽"。能不能用，取决于第 4.3 节那条延迟阶梯：

$$\text{换入一层数据时间} \approx \frac{\text{数据量}}{\text{NVMe 带宽}} + \text{NVMe 延迟}$$

- 若**计算时间 > 换入时间**，可用 prefetch 把 IO 藏在计算后面 → offload 几乎免费。
- 若**计算时间 < 换入时间**,NVMe 成瓶颈 → offload 拖慢整体。
- 所以 offload 偏好**计算密集、对延迟不那么敏感**的离线/高吞吐场景;在线低延迟服务通常先 offload 到 CPU 内存,NVMe 作为最后兜底。

## 8. 数值例子 / 手算

### 例 1：算一块 Gen4 x4 盘的带宽上限

$$4\ \text{lane} \times 16\ \text{GT/s} \times \frac{128}{130} \times \frac{1}{8} \approx 7.9\ \text{GB/s}$$

所以厂商标"顺序读 7000 MB/s"是吃满了链路，再快也被 PCIe 卡住——除非上 Gen5(~16 GB/s)。

### 例 2：checkpoint 要写多久

设一个 70B(700 亿参数)模型，训练用混合精度，需要存权重 + 优化器状态。粗估优化器状态(Adam fp32)约为参数量 ×12 字节，权重(bf16)×2：

$$\text{总量} \approx 70\times10^9 \times (12 + 2)\ \text{B} \approx 980\ \text{GB} \approx 1\ \text{TB}$$

单盘顺序写按 ~5 GB/s 算：

$$T \approx \frac{1000\ \text{GB}}{5\ \text{GB/s}} = 200\ \text{秒} \approx 3.3\ \text{分钟}$$

> 结论：单盘存 1 个 70B checkpoint 要几分钟，训练全程阻塞不可接受。对策：① 多盘 RAID0/分片并行写;② 异步 checkpoint;③ 只存必要分片(ZeRO 切分后各 rank 只写自己那份)。8 盘并行 → 理论 ~25 秒。

### 例 3：DataLoader 喂得饱吗

假设单 GPU 训练每步消费 200 MB 样本、每步 50 ms，则需带宽：

$$\frac{200\ \text{MB}}{0.05\ \text{s}} = 4\ \text{GB/s}$$

一块 Gen4 NVMe(~7 GB/s)单卡够用；但 8 卡同机就要 ~32 GB/s，单盘不够 → 需多盘或本地 NVMe 池 + 缓存。

### 例 4：IOPS 和带宽换算自检

某盘标随机读 1,000,000 IOPS @ 4KB：

$$1{,}000{,}000 \times 4\ \text{KB} = 4{,}000{,}000\ \text{KB/s} \approx 3.8\ \text{GB/s}$$

说明 4K 随机读还没吃满 Gen4 链路(被盘内部并行度/延迟限制),而顺序读能到 7 GB/s。

## 9. 选型清单

| 维度 | 看什么 | 说明 |
|------|------|------|
| PCIe 代数 | Gen4 / Gen5 | 看主板/服务器支持;Gen5 盘插 Gen4 槽会降速 |
| 容量 | TB 级 | AI 场景越大越好,但单盘越大重建/故障域越大 |
| 企业盘 vs 消费盘 | **企业盘** | 有掉电保护(PLP 电容)、稳定 QoS、长质保 |
| 耐久度 DWPD | ≥1,写多选 3 | DWPD=每天可全盘写几次×质保年限;checkpoint 写多要高 |
| 耐久度 TBW | 总写入量 | 与 DWPD 等价的另一种标法 |
| 持续性能 | 看稳态曲线 | 消费盘 SLC 缓存用完会"掉速",企业盘稳态平 |
| 散热 | 散热片/风道 | Gen4/5 盘满载发热大,过热触发 thermal throttle 降速 |
| 形态 | U.2/U.3/EDSFF | 服务器选可热插拔形态;M.2 多用于消费/边缘 |
| NVMe-oF | 是否需远程共享 | 需把 NVMe 池给多机共享时用 NVMe over Fabric(见参考) |

### 选型口诀

- **训练大集群**：企业级 U.2/EDSFF + 高 DWPD + 多盘并行,服务 checkpoint 与数据池。
- **推理 offload**：高顺序读带宽 + 低延迟,配合 GDS;容量看 offload 规模。
- **预算敏感/边缘**：消费级 M.2,但注意稳态掉速和无掉电保护的风险。

> 具体型号规格、DWPD/TBW、Gen 支持以**厂商官方 datasheet 为准**,本文数值均为数量级速记。

## 常见问题

| 问题 | 答案 |
|------|------|
| NVMe 一定比 SATA SSD 快吗? | 同代介质下几乎总是,因为公路(PCIe)和协议(NVMe 多队列/门铃)都更优;但小负载、低并发下差距没那么大。 |
| NVMe 能当内存用吗? | 不能直接当内存,延迟比 DRAM 慢 ~100–1000 倍;但可作"扩展层",靠 offload/换页机制近似扩大可用容量。 |
| M.2 就等于 NVMe 吗? | 不。M.2 是**形态**,有的 M.2 槽走 SATA 协议(慢)。买之前确认是 "M.2 NVMe(PCIe)" 而非 "M.2 SATA"。 |
| 为什么我的 Gen5 盘没跑到 16 GB/s? | 可能槽位只给 x2/降到 Gen4、散热限速(throttle)、或负载是随机小块(看 IOPS 不看带宽)。 |
| GDS(GPUDirect Storage)必须用吗? | 非必须,但 offload/大数据加载场景能显著省 CPU、降延迟;需要驱动、文件系统和盘配合支持。 |
| AI 训练用消费盘行不行? | 短期/小规模可以,但无掉电保护、DWPD 低、稳态掉速,大量 checkpoint 写会很快磨损,生产环境用企业盘。 |
| checkpoint 慢怎么办? | 多盘并行 + 异步 checkpoint + ZeRO 分片各 rank 只写自己那份;别让同步落盘阻塞训练。 |
