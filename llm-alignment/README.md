## 0. 一句话锚点

**对齐 = 在不大改模型"知识"的前提下，调整它的"行为"，使输出符合人类偏好（Helpful 有用、Honest 诚实、Harmless 无害，即 3H）。**

预训练模型本质是一个"超强的下文续写器"——给它"中国的首都是"，它能续上"北京"。但你问它"帮我写封道歉邮件"，它可能续写出"……以及如何写道歉邮件的 10 个技巧"，因为互联网语料里"问题后面常跟更多问题"。**对齐就是把"续写器"训练成"应答器"。**

## 1. 地基：对齐解决什么问题

预训练目标是"预测下一个 token"，它优化的是**语言建模似然**，不是"对人有用"。这带来三类错位：

```
        预训练学到的能力                 人类真正想要的
   ┌───────────────────────┐      ┌───────────────────────┐
   │ 知识/语法/世界模型      │      │ 听懂指令(instruction)  │
   │ 模仿语料的"平均腔调"    │ ===> │ 有帮助(helpful)        │
   │ 既能写好话也能写坏话    │      │ 不胡说(honest)         │
   │ 没有"该不该说"的概念    │      │ 不作恶(harmless)       │
   └───────────────────────┘      └───────────────────────┘
            目标错配(objective mismatch)
```

- **能力 ≠ 意图**：模型"会"做某事，不代表它"愿意按你的格式/语气"做。
- **似然 ≠ 偏好**：语料里高频出现的回答，未必是人类最喜欢的回答（比如又长又水的答案）。
- **安全缺口**：纯语言模型没有"拒绝有害请求"的内在动机，需要显式注入。

对齐的核心思想：**用"人类偏好信号"替换/补充"语言建模似然"，作为新的优化目标。** 偏好怎么表达、怎么变成可优化的损失，就是各种对齐算法的分歧点。

## 2. 全景：从预训练到可用助手的三段式流水线

业界主流（以 InstructGPT/ChatGPT 路线为代表）是 **Pretrain → SFT → 偏好对齐** 三段：

```
 ┌──────────┐   海量无标注文本    ┌──────────┐
 │ Pretrain │ ─────────────────> │ Base 模型 │  会"续写"，不会"应答"
 └──────────┘   下一token预测     └────┬─────┘
                                       │ (指令-回答)成对数据
                                       v
                                 ┌──────────┐
                                 │   SFT    │  监督微调：学会"应答格式"
                                 └────┬─────┘
                                      │ SFT 模型(已能对话，但偏好粗糙)
                                      v
            ┌─────────────────────────┴─────────────────────────┐
            │                偏好对齐(Preference Alignment)        │
            │  路线A: RLHF = 训练RM + PPO 强化学习                  │
            │  路线B: 直接偏好优化 = DPO / ORPO / KTO ... (无需RL)  │
            └─────────────────────────┬─────────────────────────┘
                                      v
                                ┌──────────┐
                                │ 对齐模型  │  Helpful + Honest + Harmless
                                └──────────┘
```

> 直觉类比：Pretrain 是"读完图书馆"，SFT 是"上岗培训学会工作话术"，偏好对齐是"老员工带教，反复纠正你哪句说得更得体"。

## 3. SFT：监督微调（对齐的起点）

**做什么**：用人工/半自动构造的高质量 `(指令, 理想回答)` 数据，对 Base 模型做标准的有监督学习（交叉熵损失），让模型学会"看到指令就给出格式正确、内容相关的回答"。

```
 输入:  <用户>帮我把这句翻译成英文：今天天气很好</用户><助手>
 标签:  The weather is nice today.<eos>
 损失:  只对"助手回答"部分的 token 算交叉熵(prompt 部分通常 mask 掉)
```

- 关键点：**只在"回答"token 上回传梯度**（loss mask），否则模型会去学"如何提问"。
- SFT 决定了模型的"能力上界基本盘"和"风格基线"；数据质量 > 数据数量（少而精往往胜过多而杂）。
- 局限：SFT 只能教"什么是好答案"（正例模仿），无法直接告诉模型"什么是坏答案、坏到什么程度"。要表达"A 比 B 好"这种**相对偏好**，就需要下一步。

## 4. 奖励模型（Reward Model, RM）：把"人类偏好"变成一个分数

**核心问题**：人类很难写出"完美答案"，但很容易判断"A 和 B 哪个更好"。RM 就是把这种**成对比较**蒸馏成一个可计算的标量打分函数 $r_\theta(x, y)$。

```
 同一个 prompt x，让模型采样多个回答 → 人工排序
      回答A ≻ 回答B ≻ 回答C ≻ 回答D   (≻ 表示"更优")
                  │ 拆成成对(pairwise)
                  v
      训练 RM 使 r(x,A) > r(x,B) > r(x,C) > r(x,D)
```

- **结构**：通常拿 SFT 模型，把最后的"预测下一 token"头换成一个**输出单一标量**的回归头。
- **损失（Bradley-Terry 成对损失）**：对一对"优胜 $y_w$ / 劣败 $y_l$"，让优者得分更高：

  $$\mathcal{L}_{RM} = -\log \sigma\big(r_\theta(x, y_w) - r_\theta(x, y_l)\big)$$

  其中 $\sigma$ 是 sigmoid。直觉：把"好答案减坏答案"的分差推向正无穷，$\sigma$ 推向 1，$-\log$ 推向 0。
- RM 的好坏直接决定 RLHF 上限——RM 学偏了，强化学习就会"优化一个错的目标"（reward hacking 的根源）。

## 5. 路线 A：RLHF + PPO 的完整闭环

RLHF（Reinforcement Learning from Human Feedback）把对齐建模成强化学习问题：**策略 = 语言模型，动作 = 生成 token，奖励 = RM 打分**。最常用的优化算法是 **PPO（近端策略优化）**。

```
  ┌─────────────────────────── PPO 训练一步 ───────────────────────────┐
  │  1) 取 prompt x                                                    │
  │  2) Actor(待训练策略 π_θ) 采样生成回答 y                            │
  │  3) Reward Model 给 (x,y) 打分  r = r_φ(x,y)                        │
  │  4) Reference(冻结的SFT) 算 KL 惩罚: 防止 π_θ 跑太远               │
  │        最终奖励 = r - β·KL(π_θ || π_ref)                            │
  │  5) Critic(价值网络) 估计每一步的价值, 算优势 Advantage             │
  │  6) PPO 裁剪目标更新 Actor & Critic                                 │
  └────────────────────────────────────────────────────────────────────┘

   涉及 4 个模型(显存大户):
   ┌─────────┐  ┌──────────┐  ┌──────────────┐  ┌──────────────┐
   │ Actor π │  │ Critic V │  │ Reward Model │  │ Reference π0 │
   │ (要训练) │  │ (要训练) │  │   (冻结)     │  │   (冻结)     │
   └─────────┘  └──────────┘  └──────────────┘  └──────────────┘
```

**为什么要 KL 惩罚？** 如果只让模型最大化 RM 分数，它会找到 RM 的漏洞、生成人类看不懂但 RM 给高分的"乱码捷径"（reward hacking）。KL 项把策略"拴在" SFT 模型附近，相当于一根橡皮筋：可以优化，但别走太远。$\beta$ 控制橡皮筋的硬度——$\beta$ 太大学不动，太小会跑飞。

**PPO 的"近端/裁剪"思想**：每次更新不让新策略相对旧策略变化太大（用概率比 $r_t(\theta)=\pi_\theta/\pi_{old}$ 的裁剪），保证训练稳定。这也是 PPO 比早期策略梯度更稳的关键。

**痛点**：要同时持有 4 个模型、采样+打分+更新串行、超参敏感（学习率、$\beta$、采样温度、batch 配比都要调）。这正是路线 B 出现的动机。

> 简化变体：**GRPO**（去掉 Critic，用同 prompt 多次采样的组内相对优势替代价值网络）大幅降低显存与工程复杂度，被 DeepSeek 等用于推理对齐；**RLAIF** 用 AI 反馈代替部分人工标注，降低标注成本。具体超参与实现以官方文档/源码为准。

## 6. 路线 B：跳过 RL 的"直接偏好优化"

观察：RLHF 绕了一大圈（人偏好 → RM → RL）。能不能**直接用偏好数据训练策略**，省掉 RM 和 PPO？这催生了一类"无 RL"方法。

### 6.1 DPO（Direct Preference Optimization）

数学上证明：RLHF 的"带 KL 约束的奖励最大化"有闭式最优解，把奖励反解成策略本身，于是可以**直接用一个分类式损失**优化策略，不再需要显式 RM 和在线采样：

$$\mathcal{L}_{DPO} = -\log \sigma\Big(\beta\big[\log\tfrac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \log\tfrac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\big]\Big)$$

直觉：**提高"好答案"相对参考模型的概率，压低"坏答案"的概率**，$\beta$ 仍起 KL 约束作用。只需 `(x, y_w, y_l)` 离线偏好对，训练像普通监督学习一样稳。详见 [[llm-alignment/DPO]]。

```
  RLHF:  偏好数据 ─> 训练RM ─> PPO在线采样+RL  (4模型, 复杂)
  DPO :  偏好数据 ──────────> 一个对比损失直接训策略 (2模型: π + 冻结ref, 简单)
```

### 6.2 ORPO（Odds Ratio Preference Optimization）

更激进：**连参考模型都不要，把 SFT 和偏好对齐合并成一步**。在标准 SFT 交叉熵损失上，加一个基于"胜率/几率比（odds ratio）"的惩罚项，直接拉开好坏答案的几率。

- 优点：一个阶段搞定（省掉单独的 SFT 阶段和 ref 模型），流程最短。
- 代价：单一损失要同时管"学会回答"和"对齐偏好"，权衡系数需谨慎调。
- 论文：*ORPO: Monolithic Preference Optimization without Reference Model*；代码见 https://github.com/xfactlab/orpo （具体实现以官方仓库为准）。

### 6.3 其他变体（了解即可）

- **KTO**：用前景理论（人对得失的不对称感受）建模，只需"好/坏"二元标签，不必成对。
- **IPO / SimPO / CPO**：针对 DPO 的过拟合、长度偏置等问题做的改良。

## 7. 横向对比

| 方法 | 需要 RM | 需要在线采样/RL | 需要参考模型 | 工程复杂度 | 直觉一句话 |
| --- | --- | --- | --- | --- | --- |
| SFT | ❌ | ❌ | ❌ | 低 | 模仿好答案 |
| RLHF(PPO) | ✅ | ✅ | ✅ | 高 | 用奖励信号在线打磨 |
| GRPO | ✅(或规则奖励) | ✅ | ✅ | 中 | PPO 去 Critic 省显存 |
| DPO | ❌ | ❌(离线) | ✅ | 低-中 | 直接对比好坏答案 |
| ORPO | ❌ | ❌(离线) | ❌ | 低 | SFT+对齐合一 |
| KTO | ❌ | ❌(离线) | ✅ | 低-中 | 只需好/坏标签 |

> 没有"最好"，只有"最合适"：标注预算紧、想快速出活 → DPO/ORPO；要榨干性能、有算力和工程团队、需要在线优化复杂奖励（如推理正确性）→ RLHF/GRPO。

## 8. 工程落地：典型流程与关键配置项

一个最小可用的对齐流水线：

```
 数据: SFT集(指令-回答)  +  偏好集(prompt, chosen, rejected)
   │
   ├─ Step1 SFT:   base_model + sft_data ─> sft_model
   │      关键配置: 学习率(小)、epoch(防过拟合)、loss_mask(只算回答)、最大长度
   │
   └─ Step2 对齐:
         ├ 走RLHF: 先用偏好集训 RM，再 PPO
         │    关键配置: KL系数β、采样温度、PPO裁剪范围、rollout/更新 batch 比例
         └ 走DPO : 直接 sft_model + 偏好集
              关键配置: β(KL强度)、参考模型来源(通常=sft_model)、学习率
```

各类参数"做什么用"（具体名字/默认值以所用框架文档为准）：

- **学习率**：对齐阶段普遍比预训练小很多——你在"微调行为"，不是"重学知识"，步子大了会灾难性遗忘。
- **$\beta$ / KL 系数**：偏好优化"用力程度"的旋钮。大 → 保守、贴近 SFT；小 → 激进、易跑偏或胡说。
- **参考模型**：DPO/PPO 里那个"冻结的锚"，一般取 SFT 后的权重；它定义了"原点"。
- **采样温度（仅在线方法）**：太低探索不足、太高样本噪声大。
- **数据配比**：Helpful 与 Harmless 数据的比例会拉扯模型"乐于助人"与"安全拒绝"之间的平衡。

落地常配合 PEFT（如 LoRA）只训练少量参数以省显存；训练框架常用 DeepSpeed/Megatron 做并行。参见 [[ai-framework/deepspeed/README]] [[llm-train/README]]。

## 常见问题 / 坑

| 现象 | 根因 | 对策 |
| --- | --- | --- |
| 模型对齐后"变笨"/丢失知识 | 灾难性遗忘，对齐学习率过大/数据偏窄 | 调小学习率、混入通用数据、用 LoRA |
| RLHF 训出乱码但 RM 给高分 | Reward hacking，RM 有漏洞 + KL 太弱 | 增大 $\beta$、改进 RM、加约束 |
| 回答越来越长越啰嗦 | 长度偏置（人类/RM 偏好长答案） | 长度惩罚、用 SimPO 类改良、数据去偏 |
| 过度安全、动不动拒绝 | Harmless 数据过多/对齐税过重 | 平衡数据配比、设拒绝边界 |
| DPO 训练后 chosen 概率也下降 | DPO 已知现象：可能同时压低两者 | 关注"分差"而非绝对概率、试 IPO/ORPO |
| PPO 训练不稳定/崩溃 | 超参敏感、4 模型协同难 | 先用 DPO 验证数据，再上 RLHF；细调 KL/裁剪 |
| 评测分高但实际体感差 | RM/自动指标 ≠ 真实人类偏好 | 加人评、红队测试、多维评测 |

> 一句忠告：**对齐效果的天花板由数据质量（尤其偏好标注的一致性）决定，算法只是把数据里的信号高效"压"进模型。** 先把数据做对，再纠结用哪个 loss。
