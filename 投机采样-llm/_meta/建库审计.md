## 4. 建库过程中踩过的坑（不要重踩）

1. **Bash heredoc 里嵌中文 Python 代码**：`print("...「引号」...")` 用 ASCII 双引号会直接语法错误；一律用 `「」` 或改用 Write 工具写文件。
2. **控制台显示乱码 ≠ 文件编码错**：Git Bash 控制台按 GBK 显示 UTF-8 会花屏，但文件本身是正确的 UTF-8。用 `open(..., 'rb')` 看字节确认，别乱"修"。
3. **自检器自身的假阳性**（三次）：
   - 铁律一把**双链文件名**里的"无损"二字判成违规 → 检查前必须剥掉 `[[...]]` 与行内代码；
   - 铁律五把**正在声明禁用**那些句式的行判成违规 → 加"元陈述"豁免；
   - 铁律五逐处计数，把交叉引用全判成违规 → 改成按 (篇目 × 编号) 聚合。
   **把可执行验证当论证基础的库，必须同时怀疑自己的验证。**
4. **并发 agent 上限是 20**，且调研 agent 会自己再派子 agent，很容易占满；写作 agent 要分批派。
5. **WebSearch 配额 200/200 会被并行 agent 快速吃光**。用完后改走 `WebFetch` + `https://lite.duckduckgo.com/lite/?q=` 或直接构造 arXiv/GitHub raw URL。**配额用完不是编造的理由。**
6. **调研 agent 边写边扩**：写作 agent 可能读到半成品版本（RS-1 从 483 行扩到 2001 行）。派写作 agent 前要确认调研已完成，或事后用 SendMessage 让它复核。
7. **WebFetch 的摘要模型会编造内容**：建库中至少两次 —— 一次编造了一张 12 行的 MagicDec 表格，一次把 SGLang release 的年份从 2026 读成 2024。**凡二手摘要给的表格与日期，必须回一手页面（atom/API/raw）核对。**
8. ⭐**arXiv 编号的前四位 YYMM 不等于 v1 的年月**：月底投稿会拿到下个月的编号（实测 147 个里有 7 个不一致，最大差两个月）。**别用编号去推年月**，要用官方 `published` 字段。
9. **改了基座代码要通知所有下游**：`speedup.py` 修了 attention FLOPs 漏乘层数的 bug 之后，第 18、19、22、23 篇的数字全要重算。SendMessage 时**要发对收件人**（我曾把给第 22 篇的勘误发给了第 19 篇）。
9. **⭐ 别把 arXiv 版本号焊死进正文 URL**（2026-08-22 复核挖出来的坑，本库为它误禁了一条真数据）：库里四处都写 `https://arxiv.org/html/2601.11580**v1**`，于是**永远读不到 2026-03-18 的 v2**，而树验证那整节只在 v2 里。结果是网站摘要与"论文正文"看起来互相矛盾，我按"论文正文优先"把一条**真数据**判成【待核验】并禁止引用，还连累第 25 篇把一条判断从 A 降到 B。
   **规矩三条**：① 引用论文正文**先开 `abs/` 页**看 *"last revised …(this version, vN)"*，正文 URL 用**不带版本号**的形式，或显式写明"本库核的是 vX、哪天核的"；② **"论文里没有 X"这类否定断言，必须连版本号与核验日期一起记** —— 否定断言的保质期比肯定断言短得多；③ **网站摘要与论文"打架"时，第一件事不是判谁可信，是查它们是不是同一个版本。**
10. **⭐ "我抽不到" ≠ "原文没有"**（同日复核的另一半）：DeepSeek-V3 那两个数四次抽取失败，其中一次明确报告 *"Content truncated due to length"*，本库当时正确地忍住没编，但也差点把它读成"原文可能根本没有"。**正确动作是换渲染 + 落盘本地检索**（HTML v1/v2 + 官方 PDF 三份 `curl` 下来，`pdftotext -layout` + 正则），**而不是换一个摘要模型再问一遍** —— 摘要模型问十遍还是那个截断。三渲染交叉一致，才是"核实"。

### 7.2 B 类 4 处：检查器的假阳性 → 新增「表格列头即主语」豁免

第 21 篇 §6.3「等收益线」表里的 **2.21× / 3.76× / 5.76× / 8.52×**
**不是加速比**：那一列是「草稿成本 $c$ 相对基准 $c{=}0.02$ 的倍数」，
整张表的加速比恒等于最后一列的 3.1989（这正是"等收益线"的定义）。
主语是**成本**不是速度，属既有 (c) 类「非速度主语」。

问题在于 (c) 原来只看**同一行**的左右文字，而在 markdown 表里，
**一个数字的主语不在同一行，而在它那一列的表头**。所以豁免这样补：

- 新增 `table_header_cells()`：数据行 → 往上找 `|---|` 分隔行 → 取它上一行为表头；
  中途遇到空行或标题就放弃（不会张冠李戴上一张表的表头）。
- `speedup_matches()` 增加可选的 `headers` / `raw` 参数：把**匹配所在那一列**的表头
  单元格并进 (c) 的左侧线索。**两条护栏**保证它不放过真违规：
  ① 只取匹配那一列的表头，不取整行 —— 否则同表里只要有一列叫"加速比"，
  整张表都会被那三个字带偏；② 表头里出现任何速度类词就**一律不豁免**，
  与"同行出现速度词就不豁免"同权。
- 配套把 `strip_for_rules()` 改成**等长替换**（挖掉的双链/行内代码用同长度空白填回），
  否则偏移量对不上、算不出列号。这一步对铁律一的判定完全无影响（内容一样是空白）。

同时，第 21 篇 §6.3 的列头由「相对基准的**倍数**」改成「相对基准的**成本倍数**」，
并在表前加了一句点明主语 —— 这是**把主语写出来**，不是为了消 WARN 而删数字。

一个天天报警而永远无需处理的检查项，**比没有这个检查项更糟** —— 它会训练读者忽略告警。
这一轮抓出两个：

| 检查项 | 原来的毛病 | 改法 | 效果 |
|---|---|---|---|
| `verify.py --consistency` | 冲突窗口是「同行 ±1 行」，把同段里**别的工作**的数字算到这个编号头上 | 收窄到**同一句**（按中英文句读切） | 13 组 → **3 组** |
| `verify.py` 铁律五 | 把 `_research/RS-*` 也算进来。那是调研原始材料，末尾成片 URL 清单本就不写年月 | 只管**正文章节**，RS-* 单列为「参考，不计违规」 | 正文 **0 个**（40 个原来全在调研笔记里） |
| `citecheck.py` 判决行 | 拿 ② 号「编号 YYMM 与 v1 年月不符」当失败，而**那是 arXiv 的正常现象** | 判决只看**存在性**（有没有编造的编号）；② 降级为提示 | 不再无故报「未通过」 |
| `--consistency` 的数字捕获 | 把 **`4× A800-40GB` 里的 4 当成 4× 加速比** —— 那是**卡数** | `N×` 后紧跟硬件型号则跳过（`DEVICE_AFTER`） | 3 组 → **2 组** |
| `--consistency` 的剩余 2 组 | 只说"不一致，请人工核"，没说是哪种不一致 | 各篇数字集合若成**包含链**，自动标注「子集关系：详略不同，非矛盾」 | 剩下 2 组**全部被解释掉**，不再需要人工翻 |

> 三处改动都配了反例测试（`test_verify_rules.py` 新增 6 个）：
> **降噪不许把真信号一起降掉** —— `2.21×`、`3.6×（batch=1）` 这类真加速比必须仍被捕获，
> 收窄到"同一句"之后同句内的数字必须仍看得见，铁律五在正文里必须仍然为 0。

> **判据**：告警要么可处理，要么不该存在。铁律五那 40 条**一条都不需要处理**，
> 所以问题在检查器的作用域，不在库。

顺带修掉一个**静默截断**：铁律五的清单只打印前 15 条却不说还有多少，
现在会明说「另有 N 条未列出」。**静默的 top-N 会被读成"就这么多"**，
这与本库对 agent 报告的态度是同一条原则。

### 8.4 这一轮新踩的坑

1. ⭐**幂等判据不能拿「新内容的开头」去查**：补丁的 `new` 往往是「锚点 + 新增」，
   拿 `new[:24]` 去查等于查锚点 —— 锚点一直都在，于是**每次都被误判成"已存在"而跳过**。
   这一轮 4 个补丁里有 2 个被它静默跳过了，是复跑时才发现的。正确做法是只看
   `new.replace(old, "")` 之后**真正新增出来的那部分**。
2. **Windows 控制台的中文花屏可以根治**：`PYTHONIOENCODING=utf-8`。
   在此之前我一直靠"读字节确认文件没坏"来绕过，其实只要设这个环境变量就不用绕。
3. **`Edit` 工具改不动「源码里写着 `\uXXXX` 转义、而我按渲染后的字符去匹配」的行** ——
   这种行要么按源码里的字面形式匹配，要么写个纯 ASCII 脚本改字节。
4. **双链一定要抄全名**：这一轮手写的 3 条双链全部只写了标题前半段
   （`[[07-无损的三种口径]]` 而真名是 `[[07-无损的三种口径-分布无损不等于结果相同]]`），
   三条全是死链。**双链不要凭记忆写，去 `ls` 一下。**
