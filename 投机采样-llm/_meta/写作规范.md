## 1. 五条铁律

### 铁律一：说「无损」必须标口径，三选一，不许含糊

"投机采样是无损的"这句话在社区里被说烂了，但**它在三种完全不同的意义下被使用**：

| 口径 | 含义 | 谁属于这一类 |
|---|---|---|
| **L1 分布无损（exact）** | 输出是**目标模型分布 $p$ 的精确样本**；同一个 prompt 跑两次结果可以不同，但**分布逐点相等** | 标准投机采样（Leviathan / Chen）、EAGLE 系列、MTP 草稿 |
| **L2 贪心等价（greedy-exact）** | 温度=0 时，输出序列与目标模型逐 token **完全相同** | 上面那些在 $T=0$ 下的退化情形；blockwise parallel decoding |
| **L3 近似（lossy）** | 放宽了接受判据，**分布已经不等于 $p$** | Medusa 的 typical acceptance、各种阈值放宽、部分"自投机"设置 |

**凡在正文里写"无损"，必须在同一段内标明是 L1 / L2 / L3 中的哪一个。**
没标口径的"无损"视为未完成。特别地：**L1 不蕴含"结果一样"**（见第 07 篇），
把"无损"讲成"结果和不开投机时一模一样"是社区里最高频的错误，遇到必须点名纠正。

### 铁律二：任何加速比数字不许裸奔

写下 "2.3×"、"提速 3 倍"、"acceptance length 4.2" 之前，**同一段必须给全下面这张单**：

1. **batch size**（最关键。bs=1 的 3× 和 bs=64 的 3× 是两回事，后者常常根本不存在）
2. **γ**（一次投机的草稿长度 / 树的规模）
3. **α 或平均接受长度**（并注明是哪种定义，见铁律一的口径问题在 05 篇）
4. **draft 与 target 的具体组合**（参数量、是否同 tokenizer、是否同族）
5. **硬件与精度**（H100/A100/MI300X，fp16/fp8/int4——**权重精度直接改带宽账**）
6. **测的是什么**（TPOT？端到端延迟？还是吞吐 tokens/s？**延迟涨了吞吐也可能跌**）
7. **任务分布**（代码 / 摘要 / 开放对话 —— 接受率能差 2 倍以上）

缺项的数字，要么去查补全，要么**原样引用并显式标注「口径不全，不可横向比较」**。
禁止把不同来源的加速比放进同一张表格做比较，除非你已核对上面 7 项一致。

### 铁律三：每个「它很好」必须配一条「它什么时候是负收益」

本库的立场：**投机采样是一笔用算力换延迟的交易，这笔交易经常是亏的。**
每篇介绍某方法优点之后，必须至少写一条**明确的失效条件**（不是"可能效果不好"这种废话，
要写成可判定的形式：如"当 batch ≥ X 且序列长 ≥ Y 时，吞吐下降"）。

没有失效条件小节的篇目视为未完成。

### 铁律四：数学断言必须有可执行验证，且正文指名引用

本库和"靠来源"的库不同：**无损性、接受率、加速比都是数学命题，能被代码判真假。**

凡写"可以证明""等价于""恒成立""期望是"的地方，必须在 `_lab/` 里有对应测试，
并在正文指名（例如"见 `_lab/test_lossless.py::test_exact_distribution`"）。
`_lab/verify.py --tests` 会强制检查：**正文引用的每一个测试都必须真实存在（零虚引）**。

没有对应验证的强断言，要么补验证，要么改写成"据 XXX 报告（URL）"并标出处。

### 铁律五：史料必须可追溯，不许出现没有主语的句子

历史篇（08–15）与前沿篇（24–25）里，每提到一个工作，必须给全：

- **年月**（arXiv v1 的年月，不是发表年）
- **arXiv 编号或 URL**
- **作者/机构**（第一作者 + 机构）
- **它相对前作新增了什么**（一句话，具体到机制）
- **它的哪些主张后来被推翻/淘汰了**（如果有；没有就写"截至查证日未见推翻"）

**禁止写**："最近有研究表明……"、"业界普遍认为……"、"有工作把它提升到了 X 倍"。
每一条都要能点名到人、到论文、到 URL。**查不到就写「未查证」，绝不编造。**

## 2. 统一模板（十段式）

每篇正文按此顺序，小节标题可微调，但**段位不许缺**：

1. **一句话** —— 这一篇要讲清的那件事（不超过 3 行）
2. **从哪来 / 要解决什么** —— 没有它会怎样；对历史篇是"前一代卡在哪"
3. **机制拆解** —— 精确定义 + 完整符号 + 形状/复杂度标注
4. **逐步推导或逐步走查** —— 不跳步。数学篇给推导，工程篇给"一个 step 里发生了什么"
5. **小数字算例** —— 用很小的词表（如 $|V|=5$）、很短的 γ（如 3），**从头算到尾给出具体数字**
6. **代码验证** —— 指向 `_lab/` 的实现与测试，贴关键片段与**实跑输出的真实数字**
7. **口径与坑** —— 本篇涉及的口径分歧（α 怎么定义、加速比怎么测），至少 1 条
8. **失效条件（铁律三）** —— 什么时候这个方法反而更慢/更差，尽量可判定
9. **自测题** —— 3–5 道，附答案要点
10. **延伸与双链** —— 链到相关篇目 + 本篇来源

历史篇（08–15）额外要求：**第 2 段必须是"前一代卡在哪"，最后额外加一小节
「它新增了什么 / 什么被后来推翻」**（铁律五）。

## 4. 社区解释：要采纳，更要评点

用户明确要求「采纳社区的精彩解释」。做法是：

**采纳**：遇到某个概念社区里有公认讲得好的比喻/图/代码，**用它**，并注明出处与作者。
典型的好来源（举例，不限于）：

- Jay Mody / Jay Alammar 类的图解式讲解
- Hugging Face blog 的 assisted generation 系列
- vLLM / SGLang / TensorRT-LLM 的官方 blog 与 design doc
- PyTorch blog（gpt-fast 系列）
- Lilian Weng、Sebastian Raschka 等人的综述博客
- 原论文本身（Leviathan 2211.17192、Chen 2302.01318、Stern 2018 等）
- 知乎/B站/掘金的高赞讲解（标 C 级来源，**但必须说清它好在哪、哪里讲错了**）

**评点**：引用社区材料时必须回答两问：**① 它好在哪（具体到那个比喻/那张图解决了什么理解障碍）；
② 它有没有简化或讲错的地方。** 社区讲解在本主题上的高频错误（遇到要点名）：

- 把"无损"讲成"输出和不开投机完全一样"（混淆 L1 与 L2，见铁律一）
- 把接受判据写成 `p(x) > q(x) 就接受`（漏了 $\min(1,p/q)$ 的随机性）
- 拒绝后**直接用 $p$ 重采**（错的，必须用 $p' = \text{norm}(\max(0, p-q))$，否则分布有偏）
- 说"草稿模型越小越好"（忽略 α 塌方；这是 c 与 α 的权衡）
- 说"投机解码提升吞吐"（**在大 batch 下常常相反**）
- 把 Medusa 的 typical acceptance 也说成无损（那是 L3）
- 把 MTP 的训练目标和推理时的草稿用法混为一谈

**第 26 篇是社区解释的专篇**，其它篇遇到相关材料也要就地引用与评点。
