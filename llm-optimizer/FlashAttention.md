## 0. 一句话锚点
- **标准注意力**：先算出整张分数矩阵 $S=QK^\top$（n×n），存到 HBM，再 softmax，再乘 V。瓶颈是这张 n×n 矩阵的**反复读写显存**。
- **FlashAttention**：把 Q、K、V 切块，逐块在**片上 SRAM**里算，用 **online softmax** 边算边把结果累加进输出，**永不把完整 n×n 写回显存**。
- 关键认知：**它不省计算量（FLOPs 几乎一样），它省的是显存占用和访存次数（IO）**。GPU 上注意力是**访存受限（memory-bound）**的，省访存就等于省时间。所以叫 **IO-aware**。

## 1. 地基：先把注意力和 GPU 内存讲清

### 1.1 注意力到底在算什么
给定一段长度为 $n$ 的序列，每个位置有一个查询向量 $q$、键向量 $k$、值向量 $v$，维度都是 $d$。堆叠成矩阵 $Q,K,V \in \mathbb{R}^{n\times d}$。注意力定义为：

$$O = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V$$

拆成三步看：
1. **打分**：$S = QK^\top / \sqrt{d}$，$S\in\mathbb{R}^{n\times n}$。$S_{ij}$ = 第 $i$ 个 query 和第 $j$ 个 key 的相似度。
2. **归一化**：$P=\mathrm{softmax}(S)$，按**行**做。第 $i$ 行：$P_{ij} = \dfrac{e^{S_{ij}}}{\sum_{l} e^{S_{il}}}$，每行和为 1，是一组权重。
3. **加权求和**：$O = PV$，第 $i$ 行输出 = 用 $P$ 的第 $i$ 行权重对所有 $v$ 加权平均。

> **softmax 为什么要减最大值**：直接算 $e^{S_{ij}}$，若 $S_{ij}$ 大（比如 100），$e^{100}\approx 2.7\times10^{43}$ 直接 float 上溢。所以工程上一律算 $e^{S_{ij}-m_i}$，其中 $m_i=\max_j S_{ij}$。减去常数不改 softmax 结果（分子分母同乘 $e^{-m_i}$）。**这个 $m_i$ 正是 online softmax 要在线维护的东西。**

### 1.2 GPU 内存层级（为什么访存是瓶颈）
详见 [[ai-infra/算力/GPU工作原理]]，这里给最小够用版。一块 A100 大致：

```
        容量          带宽           延迟      角色
寄存器   ~256KB/SM    ~极快          ~1cyc    线程私有
SRAM    ~192KB/SM    ~19 TB/s       ~低      片上共享内存(shared mem)，超快超小
HBM     ~40-80 GB    ~1.5-2 TB/s    ~高      显存，大但比 SRAM 慢约一个数量级
```

```
   [SM 核心] <-- 寄存器/SRAM(快,小) -->  片上
        |
        |  ~1.5 TB/s, 慢       <== 注意力的钱都花在这条路上
        v
      [ HBM 显存 (大,慢) ]
```

核心矛盾：**算得快（算力 TFLOPS 很高），但搬数据慢（HBM 带宽相对低）**。一个 kernel 是「算力受限」还是「访存受限」，看它的**算术强度** = FLOPs / 字节访存。注意力的 softmax、逐元素运算算术强度很低 —— **每搬一个数只做几次运算** —— 所以它是**访存受限**：时间几乎全花在等 HBM 数据上，核心在空转。**优化注意力 = 减少 HBM 读写次数。**

## 2. 标准注意力的痛点：物化 n×n 矩阵

标准实现（PyTorch 朴素版）的访存账：

```
Q,K,V (n×d) ─读─► 算 S=QK^T ─写─► [S: n×n] 落 HBM
[S] ─读─► softmax ─写─► [P: n×n] 落 HBM
[P] ─读─► 算 O=PV ─写─► O (n×d)
```

问题全在那两张 **n×n 中间矩阵 $S$ 和 $P$**：
- **显存爆炸**：$S$ 占 $n^2$ 个元素。$n=2048$、fp16(2字节) 时 = $2048^2\times2 = 8\,\mathrm{MB}$ —— 单头看着不多，但**乘上 batch×heads**。设 batch=16、heads=32，就是 $16\times32\times8\,\mathrm{MB}=4\,\mathrm{GB}$，只为一层的中间结果。$n$ 翻倍显存翻 4 倍：$n=8192$ 时单头就 128MB。这就是为什么长上下文以前"显存爆"。
- **访存爆炸**：$S$ 和 $P$ 每个都被**完整写一遍、读一遍** HBM。softmax 还要再把 $S$ 整行读进来求 max 和 sum。这些 n×n 级别的 HBM 往返，正是访存受限的元凶。

> **一句话**：朴素注意力慢，不是因为乘法多，而是因为为了那张 n×n 矩阵，在 HBM 上来回搬了太多次数据。

## 3. 分块 tiling：把大矩阵切成放得进 SRAM 的小块

**思路**：既然 SRAM 快但只有 ~192KB，那就别一次处理整行，把 Q、K、V 沿序列维切成小块（tile / block），每次只把**几个小块**搬进 SRAM，在片上算完再走。

设把 Q 切成行块，每块 $B_r$ 行；K、V 切成列块，每块 $B_c$ 行：

```
          K 块:  K1   K2   K3   K4
                ┌────┬────┬────┬────┐
   Q 块 Q1 ───► │S11 │S12 │S13 │S14 │   每个 Sij 是 Br×Bc 的小块
            Q2  │S21 │S22 │S23 │S24 │   只在 SRAM 里短暂存在,算完即弃
            Q3  │S31 │ .. │    │    │
                └────┴────┴────┴────┘
```

每个小块 $S_{ij}=Q_iK_j^\top$ 只有 $B_r\times B_c$ 大，能放进 SRAM。**但有个拦路虎**：softmax 是**按整行**归一化的，而我们一次只看到一行的**一段**（一个 K 块）。在只见局部的情况下，怎么算出全局正确的 softmax？答案就是下一节的 **online softmax**。

> **块大小怎么定（手算）**：SRAM 一次要同时放下 $Q_i(B_r\times d)$、$K_j$、$V_j(B_c\times d)$ 和分数块 $S_{ij}(B_r\times B_c)$。设 $d=64$、fp16(2字节)、SRAM 可用约 192KB=196608 字节。若取 $B_r=B_c=64$：$Q_i$ 块 $64\times64\times2=8$KB，$K_j$ 8KB，$V_j$ 8KB，$S$ 块 $64\times64\times2=8$KB，合计约 32KB，**远小于 192KB，放得下且有余量做双缓冲**。块取太大放不下、太小并行/访存效率低，实现里按硬件调成 64/128 这类值。

## 4. online softmax：核心魔法（带完整推导）

### 4.1 问题重述
要算一行的 $\mathrm{softmax}$，需要全行的 $\max$（记 $m$）和全行的指数和（记 $\ell=\sum e^{x_j-m}$）。但分块后我们是一块一块看到这行的数的。**目标：每来一个新块，只用「当前累计的 $m,\ell$」和「新块的数」，就把 $m,\ell$ 和部分输出更新对，最终等于看全行的结果。**

### 4.2 在线更新 max 和分母 ℓ（递推推导）
假设处理到某一步，对已见过的数维护：当前最大值 $m^{\text{old}}$、当前分母 $\ell^{\text{old}}=\sum_{\text{已见}}e^{x-m^{\text{old}}}$。现在来一个新块，块内最大值 $\tilde m$、块内分母 $\tilde\ell=\sum_{\text{新块}}e^{x-\tilde m}$。

新的全局最大值显然是
$$m^{\text{new}}=\max(m^{\text{old}},\tilde m).$$

合并分母时，**两边都得改成减去新的 $m^{\text{new}}$**。注意一个恒等式：把 $e^{x-m^{\text{old}}}$ 改成以 $m^{\text{new}}$ 为基准，只需乘一个修正因子：
$$e^{x-m^{\text{new}}}=e^{x-m^{\text{old}}}\cdot e^{m^{\text{old}}-m^{\text{new}}}.$$
所以
$$\boxed{\ell^{\text{new}}=\underbrace{e^{m^{\text{old}}-m^{\text{new}}}}_{\text{修正旧的}}\ell^{\text{old}}+\underbrace{e^{\tilde m-m^{\text{new}}}}_{\text{修正新块的}}\tilde\ell}$$
其中那个 $e^{m^{\text{old}}-m^{\text{new}}}\le 1$ 的因子叫 **rescale（缩放修正因子）**，它把"按旧 max 算的旧值"翻译成"按新 max 算"。这是整个算法的灵魂。

> **为什么 rescale 因子总是 $\le 1$**：因为 $m^{\text{new}}=\max(m^{\text{old}},\tilde m)\ge m^{\text{old}}$，所以指数 $m^{\text{old}}-m^{\text{new}}\le 0$，$e$ 的非正次幂必 $\le1$。直觉上：max 只会变大不会变小，原来"减得不够多"的旧指数值，现在要按更大的基准缩小，所以乘个 $\le1$ 的因子缩一下。**只要新块没刷新 max（$\tilde m\le m^{\text{old}}$），rescale=1，旧累加器原封不动**——这正是数值稳定的来源。

### 4.3 输出也要在线累加（关键）
我们不想存 $P$，而是想直接累加输出 $O=\sum_j P_{ij}v_j$。麻烦在于 $P_{ij}=e^{S_{ij}-m}/\ell$ 里的 $m,\ell$ 还在变。**技巧：先累加未归一化的分子，最后再除一次 $\ell$。** 维护一个未归一化输出累加器
$$O^{\text{unnorm}}=\sum_{\text{已见 }j} e^{S_{ij}-m}\,v_j.$$
当 $m$ 从 $m^{\text{old}}$ 更新到 $m^{\text{new}}$ 时，旧的累加器也要乘同一个 rescale 因子：
$$O^{\text{new}}=e^{m^{\text{old}}-m^{\text{new}}}\,O^{\text{old}}+\sum_{\text{新块}} e^{S_{ij}-m^{\text{new}}}v_j.$$
全部块处理完后，**最后做一次除法**：$O_i = O^{\text{unnorm}}/\ell$。这样我们**从头到尾没存过任何 n×n 矩阵**，只维护了每行三个小东西：$m$（标量）、$\ell$（标量）、$O^{\text{unnorm}}$（长度 $d$ 的向量）。

```
每个 query 行的"状态"只有:
   m  : 标量(running max)
   ℓ  : 标量(running 分母)
   O  : d 维向量(running 未归一化输出)
来一个 K/V 块 → 算块内分数 → 更新 m → rescale 旧 ℓ,O → 累加新块 → 丢弃块
```

## 5. 完整算法 + 内存布局

**两层循环**（v1 的写法）：外层遍历 K/V 块，内层遍历 Q 块；v2 把外层换成 Q 块（见第 8 节）。以 v2 视角（外 Q 内 KV）描述更直观：

```
for 每个 Q 块 Qi (放进 SRAM, 初始化 m=-inf, ℓ=0, O=0):
    for 每个 K/V 块 Kj,Vj (依次搬进 SRAM):
        S = Qi @ Kj^T / sqrt(d)        # Br×Bc 小块, 在 SRAM
        m_blk = rowmax(S)
        m_new = max(m, m_blk)
        P = exp(S - m_new)             # 未归一化权重
        rescale = exp(m - m_new)       # 修正因子
        ℓ = rescale*ℓ + rowsum(P)
        O = rescale*O + P @ Vj         # 累加未归一化输出
        m = m_new
    O = O / ℓ                          # 收尾归一化, 整块一次性写回 HBM
    写回 Oi, 以及 logsumexp Li=m+log(ℓ)  # Li 留给反向用
```

内存布局对比：

```
标准注意力 (HBM 往返多):
  HBM: Q,K,V ─► [S n×n] ─► [P n×n] ─► O      ← 红色 n×n 反复进出 HBM

FlashAttention (n×n 只活在 SRAM):
  HBM: Q,K,V ───────────────────────► O
            │  小块进 SRAM,算完即弃   ▲
            └── S,P 从不落 HBM ───────┘
```

## 6. 反向传播：用「重算」代替「存储」

训练要反传，标准做法得存下 $P$（n×n）供反向用 —— 又回到显存爆炸。FlashAttention 的招：**前向只额外存每行的 logsumexp $L_i=m_i+\log\ell_i$（一个标量/行，共 $O(n)$）**；反向时，**用存下的 $Q,K,V,O,L$ 当场重新算出需要的 $S$、$P$ 小块**，算完即弃。

> 这是经典的 **recomputation / activation checkpointing** 思想：**多花一点计算，换巨量显存**。因为注意力是访存受限的，重算的 FLOPs 几乎不增加墙钟时间，却省掉了存 n×n 的 HBM 读写，反向也因此变快。

## 7. 复杂度分析

| 维度 | 标准注意力 | FlashAttention |
|---|---|---|
| 计算量 FLOPs | $O(n^2 d)$ | $O(n^2 d)$ **一样**（不是近似） |
| 额外显存(中间) | $O(n^2)$ | $O(n)$（只存 $O,L$，不存 $S,P$） |
| HBM 访存量 | $O(n^2)$ 量级 | $\approx O\!\left(\dfrac{n^2 d^2}{M}\right)$，$M$=SRAM 大小，**大幅下降** |
| 数值结果 | 基准 | **逐位等价**（同精度下） |

**为什么时间变快却没减 FLOPs**：因为注意力是 memory-bound，瓶颈是 HBM 访存而非算力。把 $O(n^2)$ 的 HBM 访存降到 $O(n^2 d^2/M)$（$M\gg d^2$），相当于让核心不再空等数据，算力利用率上去了，墙钟时间随之下降。**省 IO = 省时间**，这就是 IO-aware 的全部意义。

> **手算访存**：$n=4096,d=64$，朴素 fp16 写 $S$ 一次 = $4096^2\times2=32$MB，再读 32MB，仅 $S$ 一项就 64MB HBM 往返；FlashAttention 把这 64MB 几乎清零，只换来 $O,L$ 的 $4096\times64\times2\approx0.5$MB 写回。

## 8. v1 / v2 / v3 思路演进

| 版本 | 年份 | 核心改进 | 一句话 |
|---|---|---|---|
| **v1** | 2022 | tiling + online softmax + 重算反传 | 首次让注意力 IO-aware，长序列不爆显存 |
| **v2** | 2023 | 循环顺序/并行重排，减非矩阵乘运算 | 同样的数学，吃满 GPU |
| **v3** | 2024 | 面向 Hopper(H100) 的异步与低精度 | 榨干新硬件特性 |

- **v1（FlashAttention）**：奠基。提出"不物化 n×n、分块 + online softmax、反向重算"三件套。外层循环遍历 K/V 块，每个 Q 块的中间状态要在内层循环间反复读写，**并行度和寄存器利用还不够理想**。

- **v2（FlashAttention-2）**：**数学完全不变，纯工程提速**。三个关键点：
  1. **交换循环顺序**：外层改成遍历 **Q 块**，内层遍历 K/V 块。这样每个 Q 行的 $m,\ell,O$ 状态在内层循环里只活在寄存器/SRAM，减少读写。
  2. **减少非 matmul 运算**：rescale（$O$、$\ell$ 乘修正因子）这类逐元素运算在 GPU 上比 matmul"贵"（Tensor Core 不加速它们）。v2 把"每步都给 $O$ 做除法"推迟到**整行结束才除一次 $\ell$**，省掉大量逐元素运算。
  3. **更好的并行划分**：沿序列长度维度切分并行，让 SM 占用率更满，尤其长序列下并行度更高。
  - 效果：在 A100 上接近 GPU 理论算力利用率的较高比例，比 v1 显著更快。

- **v3（FlashAttention-3）**：**面向 Hopper 架构（H100）的硬件特化**，思路是"让搬数据和算数据重叠起来、并用更低精度"：
  1. **异步流水（warp specialization / TMA）**：用 Hopper 的异步拷贝引擎，让"从 HBM 搬下一块"与"在 SRAM 算当前块"**重叠**，隐藏访存延迟（生产者-消费者）。
  2. **matmul 与 softmax 重叠**：让 Tensor Core 做矩阵乘的同时，另一部分硬件做 softmax 的指数/缩放，不互相空等。
  3. **低精度（FP8）支持**：利用 H100 的 FP8，进一步提升吞吐，并配合处理 FP8 的数值缩放问题。
  - 一句话：v3 把"算法已经最优"的注意力，对准**特定新硬件的异步与低精度能力**再压一层。
  > 具体加速比/支持矩阵以官方论文与实现文档为准。

- **Block-sparse FlashAttention**：在分块框架上天然支持**稀疏/带掩码注意力**——某些 $Q_i$ 与 $K_j$ 块的交互被掩掉（如因果 causal、局部窗口），直接**跳过整块计算**，进一步省时省存。因果掩码下右上三角的块可整块跳过，约省一半计算。

## 9. 数值示例 / 手算：把 online softmax 走一遍

设某个 query 行对应 4 个分数 $S=[3,\;1,\;4,\;2]$，分两块来：块A $=[3,1]$，块B $=[4,2]$。$v$ 取标量方便手算：$v=[10,20,30,40]$。
**目标**：online 算出的结果应等于直接 softmax。

**直接基准**：$\max=4$。$e^{S-4}=[e^{-1},e^{-3},e^{0},e^{-2}]=[0.3679,0.0498,1,0.1353]$，和 $\ell=1.5530$。
权重 $P=[0.2369,0.0321,0.6439,0.0871]$。输出 $O=\sum P\cdot v=0.2369\cdot10+0.0321\cdot20+0.6439\cdot30+0.0871\cdot40=2.369+0.642+19.32+3.485=\mathbf{25.82}$。

**online 过程**：
- 初始：$m=-\infty,\ \ell=0,\ O=0$。
- **块A $[3,1]$**：块内 $m_{blk}=3$，$m^{new}=\max(-\infty,3)=3$。rescale $=e^{-\infty-3}=0$。
  $e^{S-3}=[e^{0},e^{-2}]=[1,0.1353]$，块内和 $=1.1353$。
  $\ell=0\cdot0+1.1353=1.1353$。
  $O=0\cdot0+(1\cdot10+0.1353\cdot20)=10+2.706=12.706$。
- **块B $[4,2]$**：块内 $m_{blk}=4$，$m^{new}=\max(3,4)=4$。rescale $=e^{3-4}=e^{-1}=0.3679$。
  $e^{S-4}=[e^{0},e^{-2}]=[1,0.1353]$，块内和 $=1.1353$。
  $\ell=0.3679\cdot1.1353+1.1353=0.4177+1.1353=1.5530$ ✅（与基准一致）。
  $O=0.3679\cdot12.706+(1\cdot30+0.1353\cdot40)=4.674+(30+5.413)=4.674+35.413=40.087$。
- **收尾归一化**：$O/\ell=40.087/1.5530=\mathbf{25.81}$ ✅（与基准 25.82 一致，尾数差是四舍五入）。

> **看懂了什么**：块A 的旧累加 12.706 在块B 被乘了 rescale 0.3679 修正过来；最后只除了一次 $\ell$。全程没存任何完整分数向量，结果和直接 softmax 相等。这就是 FlashAttention 在做的事，只不过把标量换成向量/矩阵块。

| 是否精确 | ✅ | ✅ | ✅ | ✅(FP8 有量化误差) |
| HBM 访存 | 高 | 低 | 低 | 更低(异步隐藏) |
| 关键技术 | — | tiling+online softmax+重算 | 循环重排+少逐元素+并行 | 异步流水+FP8 |
| 适用 | 短序列/教学 | 长序列训练推理 | A100 等 | Hopper/H100 |

## 常见问题
| 疑问 | 真相 |
|---|---|
| FlashAttention 是近似算法吗？ | 不是。同精度下与标准注意力**逐位等价**，只是计算顺序和存储不同。 |
| 它减少了计算量(FLOPs)吗？ | 几乎没有。FLOPs 仍是 $O(n^2d)$。它减的是**显存占用**和 **HBM 访存次数**。 |
| 那为什么会变快？ | 因为注意力**访存受限**。省 HBM 访存让核心不空等，算力利用率上去，墙钟时间下降。 |
| online softmax 的精髓是？ | 在线维护 running $\max\,m$ 和分母 $\ell$，每来新块用 **rescale 因子 $e^{m^{old}-m^{new}}$** 把旧累加修正到新基准。 |
| 反向传播怎么不爆显存？ | 不存 $P$，只存每行 logsumexp($O(n)$)，反向时**重算** $S,P$ 小块（用算力换显存）。 |
| 为什么块要做得能放进 SRAM？ | SRAM 比 HBM 快约一个数量级。把 n×n 关进 SRAM 即弃，就避免了它在 HBM 的反复往返。 |
| v2 相对 v1 改了数学吗？ | 没有。纯工程：换循环顺序、少做非 matmul 运算、提高并行度。 |
| 推理解码阶段也用它吗？ | 解码 query 只有 1 行，瓶颈变成读 KV；衍生出 Flash-Decoding 按 KV 并行，见下方链接。 |
| 它和 KV cache 什么关系？ | 正交互补。KV cache 省的是重复算 K/V；FlashAttention 省的是算注意力时的显存与访存。 |
