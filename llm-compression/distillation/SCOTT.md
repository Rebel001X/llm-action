# SCOTT (思维链蒸馏)

> 把大模型「会推理」的能力——而不仅仅是「答案对」——蒸馏进一个小几个数量级的学生模型，并强制学生「言行一致」(说出的推理链真的支撑它给出的答案)。📍 导航：[[00-知识地图]]

## 0. 一句话锚点

> **SCOTT = 让大模型先"为正确答案找理由"(对比解码)，再逼小模型"先说理由、且必须按理由作答"(反事实/一致性约束)。**

普通 CoT 蒸馏的毛病：学生学会了"输出一段看起来像推理的话 + 一个答案"，但这两者**互不相干**——答案是背下来的，推理是装饰。SCOTT 同时治两个病：

- **教师病**：大模型生成的理由可能和黄金答案**无关**(unfaithful teacher)。→ 用**对比解码**修。
- **学生病**：小模型可能**无视理由**直接背答案(reasoning shortcut)。→ 用**反事实推理**修。

## 1. 地基 / 前置

### 1.1 三个最原子的概念

**(1) CoT (Chain-of-Thought, 思维链)**：让模型在给出最终答案前，先生成一串中间推理文字(称为 rationale / 论据 / 基本原理)。

```
问题: 仓鼠藏了18颗瓜子, 吃掉1/3, 又藏了6颗, 现在有几颗?
普通输出:  "16"                       ← 只有答案
CoT 输出:  "18的1/3是6, 吃掉后剩12,    ← rationale(理由)
            再加6, 共18颗。答案: 18"    ← answer(答案)
```

**(2) 知识蒸馏 (Knowledge Distillation)**：用一个大模型(教师 T)产生的信息，去训练一个小模型(学生 S)，让小模型逼近大模型能力。这里蒸的不是 logits，而是**教师生成的推理文本**。

**(3) Faithfulness (可信/忠实)**：一段推理是"可信的"，当且仅当**模型的答案确实是由这段推理推出来的**。可信 ≠ 答案对。

```
不可信但答案对:  理由="天空是蓝的"        答案="18" (对)   ← 理由没用, 是装饰
可信:           理由="18×(2/3)=12,+6=18"  答案="18" (对)   ← 答案真的来自理由
```

### 1.2 为什么这是个真问题

```
       ┌────────────────────────────────────────────┐
       │  普通 CoT 蒸馏 (Hard-label / 直接微调)        │
       │                                              │
       │   教师生成: rationale R  +  answer A          │
       │            └ 可能 R 与 A 无关(教师病)         │
       │                  │                           │
       │                  ▼  直接拿去微调              │
       │   学生学到: "见到此题 → 吐 R, 吐 A"           │
       │            └ 学生可能跳过 R 直接背 A(学生病)   │
       └────────────────────────────────────────────┘
   结果: 小模型 CoT "好看不好用", 改 R 不影响 A → 推理是假的
```

SCOTT 的目标：让蒸出来的小模型，**改了理由就会改答案**，证明答案真的依赖理由。

## 2. SCOTT 整体框架(两阶段)

```
╔══════════════════════════════════════════════════════════════╗
║                    SCOTT 两阶段蒸馏框架                          ║
╠══════════════════════════════════════════════════════════════╣
║                                                                ║
║  阶段A: 教师端 —— 引出"支持黄金答案"的可信理由                    ║
║  ┌──────────────────────────────────────────────────────┐    ║
║  │  输入: 问题 Q + 训练集黄金答案 A*                        │    ║
║  │  大型 LM(教师)                                          │    ║
║  │        │ 对比解码 (Contrastive Decoding)               │    ║
║  │        │  = P(token | Q, A*) 相对 P(token | Q) 的提升    │    ║
║  │        ▼                                               │    ║
║  │  理由 R: 只有"考虑了答案 A* 才更可信"的 token 被强化     │    ║
║  └──────────────────────────────────────────────────────┘    ║
║                          │ (Q, R, A*) 三元组                   ║
║                          ▼                                     ║
║  阶段B: 学生端 —— 学会"先说理由, 且必须依理由作答"               ║
║  ┌──────────────────────────────────────────────────────┐    ║
║  │  小型 LM(学生), 两个训练目标:                            │    ║
║  │   ① 事实目标: 给定 Q → 生成 R → 生成 A*  (常规 CoT)      │    ║
║  │   ② 反事实目标: 给定 Q + 一个"会导向不同答案的理由 R'"   │    ║
║  │                 → 必须预测对应的不同答案 A' (≠ A*)       │    ║
║  └──────────────────────────────────────────────────────┘    ║
║                                                                ║
║  产物: 自洽(self-consistent)小 CoT 模型                        ║
╚══════════════════════════════════════════════════════════════╝
```

一句话串起来：**教师负责"理由可信"，学生负责"答案依赖理由"。**

## 3. 教师端：对比解码引出可信理由

### 3.1 问题：直接 prompt 教师，理由可能"跑题"

如果只给教师 `Q`，让它自由生成理由，大模型常常生成"语法通顺但与正确答案不强相关"的理由——因为语言模型默认按"哪个 token 最流畅"解码，而不是按"哪个 token 最支持答案 A*"解码。

### 3.2 对比解码 (Contrastive Decoding) 的机制

核心思想：**同一个 token，在"看到答案"和"没看到答案"两种条件下生成概率的差异，反映了它对答案的支撑度。**

设当前要生成理由的下一个 token $t$，定义打分：

$$
\text{score}(t) = \log P_T(t \mid Q, A^*, R_{<i}) - \lambda \cdot \log P_T(t \mid Q, R_{<i})
$$

- 前项 $\log P_T(t \mid Q, A^*)$：**给了黄金答案** $A^*$ 后，模型想生成 $t$ 的对数概率。
- 后项 $\log P_T(t \mid Q)$：**没给答案**时模型想生成 $t$ 的对数概率。
- $\lambda$：对比强度(超参，常取 ~1)。

**直觉**：如果一个 token 只在"知道答案"时概率才飙升，说明它**专门服务于这个答案**(高支撑度) → 分数高，被选中。如果一个 token 在两种情况下概率都一样高(比如 "the"、"is" 这种通用词，或与答案无关的流畅废话)，相减后趋于 0 → 不被特别强化。

```
对比解码: 强化"只因答案而变可信"的 token
─────────────────────────────────────────────
token        logP(·|Q,A*)   logP(·|Q)   score=差
"18×2/3=12"    -0.5          -3.0        +2.5  ★强化(支持答案)
"天空"         -2.0          -2.1        +0.1  ✗抑制(与答案无关)
"the"          -0.3          -0.3         0.0  ✗中性词
─────────────────────────────────────────────
→ 生成的理由聚焦在"为什么是 A*", 而非泛泛而谈
```

### 3.3 产物

教师对每条训练样本输出三元组 $(Q, R, A^*)$，其中 $R$ 是**对答案高支撑**的理由。这批数据就是学生的"教材"。

## 4. 学生端：反事实推理 + 一致性约束

教师把理由做"可信"了，但学生还可能**无视理由、直接背答案**(因为很多 QA 数据集里答案有捷径偏置：题型→答案的浅层映射)。SCOTT 用**两个目标**逼学生尊重理由。

### 4.1 目标①：事实推理 (Factual / 正向)

标准 CoT 微调：给问题 $Q$，学生先生成理由 $\hat R$，再据此生成答案。

$$
\mathcal{L}_{\text{fact}} = -\log P_S(R \mid Q) \;-\; \log P_S(A^* \mid Q, R)
$$

学生学会"先说理由、再作答"。但仅此还不够——它可能学成"理由是摆设、答案靠记忆"。

### 4.2 目标②：反事实推理 (Counterfactual) —— SCOTT 的灵魂

**做法**：给学生一个**被故意改造过、会导向不同答案**的理由 $R'$，要求学生**必须**预测出那个**不同的答案** $A'$($A' \neq A^*$)。

```
反事实样本构造
────────────────────────────────────────────────
原始(事实):   Q + R(支持"18")        → 必须答 18
反事实:       Q + R'(被改成支持"20")  → 必须答 20  ← 强制!
────────────────────────────────────────────────
若学生只会背"此题答18", 它在反事实样本上会答错
→ 损失变大 → 逼它真正"读"理由再作答
```

$$
\mathcal{L}_{\text{cf}} = -\log P_S(A' \mid Q, R')
$$

**为什么这能保证一致性 (self-consistency)？** 因为如果学生想同时在事实样本(理由→A\*)和反事实样本(理由'→A')上都拿低损失，它**唯一的办法**就是真的把答案当成"理由的函数"。一旦答案随理由变化，"改理由就改答案"成立 → 推理是**可信**的。

$R'$ 的构造：用扰动器(perturber，可由教师或规则生成)把原理由里的关键论断替换/否定，使其逻辑上指向另一个答案，并配上对应的目标答案 $A'$。

### 4.3 一致性约束总览图

```
        学生 S 的两条约束(同时满足才达标)
   ┌───────────────────────────────────────┐
   │  事实:  (Q, R   ) ──► A*   ← 正确答案    │
   │  反事实:(Q, R'  ) ──► A'   ← 改了理由,    │
   │                            答案也得改     │
   └───────────────────────────────────────┘
              ▲                    ▲
              │   两者都要对 ⇒      │
              └── 答案 = f(理由) ───┘
                 ⇒ self-consistent / faithful
```

## 5. 为什么"能把推理能力蒸出来"

很多人疑惑：小模型参数那么少，凭什么学会大模型的推理？拆三层讲清。

### 5.1 推理能力 ≠ 知识量，而是「过程模板」

CoT 的本质是把一个难映射 $Q \to A$ **分解成若干简单的小步**。小模型未必能一步背出答案，但**逐步小算/小推断**它做得到。教师生成的 $R$ 就是把"怎么分步"显式写出来当**监督信号**——这是普通"题→答案"标注里**没有的中间监督**。

```
难: Q ───────────────────► A      (小模型直接跳, 学不会)
易: Q → 步1 → 步2 → 步3 → A      (每步都简单, 小模型可学)
        └────── R 提供了"分步路径"这一额外监督 ──────┘
```

### 5.2 暗知识 (Dark Knowledge) 的文本版

经典蒸馏蒸的是 soft logits(类别间相对关系)。SCOTT 蒸的是**推理路径文本**——它比单个答案携带的信息量大得多：一条理由隐含了"该用哪条规则、按什么顺序、排除了哪些干扰"。学生学的是这套**程序性知识**。

### 5.3 为什么必须配可信约束才"真"学到

如果不加第 3、4 节的两个修正，学生很可能学成"模式匹配题型→答案"，看起来会 CoT 实则没学到推理。SCOTT 的贡献正是：**让蒸出来的推理是可被验证、可被改写、改了就生效的真推理**，而非花架子。论文实验显示：SCOTT 学生在最终任务性能与基线相当的同时，理由的**可信度(faithfulness)显著更高**；且因为答案真的依赖理由，**改进理由就能进一步提升性能**——这是花架子模型做不到的。

## 6. 训练目标与损失全貌

学生的总损失把三块拼起来：

$$
\mathcal{L}_{\text{SCOTT}} \;=\; \underbrace{\mathcal{L}_{\text{rationale}}}_{\text{学会生成理由}} \;+\; \underbrace{\mathcal{L}_{\text{fact}}}_{\text{理由}\to A^*} \;+\; \alpha \cdot \underbrace{\mathcal{L}_{\text{cf}}}_{\text{反事实: 理由}'\to A'}
$$

```
┌─────────────────────────────────────────────────────────┐
│ 数据流水线 (端到端)                                        │
│                                                           │
│  训练集(Q, A*)                                            │
│      │                                                    │
│      ▼  阶段A: 教师 + 对比解码                            │
│  (Q, R, A*)  ← 可信理由                                   │
│      │                                                    │
│      ├──► 事实样本   (Q, R ) → A*                         │
│      │                                                    │
│      └──► 扰动器构造  (Q, R') → A'   ← 反事实样本          │
│                                                           │
│      ▼  阶段B: 微调小学生 S (上面三项损失)                  │
│  自洽小 CoT 模型                                          │
└─────────────────────────────────────────────────────────┘
```

> 备注：论文中还强调蒸馏要**无泄漏(leakage-free)**——理由里不能直接把黄金答案"抄"进去，否则学生会走捷径直接读答案而非推理。对比解码 + 反事实正是为了堵这个捷径。

## 7. 数值例子 / 手算

### 7.1 对比解码挑 token (手算)

题目片段，当前要在理由里选下一个 token，候选三个。$\lambda=1$。

| 候选 token | $\log P(\cdot\mid Q,A^*)$ | $\log P(\cdot\mid Q)$ | score = 差 |
|---|---|---|---|
| `"12颗(18×2/3)"` | $-0.4$ | $-2.9$ | **$+2.5$** ✅选中 |
| `"很多颗"` | $-1.0$ | $-1.2$ | $+0.2$ |
| `"今天天气好"` | $-2.5$ | $-2.4$ | $-0.1$ ❌ |

`"12颗(18×2/3)"` 只有在"知道最终答案"时概率才暴涨 → 高支撑 → 被写进理由。无关的流畅废话被自然排除。

### 7.2 反事实如何"逼出"一致性 (手算直觉)

假设学生有两种策略，看哪种损失更低：

```
策略X(背答案): 不管理由, 此题型一律答 18
  事实样本 (Q,R →18):   答18 ✓  loss低
  反事实   (Q,R'→20):   还答18 ✗  loss高 ←被惩罚!
  ───────────────────────────────────
  总损失 = 低 + 高 = 中高

策略Y(读理由): 答案 = 理由蕴含的结论
  事实样本 (Q,R →18):   读R得18 ✓ loss低
  反事实   (Q,R'→20):   读R'得20 ✓ loss低
  ───────────────────────────────────
  总损失 = 低 + 低 = 最低  ← 梯度推向这里
```

梯度下降会把模型推向**策略Y**，因为只有真读理由才能在两类样本上同时低损失。这就是"一致性约束"在数学上为何成立。

## 8. SCOTT vs DeepSeek-R1 蒸馏 — 全面对照

两者都叫"蒸馏推理"，但范式截然不同。参见 [[llm-algo/deepseek/DeepSeek-R1]]。

```
SCOTT                            R1 蒸馏
─────────────────────────       ─────────────────────────
监督来自: 对比解码挑理由           监督来自: R1 大模型直接生成长CoT
约束: 反事实/一致性损失            约束: 无显式一致性约束(靠数据量)
理由筛选: 看是否"支持答案"          理由筛选: 拒绝采样(只留答对的样本)
目标: 可信/忠实推理(faithful)     目标: 提升小模型最终准确率
规模: 学生常 <1B (T5/小LM时代)    学生: 1.5B~70B (Qwen/Llama)
教师: 通用大 LM(如 GPT-3 级)      教师: 专门RL训出的推理模型 R1
```

### 8.1 三大本质差异

**(1) 谁来保证理由质量**
- SCOTT：用**对比解码**主动构造"高支撑"理由 + **反事实**主动验证。是**机制层面**的保证。
- R1：用**拒绝采样**——大量采样 R1 的 CoT，只保留**最终答案正确**的(约 80 万条 SFT 数据)，靠"答对即留"过滤。是**数据层面**的保证，不检验理由是否真支撑答案。

**(2) 在不在乎"可信度"**
- SCOTT：**核心目标**就是 faithfulness——改理由必须改答案。
- R1 蒸馏：核心目标是**准确率/能力迁移**，不专门约束理由忠实性(R1 的长 CoT 经验上已相当连贯，但无形式化一致性损失)。

**(3) 教师本身怎么来**
- SCOTT：教师是**现成的通用大 LM**，靠 prompt + 对比解码引出理由。
- R1：教师 R1 是先用**大规模强化学习(GRPO)** 专门训出"会深度思考"的模型，再用它的输出做 SFT 蒸馏。推理能力先在教师里"长出来"，再蒸下去。

### 8.2 一句话总结对照

> **SCOTT 解决"小模型的 CoT 是不是真的"(可信性)；R1 蒸馏解决"小模型能不能学会强推理"(能力上限)。** 两者正交，理念上可叠加——用 R1 当教师产长 CoT，再套 SCOTT 的反事实约束保证可信，是有意思的组合方向(论文未做，属延伸思考)。

与 [[llm-compression/distillation/MINILLM]] 的关系：MINILLM 改的是**蒸馏的散度目标**(用反向 KL 让学生别去拟合教师分布的低概率尾巴)，是**分布层面**的蒸馏改进；SCOTT 改的是**蒸什么内容 + 内容的可信约束**，是**推理文本层面**的改进。两条线互补。

## 常见问题 (FAQ)

| 问题 | 回答 |
|------|------|
| 对比解码和"普通让教师生成理由"差在哪？ | 普通解码按"最流畅"选 token；对比解码按"最支持答案"选 token，理由更贴黄金答案。 |
| 反事实样本会不会教学生说错话？ | 不会。反事实样本里"错答案"是**配着错理由**给的，逻辑自洽；它教的是"答案要跟理由走"，而非教错知识。 |
| 不加反事实约束行不行？ | 行但会退化：学生易学成"背题型→答案"，CoT 成摆设(reasoning shortcut)。反事实是堵捷径的关键。 |
| SCOTT 适合多大的学生？ | 论文是小 LM(T5 级，常 <1B)。思想可迁到更大学生，但反事实数据构造成本上升。 |
| 和 R1 蒸馏二选一吗？ | 不冲突。R1 蒸"能力强不强"，SCOTT 蒸"推理真不真"，可组合。 |
| "无泄漏(leakage-free)"指什么？ | 理由里不能直接把黄金答案抄进去，否则学生读答案不推理。对比解码+反事实共同防泄漏。 |
| faithfulness 怎么量化？ | 常用"扰动理由后答案是否随之改变"等指标——改理由不改答案=不可信。 |
| 为什么小模型学得会推理？ | CoT 把难映射拆成易小步(见§5)；理由提供了普通标注没有的**中间过程监督**。 |
