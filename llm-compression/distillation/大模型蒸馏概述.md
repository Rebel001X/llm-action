## 0. 一句话锚点

知识蒸馏（Knowledge Distillation, KD）是一种提升模型性能和泛化能力的机器学习技术。它把知识从**复杂的教师模型（Teacher）**转移到**更简单的学生模型（Student）**。核心思想：**把教师模型的综合知识转化为更精简、更高效的表示**。

在大模型语境下，教师就是 LLM。我们按"是否把 LLM 的**涌现能力（Emergent Ability, EA）**蒸馏进小语言模型（SLM）"把方法分两类：

- **Standard KD（标准蒸馏）**：学生学 LLM 的常见知识，如输出分布、特征信息。
- **EA-based KD（基于涌现能力的蒸馏）**：不止迁移常识，还蒸馏涌现能力（ICL / CoT / IF）。

## 1. 地基：为什么软标签比硬标签强

普通监督学习用**硬标签（one-hot）**：猫=1，狗=0，马=0。这只告诉模型"是猫"，丢掉了"它有多像狗、多不像马"的信息。

教师模型输出的是一整条**概率分布（软标签 soft label）**：猫=0.9，狗=0.09，马=0.01。这条分布里藏着**暗知识（dark knowledge）**——"狗比马更像猫"这种类间关系，正是泛化能力的来源。

```
   硬标签（one-hot）            软标签（教师分布）
   ┌──────────────┐            ┌──────────────┐
   │ 猫  1.0      │            │ 猫  0.90 ←主  │
   │ 狗  0.0      │            │ 狗  0.09 ←暗  │  暗知识 = 类间相似度
   │ 马  0.0      │            │ 马  0.01      │
   └──────────────┘            └──────────────┘
   信息量：1 bit               信息量：整条分布
```

**温度 T（temperature）** 用来"软化"分布。把 logits $z_i$ 除以 $T$ 再做 softmax：

$$ q_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)} $$

- $T=1$：原始 softmax，分布尖锐。
- $T>1$：分布更平滑，暗知识更突出（小概率被放大，更易被学生学到）。

学生用 **KL 散度**去逼近教师的软分布。两个分布 $p$（教师）、$q$（学生）：

$$ D_{KL}(p \| q) = \sum_i p_i \log \frac{p_i}{q_i} $$

> 前置链接：softmax/logits 来自 [[llm-algo/transformer/模型架构]]；蒸馏属于压缩家族，与量化并列见 [[llm-compression/README]]。

## 3. Standard KD：白盒生成式 LLM 的蒸馏

Standard KD 旨在让学生模型学习 LLM 所拥有的**常见知识**（输出分布、特征信息）。这与传统 KD 类似，区别在于**教师模型是 LLM**。代表方法：**MINILLM** 与 **GKD**。

### 3.1 前向 KL 的陷阱与 MINILLM 的反向 KL

经典 KD 最小化**前向 KL** $D_{KL}(p\|q)$（$p$ 教师、$q$ 学生）。在生成式 LLM 上，**MINILLM** 观察到：最小化前向 KL 会逼学生去**覆盖教师分布的所有区域**，包括教师里"不太可能"的低概率区域——结果学生在这些区域**高估概率**，自由生成（free-running）时就会吐出不靠谱的样本。

```
   前向 KL D(p||q)：mean-seeking（覆盖一切）
        p（教师，双峰）
        ╱╲      ╱╲
       ╱  ╲    ╱  ╲
   q 被迫摊平去盖住两峰 → 中间低概率区被高估 → 生成胡话

   反向 KL D(q||p)：mode-seeking（抓主峰）
        p（教师，双峰）
        ╱╲      ╱╲
       ╱  ╲    ╱  ╲
   q 只钻一个峰 → 不高估低概率区 → 生成更可靠
```

**MINILLM 的解法**：改最小化**反向 KL** $D_{KL}(q\|p)$。这能阻止学生高估教师分布中的低概率区域，从而**提升生成样本质量**。详见 [[MINILLM]]。

### 3.2 GKD：自回归模型蒸馏的两个病根

**GKD（Generalized KD）** 探索自回归模型的蒸馏（白盒生成 LLM 是其子集）。它识别出两个关键问题：

1. **分布不匹配（distribution mismatch）**：训练时喂给学生的是**教师/真值的输出序列**，但部署时学生消费的是**自己生成的序列**——训练与推理的输入分布对不上（即经典的 exposure bias）。
2. **模型欠定（under-specification）**：学生容量不足，**没有足够表达力去匹配教师分布**。

**GKD 的解法**：
- 对(1)——训练期间**对学生自己的输出序列采样**（on-policy），让训练分布贴近部署分布。
- 对(2)——优化**替代散度（反向 KL）**来缓解欠定问题。

详见 [[GKD]]。

| 方法 | 病根 | 散度选择 | 关键招式 |
|------|------|----------|----------|
| 经典 KD | — | 前向 KL | 静态软标签 |
| MINILLM | 前向 KL 高估低概率区 | 反向 KL | mode-seeking |
| GKD | 训练/部署分布不匹配 + 欠定 | 反向 KL | 训练时在线采样学生输出 |

## 4. EA-based KD：蒸馏涌现能力

**基于 EA 的 KD** 不仅迁移 LLM 的常识，还包括蒸馏它们的**涌现能力**。

为什么需要单独一类？因为与 BERT（330M）、GPT-2（1.5B）这类较小模型相比，GPT-3（175B）、PaLM（540B）等 LLM 展现出独特行为：在处理复杂任务时表现出**令人惊讶的能力**，称为**涌现能力（Emergent Ability）**。涌现能力包含几个有趣方面：

| 涌现能力 | 英文 | 一句话 |
|----------|------|--------|
| 上下文学习 | In-context Learning (ICL) | 给几个示例，不更新梯度就会做新任务 |
| 思维链 | Chain-of-Thought (CoT) | 把中间推理步骤写进提示，提升推理 |
| 指令遵循 | Instruction Following (IF) | 只读任务描述就能执行新任务 |

```
   规模阈值前        规模阈值后（涌现）
   能力 ▁▁▁▁▁  ──→   能力 ▁▁▁▁▟▛  突然跃升
   (小模型平坦)       (大模型 ICL/CoT/IF 出现)
```

## 5. ICL 蒸馏：迁移上下文小样本学习能力

**ICL** 采用结构化自然语言提示，含任务描述 + 可能的几个任务示例（演示 demonstration）。通过这些示例，LLM 无需显式梯度更新就能掌握并执行新任务。

论文 *In-context Learning Distillation: Transferring Few-shot Learning Ability of Pre-trained Language Models* 引入了 **ICL 蒸馏**：把上下文小样本学习 + 语言建模能力从 LLM 转移到 SLM。做法是**把上下文学习目标与传统语言建模目标相结合**。

两种小样本学习范式：

| 范式 | 训练方式 | 适配新任务 | 性能 | 代价 |
|------|----------|-----------|------|------|
| **Meta-ICT** | 用 ICL 目标在不同任务上**元训练** | 靠上下文学习适配**未见任务** | 较低 | 较省算力 |
| **Multitask-ICT** | 用 ICL 目标 + target 任务的若干示例**微调** | 微调后再 ICL 预测 | **更优** | 任务适配需更多算力 |

结论：Multitask-ICT 性能优于 Meta-ICT，但在任务适配过程中需要更多计算资源（计算更密集）。

## 6. CoT 蒸馏：迁移思维链推理能力

与 ICL 不同，**CoT** 把**中间推理步骤**（能导向最终输出）合并进提示，而非只用简单的输入-输出对。一批代表性方法：

| 方法 | 提出者 | 核心做法 |
|------|--------|----------|
| **MT-CoT** | Li et al., 2022 | 用 LLM 产生的解释加强小型推理机；多任务学习框架，让小模型兼具强推理 + 生成解释能力 |
| **Fine-tune-CoT** | Ho et al., 2023 | 从 LLM **随机采样生成多个推理解**，数据增强助力学生学习 |
| **Fu 等人** | — | 发现语言模型多维能力间的**权衡**；从大教师提取 CoT 推理路径，提升**分布外（OOD）泛化** |
| **Hsieh 等人** | — | 把 LLM rationale（原理）作为**额外指导**，在多任务框架内训小模型 |
| **SOCRATIC CoT** | Shridhar et al., 2023 | 训**两个**蒸馏模型：问题分解器 + 子问题求解器 |
| **DISCO** | Chen et al., 2023 | 基于 LLM 的**全自动反事实知识蒸馏**：工程化提示让 LLM 生成短语扰动 |
| **SCOTT** | Wang et al., 2023a | **对比解码**把每个 rationale 与答案绑定，引导学生反事实推理 |

要点展开：

- **SOCRATIC CoT**：分解器把原始问题拆成一系列子问题，子问题求解器负责解决它们——分而治之。
- **DISCO**：先用工程化提示让 LLM 生成短语扰动，再用**特定任务的教师模型过滤**这些扰动，提取**高质量反事实数据**。
- **SCOTT**：为保证 rationale 的准确性，采用对比解码把每个 rationale 与答案联系起来，鼓励老师给出**相关**理由；同时引导学生做反事实推理，根据"导致不同答案"的理由来预测。详见 [[SCOTT]]。

```
   SOCRATIC CoT 流水线
   原始问题 ──分解器──▶ [子问题1, 子问题2, 子问题3]
                         │       │       │
                      求解器  求解器  求解器
                         └───────┴───────┘──▶ 最终答案
```

## 7. IF 蒸馏：迁移指令遵循能力

**IF** 致力于**仅基于阅读任务描述**就能执行新任务，而不依赖少数样本。用一系列以指令表示的任务做微调后，模型就能准确执行**以前未见过的指令**所描述的任务。

例如 **Lion**（Jiang et al., 2023）利用 LLM 的适应性提升学生表现：**提示 LLM 识别并生成"hard"指令**，再用这些 hard 指令增强学生能力。本质是利用 LLM"用途广泛"的特性来指导学生学习，去应对复杂指令和任务。

```
   Lion 的对抗式循环（adversarial）
   ┌──────────────────────────────────────┐
   │  学生答错的题  ──▶  LLM 生成更难指令   │
   │       ▲                    │          │
   │       └──── 学生再训练 ◀────┘          │
   └──────────────────────────────────────┘
   越训越难 → 持续逼出学生短板
```

## 8. 数值手算：温度怎么软化分布（自洽示例）

设教师对 3 个类的 logits 为 $z = [4, 1, 0]$。

**$T=1$（原始）**：$\exp = [54.6, 2.72, 1.0]$，和 $=58.3$
$$ q = [0.937,\ 0.047,\ 0.017] $$
分布尖锐——几乎只看到"类别1"。

**$T=4$（软化）**：$z/T = [1, 0.25, 0]$，$\exp = [2.72, 1.28, 1.0]$，和 $=5.0$
$$ q = [0.544,\ 0.256,\ 0.200] $$

软化后第 2、3 类的概率从 0.047/0.017 抬到 0.256/0.200——**暗知识被放大**，学生能学到"类2 比类3 更接近类1"。这正是高温蒸馏比直接学硬标签更有效的直觉。

> 注意：蒸馏损失里软标签那一项常乘 $T^2$ 做梯度尺度补偿（因为 softmax 对 $z/T$ 求导会引入 $1/T^2$ 因子）。

## 实操：损失函数编排（把原理落到训练代码的形状）

蒸馏的训练目标通常是**两项的加权和**：学生既要拟合教师软分布（蒸馏项），又要拟合真值硬标签（监督项）。

$$ \mathcal{L} = \alpha \cdot \underbrace{T^2 \, D_{KL}(p_T \| q_T)}_{\text{蒸馏项(软标签)}} + (1-\alpha)\cdot \underbrace{\text{CE}(y, q_{T=1})}_{\text{监督项(硬标签)}} $$

- $p_T, q_T$：温度 $T$ 下教师、学生的软分布。
- $\alpha$：蒸馏项权重，常取 0.5～0.9。
- **Standard KD（MINILLM/GKD）的关键替换**：把前向 KL $D_{KL}(p\|q)$ 换成**反向 KL** $D_{KL}(q\|p)$，并（GKD）在训练时**采样学生自己的输出序列**。

伪代码骨架（说明散度方向与采样位置，非可运行命令，避免编造接口）：

```python
# 教师固定不更新（eval），学生训练
teacher.eval(); student.train()

# GKD 关键：on-policy 采样学生输出，缓解训练/部署分布不匹配
y_hat = student.generate(x)          # 学生自己生成序列
with torch.no_grad():
    p = teacher.log_prob(y_hat)      # 教师在"学生序列"上的分布
q = student.log_prob(y_hat)

# MINILLM 关键：反向 KL  D(q || p)，mode-seeking，避免高估低概率区
loss_kd = reverse_kl(q, p)           # = sum q*(log q - log p)
loss_sft = cross_entropy(y_true, student(x))
loss = alpha * loss_kd + (1 - alpha) * loss_sft
loss.backward()
```

> 不同方法的差异主要落在三处：**散度方向**（前向/反向 KL）、**喂给学生的序列从哪来**（真值 vs 学生自采样）、**学的是分布还是涌现能力**（Standard vs EA）。

## 常见问题/坑

| 现象 | 根因 | 对策 |
|------|------|------|
| 学生自由生成时吐胡话 | 前向 KL 逼学生覆盖教师低概率区并高估它 | 改用反向 KL（MINILLM）做 mode-seeking |
| 训练好但部署掉点 | 训练喂真值序列、部署喂学生自生成序列，分布不匹配 | 训练期 on-policy 采样学生输出（GKD） |
| 学生学不动教师 | 容量鸿沟太大（如 540B→1B），模型欠定 | 选合适学生规模 / 用反向 KL / 加中间层特征蒸馏 |
| 高温没效果 | 软标签项忘乘 $T^2$，梯度被 $1/T^2$ 缩没了 | 蒸馏项乘 $T^2$ 做尺度补偿 |
| 反事实/推理数据噪声大 | 直接用 LLM 生成的 rationale 不可靠 | 用任务教师过滤（DISCO）/ 对比解码绑定答案（SCOTT） |
| 涌现能力没迁移过去 | 只做了 Standard KD（学分布） | 用 EA-based KD：ICL/CoT/IF 专门蒸涌现能力 |
| Multitask-ICT 训练太贵 | 任务适配阶段算力密集 | 资源紧时退回 Meta-ICT，牺牲一点性能换省算力 |
