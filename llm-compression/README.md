## 0. 一句话锚点

**模型压缩 = 在"精度损失可接受"的预算内，减少模型的存储、计算和访存开销。** 四条主线：
- **量化**：让每个数占的比特更少（精度维度）。
- **剪枝**：让数的个数更少（稀疏维度）。
- **蒸馏**：让模型的结构本身更小（容量维度）。
- **低秩**：让矩阵的"信息维度"更少（秩维度）。

记住一句话：**它们压的是不同的轴，所以可以叠加。**

## 1. 地基/前置（它解决什么问题）

### 1.1 大模型到底"重"在哪

一个 Transformer 大模型，开销主要来自三处。先把单位讲清楚，后面才不会糊涂：

- **参数（Weights）**：模型学到的数，决定**模型文件大小**和**显存占用**。7B 模型 = 70 亿个参数。
- **激活（Activations）**：前向时每层的中间结果，决定**运行时显存**。
- **KV Cache**：自回归生成时缓存的历史 Key/Value，序列越长越大，长上下文时是显存大头。

显存占用的最朴素公式（仅推理、仅权重）：

$$
\text{显存(字节)} \approx \text{参数量} \times \text{每参数字节数}
$$

7B 模型，FP16（每参数 2 字节）：$7\times10^9 \times 2 = 14\text{ GB}$。一张 16GB 显卡刚好卡死，根本留不出激活和 KV Cache 的空间——**这就是要压缩的直接动机。**

### 1.2 为什么"能"压（压缩的物理前提）

```
            为什么大模型可以被压缩？
            ┌───────────────────────────────────────┐
            │ 1. 冗余：参数高度过参数化(over-param)  │  → 剪枝/低秩
            │ 2. 容差：权重对小扰动不敏感           │  → 量化
            │ 3. 平滑：输出分布含"暗知识"可迁移      │  → 蒸馏
            │ 4. 低秩：权重矩阵奇异值衰减很快        │  → 低秩分解
            └───────────────────────────────────────┘
```

四条路线各自利用了上面一条"先天冗余"。这是理解全篇的总钥匙：**压缩不是无中生有，而是把本来就没用满的部分挤掉。**

### 1.3 四条路线的"压缩轴"对比

```
          一个权重矩阵 W (假设 4x4，值是 FP16)
          ┌────────────────────────────┐
   原始    │ 16个数 × 16 bit = 256 bit  │
          └────────────────────────────┘
            │         │        │        │
     量化   ▼         │        │        │   每个数 16→4 bit
          16个数×4bit=64 bit   │        │   轴：比特数
            │         ▼        │        │
     剪枝   │      8个数(一半置零)        │   数的个数 16→8
            │      ×16bit=128 bit        │   轴：稀疏度
            │         │        ▼        │
     低秩   │         │   W=A·B, 4x2·2x4 │   16→16个但秩低
            │         │   16数×16bit     │   轴：秩
            │         │        │        ▼
     蒸馏   │         │        │   换更小的模型 2x2
            │         │        │   整体容量↓     轴：容量
```

## 2. 量化（Quantization）：把每个数用更少的比特表示

### 2.1 原理：从底层讲清"映射"

浮点数 FP16 能表示很大范围、很高精度，但占 16 比特。量化的核心思想：**在一个张量内，数的取值范围其实有限，可以用一个"缩放因子" $s$ 把浮点区间线性映射到低比特整数区间。**

最常见的对称均匀量化（INT8 为例）：

$$
q = \text{round}\left(\frac{x}{s}\right), \quad s = \frac{\max(|x|)}{2^{b-1}-1}, \quad \hat{x} = q \times s
$$

- $x$：原始浮点权重
- $s$：缩放因子（scale），决定"一格"代表多大
- $q$：量化后的整数（INT8 范围 $[-127,127]$）
- $\hat{x}$：反量化回来的近似值，$\hat{x}\neq x$ 的差就是**量化误差**

```
   浮点轴 (FP16)          INT8 整数轴
   -3.7 ────────┐
                │  ÷s, round
   -1.2 ──────┐ │ ───────────►  -42   -127 ┐
    0.0 ────┐ │ │ ───────────►    0       0 │ 256个格子
    2.4 ──┐ │ │ │ ───────────►   83     127 ┘
    3.7 ─┘ │ │ │
           连续无限         离散256级
```

### 2.2 关键拆解：误差从哪来、怎么压住

1. **量化粒度（granularity）**：per-tensor（整个张量一个 $s$）误差大但省；per-channel / per-group（每列/每 128 个一个 $s$）误差小、是当前主流。
2. **异常值（outlier）问题**：LLM 激活里有少数极大值，会把 $\max(|x|)$ 撑大，导致大多数正常值挤在很少几格里。`LLM.int8()`、`SmoothQuant` 都在专门治这个。
3. **PTQ vs QAT**：
   - **PTQ（训练后量化）**：拿现成模型直接量化，可能配少量校准数据。快、便宜，是 LLM 主流。代表：GPTQ、AWQ。
   - **QAT（量化感知训练）**：训练时就模拟量化误差，让模型学会适应。精度高但要重训，代表：LLM-QAT。

```
  PTQ：  预训练模型 ──[校准数据]──► 量化模型   (小时级)
  QAT：  预训练模型 ──[带伪量化的再训练]──► 量化模型 (天级，精度更高)
```

### 2.3 命名约定：W4A16 是什么意思

`W{x}A{y}` = 权重 $x$ 比特、激活 $y$ 比特。常见：
- **W8A8**：权重激活都 INT8，吃 INT8 算力，计算也加速（SmoothQuant）。
- **W4A16**：权重 INT4、激活 FP16，主要省显存+省访存，是单卡跑大模型最常用（GPTQ/AWQ）。

适用：**几乎所有部署场景的第一选择**，性价比最高。深入见 [[llm-compression/quantization/量化基础]]。

## 3. 剪枝（Pruning）：把不重要的连接删掉

### 3.1 原理

过参数化意味着很多权重接近 0，删掉对输出影响很小。剪枝就是**按某种重要性度量把一部分权重永久置零**。最朴素的重要性 = 权重绝对值 $|w|$（幅度剪枝）。

### 3.2 关键区分：非结构化 vs 结构化（决定能不能真加速）

```
  非结构化剪枝(unstructured)        结构化剪枝(structured)
  ┌─────────────┐                  ┌─────────────┐
  │ 1 0 3 0 │ 散点置零            │ 1 2 3 4 │
  │ 0 5 0 7 │ 矩阵仍是稠密形状    │ 0 0 0 0 │ 整行/整列/整头删
  │ 8 0 0 2 │ 通用GPU无法加速     │ 8 9 1 2 │
  │ 0 4 6 0 │ (除非2:4半结构化)   │ 0 0 0 0 │ 矩阵真的变小→真加速
  └─────────────┘                  └─────────────┘
```

- **非结构化**：精度高、压缩率高，但稀疏分布零散，普通 GPU 的稠密矩阵乘法吃不到加速。需要专门稀疏 kernel 才有收益。
- **2:4 半结构化**：每 4 个里固定 2 个为 0。NVIDIA Ampere+ 的 Sparse Tensor Core 原生支持，理论 2× 加速，是工程上"既稀疏又能加速"的折中。
- **结构化**：删整行/整列/整个注意力头/整层。形状直接变小，任何硬件都加速，但精度损失最大，常需微调恢复。

适用：**对延迟敏感、且能承受一轮恢复微调**的场景。LLM 上单独大幅剪枝较激进，常与量化组合。详见 [[llm-compression/sparsity/README]]。

## 4. 蒸馏（Distillation）：让小模型模仿大模型

### 4.1 原理：软标签里的"暗知识"

硬标签只告诉你"这是猫"。但大模型（教师）输出的**软分布**告诉你"90% 猫、8% 狗、2% 老虎"——这些相对概率隐含了类别间的相似结构，叫**暗知识（dark knowledge）**。蒸馏让小模型（学生）去拟合这个分布，比只学硬标签学到更多。

经典 KD 损失（Hinton）：

$$
\mathcal{L} = \alpha\, T^2\, \text{KL}(p_T^\tau \,\|\, p_S^\tau) + (1-\alpha)\, \text{CE}(y, p_S)
$$

- $p^\tau = \text{softmax}(z/T)$，温度 $T>1$ 把分布"摊平"，放大小概率项里的信息
- 第一项学教师的软分布，第二项仍学真实标签

```
   硬标签:  [0, 0, 1, 0]          (只有答案)
   软标签:  [.02, .08, .90, .00]  (含"猫像狗不像鸟"的结构)
            ↑教师给出，温度T摊平后学生更易学
   学生 ── 拟合软标签 ──► 用更小容量逼近教师行为
```

### 4.2 LLM 蒸馏的特殊性

LLM 是生成式的，传统"对齐每个 token 分布"的前向 KL 会让学生**试图覆盖教师的所有模式**，对小学生不现实。`MiniLLM` 改用**反向 KL**，让学生聚焦教师的主模式、避免在低概率区域瞎编——这是 LLM 蒸馏的关键改进，详见 [[llm-compression/distillation/MINILLM]]。另有黑盒蒸馏：直接用大模型生成的数据微调小模型（如各种 self-instruct 数据集）。

适用：**有强教师、且想得到一个原生就小的模型**（不只是压缩既有模型）。代价是要训练。

## 5. 低秩分解（Low-Rank）：把大矩阵拆成两个小矩阵

### 5.1 原理

权重矩阵 $W\in\mathbb{R}^{d\times d}$ 的奇异值往往衰减很快——意味着它"有效秩"远小于 $d$。用 SVD 取前 $r$ 个奇异值，把 $W\approx A B$，其中 $A\in\mathbb{R}^{d\times r}$、$B\in\mathbb{R}^{r\times d}$：

$$
\text{参数量}: d^2 \;\longrightarrow\; 2dr \quad(\text{当 } r \ll d \text{ 时大幅减少})
$$

```
       W (d×d)                A (d×r)   B (r×d)
   ┌───────────┐          ┌───┐   ┌───────────┐
   │           │    ≈     │   │ × │           │
   │  d² 个数  │          │d×r│   │   r×d     │
   │           │          │   │   └───────────┘
   └───────────┘          └───┘
   例 d=4096,r=64: 1677万 → 2×4096×64=52万，省97%
```

### 5.2 两个角色：压缩 vs 微调

- **作为压缩**：直接分解已有权重，减少参数与计算，但激进时掉点，常需微调恢复。
- **作为高效微调（LoRA）**：冻结原 $W$，只训练旁路低秩 $AB$，$W' = W + AB$。这其实是低秩思想最成功的落地——不是压模型，而是**压"微调增量"**。

适用：FFN/注意力投影等大方阵层；与量化结合即 **QLoRA**（量化基座 + 低秩微调）。

## 6. 推理加速到底从哪来

很多人以为"模型小了自然就快了"，但加速来源必须分清，否则会选错方案。LLM 自回归生成的**解码阶段是访存瓶颈（memory-bound）**，不是算力瓶颈。

```
         三条加速路径                            谁受益
   ┌──────────────────────────────┐
   │ ① 访存↓: 权重比特数变少        │  量化(W4) ★解码阶段最爽
   │   每步从显存搬的字节数↓         │  低秩(参数↓)
   ├──────────────────────────────┤
   │ ② 算力↓: 用低比特/稀疏算子     │  W8A8量化、2:4稀疏
   │   Tensor Core 吞吐翻倍         │  ★预填充/大batch受益
   ├──────────────────────────────┤
   │ ③ 参数量↓: 干脆算得更少        │  剪枝(结构化)、蒸馏
   │   FLOPs 直接下降               │  ★全程受益
   └──────────────────────────────┘
```

**关键洞察**：单请求解码时，瓶颈是"把 14GB 权重从显存搬进计算单元"。W4 量化让搬运量降到 1/4，**即使计算还是 FP16，也能近似 4× 加速**——这就是 W4A16 在单卡部署如此流行的根因。而 W8A8 的额外好处是计算也用 INT8 Tensor Core，在大 batch / 预填充阶段进一步省算力。

## 7. 组合策略：叠 buff 的正确姿势

四条路线压的是不同轴，**可以组合**，但有顺序和坑：

```
   推荐组合管线（从训练侧到部署侧）
   ┌────────┐   ┌────────┐   ┌────────┐   ┌────────┐
   │ 蒸馏   │──►│ 剪枝   │──►│ 低秩   │──►│ 量化   │
   │得小模型│   │去冗余  │   │压增量  │   │降比特  │
   └────────┘   └────────┘   └────────┘   └────────┘
      训练期       训练期        微调期       部署期(最后做)
```

经典组合：
- **量化 + 蒸馏**：先蒸馏得小模型，再量化部署（白盒大模型→小模型→W4 上线）。
- **剪枝 + 微调 + 量化**：结构化剪枝后用蒸馏/微调恢复精度，最后量化。
- **量化 + 低秩 = QLoRA**：4-bit 量化基座 + LoRA 微调，单卡微调大模型的事实标准。

**坑**：量化通常**放最后**（它对权重数值最敏感，先量化再剪枝/微调会让误差互相放大）；剪枝和量化叠加时误差会叠加，需要逐步、带恢复地做。工程经验见 [[llm-compression/经验]]。

## 数值例子：手算一遍才有体感

**场景**：把一个 7B 模型（70 亿参数）部署到一张 16GB 显卡，跑长上下文推理。

**Step 1 — 原始 FP16 占用**

$$
7\times10^9 \times 2\text{ B} = 14\text{ GB（仅权重）}
$$

加上激活 + KV Cache，16GB 卡直接 OOM。

**Step 2 — W4A16 量化（权重 INT4）**

$$
7\times10^9 \times 0.5\text{ B} = 3.5\text{ GB}
$$

权重显存降到 1/4，省出约 10.5GB 给 KV Cache 和激活——**直接从"跑不起来"变成"轻松跑"。**

**Step 3 — 解码加速估算**

解码 1 个 token，FP16 要搬 14GB 权重，W4 只搬 3.5GB。在访存瓶颈下：

$$
\text{加速比} \approx \frac{14}{3.5} = 4\times \;(\text{理想上限，实际约 } 2\text{–}3\times)
$$

**Step 4 — 精度代价**

| 方案 | 权重显存 | 典型精度损失（困惑度/任务点） |
| --- | --- | --- |
| FP16 | 14 GB | 基准 |
| W8A8 (SmoothQuant) | 7 GB | ≈ 无损 |
| W4A16 (GPTQ/AWQ) | 3.5 GB | 极小（<1%，good-quant 下） |
| W3 及以下 | 2.6 GB | 开始明显掉点，需更精细方案 |

**结论**：W4A16 是显存/精度的甜点区。再激进就要靠组合策略（蒸馏出更小模型）而非继续压比特。

## 对照表：四条路线横评

| 维度 | 量化 | 剪枝 | 蒸馏 | 低秩 |
| --- | --- | --- | --- | --- |
| 压缩的轴 | 比特数 | 参数个数 | 模型容量 | 矩阵秩 |
| 典型压缩率 | 2–4× | 2–10×(结构化掉点) | 看学生大小 | 2–10× |
| 是否需训练 | PTQ不用/QAT要 | 常需恢复微调 | **必须训练** | 压缩需微调 |
| 推理加速来源 | 访存(+算力W8A8) | FLOPs(结构化才真省) | FLOPs | FLOPs+访存 |
| 通用GPU能加速 | ✅ | 仅结构化/2:4 | ✅ | ✅ |
| 精度风险 | 低(W4)→高(W2) | 中→高 | 中(看蒸馏质量) | 中 |
| LLM 落地成熟度 | ★★★★★ | ★★ | ★★★ | ★★★★(LoRA) |
| 代表方法 | GPTQ/AWQ/SmoothQuant | Wanda/SparseGPT/2:4 | MiniLLM/GKD | LoRA/QLoRA |

## 8. 选型决策树

```
  你的核心瓶颈是什么？
  │
  ├─ 显存装不下 / 想单卡跑大模型
  │     └─► 量化 W4A16 (GPTQ/AWQ)  ← 首选，性价比最高
  │
  ├─ 延迟要再低、且有 Ampere+ 硬件
  │     └─► W8A8 量化 + 2:4 结构化稀疏
  │
  ├─ 想要一个"原生就小"的模型上线
  │     └─► 蒸馏 (MiniLLM/黑盒数据蒸馏) → 再量化部署
  │
  ├─ 显存有限但还要微调
  │     └─► QLoRA (4-bit 量化基座 + LoRA 低秩微调)
  │
  └─ 追求极致小、能承受多轮恢复训练
        └─► 蒸馏 + 结构化剪枝 + 量化  组合管线
```

**经验法则**：
1. **先量化**——投入最小、收益最大、风险最低，90% 的部署需求 W4A16 就够了。
2. **不够再组合**——量化到 W4 还装不下/还不够快，才考虑蒸馏出更小模型或上结构化稀疏。
3. **量化永远放最后一步**做，前面的训练性操作（蒸馏/剪枝/微调）先做完。
4. **永远拿真实评测把关精度**，不要只看困惑度，下游任务点数才是命根子。
