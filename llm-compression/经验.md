## 0. 一句话锚点

**模型压缩 = 用更少的比特数 / 更少的参数 / 更少的计算，逼近原模型的输出分布。** 三条主线：
- **量化（Quantization）**：降比特，FP16 → INT8/INT4，改"每个数占几位"。**首选、性价比最高**。
- **蒸馏（Distillation）**：大模型当老师，训小模型当学生，改"模型有多大"。**最费力、上限最高**。
- **剪枝（Pruning）**：删掉不重要的权重/结构，改"有多少非零参数"。**对 LLM 收益最不稳定**。

```
原始 FP16 模型
   │
   ├── 量化  ──► 比特↓  (16→8→4)   显存↓↓  速度↑   精度略↓   改动小
   ├── 蒸馏  ──► 参数↓  (70B→7B)   全方位↓↓↓        精度看数据 改动大(要训练)
   └── 剪枝  ──► 非零↓  (稠密→稀疏) 显存↓  速度看硬件 精度易塌   LLM上慎用
```

## 1. 地基：先把"为什么要压、能压多少"算清楚

### 1.1 显存账（推理时显存花在哪）

一个 N 参数、dtype 为 b 字节的模型，**权重显存** $= N \times b$。

逐数算一遍（Llama-7B，N≈6.7e9）：

| 精度 | 每参字节 b | 权重显存 | 相对 FP16 |
|---|---|---|---|
| FP32 | 4 | 6.7e9×4 ≈ 26.8 GB | 200% |
| FP16/BF16 | 2 | 6.7e9×2 ≈ 13.4 GB | 100% |
| INT8 | 1 | 6.7e9×1 ≈ 6.7 GB | 50% |
| INT4 | 0.5 | 6.7e9×0.5 ≈ 3.35 GB | 25% |

> 注意：这只是**权重**。推理时还要加 **KV Cache**，长上下文场景 KV 往往比权重还大（见 §6）。

**KV Cache 显存**（关键，常被忽略）：
$$\text{KV} = 2 \times L \times n_{kv} \times d_{head} \times S \times B \times b$$
其中 2=K和V，L=层数，$n_{kv}$=KV头数，$d_{head}$=每头维度，S=序列长，B=batch，b=字节数。

Llama-7B 例（L=32, $n_{kv}$=32, $d_{head}$=128, FP16 b=2），S=4096, B=1：
$$2\times32\times32\times128\times4096\times1\times2 = 2{,}147{,}483{,}648 \text{ B} \approx 2\,\text{GB}$$
S 拉到 32768、B=8 时 → **约 128 GB**，远超权重。这就是为什么长上下文一定要做 KV 量化。

### 1.2 精度-速度-成本三角

```
        精度(质量)
          /\
         /  \
        /    \   你只能挑两个角，第三个要妥协
       /______\
   速度        成本(显存/钱)
```
- 量化：牺牲一点精度，换速度+成本，三角里最划算的"折中点"。
- 蒸馏：通过训练把精度"买"回来，但花了大量训练成本。

### 1.3 为什么能压（压缩的物理基础）

1. **权重冗余**：神经网络过参数化，多数权重接近 0 或彼此相关。
2. **激活分布集中**：大部分激活值挤在一个小区间，少数 outlier 拉宽范围（量化的核心矛盾，见 §3、§5）。
3. **任务对精度不敏感**：下游任务的 logits argmax 对低位扰动有容忍度。

## 2. 量化 / 蒸馏 / 剪枝选型（决策树）

### 2.1 一张图决定先做什么

```
                  我要压缩一个 LLM
                         │
          ┌──────────────┴───────────────┐
       能否重训/微调?                    不能(只有权重)
          │                                │
   ┌──────┴──────┐                  ┌──────┴───────┐
 有大量数据+算力    数据少          显存是瓶颈      速度是瓶颈
    │                │                │              │
  蒸馏到小模型    量化(PTQ)      W4A16量化      W8A8量化
 +量化(叠加)     (GPTQ/AWQ)    (AWQ/GPTQ)    (SmoothQuant)
    │
  上限最高但最贵
```

### 2.2 优先级口诀

**"先量化，再蒸馏，剪枝最后且很可能不做"**：

| 技术 | 何时首选 | 何时别用 | 典型工具 |
|---|---|---|---|
| **PTQ 量化** | 没有训练资源、要快速上线 | 模型已经很小(<1B)、精度极敏感 | GPTQ, AWQ, SmoothQuant |
| **QAT 量化** | 有训练资源、PTQ 掉点超阈值 | 没数据/没算力 | LLM-QAT |
| **蒸馏** | 要从 70B 降到 7B 级别、长期服务 | 一次性任务、没标注/没教师 | response/feature 蒸馏 |
| **结构化剪枝** | 硬件不支持稀疏加速但要减层 | 想靠它大幅压缩(LLM上易塌) | 层剪枝/宽度剪枝 |
| **非结构化稀疏** | 有 2:4 稀疏硬件(A100/H100) | 无稀疏硬件(只省显存不提速) | SparseGPT, Wanda |

> **为什么剪枝对 LLM 最不稳**：LLM 的注意力头/FFN 维度耦合度高，删任一结构都会让残差流分布漂移；且无重训时误差无法被吸收。非结构化稀疏即便达到 50% 稀疏度，没有 2:4 稀疏 Tensor Core 也**只省显存、不提速**（稀疏矩阵乘在稠密硬件上反而慢）。

## 3. 量化深挖：从最底层讲清

### 3.1 量化到底在做什么（per-tensor 对称量化）

把一组浮点 $x$ 映射到整数 $q$。**对称量化**：
$$\text{scale } s = \frac{\max(|x|)}{2^{b-1}-1}, \qquad q = \text{round}\!\left(\frac{x}{s}\right), \qquad \hat{x}=q\cdot s$$

**逐数手算**（INT8，b=8，整数范围 [-127,127]）：
设权重向量 $x=[0.1, -0.5, 2.3, -3.0, 0.02]$。
- $\max|x| = 3.0$
- $s = 3.0 / 127 = 0.02362$
- 量化：$q = \text{round}(x/s) = [4, -21, 97, -127, 1]$
- 反量化：$\hat x = q\cdot s = [0.0945, -0.496, 2.291, -3.0, 0.0236]$
- 量化误差：$x-\hat x = [0.0055, -0.004, 0.009, 0, -0.0036]$ → 误差被 outlier(-3.0) 的大 scale 拉到极小数 0.02 上时最伤（0.02→0.0236，相对误差 18%）。

```
浮点值 x:  -3.0 ........ -0.5 .. 0.1 0.02 ......... 2.3
            │            │     │   │              │
量化格点 q: -127 ...... -21 .. 4   1 ........... 97   (8bit=256格)
            └──── outlier 把 scale 撑大，小值挤进同一格 ────┘
```
**核心矛盾**：一个 outlier（-3.0）撑大 scale，导致所有小值的量化分辨率变差。这是 §5 精度回退的头号原因。

### 3.2 非对称量化（带 zero-point）

激活常是非负或偏斜分布，用非对称：
$$s = \frac{\max(x)-\min(x)}{2^b-1}, \quad z = \text{round}\!\left(-\frac{\min(x)}{s}\right), \quad q=\text{round}(x/s)+z$$
zero-point $z$ 让 0 能被精确表示，对 ReLU/GeLU 后的激活更友好。

### 3.3 粒度：per-tensor / per-channel / per-group

```
per-tensor    [整个权重矩阵共用 1 个 scale]   省内存,精度最差
per-channel   [每个输出通道 1 个 scale]       常用于权重
per-group     [每128个元素 1 个 scale]        W4 标配(group_size=128)
```
group_size 越小越准、metadata 越多。INT4 常用 group=128，额外存储开销：每 128 个 4bit 数(64B)配一个 FP16 scale(2B) → **+3.1%** 存储，换来精度大幅回升。

### 3.4 命名约定 WxAy 与场景对应

| 方案 | 权重 | 激活 | 瓶颈解 | 代表 |
|---|---|---|---|---|
| W8A16 | INT8 | FP16 | 省显存,几乎不掉点 | 简单 PTQ |
| W4A16 | INT4 | FP16 | **显存型**,单卡跑大模型 | [[llm-compression/quantization/GPTQ\|GPTQ]], AWQ |
| W8A8 | INT8 | INT8 | **吞吐型**,Tensor Core 整数加速 | [[llm-compression/quantization/SmoothQuant\|SmoothQuant]] |
| W4A8 | INT4 | INT8 | 两者兼顾,较新 | [[llm-compression/quantization/QQQ-W4A8\|QQQ]] |
| FP8 | E4M3 | E5M2 | H100 原生,训练+推理 | [[llm-compression/quantization/fp8\|FP8]] |

> 经验：**单 batch / 显存受限 → W4A16**（瓶颈是搬权重，激活算得快无所谓）；**大 batch / 吞吐受限 → W8A8**（瓶颈是计算，让 INT8 Tensor Core 干活）。

## 4. 校准数据：PTQ 成败的隐形开关

PTQ 不训练，但需要喂少量样本"看一眼激活分布"来定 scale / 修正权重（GPTQ 的 Hessian、AWQ 的激活幅度、SmoothQuant 的迁移因子都靠它）。

### 4.1 选什么数据

| 维度 | 推荐 | 反面教材 |
|---|---|---|
| 分布 | 贴近**真实推理流量**（同领域、同语言） | 纯英文校准、却服务中文 |
| 多样性 | 覆盖代码/对话/长文等多场景 | 全是同一模板的短句 |
| 长度 | 含长样本(≥2048 token)以激发 outlier | 全是 32 token 短句 |
| 来源 | C4/Pile/WikiText 通用 + 自有业务数据混合 | 只用训练集导致过拟合校准 |

### 4.2 多少条够

- 经验区间：**128 ~ 512 条**，每条 2048 token 左右。
- 太少（<32）：scale 估计方差大，outlier 漏采 → 部分层量化范围错。
- 太多（>1024）：边际收益递减，GPTQ Hessian 计算变慢。
- **手算直觉**：128 条 × 2048 token ≈ 26 万 token，足以让每个通道的激活直方图统计稳定（>1000 样本/通道量级）。

### 4.3 校准踩坑（高频事故）

1. **语言/领域错配**：用英文 wiki 校准服务中文客服 → 中文 token 激活分布没被看到，scale 偏小，溢出截断 → 中文输出乱码。**修法**：换业务同分布校准集。
2. **seq_len 太短**：长上下文位置才出现的 outlier 没采到 → 上线后长文掉点。**修法**：校准用 ≥ 部署上下文一半的长度。
3. **BOS/system prompt 污染**：每条都带相同前缀，统计被前缀主导。**修法**：去重前缀或采样多模板。
4. **数据泄露评估**：拿测试集当校准 → 离线指标虚高。**修法**：校准/评估严格分离。

## 5. 精度回退排查：5 步定位法

量化后掉点（perplexity 升、下游准确率降），按下面顺序排，**从最可能到最少见**：

```
┌─ Step1 基线对齐 ─► FP16 baseline 是否本来就对? 评测脚本/解码参数一致?
├─ Step2 缩范围   ─► 全 W4A16 掉点 → 退到 W8A16 是否恢复? 定位是权重还是激活
├─ Step3 逐层归因 ─► 逐层换回 FP16,看哪层换回后掉点消失 → 锁定敏感层
├─ Step4 看分布   ─► 该层激活有没有 outlier? per-channel max 直方图
└─ Step5 改配置   ─► 敏感层保 FP16 / 减 group_size / 换 AWQ / SmoothQuant
```

### 5.1 逐层归因怎么做（核心技巧）

把模型每一层独立量化，其余保持 FP16，测每层"单独量化"的掉点贡献。或反过来——全量化后逐层**换回** FP16。掉点主要由**少数敏感层**贡献：
- **第一层 / 最后一层**（embedding 近端、输出 head）通常最敏感 → 常保 FP16。
- **MoE 的 gate / router 层**：决定 token 走哪个专家，量化误差会让路由翻转，错一个 token 的专家选择影响整段输出。**经验：MoE gate 层对量化敏感，通常不量化以保持完全精度。** 详见 [[llm-compression/quantization/moe模型量化]]。
- **LayerNorm / 含 outlier 的 down_proj**：激活 outlier 重灾区。

### 5.2 数值示例：一个敏感层的影响

设某 router 层 logits = $[2.01, 2.00, 1.0]$，softmax 后专家1险胜。量化把 logits 抖成 $[2.00, 2.01, 1.0]$ → argmax 翻到专家2 → 整个 token 用错专家。**单个 0.01 的量化噪声 → 100% 路由错误**。这就是 gate 层不能量化的根因（误差不被"平均掉"，而是触发离散翻转）。

### 5.3 常用补救手段优先级

```
1. 敏感层保 FP16 (mixed precision)   ← 最省事,先试
2. 减小 group_size (128→64→32)       ← 权重量化掉点
3. 换算法: GPTQ→AWQ / 加 SmoothQuant ← 激活 outlier 掉点
4. PTQ 救不回 → 上 QAT (LLM-QAT)     ← 终极手段,要训练
```

## 6. KV Cache 量化注意事项

§1.1 算过，长上下文 KV 显存能超过权重，所以 KV 量化是长文服务的刚需。但 KV 比权重更难量化。详见 [[llm-compression/quantization/kv-cache-quant]]。

### 6.1 为什么 KV 难量化

```
权重: 离线一次量化,误差固定
KV  : 每生成1个token都新增K,V,误差随序列累积,且参与后续每一步注意力
```
注意力 $\text{softmax}(QK^\top/\sqrt d)V$ 对 K 的误差敏感：K 进 softmax，小扰动经指数放大。

### 6.2 K 和 V 要分开处理（关键经验）

实测 **Key 比 Value 更难量化**，且方向相反：
- **Key cache**：outlier 集中在**特定 channel**（某些维度天生幅度大）→ 应 **per-channel** 量化（沿 head_dim）。
- **Value cache**：分布较均匀，**per-token** 量化即可。

```
Key  [d0  d1  d2 ... d127]   ← 某几个 channel 是 outlier
      ███ ░  ░  ...  ░        per-channel: 每列单独 scale ✔
                              per-token:   被 outlier 列毁掉 ✘

Value 较均匀 → per-token 足够,实现简单
```

### 6.3 实战注意

1. **保留近窗 FP16**：最近 N 个 token 的 KV 留 FP16（注意力权重最大），更早的才量化 → "attention sink + recent window 全精度"。
2. **量化粒度别太粗**：KV per-tensor 几乎必崩，至少 per-token/per-channel。
3. **INT4 KV 慎用**：KV 到 INT4 长文常崩，**INT8 KV 是稳妥点**；要更省用 KIVI/FP8 KV。
4. **和 PagedAttention/FlashAttention 的兼容**：量化 KV 需要 kernel 支持反量化融合，否则反量化开销吃掉收益。

## 7. 不同硬件支持差异

量化方案能不能**真正提速**，取决于硬件有没有对应的低精度计算单元。**省显存到处都行，提速看硬件**。

| 硬件 | INT8 | INT4 | FP8 | 2:4稀疏 | 备注 |
|---|---|---|---|---|---|
| A100 (Ampere) | ✔ TensorCore | 反量化成FP16算 | ✘ | ✔ | W4A16省显存,计算仍走FP16 |
| H100 (Hopper) | ✔ | ✔(部分) | ✔ E4M3/E5M2 | ✔ | FP8 训练+推理首选 |
| RTX 4090 (Ada) | ✔ | ✔ | ✔ FP8 | ✔ | 消费卡,FP8/INT4性价比高 |
| Ascend 910 | ✔ | 看算子库 | 部分 | 看版本 | 用 CANN,方案要适配 |
| 手机/边缘(NPU) | ✔ INT8主力 | 部分 | ✘ | ✘ | INT8 是端侧主流,常配QAT |
| CPU (AVX512-VNNI) | ✔ | 模拟 | ✘ | ✘ | INT8 有 VNNI 加速 |

**关键经验**：
- **W4A16 在 A100 上不提速计算**——A100 没 INT4 矩阵单元，权重先反量化回 FP16 再算，**收益全在省显存（能装下大模型）+ 减少显存带宽搬运**。带宽受限场景（小 batch decode）反而提速明显。
- **FP8 要 H100/4090** 这类有原生 FP8 Tensor Core 的卡才划算。
- **2:4 结构化稀疏要 Ampere+**，且需 cuSPARSELt，理论 2x，实际常 1.3~1.5x。
- 端侧（手机 NPU）几乎只认 **INT8**，且通常要 **QAT** 才能保住精度。

## 8. 组合策略：多技术怎么叠

### 8.1 叠加顺序（有讲究）

```
蒸馏(改结构,先做)
   ↓ 得到小学生模型
剪枝(再删冗余,可选,LLM上慎用)
   ↓
量化(最后做,PTQ/QAT)
   ↓
量化-KV + 量化-权重 同时上
```
**为什么这个顺序**：蒸馏/剪枝改变模型本身（参数级），量化是最后一道"装箱"工序（表示级）。反过来先量化再蒸馏，会在量化噪声上训练，得不偿失。

### 8.2 经典组合配方

| 目标 | 配方 | 收益示例(相对FP16 7B) |
|---|---|---|
| 单卡塞下大模型 | W4A16(AWQ) + INT8 KV | 显存 13.4GB → ~4GB |
| 极致吞吐 | W8A8(SmoothQuant) + 大batch | 吞吐 ~2x |
| 从70B到能用的小模型 | 蒸馏→7B + W4A16 | 70B(140GB)→7B-INT4(~4GB) |
| 端侧部署 | 蒸馏→1B + QAT INT8 | 可跑手机 NPU |
| H100 训练+推理 | FP8 训练 + FP8 推理 | 省显存+提速,精度近FP16 |

### 8.3 组合的坑

1. **误差叠加非线性**：蒸馏掉 1%、量化掉 1%，组合可能掉 3%（误差不是简单相加，会相互放大）。**对策**：每加一层压缩就重测，别一次叠满。
2. **量化 + LoRA**：QLoRA 思路——base 量化到 NF4，LoRA 旁路保 FP16/BF16，微调只更新 LoRA。base 量化误差被 LoRA 自适应吸收。
3. **MoE + 量化**：专家 FFN 可量化，但 gate 必须保精度（§5.2）。

## 9. 数值示例：完整走一遍 7B 模型 W4A16 量化

**目标**：Llama-7B（FP16 13.4GB）量化到 W4A16，group_size=128，估算显存与误差。

**Step1 权重显存**：
$$6.7\text{e}9 \times 0.5\text{B} = 3.35\,\text{GB (INT4 主体)}$$

**Step2 加 scale 开销**（group=128，每组1个FP16 scale）：
$$\frac{6.7\text{e}9}{128}\times 2\text{B} = 1.05\text{e}8\,\text{B} \approx 0.105\,\text{GB}$$
合计权重 ≈ **3.46 GB**（相比 FP16 的 13.4GB，**省 74%**）。

**Step3 加 INT8 KV**（S=4096, B=1，对比 §1.1 的 FP16 2GB）：
$$2\text{GB} \times \frac{1\text{B}}{2\text{B}} = 1\,\text{GB}$$

**Step4 总显存**：3.46 + 1 ≈ **4.46 GB** → **一张 8GB 消费卡能跑 7B + 4K 上下文**。

**Step5 单组量化误差估计**：组内 128 个权重，设 $\max|w|=0.8$，INT4 范围 [-7,7]：
$$s = 0.8/7 = 0.114, \quad \text{量化步长} = s = 0.114$$
单权重最大量化误差 $\le s/2 = 0.057$。一个值 $w=0.3$ → $q=\text{round}(0.3/0.114)=3$ → $\hat w = 3\times0.114=0.342$，误差 0.042（相对 14%）。group_size 缩到 64 时该组 max 更小、s 更小、误差减半——这就是减 group_size 救精度的数学原因。

## 10. 常见问题 / 高频追问

| 问题 | 踩点答案 | 追问/陷阱 |
|---|---|---|
| W4A16 在 A100 上为啥不一定快? | A100 无 INT4 算力,权重反量化回 FP16 算;收益是省显存+省带宽,decode 带宽受限时才显著提速 | 那啥时候快? → 小 batch decode(带宽受限);大 batch prefill(算力受限)收益小 |
| GPTQ 和 AWQ 怎么选? | GPTQ 用 Hessian 逐列量化补偿误差;AWQ 按激活幅度保护重要权重通道。激活 outlier 重 → AWQ;通用 → 都试,AWQ 常更稳更快 | 都要校准集吗? → 都要,AWQ 对校准量更不敏感 |
| 为什么激活比权重难量化? | 权重静态分布窄;激活动态且有 systematic outlier(某些channel恒大),撑大scale毁小值 | 解法? → SmoothQuant 把难度从激活"迁移"一部分到权重 |
| KV 量化为何 Key 用 per-channel? | Key 的 outlier 集中在固定 channel,per-token 会被 outlier 列毁掉;Value 均匀用 per-token | INT4 KV 行不行? → 长文常崩,INT8 才稳 |
| MoE 哪层不能量化? | gate/router 层。量化噪声让 argmax 翻转→路由到错专家→整段输出错(离散翻转,误差不被平均) | 专家 FFN 能量化吗? → 能,主体收益在这 |
| 蒸馏和量化先做谁? | 先蒸馏(改结构)后量化(改表示);反了会在量化噪声上训练 | 剪枝放哪? → 蒸馏后量化前,但 LLM 上常跳过 |
| 量化后掉点怎么快速定位? | 5步:基线对齐→缩范围(W8A16试)→逐层换回FP16归因→看激活outlier→敏感层保FP16/减group | 救不回怎么办? → 上 QAT |
| 校准数据要多少/选啥? | 128~512条×2048token,贴真实流量同领域同语言,含长样本 | 用测试集校准行吗? → 数据泄露,离线指标虚高 |
| 稀疏剪枝为啥常不提速? | 非结构化稀疏在稠密硬件上只省显存;要 2:4 稀疏 + Ampere+ + cuSPARSELt 才提速,实测约1.3~1.5x | 那为啥还做? → 有稀疏硬件时;或纯为省显存 |
| FP8 比 INT8 好在哪? | FP8 有指数位,动态范围大,对 outlier 更友好,训练也能用;但要 H100/Ada 原生支持 | 没 H100 呢? → 退 INT8 PTQ |
