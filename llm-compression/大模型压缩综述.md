## 0. 一句话锚点

LLM 大到"装不下、算不快、传不动"，但其中**大量参数对结果几乎无贡献（冗余）**。模型压缩 = **在尽量不掉精度的前提下，砍掉这些冗余**，换取更小存储、更省显存、更快推理。

四条主路（本综述的核心分类）：

```
                  ┌────────────── 模型压缩 ──────────────┐
                  │                                      │
        剪枝 Pruning      蒸馏 Distillation     量化 Quantization   低秩分解 Low-Rank
        删"权重/结构"      大模型→小模型转移      高比特→低比特         W ≈ A·B
        (改 0 的个数)      (改模型大小)          (改每个数的位宽)      (改矩阵的秩)
```

> 关键直觉：**剪枝**动的是"哪些数变 0"，**量化**动的是"每个数用几位存"，**蒸馏**动的是"换一个更小的模型重学"，**低秩**动的是"把一个大矩阵换成两个小矩阵"。四者正交，**可组合**（见第 7 节）。

## 1. 地基：LLM 的资源账单从哪来

要理解"压什么"，先看一台 LLM 的成本由哪三块构成。

```
显存占用 ≈ 权重 + 激活/KV-Cache + 优化器状态(仅训练)
           └ 压缩主战场          └ 推理时随序列增长     └ 训练专属
```

**① 权重显存底盘**（推理最硬的下限）：

$$\text{权重显存} = \text{参数量} \times \text{每参数字节数}$$

| 模型 | 参数量 | FP16(2B) | INT8(1B) | INT4(0.5B) |
|------|--------|----------|----------|-----------|
| LLaMA-7B | 7e9 | 14 GB | 7 GB | 3.5 GB |
| LLaMA-13B | 13e9 | 26 GB | 13 GB | 6.5 GB |
| LLaMA-70B | 70e9 | 140 GB | 70 GB | 35 GB |

手算：7B 模型 FP16 → $7\times10^9 \times 2\text{ byte} = 1.4\times10^{10}\text{ byte} \approx 14\text{ GB}$。一张 24 GB 的 4090 装得下 7B FP16，但装不下 13B FP16 → **这就是压缩的刚需场景**。

**② 计算量**：一次前向 ≈ $2N$ FLOPs/token（$N$=参数量）。砍参数（剪枝）或降位宽（量化）都能减少实际算力开销。

**③ 训练专属**：Adam 优化器状态约为权重的 2 倍（一阶+二阶动量），梯度 1 倍——所以训练侧压缩常配合 [[llm-train/peft/PEFT-API]]（如 LoRA）而非纯推理压缩。

> 记住这条因果链：**参数多 → 字节多 → 显存爆 / 算得慢 → 需要压缩**。压缩的四条路，本质都在攻击"参数量 × 每参数字节数"这个乘积。

## 2. 剪枝（Pruning）：删冗余的权重与结构

> 原文核心：剪枝通过删除不必要或冗余的组件来减少模型大小/复杂度。大量冗余参数对性能几乎无影响，直接剪掉后性能不会损失太多。剪枝对存储、内存效率、计算效率都更友好。

### 2.1 为什么剪枝有效

神经网络是**过参数化（over-parameterized）**的——训练时需要冗余来帮助优化收敛，但训完之后很多权重接近 0 或对输出贡献极小。剪枝就是把这些"训练用的脚手架"拆掉。

```
剪枝前权重矩阵          剪枝后(稀疏)
┌───────────────┐      ┌───────────────┐
│ 0.8 0.01 0.7  │      │ 0.8  0   0.7  │   ← 0.01、0.02 被判为冗余→置0
│ 0.02 0.9 0.6  │  →   │  0  0.9  0.6  │
│ 0.7 0.05 0.03 │      │ 0.7  0    0   │
└───────────────┘      └───────────────┘
```

### 2.2 两大类：结构化 vs 非结构化

原文要点：**两者主要区别在于剪枝目标和由此产生的网络结构。**

```
非结构化剪枝 (Unstructured)        结构化剪枝 (Structured)
针对"单个参数"                     按规则剪"连接/分层结构"
→ 不规则稀疏 (零散的 0)            → 保留整体网络结构
─────────────────────────         ─────────────────────────
W:  ■ □ ■ □ □                     整列/整通道/整 head 被删
    □ ■ □ ■ ■        vs           ┌─■─┐         ┌─■─┐
    ■ □ □ ■ □                     │ ■ │ ──删整列→ │ ■ │  (矩阵真的变小)
精度损失小，但普通 GPU 难加速       精度损失略大，但硬件直接提速
(需 2:4 稀疏等专门支持)            (矩阵维度变小 = 真实计算变少)
```

| 维度 | 非结构化剪枝 | 结构化剪枝 |
|------|-------------|-----------|
| 剪枝对象 | 单个权重元素 | 整行/列/通道/注意力头/层 |
| 产生结构 | 不规则稀疏矩阵 | 规则、更小的稠密矩阵 |
| 精度保持 | 更好（粒度细） | 略差（粒度粗） |
| 实际加速 | 需专用稀疏内核/硬件（如 2:4 稀疏） | 通用硬件即可加速 |
| 代表方法 | SparseGPT、Wanda | LLM-Pruner |

> 一句话选型：**想要通用 GPU 上真加速 → 结构化**；**想最大保精度且有稀疏硬件支持 → 非结构化**。最近的研究致力于把 LLM 与剪枝结合，应对 LLM 的大规模与高计算成本。

### 2.3 原文收录的代表方法（保留真实仓库）

**结构化剪枝**
- **LLM-Pruner** — https://github.com/horseee/LLM-Pruner （300+ stars）
  - 思路：基于梯度信息发现"耦合结构"，按依赖关系成组剪枝，剪后用少量数据 LoRA 微调恢复。

**非结构化剪枝**
- **SparseGPT** — https://github.com/IST-DASLab/sparsegpt （400+ stars）
  - 思路：把剪枝转化为分层最小二乘重建问题，一次前向即可剪到 50% 稀疏几乎不掉精度，无需重训。
- **LoRAPrune** —（剪枝 + 低秩分解的组合，见第 5 节）
- **Wanda**（Weights **and** Activations）— https://github.com/locuslab/wanda （300+ stars）
  - 思路：剪枝重要性 = |权重| × |输入激活范数|，**无需梯度、无需重训**，极简却有效。

> 三者对照的钥匙：SparseGPT 用"重建"，Wanda 用"权重×激活"，LLM-Pruner 用"梯度+依赖+微调恢复"。

## 3. 知识蒸馏（Knowledge Distillation, KD）

> 原文核心：把知识从复杂的**教师模型（teacher）**转移到更简单的**学生模型（student）**，核心思想是从教师的全面知识中提炼出更精简高效的表示。本综述聚焦"用 LLM 当教师"的蒸馏。

### 3.1 为什么蒸馏有效：软标签比硬标签信息更多

```
硬标签(one-hot)          软标签(教师输出分布)
"猫"                     猫:0.7  狗:0.2  虎:0.08 ...
[1,0,0,0]        vs      [0.7,0.2,0.08,...]
只说"是猫"               还说"像狗多过像虎" ← 暗知识(dark knowledge)
```

学生不仅学"答案对不对"，还学教师在各类别上的**相对概率（暗知识）**，因此小模型能逼近大模型的判断方式。

### 3.2 两大分类（原文分类轴：是否蒸馏"涌现能力 EA"）

原文按方法是否侧重把 LLM 的**涌现能力（Emergent Abilities, EA）**蒸馏到小模型（SLM）分两类：

```
                知识蒸馏 KD
        ┌───────────────┴───────────────┐
   Standard KD                      EA-based KD
   学"常见知识"                      额外蒸馏"涌现能力"
   (输出分布、特征信息)                ┌────────┼────────┐
   类似传统 KD                       ICL      CoT       IF
                                   上下文学习 思维链   指令跟随
```

**Standard KD**：让学生学习教师（LLM）拥有的常见知识，如输出分布与特征信息，类似传统 KD。
- **MINILLM** —（清华 & 微软研究院）https://github.com/microsoft/LMOps/tree/main/minillm
  - 关键改动：用**反向 KL 散度**替代标准前向 KL，避免学生在教师低概率区域过度自信。
- **GKD**（Generalized Knowledge Distillation）—（Google DeepMind）
  - 论文：*GKD: Generalized Knowledge Distillation for Auto-regressive Sequence Models*，针对自回归序列模型，缓解训练/推理分布不匹配（on-policy 蒸馏）。

**EA-based KD**：不仅转移常见知识，还蒸馏 LLM 独特的**涌现能力**。细分三支：

**① In-Context Learning（上下文学习 ICL）**
- *In-context Learning Distillation: Transferring Few-shot Learning Ability of Pre-trained Language Models* —（哥伦比亚大学）

**② Chain-of-Thought（思维链 CoT）**——把"推理过程"也教给小模型
- **MT-COT** — *Explanations from Large Language Models Make Small Reasoners Better* —（加州大学圣塔芭芭拉分校、腾讯 AI 实验室、微软等）
- **Fine-tune-CoT** — *Large language models are reasoning teachers* — https://github.com/itsnamgyu/reasoning-teacher
- *Specializing Smaller Language Models towards Multi-Step Reasoning* —（爱丁堡大学、艾伦 AI 研究所）
- **DISCO** — *DISCO: Distilling Counterfactuals with Large Language Models* — https://github.com/eric11eca/disco （12）—（洛桑联邦理工 NLP 实验室、艾伦 AI 研究所）
- **SCOTT** — *SCOTT: Self-Consistent Chain-of-Thought Distillation* —（南加州大学计算机科学系、亚马逊）
- **SOCRATIC CoT** —（苏黎世联邦理工计算机科学系）

**③ Instruction Following（指令跟随 IF）**
- **Lion** — *Lion: Adversarial Distillation of Closed-Source Large Language Model* —（香港科技大学）https://github.com/YJiangcm/Lion （144）
  - **三个角色**：教师、审阅者、生成者
  - **三个步骤**：模仿、辨别、生成（对抗式循环：生成者造难样本，审阅者挑教师/学生差距大的样本，迭代逼近）
  - 成果：7B LLaMA 接近 ChatGPT 95% 能力。参考报道：https://it.sohu.com/a/680520547_121119001

> CoT 蒸馏的钥匙：让小模型不仅给答案，还**生成中间推理步骤**——把"会推理"这个涌现能力压进小模型。

## 4. 量化（Quantization）

> 原文此节为占位。量化是四族中**工程落地最广**的一支：不改模型结构、不改参数个数，只把每个数的**位宽**从 FP16/BF16 降到 INT8/INT4/FP8 等。

### 4.1 核心机制（一图说清）

```
FP16 权重区间 [-w_max, w_max]   →   映射到 INT8 整数 [-127, 127]
   real value  w  ──────────────────────────► q = round(w / scale)
   scale = w_max / 127                          反量化 ŵ = q × scale
```

最朴素的对称量化：$scale = \dfrac{\max|W|}{2^{b-1}-1}$，$q=\text{round}(W/scale)$，$\hat W = q\times scale$。

数值示例（INT8，$w_{max}=1.0$）：$scale = 1.0/127 \approx 0.00787$。权重 $0.5 \to q=\text{round}(0.5/0.00787)=64 \to \hat W = 64\times0.00787 = 0.504$，量化误差 0.004。

| 位宽 | 每参数字节 | 7B 模型显存 | 相对 FP16 |
|------|-----------|------------|-----------|
| FP16/BF16 | 2 | 14 GB | 1.0× |
| FP8 | 1 | 7 GB | 0.5× |
| INT8 | 1 | 7 GB | 0.5× |
| INT4 | 0.5 | 3.5 GB | 0.25× |

> 难点不在"怎么除以 scale"，而在**离群值（outlier）**：少数极大激活值会把 scale 撑大，导致绝大多数小值挤进几个量化格子——这正是 SmoothQuant / GPTQ / LLM.int8() 要解决的问题。详见专题：[[llm-compression/quantization/量化基础]]、[[llm-compression/quantization/GPTQ]]、[[llm-compression/quantization/fp8]]。

## 5. 低秩因式分解（Low-Rank Factorization）

把一个大权重矩阵近似拆成两个小矩阵之积：

$$W_{m\times n} \approx A_{m\times r}\, B_{r\times n}, \quad r \ll \min(m,n)$$

```
   W (m×n)              A (m×r)   ×   B (r×n)
┌──────────┐         ┌──┐
│          │   ≈     │  │  ×  ┌──────────┐
│  m × n   │         │m×r│     │  r × n   │
└──────────┘         └──┘      └──────────┘
参数 m·n             参数 m·r + r·n   ← 当 r 小时大幅减少
```

参数量从 $mn$ 降到 $mr+rn=r(m+n)$。手算：$m=n=4096,\ r=64$ → 从 $1.68\times10^7$ 降到 $64\times8192\approx5.2\times10^5$，约 **32×** 压缩。

原文给出的两个"组合型"代表（低秩 + 另一族叠加）：
- **ZeroQuant-FP**（低秩分解 + **量化**）
- **LoRAPrune**（低秩分解 + **剪枝**）

> 这正好印证第 0 节"四族正交、可组合"：低秩很少单打独斗，常作为"恢复精度/进一步压缩"的搭档。

## 6. 指标与基准（Metrics & Benchmarks）

### 6.1 指标

> 原文：LLM 推理效率可用多种指标衡量，这些指标考虑性能的不同方面，通常与准确性、零样本能力一起呈现。

| 指标 | 含义 | 直觉/公式 |
|------|------|----------|
| 参数规模（#Params） | 模型参数总数 | 决定显存底盘 |
| 模型规模（Model Size） | 落盘/显存字节数 | 参数量 × 每参数字节 |
| 压缩比（Compression Ratio） | 原大小 / 压后大小 | $\dfrac{S_{orig}}{S_{comp}}$，越大越省 |
| 推理时间（Inference Time） | 端到端时延 | 关注 [[llm-eval/llm-performance/大模型场景下训练和推理性能指标名词解释]] |
| 浮点运算（FLOPs） | 计算量 | ≈ $2N$/token（$N$=参数量） |

> 关键提醒：**压缩比高 ≠ 好**。必须同时看准确率/零样本能力是否守住，否则就是"压坏了"。压缩比与精度的权衡，是整个领域的主线。

### 6.2 基准（Benchmarks）

> 原文：基准旨在相对未压缩 LLM，衡量压缩 LLM 的有效性、效率与准确性，通常由覆盖一系列 NLP 挑战的多任务/数据集组成。常用基准包括但不限于 **HULK** 与 **ELUE**。

```
评估一个压缩方法，至少答三问：
  有效性 Effectiveness ── 任务准确率掉了多少？
  效率   Efficiency    ── 时延/显存/FLOPs 省了多少？
  准确性 Accuracy      ── 零样本/few-shot 能力是否守住？
```

## 7. 四族对照表 + 组合策略

| 维度 | 剪枝 Pruning | 蒸馏 KD | 量化 Quantization | 低秩 Low-Rank |
|------|-------------|---------|-------------------|---------------|
| 改的是 | 权重的"0 个数" | 整个模型（换小的） | 每个数的位宽 | 矩阵的秩 |
| 改结构吗 | 结构化会改 | 改（新小模型） | 不改 | 改（拆两矩阵） |
| 需重训吗 | 部分需微调恢复 | 必须（学生重学） | PTQ 不需 / QAT 需 | 常需微调 |
| 通用硬件加速 | 结构化 ✅ / 非结构化 ⚠️ | ✅（小模型本就快） | ✅（INT8 内核成熟） | ✅ |
| 工程成熟度 | 中 | 中 | **高（落地最广）** | 中 |
| 典型组合 | LoRAPrune(+低秩) | — | ZeroQuant-FP(+低秩) | 与剪枝/量化叠 |

**组合逻辑（因为四族正交）**：
```
量化  +  低秩   = ZeroQuant-FP   (位宽↓ 再 秩↓)
剪枝  +  低秩   = LoRAPrune      (删权重 + 低秩恢复)
量化  +  剪枝   = 稀疏 + 低比特   (双重压缩)
蒸馏  +  量化   = 先蒸出小模型再量化  (端侧部署常用)
```

> 实践默认起点：**先量化**（性价比最高、对精度最友好、生态最全），不够再叠剪枝/蒸馏/低秩。

## 常见问题 / 坑

| 坑 | 现象 | 原因 | 规避 |
|----|------|------|------|
| 非结构化剪枝"没变快" | 稀疏度 50% 但推理时延几乎不变 | 普通 GPU 不识别零散稀疏，仍按稠密算 | 用结构化剪枝，或 2:4 稀疏 + 专用内核 |
| 量化崩精度 | INT4 后困惑度暴涨 | 激活离群值把 scale 撑大，小值被挤没 | 用 GPTQ/SmoothQuant/混合精度保护离群通道 |
| 蒸馏学不会"推理" | 小模型答案对、过程乱 | 只蒸了输出分布(Standard KD) | 用 EA-based KD：蒸 CoT 中间步骤 |
| 只看压缩比 | 压缩比很高但任务全崩 | 忽略了准确率/零样本能力守不守得住 | 压缩比与精度**配对**评估（HULK/ELUE） |
| 低秩选错 r | r 太小掉精度，r 太大不省 | 秩是精度↔压缩的旋钮 | 按层调 r + 微调恢复 |
| 蒸馏忘了分布匹配 | 学生训练好、推理飘 | 训练用教师强制(teacher forcing)、推理自回归 | 用 GKD 这类 on-policy 蒸馏 |
| QAT vs PTQ 混淆 | 想免训练却选了 QAT | PTQ 免训练、QAT 需重训 | 优先 PTQ，精度不够再上 QAT |
