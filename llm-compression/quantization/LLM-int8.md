## 0. 一句话锚点

把矩阵乘法 $X W$ 拆成两条路：
- **离群列**（少数几个，绝对值 ≥ 阈值 6）→ 原样保留 **FP16**，精确无损；
- **其余列**（绝大多数）→ **INT8** 向量级量化，速度快、省显存。

两路结果相加，得到 FP16 输出。离群值不进 INT8，所以不会污染量化；其余值本来就温和，量化误差极小。结果：**与 FP16 推理几乎逐点一致**。

```
          ┌─ 离群列(极少) ─→ [FP16 matmul] ──┐
   X·W ───┤                                   (+)──→ FP16 输出
          └─ 普通列(绝大多数)→ [INT8 matmul]─┘
```

## 1. 地基：从最底层讲起

### 1.1 量化到底在做什么

量化 = 把连续的浮点数压到一组离散整数上。最常用的是**对称线性量化**：

$$ q = \mathrm{round}\!\left(\frac{x}{s}\right), \qquad s = \frac{\max(|x|)}{2^{b-1}-1} $$

- $x$：原始浮点值；$s$：缩放因子（scale）；$b$：位宽。
- INT8 时 $b=8$，有符号整数范围是 $[-128, 127]$，对称量化用 $127$（即 $2^{7}-1$）做满刻度。
- 反量化（dequant）：$\hat{x} = q \cdot s$，得到一个近似原值的浮点数。

**为什么需要 scale**：INT8 只能表示 256 个台阶。如果你的数据在 $[-6, 6]$，就把 6 映射到 127，每个台阶约 $6/127 \approx 0.047$。scale 就是「一个整数台阶代表多少浮点」。

### 1.2 INT8 的动态范围为什么是死穴

INT8 满打满算 256 个值。**台阶大小由该向量里的最大绝对值决定**——因为 scale = 最大值 / 127。

```
正常向量  最大值=6   → 台阶 0.047 → 精细
被离群污染 最大值=60  → 台阶 0.47  → 粗糙10倍！
```

一旦向量里混进一个 60，scale 被这个 60「撑大」10 倍，**其余所有正常值的量化台阶也跟着粗 10 倍**，它们的有效精度从 ~7.6 bit 掉到 ~3.6 bit。这就是离群值的破坏力：它不是自己掉点，而是**连累全体**。

## 2. 离群特征（Emergent Features）现象

LLM.int8() 论文的核心实证发现：

> 大模型激活（hidden states）中存在少量**离群值**，其绝对值远大于其余值；并且它们**系统性地集中在极少数固定的特征维度（通道/列）**上，称为 **Emergent Features / 离群特征**。

关键观察：

1. **集中**：在一个 $d=4096$ 的隐藏维度里，离群值往往只落在 **6~ 几十个固定列**上，其余几千列都正常。
2. **系统性**：同一列在几乎所有 token、所有层都离群，不是随机噪声，是有结构的。
3. **规模相变（phase transition）**：参数量 **> 6B** 的 Transformer，几乎每层都稳定出现这些超阈值离群点；小模型里虽也有苗头，但不致命。这是「涌现（emergent）」一词的由来——它随规模突然变得普遍而剧烈。

```
hidden states  X  (shape: tokens × d)，d=4096
列索引:  0   1   2   ... 1023 ...        4095
       ┌───┬───┬───┬───┬────┬───┬───┬───┐
token0 │0.3│0.1│ 47│0.2│ ...│0.4│ 38│0.1│
token1 │0.2│0.4│ 51│0.1│ ...│0.3│ 41│0.2│
token2 │0.1│0.2│ 49│0.3│ ...│0.2│ 39│0.1│
       └───┴───┴───┴───┴────┴───┴───┴───┘
              ↑离群列          ↑离群列   ←─ 整列都大，跨 token 一致
```

**为什么离群值这么毒**：Transformer 把所有元素通过注意力和残差互相关联，单层的量化误差会在传播几层后**累积、放大、相互混杂**。因此对 >6B 模型，经典逐张量/逐通道量化会直接崩坏。

## 3. 为什么 per-token / per-channel 都救不了

先厘清量化粒度（详见 [[llm-compression/quantization/量化基础]]）：

| 粒度 | scale 按谁算 | 离群值的影响范围 |
|------|-------------|----------------|
| per-tensor | 整个张量一个 scale | 一个离群值毁全张量 |
| per-token（按行） | 每行一个 scale | 含离群值的那一行被毁 |
| per-channel（按列） | 每列一个 scale | 含离群值的那一列被毁 |

问题在于：离群值**整列都大**（per-channel 救不了那一列），而该列又被**几乎所有 token 用到**（per-token 也躲不开，因为每一行都要乘到这列对应的权重）。无论你怎么切粒度，只要把离群值塞进 INT8，那一片乘法就废。

```
per-token:  scale 随行变 → 但离群列每行都贡献大值 → 行 scale 仍被撑大
per-channel: scale 随列变 → 离群列自己的 scale 巨大 → 该列量化台阶极粗
```

**结论**：换粒度只是移动伤口，治不了病。唯一的根治法——**把离群值从 INT8 里彻底拿出去**。这就是混合精度分解。

## 4. 向量级量化（vector-wise quantization）

这是 INT8 那一路的算法。普通量化给整块矩阵一个 scale；向量级量化给**每个参与点积的向量各自一个 scale**。

设矩阵乘 $C = X W$，其中 $X \in \mathbb{R}^{m\times k}$、$W \in \mathbb{R}^{k\times n}$。
输出元素 $C_{ij} = \sum_t X_{it} W_{tj}$ 是 $X$ 的第 $i$ 行与 $W$ 的第 $j$ 列做点积。

- 给 $X$ 的**每一行** $i$ 一个 scale $s^x_i = \max_t|X_{it}|/127$；
- 给 $W$ 的**每一列** $j$ 一个 scale $s^w_j = \max_t|W_{tj}|/127$；
- 量化：$\hat{X}_{it}=\mathrm{round}(X_{it}/s^x_i)$，$\hat{W}_{tj}=\mathrm{round}(W_{tj}/s^w_j)$，都是 INT8。
- INT8 累加：$A_{ij}=\sum_t \hat{X}_{it}\hat{W}_{tj}$（INT32 累加器）。
- 反量化：

$$ C_{ij} \approx s^x_i \cdot s^w_j \cdot A_{ij} $$

```
      W 列 j: scale s^w_j (按列量化权重)
        │
        ▼
X 行 i ─► [ Σ x̂·ŵ  → INT32 ] ─► × (s^x_i · s^w_j) ─► C_ij (FP16)
  ▲
  scale s^x_i (按行量化激活)
```

**为什么行×列**：因为每个输出点只由「一行」和「一列」决定，给它俩各自最贴合的 scale，能把量化误差压到最低。这比 per-tensor 精细得多，是 LLM.int8() INT8 路的基础。但单靠它仍扛不住离群值——所以要叠加第 5 节。

## 5. 混合精度分解（核心机制）

把激活 $X$ 的列集合分成两组：
- $O$ = 离群列（含任一 $|X_{it}| \ge \tau$ 的列，论文阈值 $\tau = 6$）；
- $R$ = 其余正常列。

矩阵乘按列可加性拆开（$X W = X_{:,O}W_{O,:} + X_{:,R}W_{R,:}$）：

$$ C = \underbrace{X_{:,O}\,W_{O,:}}_{\text{FP16, 精确}} \;+\; \underbrace{\mathrm{dequant}\big(\hat{X}_{:,R}\,\hat{W}_{R,:}\big)}_{\text{INT8 向量级量化}} $$

三步落地（与文件原有方向一致）：

1. **检测**：从输入隐藏状态中，按列扫描，提取出现 $\ge 6$ 的离群列索引集合 $O$。
2. **分两路算**：离群子矩阵 $X_{:,O}, W_{O,:}$ 走 **FP16** 普通 matmul；其余 $X_{:,R}, W_{R,:}$ 走第 4 节的 **INT8 向量级** matmul。
3. **合并**：把 INT8 结果反量化回 FP16，与 FP16 离群结果**逐元素相加**，得最终 FP16 输出。

```
        d 列, 假设第 2、6 列离群
   ┌──────────────────────────────┐
 X │ · · X · · · X · · ·          │  hidden states
   └──┬───┬─────────┬─────────────┘
      │   │离群(O)   │其余(R)
      ▼   ▼          ▼
   ┌────────┐   ┌──────────────┐
   │X[:,O]  │   │X[:,R]        │
   │ FP16   │   │ INT8(行scale)│
   └───┬────┘   └──────┬───────┘
       │×W[O,:]FP16    │×Ŵ[R,:]INT8
       ▼               ▼
   ┌────────┐   ┌──────────────┐
   │C_outlier│  │C_int8→dequant│
   └───┬────┘   └──────┬───────┘
       └──────(+)──────┘
              ▼
          C (FP16) 最终输出
```

**关键洞察**：$|O|$ 通常只有几个到几十个，相对 $d=4096$ 占比 < 1%。所以「FP16 那一路」的额外计算量和显存几乎可忽略，整体仍享受 INT8 的 8-bit 存储与吞吐红利。

## 6. 为什么不掉点（数学直觉）

掉点的根源在第 1.2 节：离群值撑大 scale，连累全体。混合精度分解**对症下药**：

1. **离群列零误差**：$O$ 走 FP16，本身就是原精度，没有任何量化误差。占据 99% 数值能量的「大值」被精确处理。
2. **INT8 路的 scale 不再被污染**：因为 $\ge 6$ 的值已被移走，$R$ 里最大值通常就是个位数。scale 回归到正常台阶（如 0.047 而非 0.47），普通值的量化误差恢复到 INT8 本该有的低水平。
3. **误差不再跨层累积放大**：单层误差被压住，Transformer 的层间耦合就不会把误差滚雪球。

用误差量级估计：设普通值典型量化误差 $\approx s/2$。
- 不分解：被离群撑大后 $s \approx 0.47$，误差 $\approx 0.235$；
- 分解后：$s \approx 0.047$，误差 $\approx 0.0235$。
**误差直接缩小约 10 倍**，而最大的那些值索性零误差。两者叠加，输出与 FP16 几乎逐点重合——这就是「零掉点」的来源。

> 对比思路：[[llm-compression/quantization/SmoothQuant]] 走另一条路——不剥离群值，而是把激活的离群「难度」用等价变换搬一部分到权重上（$X\to X/s$，$W\to sW$），让两边都好量化，从而整网都能跑 INT8。LLM.int8() 留 FP16 后路，SmoothQuant 追求全 INT8 推理；前者精度优先且兼容性好，后者吞吐更高。

## 7. 逐数手算一个完整分解例子

取一个 mini 例子：$X$ 为 1 个 token × 4 维，$W$ 为 4×1，算 $C = XW$（一个标量输出）。

```
X = [ 0.5,  60.0,  0.3,  -0.4 ]      ← 第 2 维(列1)是离群值 60
W = [ 0.10, 0.20, -0.30, 0.40 ]ᵀ
```

### 7.1 真值（FP32 基准）

$$ C = 0.5(0.10) + 60(0.20) + 0.3(-0.30) + (-0.4)(0.40) $$
$$ = 0.05 + 12.0 - 0.09 - 0.16 = \mathbf{11.80} $$

### 7.2 方案 A：不分解，直接 INT8（看它怎么崩）

scale 由 $X$ 最大绝对值 60 决定：$s^x = 60/127 = 0.4724$。
量化：
- $0.5/0.4724 = 1.06 \to 1$
- $60/0.4724 = 127.0 \to 127$
- $0.3/0.4724 = 0.635 \to 1$
- $-0.4/0.4724 = -0.847 \to -1$

反量化回浮点：$[0.472,\ 60.0,\ 0.472,\ -0.472]$。
注意 $0.3$ 被量化成 $0.472$（误差 57%），$0.5$ 被量化成 $0.472$。
代入：
$$ C_A = 0.472(0.10)+60(0.20)+0.472(-0.30)+(-0.472)(0.40) $$
$$ = 0.047+12.0-0.142-0.189 = \mathbf{11.716} $$
小值项误差被放大；多个这种乘法层层累积后，最终输出会显著漂移。这里单层误差 $|11.80-11.716|=0.084$，**但 transformer 几十层叠加就崩**。

### 7.3 方案 B：混合精度分解（LLM.int8()）

**第 1 步 检测**：阈值 $\tau=6$，列 1 的 $60 \ge 6$ → 离群集合 $O=\{1\}$，其余 $R=\{0,2,3\}$。

**第 2 步 离群路（FP16，精确）**：
$$ C_O = X_1 W_1 = 60 \times 0.20 = \mathbf{12.0} \quad(\text{无误差}) $$

**第 3 步 INT8 路（向量级量化 $R$ 部分）**：
$X_R = [0.5, 0.3, -0.4]$，最大绝对值 0.5 → $s^x = 0.5/127 = 0.003937$。
- $0.5/0.003937 = 127 \to 127$
- $0.3/0.003937 = 76.2 \to 76$
- $-0.4/0.003937 = -101.6 \to -102$

$W_R = [0.10, -0.30, 0.40]$，最大绝对值 0.4 → $s^w = 0.4/127 = 0.003150$。
- $0.10/0.003150 = 31.7 \to 32$
- $-0.30/0.003150 = -95.2 \to -95$
- $0.40/0.003150 = 127 \to 127$

INT32 累加 $A=\sum \hat{x}\hat{w}$：
$$ A = 127(32) + 76(-95) + (-102)(127) = 4064 - 7220 - 12954 = -16110 $$

反量化：$C_R = s^x \cdot s^w \cdot A = 0.003937 \times 0.003150 \times (-16110)$
$$ = 1.2402\times10^{-5} \times (-16110) = \mathbf{-0.1998} $$
（对照真值 $R$ 部分：$0.05 - 0.09 - 0.16 = -0.20$，几乎完全一致！）

**第 4 步 合并**：
$$ C_B = C_O + C_R = 12.0 + (-0.1998) = \mathbf{11.8002} $$

### 7.4 三者对比

| 方案 | 结果 | 与真值 11.80 的误差 |
|------|------|--------------------|
| FP32 真值 | 11.8000 | 0（基准） |
| A：纯 INT8 | 11.7160 | 0.0840 |
| B：LLM.int8() | 11.8002 | **0.0002** |

误差从 0.084 降到 0.0002，**缩小约 400 倍**。核心原因：离群值 60 走了 FP16 零误差，INT8 路的 scale 从被撑大的 0.47 回落到 0.0039，小值精度全回来了。这就是「为什么不掉点」的逐数证据。

## 8. 复杂度 / 显存对照

| 维度 | FP16 | 纯 INT8 | LLM.int8() |
|------|------|---------|-----------|
| 权重存储 | 16-bit | 8-bit | 8-bit（离群列权重也常压 INT8，离群在激活侧） |
| 激活精度 | 16-bit | 8-bit | 离群列 16-bit + 其余 8-bit |
| 显存（权重） | 1× | 0.5× | ≈0.5× |
| 精度（>6B） | 基准 | 显著掉点 | ≈ 无损 |
| 额外开销 | — | — | 离群列检测 + 一次小 FP16 matmul + 散列/合并 |
| 推理速度 | 基准 | 最快 | 比纯 FP16 省显存，但因 FP16 旁路 + 数据搬运，吞吐未必超 FP16 |

权衡一句话：**LLM.int8() 买的是「在消费级显存里塞下大模型且不掉点」**，不是极致吞吐。要极致吞吐去看 [[llm-compression/quantization/SmoothQuant]] 这类全 INT8/INT4 路线。

参考实现：bitsandbytes（`https://github.com/TimDettmers/bitsandbytes`，具体 API 以官方文档为准）。

## 9. 常见问题

| 疑问 | 真相 |
|------|------|
| 阈值非得是 6 吗？ | 论文经验值：提取所有 $\ge 6$ 的离群值即可完全恢复推理精度。6 是工程上稳健的经验阈值，不是理论必然。 |
| 离群值占比那么小，值得专门处理？ | 正是因为「数量少但数值巨大」，它承载了大部分数值能量，又毒化 scale——少量元素决定成败。 |
| 为什么小模型不用这套？ | <6B 模型离群现象未达到「每层系统性出现」的相变，普通 INT8 量化通常够用。 |
| FP16 旁路会不会很慢？ | 离群列占比 <1%，那次 FP16 matmul 很小；主要开销在「检测离群 + 收集/散回列 + 合并」的数据搬运。 |
| 它和 SmoothQuant 谁更好？ | 目标不同：LLM.int8() 精度优先、保留 FP16 后路、即插即用；SmoothQuant 用等价缩放把离群难度搬到权重，追求全 INT8 高吞吐。 |
| 权重也有离群值吗？ | 权重分布通常温和，离群主要在**激活**侧。所以分解是按激活的列来做的。 |
| 为什么用向量级而非 per-tensor？ | 每个输出点只依赖一行一列，给行/列各自的 scale 能把 INT8 误差压到最低，是这套方案的精度地板。 |
