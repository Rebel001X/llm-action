## 0. 一句话锚点

量化的核心只有一条公式：**用一个仿射变换把实数 $r$ 和整数 $q$ 绑定起来**

$$ r \approx S\,(q - Z) \qquad\Longleftrightarrow\qquad q = \mathrm{clip}\!\Big(\mathrm{round}\big(\tfrac{r}{S}\big) + Z,\ q_{min},\ q_{max}\Big) $$

其中 $S$（scale，缩放因子，正实数）决定"一个整数步长代表多大的实数"，$Z$（zero-point，零点，整数）决定"整数轴上哪个值对应实数 0"。**量化的一切流派，都是在回答两个问题：$S$ 和 $Z$ 怎么定、按多大的粒度定。** 把这两句话刻进脑子，后面全是细节。

## 1. 地基：为什么要量化

LLM 推理在三个维度上昂贵，量化同时帮你省三个：

```
            FP16 基线                INT8 之后
显存占用    每参数 2 字节            每参数 1 字节        → 模型能塞进更小的卡
访存带宽    搬 2 字节/参数           搬 1 字节/参数        → 解码阶段瓶颈在带宽，直接 2x
算力        FP16 Tensor Core        INT8 Tensor Core     → 整数 MAC 吞吐更高、能耗更低
```

**为什么显存是第一痛点**：一个 70B 模型，FP16 权重 = $70\times10^9 \times 2\,\text{B} = 140\,\text{GB}$，单张 80GB 的 H100 装不下；INT8 砍到 70GB 勉强单卡，INT4 砍到 35GB 轻松单卡。逐数看：

| 精度 | 每参数字节 | 70B 权重显存 | 单卡(80GB)能否放下 |
| --- | --- | --- | --- |
| FP32 | 4 | 280 GB | 否 |
| FP16/BF16 | 2 | 140 GB | 否 |
| INT8 / FP8 | 1 | 70 GB | 勉强 |
| INT4 | 0.5 | 35 GB | 可以 |

**为什么访存带宽是第二痛点**：自回归解码时每生成一个 token 都要把整套权重从显存读进计算单元一遍。读 140GB vs 读 70GB，时间差一倍。**解码阶段是 memory-bound（受带宽限制）的，所以量化对解码延迟的收益往往比算力收益更直接。**

> 一句话：量化省的不是"算得快"那么简单，**最大的红利是少搬数据**。

## 2. 地基：浮点数是怎么存的（理解量化的前提）

要懂量化为什么"有损"，先得懂浮点本身。IEEE 754 把一个数拆成三段：符号 sign、指数 exponent、尾数 mantissa。

```
FP32:  [S][  exponent 8 ][      mantissa 23      ]   动态范围大、精度高、占 4 字节
FP16:  [S][ exp 5 ][   mantissa 10   ]              范围小、精度中、占 2 字节
BF16:  [S][  exponent 8 ][ mant 7 ]                 范围=FP32、精度低、占 2 字节
FP8E4M3:[S][exp4][mant3]                            范围更小、精度更低、占 1 字节
INT8:  [S][      7 位定点整数      ]                无指数段，等间隔
```

关键区别：**浮点是"非均匀"的——指数段让它在 0 附近密、远处疏**；而 **INT 是"均匀"的——相邻可表示值间距处处相等（就是 $S$）**。量化的本质就是：把原本非均匀分布的浮点值，强行塞进均匀的整数网格里，**塞不进网格点的部分被四舍五入，这就是量化误差的来源**。

## 3. 定点表示：scale 与 zero-point 从哪来

设我们要量化的实数落在区间 $[r_{min}, r_{max}]$，目标整数区间是 $[q_{min}, q_{max}]$（INT8 非对称常用 $[-128,127]$，对称常用 $[-127,127]$）。我们想要一条直线把两条数轴对齐：

```
实数轴:   r_min ──────────────── 0 ──────────── r_max
            │                                      │
            ▼  线性映射 q = r/S + Z                 ▼
整数轴:   q_min ─────────────────────────────── q_max
```

要让两个端点对齐，scale 和 zero-point 必须满足：

$$ S = \frac{r_{max}-r_{min}}{q_{max}-q_{min}}, \qquad Z = \mathrm{round}\!\Big(q_{min} - \frac{r_{min}}{S}\Big) $$

- **$S$ 的物理意义**：整个实数跨度被切成 $(q_{max}-q_{min})$ 段，每段宽 $S$。$S$ 越小，分辨率越细，误差越小，但能覆盖的范围也越小。
- **$Z$ 的物理意义**：实数 0 对应的整数。为什么 $Z$ 必须是整数？因为在很多算子里（如 ReLU、padding、卷积补零）"精确表示 0"很重要，若 0 落在两个整数网格之间会引入系统性偏差。把 $Z$ round 成整数就保证 $r=0$ 能被精确反量化回 0。
- **反量化（dequantize）**：$\hat r = S(q-Z)$，注意 $\hat r$ 一般 $\ne r$，差值即量化误差。

## 4. 对称 vs 非对称

这两者的差别就一句话：**$Z$ 是否被强制设为 0**。

### 4.1 对称量化（Z=0，absmax 量化）

强制 $Z=0$，映射退化为 $q=\mathrm{round}(r/S)$。范围取对称：令 $\alpha=\max(|r_{min}|,|r_{max}|)$（绝对值最大值，故名 **absmax**），则

$$ S = \frac{\alpha}{q_{max}} = \frac{\alpha}{127}\ (\text{INT8 对称}) $$

```
实数:   -α ───────────── 0 ───────────── +α
整数:  -127 ───────────── 0 ───────────── +127     (Z=0，零点天然对齐)
```

- **优点**：$Z=0$，反量化只剩一次乘法，硬件友好；矩阵乘里没有跨项交叉项（见下文)，计算最干净。
- **缺点**：当数据分布偏向一侧（如 ReLU 后全为正 $[0, r_{max}]$），对称范围 $[-\alpha,\alpha]$ 浪费了一半网格点（负半轴全空），有效分辨率减半。
- **何时用**：**权重**通常近似零均值对称分布，对称量化是默认选择。

### 4.2 非对称量化（Z≠0，zero-point 量化）

不强制 $Z=0$，用真实的 $[r_{min},r_{max}]$ 算出 $S$ 和 $Z$。

```
实数:    r_min ──────── 0 ──────────────── r_max     (0 不在正中间)
整数:    -128 ─── Z ──────────────────────── 127     (Z 落在某个非零整数处)
```

- **优点**：充分利用全部网格点，对**偏斜分布**（如 GELU/ReLU 后的激活、全正或全负）分辨率更高。
- **缺点**：$Z\ne0$ 会在矩阵乘里引入额外的交叉项，需要额外加法/预计算（见 §4.3）。
- **何时用**：**激活**常呈偏斜分布，非对称更划算。

### 4.3 为什么对称更适合矩阵乘（关键工程动机）

考虑量化矩阵乘 $\sum_i w_i x_i$。代入 $w_i=S_w(q^w_i-Z_w)$、$x_i=S_x(q^x_i-Z_x)$：

$$ \sum_i w_i x_i = S_w S_x \sum_i (q^w_i-Z_w)(q^x_i-Z_x) = S_w S_x\Big[\underbrace{\sum q^w_i q^x_i}_{\text{INT 主项}} - Z_w\!\sum q^x_i - Z_x\!\sum q^w_i + N Z_w Z_x\Big] $$

主项是纯整数乘加（Tensor Core 直接干），但后面三个**交叉项**来自非零 $Z$。如果对称量化（$Z_w=Z_x=0$），三项全部消失，只剩干净的整数 GEMM。**这就是为什么权重几乎总用对称、激活才考虑非对称的根本原因。**

## 5. 量化粒度：per-tensor / per-channel / per-group

粒度 = **一组共享同一对 $(S,Z)$ 的元素有多大**。粒度越细，越能贴合局部分布、误差越小，但元数据（每组要存一个 scale）越多、kernel 越复杂。

```
权重矩阵 W  (行=输出通道, 列=输入维度)

per-tensor          per-channel(逐输出通道)     per-group(每行切成小段)
┌─────────────┐     ┌─┬─┬─┬─┬─┬─┐              ┌──┬──┬──┐  每段(如128列)
│             │     │ │ │ │ │ │ │              │S1│S2│S3│  一个 scale
│   1 个 S    │     │S│S│S│S│S│S│              ├──┼──┼──┤
│   全张量共享│     │1│2│3│4│5│6│              │S4│S5│S6│
└─────────────┘     └─┴─┴─┴─┴─┴─┘              └──┴──┴──┘
1 个 scale          每列(输出通道)1个           每 group_size 个元素 1 个
最省, 最粗            权重首选                    INT4 标配(g=128/64)
```

- **per-tensor**：整张量一个 $(S,Z)$。最省、最快，但只要有一个离群值（outlier）把 $\alpha$ 撑大，所有元素的分辨率都被拖垮。LLM 激活里普遍存在离群值，per-tensor 激活量化常常掉点严重——这正是 [[llm-compression/quantization/SmoothQuant]] 要解决的问题。
- **per-channel（逐通道）**：沿输出通道维各自一套 $S$。权重量化的主流，每个神经元自适应自己的幅度。注意：通常只对**权重**做 per-channel，激活做 per-channel 会破坏 GEMM 的规约维对齐。
- **per-group（逐组）**：把每个通道再切成长度 $g$（常见 64/128）的小段，每段一个 $S$。这是 INT4 权重量化（如 [[llm-compression/quantization/GPTQ]]、AWQ）的标配——4 比特太容易溢出，必须靠细粒度补偿。

**元数据开销逐数估算**：一个 $4096\times4096$ 权重矩阵，INT4 主体 = $4096^2\times0.5\text{B}\approx8\text{MB}$。若 per-group（$g=128$，FP16 存 scale）：scale 个数 $=4096\times(4096/128)=4096\times32=131072$ 个，占 $131072\times2\text{B}=256\text{KB}$，仅占主体的 **3.2%**——用 3% 的存储换来 INT4 不崩，非常值。

## 6. 校准：$r_{min}, r_{max}$ 到底取多少

$S$ 依赖于范围，而范围怎么定大有讲究。直接取 min/max 会被离群值绑架。常见校准（calibration）策略：

| 方法 | 思路 | 代价 / 适用 |
| --- | --- | --- |
| Min-Max | 直接取观测到的最小/最大值 | 简单；对离群值极敏感 |
| 百分位 (percentile) | 取如 99.9% 分位，裁掉极端尾部 | 牺牲少量大值换整体分辨率 |
| MSE 最优 | 搜一个裁剪阈值使量化前后均方误差最小 | 权重常用，效果稳 |
| KL 散度 (熵) | 选范围使量化前后分布的 KL 散度最小 | TensorRT 经典做法 |

**权重是静态的**（推理时不变，离线一次算好）；**激活是动态的**（随输入变化），所以激活校准要么跑一批校准集统计（静态量化），要么运行时实时算 $S$（动态量化）。原理细节以各框架官方文档为准。

## 7. 数值示例：一个张量从头量化→反量化→算误差（逐数手算）

取一个小权重向量（FP32）：

$$ r = [\,0.0,\ -0.7,\ 1.5,\ -2.1,\ 0.9\,] $$

目标：INT8。我们各做一遍对称和非对称，看误差差别。

### 7.1 对称（absmax，INT8 → [-127,127]）

**第 1 步 求 absmax**：$\alpha=\max(|0.0|,|{-0.7}|,|1.5|,|{-2.1}|,|0.9|)=2.1$。

**第 2 步 求 scale**：$S=\dfrac{\alpha}{127}=\dfrac{2.1}{127}=0.016535$。$Z=0$。

**第 3 步 量化** $q=\mathrm{round}(r/S)$：

| $r$ | $r/S$ | $q=\mathrm{round}$ |
| --- | --- | --- |
| 0.0 | 0.00 | 0 |
| -0.7 | -42.33 | -42 |
| 1.5 | 90.72 | 91 |
| -2.1 | -127.00 | -127 |
| 0.9 | 54.43 | 54 |

**第 4 步 反量化** $\hat r = S\cdot q$：

| $q$ | $\hat r = 0.016535\,q$ | 误差 $\hat r - r$ |
| --- | --- | --- |
| 0 | 0.00000 | +0.00000 |
| -42 | -0.69449 | +0.00551 |
| 91 | 1.50472 | +0.00472 |
| -127 | -2.10000 | 0.00000 |
| 54 | 0.89289 | -0.00711 |

**第 5 步 误差度量**（均方误差 MSE）：

$$ \text{MSE}=\tfrac{1}{5}\big(0^2+0.00551^2+0.00472^2+0^2+0.00711^2\big)=\tfrac{1}{5}(9.857\times10^{-5})=1.97\times10^{-5} $$

注意端点 $-2.1$（恰好等于 $-\alpha$）量化误差为 0，这是对称量化端点必然对齐的特性。

### 7.2 非对称（zero-point，INT8 → [-128,127]）

**第 1 步 真实范围**：$r_{min}=-2.1,\ r_{max}=1.5$。

**第 2 步 scale**：$S=\dfrac{r_{max}-r_{min}}{q_{max}-q_{min}}=\dfrac{1.5-(-2.1)}{127-(-128)}=\dfrac{3.6}{255}=0.014118$。

**第 3 步 zero-point**：$Z=\mathrm{round}\!\big(q_{min}-\tfrac{r_{min}}{S}\big)=\mathrm{round}\!\big(-128-\tfrac{-2.1}{0.014118}\big)=\mathrm{round}(-128+148.75)=21$。

**第 4 步 量化** $q=\mathrm{round}(r/S)+Z$：

| $r$ | $r/S$ | $+Z$ | $q$ |
| --- | --- | --- | --- |
| 0.0 | 0.0 | 21 | 21 |
| -0.7 | -49.58 | -28.58 | -29 |
| 1.5 | 106.25 | 127.25 | 127（clip） |
| -2.1 | -148.75 | -127.75 | -128 |
| 0.9 | 63.75 | 84.75 | 85 |

**第 5 步 反量化** $\hat r=S(q-Z)$，例如 $r=0.9$：$\hat r=0.014118\,(85-21)=0.014118\times64=0.90353$，误差 $+0.00353$。逐项算完 MSE $\approx 1.5\times10^{-5}$。

**结论对比**：本例非对称略优，因为分布偏负（$-2.1$ 比 $+1.5$ 远），对称的 $\alpha=2.1$ 让正半轴只用到了 $1.5/2.1\approx71\%$ 的网格。**数据越偏斜，非对称的优势越大**——这正是激活倾向非对称的实证。

## 8. PTQ vs QAT

量化插入训练流程的时机不同，分两大类。

```
PTQ (训练后量化)                          QAT (量化感知训练)
┌──────────┐  小校准集   ┌────────┐       ┌──────────┐  插入伪量化  ┌────────┐
│训练好的   │ ─────────▶ │ 统计S,Z │       │训练好的   │ ─────────▶ │继续训练 │
│FP 模型    │            │直接量化 │       │FP 模型    │  反传更新   │权重适应 │
└──────────┘            └────────┘       └──────────┘            └────────┘
 几分钟~几小时, 无需训练数据梯度            需要训练资源, 精度上限更高
```

| 维度 | PTQ | QAT |
| --- | --- | --- |
| 是否需要反向训练 | 否（只前向跑校准集） | 是 |
| 计算成本 | 低（分钟级） | 高（重新训练/微调） |
| 精度（尤其低比特） | 中，INT8 常无损，INT4 可能掉点 | 高，INT4 也能拉回 |
| LLM 现状 | 主流（GPTQ/AWQ/SmoothQuant 都是 PTQ） | 成本太高，LLM 上少用 |

**QAT 的关键技巧——直通估计器 STE（Straight-Through Estimator）**：量化里的 $\mathrm{round}$ 处处导数为 0，梯度没法回传。STE 在前向用真量化、反向时**假装 round 的导数是 1**（梯度直接穿过），从而让权重能感知量化误差并被训练所补偿。这是 QAT 能 work 的数学核心。

**为什么 LLM 偏爱 PTQ**：重新训百亿参数代价太大，而 GPTQ/AWQ 这类"逐层补偿型 PTQ"已能在 INT4 上做到接近无损——见 [[llm-compression/quantization/GPTQ]]。

## 9. INT8 / INT4 / FP8 概览

```
INT8   均匀网格, 256 级    成熟稳, 激活+权重通用, 推理首选基线
INT4   均匀网格, 16 级     权重专用, 必配 per-group + 补偿(GPTQ/AWQ), 显存杀手
FP8    浮点(E4M3/E5M2)     非均匀, 动态范围大, 训练+推理皆可, 需硬件支持(Hopper+)
```

| 格式 | 比特 | 表示方式 | 典型用途 | 关键权衡 |
| --- | --- | --- | --- | --- |
| INT8 | 8 | 均匀整数 | 激活+权重，PTQ 基线 | 对离群值敏感，需 SmoothQuant 类手段平滑激活 |
| INT4 | 4 | 均匀整数 | **权重**量化 | 仅 16 个级，必须 per-group+逐层补偿；激活一般不做 INT4 |
| FP8 E4M3 | 8 | 1+4+3 浮点 | 高精度需求的激活/权重 | 范围 ±448，精度高于 E5M2 |
| FP8 E5M2 | 8 | 1+5+2 浮点 | 梯度/大动态范围 | 范围更大、精度更低，像低配 BF16 |

**FP8 为什么和 INT8 不同**：同样 8 比特，**INT8 是均匀的、FP8 是非均匀的**。FP8 用指数段换来"小值密、大值疏"，天然适配 LLM 激活那种"大部分值很小、少数离群值很大"的长尾分布——离群值不会像 INT8 那样把整组 scale 撑爆。代价是硬件得原生支持 FP8 Tensor Core（NVIDIA Hopper/Ada 起）。细节见 [[llm-compression/quantization/fp8]]。

**选型直觉**：
- 想稳、想快、想兼容广 → **INT8**（激活配 SmoothQuant，权重 per-channel）。
- 显存极度紧张、只压权重 → **INT4**（per-group + GPTQ/AWQ）。
- 有 Hopper 卡、要兼顾训练与精度 → **FP8**。

## 复杂度 / 精度对照表

| 方案 | 每参数字节 | 70B 显存 | 相对 FP16 精度损失 | 主要门槛 |
| --- | --- | --- | --- | --- |
| FP16/BF16 | 2 | 140 GB | 0（基线） | — |
| FP8 | 1 | 70 GB | 很小 | 需 Hopper+ 硬件 |
| INT8 (W8A8) | 1 | 70 GB | 小（激活需平滑） | 离群值处理 |
| INT4 (W4A16) | 0.5 | 35 GB | 中（靠补偿拉回） | per-group + GPTQ/AWQ |

> 记法 **WxAy**：权重 x 比特、激活 y 比特。W4A16 = 4 比特权重、16 比特激活（最常见的省显存配置）；W8A8 = 权重激活都 8 比特（省算力+显存）。

## 常见问题

| 疑问 | 真相 |
| --- | --- |
| 量化是不是直接"砍小数位"？ | 不是。是仿射映射 $r=S(q-Z)$，靠 round 取整，端点对齐范围而非简单截断。 |
| 对称量化一定比非对称差吗？ | 否。权重近零均值对称分布时对称更优且更快；偏斜分布（激活）才轮到非对称。 |
| zero-point 为什么必须是整数？ | 为了让实数 0 能被精确表示/反量化（ReLU、padding 依赖精确 0），避免系统性偏差。 |
| per-tensor 为什么在 LLM 激活上掉点？ | 激活有少数巨大离群值撑大 $\alpha$，全张量共享一个 scale 导致正常值分辨率塌缩。 |
| INT4 为什么要 per-group？ | 仅 16 个量化级，粒度不细就溢出严重；per-group 用极小存储开销换回精度。 |
| 同是 8 比特，FP8 凭啥比 INT8 抗离群值？ | FP8 有指数段是非均匀的，大值稀疏不会撑爆 scale；INT8 均匀，离群值会拖垮整组。 |
| PTQ 和 QAT 选哪个？ | LLM 几乎全用 PTQ（重训太贵），QAT 仅在极低比特且能承担训练成本时考虑。 |
| 量化误差能完全消除吗？ | 不能，round 必然丢信息；只能靠细粒度、好校准、逐层补偿把误差压到不影响精度。 |
