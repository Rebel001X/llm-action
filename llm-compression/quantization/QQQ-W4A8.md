## 0. 一句话锚点

一句话：**QQQ = 权重存成 4bit、激活算成 8bit，矩阵乘法在 INT8 Tensor Core 上跑。**

- "权重 4bit" → 模型文件小一半（相对 W8），显存占用小，**权重搬运（memory-bound 的 decode 阶段）更快**。
- "激活 8bit" → 矩阵乘法的两个操作数都是 INT8 → 能用 GPU 的 **INT8 Tensor Core**（峰值算力约为 FP16 的 2 倍，**compute-bound 的 prefill / 大 batch 阶段**更快）。
- 关键难点：W4 和 A8 的"数"位宽不一样，硬件 MMA 指令需要两边等宽。QQQ 的工程核心就是**在 kernel 里把 W4 实时升位成 W8，再做 INT8×INT8 的乘累加**，且这一步几乎不花额外时间。

一句话对比记忆：

```
W4A16 = 省显存、不省算力（激活还是 FP16，走不了 INT8 Tensor Core）
W8A8  = 省算力、不够省显存（权重还是 8bit，模型仍偏大）
W4A8  = 显存按 W4 省 + 算力按 A8 提  ← QQQ 的甜点
```

## 1. 地基 / 前置（不假设你记得公式）

### 1.1 什么叫"量化"

把一个浮点数 $x$（FP16/FP32）映射成低位整数 $q$，乘一个比例因子 $s$（scale）就能近似还原：

$$ q = \mathrm{round}\!\left(\frac{x}{s}\right),\qquad \hat{x} = s\cdot q $$

- $s$ 决定"一格代表多大"。$s$ 越小越精细，但能表示的最大值越小。
- $b$ bit 的有符号整数范围约 $[-2^{b-1},\,2^{b-1}-1]$。
  - INT8 → $[-128,127]$
  - INT4 → $[-8,7]$（仅 16 个台阶！精度天然吃紧）

对称量化用上式（零点固定在 0）；非对称量化再加一个零点 $z$：$q=\mathrm{round}(x/s)+z$。

### 1.2 scale 粒度（granularity）——QQQ 反复用到

```
per-tensor   : 整个张量 1 个 scale     → 最快, 最糙
per-channel  : 每个输出通道(行/列)1个   → 折中
per-group    : 每 g 个元素 1 个(如 g=128)→ 最精细, 元数据最多
```

直觉：离群值越严重，越需要细粒度 scale 来"局部兜底"。QQQ 的**权重**通常用 **per-group（如 group=128）或 per-channel**；**激活**用 **per-token（每个 token 一行一个 scale）的 INT8 动态量化**。

### 1.3 这页要记住的三件事

1. INT4 只有 16 个台阶，**权重量化误差是 QQQ 的主要精度风险**。
2. 激活里有"离群通道"（值特别大），**直接 A8 会被离群值撑大 scale，淹没正常值**。
3. 硬件喜欢"两边等宽"的整数乘法——这是 W4A8 必须解决的工程矛盾。

## 2. "位宽组合"全景：W4A16 / W8A8 / W4A8

记号：`W=权重位宽, A=激活位宽`。

```
            权重存储     激活计算     矩阵乘硬件         主要收益          主要痛点
W16A16(基线) FP16        FP16        FP16 Tensor Core   —                 显存大/算力基线
W8A8        INT8        INT8        INT8 Tensor Core   算力↑(~2x) 带宽↑   权重仍 8bit, 偏大
W4A16       INT4        FP16        FP16 (需反量化W)   显存↓↓ decode 快   prefill/大batch 不快
W4A8 (QQQ)  INT4        INT8        INT8 Tensor Core   显存↓↓ + 算力↑     工程难: W4→W8 升位
```

### 2.1 W4A16（GPTQ / AWQ 的典型落地形态）

- 权重 INT4 存盘，**推理时把 W 反量化回 FP16**，再和 FP16 激活做 FP16 GEMM。
- 好处：decode 阶段是 **memory-bound**（瓶颈是搬权重），W4 把权重搬运量砍半 → 单请求 token 生成快。
- 短板：算力侧仍是 FP16 GEMM，**走不了 INT8 Tensor Core**；prefill 长序列、大 batch（compute-bound）时不占便宜。

### 2.2 W8A8（SmoothQuant 的典型形态）

- 权重、激活都 INT8 → 两边等宽，直接喂 INT8 Tensor Core，**算力翻倍、带宽减半**。
- 短板：权重仍 8bit，模型体积是 W4 的两倍；显存敏感（如长上下文 KV、单卡塞大模型）时不够省。

### 2.3 W4A8（QQQ）：要两头好处

- 权重 INT4（显存/带宽按 W4 省）+ 激活 INT8（算力按 A8 提）。
- **代价**：MMA 指令要求两操作数等宽，于是必须在 kernel 内把 W4 即时升位到 W8。这正是 QQQ 工程贡献的核心。

## 3. 为什么 W4A8 能同时"省显存 + 高算力"

把推理拆成两个阶段看（这是理解一切量化收益的关键）：

```
Prefill (处理长 prompt) ─ 大矩阵乘 ─ compute-bound ─ 瓶颈=算力(FLOPs)
Decode  (逐 token 生成) ─ 小矩阵乘 ─ memory-bound  ─ 瓶颈=搬权重(带宽)
```

- **Decode 看带宽**：每生成 1 个 token，要把整套权重从显存读一遍。W4 比 W8 少搬一半字节 → decode 快。W4A16 已能拿到这一份。
- **Prefill / 大 batch 看算力**：激活是 INT8 才能点亮 INT8 Tensor Core（峰值约 2× FP16）。W4A16 的激活还是 FP16，拿不到这份；W8A8 能拿，但它权重 8bit、decode 带宽收益减半。

**QQQ 的算盘**：用 W4 拿满 decode 的带宽收益，用 A8 拿满 prefill/大 batch 的算力收益——两个阶段都不亏。

```
          decode带宽收益   prefill算力收益
W4A16          ✔(满)            ✘
W8A8           ~(半)            ✔
W4A8(QQQ)      ✔(满)            ✔     ← 两头都要
```

> 当然没有免费午餐：W4A8 比 W4A16 多了"激活也要量化"的精度风险（离群值），且 kernel 更复杂。下面两节就是 QQQ 怎么把这两个代价压住。

## 4. 激活离群值（outlier）：A8 的最大障碍 + QQQ 的平滑

### 4.1 为什么离群值要命

LLM（尤其 GLU / 残差后）某些**激活通道**的幅值比其他通道大几十上百倍。per-tensor / per-token 的 INT8 量化要覆盖最大值，scale 被这几个大通道撑大：

```
正常通道值 ~ ±2     离群通道值 ~ ±200
若共用一个 scale 覆盖到 200:
   一格 ≈ 200/127 ≈ 1.57
   正常通道的 ±2 只落在 ≈ ±1 格里 → 几乎全被量化噪声吃掉 → 精度崩
```

### 4.2 SmoothQuant 思路（QQQ 沿用并增强）

核心：**把"难量化的激活"难度搬一部分给"好量化的权重"**。对某条通道乘缩放 $s_j$：

$$ Y = (X \,\mathrm{diag}(s)^{-1})\cdot(\mathrm{diag}(s)\,W) = \hat{X}\,\hat{W} $$

- $X$ 的离群通道除以 $s_j$（变小，好量化）；$W$ 的对应通道乘 $s_j$（变大，但权重分布本就平整，承受得起）。
- $s_j$ 取在"激活峰值"和"权重峰值"之间平衡（迁移强度超参 $\alpha$）。这一步是**等价变换**（数学上乘积不变），属于**离线**操作，推理时不额外花时间。

```
   激活X (有离群)            平滑后 X̂ (平整)
   ┌────────────┐  ÷ s_j    ┌────────────┐
   │ ▁▁█▁▁▁█▁▁  │  ───────► │ ▁▁▁▁▁▁▁▁▁  │  → INT8 好量化
   └────────────┘           └────────────┘
   权重W (平整)              W̃ = diag(s)·W (略放大, 仍可控)
   ┌────────────┐  × s_j    ┌────────────┐
   │ ▁▁▁▁▁▁▁▁▁  │  ───────► │ ▁▁▃▁▁▁▃▁▁  │  → INT4 量化(配重排+GPTQ)
   └────────────┘           └────────────┘
```

> QQQ 相对单纯 SmoothQuant 的增强点：激活更激进（A8 已是标配）的同时，权重压到 4bit 需要更强的权重侧手段（见第 5 节的"自适应重排 + GPTQ"），否则平滑迁移给权重的"额外幅值"会在 INT4 的 16 台阶上放大误差。

## 5. 自适应权重重排（adaptive reordering）+ GPTQ 取整

W4 只有 16 个台阶，量化误差天然大。QQQ 在权重侧叠两层手段。

### 5.1 自适应通道重排（adaptive channel reordering）

问题：per-group 量化把"相邻通道"打包共用一个 scale。如果一个 group 里既有大幅通道又有小幅通道，scale 又被大值撑大，小值被淹没——和激活离群同理，只是发生在权重的"组内"。

QQQ 的办法：**按某种重要性/幅值把通道重新排列**，让"幅值相近"的通道聚到同一 group，使每个 group 的 scale 更贴合本组数据。

```
重排前 (组内混杂, scale被大值撑大):
 group0:[ 大  小  大  小 ]  scale过大→小值丢精度
重排后 (相近的聚一起, scale各自贴合):
 group0:[ 大  大  大  大 ]  scale适配大值
 group1:[ 小  小  小  小 ]  scale适配小值 → 整体误差↓
```

- "自适应"指排列方式不是固定的，而是依数据（如 Hessian/激活统计）选出。
- 重排是**离线**做的，会记录一个置换索引；推理时通过对激活/输出做对应的索引调整来保持等价（不破坏正确性）。

### 5.2 GPTQ 式逐列误差补偿取整

不是各权重独立四舍五入，而是**逐列量化并把误差补偿到尚未量化的列**（基于二阶 Hessian 信息）：量化第 $j$ 列后，把它的取整误差按相关性"摊"到后面的列上，整体重建误差更小。这是 W4 在 16 台阶下还能保持精度的关键之一。参见 [[llm-compression/quantization/GPTQ]]。

```
列1量化→产生误差 e1 →把 e1 补偿进 列2..列n
列2量化(已含e1补偿)→误差 e2 →补偿进 列3..列n
... 误差不堆积, 整体 ‖WX - ŴX‖ 更小
```

### 5.3 这一节小结

QQQ 权重侧 = **平滑（迁移幅值）→ 自适应重排（理顺组内分布）→ GPTQ 取整（误差补偿）**，三者叠起来才把 INT4 的精度损失压到可接受。

## 6. 反量化路径：W4A8 在哪里变成 W8A8

硬件 MMA（如 Tensor Core 的 `mma.m16n8k32` 类 INT8 指令）要求两个操作数都是 INT8。QQQ 的策略：**权重以 INT4 存放与搬运，进了计算单元前即时升位（unpack）成 INT8**。

```
显存(GPU DRAM)            片上(寄存器/共享内存)        计算单元
┌──────────────┐  load   ┌──────────────────┐        ┌─────────────┐
│ W: INT4 packed│ ──────► │ unpack INT4→INT8  │ ─────► │ INT8 × INT8 │
│ (省带宽:半字节)│         │ (移位/查表, 廉价)  │        │  MMA 累加    │
└──────────────┘         └──────────────────┘        └─────────────┘
                          ▲                                  │
   X: INT8 (per-token)────┘                                  ▼
                                                  INT32 部分和 → 反量化
                                                  ×(s_W · s_X) → FP16 输出
```

关键点：

- **W 的"小"只体现在搬运链路**（DRAM→片上），半字节传输省带宽——decode 收益来自这里。
- **升位发生在片上**，用位移/查表把每个 INT4 摊成 INT8，几乎不增加访存，只是少量 ALU 操作，被 MMA 的算力掩盖（latency hiding）。
- 乘累加在 **INT8 Tensor Core** 上完成，结果是 INT32 部分和；最后乘回 **权重 scale × 激活 scale** 反量化成 FP16/BF16。
- 因为做了第 4 节的"激活平滑"和第 5 节的"通道重排"，这里的 scale 应用要按对应粒度/置换正确组装——这正是 QQQ 专用 kernel 要处理的细节。

## 7. W4A8 GEMM Kernel：速度从哪来

一句话：通用框架没有"现成的 W4A8 GEMM"，QQQ 自己写了一个，把"INT4 解包 + per-group 权重 scale + per-token 激活 scale + INT8 MMA"融合（fuse）在一个 kernel 里，避免来回读写显存。

```
        ┌────────────────────── QQQ W4A8 GEMM (融合) ──────────────────────┐
        │                                                                  │
  W INT4│  global→shared      unpack       ┌── INT8 MMA (Tensor Core) ──┐  │
 (packed│  (向量化加载,省带宽) INT4→INT8 ─► │  ΣX·W  → INT32 accumulate  │  │
        │                                  └────────────┬───────────────┘  │
  X INT8│  global→shared ─────────────────────────────► │                  │
(per-tok│                                                ▼                  │
  scale)│        epilogue:  acc(INT32) × s_W(per-group) × s_X(per-token)   │
        │                   (+ 反置换 reorder) → FP16/BF16 输出             │
        └──────────────────────────────────────────────────────────────────┘
```

收益拆解：

| 来源 | 机制 | 收益面 |
|------|------|--------|
| INT4 权重搬运 | DRAM→shared 只搬半字节 | decode/带宽 |
| INT8 Tensor Core | 两操作数等宽，峰值≈2×FP16 | prefill/大 batch/算力 |
| 融合 epilogue | unpack/scale/reorder 不落显存 | 减少访存往返 |
| per-token 动态激活量化 | 每行自适配，精度好且无需校准激活 | 精度 |

> 实测层面：QQQ 论文/仓库报告在主流大模型与 GPU（如 A100/L40 级）上，相对 FP16 取得可观的端到端吞吐提升，且在多数任务精度接近 W8A8、明显优于朴素 W4A8。**具体倍数随模型、序列长度、batch、GPU 而变，请以官方基准为准**，不在此编造精确数字。

何时选 QQQ（W4A8）：

```
显存吃紧(想要 W4 体积) 且 又是 compute-bound 场景(长 prefill / 大并发 batch)
→ W4A8 是甜点
若纯单请求短输出(纯 decode/带宽) → W4A16 往往已够
若显存充裕只求算力           → W8A8 更简单稳妥
```

## 数值例子 / 手算对照

### 例 1：INT4 vs INT8 的"台阶"直觉

设某权重通道最大绝对值 $\max|w| = 0.8$，对称量化。

- **INT8**：$s = 0.8/127 \approx 0.0063$。一个真实值 $w=0.31$：$q=\mathrm{round}(0.31/0.0063)=\mathrm{round}(49.2)=49$，还原 $\hat w = 49\times0.0063 = 0.3087$，误差 ≈ 0.0013。
- **INT4**：$s = 0.8/7 \approx 0.1143$。同一个 $w=0.31$：$q=\mathrm{round}(0.31/0.1143)=\mathrm{round}(2.71)=3$，还原 $\hat w = 3\times0.1143 = 0.3429$，误差 ≈ 0.033。

**误差放大约 25 倍** → 这就是为什么 W4 必须叠加平滑/重排/GPTQ 来补救，而 A8（误差小）则放心交给 Tensor Core。

### 例 2：激活离群导致 scale 被撑大（呼应第 4 节）

某 token 的激活向量（8 维示意）：`[1.8, -2.1, 1.5, 180, -1.9, 2.0, -1.7, 1.6]`，离群在第 4 维。

- 直接 per-token INT8：$s = 180/127 \approx 1.417$。正常值 $1.8$：$q=\mathrm{round}(1.8/1.417)=1$，还原 $1.417$，误差 ≈ 0.38（相对误差 21%！）。
- 经平滑把第 4 维 ÷ $s_4$（如 $s_4=64$）→ 该维变 $\approx 2.8$，整向量峰值降到约 $2.8$ → $s = 2.8/127 \approx 0.022$。正常值 $1.8$：$q=82$，还原 $1.804$，误差 ≈ 0.004。
- **正常通道相对误差从 ~21% 降到 ~0.2%**——平滑把"被离群撑大的 scale"救了回来。

### 例 3：W4A8 与 W4A16 / W8A8 的资源账（per-tensor 量级估算，仅示意）

设某线性层权重 $4096\times4096$。

| 方案 | 权重字节(≈) | 权重相对带宽 | MMA 算力 |
|------|------------|------------|---------|
| FP16 | 16M·2 = 32 MB | 1.0× | FP16 (1×) |
| W8A8 | 16M·1 = 16 MB | 0.5× | INT8 (≈2×) |
| W4A16 | 16M·0.5 = 8 MB | 0.25× | FP16 (1×) |
| **W4A8** | **16M·0.5 = 8 MB** | **0.25×** | **INT8 (≈2×)** |

（group scale 等元数据为小量，忽略。）W4A8 在"权重带宽"和"算力"两栏都拿到最优档位——这张表就是 QQQ 整个动机的浓缩。

## 常见问题（FAQ）

| 问题 | 回答 |
|------|------|
| QQQ 和 SmoothQuant 的关系？ | QQQ **沿用** SmoothQuant 的激活-权重幅值迁移（等价变换）来平滑离群，但把权重压到 4bit，并叠加自适应重排 + GPTQ。SmoothQuant 本身是 W8A8。 |
| QQQ 和 GPTQ/AWQ 的关系？ | GPTQ/AWQ 多为 **W4A16**（激活 FP16）。QQQ 借用 GPTQ 式误差补偿取整做权重，但激活做 INT8，从而点亮 INT8 Tensor Core。 |
| 为什么不直接 W4A4？ | A4 离群更难压、台阶太少，精度普遍崩；硬件 INT4 算力支持也更受限。A8 是"精度/算力"更稳的折中。 |
| 激活要不要校准集？ | QQQ 激活用 **per-token 动态量化**（运行时按每行算 scale），不依赖离线激活校准；权重的平滑/重排/GPTQ 需要少量校准数据。 |
| W4A8 一定比 W4A16 快吗？ | 不一定。纯 decode/单请求（memory-bound）两者接近；在 prefill / 大 batch（compute-bound）W4A8 靠 INT8 Tensor Core 才显著领先。 |
| 升位 INT4→INT8 不会拖慢吗？ | 升位是片上廉价的位移/查表，开销被 MMA 算力掩盖；省下的是 DRAM→片上的搬运带宽，净收益为正。 |
| 精度大概什么水平？ | 论文报告多数任务接近 W8A8、远好于朴素 W4A8；具体掉点随模型/任务而变，**以官方评测为准**。 |
| 通道重排会破坏正确性吗？ | 不会。重排是等价置换，离线记录索引，推理时在激活/输出侧做对应反置换保持数学等价。 |
