## 0. 一句话锚点

**FP8 = 8 位的浮点数。** 它不像 INT8 那样把数轴切成等距的格子，而是像 FP16/FP32 一样用 `符号 × 尾数 × 2^指数` 表示数，只是把总位数压到 8 位。代价是只剩两种实用切分：**E4M3**(4 位指数 + 3 位尾数，精度优先)和 **E5M2**(5 位指数 + 2 位尾数，范围优先)。在 Hopper(H100)、Blackwell 等带 FP8 Tensor Core 的硬件上，FP8 矩阵乘吞吐约为 FP16 的 2 倍、FP32 的 4 倍，且显存/带宽减半。

## 1. 地基：一个浮点数是怎么用二进制编码的

不假设你记得 IEEE-754。我们从最原子的事实开始：**任何浮点数 = 符号位 S + 指数字段 E + 尾数字段 M**。

```
 ┌─┬───────────┬──────────────┐
 │S│  exponent │   mantissa   │
 └─┴───────────┴──────────────┘
  1     k bits       m bits
```

解码规则(归一化/normal 数)：

$$ \text{value} = (-1)^S \times \left(1 + \frac{M}{2^m}\right) \times 2^{(E - \text{bias})} $$

逐项拆开，每一项**为什么这样设计**：

- **$(-1)^S$**：1 位符号，0 为正、1 为负。和正负无关精度，只是方向。
- **$\big(1 + \frac{M}{2^m}\big)$ —— 尾数(significand)**：注意那个隐含的 `1.`。归一化浮点数总把数写成 `1.xxxx × 2^e` 的形式(就像科学计数法 $1.\dots\times 10^e$)，所以整数部分恒为 1，**不存**，白送一位精度。`M` 是小数点后的二进制位，决定**相对精度**(同一指数档内能区分多细)。
- **$2^{(E-\text{bias})}$ —— 指数**：决定数的**量级/动态范围**。`bias`(偏置)是为了让指数字段能表示负指数：字段是无符号整数 $0\dots 2^k-1$，减掉 bias 后才能取到负值。通常 $\text{bias}=2^{k-1}-1$。
- **subnormal(次正规数)**：当 $E=0$ 时规则变为 $(-1)^S\times\frac{M}{2^m}\times 2^{1-\text{bias}}$(隐含位变 0)，用来表示**比最小 normal 还小**的数，避免在 0 附近突然「掉到 0」。

**核心直觉**：指数位多 → 范围宽；尾数位多 → 精度高。8 个 bit 是固定预算，**两者此消彼长**。这就是为什么 FP8 必须分裂成两种格式。

## 2. E4M3 与 E5M2：位分配与动态范围

8 位预算 = 1 符号 + 指数 + 尾数。两种主流切法(OCP / NVIDIA-Arm-Intel 联合标准)：

```
E4M3 (精度优先, bias=7)        E5M2 (范围优先, bias=15)
 ┌─┬─┬─┬─┬─┬─┬─┬─┐             ┌─┬─┬─┬─┬─┬─┬─┬─┐
 │S│ E E E E │ M M M │         │S│ E E E E E │ M M │
 └─┴─────────┴───────┘         └─┴───────────┴─────┘
  1    4         3              1      5        2
```

把每种格式的边界数算出来(这些数务必记住)：

| 量 | E4M3 | E5M2 | 怎么来的 |
|---|---|---|---|
| 指数位 / 尾数位 | 4 / 3 | 5 / 2 | 位分配 |
| bias | 7 | 15 | $2^{k-1}-1$ |
| 最大正规数 | **448** | **57344** | 见下 |
| 最小正规数 | $2^{-6}\approx 0.0156$ | $2^{-14}\approx 6.1\times10^{-5}$ | $2^{1-\text{bias}}$ |
| 最小次正规数 | $2^{-9}\approx 1.95\times10^{-3}$ | $2^{-16}\approx 1.53\times10^{-5}$ | $\frac{1}{2^m}2^{1-\text{bias}}$ |
| 同档相对步长(尾数 ULP) | $2^{-3}=12.5\%$ | $2^{-2}=25\%$ | $2^{-m}$ |
| 特殊值约定 | 无 Inf；仅 `S.1111.111`=NaN | 有 Inf/NaN(IEEE 风格) | OCP 约定 |

**E4M3 最大值为什么是 448 而不是 IEEE 那套？** E4M3 牺牲了 Inf 来多换一个有效指数。最大指数字段 1111 不全保留给 Inf，只有尾数全 1 那个码点 `S.1111.111` 当 NaN，其余可用：

$$ \max = \left(1+\frac{6}{8}\right)\times 2^{(15-7)} = 1.75 \times 2^{8} = 1.75\times 256 = 448 $$

**E5M2 走 IEEE 风格**，指数字段全 1(=31)整档保留给 Inf/NaN，最大正规指数字段是 30：

$$ \max = \left(1+\frac{3}{4}\right)\times 2^{(30-15)} = 1.75 \times 2^{15} = 1.75\times 32768 = 57344 $$

**动态范围对比**(最大/最小正规之比，量级跨度)：

```
E4M3:  448 / 0.0156  ≈ 2.9e4   动态范围窄, 但每档分 8 级(尾数3位)→精度高
E5M2:  57344 / 6.1e-5 ≈ 9.4e8  动态范围宽, 但每档只分 4 级(尾数2位)→精度粗
FP16:  ~6.5e4 / 6e-5  指数5位, 尾数10位 → 又宽又准, 但要16位
```

一句话记忆：**E4M3 像近视眼镜(看得细、看不远)，E5M2 像望远镜(看得远、看不细)。**

## 3. 为什么 FP8 能「兼顾」范围与精度(而 INT8 不能)

关键在**浮点数的步长是相对的**，整数的步长是绝对的。

```
INT8 (对称, scale=s): 数轴被切成 256 个【等距】格子, 间距恒为 s
   |----|----|----|----|----|----|----     间距处处相同
   小数和大数用同样粗的尺子量 → 小数被淹没

FP8: 每跨一个 2 的幂, 步长翻倍(指数变), 档内再等分(尾数)
   |-|-|-| |--|--|--| |----|----|----|       近 0 处密, 远处疏
   0  0.25     0.5         1            2
   小数用细尺、大数用粗尺 → 相对误差恒定
```

数学上，FP8 的**相对量化误差**近似恒定：

$$ \frac{|x - \hat{x}|}{|x|} \lesssim 2^{-(m+1)} \quad(\text{尾数 } m \text{ 位}) $$

E4M3 约 $2^{-4}=6.25\%$ 上界(平均更小)，**与 $x$ 的大小无关**。这正是神经网络想要的：网络里的权重/激活/梯度往往**横跨好几个数量级**(梯度尤其有长尾)，而我们关心的是**相对**误差(信噪比)而非绝对误差。

- **范围**来自指数位 → 不会因为出现一个大激活就溢出(clip)。
- **精度**来自「相对步长恒定」→ 小数不会被舍入成 0(下溢)。

INT8 两头不讨好：要么 scale 大(能覆盖大数但小数全归 0)，要么 scale 小(小数精细但大数被截断)。FP8 用指数位天然化解了这个矛盾——**这就是「The Power of the Exponent」**(论文标题)。

## 4. Scaling：FP8 的灵魂操作

E4M3 的可用范围只到 448，最小正规数才 0.0156。真实张量的数值范围常常**不在这个窗口里**(比如权重多在 ±0.1，梯度可能小到 1e-6)。若直接塞进 FP8：大数 clip、小数下溢成 0，全废。

**解决：先乘一个缩放因子 scale，把张量「搬」到 FP8 的甜区，算完再除回来。**

```
原始张量 x  ──×scale──►  x_scaled  ──round──►  FP8  ──存储/计算
  (量级乱)                (落进[~0.02, 448])         (8-bit)
                                                        │
反量化: x ≈ FP8_value / scale  ◄────────────────────────┘
```

**怎么选 scale？** 最常见是 **amax(absmax) 缩放**：让张量绝对值最大者刚好顶到 FP8 上限。

$$ \text{scale} = \frac{\text{FP8\_MAX}}{\max(|x|)} = \frac{448}{\text{amax}} \quad(\text{E4M3}) $$

**逐数手算(amax 缩放)**：设某权重块 $x = [0.001,\ 0.42,\ 3.1,\ 127.0,\ 0.0008]$。

- $\text{amax} = 127.0$
- $\text{scale} = 448 / 127.0 \approx 3.528$
- 缩放后 $x' = [0.00353,\ 1.482,\ 10.94,\ 448.0,\ 0.00282]$
  - 最大值 127.0 → 正好 448(顶满，不溢出 ✓)
  - 最小值 0.0008 → 0.00282 > E4M3 最小次正规 0.00195 ✓ **没被冲成 0**
  - 若**不缩放**直接量化，0.0008 < 0.00195 会下溢成 **0**，信息全丢。
- 计算 $y = Wx$ 时用 FP8 算，结果再除以 scale 还原。

**粒度(granularity)——FP8 训练成败的关键**：

```
per-tensor  : 整张量共享 1 个 scale  ──最省, 但被离群值绑架
per-channel : 每行/列一个 scale      ──INT8 常用
per-block   : 每 N×N 小块一个 scale  ──DeepSeek-V3 用 1×128 / 128×128
per-token   : 激活每个 token 一个     ──激活动态范围大时用
```

块越细，离群值的「污染半径」越小 → 精度越高，但 scale 元数据和 dequant 开销越大。DeepSeek-V3 选 **细粒度 block-wise scaling** 正是为了在 FP8 这么窄的格式里压住离群值。

**delayed scaling(延迟缩放)**：amax 要先扫一遍张量才知道，开销大。工程上常用**历史 amax 的滑动窗口**预测当前 scale，避免额外一次遍历——这是 Transformer Engine 等库的标准技巧(具体实现以官方文档为准)。

## 5. FP8 训练：以 DeepSeek-V3 为例

FP8 训练比推理难得多，因为**前向、反向、梯度**三条数据流的数值特性完全不同：

```
                       前向 (activations, weights)
 输入 x ──[FP8 GEMM]──► 激活 a ──...──► loss
   ▲                                      │
   │            反向 (gradients) — 长尾、量级小、需要范围
   └──────────[FP8 GEMM]◄─────────────────┘

经验法则:
  权重/激活 GEMM   → E4M3 (要精度)
  梯度            → E5M2 (要范围, 防梯度下溢)
  主权重/优化器状态 → 仍用 FP32/BF16 (master weights 高精度累加)
```

**为什么梯度偏爱 E5M2？** 反向传播里梯度常有长尾且整体偏小，一旦下溢成 0，参数就不更新了(等价于学习停滞)。E5M2 的指数位多 1 位、动态范围大 4 个数量级，更能兜住小梯度——这是 OCP/NVIDIA 给的经验分工。

**DeepSeek-V3 的 FP8 训练要点**(论文 / 技术报告，细节以官方为准)：

1. **细粒度 block-wise 量化**：激活按 `1×128` tile、权重按 `128×128` block 各自算 scale，而非 per-tensor。把离群值关进小块里，单个大值不再拖垮整张量。
2. **高精度累加(accumulation)**：FP8 只用在 GEMM 的**输入**；Tensor Core 内部乘加的**累加器走更高精度**(FP32/BF16)，再周期性提升到 CUDA Core 累加，避免 8-bit 累加的误差雪崩。
3. **混合格式**：前向 E4M3、敏感处保 BF16；优化器一阶/二阶矩、master weight 仍高精度。
4. **收益**：相比 BF16 训练，FP8 让 GEMM 吞吐近翻倍、显存与通信带宽显著下降，使其能在有限算力下训练超大 MoE。

**ASCII：FP8 GEMM 的「低精度算、高精度攒」**

```
A(FP8) × B(FP8) ─► 乘积(部分积) ─► 累加器(FP32) ─► 输出(BF16/FP8)
   8b     8b         13~16b           32b            还原 scale
   └ 省显存/带宽 ┘   └ 算得快 ┘     └ 防误差累积 ┘
```

## 6. FP8 推理

推理只有前向，比训练简单：

- **权重**离线量化为 E4M3(per-channel 或 per-block scale 预先算好、随模型保存)。
- **激活**在线量化：运行时按 amax 求 scale(per-token 或 per-tensor)。
- **KV Cache** 也可量化到 FP8，显存占用直接减半，长上下文收益巨大。
- **GEMM** 走 FP8 Tensor Core，吞吐约 2× FP16。

```
权重(FP8, 离线)─┐
                ├─► FP8 GEMM ─► 反量化 ─► 下一层
激活(FP8, 在线)─┘    (H100)     (×scale)
KV-Cache(FP8) ──► 注意力, 显存减半
```

**何时用 FP8 推理**：H100/H200/Blackwell 这类有 FP8 Tensor Core 的卡上，大模型(尤其长上下文、KV 占显存)优先 FP8；老卡(无 FP8 单元)上 FP8 反而要软件模拟，不划算，退回 INT8/W4A16。

## 7. FP8 vs INT8

| 维度 | FP8 (E4M3/E5M2) | INT8 |
|---|---|---|
| 表示 | 浮点：指数+尾数 | 定点：等距整数 |
| 步长 | **相对**(近 0 密、远疏) | **绝对**(处处等距) |
| 动态范围 | 宽(E5M2 跨 ~9 个数量级) | 窄(单一 scale 决定) |
| 离群值鲁棒性 | 强(指数自适应) | 弱(一个大值撑大 scale，小数全糊) |
| 用于训练 | **可以**(梯度也能表示) | 几乎不行(范围不够，梯度下溢) |
| 标定/校准 | scale 简单(amax)，常免校准 | 需 calibration / 处理离群(SmoothQuant 等) |
| 硬件 | Hopper+ Tensor Core 原生 | 几乎所有卡都支持 |
| 同位宽精度 | 大数量级跨度场景更稳 | 数值集中、范围已知时反而更省(无指数位浪费) |

**一句话**：数值**横跨多个量级**(激活离群、梯度长尾) → FP8 占优；数值**集中在已知小范围**且硬件无 FP8 单元 → INT8 仍香。训练几乎只能选 FP8，推理两者按硬件取舍。

## 8. 手把手：把一个十进制数算成 FP8(E4M3)

目标：把 **0.3125** 编码成 E4M3。

**第 1 步：写成二进制科学计数法。**
$0.3125 = \frac{5}{16} = 0.0101_2$。把小数点右移到第一个 1 后面：

$$ 0.0101_2 = 1.01_2 \times 2^{-2} $$

**第 2 步：定指数字段。** E4M3 的 bias = 7，真实指数 $e=-2$：

$$ E_{\text{field}} = e + \text{bias} = -2 + 7 = 5 = 0101_2 $$

**第 3 步：定尾数字段。** 去掉隐含的「1.」，小数部分是 $.01_2$，补足 3 位 → $010_2$，即 $M=2$。

**第 4 步：拼起来。** 正数 $S=0$：

```
 S  E E E E   M M M
 0  0 1 0 1   0 1 0     =  0x2A
```

**第 5 步：反解验证。**

$$ (-1)^0 \times \left(1 + \frac{2}{8}\right)\times 2^{(5-7)} = 1.25 \times 2^{-2} = 1.25 \times 0.25 = 0.3125\ ✓ $$

**再来一个有舍入的：把 0.1 编码成 E4M3。**
$0.1 = 1.1001100\ldots_2 \times 2^{-4}$。$E_{\text{field}}=-4+7=3$。尾数取 3 位：`.100`(后面 `1100...` 需舍入；按就近舍入，第 4 位是 1 → 向上进位到 `.101`)。

- 取 `.101` → 值 $=(1+5/8)\times2^{-4}=1.625\times0.0625=0.1015625$，误差 $\approx 1.6\%$。
- 取 `.100` → 值 $=1.5\times0.0625=0.09375$，误差 $\approx 6.25\%$。
- 就近舍入选 `.101`，**相对误差约 1.6%**，正好印证 §3 的「相对误差 $\lesssim 2^{-(m+1)}=6.25\%$」上界。

**结论**：FP8 不能精确表示 0.1(就像 FP32 也不能)，但**相对误差被尾数位锁死**，且**与 0.1 的量级无关**——换成 100 或 0.001，相对误差量级一样。

## 10. 常见疑问

| 疑问 | 真相 |
|---|---|
| FP8 就是 INT8 的浮点版，差不多吧？ | 不。INT8 等距、FP8 不等距。FP8 用指数位换动态范围，离群值/梯度场景完胜 INT8。 |
| E4M3 和 E5M2 选哪个？ | 前向权重/激活用 E4M3(要精度)，反向梯度用 E5M2(要范围防下溢)。 |
| FP8 训练就是把所有东西变 8-bit？ | 否。只有 GEMM 的**输入**是 FP8；累加器、master weight、优化器状态仍是 FP32/BF16。 |
| 为什么必须 scaling？ | 因为 E4M3 窗口只到 448、下到 0.0156，真实张量量级常在窗口外，不缩放就 clip + 下溢全废。 |
| 不缩放最坏会怎样？ | 小数下溢成 0(信息全丢)、大数 clip 成 448(梯度爆/精度崩)。 |
| E5M2 最大值为啥 57344 不是 448？ | E5M2 多 1 位指数(范围 ×~$2^{8}$)、少 1 位尾数(精度 /2)。指数位决定量级。 |
| FP8 能精确表示 0.1 吗？ | 不能，但相对误差被尾数位锁在 ~1.6%，且与数的量级无关。 |
| 老 GPU 上能用 FP8 吗？ | 无 FP8 Tensor Core 的卡只能软件模拟，没有加速收益，不如用 INT8/W4A16。 |
| FP8 推理一定比 INT8 准？ | 数值跨多量级时是；数值集中且校准好时 INT8 也能很准。看分布和硬件。 |
