## 0. 一句话锚点

- **GPTQ = "G(PT 模型的) P(ost-training) T(raining-free) Q(uantization)"**，一种**后训练(post-training)、不需要反向传播、逐层(layer-wise)** 的权重量化方法。
- 核心动作只有一句：**每量化掉一列权重，就立刻把这一列产生的量化误差，按二阶最优的方式"摊"到那一层里还没被量化的列上去。**
- 结果：在 W4(权重 4-bit、激活仍 FP16) 下，OPT/BLOOM/LLaMA 等大模型的困惑度(perplexity)几乎不变；甚至能做到 W3。

## 1. 地基：把每个名词拆到最原子

### 1.1 什么是"量化"
神经网络权重原本是 FP16/FP32 浮点数。量化 = 用更少的比特(如 4-bit，只有 $2^4=16$ 个台阶)去近似表示它们。最朴素的做法是 **RTN(Round To Nearest，四舍五入到最近台阶)**：

$$
\hat{w} = \text{clip}\Big(\text{round}\big(\tfrac{w}{s}\big) + z,\; 0,\; 2^b-1\Big), \qquad s=\frac{w_{\max}-w_{\min}}{2^b-1}
$$

其中 $s$ 是 scale(每台阶代表多大浮点值)，$z$ 是 zero-point(非对称量化里把浮点 0 对齐到哪个整数台阶)。**LLM.int8()、SmoothQuant 本质都属于 RTN**——它们只是在量化前对数值做了缩放/搬移，舍入这一步仍是"各管各、就近取整"。

### 1.2 RTN 的根本缺陷：它"贪心且短视"
RTN 对每个权重**独立**地就近取整，完全不知道：

1. 这个权重在**实际计算 $y=Wx$ 时有多重要**（同样的舍入误差，乘以大的激活就放大成大的输出误差）；
2. 一个权重舍入错了，能不能**让相邻权重反向偏一点来抵消**。

GPTQ 要做的，正是把这两点用数学补回来。

### 1.3 关键视角转换：量化是一个"重建"优化问题
不要再想"逐个权重取整"，而是想"**让这一层的输出尽量不变**"。设某线性层权重 $W \in \mathbb{R}^{d_{row}\times d_{col}}$，喂进一批**校准数据**(几百条样本)得到输入 $X$。目标：

$$
\arg\min_{\widehat{W}} \;\big\| W X - \widehat{W} X \big\|_2^2
\quad\text{s.t. } \widehat{W} \text{ 的每个元素都落在量化网格上}
$$

这就是 GPTQ 的总纲：**不是让权重接近原权重，而是让"权重×激活"的输出接近原输出。**

```
RTN 的世界观:            GPTQ 的世界观:
 w_i ── round ──► ŵ_i     min ‖WX - ŴX‖²
 (每个权重各自就近)        (整层输出对齐, 权重之间可互相补偿)
```

## 2. 为什么"逐层(layer-wise)"

一个 70B 模型几百层，若把整个网络一起优化(端到端，需要反向传播)，显存和算力都扛不住，而且后训练量化的前提就是"**不训练、快**"。

GPTQ 的妥协：**把全网拆成一层层独立的最小二乘子问题**。逐层处理时，"输入 $X$"用上一层(已量化)的真实输出，因此误差不会无限累积。每层内部，问题退化成上面的 $\|WX-\widehat WX\|_2^2$，**可以用线性代数闭式求解，不需要梯度**。

```
 ┌─────┐   X1   ┌─────┐   X2   ┌─────┐
 │ 层1 │ ─────► │ 层2 │ ─────► │ 层3 │ ─► ...
 └─────┘        └─────┘        └─────┘
   ▲ 量化层1 → 用量化后的输出当层2的输入 → 再量化层2 ...
   逐层 "贪心" 推进, 但每层内部是 "最优重建"
```

## 3. 推导核心：从 OBD / OBS / OBQ 到 GPTQ

GPTQ 的数学血统来自一条经典剪枝线：**OBD → OBS → OBC/OBQ**。理解它必须理解"二阶 Taylor + Hessian"。

### 3.1 损失对权重扰动的二阶展开
设层重建损失 $E(W)=\|WX-\widehat WX\|^2$。把权重写成向量 $w$，做小扰动 $\delta w$ 的 Taylor 展开：

$$
\delta E \approx \underbrace{g^\top \delta w}_{\text{一阶}} + \tfrac{1}{2}\,\delta w^\top H\, \delta w
$$

- $g=\partial E/\partial w$ 是梯度。在"已收敛/最优"权重处 $g\approx 0$，所以一阶项扔掉。
- $H=\partial^2 E/\partial w^2$ 是 **Hessian(二阶导矩阵)**：它编码了"扰动每个权重对损失的敏感度，以及权重之间的耦合"。

对最小二乘 $E=\|WX-\widehat WX\|^2$，Hessian 有**漂亮的闭式**：

$$
\boxed{\,H = 2\,X X^\top\,}\quad(\text{每一行权重共享同一个 } H,\ \text{因为它只和输入 }X\text{ 有关})
$$

> 直觉：$XX^\top$ 是输入特征的"协方差/格拉姆矩阵"。某个输入维度越活跃(方差大)，对应权重列越"重要"，量化它越要小心。

### 3.2 OBS：删掉一个权重的最优补偿（核心公式）
**OBS(Optimal Brain Surgeon)** 问的是：在 $H$ 约束下，**强制把第 $q$ 个权重设为某个值**(剪枝就是设为 0；量化就是设为最近的网格点)，**其余权重该怎么调，才能让 $\delta E$ 最小？**

这是一个等式约束的二次规划，用拉格朗日乘子可解出**闭式解**：

- 量化第 $q$ 个权重(把 $w_q$ 改成网格点 $\hat w_q$，误差 $e_q=w_q-\hat w_q$)带来的**最小损失增量**：

$$
\delta E_q = \frac{e_q^{2}}{\,[H^{-1}]_{qq}\,}=\frac{(w_q-\hat w_q)^2}{[H^{-1}]_{qq}}
$$

- 对**其余所有未量化权重**的**最优补偿更新**：

$$
\boxed{\,\delta w = -\,\frac{w_q-\hat w_q}{[H^{-1}]_{qq}}\;\cdot\;H^{-1}_{:,q}\,}
$$

把这两条读懂，就读懂了 GPTQ 的全部灵魂：

1. **谁先量化？** 选 $\delta E_q$ 最小的那个(代价最低)——这就是"按重要性排序"的来源(§5)。
2. **量化完怎么办？** 用 $H^{-1}$ 的第 $q$ 列，把误差**反向**摊给其它权重，让整层输出几乎不动。

```
 量化 w_q (就近取整) → 产生误差 e_q
        │
        ▼
 用 H⁻¹ 的第 q 列, 给 "还没量化" 的权重打补偿:
   w_rest  +=  -(e_q / [H⁻¹]_qq) · H⁻¹_{:,q}
        │
        ▼
 整层输出 WX 几乎不变 (误差被吸收, 没扩散到输出)
```

### 3.3 OBQ：把"剪枝"换成"量化"
**OBC/OBQ** 就是把 OBS 的"设为 0"换成"设为最近量化网格点"，并对一行权重逐个处理。GPTQ = **OBQ 的极速工程版**。

## 4. 闭式解的"为什么"再补一刀（几何直觉）

为什么补偿方向是 $H^{-1}_{:,q}$ 而不是别的？因为 $H=XX^\top$ 描述了误差曲面的"椭球"形状。$H^{-1}$ 把"在哪个方向上改权重最不痛(损失上升最慢)"指出来。沿这个方向补偿，等于在最平坦的山谷里挪动，**用最小的损失代价吃掉 $w_q$ 被量化造成的窟窿**。

```
   损失等高线 (由 H 决定的椭球)
        ____
      /  ·   \      · = 量化后被迫离开的点
     |    \   |     ↘ 沿 H⁻¹ 方向滑回谷底 = 补偿
      \    \_/      谷底 = 重建损失最小
        \___/
```

## 5. 为什么"按重要性顺序"量化（误差顺序的玄机）

朴素直觉：先量化**最不重要/误差代价最小**的列，把"难啃的、影响大的"列留到后面，让它们能享受更多次补偿、并保留尽量大的自由度。OBQ 严格按 $\delta E_q$ 升序逐个挑列处理。

但 GPTQ 论文有一个反直觉的关键发现：**对同一层的所有行，强行用同一个固定顺序(从左到右)量化，几乎不掉精度，却能大幅加速**。理由：

- 大模型里，"哪个权重重要"很大程度由共享的 $H$ 决定，**逐行各排各的序**收益很小；
- 但**"act-order"(又叫 desc_act)** 这个折中很有用：**按 $H$ 对角线(即输入激活方差 $\text{diag}(XX^\top)$)从大到小**确定列顺序——**先处理最重要的列**，让重要列的误差有最多后续列来补偿。这是实践中常打开的开关。

```
 列重要性 (diag H = 各输入维度活跃度):
 col:  c0   c1   c2   c3   c4
 |H|:  0.9  0.1  0.7  0.2  0.5
       ███  █    ██   █    ██
 act-order 顺序(降序): c0 → c2 → c4 → c3 → c1
 (先量化重要列, 给它们留最多补偿机会)
```

## 6. GPTQ 对 OBQ 的三大工程加速（为什么能跑 175B）

OBQ 对每行单独算/更新 $H^{-1}$，复杂度 $O(d_{row}\cdot d_{col}^3)$，175B 模型要算几年。GPTQ 三招砍到几小时：

1. **任意固定顺序 + 全行共享 $H^{-1}$**：既然顺序无所谓，所有行用**同一个**列顺序、**同一个** $H^{-1}$，省掉逐行重算。复杂度降到 $O(d_{col}^3 + d_{row}d_{col}^2)$。
2. **惰性批量更新(Lazy Batch-Update)**：补偿更新对显存带宽不友好(每量化一列就刷全矩阵)。GPTQ 把列分成 **block(如 128 列一块)**：块内逐列更新，块外的更新攒着，整块算完一次性刷出去，**计算访存比大幅提升**。
3. **Cholesky 分解保数值稳定**：反复用 $H^{-1}$ 会累积数值误差(尤其加阻尼后)。GPTQ 预先对 $H$ 做一次 **Cholesky 分解**，把所需的 $H^{-1}$ 信息一次性、稳定地取出来。还会给 $H$ 加一个小阻尼 $\lambda I$（$\lambda$ 取 $H$ 对角均值的约 1%），保证可逆。

```
 列分块 (block=128):
 [ blk0 | blk1 | blk2 | ... ]
   ↑逐列量化+块内补偿     ↑攒着的跨块补偿, 整块算完一次刷出
```

## 7. group-size：精度与开销的旋钮

一个权重矩阵很大，用**一个** scale/zero-point 覆盖整列太粗。**group-size = 每多少个权重共享一组 scale/zp**。

- `group_size=-1`：整列(per-column)一组 scale，最省额外存储、精度最低。
- `group_size=128`：每 128 个权重一组(最常用)。精度好很多，额外 scale 开销小。
- `group_size=32`：更细，精度再升，额外开销变大。

**额外开销手算**：一列长 $4096$，FP16 scale + INT? zp。
- `g=128` → 每列 $4096/128=32$ 组 → 多存 32 个 scale。相对 4096 个 4-bit 权重(=2048 字节)，32 个 FP16 scale = 64 字节，**仅 +3% 存储**，却显著提精度——所以 `128` 是甜点。
- `g=-1` → 1 个 scale，几乎零开销，但 outlier 一多就崩。

```
 group_size=128 的一列(共4096元素):
 [g0:128个权重|scale0,zp0][g1:128个|s1,z1]...[g31|s31,z31]
   每组独立 scale → 局部 outlier 不再污染整列
```

## 8. 完整算法 + 数据流

```
输入: 权重 W(d_row×d_col), 校准激活 X, 位宽 b, group_size, 阻尼 λ
1. H = 2 X Xᵀ                         # d_col×d_col Hessian
2. H += λ·mean(diag(H))·I             # 阻尼, 保证可逆
3. (可选 act-order) 按 diag(H) 降序重排列, 同步重排 W
4. H⁻¹ ← Cholesky(H) 取上三角         # 数值稳定地拿到补偿系数
5. for 每个 block(128 列):
      for block 内每列 j:
         5a. 对 W[:,j] 按 group 的 scale/zp 做就近量化 → Ŵ[:,j]
         5b. 误差 e = (W[:,j] - Ŵ[:,j]) / [H⁻¹]_jj
         5c. 块内补偿: W[:,j+1:blk_end] -= e ⊗ H⁻¹[j, j+1:blk_end]
      5d. 跨块补偿: W[:,blk_end:] -= E_block ⊗ H⁻¹[blk, blk_end:]
6. 返回量化后的 Ŵ + 每组 scale/zp
```

数据流总览：

```
 校准集 ──► 前向 ──► 收集每层输入 X ──► H=2XXᵀ
                                        │
   权重 W ─────────────────────────────►│ GPTQ 逐列量化+补偿
                                        ▼
                              Ŵ(4-bit) + scales  ──► 落盘/推理
```

## 9. 数值示例（一个 3×3 的逐数手算）

为看清"误差补偿"，简化为**1 行权重、3 列**，对称量化、台阶 $s=1$(即量化网格 = 整数)。

设权重 $w=[2.4,\ -0.7,\ 1.6]$，校准输入构成的 Hessian（已含阻尼，便于手算取整洁值）：

$$
H=\begin{bmatrix}4&1&0\\1&3&1\\0&1&2\end{bmatrix},\qquad
H^{-1}\approx\begin{bmatrix}0.294&-0.176&0.088\\-0.176&0.706&-0.353\\0.088&-0.353&0.676\end{bmatrix}
$$

**Step 1：量化第 1 列** $w_1=2.4 \to \hat w_1=2$。误差 $e_1=2.4-2=0.4$。
- 损失增量 $\delta E_1 = e_1^2/[H^{-1}]_{11}=0.16/0.294=0.544$。
- 补偿系数 $c=e_1/[H^{-1}]_{11}=0.4/0.294=1.361$。
- 给第 2、3 列补偿：$\delta w=-c\cdot H^{-1}_{:,1}$
  - $w_2 \mathrel{-}= 1.361\times(-0.176)=-0.240 \Rightarrow w_2=-0.7+0.240=-0.460$
  - $w_3 \mathrel{-}= 1.361\times(0.088)=0.120 \Rightarrow w_3=1.6-0.120=1.480$
- 现在 $w=[2(已定),\ -0.460,\ 1.480]$。

**Step 2：量化第 2 列** $w_2=-0.460 \to \hat w_2=0$（最近整数）。误差 $e_2=-0.460-0=-0.460$。
- 只能补偿剩下的第 3 列（用 $H^{-1}$ 在"未量化子块"上的元素，这里近似用 $[H^{-1}]_{33},[H^{-1}]_{23}$）。
- 补偿系数 $c_2=e_2/[H^{-1}]_{22}=-0.460/0.706=-0.652$。
- $w_3 \mathrel{-}= c_2\times[H^{-1}]_{23}=(-0.652)\times(-0.353)=0.230 \Rightarrow w_3=1.480-0.230=1.250$。

**Step 3：量化第 3 列** $w_3=1.250 \to \hat w_3=1$。误差 $e_3=0.250$，无列可补，结束。

**结果对比**：
- 朴素 RTN：$[2.4,-0.7,1.6]\to[2,-1,2]$，逐元素误差 $[0.4,\,0.3,\,0.4]$。
- GPTQ：最终 $\hat w=[2,\,0,\,1]$，但**中间把误差"搬运"过**，使得在 $H$ 度量下整层输出 $\|WX-\widehat WX\|$ 比 RTN 小——补偿把第 1 列的 0.4 误差，部分转化成第 2、3 列可吸收的形态。
- 直观看 $\delta E$：GPTQ 每步只付出 $\delta E_1=0.544$ 等"沿最平缓方向"的代价，而 RTN 三个误差各自满额计入 $H$，加权后更大。

> 要点不是"哪个矩阵更接近原权重"，而是"**在 $H=XX^\top$ 这个加权度量下，输出误差更小**"。手算里 GPTQ 始终沿 $H^{-1}$ 方向移动，正是这个加权度量下的最优路径。

## 10. 对照 / 复杂度表

| 维度        | RTN          | GPTQ                    | AWQ                       | SmoothQuant            |
| ---------- | ------------ | ----------------------- | ------------------------- | --------------------- |
| 量化对象    | 权重(就近)    | **权重**(最优重建)        | 权重                       | **权重+激活** 都量化   |
| 用二阶信息  | 否           | **是(Hessian=XXᵀ)**      | 否(用激活幅度选重要通道)    | 否                    |
| 核心思想    | 四舍五入      | 逐列量化+误差补偿(OBS)    | 保护"显著权重"通道, 等价缩放 | 把激活难度"搬"给权重    |
| 需校准数据  | 否           | **是(几百条)**           | 是(少量)                   | 是(估缩放因子)         |
| 需反向传播  | 否           | 否                       | 否                        | 否                    |
| 典型精度    | W8 尚可, W4 崩 | **W4 几乎无损, W3 可用**  | W4 无损, 对指令模型更稳     | W8A8 无损             |
| 主要收益    | 简单         | 极致低比特权重           | 实现简单、硬件友好          | 让 INT8 激活成为可能   |
| 复杂度      | $O(n)$       | $O(d_{col}^3+d_{row}d_{col}^2)$ | $O(d_{row}d_{col})$级 | $O(d_{row}d_{col})$  |

**W4 精度直觉**：4-bit = 16 个台阶。RTN 下，少数 outlier 权重把 scale 撑大，导致大多数普通权重挤在几个台阶里 → 信息坍塌。GPTQ 通过补偿，把"被迫取整"的损失转嫁出去，使 16 个台阶被"用得更值"，因而 W4 能逼近 FP16。

**GPTQ vs AWQ 一句话**：
- **GPTQ**：相信"二阶最优重建"。对**所有**权重做最优补偿，精度上限高，但要算 Hessian/逆，工程更重，对校准集和 act-order 较敏感。
- **AWQ(Activation-aware Weight Quantization)**：相信"只有少数(约 1%)由**激活幅度**指认的显著权重通道重要"。它**不改舍入策略**，而是对显著通道乘一个保护缩放(再在另一侧除回去，等价变换不改输出)，让这些通道量化误差变小。更简单、无需 Hessian、对推理 kernel 更友好，在指令微调模型上常更稳。
- **关系**：两者正交，都属"weight-only PTQ"，常可二选一；AWQ 工程更轻，GPTQ 在极低比特(W3)潜力更大。SmoothQuant 则是**另一条赛道**——它要量化**激活**(W8A8)，靠把激活的 outlier 难度迁移到权重侧(见 [[llm-compression/quantization/SmoothQuant]])。

## 11. 常见问题

| 疑问                                   | 真相                                                                 |
| ------------------------------------- | ------------------------------------------------------------------- |
| GPTQ 要训练/反向传播吗？                 | **不**。它是 PTQ，只前向跑校准集求 $H=XX^\top$，全程线性代数闭式解。      |
| GPTQ 把激活也量化了吗？                  | **没有**。GPTQ 是 weight-only：权重 INT4、激活仍 FP16。要省激活找 SmoothQuant。 |
| 校准集要很多吗？                         | 通常**几百条**(如 128 条序列)就够，远小于训练集。但分布要贴近真实用途。   |
| Hessian 怎么来的，要算二阶导吗？          | 对最小二乘重建，$H$ **恰好 = $2XX^\top$**，只需前向收集输入，无需真求二阶导。 |
| 为什么 RTN 在 W4 崩、GPTQ 不崩？         | RTN 各权重独立取整、误差无处可去；GPTQ 把误差沿 $H^{-1}$ 补偿给后续列，输出几乎不变。 |
| act-order(desc_act) 一定要开吗？        | 不一定。开了通常更准(尤其低比特)，但可能略增推理 kernel 复杂度，按需权衡。  |
| group_size 越小越好吗？                  | 越小越准但额外 scale 开销越大、kernel 越复杂。**128 是公认甜点**。        |
| GPTQ 和 AWQ 能叠加吗？                   | 通常二选一(都是 weight-only)。生产中按硬件 kernel 支持与实测精度挑一个。   |
| 量化误差会逐层累积爆炸吗？                | 不会失控：逐层用**上一层量化后真实输出**当输入，误差被吸收在每层重建里。   |
| 为什么补偿方向偏偏是 $H^{-1}$ 的列？      | 因为 $H$ 定义了损失椭球，$H^{-1}$ 指向"改权重最不痛"的方向，补偿代价最小。 |
