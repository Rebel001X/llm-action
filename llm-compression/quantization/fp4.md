## 0. 一句话锚点

**FP4 = 一个 4-bit 的微型浮点数，位布局是 E2M1（1 sign + 2 exponent + 1 mantissa）。** 单独一个 FP4 只能表示 16 个离散值、动态范围极窄，所以实际系统里从来不是"裸 FP4"，而是 **一小块（block）元素共享一个高精度缩放因子（scale）**：

- **MXFP4**：block=32 个元素，共享一个 **E8M0**（8-bit 纯指数，即 2 的幂）scale。OCP 标准。
- **NVFP4**：block=16 个元素，共享一个 **E4M3（FP8）** scale，外加一个 per-tensor 的 FP32 全局 scale。NVIDIA 私有，Blackwell 原生。

目标：把权重/激活压到 ~4 bit，**显存减半（相对 FP8）**、**张量核吞吐翻倍**，精度损失尽量小。

## 1. 地基 / 前置（每个词拆到最原子）

### 1.1 浮点数 = 符号 × 尾数 × 2^指数

任何浮点格式都是三段：

```
  [S] [   E (指数) ]  [  M (尾数) ]
   1       e bits         m bits
```

值的公式（normal 规格化数）：

$$ x = (-1)^S \times (1 + M/2^m) \times 2^{(E - \text{bias})} $$

- $S$：符号位，0 正 1 负。
- $E$：指数字段（无符号整数），减去固定 **bias** 才是真实指数。bias 通常取 $2^{e-1}-1$。
- $M$：尾数字段。$(1+M/2^m)$ 这个 1 叫 **隐含前导 1**（hidden bit），规格化数都有。
- **指数 → 动态范围**（能表示多大/多小），**尾数 → 精度**（同一档位内分得多细）。

### 1.2 subnormal（次正规数）补最小档

当 $E=0$ 时，隐含前导 1 变成 0，公式改成：

$$ x = (-1)^S \times (0 + M/2^m) \times 2^{(1-\text{bias})} $$

作用：让 0 附近还能再细分几个点，避免"从最小正规数直接掉到 0"的断崖。FP4 里这一档非常重要（见 §2）。

### 1.3 量化（quantize）= 把连续值塞进有限格点

```
连续实数  ───────●─────────────►
              │  四舍五入到最近格点
FP4 格点   ─●──●──●──●──●──●──►   只有 16 个点
```

量化误差 = 真实值 − 最近格点值。格点越密误差越小；FP4 只有 16 个点，所以格点很稀，必须靠缩放把数据"对齐"到格点密集的区域。

### 1.4 scale（缩放因子）= 量化的"放大镜"

核心思想：存的不是 $x$，而是 $\hat{x}=\text{round}(x/s)$ 这个小整数化的低比特数 + 一个高精度的 $s$。还原时 $x \approx s \cdot \hat{x}$。

- $s$ 选得好，能把一组数据映射到 FP4 格点最密、范围最匹配的地方。
- **per-tensor scale**：整个张量共用一个 $s$ → 省，但一个离群值就拉垮所有数。
- **block scale（微缩放，micro-scaling）**：每一小块（16/32 个数）一个 $s$ → 离群值只影响本块。FP4 必须走这条路。

## 2. FP4 = E2M1 的位分配（核心）

### 2.1 4 个 bit 怎么切

```
 bit:   3      2   1      0
       ┌───┬───────────┬─────┐
       │ S │   E E     │  M  │
       └───┴───────────┴─────┘
         1bit   2bit      1bit
       符号    指数      尾数
```

- $e=2$ → 指数字段 0..3；bias $=2^{2-1}-1=1$。
- $m=1$ → 尾数只有 0 或 1，即 $(1+M/2)\in\{1.0,\;1.5\}$。

### 2.2 把 16 个编码全部列出来

非负半边（S=0），用 §1.1/§1.2 公式逐个算：

| E(二进制) | M | 类型 | 计算 | 值 |
|---|---|---|---|---|
| 00 | 0 | subnormal | $0\times2^{1-1}=0\times2^0$ | **0.0** |
| 00 | 1 | subnormal | $(1/2)\times2^{0}$ | **0.5** |
| 01 | 0 | normal | $(1+0)\times2^{1-1}=1\times2^0$ | **1.0** |
| 01 | 1 | normal | $1.5\times2^{0}$ | **1.5** |
| 10 | 0 | normal | $1\times2^{2-1}=1\times2^1$ | **2.0** |
| 10 | 1 | normal | $1.5\times2^{1}$ | **3.0** |
| 11 | 0 | normal | $1\times2^{3-1}=1\times2^2$ | **4.0** |
| 11 | 1 | normal | $1.5\times2^{2}$ | **6.0** |

加上符号位 → 共 16 个值：

$$ \{0,\;\pm0.5,\;\pm1,\;\pm1.5,\;\pm2,\;\pm3,\;\pm4,\;\pm6\} $$

（注意：E2M1 标准里 **没有 Inf/NaN**，把所有编码都用来表数；$\pm0$ 算一个 0，所以是 15 个不同数值。$\max=6$，$\min_{\text{正规}}=1$，$\min_{\text{subnormal}}=0.5$。）

### 2.3 数轴可视化——格点严重不均匀

```
0   0.5  1  1.5    2        3          4              6
●────●───●───●─────●────────●──────────●──────────────●
 0.5  0.5 0.5  0.5    1.0        1.0          2.0
└── 间隔随值变大而变大（浮点的本性：相对精度恒定）──┘
```

观察：**间隔不是均匀的**（这正是浮点和 INT4 的本质区别，见 §6）。靠近 0 的地方密、远处稀。所以 FP4 天然适合"绝对值小、偶有大数"的神经网络张量分布（接近正态/拉普拉斯）。

## 3. 为什么必须 Block Scaling（不能裸用 FP4）

### 3.1 痛点：4 bit 的动态范围只有 12 倍

最大正规 6.0 / 最小正规 1.0 = 6；连 subnormal 0.5 也才到 12 倍跨度。而一个 Transformer 权重矩阵里，元素能从 0.0001 跨到 0.5，**动态范围上千倍**。直接量化：要么大数溢出截断（clip 到 6），要么小数全部 round 成 0（underflow）。两头都崩。

### 3.2 解法：每一小块配一个 scale

把一行（或一列）切成连续小块，每块 $B$ 个元素，取本块绝对值最大者 $\text{amax}$ 决定 scale：

$$ s = \frac{\text{amax}(\text{block})}{6.0}, \qquad \hat{x}_i=\text{round\_to\_FP4}\!\left(\frac{x_i}{s}\right) $$

这样每块的最大值正好被映射到 FP4 的满量程 6.0，块内所有数都落到 [−6,6] 里、用尽 16 个格点。**离群值只污染自己那一块的 scale，不再波及全张量。**

```
 一行权重（很多元素，动态范围大）
 ┌──────┬──────┬──────┬──────┐
 │ blk0 │ blk1 │ blk2 │ blk3 │   每块 B 个元素
 └──┬───┴──┬───┴──┬───┴──┬───┘
   s0     s1     s2     s3        每块一个高精度 scale
   ↓      ↓      ↓      ↓
 块内元素全部除以本块 s，再 round 到 16 个 FP4 格点
```

### 3.3 存储成本：scale 摊薄到每个元素几乎免费

block=32 时，scale（8 bit）摊到 32 个元素 → 每元素多 $8/32=0.25$ bit。
所以 **MXFP4 实际比特数 ≈ 4 + 0.25 = 4.25 bit/元素**。NVFP4 block=16、scale=8bit（FP8）→ $4+8/16=4.5$ bit/元素（还要再加可忽略的 per-tensor FP32 全局 scale）。

## 4. MXFP4 与 NVFP4 的"微缩放"差异

两者都是 §3 的 block scaling，区别在 **块大小** 和 **scale 用什么格式**。

### 4.1 MXFP4（OCP Microscaling 标准）

```
 block = 32 个 FP4 元素
        ┌────────────────────────────┐
 数据   │ e0 e1 ... e31  (各 4-bit)   │  = 32 × 4 = 128 bit
        └────────────────────────────┘
 scale  │ X  (E8M0, 8-bit) │              共享 1 个
```

- scale 格式 = **E8M0**：8 bit 纯指数、无尾数无符号，**只能表示 2 的整数次幂**（$2^{-127}\sim2^{127}$，外加一个 NaN 编码）。
- 优点：scale 是 2 的幂 → 乘除可用移位、硬件极省，标准开放（AMD/Intel/Nvidia 都支持）。
- 缺点：scale 粒度粗（只能取 2 的幂），32 个数共享一个，块内若分布再细就吃量化误差。

### 4.2 NVFP4（NVIDIA 私有，Blackwell 原生）

```
 block = 16 个 FP4 元素
        ┌──────────────────┐
 数据   │ e0 ... e15 (4bit)│  = 16 × 4 = 64 bit
        └──────────────────┘
 块 scale│ X (E4M3 / FP8)  │   每 16 个元素一个
 全局    │ G (FP32)        │   每张量一个，二级缩放
```

- **两级缩放**：先 per-tensor FP32 全局 scale $G$ 把整张量拉进范围，再 per-16 的 FP8(E4M3) 块 scale $X$ 精调。还原：$x \approx G \cdot X \cdot \hat{x}$。
- block 更小（16 vs 32）→ 对离群值更敏感、更精细。
- scale 是 **E4M3 真浮点**（有尾数）→ 比 E8M0 表达更细，不再被限制为 2 的幂，量化误差更低。
- 代价：scale 开销更大（4.5 vs 4.25 bit/元素），且为 NVIDIA 私有格式。

### 4.3 一图看清差异

```
                MXFP4              NVFP4
 block 大小      32                 16
 块 scale 格式   E8M0(纯指数,2的幂)  E4M3(FP8 真浮点)
 全局 scale      无                 FP32 per-tensor
 有效 bit/元素   ~4.25              ~4.5
 标准            OCP 开放           NVIDIA 私有
 精度            较低               更高（同 4-bit 下）
```

经验：相同 4-bit 预算下，**NVFP4 精度普遍优于 MXFP4**（更小的块 + 更细的 scale），代价是稍多比特和厂商绑定。

## 5. Blackwell 硬件支持

- **第五代 Tensor Core** 原生支持 FP4（NVFP4 与 MXFP4 均在硬件解码路径里），block scaling 由硬件自动做缩放/反缩放，不用软件循环。
- 官方口径（以 NVIDIA 数据手册为准）：B200 的 **FP4 稠密算力约为 FP8 的 2 倍**（同一张量核单位时间能塞进 2 倍的 4-bit MAC）。GB200（双 B200 + Grace）整机 FP4 算力进一步翻倍叠加。
- 显存角度：模型权重从 FP8(1 byte) → FP4(0.5 byte) **再省一半**，配合 NVLink 让超大模型推理的"每 GPU 装更多参数"。
- 上一代 Hopper(H100) **没有** FP4 张量核（只到 FP8）；Ada/Hopper 上跑 FP4 只能软件模拟，享不到 2× 吞吐。
- 软件栈：**TensorRT-LLM / Transformer Engine / cuDNN / CUTLASS** 提供 NVFP4/MXFP4 的 GEMM 与量化算子；训练侧 Transformer Engine 支持 FP4 的前向（推理为主，训练 FP4 仍是前沿）。

```
 精度演进与硬件：
 Volta   FP16 ──► Ampere TF32/INT8 ──► Hopper FP8 ──► Blackwell FP4
                                          (H100)        (B100/B200/GB200)
 每代张量核相对吞吐大致翻倍，比特数减半
```

## 6. FP4 vs INT4 vs FP8 横向对比（本质差异）

### 6.1 FP4(浮点) vs INT4(定点)——格点分布完全不同

```
 INT4（对称, scale=s）: 格点【均匀】
 -7s ... -s  0  s  2s ... 7s     间隔恒为 s
 ●───●───●───●───●───●───●───●

 FP4(E2M1): 格点【非均匀】, 近 0 密、远处稀
 0  .5  1  1.5  2    3      4        6
 ●──●───●──●────●────●──────●────────●
```

- **INT4** 在均匀分布数据上更省格点（16 个点全均匀）；但对长尾/正态分布的神经网络张量，大量格点浪费在很少出现的大值区。
- **FP4** 用浮点的"相对精度恒定"特性，把格点按数量级铺开，**天然贴合权重/激活的钟形分布**，小值附近精度高——这正是 LLM 量化想要的。
- 两者都常配 block scaling；趋势是 **训练/前沿低比特用 FP4**，传统 PTQ 权重量化仍大量用 INT4（GPTQ/AWQ 生态成熟）。

### 6.2 三格式对照

| 维度 | FP8(E4M3) | FP4(E2M1)+block | INT4+block |
|---|---|---|---|
| 比特/元素 | 8 | ~4.25(MX)/4.5(NV) | ~4.25 |
| 表示数个数 | 256 | 16(裸) | 16(裸) |
| 格点分布 | 非均匀(浮点) | 非均匀(浮点) | 均匀(定点) |
| 动态范围 | 宽 | 窄→靠 scale 补 | 窄→靠 scale 补 |
| 硬件加速 | Hopper+ | Blackwell+ | INT8 核/部分支持 |
| 典型用途 | 训练/推理主力 | 推理(前沿训练) | PTQ 权重量化 |
| 精度损失 | 很小 | 中(需好的 scale) | 中(对离群值敏感) |

## 7. 数值示例 / 逐数手算（重点）

### 例 A：把单个数 $x=2.6$ 量化成 FP4（直接、无 scale）

1. FP4 正格点：$\{0,0.5,1,1.5,2,3,4,6\}$。
2. $2.6$ 落在 $2.0$ 与 $3.0$ 之间，中点 $2.5$。$2.6>2.5$ → round 到 **3.0**。
3. 反量化值 $=3.0$，**量化误差** $=|2.6-3.0|=0.4$，相对误差 $0.4/2.6\approx15.4\%$。
   （可见裸 FP4 在 2~3 这档已很粗——这就是为什么要 scale 把数据搬到更密的档。）
4. 编码：$3.0 = 1.5\times2^1$ → $E-1=1\Rightarrow E=10_2$，$M=1$，$S=0$ → 二进制 **0 10 1 = `0101`**。
   对照 §2.2 表确认：`E=10,M=1` → 3.0 ✓。

### 例 B：一个 block 的完整量化（NVFP4 风格，B=16 简化演示）

设某块绝对值最大元素 $\text{amax}=5.2$，取其中一个元素 $x_i=1.7$。

1. **算块 scale**（让 amax 映射到满量程 6）：
   $$ s=\frac{\text{amax}}{6.0}=\frac{5.2}{6.0}=0.8667 $$
2. **缩放**：$x_i/s = 1.7/0.8667 = 1.9615$。
3. **round 到 FP4 格点**：$1.9615$ 在 $1.5$ 与 $2.0$ 间，中点 $1.75$，$1.9615>1.75$ → 取 **2.0**（编码 `0100`，见 §2.2）。
4. **反量化还原**：$\hat{x}_i = s\times 2.0 = 0.8667\times2.0 = 1.7333$。
5. **误差**：$|1.7-1.7333|=0.0333$，相对 $\approx2.0\%$。
   对比例 A 的裸量化 15%，**block scaling 把误差从 15% 量级压到 2%**——这就是 scale 的价值。

### 例 C：显存账（7B 模型，权重量化）

每元素字节数：FP16=2，FP8=1，FP4≈0.5（+scale 开销）。$7\times10^9$ 参数：

| 格式 | 每元素 | 权重显存 | 相对 FP16 |
|---|---|---|---|
| FP16 | 2 B | 14.0 GB | 1.00× |
| FP8 | 1 B | 7.0 GB | 0.50× |
| **MXFP4** | 4.25 bit=0.531 B | $7e9\times0.531\approx$ **3.72 GB** | **0.27×** |
| **NVFP4** | 4.5 bit=0.5625 B | $7e9\times0.5625\approx$ **3.94 GB** | 0.28× |

结论：FP4 让 7B 权重压到 ~3.7–3.9 GB，单卡能装更大模型或更多并发。

### 例 D：吞吐账

若 FP8 GEMM 在 B200 上达 $X$ TFLOPS，FP4 张量核 ~2× → $2X$。一个 $[M,K]\times[K,N]$ 矩阵乘需 $2MKN$ FLOPs，理论耗时减半（实际受 scale 反量化、访存带宽折扣，约 1.5–1.8×）。

## 8. 工程实践与踩坑

- **激活更难量化**：激活有大量动态离群值，FP4 激活通常配更小 block 或保留部分高精度通道（混合精度）。权重 FP4 比激活 FP4 更稳。
- **W4A8 折中**：ZeroQuant-FP 等工作用 **FP4 权重 + FP8 激活**，兼顾压缩与精度；这是早期 4-bit 浮点的实用配方。
- **scale 选取**：amax 法简单但受单点离群拉偏；可用 percentile / MSE 搜索更优 scale。
- **二级缩放对齐**：NVFP4 的 FP32 全局 scale 要先做，否则块 scale(E4M3) 自身也会溢出。
- **训练 FP4 仍前沿**：反向梯度对低比特更敏感，目前 FP4 多用于推理与前向；训练常 FP4 前向 + 高精度主权重/优化器状态。
- **相关论文**：LLM-FP4（4-bit 浮点 PTQ，https://github.com/nbasyl/LLM-FP4）、ZeroQuant-FP（W4A8 用浮点格式优于整型）。

## 9. 面试高频问答

**Q1：FP4 的 E2M1 是什么意思？能表示哪些数？**
踩点：1 符号 + 2 指数 + 1 尾数，bias=1；正格点 $\{0,.5,1,1.5,2,3,4,6\}$ 加符号共 16 编码，无 Inf/NaN，max=6。
追问：为什么 max 是 6 不是更大？→ 指数最大 E=11→真实指数 2，尾数最大 1.5，$1.5\times4=6$。

**Q2：为什么单独 FP4 不能用，必须 block scaling？**
踩点：4-bit 动态范围才 ~12 倍，张量动态范围上千倍，会同时溢出+下溢；block scaling 让每块 amax 对齐满量程 6，离群值只污染本块。

**Q3：MXFP4 和 NVFP4 区别？**
踩点：块大小 32 vs 16；scale 格式 E8M0(2 的幂) vs E4M3(FP8 真浮点)；NVFP4 多一级 FP32 全局 scale；NVFP4 精度更高、比特略多、私有；MXFP4 是 OCP 开放标准、更省。

**Q4：FP4 和 INT4 哪个好？**
踩点：没有绝对好坏。FP4 格点非均匀贴合钟形分布、近 0 精度高；INT4 均匀、生态成熟(GPTQ/AWQ)。LLM 张量长尾→FP4 常更优；都需 block scale。

**Q5：哪代硬件支持 FP4？吞吐提升多少？**
踩点：Blackwell（B100/B200/GB200）第五代张量核原生；FP4 稠密算力约 FP8 的 2 倍；Hopper(H100) 不支持，只能软件模拟。

**Q6：FP4 量化误差怎么估？**
踩点：见 §7 例 A/B——裸量化在 2~3 档相对误差可达 15%，加 block scale 后压到 ~2%。

## 10. 复杂度 / 对照表

| 项 | MXFP4 | NVFP4 |
|---|---|---|
| 元素格式 | E2M1 | E2M1 |
| 块大小 | 32 | 16 |
| 块 scale | E8M0(8bit) | E4M3(8bit, FP8) |
| 全局 scale | 无 | FP32 per-tensor |
| 有效 bit/元素 | ~4.25 | ~4.5 |
| 标准归属 | OCP 开放 | NVIDIA 私有 |
| 硬件 | Blackwell+(及兼容) | Blackwell 原生 |
| 同比特精度 | 基线 | 通常更高 |

| 格式 | 比特 | 格点数 | 分布 | 适用 |
|---|---|---|---|---|
| FP8 E4M3 | 8 | 256 | 浮点 | 训练/推理主力 |
| FP8 E5M2 | 8 | 256 | 浮点(更大范围) | 梯度 |
| FP4 E2M1 | 4(+scale) | 16 | 浮点 | 推理/前沿训练 |
| INT4 | 4(+scale) | 16 | 定点均匀 | PTQ 权重 |

## 11. 常见问题 / 高频追问

| 问题 | 要点 |
|---|---|
| FP4 有 NaN/Inf 吗？ | E2M1 标准没有，全部编码用于表数（最大化 16 个格点利用率）。 |
| E8M0 为什么没尾数？ | 它只当 scale 用，只需表示"2 的某次幂"做缩放，纯指数最省且乘除可移位。 |
| block 越小越好吗？ | 精度更高但 scale 开销占比上升（16→4.5bit，8→更多）；NVFP4 选 16 是精度/开销折中。 |
| FP4 能直接训练大模型吗？ | 前向可以；反向梯度对低比特敏感，目前多 FP4 前向 + 高精度主权重，纯 FP4 训练仍前沿。 |
| 为什么 amax 映射到 6 而非更大？ | 6 是 FP4 满量程，映射到 6 能用满 16 个格点又不溢出。 |
| 激活也能 FP4 吗？ | 难，离群多；常 W4A8 或对敏感通道保留高精度（混合精度）。 |
| FP4 相对 FP8 省多少显存？ | 权重再减半（1B→~0.53–0.56B/元素），见 §7 例 C。 |
| 没有 Blackwell 能用 FP4 吗？ | 可软件模拟做研究，但拿不到 2× 张量核吞吐，实用价值有限。 |
