## 0. 一句话锚点

**量化 = 把一个高精度浮点张量 $X$，映射到一个低比特整数张量 $X_q$，再用一个缩放因子 $s$（和零点 $z$）把它「还原」回近似浮点。**

$$X_q = \text{round}\left(\frac{X}{s}\right) + z, \qquad \hat{X} = s\cdot(X_q - z)\approx X$$

- $s$（scale）：每个量化格子代表多大的浮点跨度，是**连续→离散**的步长。
- $z$（zero-point）：浮点 0 对应到哪个整数，用来处理**非对称分布**。
- 还原后的 $\hat{X}\neq X$，差值就是**量化误差**——量化的全部学问，就是想方设法把这个误差压到模型「感觉不到」。

---

## 1. 地基：为什么要量化（显存与带宽的账）

LLM 推理的瓶颈往往不是算力，而是**把权重和 KV-Cache 从显存搬进计算单元的带宽**。比特数直接决定搬运量。

**显存粗算公式**（仅权重）：

$$\text{显存(GB)} \approx \frac{\text{参数量} \times \text{每参数字节数}}{10^9}$$

以 7B 模型为例（手算）：

| 精度 | 每参数字节 | 7B 权重显存 | 相对 FP16 |
|---|---|---|---|
| FP32 | 4 | ≈ 28 GB | 200% |
| FP16 / BF16 | 2 | ≈ 14 GB | 100% |
| INT8 | 1 | ≈ 7 GB | 50% |
| INT4 | 0.5 | ≈ 3.5 GB | 25% |

> 这就是「INT4 让大模型塞进单卡」的本质——见原文提到的 **QLoRA 使大型模型可以在单个 GPU 上进行微调**。

```
浮点世界(连续)              整数世界(离散)
   .  .  ..  . . .            |  |  |  |  |  |
 --|----------|--   ==量化==>  0  1  2 ... 255   (INT8: 2^8=256格)
 X_min      X_max            每格步长 s = (X_max - X_min) / 255
```

**核心权衡**：比特越少 → 显存/带宽越省、越快，但格子越粗 → 量化误差越大 → 精度越易掉。整张笔记都在围绕这个权衡找平衡点。

## 2. 线性量化：对称 vs 非对称

「线性」指浮点到整数是**等间距**映射（步长 $s$ 处处相同）。这是绝大多数硬件友好量化的基础。

### 2.1 对称量化（Symmetric）

零点 $z=0$，浮点 0 直接对应整数 0，量化区间关于原点对称。

$$s = \frac{\max(|X|)}{2^{b-1}-1}, \qquad X_q = \text{round}\left(\frac{X}{s}\right)$$

- INT8 对称：范围 $[-127, 127]$（留 $-128$ 不用以保持对称）。
- **优点**：还原时只需一次乘法（无加零点），矩阵乘法里整数累加直接对应浮点乘加，硬件最快。
- **适用**：权重——经过训练的权重分布通常近似以 0 为中心。

**手算**：设权重 $\max|w|=0.8$，INT8 对称 → $s = 0.8/127 \approx 0.0063$。
权重 $0.5$ → $\text{round}(0.5/0.0063)=\text{round}(79.4)=79$ → 还原 $79\times0.0063=0.4977$，误差 $0.0023$。

### 2.2 非对称量化（Asymmetric）

零点 $z\neq0$，用整段整数范围 $[0, 2^b-1]$ 去贴合一个**不对称**的浮点区间。

$$s = \frac{X_{\max}-X_{\min}}{2^b-1}, \qquad z = \text{round}\left(-\frac{X_{\min}}{s}\right)$$

- INT8 非对称：范围 $[0, 255]$。
- **优点**：分布偏向一侧时（如 ReLU 后激活恒 $\ge 0$）不浪费格子。
- **代价**：还原/矩阵乘里要处理零点 $z$，多一项整数偏置计算。
- **适用**：激活——尤其是经过非线性后偏斜的分布。

```
对称(z=0):        非对称(z≠0):
 -127  0  +127     0 ........... 255
   |---+---|         |    z      |
  关于0对称         整段贴合 [Xmin,Xmax]
```

| 维度 | 对称量化 | 非对称量化 |
|---|---|---|
| 零点 z | 0 | ≠0 |
| 整数范围 | [-127,127] | [0,255] |
| 计算开销 | 低（无零点项） | 略高 |
| 适合对象 | 权重（近0对称） | 激活（偏斜） |

## 3. 饱和量化 vs 非饱和量化（异常值怎么办）

> 对应原文：**饱和量化与非饱和量化**。这是 LLM 量化的命门——因为激活里有**异常值（outlier）**。

- **非饱和（不裁剪）**：直接用 $\max(|X|)$ 当边界。问题：只要有一个超大异常值，$s$ 被它撑大，正常值全被挤进极少数格子里，精度灾难。
- **饱和（裁剪）**：选一个**阈值 $T < \max$**，把超过 $T$ 的值「饱和」（clip）到边界，用 $T$ 算 $s$。牺牲极少数异常值，换正常值的精细分辨率。

```
非饱和:  正常值挤成一团 ←—————————→ 离群点
        [|||                        *]   ← s 太大, 浪费格子
饱和:    裁掉离群点尾巴
        [||||||||||||||||||||] | *      ← 正常值占满格子, 精度高
                              T(阈值)
```

如何选 $T$？经典做法是 **KL 散度校准**（TensorRT 风格）：用校准集统计激活直方图，遍历候选阈值，选让「截断前分布」与「量化后分布」KL 散度最小的 $T$。

这也是后文一系列算法的母题：**LLM 激活的异常值是量化的头号敌人**。

## 4. 非线性量化

线性量化步长处处相等；但权重分布往往**中间密、两端疏**（近似正态/拉普拉斯）。等间距格子在密集区太粗、在稀疏区浪费。

**非线性量化**让步长随分布变化——密的地方格子细、疏的地方格子粗。典型代表是 QLoRA 引入的 **NF4（NormalFloat4）**：基于「权重近似服从 0 均值正态分布」的假设，按正态分位点划分量化格子，使每个格子里落入的权重数量大致相等（信息论意义上的最优）。

> 对应原文：**QLORA 引入了新的数据类型、双重量化和分页优化器**。这里的「新数据类型」即 NF4，「双重量化」是把量化所用的 scale 本身再量化一次省显存。

```
线性(INT4均匀):  | | | | | | | |   ← 中间太疏
                 密       疏
非线性(NF4):     ||||  |   |    |   ← 按分布密度分配格子
                 密集区细  稀疏区粗
```

## 5. 两条路线：QAT vs PTQ

> 对应原文：**QAT、PTQ**。

| 维度 | QAT 量化感知训练 | PTQ 训练后量化 |
|---|---|---|
| 全称 | Quantization-Aware Training | Post-Training Quantization |
| 时机 | 训练/微调时插入「伪量化」节点 | 模型训完后直接量化 |
| 数据 | 需要训练数据 + 反向传播 | 仅需少量校准集（或无数据） |
| 成本 | 高（要重训） | 低（几分钟~几小时） |
| 精度 | 通常更高，尤其低比特 | 中高，4bit 以下易掉 |
| LLM 现状 | 重训太贵，较少；蒸馏类如 LLM-QAT | **主流**：GPTQ/AWQ/SmoothQuant |

```
QAT:  训练 ──伪量化──> 反向传播感知误差 ──> 模型自己学会"抗量化"
PTQ:  训练完 ──校准集统计──> 求 s,z ──> 直接转低比特(不重训)
```

**原文中的 QAT 与 PEFT-量化代表**：

- **LLM-QAT [Liu 等, 2023]**：用预训练模型自己生成的数据做**无数据蒸馏**；不仅量化权重和激活，**还量化 KV 缓存**，把 LLaMA 蒸馏为 **4 比特**模型，论证了精确 4bit LLM 的可行性。
- **PEQA [Kim 等, 2023]**：量化感知 PEFT。两阶段——①每个全连接层参数矩阵量化为「低位整数矩阵 + 标量向量」；②只微调每个下游任务的标量向量。
- **QLoRA [Dettmers 等, 2023a]**：NF4 数据类型 + 双重量化 + 分页优化器，**在不影响性能下省内存，使大模型可在单 GPU 微调**，Vicuna 基准达到 SOTA。

## 6. 量化对象：权重 / 激活 / KV-Cache

量化谁，决定了难度和收益：

```
        ┌─ 权重(Weight)   : 静态、训练后固定 → 最好量化, 收益(省显存)最直接
量化对象 ├─ 激活(Activation): 动态、随输入变化、有异常值 → 最难量化
        └─ KV-Cache       : 长序列推理时显存大头 → 量化它能撑更长上下文
```

- **仅权重量化（Weight-only）**：最常见的 LLM PTQ。激活仍用 FP16，矩阵乘前把权重反量化（或用专用 kernel）。代表：GPTQ、AWQ。收益在显存和带宽。
- **权重+激活量化（W8A8 等）**：激活也量化，矩阵乘可走整数 Tensor Core，进一步加速。难点在激活异常值。代表：SmoothQuant、LLM.int8()。
- **KV-Cache 量化**：长上下文场景 KV-Cache 比权重还大，量化它直接决定能开多长的上下文（原文 LLM-QAT 即量化 KV-Cache 以「增强吞吐并支持更长序列依赖」）。

## 7. 主流算法地图（原文综述编排 + 解释）

下面把原文给出的算法谱系，按「量化什么 / 怎么处理异常值」两条主线重组，并补上一句话原理。

### 7.1 仅权重量化（Weight-only PTQ）

| 算法 | 比特 | 一句话核心（原文） | 补充原理 |
|---|---|---|---|
| **LUT-GEMM** [Park'22] | 低位 | 仅量化权重 + BCQ 格式，优化矩阵乘以降延迟 | 用查找表(LUT)把"反量化×矩阵乘"融成查表，省解码开销 |
| **GPTQ** [Frantar'22] | 3~4 bit | 基于**近似二阶信息**的逐层量化，几乎无精度损失 | 用 Hessian 逆衡量每个权重重要性，逐列量化并把误差补偿到未量化列 → 见 [[GPTQ]] |
| **AWQ** [Lin'23] | 4 bit | **权重并非同等重要**，保护 1% 显著权重即大幅降误差 | 激活感知：按激活幅度大的通道，给对应权重通道乘缩放因子，再量化 |
| **OWQ** [Lee'23] | 混合 | 分析激活异常如何**放大**权重量化误差 | 对易受激活异常影响的权重用更高精度（混合精度） |
| **SpQR** [Dettmers'23b] | 3~4 bit | 隔离**异常权重**存高精度，其余压到 3-4 bit | 稀疏+量化混合表示 → 见 [[fp8]] 思路相邻 |

> **AWQ 关键直觉**：量化误差对最终输出的影响，由「权重重要性」加权。重要性来自**激活幅度**——某通道激活大，它的权重哪怕量化误差小，乘出来误差也被放大。所以按激活给权重通道缩放，把误差从重要通道转移走。

### 7.2 权重 + 激活量化（W·A，难在异常值）

激活异常值是这一支的核心矛盾。原文给出一条「如何对付异常值」的演化链：

```
LLM.int8()  → 把异常值挑出来走 FP16, 其余走 INT8 (混合精度分解)
   │  问题: 异常值检测/分解有开销
SmoothQuant → 把激活的"难"通过缩放搬一部分到权重, 让激活变平滑好量化
   │  观察: 同一通道跨 token 变化相似 → 逐通道缩放
RPTQ        → 不同通道范围不均 → 把通道分组聚类, 组内量化; 重排融进 LayerNorm
OliVe       → outlier-victim对(OVP): 异常值重要,其旁正常值不重要 → 牺牲后者就地处理异常
Outlier+    → 有害异常呈不对称分布且集中于特定通道 → 通道级平移+缩放纠正不对称
```

| 算法 | 一句话核心（原文） |
|---|---|
| **LLM.int8()** [Dettmers'22] | 对 transformer 矩阵乘用 **8 位**量化，推理省 GPU 显存；用**矢量量化 + 混合精度分解**处理异常值 |
| **ZeroQuant** [Yao'22] | 硬件友好量化 + 逐层知识蒸馏 + 优化的量化支持，权重/激活降到 INT8，精度几乎无损 |
| **SmoothQuant** [Xiao'22] | 观察到不同 token 在通道上变化相似，引入**逐通道缩放变换**平滑幅度，让激活更易量化 → 见 [[GPTQ]] 同属 PTQ 名作 |
| **RPTQ** [Yuan'23] | 通道范围不均 → **分组聚类量化**，并把通道重排集成进 LayerNorm 和线性层权重以降开销 |
| **OliVe** [Guo'23] | **outlier-victim 对(OVP)**：异常值重要、旁边正常值不重要，低硬件开销就地处理异常 |
| **Outlier Suppression+** [Wei'23] | 有害异常呈**不对称**、集中特定通道 → 通道级**平移+缩放**纠正不对称，量化分析最优平移/缩放值 |

### 7.3 浮点量化（FP8 / FP4）

- **ZeroQuant-FP** [Wu'23]：探索 FP 量化。结论很关键——**FP8 激活持续优于 INT8**；权重上 **FP4 与 INT4 相当甚至更优**。要求所有缩放因子为 **2 的幂**，并把缩放因子限制在单个计算组内；还集成 **LoRC（Low Rank Compensation）低秩补偿**进一步增强。详见 [[fp8]]。

> **为什么 FP 在激活上更好**：浮点有指数位，天然「非线性」——动态范围大、对异常值更宽容；而激活恰恰有大动态范围 + 异常值，所以 FP8 比等比特的 INT8 更适合激活。

### 7.4 缩放定律视角

**Dettmers & Zettlemoyer** 通过推理缩放定律分析「模型大小 vs 位精度」对零样本性能的权衡，跨多个 LLM 家族实验发现：**4 位精度几乎普遍是「总模型位数 vs 零样本准确率」的最佳平衡点**。这是「为什么大家都做 4bit」的实证依据。

## 实操：量化选型与落地建议

> 原文是综述性内容，未给具体命令；以下为基于上述方法谱系的工程选型指引（不引入未经验证的版本/参数）。

**按场景选方法（决策树）**：

```
要不要重训?
 ├─ 不能/不想重训(绝大多数) → PTQ
 │    ├─ 只想省显存、不改激活 → 仅权重量化
 │    │     ├─ 追求精度/通用 → GPTQ (4bit, 二阶信息)
 │    │     └─ 重视部署简单/激活感知 → AWQ (4bit)
 │    └─ 想吃整数 Tensor Core 加速 → 权重+激活(W8A8)
 │          └─ 激活异常值难搞 → SmoothQuant 预处理 + INT8
 ├─ 能微调且要 4bit 微调 → QLoRA (NF4 + 双重量化)
 └─ 能重训且追极致低比特 → QAT (如 LLM-QAT, 含 KV-Cache)
```

**落地要点（为什么这么做）**：

1. **权重用对称、激活用非对称**：权重近 0 对称省零点开销；激活偏斜用非对称不浪费格子。
2. **激活先 smooth 再量化**：直接量化激活会被异常值毁掉，先做 SmoothQuant 式逐通道缩放或饱和裁剪。
3. **per-channel / per-group 优于 per-tensor**：每通道或每组各自一个 scale，比整张张量共用一个 scale 误差小得多（异常通道不连累其他通道）。
4. **校准集要有代表性**：PTQ 的 $s,z$ 由校准集统计而来，分布偏了会系统性掉点。
5. **长上下文场景考虑 KV-Cache 量化**：此时 KV-Cache 是显存第一大头。

## 常见问题 / 坑

| 现象 / 问题 | 根因 | 对策 |
|---|---|---|
| INT8 激活量化后精度暴跌 | 激活异常值撑大 scale，正常值精度尽失 | 饱和裁剪 / SmoothQuant 逐通道缩放 / 混合精度分解(LLM.int8) |
| per-tensor 量化掉点严重 | 单 scale 被某个异常通道绑架 | 改 per-channel 或 per-group |
| 4bit 权重精度不稳 | 少数显著权重误差被放大 | AWQ 保护 1% 显著权重 / SpQR 隔离异常权重存高精度 |
| 对称量化用在偏斜激活上浪费一半格子 | ReLU 后激活恒 ≥0，负半区空着 | 激活改用非对称量化 |
| FP16→INT8 后矩阵乘没变快 | 只反量化没走整数 kernel | 用 W8A8 + 整数 Tensor Core，或专用 GEMM kernel |
| 校准后线上掉点 | 校准集分布 ≠ 线上分布 | 用更贴近线上的代表性校准数据 |
| 仅权重量化省了显存但 batch 大时没省多少时间 | 此时瓶颈在激活/计算而非权重带宽 | 量化激活 / 提升计算并行度 |
| INT4 激活几乎不可用 | INT 等间距对大动态范围+异常值不友好 | 激活优先考虑 FP8（ZeroQuant-FP 结论） |
| QLoRA 微调显存仍超 | scale 本身也占显存 | 启用双重量化（量化 scale）+ 分页优化器 |
