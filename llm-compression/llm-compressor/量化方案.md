## 0. 一句话锚点

**llm-compressor = "算法插件(Modifier) + 配方(Recipe) + 标准权重格式(compressed-tensors)"**，让你不写底层 CUDA、只声明"我要 W4A16 GPTQ"或"我要 FP8 动态"，就能把一个 HF 模型压成 vLLM 高速推理可用的产物。

## 1. 地基/前置：量化的最小词汇表

量化(Quantization)就是把高精度浮点数（FP16/BF16，每个数 16 bit）映射到低精度整数（INT8 8 bit / INT4 4 bit）或低精度浮点（FP8 8 bit），从而**省显存、省带宽、用更快的低精度算子**。

最核心的线性量化公式（以非对称为例）：

$$q = \mathrm{round}\!\left(\frac{x}{s}\right) + z, \qquad \hat{x} = s\,(q - z)$$

- $x$：原始浮点值；$\hat{x}$：反量化后的近似值（有误差 $x-\hat{x}$）。
- $s$（**scale**，缩放因子）：把浮点范围压进整数范围的"刻度"。$s>0$。
- $z$（**zero-point**，零点）：整数域里代表"浮点 0"的位置，用来对齐非对称分布。
- $q$：存储的整数（量化值），落在 $[q_{min}, q_{max}]$。

**对称(symmetric) vs 非对称(asymmetric)**：
- 对称：强制 $z=0$，量化区间关于 0 对称，例如 INT8 用 $[-127,127]$。公式简化为 $q=\mathrm{round}(x/s)$，硬件乘加更省（不用减 $z$）。**权重通常对称**（权重分布近似零均值）。
- 非对称：允许 $z\neq0$，能更好贴合 ReLU 后那种"只在正半轴"的激活分布。

**scale 怎么定**：常见取 $s=\dfrac{\max(|x|)}{q_{max}}$（对称，按张量最大绝对值）。这一步需要"看一眼真实数据"，所以要做 **校准(calibration)**——拿一小批样本前向，统计每层激活/权重的数值范围。

> 想再补底层公式（round 误差、clip、percentile 校准），见 [[llm-compression/quantization/量化基础]]；GPTQ 的二阶误差补偿见 [[llm-compression/quantization/GPTQ]]。

## 2. 它解决什么问题

在 llm-compressor 之前，社区里 GPTQ、AWQ、SmoothQuant、FP8 各有各的脚本、各有各的权重布局、各有各的推理 kernel。结果是：

- 算法之间无法组合（想"先 SmoothQuant 平滑、再 GPTQ 量化"要自己缝代码）。
- 导出格式五花八门，vLLM 要为每种格式写一套 loader。
- W4A16、W8A8、FP8 这些"方案"没有统一描述。

```
   ┌──────────────────── 碎片化时代 ────────────────────┐
   GPTQ脚本 ─→ gptq格式 ─┐
   AWQ脚本  ─→ awq格式  ─┤→ vLLM 要写 N 套 loader，难组合
   SQ脚本   ─→ 自定义   ─┘
   ┌──────────────── llm-compressor 之后 ───────────────┐
   GPTQ/AWQ/SQ/FP8 ── 统一 Modifier ── compressed-tensors ── vLLM 一套 loader
```

llm-compressor 把"用什么算法、量到几 bit、什么粒度、激活动不动态"全部抽象成 **QuantizationScheme**，把算法步骤抽象成 **Modifier**，把产物统一成 **compressed-tensors** 格式。一个框架，所有方案，vLLM 直接吃。

## 3. 整体架构：四层

```
┌──────────────────────────────────────────────────────────┐
│  Recipe（配方，YAML 或 Python dict / Modifier 列表）       │
│  例: SmoothQuantModifier + GPTQModifier                   │
├──────────────────────────────────────────────────────────┤
│  Modifier（算法插件）                                      │
│  GPTQModifier / AWQModifier / SmoothQuantModifier /       │
│  QuantizationModifier(通用，可配 FP8) / SparseGPTModifier │
│  —— 每个 Modifier 在某些步骤上"挂钩"模型并改写它           │
├──────────────────────────────────────────────────────────┤
│  oneshot() / Pipeline（执行引擎）                          │
│  装载校准数据 → 逐层前向 → 触发 Modifier → 写回权重       │
├──────────────────────────────────────────────────────────┤
│  compressed-tensors（落盘格式 + QuantizationScheme 元数据）│
│  量化后的 INT/FP 权重 + scale/zero_point + config.json    │
└──────────────────────────────────────────────────────────┘
                          ↓ save_pretrained
                vLLM 加载 → 高速低精度推理
```

- **Recipe**：你写的"要做什么"。一条 recipe 是一个或多个 Modifier 的有序组合。
- **Modifier**：算法本体。它声明自己作用在哪些层（`targets`，如 `Linear`）、忽略哪些层（`ignore`，如 `lm_head`）、用什么 scheme。
- **执行引擎**（入口函数 `oneshot`）：负责把校准数据喂进模型、按层收集统计量、调用 Modifier 完成变换与量化。
- **compressed-tensors**：独立的权重格式库，定义了量化权重 + 元数据怎么存，vLLM 依赖它来反序列化。

## 4. QuantizationScheme 字段逐个拆解

文件顶部的 `FP8` / `FP8_DYNAMIC` 就是两套预置 scheme。一个 scheme 描述"权重怎么量、激活怎么量"，每个由 `QuantizationArgs` 组成。逐字段看：

```
QuantizationArgs(
    num_bits   = 8,                        # 量化位宽：8(INT8/FP8) / 4(INT4) ...
    type       = QuantizationType.FLOAT,   # FLOAT→FP8 ; INT→INT8/INT4
    strategy   = QuantizationStrategy.TENSOR,  # 粒度：见第5节
    symmetric  = True,                     # 对称(z=0) / 非对称
    dynamic    = False,                    # 静态(校准时定scale) / 动态(运行时算scale)
    observer   = "minmax",                 # 怎么估范围；dynamic 时可为 None
)
```

字段含义：

| 字段 | 作用 | 取值与直觉 |
|------|------|-----------|
| `num_bits` | 位宽 | 8=INT8/FP8，4=INT4。越低越省，越易掉精度 |
| `type` | 整数还是浮点 | `INT`=定点（GPTQ/AWQ 走这条）；`FLOAT`=FP8（E4M3） |
| `strategy` | 量化粒度 | TENSOR/CHANNEL/GROUP/TOKEN，见第5节 |
| `symmetric` | 是否 z=0 | 权重多用 True；非对称激活用 False |
| `dynamic` | scale 何时算 | False=校准期定死；True=每次前向按当前张量现算 |
| `observer` | 范围估计器 | minmax / mse / 直方图等；dynamic 时常为 None |

**读懂顶部两套预置 scheme**：

```
FP8（静态全量化，W8A8-FP8）
  weights:           FLOAT8, TENSOR,  symmetric, static
  input_activations: FLOAT8, TENSOR,  symmetric, static   ← 激活也提前校准定 scale
   → 适合：吞吐极致、能接受一次校准；激活 scale 固定，kernel 最简单

FP8_DYNAMIC（权重静态 + 激活动态）
  weights:           FLOAT8, CHANNEL, symmetric, static   ← 每个输出通道一个 scale
  input_activations: FLOAT8, TOKEN,   symmetric, DYNAMIC  ← 每个 token 运行时现算 scale
   → 适合：免激活校准、对分布漂移更鲁棒；精度通常更好，kernel 略复杂
```

> 关键直觉：**动态激活**不需要校准数据来定激活 scale（运行时按当前 token 的最大值现算），所以更省事、对长尾输入更稳；代价是每步多一点点开销。**静态激活**把 scale 提前烧死，kernel 最快，但需要有代表性的校准集。

## 5. strategy 粒度：一个 scale 管多少数

这是量化精度的关键旋钮——**scale 共享得越细，越能贴合局部分布，精度越高，但元数据越多**。

```
权重矩阵 W  (shape = [out_features, in_features])
┌───────────────────────────────────────────┐
│  TENSOR：整块共用 1 个 scale                │  最省，最糙
│  ┌─────────────────────────────────────┐   │
│  │  s                                  │   │
│  └─────────────────────────────────────┘   │
│  CHANNEL：每个输出通道(行)一个 scale         │  权重常用
│  ├─ s0 ───────────────────────────────┤    │
│  ├─ s1 ───────────────────────────────┤    │
│  GROUP(g=128)：每行再切成若干列块，各一 scale│  W4A16 标配
│  ├ s0 ┤├ s1 ┤├ s2 ┤├ s3 ┤ ... (每128列)    │  精度最高
└───────────────────────────────────────────┘

激活 X (shape = [num_tokens, hidden])
  TOKEN：每个 token(行)一个 scale —— 动态量化常用
  ├─ token0: s ─┤
  ├─ token1: s ─┤
```

- **TENSOR**：最少 scale、最快，但一个离群值就把整块 scale 拉大，精度差。
- **CHANNEL**：权重按输出通道分，每行独立。FP8 权重、W8A8 权重常用。
- **GROUP**（如 group_size=128）：每行再按 128 列分组，每组一个 scale。**INT4（W4A16, GPTQ/AWQ）几乎都用 GROUP=128**，因为 4-bit 范围太小，必须细粒度才能保精度。
- **TOKEN**：激活按 token 分，天然配合 `dynamic=True`（每个 token 现算 scale）。

命名速记：**W{权重bit}A{激活bit}**。
- W4A16：权重 4bit，激活仍 16bit（不量化激活）→ GPTQ/AWQ 主战场，省显存、单请求/低并发更快。
- W8A8：权重 8bit、激活 8bit → 用 INT8 或 FP8 算子，**高吞吐**场景（大 batch、compute-bound）收益大。
- W8A16 / FP8 等是中间档。

## 6. 四大算法的机制（讲原理，不编 CLI）

### 6.1 GPTQ —— 逐层最小化量化误差（W4A16 王牌）

GPTQ（详见 [[llm-compression/quantization/GPTQ]]）不是简单 round，而是**带误差补偿的二阶量化**。核心问题：量化某个权重列会引入误差，能不能调整还没量化的列来"抵消"这个误差？

它对每层 $W$ 求解最小化重构误差 $\|WX - \hat{W}X\|^2$，用海森矩阵 $H = 2XX^\top$ 的逆来指导补偿。逐列量化，量完一列就把误差按 $H^{-1}$ 传播给剩余列：

```
列0 量化 → 产生误差 e0
          → 把 e0 按 H⁻¹ 比例补偿到 列1..N （让它们"提前修正"）
列1 量化（已含修正）→ 误差 e1 → 补偿到 列2..N
...
```

效果：W4A16 GROUP=128 下精度损失很小。在 llm-compressor 里用 `GPTQModifier(scheme="W4A16")`。需要**校准数据**（统计 $XX^\top$）。

### 6.2 AWQ —— 激活感知的权重缩放（同为 W4A16 路线）

AWQ 的洞察：不是所有权重一样重要，**被大激活乘到的权重通道更重要**。与其直接量化，不如先给"重要通道"乘一个缩放 $s>1$ 把它们放大（量化时相对误差变小），再在激活侧除以 $s$ 抵消，保持数学等价：

$$y = (W \cdot \mathrm{diag}(s))\,(\mathrm{diag}(s)^{-1} x)$$

```
   原始:   y = W x
   AWQ :   y = (W·s)·(s⁻¹·x)      数学等价，但 W·s 更"好量化"
   s 由激活幅度决定：激活大的通道 → s 大 → 该通道权重被保护
```

AWQ 通常无需反向传播、速度快、对指令模型友好。`AWQModifier(scheme="W4A16")`。

### 6.3 SmoothQuant —— 把激活离群值"搬"到权重（为 W8A8 铺路）

激活里常有少数维度数值特别大（离群值 outlier），导致激活很难量化。SmoothQuant 引入逐通道平滑因子 $s$，**把激活的难度按比例转移到权重**（权重本来好量化）：

$$\hat{Y} = (X\,\mathrm{diag}(s)^{-1})\,(\mathrm{diag}(s)\,W)$$

```
   激活 X 有 outlier(尖峰)  ── 难量化
   权重 W 平滑              ── 好量化
   SmoothQuant: X←X/s , W←W·s
   → 激活变平滑、权重稍微变陡，两边都"中等好量化"→ W8A8 可行
```

平滑强度由超参 $\alpha$（migration strength，常 0.5~0.8）控制。SmoothQuant 本身**不量化**，它是个"预处理 Modifier"，常和 GPTQ/Quantization 串联使用。`SmoothQuantModifier(smoothing_strength=0.8)`。

### 6.4 FP8 —— 8-bit 浮点，硬件原生支持

FP8（`type=FLOAT, num_bits=8`）不是定点而是浮点，常用 **E4M3**（1 符号 + 4 指数 + 3 尾数）。相比 INT8，浮点的指数位让它**动态范围大**，更耐离群值，且 Hopper/Ada 等 GPU 有原生 FP8 Tensor Core。

```
INT8:  线性刻度，范围窄，离群值会 clip
FP8(E4M3): 指数刻度，近 0 密、远处疏，动态范围 ~±448
   → 不需要 GPTQ 那样的误差补偿，常常"直接量化"即可
```

FP8 在 llm-compressor 里走通用的 `QuantizationModifier`，配上文件顶部那种 `FP8` / `FP8_DYNAMIC` scheme 即可，**不需要校准数据**（尤其 DYNAMIC 版本）。这是它相对 GPTQ/AWQ 的最大易用性优势。

### 6.5 四算法对照

| 算法 | 典型方案 | 量谁 | 要校准? | 误差补偿 | 主要收益场景 |
|------|---------|------|--------|---------|-------------|
| GPTQ | W4A16 INT | 权重 | 要 | 海森二阶 | 省显存、低并发更快 |
| AWQ | W4A16 INT | 权重 | 要(少量) | 激活感知缩放 | 省显存、指令模型 |
| SmoothQuant | 预处理→W8A8 | (平滑) | 要 | 激活↔权重迁移 | 为 INT8 W8A8 铺路 |
| FP8 | W8A8 FLOAT | 权重+激活 | 不要/少 | 无(浮点够用) | 高吞吐、上手最快 |

## 7. Recipe 配置思路：用 Modifier 串流水线

Recipe 的精髓是**组合**。每个 Modifier 声明三件事：作用对象、忽略对象、量化 scheme。典型组合：

```
# 思路示意（字段名以官方文档为准，这里讲"配置心智模型"）
recipe = [
    SmoothQuantModifier(smoothing_strength=0.8),     # ① 先平滑激活
    GPTQModifier(
        targets="Linear",      # 量化所有 Linear 层
        scheme="W8A8",         # 权重8 激活8（INT）
        ignore=["lm_head"],    # 输出头不量化，保精度
    ),                                               # ② 再 GPTQ 量化
]
# FP8 路线则单独一个 Modifier：
recipe_fp8 = QuantizationModifier(scheme="FP8_DYNAMIC", ignore=["lm_head"])
```

配置心智模型（六问）：

```
① 目标硬件？ Hopper/Ada 有 FP8 → 优先 FP8 ; 老卡/要INT4 → GPTQ/AWQ
② 瓶颈是显存还是吞吐？
     显存(单卡装不下) → W4A16 (GPTQ/AWQ)
     吞吐(大batch)    → W8A8 (FP8 或 INT8+SmoothQuant)
③ 有没有校准数据？ 没有/想省事 → FP8_DYNAMIC（免激活校准）
④ 哪些层别动？ ignore=["lm_head", 路由门控等敏感层]
⑤ INT4 粒度？ group_size=128 几乎是默认
⑥ 要不要叠加稀疏？ 可再加 SparseGPTModifier（2:4 稀疏）与量化组合
```

预置 scheme 名（如 `"W4A16"`, `"W8A8"`, `"FP8"`, `"FP8_DYNAMIC"`）是字符串快捷方式，等价于一组 `QuantizationArgs`，就是文件顶部展开的样子。**精确字段名与可选 scheme 列表以官方文档为准**。

## 8. 整体流程：从 HF 模型到 vLLM 产物

```
 HF 模型 (FP16/BF16)
      │
      ▼  ① 加载模型 + tokenizer
 ┌─────────────────────────────────────────────┐
 │ oneshot(model, recipe, dataset, ...)         │
 │                                              │
 │  ② 取校准集(几百条样本)，逐层前向            │
 │  ③ Modifier 收集统计：                       │
 │       SmoothQuant→激活/权重幅度              │
 │       GPTQ→ H = XXᵀ                           │
 │       AWQ→ 激活重要性                         │
 │  ④ Modifier 变换权重：平滑 / 缩放 / 补偿量化 │
 │  ⑤ 计算 scale / zero_point，量化成 INT/FP8   │
 │  ⑥ 打包成 compressed-tensors                 │
 └─────────────────────────────────────────────┘
      │
      ▼  ⑦ save_pretrained("./model-quant")
 量化权重 + config.json(含 quantization_config) + scale 表
      │
      ▼  ⑧ vLLM 直接加载
 LLM("./model-quant")  → 低精度高速推理
```

- **校准集**：FP8_DYNAMIC 可以几乎不用；GPTQ/AWQ/SmoothQuant 需要几百条有代表性的样本（一般用领域内文本即可）。
- **逐层处理**：为省显存，引擎通常一层一层处理（处理完一层就释放该层的中间量），所以即便大模型也能在有限显存上量化。
- **不需要训练**：oneshot 是后训练量化(PTQ)，不做反向更新（GPTQ 的"补偿"是闭式解，不是梯度训练）。

## 9. 导出与 vLLM 兼容：compressed-tensors

llm-compressor 的产物用 **compressed-tensors** 库序列化。落盘后目录里关键的是 `config.json` 中的 `quantization_config`，它记录了每组权重的 scheme（位宽/类型/粒度/对称性）和 scale/zero-point 的存储布局。

```
model-quant/
├── config.json            ← 含 quantization_config（scheme 元数据）
├── model.safetensors      ← 量化后的 INT4/INT8/FP8 权重 + scale + zero_point
└── tokenizer.*
        │
        ▼ vLLM 启动时读取 quantization_config
   选择匹配的反量化/低精度 kernel（W4A16 marlin / FP8 cutlass 等）
```

为什么 vLLM 能"一套 loader 通吃"：因为所有算法最终都落到**同一种格式描述**（compressed-tensors 的 scheme），vLLM 只需按 scheme 字段挑 kernel，而不必关心你当初用的是 GPTQ 还是 AWQ。这正是第 2 节"统一格式"的兑现。vLLM 端用法见 [[llm-inference/vllm/README]]。

## 数值例子：把 scale 算到底

**例 1：INT8 对称量化一个权重行**
设某通道权重 $w=[-0.42,\ 0.11,\ 0.95,\ -0.88]$，对称 INT8 用 $[-127,127]$。

- $\max|w| = 0.95$，scale $s=\dfrac{0.95}{127}\approx 0.00748$。
- $q=\mathrm{round}(w/s)$：
  - $-0.42/0.00748\approx-56.1 \to -56$
  - $0.11/0.00748\approx 14.7 \to 15$
  - $0.95/0.00748\approx 127.0 \to 127$
  - $-0.88/0.00748\approx-117.6 \to -118$
- 反量化 $\hat w=s\,q$：$[-0.4188,\ 0.1122,\ 0.9500,\ -0.8826]$，误差均 < 0.004。

**例 2：INT4 GROUP 为什么必须细粒度**
INT4 对称只有 $[-7,7]$ 共 15 个台阶。若整行（含一个 outlier=6.0，其余都 <0.5）共用一个 scale：$s=6.0/7\approx0.857$，那么 0.3 这种小权重 $q=\mathrm{round}(0.3/0.857)=0$ —— **直接归零，信息全丢**。改成 group_size=128 后，outlier 被隔离在它自己的小组，其它组用各自的小 scale，小权重得以保留。这就是 W4A16 必配 GROUP 的原因。

**例 3：FP8(E4M3) 的动态范围优势**
E4M3 可表示约 $\pm448$，且近 0 处分辨率很高。一个含 outlier 的激活 $[0.01, 0.02, 256.0]$：
- INT8 对称：$s=256/127\approx2.016$，则 $0.01\to\mathrm{round}(0.005)=0$，小值全丢。
- FP8：256 在范围内不 clip，0.01 仍落在某个可表示的小指数档位，**两端都保住**。
这解释了为何 FP8 常常"直接量化"就够，不必像 INT8 那样先 SmoothQuant。

**例 4：W4A16 显存收益**
7B 模型 FP16 权重约 $7\times10^9\times2\text{B}\approx14\,\text{GB}$。W4A16 权重约 4bit：$7\times10^9\times0.5\text{B}\approx3.5\,\text{GB}$，再加 group scale（每128列一个 FP16 scale，开销很小）。**约 4 倍显存压缩**，单张消费级卡即可放下（数值为估算，实际含 embedding/未量化层略大，以实测为准）。

## 常见问题

| 问题 | 答案 |
|------|------|
| GPTQ 和 AWQ 选哪个？ | 都走 W4A16；AWQ 多数情况更快更省事、指令模型友好，GPTQ 在某些任务精度略稳。可都试，看下游指标 |
| FP8 和 INT8 选哪个？ | 有 Hopper/Ada → FP8（免/少校准、耐 outlier、上手快）；老卡或要极致 INT 算子 → INT8+SmoothQuant |
| 为什么要 ignore lm_head？ | 输出头对精度敏感，量化它常明显掉点；通常保留高精度 |
| 静态 vs 动态激活？ | 静态最快但需校准且怕分布漂移；动态(TOKEN)免校准、更鲁棒，开销略大。求稳选 FP8_DYNAMIC |
| 没有校准数据能量化吗？ | FP8_DYNAMIC 基本可以；GPTQ/AWQ/SmoothQuant 需要几百条代表性样本 |
| group_size 怎么选？ | INT4 常用 128；更小(64)精度略高但元数据更多、更慢 |
| 能叠加稀疏吗？ | 能，SparseGPTModifier(2:4) 可与量化 Modifier 组合，先稀疏后量化 |
| 量化后怎么部署？ | save_pretrained 出 compressed-tensors，vLLM 直接 `LLM(path)` 加载，自动选 kernel |
| W4A16 一定更快吗？ | 显存友好、低并发/单请求受益；大 batch、compute-bound 时 W8A8/FP8 吞吐更高 |
| recipe 字段记不准？ | scheme 名("W4A16"/"FP8_DYNAMIC")是稳定快捷方式；精确参数以官方文档为准，不要硬背 |
