## 0. 一句话锚点

- **量化(Quantization)**：用更少的比特(FP16→INT8/INT4)表示权重/激活，**省显存 + 省带宽 + 用整数算子加速**。
- **蒸馏(Distillation)**：训一个小模型(student)去模仿大模型(teacher)的**输出分布**，换"参数量"。
- **剪枝(Pruning)**：把"不重要"的权重/神经元/注意力头**置零或删掉**，换"冗余"。
- 一句记忆：**量化改比特，蒸馏改架构，剪枝改连接**。三者正交，可叠加。

## 1. 地基：为什么大模型必须压缩

### 1.1 显存账本(最高频开场题)

推理显存 ≈ **模型权重 + KV Cache + 激活临时**。权重是大头。一个参数占几字节由 dtype 决定：

```
FP32 = 4 字节   FP16/BF16 = 2 字节   INT8 = 1 字节   INT4 = 0.5 字节
```

**手算：7B 模型权重显存**

$$ \text{显存} = N_{params} \times \text{bytes/param} $$

| dtype | bytes | 7B 权重显存 | 70B 权重显存 |
|-------|-------|-------------|--------------|
| FP32  | 4     | 28 GB       | 280 GB       |
| FP16  | 2     | 14 GB       | 140 GB       |
| INT8  | 1     | 7 GB        | 70 GB        |
| INT4  | 0.5   | 3.5 GB      | 35 GB        |

结论：**70B 模型 FP16 放不进单卡 A100(80GB)，INT4 后 35GB 单卡可跑**。这就是量化的核心商业价值。

### 1.2 浮点 vs 整数：到底压缩了什么

一个 FP16 数有 1 符号 + 5 指数 + 10 尾数 = 16 bit，表示范围广但"连续"。INT8 只有 256 个离散格点。量化的本质是：

```
连续的 FP16 值域   ──映射──>   {-128, ..., 127}  这 256 个整数格子
    [-w_max, w_max]                每个格子宽度 = scale
```

**为什么能这么干**：神经网络权重对小扰动**鲁棒**(本身训练就有噪声/dropout)，损失一点精度换 2~4 倍显存通常可接受。

## 2. 量化数学(必背核心)

### 2.1 仿射量化(Affine / 非对称)

把浮点 $x$ 映射到整数 $q$：

$$ q = \text{round}\left(\frac{x}{s}\right) + z, \qquad s = \frac{x_{max}-x_{min}}{q_{max}-q_{min}} $$

- $s$ = **scale**(缩放，浮点)，决定每格宽度
- $z$ = **zero-point**(零点，整数)，保证浮点 0 能精确表示(对 padding/ReLU 很重要)
- **反量化(dequant)**：$ \hat{x} = s \cdot (q - z) $

### 2.2 对称量化(Symmetric)

令 $z=0$，值域强制对称 $[-\alpha, \alpha]$：

$$ s = \frac{\alpha}{2^{b-1}-1}, \qquad q = \text{clamp}\big(\text{round}(x/s),\ -2^{b-1},\ 2^{b-1}-1\big) $$

权重通常用对称(分布近似零均值，省去 zero-point 加法，算子更快)；激活有时用非对称(ReLU 后全正，分布偏)。

### 2.3 量化的两类误差

```
量化误差 = 舍入误差(round) + 截断误差(clamp/clip)
           ↑ scale 太小才精细       ↑ scale 太小会把 outlier 截飞
                       ←── 矛盾，scale 选择是个权衡 ──→
```

舍入误差期望 $\approx s/\sqrt{12}$(均匀分布假设)。**scale 越小越精细，但 outlier 越容易被 clamp 截断爆掉** —— 这是后面 §4 掉点的数学根源。

## 3. 量化粒度与时机

### 3.1 粒度(granularity)

```
per-tensor    : 整个权重矩阵 1 个 scale         最快, 最糙
per-channel   : 每个输出通道 1 个 scale         权重常用, 精度好
per-group     : 每 g 个元素(如128)1 个 scale    INT4 标配(GPTQ/AWQ)
per-token     : 每个 token 的激活 1 个 scale    激活动态量化常用
```

粒度越细，scale 越贴合局部分布，掉点越小，但元数据(scale 表)开销越大。**INT4 几乎必须 group-wise(g=128)**，否则掉点严重。

### 3.2 PTQ vs QAT

| | PTQ 训练后量化 | QAT 量化感知训练 |
|--|--------------|----------------|
| 是否重训 | 否(只需少量校准数据) | 是(插入伪量化节点反传) |
| 成本 | 低(几分钟~几小时) | 高(接近重训) |
| 精度 | INT8 好、INT4 易掉点 | 最好，能压到 INT4/更低 |
| LLM 现状 | **主流**(GPTQ/AWQ 都是 PTQ) | LLM 上少用(太贵) |

### 3.3 Weight-only vs Weight+Activation

- **Weight-only(W4A16)**：只量化权重，激活保持 FP16。瓶颈是**显存带宽**(decode 阶段每步都要把权重从显存搬进算力)，所以即使算的时候反量化回 FP16，**省带宽就提速**。GPTQ/AWQ 属此类。
- **Weight+Activation(W8A8)**：权重激活都量化，用真 INT8 矩阵乘(GEMM)算子，**省算力**，适合 compute-bound 的 prefill/大 batch。SmoothQuant、LLM.int8() 属此类。

## 4. 为什么会掉点：离群值(Outlier)

这是量化面试**最核心的"为什么"**。

```
激活值分布(某些层):
  绝大多数 token 的激活   |||||||||||  集中在 [-1, 1]
  极少数维度的 outlier               ●  突然冒到 +70

per-tensor scale 被这个 70 撑大:
  s = 70 / 127 ≈ 0.55
  => [-1,1] 区间内的正常值全挤进 round(1/0.55)=±2 这 5 个格子里
  => 正常值的信息几乎全丢 → 掉点
```

**关键事实**(LLM.int8() 论文)：当模型 > 6.7B 时，激活会出现**系统性 outlier**，固定出现在某些特征维度，幅度可达普通值的 100 倍。它们对模型效果**至关重要**(删了就崩)，又**破坏量化**(撑大 scale)。

后续三大方法本质都在解决 outlier：

| 方法 | 思路一句话 |
|------|-----------|
| LLM.int8() | 把 outlier 维度**单独拎出来用 FP16 算**，其余 INT8 |
| SmoothQuant | 把激活的难度**数学等价地搬一部分到权重**上 |
| AWQ | 识别**重要权重通道**，用 scale 保护它不被压坏 |
| GPTQ | 不躲 outlier，而是**逐列量化 + 二阶误差补偿** |

## 5. GPTQ：二阶误差补偿

**目标**：逐层最小化量化前后输出的 L2 误差 $\|WX - \hat{W}X\|^2$。

**核心洞察(源自 OBQ/OBS)**：量化某个权重产生的误差，可以**用 Hessian 信息更新其余还没量化的权重来补偿**。

$$ H = 2XX^\top \quad(\text{该层输入的二阶统计}) $$

**逐列贪心**：量化第 $q$ 列权重 $w_q \to \hat{w}_q$，产生误差 $\delta = w_q - \hat{w}_q$，把它按 Hessian 逆传播到剩余列：

$$ \Delta w_{rest} = -\frac{\delta}{[H^{-1}]_{qq}} \cdot H^{-1}_{:,q} $$

```
列1 列2 列3 ... 列N
[Q] [ ] [ ] ... [ ]   量化列1, 产生误差δ
 └──补偿─→ 更新列2..N, 把δ"摊"到后面
     [Q] [ ] ... [ ]   再量化列2...
```

- **GPTQ 的工程贡献**：把 OBQ 的 $O(d^4)$ 降到可处理 LLM 的规模(任意固定列序 + Cholesky 分解 + lazy batch update)。
- 通常 **W4A16 group=128**，4-bit 几乎无损。
- 校准数据：约 128 条序列即可。

## 6. AWQ：激活感知权重量化

**核心观察**：不是所有权重一样重要。**激活值大的输入通道，对应的权重通道更重要**(因为它们对输出贡献大)。AWQ 不重训、不用 Hessian，只做**逐通道缩放**保护重要权重。

数学等价(不改变输出)：

$$ y = Wx = (W \cdot \text{diag}(s)) \cdot (\text{diag}(s)^{-1} x) $$

对重要通道乘一个 $s>1$ 放大权重(量化更精细)，同时把激活除以 $s$(转移到激活的反量化里吸收)。$s$ 由激活幅度的统计搜索得到(通常 $s = (\text{act\_scale})^\alpha$，网格搜 $\alpha$)。

```
重要通道(激活大):  权重 ×s  → 量化格子相对更密 → 误差小
普通通道:           权重 ×1  → 正常量化
        净效果: 把比特预算"花在刀刃上"
```

- 只需 weight-only，**对校准集不敏感**(不像 GPTQ 依赖校准分布)，泛化好。
- W4A16，速度/精度常优于 GPTQ，是开源部署主流。

## 7. SmoothQuant：把难度从激活搬到权重

**问题**：W8A8 想用真 INT8 GEMM 提速，但**激活有 outlier 难量化**，而**权重很好量化**(分布平滑)。难度不均衡。

**核心**：通过逐通道缩放，把激活的"难度"**等价地迁移一部分到权重**：

$$ Y = (X \,\text{diag}(s)^{-1})(\text{diag}(s)\, W), \qquad s_j = \frac{\max(|X_j|)^\alpha}{\max(|W_j|)^{1-\alpha}} $$

```
迁移前:  激活 ▁▁▁█▁▁(outlier尖)   权重 ▃▃▃▃▃▃(平滑)  → 激活难量化
迁移后:  激活 ▃▃▃▅▃▃(被压平)       权重 ▃▃▄▅▄▃(略变难)  → 两边都好量化
         迁移强度 α(常0.5)平衡两边
```

- $\alpha$ 是迁移强度(常 0.5)：$\alpha$ 大→更多难度给权重。
- 缩放可**离线融入前一层**(如 LayerNorm 的权重)，推理零额外开销。
- 实现 W8A8 真加速 + 精度几乎无损，适合大 batch / prefill。

## 8. INT8 / FP8 与 LLM.int8()

### 8.1 LLM.int8()(混合精度分解)

```
激活矩阵按列扫描, 找出含 outlier 的维度(|x|>阈值, 如6.0):
  ┌─ outlier 列(极少, <0.1%) ─→ 走 FP16 矩阵乘
  └─ 普通列(绝大多数)       ─→ 走 INT8 矩阵乘
最后两部分结果相加。零掉点, 但有分支开销。
```

bitsandbytes 的 `load_in_8bit` 即此法。优点零掉点，缺点 outlier 分支降速。

### 8.2 FP8(E4M3 / E5M2)

INT8 是均匀格点，FP8 是**浮点格点**(指数+尾数)，对**动态范围大**的数据更友好(近 0 处密，远处疏)，天然抗 outlier。

| 格式 | 符号 | 指数 | 尾数 | 用途 |
|------|------|------|------|------|
| E4M3 | 1 | 4 | 3 | 前向(精度优先) |
| E5M2 | 1 | 5 | 2 | 反向梯度(范围优先) |

H100/B200 有 FP8 Tensor Core，**训练+推理都能用**，是新硬件的主流方向。

## 9. 蒸馏(Knowledge Distillation)

**思想**：teacher 的 softmax 输出(软标签)比 one-hot 硬标签含更多信息("猫"也有点像"狗")。

带温度 $T$ 的软标签：

$$ p_i = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)} \qquad \mathcal{L} = \alpha\, T^2\, \text{KL}(p^{teacher}\|p^{student}) + (1-\alpha)\,\text{CE}(y, p^{student}) $$

- $T>1$ 把分布**软化**，放大类间相对关系(暗知识 dark knowledge)。乘 $T^2$ 补偿梯度尺度。
- **白盒**(有 teacher logits，如 DistilBERT)vs **黑盒**(只有文本输出，用 teacher 生成数据做 SFT，即"数据蒸馏"，是当下 LLM 主流)。
- 经典：DistilBERT(6 层蒸 12 层，保留 ~97% 性能，快 60%)。

## 10. 剪枝(Pruning)

```
非结构化(unstructured): 单个权重置零 → 稀疏矩阵
   ✅ 精度损失小   ❌ 通用GPU无法加速(随机稀疏)
结构化(structured):     整行/列/头/层删掉 → 矩阵真变小
   ✅ 直接提速      ❌ 掉点更明显
半结构化 2:4:          每4个权重保留2个 → A100 稀疏Tensor Core 提速~2x
```

- 重要性判据：权重幅度(magnitude)、二阶(OBS/Hessian)、**Wanda**(权重×激活幅度，无需重训，专为 LLM)、SparseGPT(GPTQ 思路用于剪枝)。
- LLM 上结构化剪枝(剪层/剪头)+ 少量微调恢复，是常见做法。

## 11. 数值示例：一条向量走完量化全流程

权重向量 $W = [0.12,\ -0.34,\ 0.05,\ 2.10,\ -0.08]$，做 **INT8 对称 per-tensor**。

**第 1 步：求 scale**。$\alpha = \max|W| = 2.10$，$q_{max}=127$：
$$ s = 2.10 / 127 = 0.01654 $$

**第 2 步：量化** $q=\text{round}(W/s)$：
```
0.12 / 0.01654 =  7.25  → round →   7
-0.34/ 0.01654 = -20.6  → round → -21
0.05 / 0.01654 =  3.02  → round →   3
2.10 / 0.01654 = 127.0  → round → 127
-0.08/ 0.01654 = -4.84  → round →  -5
q = [7, -21, 3, 127, -5]   (每个仅占 1 字节, 原来 2 字节)
```

**第 3 步：反量化** $\hat{W}=s\cdot q$：
```
[0.1158, -0.3473, 0.0496, 2.1000, -0.0827]
误差 ε = [+0.0042, +0.0073, +0.0004, 0.0, +0.0027]
```

**第 4 步：看 outlier 的破坏**。如果把 2.10 改成 outlier **70.0**：
$$ s = 70/127 = 0.551 $$
```
0.12 / 0.551 = 0.218 → round → 0    ← 信息全丢!
-0.34/ 0.551 = -0.617→ round → -1
0.05 / 0.551 = 0.091 → round → 0    ← 信息全丢!
```
→ 正常的小权重全被舍入成 0/±1，**这就是 §4 掉点的数值证据**。SmoothQuant/AWQ 正是为了避免这种 scale 被撑爆。

**压缩比验证**：5 个数，FP16=10 字节，INT8=5字节+1个scale(4字节FP32)=9字节。向量短时元数据占比高，**矩阵越大压缩比越接近 2×**(group/per-channel 的 scale 表才划算)。

## 12. 对照表：方法横评

| 方法 | 类型 | 比特 | 重训 | 掉点核心手段 | 加速来源 |
|------|------|------|------|--------------|----------|
| LLM.int8() | W8A8 | 8 | 否 | outlier 走 FP16 | 算力(部分) |
| SmoothQuant | W8A8 | 8 | 否 | 难度迁移到权重 | INT8 GEMM |
| GPTQ | W4A16 | 4 | 否 | Hessian 误差补偿 | 显存带宽 |
| AWQ | W4A16 | 4 | 否 | scale 保护重要通道 | 显存带宽 |
| FP8 | W8A8 | 8 | 可 | 浮点格点抗 outlier | FP8 Tensor Core |
| QAT | W4/更低 | ≤4 | 是 | 训练时感知量化 | 看部署 |

**复杂度直觉**：GPTQ 要算/求逆 Hessian(贵、慢、依赖校准)；AWQ 只做缩放搜索(快、稳)；SmoothQuant 一次离线缩放(最轻)。

## 13. 常见问题 / 高频追问

| 问题 | 踩点答案 | 陷阱 |
|------|---------|------|
| 为什么 LLM 比 CNN 难量化？ | >6.7B 出现系统性激活 outlier，撑爆 scale | 不要只说"参数多" |
| GPTQ vs AWQ 选哪个？ | 精度都好；AWQ 对校准不敏感、更稳更快；GPTQ 更老更通用 | 别说 AWQ 一定更准 |
| W4A16 为什么能提速？ | decode 是**带宽瓶颈**，权重搬运量减半→提速，即便算时反量化回 FP16 | 别说"INT4 算得快"(其实算时反量化) |
| zero-point 有什么用？ | 让浮点 0 精确表示；非对称分布(ReLU 后)更准 | 对称量化 z=0 |
| 为什么 INT4 要 group-wise？ | 4-bit 仅 16 格，per-tensor 太糙；group=128 让 scale 贴合局部 | per-tensor INT4 必崩 |
| SmoothQuant 的 α 调什么？ | 激活↔权重的量化难度平衡，常 0.5 | α 不是学习率 |
| 量化会不会影响长文本/推理能力？ | 复杂推理/数学对量化更敏感，INT4 可能掉点明显，需评测 | 别说"无损" |
| 蒸馏温度 T 作用？ | 软化分布、放大暗知识；损失乘 $T^2$ 补偿梯度 | T=1 退化为普通 softmax |
| 非结构化剪枝为何 GPU 不提速？ | 随机稀疏无法用稠密 Tensor Core；需 2:4 半结构化 | 别说"置零就更快" |
| KV Cache 能量化吗？ | 能(KV cache 量化 INT8/INT4)，长上下文省显存的关键，但对精度敏感需 per-token | 注意 attention 对 KV 误差敏感 |
| FP8 比 INT8 强在哪？ | 浮点格点动态范围大、抗 outlier，且新硬件原生支持训练 | INT8 是均匀格点 |
| PTQ 和 QAT 区别？ | PTQ 不重训(LLM 主流)，QAT 插伪量化反传更准但贵 | LLM 极少全量 QAT |
