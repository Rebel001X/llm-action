## 0. 一句话锚点

- **微调(Fine-tuning)**：拿预训练好的权重 $W_0$ 当起点，在你的数据上继续做梯度下降。
- **全参数微调(Full SFT)**：所有 $W_0$ 都参与梯度更新。
- **PEFT(参数高效微调)**：冻结绝大部分 $W_0$，只训练极少量(常 <1%)新增参数。
- 一句话区分三巨头：**LoRA** 省"可训练参数+优化器显存"；**QLoRA** 在 LoRA 基础上把冻结的底座**量化到 4bit** 再省"权重显存"；**全参** 啥都不省但上限最高。

## 1. 地基/前置：一个参数到底占多少显存

这是所有显存题的根，必须刻进脑子。训练时每个**可训练**参数关联的显存来自四块：

```
            ┌─────────────────────────────────────────┐
            │ 1 个可训练参数(以 Adam + 混合精度为例)   │
            ├─────────────────────────────────────────┤
   权重     │ FP16 主权重副本           2 bytes        │
   梯度     │ FP16 梯度                 2 bytes        │
   Adam m  │ FP32 一阶动量             4 bytes        │
   Adam v  │ FP32 二阶动量             4 bytes        │
 (FP32主权重)│ 混合精度常额外存 FP32 master  4 bytes   │
            ├─────────────────────────────────────────┤
            │ 合计  ≈ 16 bytes / 参数                  │
            └─────────────────────────────────────────┘
```

**记忆口诀**：纯 Adam 混合精度训练 ≈ **16 bytes/参数**（2 权重 + 2 梯度 + 4+4 优化器 + 4 FP32 master）。
**推理**只需权重本身：FP16 = 2 bytes/参数，INT4 = 0.5 bytes/参数。

> 为什么优化器用 FP32？因为动量是长期累加的小量，FP16 的精度($2^{-10}$ 量级)会让小更新被"吃掉"(舍入到 0)，必须用 FP32 保持数值稳定。

**额外一块：激活值(activation)**。前向产生、反向要用的中间结果，与 batch、序列长、层数成正比，跟参数量无关。它是长序列训练 OOM 的真凶，靠**梯度检查点(gradient checkpointing)** 用算力换显存。

## 2. SFT 全参数微调

**做法**：解冻所有权重，按标注数据(指令-回答对)做监督学习，loss 一般是 next-token 的交叉熵，且常**只对回答部分(response)计 loss**，prompt 部分 mask 掉。

```
样本:  <s>[INST] 翻译: hello [/INST] 你好 </s>
        └────── prompt(label=-100,不计loss) ──┘ └─ response 计loss ─┘
```

**优点**：效果上限最高，能改变模型深层行为。
**缺点**：显存爆炸(见第 8 节，7B 全参约 112GB)、易**灾难性遗忘**(把通用能力学没了)、每个任务存一份全量权重。
**关键技巧**：低学习率(1e-5 ~ 2e-5)、warmup、必要时混入通用数据缓解遗忘。

## 3. LoRA —— 面试绝对重点

### 3.1 核心思想：低秩假设

预训练大模型在下游适配时，权重的**改变量 $\Delta W$ 是低秩的**(内在维度很低)。既然 $\Delta W$ 低秩，就不必学整个 $d\times k$ 的稠密矩阵，用两个瘦矩阵的乘积近似即可：

$$W = W_0 + \Delta W = W_0 + B A,\quad B\in\mathbb{R}^{d\times r},\ A\in\mathbb{R}^{r\times k},\ r\ll \min(d,k)$$

前向传播：

$$h = W_0 x + \frac{\alpha}{r} \cdot B A x$$

- $W_0$ 冻结(不算梯度、不存优化器状态)，**只训练 $A,B$**。
- $\alpha/r$ 是缩放因子(scaling)，让 $r$ 变化时不用重调学习率。

```
         x ─────────────┐
         │              │ (冻结主干)
         ▼              ▼
   ┌──────────┐   ┌──────────┐
   │   A(r×k) │   │  W0(d×k) │
   └────┬─────┘   └────┬─────┘
        ▼ r维瓶颈        │
   ┌──────────┐         │
   │   B(d×r) │         │
   └────┬─────┘         │
        │ ×(α/r)        │
        └──────►(+)◄────┘
                │
                ▼ h
```

### 3.2 初始化(高频陷阱题)

- **A 用高斯随机初始化，B 用零矩阵初始化** → 训练起点 $BA=0$，即 $\Delta W=0$，模型从预训练状态平滑出发，不引入噪声。
- 追问：**反过来(A 全零、B 高斯)行不行?** 作者实验未发现显著差异，**只要 A、B 二者之一为 0、另一非 0** 即可保证起点 $\Delta W=0$。关键是 $BA=0$，谁为零次要。
- 追问：**两个都随机非零行不行?** 不行——起点 $\Delta W\ne 0$ 会破坏预训练权重，训练初期不稳定。
- 参考：github.com/microsoft/LoRA/issues/98

### 3.3 LoRA 的省钱原理

省的是**优化器与梯度显存**(占大头的那 14 bytes)。$W_0$ 冻结后只需存它本身(权重显存仍在)，但**梯度、Adam 动量、FP32 master 全部只挂在 A、B 这极少参数上**。

### 3.4 推理零开销

训练完可把 $\Delta W=BA$ **合并**回 $W_0$：$W'=W_0+\frac{\alpha}{r}BA$，得到一个普通权重矩阵，推理时**不增加任何延迟**。多任务时也可不合并，按需热插拔不同 LoRA。

### 3.5 该插在哪、r 取多少

- 经验上插在注意力的 $W_q, W_v$ 最划算；激进可加 $W_k,W_o$ 及 MLP。
- $r$ 常取 8/16/64；$r$ 越大表达力越强、参数越多，但收益递减。
- $\alpha$ 常取 $r$ 的 1~2 倍(如 r=8,α=16)。

## 4. AdaLoRA / QLoRA / DoRA

### 4.1 AdaLoRA：自适应分配秩

LoRA 给每个矩阵**固定相同 $r$**，但各层重要性不同。AdaLoRA 把 $\Delta W$ 写成类 SVD 形式 $\Delta W = P\Lambda Q$，按奇异值的重要性**动态剪枝**——重要的层多分秩，不重要的层裁掉，把有限的参数预算花在刀刃上。

### 4.2 QLoRA：4bit 底座 + LoRA

在 LoRA 上叠三个技术，目标是单卡微调更大模型：

1. **NF4(4-bit NormalFloat)**：针对正态分布权重设计的 4bit 量化类型，信息论最优，把冻结底座 $W_0$ 从 16bit 压到 **4bit**，权重显存直接 ÷4。
2. **双重量化(Double Quant)**：连量化用的 scale 常数也再量化一次，省下平均约 0.37 bit/参数。
3. **分页优化器(Paged Optimizer)**：用 NVIDIA 统一内存，显存峰值时把优化器状态临时换到 CPU 内存，避免 OOM 崩溃。

```
   QLoRA 前向:
   ┌─────────────┐  反量化(临时)   ┌──────────┐
   │ W0 存为 NF4 │ ────────────►  │ BF16 计算 │ ──► h
   │  (4 bit)    │                └──────────┘
   └─────────────┘   梯度只流向 A、B(BF16, 16bit)
```

**关键点**：底座 4bit 只用于**存储与前向反量化计算**，LoRA 适配器 A、B 仍是 16bit 且可训练。**梯度穿过反量化后的底座流到 A、B**，但**不更新底座**。

### 4.3 DoRA：权重分解

把权重拆成**幅度(magnitude)+方向(direction)** 两部分，方向用 LoRA 学、幅度单独学，更贴近全参微调的更新模式，常在同参数量下优于 LoRA。

## 5. 提示类 PEFT(Prompt/Prefix/P-Tuning)

不改原模型权重，只在输入侧加可训练的"软提示"虚拟 token。详见 [[llm-train/peft/Prompt-Tuning]] [[llm-train/peft/Prefix-Tuning]]。

四者区别与联系(高频题)：

1. **Prompt Tuning 与 P-Tuning** 都只在 **Embedding 层**加入虚拟 token；**Prefix Tuning 与 P-Tuning v2** 在**每一层**都加虚拟 token，可训练参数更多，深层 prompt 对预测影响更直接、更稳。
2. **P-Tuning** 用 **LSTM+MLP** 编码 virtual token 再喂入模型，收敛更快。
3. **Prefix Tuning** 为防直接更新 prefix 参数导致训练不稳/掉点，在 prefix 前加 **MLP** 重参数化，**训练完只保留 prefix 参数**。

```
Prompt/P-Tuning:  [v1 v2 ... vk | 真实token...]   ← 只 Embedding 层
                   └ 软提示，可训练 ┘

Prefix/P-Tuning-v2: 每一层 KV 前都拼接可训练前缀
   Layer L:  [prefix_KV | x...]
   Layer L+1:[prefix_KV | x...]   ← 层层都有
```

## 6. 混合精度训练

**动机**：FP32 算得慢、占显存大；FP16/BF16 用 Tensor Core 快 2~8 倍、省一半显存。但纯 FP16 精度不够会发散。

| 类型 | 位宽 | 指数位 | 尾数位 | 特点 |
|------|------|--------|--------|------|
| FP32 | 32 | 8 | 23 | 基准，慢 |
| FP16 | 16 | 5 | 10 | 范围窄($\sim 6.5\times10^4$)易溢出，需 loss scaling |
| BF16 | 16 | 8 | 7 | 范围同 FP32、精度低，**大模型首选** |
| FP8(E4M3) | 8 | 4 | 3 | H100 起支持，更快 |

**FP16 为何要 Loss Scaling**：反向小梯度($<2^{-24}$)在 FP16 下舍入为 0(下溢)。做法：loss 乘大常数 $S$(如 1024)→梯度同步放大躲过下溢区→更新前再÷$S$还原。BF16 指数位和 FP32 一样宽，**不需要** loss scaling。

```
loss × S ──反向──► 梯度被放大 S 倍(躲过下溢) ──÷S──► 还原 ──► 更新FP32主权重
```

混合精度的"混合"：前向/反向用 FP16/BF16(快)，**主权重和优化器用 FP32**(稳)，这正是第 1 节里那份 FP32 master 的来源。

## 7. 分布式并行

单卡放不下/训得慢，就把模型与数据切到多卡。

```
 ┌────────────┬──────────────────────────────┬──────────┐
 │ 并行方式   │ 切什么                       │ 通信     │
 ├────────────┼──────────────────────────────┼──────────┤
 │ DP 数据并行 │ 切 batch，每卡一份完整模型   │ AllReduce梯度│
 │ TP 张量并行 │ 切单层矩阵(行/列)            │ 层内频繁(NVLink)│
 │ PP 流水并行 │ 切层(stage)，卡间接力        │ 点对点传激活 │
 │ SP 序列并行 │ 切序列维(配合 TP 省激活)     │ 配合 TP  │
 │ ZeRO        │ DP 下再切 优化器/梯度/参数   │ 通信换显存 │
 └────────────┴──────────────────────────────┴──────────┘
```

### ZeRO 三阶段(必考)

DP 下每张卡都存一份完整模型+优化器太浪费。ZeRO 把第 1 节那 16 bytes **分片**到 N 张卡：

- **ZeRO-1**：只切**优化器状态**(那 8~12 bytes)。
- **ZeRO-2**：再切**梯度**。
- **ZeRO-3**：再切**参数本身**，用到某层时临时 AllGather 回来。
- 单卡显存近似从 16·P 降到 $\frac{16P}{N}$(通信换显存)。
- **3D 并行**：TP×PP×DP(+ZeRO) 组合，是训千亿模型的标配。

```
ZeRO-3: 参数也切片
 GPU0[θ片0,g片0,opt片0]  GPU1[θ片1,g片1,opt片1] ... GPUn
   用到整层时 → AllGather 临时拼出完整层 → 算完即丢
```

## 8. 显存账逐数手算(核心)

设 7B 模型，$P=7\times10^9$，Adam + 混合精度，按 GB = $10^9$ 字节估。

**(A) 全参数微调** = 16 bytes/参数：

$$7\times10^9 \times 16\,\text{B} = 1.12\times10^{11}\,\text{B} \approx \mathbf{112\ GB}$$

→ 单张 80GB A100 装不下，必须 ZeRO/多卡。逐项拆：权重 14GB + 梯度 14GB + Adam(m,v) 56GB + FP32master 28GB = 112GB。

**(B) LoRA**(冻结底座，设可训练参数仅 $P_{lora}\approx 0.2\%P=1.4\times10^7$)：

- 冻结底座只存权重(BF16)：$7\times10^9\times2 = 14\,\text{GB}$
- 可训练部分 16 bytes：$1.4\times10^7\times16 \approx 0.22\,\text{GB}$
- 合计 $\approx \mathbf{14.2\ GB}$ → 单张 24GB 卡可行。**省了约 8 倍。**

**(C) QLoRA**(底座 4bit + LoRA)：

- 底座 NF4：$7\times10^9\times0.5 = 3.5\,\text{GB}$
- LoRA 可训练：$\approx 0.22\,\text{GB}$
- 合计 $\approx \mathbf{3.7\ GB}$(不计激活) → 单张消费级 12GB 卡可微调 7B。**再省约 4 倍。**

```
显存对比(7B,不含激活):
 全参    ████████████████████████████████████████ 112 GB
 LoRA    █████ 14.2 GB
 QLoRA   █▍ 3.7 GB
```

**(D) LoRA 可训练参数量手算**：单个 $d\times k$ 矩阵的 LoRA 参数 = $r\times k + d\times r = r(d+k)$。设 $d=k=4096,r=8$：

$$8\times(4096+4096)=8\times8192=65536\ \text{参数/矩阵}$$

对比原矩阵 $4096^2\approx1.68\times10^7$，**仅占 0.39%**。若每层给 $W_q,W_v$ 加 LoRA，32 层共 $32\times2\times65536\approx4.19\times10^6$ 参数 ≈ 全模型 0.06%。

## 常见问题/高频追问

| 问题 | 踩点答案 |
|------|----------|
| 训练时显存为何远大于参数本身? | 还要存梯度+优化器(Adam 双动量)+FP32 master+激活，Adam 混合精度 ≈16 bytes/参数 |
| LoRA 为什么省显存? | 冻结底座→只对 A、B 算梯度/存优化器，大头那 14 bytes 几乎全省 |
| QLoRA 比 LoRA 多省什么? | 把**冻结底座**从 16bit 量化到 4bit(NF4)，权重显存÷4；LoRA 只省优化器不省权重 |
| QLoRA 底座 4bit，梯度怎么流? | 前向临时反量化为 BF16 计算，梯度穿过它流到 A、B，但**不更新底座** |
| A、B 怎么初始化、为什么? | A 高斯、B 零，使起点 $BA=0$ 不扰动预训练；反过来也行，二者一零即可 |
| LoRA 推理会变慢吗? | 不会，可把 $BA$ 合并进 $W_0$；多任务时也可不合并热插拔 |
| BF16 vs FP16 选哪个? | 大模型用 BF16(指数位宽=FP32 不易溢出、免 loss scaling)；FP16 需 loss scaling |
| Loss scaling 原理? | loss×S 放大梯度躲过 FP16 下溢，更新前÷S 还原 |
| ZeRO 三阶段切什么? | 1切优化器,2加切梯度,3再切参数;显存 16P→16P/N |
| TP 与 PP 区别? | TP 切单层矩阵(层内通信频繁需 NVLink),PP 切层(卡间接力传激活,有气泡) |
| 怎么缓解微调灾难性遗忘? | 用 PEFT、低 lr、混通用数据、正则(如对 KL 约束) |
| 激活显存怎么省? | 梯度检查点(gradient checkpointing),前向丢中间值反向重算,算力换显存 |
