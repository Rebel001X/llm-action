## 0. 一句话锚点

**LLM 可视化 = 把"黑箱里的数字"映射成"人眼能比较的图形"**。
核心只有四类对象：**结构**（数据怎么流）、**注意力**（token 之间怎么连）、**表示**（向量在空间怎么分布）、**数值健康度**（权重/激活/梯度的分布、量化误差、算子耗时）。所有工具都只是这四件事的不同切片。

---

## 1. 地基：为什么"看不见"，以及可视化在解决什么

LLM 难懂的根因是**维度爆炸 + 高度并行**：

- 一个 token 的隐藏态是 $\mathbb{R}^{d}$ 向量，$d$ 动辄 4096；人眼最多看 3 维。
- 一次前向有 $L$ 层 × （注意力 + FFN），每层又有 $H$ 个注意力头并行。GPT 风格 $L=32, H=32$ 就是上千个矩阵乘同时发生。
- 训练/推理在 GPU 上是几千个 kernel 并发，时间轴上互相重叠。

可视化干三件事，对应三个"降维"：

```
 高维张量 ──(投影/聚合)──▶  2D 图        理解"语义/表示"   (t-SNE, UMAP)
 并行结构 ──(展开成流程)──▶  数据流图     理解"机制/结构"   (llm-viz, Explainer)
 时间轴   ──(火焰图/甘特)──▶  时间线       理解"性能/瓶颈"   (Nsight, Profiler)
```

> 一句话：**可视化是"有损压缩"——它丢掉细节，换来人类可比较的形状**。用它建立直觉，再回到数字做精确判断。

## 2. 端到端结构可视化：看清前向传播每一步

这一类工具把整个 Transformer 摊开成一条**可点击、可悬停**的数据流，是建立直觉最快的方式。

### 2.1 数据流全景（ASCII 版）

```
输入文本 "我 爱 你"
   │  Tokenizer
   ▼
[ids]  →  Embedding 查表  →  + 位置编码
   │                                  │
   ▼  X ∈ ℝ^{seq × d}                 │
 ┌──────────── 第 ℓ 层（共 L 层）─────────────┐
 │  X ──LayerNorm──▶ [Q K V 投影]            │
 │                       │                   │
 │              ┌── 多头注意力 ──┐           │
 │              │ scores=QKᵀ/√dk │           │
 │              │ softmax → ·V    │           │  ← §3 可视化这里
 │              └────────┬───────┘           │
 │            残差相加 + LayerNorm            │
 │                       │                   │
 │              FFN: W₂·act(W₁·X)            │
 │            残差相加 ────────► X'           │
 └────────────────────────┬──────────────────┘
                           ▼  重复 L 次
                     最终 LayerNorm
                           ▼
              LM Head (×Embeddingᵀ) → logits ∈ ℝ^{seq × vocab}
                           ▼
                  softmax → 下一个 token 概率
```

### 2.2 三个代表工具（各自看什么）

| 工具 | 看什么 | 特点 | 链接 |
| --- | --- | --- | --- |
| **Transformer Explainer**（poloclub） | 一个真实小 GPT-2 在浏览器里跑，逐 token 展示 Q/K/V、softmax、概率 | 交互、可改输入、看温度对概率的影响 | poloclub.github.io/transformer-explainer |
| **bbycroft llm-viz** | GPT-2/nano-GPT **3D 立体**展开，每个矩阵乘的数字都可见 | 把"矩阵形状/数据搬运"画成立体方块，理解显存/计算最直观 | bbycroft.net/llm |
| **Deepgram / 科普长文** | 从零讲 attention 的几何直觉 | 偏文字+插图，适合先读再上手工具 | deepgram.com/learn/... |

> 用法建议：**先 bbycroft 看"形状与数据搬运"（理解显存账），再用 Explainer 改输入看"概率怎么变"（理解 softmax/温度）。** 两者互补。

## 3. 注意力可视化：模型到底"看"了谁

注意力是 Transformer 最被研究、也最易可视化的部分，因为它天然是一个 $\text{seq}\times\text{seq}$ 的**权重矩阵**，画成热力图即可。

### 3.1 注意力热力图（单头）

```
          被看的 token (key)
          我    爱    你
       ┌───────────────────
  我   │ 0.7  0.2  0.1     ← 行和=1 (softmax)
查询   │
  爱   │ 0.1  0.6  0.3
  你   │ 0.2  0.3  0.5
       └───────────────────
   颜色越深 = 注意力权重越大
```

- 每一**行**是一个 query token 对所有 key 的注意力分布，**经过 softmax 后每行和为 1**。
- Causal（解码器）模型有**下三角掩码**：右上角全为 0（不能看未来）。
- 多头：$H$ 个头各画一张，常见现象——有的头管"上一个词"，有的头管"句法依存"，有的头是"标点/起始符吸收器"（attention sink）。

### 3.2 工具与方法

| 方法 | 它解决的问题 | 备注 |
| --- | --- | --- |
| **BertViz** | 逐层逐头看注意力连线（head view / model view / neuron view） | 经典库，编码器模型尤佳 |
| **Attention Rollout** | 单头不够看，把多层注意力"乘起来"得到 token 到 token 的总影响 | 近似，但能看全局信息流 |
| **Attention sink 观察** | 解释为什么首 token（如 `<bos>`）权重异常高 | 与 [[llm-inference/KV-Cache优化]] 的 StreamingLLM 直接相关 |

> ⚠️ 护栏：注意力权重**不等于**"可解释的因果重要性"——这是学界有争议的点（"Attention is not Explanation" vs 反驳）。可视化用来**建立假设**，不要当成铁证。

### 3.3 与工程的连接

可视化看到的"attention sink"现象，正是推理侧 **StreamingLLM / KV-Cache 驱逐策略**要保留前几个 token 的原因——可视化直接指导了缓存设计。详见 [[llm-inference/KV-Cache优化]]、[[llm-optimizer/kv-cache]]。

## 4. 嵌入与隐藏态可视化：语义住在哪

词向量/隐藏态是高维的，要看它们的"语义结构"必须降维到 2D/3D。

### 4.1 降维三件套

| 方法 | 保留什么 | 适合 | 注意 |
| --- | --- | --- | --- |
| **PCA** | 全局线性方差最大方向 | 快速看大致结构 | 非线性结构丢失 |
| **t-SNE** | 局部邻域（谁挨着谁） | 看"簇"是否分开 | 簇间距离**不可信**，受 perplexity 影响大 |
| **UMAP** | 局部+部分全局 | 大数据、更快 | 同样别过度解读距离 |

```
   原始: token 向量 ∈ ℝ^4096  （看不见）
        │  降维 (t-SNE / UMAP)
        ▼
   2D 散点:
        猫·  狗·  ┐
        马·       ├─ 动物簇
                  ┘
        红·  蓝·  绿·   ┐ 颜色簇
        国王·──王后·    ┐
        男人·──女人·    ┘ 类比关系（king-man+woman≈queen）
```

### 4.2 工具

- **TensorBoard Embedding Projector**：上传 embedding + 标签，浏览器里转着看 PCA/t-SNE/UMAP，支持最近邻查询。
- **逐层探针（probing / logit lens）**：把中间层隐藏态直接乘 LM Head，看"模型在第几层就已经知道答案"——能可视化"信息何时形成"。

> 经典直觉验证：$\text{vec}(\text{king}) - \text{vec}(\text{man}) + \text{vec}(\text{woman}) \approx \text{vec}(\text{queen})$，在投影图上表现为**平行四边形**。这是嵌入可视化最著名的"啊哈"时刻。

## 5. 量化与权重分布可视化：为什么掉点、离群值在哪

这是 llm-action 量化方向的高频痛点，可视化是定位"量化误差从哪来"的利器。详见 [[llm-compression/quantization/量化基础]]、[[llm-compression/quantization/fp8]]。

### 5.1 权重/激活直方图

量化的本质：把连续的 FP 值映射到有限个整数格点。**分布形状决定量化好坏**。

```
权重直方图（FP16，理想：钟形、对称）
 频
 数 │      ▁▃▅█▅▃▁
    │    ▁▃       ▃▁
    └────┼────┼────┼────  值
       -0.1   0   0.1     ← 集中在 0 附近 → 量化友好

激活直方图（常见：长尾 + 离群值）
 频
 数 │ █▇                       离群值
    │ █▇▅▃▁                      ↓
    └──┼──┼──┼──┼──┼──┼──┼──┼── ·  值
       0                        50  ← 极少数巨大值，但毁掉量化范围
```

**关键洞察**：一个绝对值 50 的离群值会把量化范围 $[-50, 50]$ 撑大，于是 8-bit 的 256 个格点大部分浪费在空旷区，**正常的小值被挤进极少数格点 → 精度崩溃**。这就是 LLM.int8()、SmoothQuant、AWQ 等方法要专门处理离群值的原因。

### 5.2 量化误差热力图

```
      量化误差 |W - dequant(quantize(W))|  逐通道
 通道 0 │ ░░░░░░░░░  小误差
 通道 1 │ ░░░░░░░░░
 通道 2 │ ████████░  ← 离群通道，误差爆炸（重点保护对象）
 通道 3 │ ░░░░░░░░░
```

- 这种图直接告诉你**哪些通道要保 FP16 / 要做 per-channel / 要 smooth**。
- Maarten Grootendorst 的《A Visual Guide to Quantization》就是用大量这类直方图把 INT8/INT4/GPTQ/AWQ 讲清楚的——强烈推荐配套阅读（newsletter.maartengrootendorst.com）。

### 5.3 数值示例（对称 INT8 量化）

给定权重张量最大绝对值 $\alpha = \max|W| = 0.1$，目标 8-bit 对称量化（范围 $[-127, 127]$）：

$$ \text{scale } s = \frac{\alpha}{127} = \frac{0.1}{127} \approx 7.87\times10^{-4} $$

量化：$q = \text{round}(w / s)$，反量化：$\hat w = q \cdot s$。

- 取 $w = 0.043$ → $q = \text{round}(0.043 / 7.87e{-}4) = \text{round}(54.6) = 55$ → $\hat w = 55 \times 7.87e{-}4 \approx 0.0433$，误差约 $0.0003$。✅ 友好。

**现在混入一个离群值** $w_{out}=5.0$，则 $\alpha=5.0$，$s = 5.0/127 \approx 0.0394$。
- 同样的 $w = 0.043$ → $q = \text{round}(0.043/0.0394) = \text{round}(1.09) = 1$ → $\hat w = 0.0394$，**误差从 0.0003 暴涨到约 0.0036（≈12 倍）**。

> 这一手算精确解释了"**一个离群值如何拖垮整层量化精度**"，也解释了 per-channel / per-group 量化为什么有效——把离群值隔离在自己的小范围里。

## 6. 性能可视化：哪一层、哪个 kernel 最慢

理解了"算什么"，接下来要看"算得快不快"。性能可视化是 GPU 调优的眼睛。深入见 [[nsight]]、[[Pytorch-Profiler]]、[[nvtx]]。

### 6.1 时间线（火焰图 / 甘特图）

```
时间 ──────────────────────────────────────────▶
CPU │ ▮launch  ▮launch  ▮launch  ......          (Python 在排队发 kernel)
GPU │   ▮matmul▮  ▮softmax▮ ░░gap░░ ▮matmul▮      (░ = GPU 空转 = bubble)
     │            ↑ 内核间空隙 → CPU 喂不饱 GPU = launch bound
```

- **看 GPU 时间线有没有空隙（bubble）**：有大量空隙 → CPU/launch 受限，考虑 CUDA Graph、增大 batch、算子融合。
- **看哪个 kernel 最宽**：最宽的就是热点。LLM 里通常是大 GEMM（注意力/FFN 投影）或未融合的 elementwise。

### 6.2 三层工具分工

| 层级 | 工具 | 看什么 | 典型结论 |
| --- | --- | --- | --- |
| 框架/算子 | **PyTorch Profiler + TensorBoard** | 每个 op 的 CPU/GPU 时间、调用次数、内存 | "softmax 没融合，调用 1 万次" |
| GPU 全局 | **Nsight Systems** | 时间线、SM 占用、kernel 重叠、NCCL 通信 | "通信和计算没重叠，all-reduce 阻塞" |
| 单 kernel | **Nsight Compute** | 单 kernel 的内存/计算瓶颈、roofline | "这个 GEMM 是 memory bound" |
| 自定义打标 | **NVTX** | 给代码段染色，对齐时间线与业务逻辑 | "attention 段占 40% 时间" |

### 6.3 Roofline：一张图判断"该优化什么"

```
 性能(FLOP/s)
   │            ┌──────── 计算上限 (峰值算力)
   │          ╱
   │        ╱ ← 内存带宽斜坡
   │      ╱ ·算子A(memory bound→提算术强度/融合)
   │    ╱  ·算子B(compute bound→换更快kernel/精度)
   └──────────────────────▶ 算术强度 (FLOP/Byte)
```

- 点在**斜坡**上 → memory bound → 该做**融合/降精度/减少搬运**（FlashAttention 正是为此，见 [[llm-optimizer/FlashAttention]]）。
- 点在**平台**上 → compute bound → 该换更快 kernel 或更低精度（FP8，见 [[llm-compression/quantization/fp8]]）。

## 7. 训练过程可视化：曲线会"说话"

| 曲线 | 健康形态 | 异常信号 → 诊断 |
| --- | --- | --- |
| **loss** | 平滑下降后收敛 | 突然飞起 → 学习率过大/数据脏；阶梯 → LR scheduler |
| **梯度范数 ‖g‖** | 平稳、被 clip 在阈值内 | 尖刺/爆炸 → 加 grad clip、查 LayerNorm |
| **学习率** | 与 warmup/decay 一致 | 形状不对 → scheduler 配错 |
| **权重/激活分布随步数** | 缓慢移动 | 分布漂移剧烈 → 不稳定 |
| **GPU 利用率/吞吐** | 高且稳定 | 锯齿 → 数据加载瓶颈 |

工具：**TensorBoard**（开源、标量+直方图+图结构）、**Weights & Biases**（云端、对比多次实验、超参扫描）。

> 直方图随时间堆叠的"山脊图"特别有用：能一眼看出某层激活是否随训练**逐渐饱和/死亡**（如 ReLU 死神经元、GELU 饱和）。

## 8. 方法论：把可视化拼成一套调试流程

```
现象 ──▶ 选切片 ──▶ 可视化 ──▶ 提假设 ──▶ 回到数字验证
                                  │
   ┌──────────────────────────────┘
   ▼
不懂模型在算啥   → §2 结构可视化（先建直觉）
怀疑注意力异常   → §3 注意力热力图（attention sink？）
量化掉点         → §5 权重/激活直方图 + 误差热力图（找离群通道）
速度慢           → §6 时间线 + roofline（memory/compute/launch bound？）
训练不收敛       → §7 loss/梯度范数曲线（爆炸？漂移？）
```

**黄金法则三条：**
1. **先看形状，再看数字**：可视化建立假设，profiler/指标做定量确认。
2. **小模型先验证**：用 GPT-2 small 在浏览器工具上理解机制，再外推到大模型。
3. **可视化是有损的**：t-SNE 距离、注意力权重都不可全信，永远交叉验证。

## 9. 关键公式与数值速查

**注意力（被热力图可视化的对象）：**
$$ \text{Attn}(Q,K,V) = \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V $$
热力图画的就是括号里 softmax 后的 $\text{seq}\times\text{seq}$ 矩阵。

**对称量化（被直方图/误差图可视化的对象）：**
$$ s=\frac{\max|W|}{2^{b-1}-1},\quad q=\text{round}(W/s),\quad \hat W = q\cdot s,\quad \text{误差}=|W-\hat W| $$

**Roofline 拐点（性能图的核心阈值）：**
$$ I_{\text{ridge}} = \frac{\text{峰值算力 (FLOP/s)}}{\text{峰值带宽 (Byte/s)}} \quad\Rightarrow\quad I < I_{\text{ridge}}\text{ 为 memory bound} $$

**降维（嵌入可视化的目标函数，t-SNE 直觉）：** 让高维近邻在低维仍是近邻，最小化高维概率分布 $P$ 与低维 $Q$ 的 KL 散度 $\text{KL}(P\|Q)$。

## 评价 / 对照 / 局限

| 维度 | 优势 | 局限 / 陷阱 |
| --- | --- | --- |
| 结构可视化（Explainer/llm-viz） | 建立直觉无可替代 | 仅小模型；大模型规模无法照搬 |
| 注意力热力图 | 直观看 token 关系 | 权重 ≠ 因果重要性（学界有争议） |
| 嵌入降维（t-SNE/UMAP） | 看语义簇 | 距离/簇间距不可信，受超参影响大 |
| 量化分布图 | 精准定位离群值 | 需配合实际精度评测，图不等于掉点幅度 |
| 性能时间线/roofline | 直击瓶颈 | 需正确打标（NVTX），否则对不上业务 |
| 训练曲线 | 早期发现发散 | 是结果指示器，不直接给根因 |

**一句话收尾**：可视化不是为了好看，而是为了**把"我猜模型坏在这"变成"我看到模型坏在这"**——它是直觉的放大镜，但永远要用数字复核。
